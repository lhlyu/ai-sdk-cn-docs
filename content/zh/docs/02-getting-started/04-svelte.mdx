# Svelte 快速入门

AI SDK 是一个强大的 TypeScript 库，旨在帮助开发者构建 AI 驱动的应用程序。

在本快速入门教程中，你将构建一个带有流式聊天用户界面的简单智能体。在此过程中，你将学习在自己的项目中使用 SDK 所需的关键概念和技术。

如果你不熟悉[提示词工程](/docs/advanced/prompt-engineering)和[HTTP 流式传输](/docs/foundations/streaming)的概念，可以选择先阅读这些文档。

## 前提条件

要遵循本快速入门，你需要：

- 在本地开发机器上安装 Node.js 22+ 和 pnpm。
- 一个 [Vercel AI Gateway](https://vercel.com/ai-gateway) API 密钥。

如果你还没有获取 Vercel AI Gateway API 密钥，可以通过在 Vercel 网站上[注册](https://vercel.com/d?to=%2F%5Bteam%5D%2F%7E%2Fai&title=Go+to+AI+Gateway)来获取。

## 创建 API 路由

创建一个 SvelteKit 端点 `src/routes/api/chat/+server.ts` 并添加以下代码：

```tsx filename="src/routes/api/chat/+server.ts"
import {
  streamText,
  type UIMessage,
  convertToModelMessages,
  createGateway,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';

import { AI_GATEWAY_API_KEY } from '$env/static/private';

const gateway = createGateway({
  apiKey: AI_GATEWAY_API_KEY,
});

export async function POST({ request }) {
  const { messages }: { messages: UIMessage[] } = await request.json();

  const result = streamText({
    model: gateway('anthropic/claude-sonnet-4.5'),
    messages: await convertToModelMessages(messages),
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

<Note>
  如果你看到 `AI_GATEWAY_API_KEY` 或你的 `POST` 函数出现类型错误，请运行开发服务器。
</Note>

让我们看看这段代码中发生了什么：

1. 使用 `ai` 包中的 `createGateway` 函数创建一个网关提供商实例。
2. 定义一个 `POST` 请求处理程序，并从请求体中提取 `messages`。`messages` 变量包含你和聊天机器人之间的对话历史，为聊天机器人提供进行下一次生成所需的上下文。`messages` 是 `UIMessage` 类型，专为在应用程序 UI 中使用而设计——它们包含完整的消息历史以及相关元数据，如时间戳。
3. 调用从 `ai` 包导入的 [`streamText`](/docs/reference/ai-sdk-core/stream-text) 函数。此函数接受一个配置对象，其中包含 `model` 提供商（在步骤 1 中定义）和 `messages`（在步骤 2 中定义）。你可以传递额外的[设置](/docs/ai-sdk-core/settings)来进一步自定义模型的行为。`messages` 键期望一个 `ModelMessage[]` 数组。此类型与 `UIMessage` 不同，因为它不包含元数据，例如时间戳或发送者信息。为了在这些类型之间进行转换，我们使用 `convertToModelMessages` 函数，它会剥离 UI 特定的元数据，并将 `UIMessage[]` 数组转换为模型期望的 `ModelMessage[]` 格式。
4. `streamText` 函数返回一个 [`StreamTextResult`](/docs/reference/ai-sdk-core/stream-text#result-object)。将其 `stream` 传递给 `toUIMessageStream`，并使用 `createUIMessageStreamResponse` 返回它，以创建一个流式响应对象。
5. 将结果返回给客户端以流式传输响应。

AI SDK 通过[第一方](/providers/ai-sdk-providers)、[兼容 OpenAI](/providers/openai-compatible-providers) 和[社区](/providers/community-providers)包支持数十个模型提供商。

import { gateway } from '@ai-sdk/gateway';

## 连接 UI

现在你已经有了一个可以查询 LLM 的 API 路由，是时候设置你的前端了。AI SDK 的 [UI](/docs/ai-sdk-ui) 包将聊天界面的复杂性抽象为一个类 `Chat`。
其属性和 API 与 React 的 [`useChat`](/docs/reference/ai-sdk-ui/use-chat) 基本相同。

使用以下代码更新你的根页面（`src/routes/+page.svelte`），以显示聊天消息列表并提供用户消息输入：

```svelte filename="src/routes/+page.svelte"
<script lang="ts">
  import { Chat } from '@ai-sdk/svelte';

  let input = '';
  const chat = new Chat({});

  function handleSubmit(event: SubmitEvent) {
    event.preventDefault();
    chat.sendMessage({ text: input });
    input = '';
  }
</script>

<main>
  <ul>
    {#each chat.messages as message, messageIndex (messageIndex)}
      <li>
        <div>{message.role}</div>
        <div>
          {#each message.parts as part, partIndex (partIndex)}
            {#if part.type === 'text'}
              <div>{part.text}</div>
            {/if}
          {/each}
        </div>
      </li>
    {/each}
  </ul>
  <form onsubmit={handleSubmit}>
    <input bind:value={input} />
    <button type="submit">发送</button>
  </form>
</main>
```

此页面使用了 `Chat` 类，默认情况下，它将使用你之前创建的 `POST` 路由处理程序。该类提供了处理用户输入和表单提交的函数和状态。`Chat` 类提供了多个实用函数和状态变量：

- `messages` - 当前的聊天消息（一个对象数组，包含 `id`、`role` 和 `parts` 属性）。
- `sendMessage` - 向聊天 API 发送消息的函数。

该组件使用本地状态来管理输入字段值，并通过调用 `sendMessage` 并传入输入文本，然后清空输入字段来处理表单提交。

LLM 的响应通过消息的 `parts` 数组访问。每条消息包含一个有序的 `parts` 数组，表示模型在其响应中生成的所有内容。这些部分可以包括纯文本、推理令牌等，你稍后会看到。`parts` 数组保留了模型输出的顺序，允许你按生成顺序显示或处理每个组件。

## 使用工具增强你的聊天机器人

虽然大型语言模型（LLM）具有令人难以置信的生成能力，但它们在处理离散任务（例如数学）和与外部世界交互（例如获取天气）方面存在困难。这就是[工具](/docs/ai-sdk-core/tools-and-tool-calling)发挥作用的地方。

工具是 LLM 可以调用的操作。这些操作的结果可以报告回 LLM，以便在下一个响应中考虑。

例如，如果用户询问当前天气，没有工具，模型只能根据其训练数据提供一般信息。但是有了天气工具，它可以获取并提供最新的、特定位置的天气信息。

让我们通过添加一个简单的天气工具来增强你的聊天机器人。

### 更新你的 API 路由

修改你的 `src/routes/api/chat/+server.ts` 文件以包含新的天气工具：

```tsx filename="src/routes/api/chat/+server.ts" highlight="5-8,25-39"
import {
  createGateway,
  streamText,
  type UIMessage,
  convertToModelMessages,
  tool,
  isStepCount,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
import { z } from 'zod';

import { AI_GATEWAY_API_KEY } from '$env/static/private';

const gateway = createGateway({
  apiKey: AI_GATEWAY_API_KEY,
});

export async function POST({ request }) {
  const { messages }: { messages: UIMessage[] } = await request.json();

  const result = streamText({
    model: gateway('anthropic/claude-sonnet-4.5'),
    messages: await convertToModelMessages(messages),
    tools: {
      weather: tool({
        description: '获取某个位置的天气（华氏度）',
        inputSchema: z.object({
          location: z.string().describe('要获取天气的位置'),
        }),
        execute: async ({ location }) => {
          const temperature = Math.round(Math.random() * (90 - 32) + 32);
          return {
            location,
            temperature,
          };
        },
      }),
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

在这个更新后的代码中：

1. 你从 `ai` 包中导入了 `tool` 函数，并从 `zod` 导入了 `z` 用于模式验证。
2. 你定义了一个包含 `weather` 工具的 `tools` 对象。这个工具：
   - 有一个描述，帮助模型理解何时使用它。
   - 使用 Zod 模式定义了 `inputSchema`，指定它需要一个 `location` 字符串来执行此工具。模型将尝试从对话上下文中提取此输入。如果无法提取，它将要求用户提供缺失的信息。
   - 定义了一个 `execute` 函数，模拟获取天气数据（在本例中，它返回一个随机温度）。这是一个在服务器上运行的异步函数，因此你可以从外部 API 获取真实数据。

现在，你的聊天机器人可以为用户询问的任何位置“获取”天气信息。当模型确定需要使用天气工具时，它将生成一个带有必要输入的工具调用。然后，`execute` 函数将自动运行，工具输出将作为 `tool` 消息添加到 `messages` 中。

尝试询问类似“纽约的天气怎么样？”的问题，看看模型如何使用新工具。

注意到 UI 中的空白响应了吗？这是因为模型没有生成文本响应，而是生成了一个工具调用。你可以通过 `message.parts` 数组中的 `tool-weather` 部分在客户端访问工具调用和随后的工具结果。

<Note>
  工具部分始终命名为 `tool-{toolName}`，其中 `{toolName}` 是你定义工具时使用的键。在这种情况下，由于我们将工具定义为 `weather`，因此部分类型是 `tool-weather`。
</Note>

## 启用多步骤工具调用

你可能已经注意到，虽然工具现在在聊天界面中可见，但模型并没有使用此信息来回答你的原始查询。这是因为一旦模型生成了工具调用，它在技术上就完成了生成。

为了解决这个问题，你可以使用 `stopWhen` 启用多步骤工具调用。默认情况下，`stopWhen` 设置为 `isStepCount(1)`，这意味着当有工具结果时，生成会在第一步后停止。通过更改此条件，你可以允许模型自动将工具结果发送回自身，以触发额外的生成，直到满足你指定的停止条件。在这种情况下，你希望模型继续生成，以便它可以使用天气工具结果来回答你的原始问题。

### 更新你的 API 路由

修改你的 `src/routes/api/chat/+server.ts` 文件以包含 `stopWhen` 条件：

```ts filename="src/routes/api/chat/+server.ts" highlight="25"
import {
  createGateway,
  streamText,
  type UIMessage,
  convertToModelMessages,
  tool,
  isStepCount,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
import { z } from 'zod';

import { AI_GATEWAY_API_KEY } from '$env/static/private';

const gateway = createGateway({
  apiKey: AI_GATEWAY_API_KEY,
});

export async function POST({ request }) {
  const { messages }: { messages: UIMessage[] } = await request.json();

  const result = streamText({
    model: gateway('anthropic/claude-sonnet-4.5'),
    messages: await convertToModelMessages(messages),
    stopWhen: isStepCount(5),
    tools: {
      weather: tool({
        description: '获取某个位置的天气（华氏度）',
        inputSchema: z.object({
          location: z.string().describe('要获取天气的位置'),
        }),
        execute: async ({ location }) => {
          const temperature = Math.round(Math.random() * (90 - 32) + 32);
          return {
            location,
            temperature,
          };
        },
      }),
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

回到浏览器，询问某个位置的天气。你现在应该看到模型使用天气工具结果来回答你的问题。

通过设置 `stopWhen: isStepCount(5)`，你允许模型在任何给定的生成中使用最多 5 个“步骤”。这可以实现更复杂的交互，并允许模型在需要时通过多个步骤收集和处理信息。你可以通过添加另一个工具将温度从华氏度转换为摄氏度来看到这一点。

### 添加另一个工具

更新你的 `src/routes/api/chat/+server.ts` 文件，添加一个新工具，将温度从华氏度转换为摄氏度：

```tsx filename="src/routes/api/chat/+server.ts" highlight="40-53"
import {
  createGateway,
  streamText,
  type UIMessage,
  convertToModelMessages,
  tool,
  isStepCount,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
import { z } from 'zod';

import { AI_GATEWAY_API_KEY } from '$env/static/private';

const gateway = createGateway({
  apiKey: AI_GATEWAY_API_KEY,
});

export async function POST({ request }) {
  const { messages }: { messages: UIMessage[] } = await request.json();

  const result = streamText({
    model: gateway('anthropic/claude-sonnet-4.5'),
    messages: await convertToModelMessages(messages),
    stopWhen: isStepCount(5),
    tools: {
      weather: tool({
        description: '获取某个位置的天气（华氏度）',
        inputSchema: z.object({
          location: z.string().describe('要获取天气的位置'),
        }),
        execute: async ({ location }) => {
          const temperature = Math.round(Math.random() * (90 - 32) + 32);
          return {
            location,
            temperature,
          };
        },
      }),
      convertFahrenheitToCelsius: tool({
        description: '将华氏度温度转换为摄氏度',
        inputSchema: z.object({
          temperature: z
            .number()
            .describe('要转换的华氏度温度'),
        }),
        execute: async ({ temperature }) => {
          const celsius = Math.round((temperature - 32) * (5 / 9));
          return {
            celsius,
          };
        },
      }),
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

现在，当你询问“纽约的天气是多少摄氏度？”时，你应该会看到一个更完整的交互：

3. 然后它将调用温度转换工具，将温度从华氏度转换为摄氏度。
4. 模型将使用该信息提供关于纽约天气的自然语言响应。

这种多步骤方法允许模型收集信息并使用它来提供更准确和上下文相关的响应，使你的聊天机器人更加有用。

这个简单的例子演示了工具如何扩展模型的能力。你可以创建更复杂的工具来与真实的 API、数据库或任何其他外部系统集成，允许模型实时访问和处理真实世界的数据。工具弥合了模型知识截止日期和当前信息之间的差距。

## `@ai-sdk/svelte` 与 `@ai-sdk/react` 有何不同？

表面上的区别是 Svelte 使用类来管理状态，而 React 使用 Hook，因此 React 中的 `useChat` 在 Svelte 中是 `Chat`。除此之外，还有几点需要注意：

### 1. 类的参数默认不是响应式的

与 React 中 Hook 在其包含组件失效时重新运行不同，Svelte 组件 `script` 块中的代码仅在组件创建时运行一次。
这意味着，如果你希望类的参数是响应式的，你需要确保向类传递一个*引用*，而不是一个值：

```svelte
<script>
  import { Chat } from '@ai-sdk/svelte';

  let { id } = $props();

  // 不起作用；类实例将创建一次，`id` 将通过值复制，并且当 $props.id 更改时不会更新
  let chat = new Chat({ id });

  // 起作用；通过引用传递 `id`，因此 `Chat` 始终拥有最新的值
  let chat = new Chat({
    get id() {
      return id;
    },
  });
</script>
```

请记住，这通常无关紧要；你传递给 `Chat` 类的大多数参数都是静态的（例如，你通常不会期望你的 `onError` 处理程序会改变）。

### 2. 你不能解构类属性

在普通的 JavaScript 中，解构类属性会按值复制它们，并使它们与其类实例“断开连接”：

```js
const classInstance = new Whatever();
classInstance.foo = 'bar';
const { foo } = classInstance;
classInstance.foo = 'baz';

console.log(foo); // 'bar'
```

在 Svelte 中，类也是如此：

```svelte
<script>
  import { Chat } from '@ai-sdk/svelte';

  const chat = new Chat({});
  let { messages } = chat;

  chat.sendMessage({ text: 'Hello, world!' }).then(() => {
    console.log(messages); // []
    console.log(chat.messages); // [{ id: '...', role: 'user', parts: [{ type: 'text', text: 'Hello, world!' }] }]
  });
</script>
```

### 3. 实例同步需要上下文

在 React 中，具有相同 `id` 的 Hook 实例是同步的——因此，如果两个 `useChat` 实例具有相同的 `id`，它们将具有相同的 `messages`、`status` 等。
对于大多数用例，你可能不需要这种行为——但如果你需要，你可以在根布局文件中使用 `createAIContext` 创建一个上下文：

```svelte
<script>
  import { createAIContext } from '@ai-sdk/svelte';

  let { children } = $props();

  createAIContext();
  // 在此之后创建的所有 Hook，或作为此组件子组件的组件中的 Hook
  // 将具有同步状态
</script>

{@render children()}
```
