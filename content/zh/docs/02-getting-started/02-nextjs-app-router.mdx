# Next.js App Router 快速入门

AI SDK 是一个强大的 TypeScript 库，旨在帮助开发者构建 AI 驱动的应用程序。

在本快速入门教程中，你将构建一个带有流式聊天用户界面的简单智能体。在此过程中，你将学习在自己的项目中使用 AI SDK 所必需的关键概念和技术。

如果你不熟悉[提示词工程](/docs/advanced/prompt-engineering)和 [HTTP 流式传输](/docs/foundations/streaming)的概念，可以选择先阅读这些文档。

## 前提条件

要遵循本快速入门指南，你需要：

- 本地开发机器上安装 Node.js 22+ 和 pnpm。
- 一个 [Vercel AI Gateway](https://vercel.com/ai-gateway) API 密钥。

如果你尚未获得 Vercel AI Gateway API 密钥，可以通过在 Vercel 网站上[注册](https://vercel.com/d?to=%2F%5Bteam%5D%2F%7E%2Fai&title=Go+to+AI+Gateway)来获取。

## 创建一个路由处理程序

创建一个路由处理程序 `app/api/chat/route.ts` 并添加以下代码：

```tsx filename="app/api/chat/route.ts"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

让我们看看这段代码中发生了什么：

1. 定义一个异步的 `POST` 请求处理程序，并从请求体中提取 `messages`。`messages` 变量包含你和聊天机器人之间的对话历史，为聊天机器人提供进行下一次生成所需的上下文。`messages` 是 `UIMessage` 类型，专为在应用程序 UI 中使用而设计——它们包含完整的消息历史以及相关元数据，如时间戳。
2. 调用从 `ai` 包导入的 [`streamText`](/docs/reference/ai-sdk-core/stream-text) 函数。此函数接受一个配置对象，其中包含 `model` 提供商和 `messages`（在步骤 1 中定义）。你可以传递额外的[设置](/docs/ai-sdk-core/settings)来进一步自定义模型的行为。`messages` 键需要一个 `ModelMessage[]` 数组。此类型与 `UIMessage` 不同，因为它不包含元数据，例如时间戳或发送者信息。为了在这些类型之间进行转换，我们使用 `convertToModelMessages` 函数，该函数会剥离 UI 特定的元数据，并将 `UIMessage[]` 数组转换为模型期望的 `ModelMessage[]` 格式。
3. `streamText` 函数返回一个 [`StreamTextResult`](/docs/reference/ai-sdk-core/stream-text#result-object)。将其 `stream` 传递给 `toUIMessageStream`，并使用 `createUIMessageStreamResponse` 返回它，以创建一个流式响应对象。
4. 最后，将结果返回给客户端以流式传输响应。

此路由处理程序在 `/api/chat` 创建了一个 POST 请求端点。

## 连接 UI

现在你已经有了一个可以查询 LLM 的路由处理程序，是时候设置你的前端了。AI SDK 的 [UI](/docs/ai-sdk-ui) 包将聊天界面的复杂性抽象为一个 Hook [`useChat`](/docs/reference/ai-sdk-ui/use-chat)。

使用以下代码更新你的根页面（`app/page.tsx`），以显示聊天消息列表并提供用户消息输入：

```tsx filename="app/page.tsx"
'use client';

import { useChat } from '@ai-sdk/react';
import { useState } from 'react';

export default function Chat() {
  const [input, setInput] = useState('');
  const { messages, sendMessage } = useChat();
  return (
    <div className="flex flex-col w-full max-w-md py-24 mx-auto stretch">
      {messages.map(message => (
        <div key={message.id} className="whitespace-pre-wrap">
          {message.role === 'user' ? 'User: ' : 'AI: '}
          {message.parts.map((part, i) => {
            switch (part.type) {
              case 'text':
                return <div key={`${message.id}-${i}`}>{part.text}</div>;
            }
          })}
        </div>
      ))}

      <form
        onSubmit={e => {
          e.preventDefault();
          sendMessage({ text: input });
          setInput('');
        }}
      >
        <input
          className="fixed dark:bg-zinc-900 bottom-0 w-full max-w-md p-2 mb-8 border border-zinc-300 dark:border-zinc-800 rounded shadow-xl"
          value={input}
          placeholder="说点什么..."
          onChange={e => setInput(e.currentTarget.value)}
        />
      </form>
    </div>
  );
}
```

<Note>
  确保在文件顶部添加 `"use client"` 指令。这允许你通过 JavaScript 添加交互性。
</Note>

此页面使用了 `useChat` Hook，默认情况下，它将使用你之前创建的 `POST` API 路由（`/api/chat`）。该 Hook 提供了用于处理用户输入和表单提交的函数和状态。`useChat` Hook 提供了多个实用函数和状态变量：

- `messages` - 当前的聊天消息（一个对象数组，包含 `id`、`role` 和 `parts` 属性）。
- `sendMessage` - 一个向聊天 API 发送消息的函数。

该组件使用本地状态（`useState`）来管理输入字段的值，并通过调用 `sendMessage` 并传入输入文本，然后清除输入字段来处理表单提交。

LLM 的响应通过消息的 `parts` 数组访问。每条消息包含一个有序的 `parts` 数组，表示模型在其响应中生成的所有内容。这些部分可以包括纯文本、推理令牌等，你将在后面看到。`parts` 数组保留了模型输出的顺序，允许你按生成顺序显示或处理每个组件。

## 使用工具增强你的聊天机器人

虽然大型语言模型（LLM）具有令人难以置信的生成能力，但它们在离散任务（例如数学）和与外部世界交互（例如获取天气）方面存在困难。这就是[工具](/docs/ai-sdk-core/tools-and-tool-calling)发挥作用的地方。

工具是 LLM 可以调用的操作。这些操作的结果可以报告回 LLM，以便在下一个响应中考虑。

例如，如果用户询问当前天气，没有工具，模型只能根据其训练数据提供一般信息。但是有了天气工具，它可以获取并提供最新的、特定于位置的天气信息。

让我们通过添加一个简单的天气工具来增强你的聊天机器人。

### 更新你的路由处理程序

修改你的 `app/api/chat/route.ts` 文件以包含新的天气工具：

```tsx filename="app/api/chat/route.ts" highlight="1-8,18-32"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  tool,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
    tools: {
      weather: tool({
        description: '获取某个位置的天气（华氏度）',
        inputSchema: z.object({
          location: z.string().describe('要获取天气的位置'),
        }),
        execute: async ({ location }) => {
          const temperature = Math.round(Math.random() * (90 - 32) + 32);
          return {
            location,
            temperature,
          };
        },
      }),
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

在此更新后的代码中：

1. 你从 `ai` 包中导入 `tool` 函数，并从 `zod` 中导入 `z` 以进行模式验证。
2. 你定义了一个包含 `weather` 工具的 `tools` 对象。此工具：
   - 有一个描述，帮助模型理解何时使用它。
   - 使用 Zod 模式定义 `inputSchema`，指定执行此工具需要一个 `location` 字符串。模型将尝试从对话上下文中提取此输入。如果无法提取，它将询问用户缺失的信息。
   - 定义一个 `execute` 函数，模拟获取天气数据（在本例中，它返回一个随机温度）。这是一个在服务器上运行的异步函数，因此你可以从外部 API 获取真实数据。

现在，你的聊天机器人可以“获取”用户询问的任何位置的天气信息。当模型确定需要使用天气工具时，它将生成一个带有必要输入的工具调用。然后，`execute` 函数将自动运行，工具输出将作为 `tool` 消息添加到 `messages` 中。

尝试询问类似“纽约的天气怎么样？”这样的问题，看看模型如何使用新工具。

注意到 UI 中的空白响应了吗？这是因为模型没有生成文本响应，而是生成了一个工具调用。你可以通过 `message.parts` 数组中的 `tool-weather` 部分在客户端访问工具调用和随后的工具结果。

<Note>
  工具部分始终命名为 `tool-{toolName}`，其中 `{toolName}` 是你在定义工具时使用的键。在这种情况下，由于我们将工具定义为 `weather`，因此部分类型是 `tool-weather`。
</Note>

## 启用多步骤工具调用

你可能已经注意到，虽然工具现在在聊天界面中可见，但模型并未使用此信息来回答你的原始查询。这是因为一旦模型生成了工具调用，它在技术上就完成了生成。

为了解决这个问题，你可以使用 `stopWhen` 启用多步骤工具调用。默认情况下，`stopWhen` 设置为 `isStepCount(1)`，这意味着在有工具结果时，生成会在第一步后停止。通过更改此条件，你可以允许模型自动将工具结果发送回自身，以触发额外的生成，直到满足你指定的停止条件。在这种情况下，你希望模型继续生成，以便它可以使用天气工具结果来回答你的原始问题。

### 更新你的路由处理程序

修改你的 `app/api/chat/route.ts` 文件以包含 `stopWhen` 条件：

```tsx filename="app/api/chat/route.ts" highlight="19"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  tool,
  isStepCount,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
    stopWhen: isStepCount(5),
    tools: {
      weather: tool({
        description: '获取某个位置的天气（华氏度）',
        inputSchema: z.object({
          location: z.string().describe('要获取天气的位置'),
        }),
        execute: async ({ location }) => {
          const temperature = Math.round(Math.random() * (90 - 32) + 32);
          return {
            location,
            temperature,
          };
        },
      }),
    },
    onStepEnd: ({ toolResults }) => {
      console.log(toolResults);
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

在此更新后的代码中：

1. 你将 `stopWhen` 设置为 `isStepCount(5)`，允许模型在任意一次生成中使用最多 5 个“步骤”。
2. 你添加了一个 `onStepEnd` 回调，用于记录交互中每个步骤的任何 `toolResults`，帮助你了解模型的工具使用情况。

返回浏览器并询问某个位置的天气。你现在应该会看到模型使用天气工具结果来回答你的问题。

通过设置 `stopWhen: isStepCount(5)`，你允许模型在任意一次生成中使用最多 5 个“步骤”。这实现了更复杂的交互，并允许模型在需要时通过多个步骤收集和处理信息。你可以通过添加另一个工具将温度从摄氏度转换为华氏度来看到这一点。

### 添加另一个工具

更新你的 `app/api/chat/route.ts` 文件，添加一个新工具，将温度从华氏度转换为摄氏度：

```tsx filename="app/api/chat/route.ts" highlight="33-48"
import {
  streamText,
  UIMessage,
  convertToModelMessages,
  tool,
  isStepCount,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
    stopWhen: isStepCount(5),
    tools: {
      weather: tool({
        description: '获取某个位置的天气（华氏度）',
        inputSchema: z.object({
          location: z.string().describe('要获取天气的位置'),
        }),
        execute: async ({ location }) => {
          const temperature = Math.round(Math.random() * (90 - 32) + 32);
          return {
            location,
            temperature,
          };
        },
      }),
      convertFahrenheitToCelsius: tool({
        description: '将华氏度温度转换为摄氏度',
        inputSchema: z.object({
          temperature: z
            .number()
            .describe('要转换的华氏度温度'),
        }),
        execute: async ({ temperature }) => {
          const celsius = Math.round((temperature - 32) * (5 / 9));
          return {
            celsius,
          };
        },
      }),
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

3. 然后它将调用温度转换工具，将温度从华氏度转换为摄氏度。
4. 模型将使用该信息提供关于纽约天气的自然语言响应。

这种多步骤方法允许模型收集信息并使用它来提供更准确和上下文相关的响应，使你的聊天机器人更加有用。

这个简单的示例演示了工具如何扩展模型的能力。你可以创建更复杂的工具来与真实的 API、数据库或任何其他外部系统集成，允许模型实时访问和处理现实世界的数据。工具弥合了模型知识截止日期和当前信息之间的差距。
