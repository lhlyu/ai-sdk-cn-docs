# 工具

尽管[大型语言模型（LLM）](/docs/foundations/overview#large-language-models)拥有令人惊叹的生成能力，
但它们在处理离散任务（例如数学）以及与外部世界交互（例如获取天气）时仍会遇到困难。

工具是 LLM 可以调用的操作。
这些操作的结果可以反馈给 LLM，以便在下一轮响应中加以考虑。

例如，当你向 LLM 询问“伦敦的天气”，并且有可用的天气工具时，它可以用伦敦作为参数调用一个工具。
该工具随后会获取天气数据并将其返回给 LLM。LLM 随后可以在其响应中使用这些信息。

## 什么是工具？

工具是一个可以被模型调用以执行特定任务的对象。
你可以通过向 `tools` 参数传递一个或多个工具，在 [`generateText`](/docs/reference/ai-sdk-core/generate-text)
和 [`streamText`](/docs/reference/ai-sdk-core/stream-text) 中使用工具。

一个工具由三个属性组成：

- **`description`**：工具的可选描述，可以影响工具被选中的时机。函数工具和动态工具可以使用字符串，也可以使用一个函数，从工具的上下文和实验性沙箱中推导出描述。
- **`inputSchema`**：一个 [Zod schema](/docs/reference/ai-sdk-core/zod-schema) 或 [JSON schema](/docs/reference/ai-sdk-core/json-schema)，用于定义工具运行所需的输入。该 schema 会被 LLM 使用，同时也用于验证 LLM 的工具调用。
- **`execute`**：一个可选的异步函数，会使用工具调用中的参数进行调用。

<Note>
  `streamUI` 使用带有 `generate` 函数的 UI 生成器工具，该函数可以返回
  React 组件。
</Note>

如果 LLM 决定使用某个工具，它将生成一个工具调用。
带有 `execute` 函数的工具会在生成这些调用时自动运行。
工具调用的输出通过工具结果对象返回。

你可以使用 `streamText` 和 `generateText` 的[多步调用](/docs/ai-sdk-core/tools-and-tool-calling#multi-step-calls-using-stopwhen)，
自动将工具结果传回给 LLM。

## 工具的类型

AI SDK 支持四种类型的工具，每种都有不同的权衡：

### 函数工具

函数工具是你完全自行定义的工具，包括描述、输入 schema 以及可选的 execute 函数。它们与提供商无关，让你拥有完全的控制权。

```ts
import { tool } from 'ai';
import { z } from 'zod';

const weatherTool = tool({
  description: 'Get the weather in a location',
  inputSchema: z.object({
    location: z.string().describe('The location to get the weather for'),
  }),
  execute: async ({ location }) => {
    // Your implementation
    return { temperature: 72, conditions: 'sunny' };
  },
});
```

**何时使用**：当你需要完全的控制权、希望具备提供商可移植性，或正在实现特定于应用程序的功能时。

### 动态工具

动态工具是函数式工具，其输入和输出类型在开发时未知。它们适用于从外部来源加载的工具，例如 MCP 服务器、用户定义的函数或数据库。

```ts
import { dynamicTool } from 'ai';
import { z } from 'zod';

const runtimeTool = dynamicTool({
  description: 'Execute a tool loaded at runtime',
  inputSchema: z.object({}),
  execute: async input => {
    // input is typed as unknown
    return runRuntimeTool(input);
  },
});
```

**何时使用**：当工具在运行时被发现或生成，并且在你编写代码时其确切的 TypeScript 输入/输出类型未知时。

### 提供商定义的工具

提供商定义的工具是指由提供商指定工具的 `inputSchema` 和 `description`，但由你提供 `execute` 函数的工具。这些有时被称为“客户端工具”，因为执行发生在你这一侧。

示例包括 Anthropic 的 `bash` 和 `text_editor` 工具。模型经过专门训练，能够有效地使用这些工具，这可以为受支持的任务带来更好的性能。

```ts
import { anthropic } from '@ai-sdk/anthropic';
import { generateText } from 'ai';

const result = await generateText({
  model: anthropic('claude-opus-4-5'),
  tools: {
    bash: anthropic.tools.bash_20250124({
      execute: async ({ command }) => {
        // Your implementation to run the command
        return runCommand(command);
      },
    }),
  },
  prompt: 'List files in the current directory',
});
```

**何时使用**：当提供商提供了一个模型经过训练能够很好使用的工具，并且你希望在该特定任务上获得更好的性能时。

### 提供商执行的工具

提供商执行的工具是完全在提供商服务器上运行的工具。你进行配置，但由提供商处理执行。这些有时被称为“服务器端工具”。

示例包括 OpenAI 的网页搜索和 Anthropic 的代码执行。这些提供了开箱即用的功能，无需你自行搭建基础设施。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-astra'),
  tools: {
    web_search: openai.tools.webSearch(),
  },
  prompt: 'What happened in the news today?',
});
```

**何时使用**：当你想要强大的功能（例如网页搜索或沙箱化代码执行），而又不想自己管理基础设施时。

### 对比

| 方面             | 函数工具           | 动态工具                 | 提供商定义的工具 | 提供商执行的工具 |
| ------------------ | ------------------------ | ----------------------------- | ---------------------- | ----------------------- |
| **执行**      | 你的代码                | 你的代码                     | 你的代码              | 提供商的服务器      |
| **Schema**         | 你定义               | 运行时定义               | 提供商定义       | 提供商定义        |
| **可移植性**    | 适用于任何提供商  | 适用于任何提供商       | 特定于提供商      | 特定于提供商       |
| **模型训练** | 通用工具使用         | 通用工具使用              | 针对该工具优化 | 针对该工具优化  |
| **设置**          | 你实现一切 | 你加载或生成工具 | 你实现 execute  | 仅需配置      |

<Note>
  提供商定义的工具和提供商执行的工具记录在每个提供商的
  页面中。有关示例，请参阅 [Anthropic Provider](/providers/ai-sdk-providers/anthropic) 和
  [OpenAI Provider](/providers/ai-sdk-providers/openai)。
</Note>

## Schema

Schema 用于定义和验证[工具输入](/docs/ai-sdk-core/tools-and-tool-calling)、工具输出以及结构化输出生成。

AI SDK 支持以下 schema：

- [Zod](https://zod.dev/) v3 和 v4，直接使用或通过 [`zodSchema()`](/docs/reference/ai-sdk-core/zod-schema)
- [Valibot](https://valibot.dev/)，通过来自 `@ai-sdk/valibot` 的 [`valibotSchema()`](/docs/reference/ai-sdk-core/valibot-schema)
- [标准 JSON Schema](https://standardschema.dev/json-schema) 兼容的 schema
- 通过 [`jsonSchema()`](/docs/reference/ai-sdk-core/json-schema) 使用原始 JSON schema

<Note>
  你还可以使用 schema 通过 `output` 设置为
  [`generateText`](/docs/reference/ai-sdk-core/generate-text) 和
  [`streamText`](/docs/reference/ai-sdk-core/stream-text) 进行结构化输出生成。
</Note>

## 细化工具输入

不同的 LLM 提供商可能会为相同的工具输入类型生成略有不同的工具输入。例如，一个提供商可能会为可选字段生成 `null`，而另一个提供商则生成空字符串。

当你并不拥有该工具时（例如使用来自第三方包的工具），你可能无法更改工具的 `inputSchema` 以同时接受这两种形态。在这些情况下，你可以使用实验性的 `experimental_refineToolInput` 选项，在解析后的工具输入被执行之前、以及在它出现在输出、生命周期回调和遥测中之前对其进行规范化。

```ts
import { generateText, tool } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: 'openai/gpt-6-luna',
  tools: {
    search: tool({
      inputSchema: z.object({
        query: z.string(),
        category: z.string().nullable(),
      }),
      execute: async ({ query, category }) => {
        return search({ query, category });
      },
    }),
  },
  experimental_refineToolInput: {
    search: input => ({
      ...input,
      category: input.category === '' ? null : input.category,
    }),
  },
  prompt: 'Search for ski jackets with no category.',
});
```

细化函数按工具进行类型化。每个函数接收其工具的类型化输入，并且必须返回具有相同类型形态的输入。

## 工具包

由于工具是 JavaScript 对象，它们可以像任何其他库一样通过 npm 打包和分发。这使得在项目之间以及与社区共享可复用的工具变得很容易。

### 使用现成的工具包

安装工具包并导入你需要的工具：

```bash
pnpm add some-tool-package
```

然后直接将它们传递给 `generateText`、`streamText` 或你的智能体定义：

```ts highlight="2, 8"
import { generateText, isStepCount } from 'ai';
import { searchTool } from 'some-tool-package';

const { text } = await generateText({
  model: 'anthropic/claude-haiku-4.5',
  prompt: 'When was Vercel Ship AI?',
  tools: {
    webSearch: searchTool,
  },
  stopWhen: isStepCount(10),
});
```

### 发布你自己的工具

你可以将自己的工具包发布到 npm 供他人使用。只需从你的包中导出工具对象：

```ts filename="my-tools/index.ts"
import { tool } from 'ai';
import { z } from 'zod';

export const myTool = tool({
  description: 'A helpful tool',
  inputSchema: z.object({
    query: z.string(),
  }),
  execute: async ({ query }) => {
    // your tool logic
    return result;
  },
});
```

然后任何人都可以通过导入来安装和使用你的工具。

要开始使用，你可以使用 [AI SDK Tool Package Template](https://github.com/vercel-labs/ai-sdk-tool-as-package-template)，它提供了一个可直接使用的起点，用于发布你自己的工具。

## 工具集

当你使用工具时，通常需要混合使用特定于应用程序的工具和通用工具。社区创建了各种工具集和资源，帮助你构建和使用工具。

- **[@tavily/ai-sdk](https://www.npmjs.com/package/@tavily/ai-sdk)** - 用于企业级智能体实时探索网页的搜索、提取、爬取和映射工具。
- **[Stripe agent tools](https://docs.stripe.com/agents?framework=vercel)** - 用于与 Stripe 交互的工具。
- **[StackOne ToolSet](https://docs.stackone.com/agents/typescript/frameworks/vercel-ai-sdk)** - 面向数百个[企业 SaaS](https://www.stackone.com/integrations) 平台的智能体集成。
- **[agentic](https://docs.agentic.so/marketplace/ts-sdks/ai-sdk)** - 一个包含 20 多个工具的集合，可连接到外部 API，例如 [Exa](https://exa.ai/) 或 [E2B](https://e2b.dev/)。
- **[Amazon Bedrock AgentCore](https://github.com/aws/bedrock-agentcore-sdk-typescript)** - 完全托管的 AI 智能体服务，包括 [**Browser**](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/built-in-tools.html)（一个快速且安全的基于云的浏览器运行时，使智能体能够与 Web 应用程序交互、填写表单、浏览网站并提取信息）和 [**Code Interpreter**](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/built-in-tools.html)（一个隔离的沙箱环境，供智能体使用 Python、JavaScript 和 TypeScript 执行代码，从而提高准确性并扩展解决复杂端到端任务的能力）。

- **[Composio](https://docs.composio.dev/providers/vercel)** - 250 多个工具，例如 GitHub、Gmail、Salesforce 以及[更多](https://composio.dev/tools)。
- **[JigsawStack](http://www.jigsawstack.com/docs/integration/vercel)** - 30 多个小型自定义微调模型，可用于特定用途。
