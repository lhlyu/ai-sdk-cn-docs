# 工具

虽然[大语言模型 (LLM)](/docs/foundations/overview#large-language-models) 具有强大的生成能力，但它们在处理离散任务（例如数学计算）以及与外部世界交互（例如获取天气信息）方面存在困难。

工具是 LLM 可以调用的操作。这些操作的结果可以报告回 LLM，以便在生成下一个响应时进行参考。

例如，当你向 LLM 询问“伦敦的天气”时，如果有一个可用的天气工具，它可能会以伦敦为参数调用该工具。该工具随后会获取天气数据并将其返回给 LLM。LLM 便可以在其响应中使用这些信息。

## 什么是工具？

工具是一个可以被模型调用来执行特定任务的对象。你可以通过向 `generateText` 和 `streamText` 的 `tools` 参数传递一个或多个工具来使用它们。

一个工具包含三个属性：

- **`description`**：可选的工具描述，可以影响工具被选中的时机。函数工具和动态工具可以使用字符串或从工具上下文和实验性沙箱派生描述的函数。
- **`inputSchema`**：一个 [Zod 模式](/docs/reference/ai-sdk-core/zod-schema) 或 [JSON 模式](/docs/reference/ai-sdk-core/json-schema)，用于定义工具运行所需的输入。该模式被 LLM 消费，也用于验证 LLM 的工具调用。
- **`execute`**：一个可选的异步函数，使用工具调用的参数进行调用。

<Note>
  `streamUI` 使用 UI 生成器工具，这些工具带有一个可以返回 React 组件的 `generate` 函数。
</Note>

如果 LLM 决定使用某个工具，它将生成一个工具调用。当这些调用生成时，带有 `execute` 函数的工具会自动运行。工具调用的输出通过工具结果对象返回。

你可以使用 `streamText` 和 `generateText` 的[多步调用](/docs/ai-sdk-core/tools-and-tool-calling#multi-step-calls-using-stopwhen)功能，自动将工具结果传回给 LLM。

## 工具类型

AI SDK 支持四种类型的工具，每种都有不同的权衡：

### 函数工具

函数工具是完全由你自己定义的工具，包括描述、输入模式和可选的执行函数。它们与提供商无关，让你拥有完全的控制权。

```ts
import { tool } from 'ai';
import { z } from 'zod';

const weatherTool = tool({
  description: '获取某个位置的天气',
  inputSchema: z.object({
    location: z.string().describe('要获取天气的位置'),
  }),
  execute: async ({ location }) => {
    // 你的实现
    return { temperature: 72, conditions: 'sunny' };
  },
});
```

**何时使用**：当你需要完全控制、希望提供商可移植，或实现特定于应用程序的功能时。

### 动态工具

动态工具是函数式工具，其输入和输出类型在开发时未知。它们对于从外部源（例如 MCP 服务器、用户定义函数或数据库）加载的工具非常有用。

```ts
import { dynamicTool } from 'ai';
import { z } from 'zod';

const runtimeTool = dynamicTool({
  description: '执行一个在运行时加载的工具',
  inputSchema: z.object({}),
  execute: async input => {
    // input 的类型为 unknown
    return runRuntimeTool(input);
  },
});
```

**何时使用**：当工具在运行时被发现或生成，并且你在编写代码时不知道其确切的 TypeScript 输入/输出类型时。

### 提供商定义的工具

提供商定义的工具是指提供商指定了工具的 `inputSchema` 和 `description`，但你提供 `execute` 函数的工具。这些有时被称为“客户端工具”，因为执行发生在你这边。

示例包括 Anthropic 的 `bash` 和 `text_editor` 工具。模型经过专门训练，可以有效地使用这些工具，从而在支持的任务上获得更好的性能。

```ts
import { anthropic } from '@ai-sdk/anthropic';
import { generateText } from 'ai';

const result = await generateText({
  model: anthropic('claude-opus-4-5'),
  tools: {
    bash: anthropic.tools.bash_20250124({
      execute: async ({ command }) => {
        // 你的实现来运行命令
        return runCommand(command);
      },
    }),
  },
  prompt: '列出当前目录中的文件',
});
```

**何时使用**：当提供商提供了一个模型经过良好训练的工具，并且你希望在该特定任务上获得更好的性能时。

### 提供商执行的工具

提供商执行的工具是完全在提供商服务器上运行的工具。你配置它们，但提供商处理执行。这些有时被称为“服务器端工具”。

示例包括 OpenAI 的 web 搜索和 Anthropic 的代码执行。它们提供开箱即用的功能，无需你设置基础设施。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-5.2'),
  tools: {
    web_search: openai.tools.webSearch(),
  },
  prompt: '今天新闻里发生了什么？',
});
```

**何时使用**：当你想要强大的功能（如 web 搜索或沙箱代码执行）而无需自己管理基础设施时。

### 比较

| 方面           | 函数工具             | 动态工具                 | 提供商定义的工具 | 提供商执行的工具 |
| -------------- | -------------------- | ------------------------ | ---------------- | ---------------- |
| **执行**       | 你的代码             | 你的代码                 | 你的代码         | 提供商的服务器   |
| **模式**       | 你定义               | 运行时定义               | 提供商定义       | 提供商定义       |
| **可移植性**   | 适用于任何提供商     | 适用于任何提供商         | 特定于提供商     | 特定于提供商     |
| **模型训练**   | 通用工具使用         | 通用工具使用             | 针对工具优化     | 针对工具优化     |
| **设置**       | 你实现所有内容       | 你加载或生成工具         | 你实现 execute   | 仅配置           |

<Note>
  提供商定义和提供商执行的工具记录在每个提供商的页面中。请参阅 [Anthropic 提供商](/providers/ai-sdk-providers/anthropic) 和 [OpenAI 提供商](/providers/ai-sdk-providers/openai) 获取示例。
</Note>

## 模式

模式用于定义和验证[工具输入](/docs/ai-sdk-core/tools-and-tool-calling)、工具输出以及结构化输出生成。

AI SDK 支持以下模式：

- [Zod](https://zod.dev/) v3 和 v4，直接使用或通过 [`zodSchema()`](/docs/reference/ai-sdk-core/zod-schema)
- [Valibot](https://valibot.dev/)，通过 `@ai-sdk/valibot` 的 [`valibotSchema()`](/docs/reference/ai-sdk-core/valibot-schema)
- 兼容[标准 JSON 模式](https://standardschema.dev/json-schema)的模式
- 通过 [`jsonSchema()`](/docs/reference/ai-sdk-core/json-schema) 的原始 JSON 模式

<Note>
  你也可以使用模式通过 `generateText` 和 `streamText` 的 `output` 设置进行结构化输出生成。
</Note>

## 优化工具输入

不同的 LLM 提供商可能为相同的工具输入类型生成略有不同的工具输入。例如，一个提供商可能为可选字段生成 `null`，而另一个提供商生成空字符串。

当你并不拥有该工具时，例如来自第三方包的工具，你可能无法更改工具的 `inputSchema` 来接受两种形状。在这些情况下，你可以使用实验性的 `experimental_refineToolInput` 选项，在解析后的工具输入被执行以及出现在输出、生命周期回调和遥测中之前，对其进行规范化。

```ts
import { generateText, tool } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: 'openai/gpt-5-mini',
  tools: {
    search: tool({
      inputSchema: z.object({
        query: z.string(),
        category: z.string().nullable(),
      }),
      execute: async ({ query, category }) => {
        return search({ query, category });
      },
    }),
  },
  experimental_refineToolInput: {
    search: input => ({
      ...input,
      category: input.category === '' ? null : input.category,
    }),
  },
  prompt: '搜索滑雪夹克，无类别。',
});
```

优化函数是按工具类型化的。每个函数接收其工具的输入，并且必须返回具有相同类型形状的输入。

## 工具包

鉴于工具是 JavaScript 对象，它们可以像任何其他库一样通过 npm 打包和分发。这使得跨项目和社区共享可重用工具变得容易。

### 使用现成的工具包

安装一个工具包并导入你需要的工具：

```bash
pnpm add some-tool-package
```

然后将它们直接传递给 `generateText`、`streamText` 或你的智能体定义：

```ts highlight="2, 8"
import { generateText, isStepCount } from 'ai';
import { searchTool } from 'some-tool-package';

const { text } = await generateText({
  model: 'anthropic/claude-haiku-4.5',
  prompt: 'Vercel Ship AI 是什么时候？',
  tools: {
    webSearch: searchTool,
  },
  stopWhen: isStepCount(10),
});
```

### 发布你自己的工具

你可以将自己的工具包发布到 npm 供他人使用。只需从你的包中导出你的工具对象：

```ts filename="my-tools/index.ts"
import { tool } from 'ai';
import { z } from 'zod';

export const myTool = tool({
  description: '一个有用的工具',
  inputSchema: z.object({
    query: z.string(),
  }),
  execute: async ({ query }) => {
    // 你的工具逻辑
    return result;
  },
});
```

任何人都可以通过导入来安装和使用你的工具。

要开始，你可以使用 [AI SDK 工具包模板](https://github.com/vercel-labs/ai-sdk-tool-as-package-template)，它提供了一个即用型起点来发布你自己的工具。
