# 多步骤界面

多步骤界面是指需要按顺序执行多个独立步骤才能完成特定任务的用户界面。

要理解多步骤界面，关键在于理解两个概念：

- 工具组合
- 应用上下文

**工具组合**是将多个[工具](/docs/ai-sdk-core/tools-and-tool-calling)组合起来创建新工具的过程。这是一个强大的概念，允许你将复杂任务分解为更小、更易管理的步骤。

**应用上下文**指应用在任何给定时间点的状态，包括用户输入、语言模型输出以及其他相关信息。

在设计多步骤界面时，你需要考虑应用中的工具如何组合以形成连贯的用户体验，以及用户逐步操作时应用上下文如何变化。

## 应用上下文

应用上下文可以理解为用户与语言模型之间的对话历史。上下文越丰富，模型生成相关响应所需的信息就越多。

在多步骤界面中，应用上下文变得更加重要。这是因为**用户在一个步骤中的输入可能会影响模型在下一步的输出**。

例如，考虑一个帮助用户记录每日食物摄入的饮食记录应用。语言模型被提供了以下工具：

- `log_meal`：接收食物名称、数量和食用时间等参数来记录一餐。
- `delete_meal`：接收要删除的餐食名称。

当用户记录一餐时，模型会生成确认餐食已记录的响应。

```txt highlight="2"
用户：记录一份鸡肉沙威玛作为午餐。
工具：log_meal("鸡肉沙威玛", "250g", "12:00 PM")
模型：已记录午餐为鸡肉沙威玛。
```

现在当用户决定删除该餐食时，模型应能引用上一步骤来识别要删除的餐食。

```txt highlight="7"
用户：记录一份鸡肉沙威玛作为午餐。
工具：log_meal("鸡肉沙威玛", "250g", "12:00 PM")
模型：已记录午餐为鸡肉沙威玛。
...
...
用户：我今天没吃午餐，能更新我的记录吗？
工具：delete_meal("鸡肉沙威玛")
模型：已从记录中删除鸡肉沙威玛。
```

在此示例中，管理应用上下文对于模型生成正确响应至关重要。模型需要了解之前的操作信息，才能为`delete_meal`工具生成参数。

## 工具组合

工具组合是将多个工具组合起来创建新工具的过程。这涉及定义每个工具的输入和输出，以及它们之间的交互方式。

这些工具如何组合形成多步骤界面的设计，对应用的用户体验和模型生成正确输出的能力都至关重要。

例如，考虑一个帮助用户预订航班的航班预订助手。该助手可以设计为包含以下工具：

- `searchFlights`：根据用户查询搜索航班。
- `lookupFlight`：根据航班号查询特定航班的详细信息。
- `bookFlight`：根据用户选择预订航班。

当用户想要查询特定航线的航班时，会调用`searchFlights`工具。这通常意味着该工具应能接收出发地和目的地等参数。

当用户想要获取特定航班的更多详细信息时，会调用`lookupFlight`工具。这通常意味着该工具应能接收航班号等参数，并返回座位可用性信息。

当用户决定预订航班时，会调用`bookFlight`工具。为了识别要预订的航班，该工具应能接收航班号、旅行日期和乘客详细信息等参数。

因此，用户与模型之间的对话可能如下所示：

```txt highlight="8"
用户：我想预订从纽约到伦敦的航班。
工具：searchFlights("纽约", "伦敦")
模型：以下是纽约到伦敦的可用航班。
用户：我想预订12月12日的BA123航班，我和我妻子一起。
工具：lookupFlight("BA123") -> "4个座位可用"
模型：好的，有座位！请提供乘客姓名。
用户：John Doe 和 Jane Doe。
工具：bookFlight("BA123", "12月12日", ["John Doe", "Jane Doe"])
模型：您的航班已预订！
```

在最后一次工具调用中，`bookFlight`工具未包含乘客详细信息，因为应用上下文中没有这些信息。因此，它要求用户在继续预订前提供乘客详细信息。

如果用户已登录应用，查询乘客信息本可以是模型在调用`bookFlight`工具前调用的另一个工具。这样，模型就不必询问用户乘客详细信息，可以直接进行预订。

```txt highlight="5,6"
用户：我想预订从纽约到伦敦的航班。
工具：searchFlights("纽约", "伦敦")
模型：以下是纽约到伦敦的可用航班。
用户：我想预订12月12日的BA123航班，我和我妻子一起。
工具：lookupContacts() -> ["John Doe", "Jane Doe"]
工具：bookFlight("BA123", "12月12日", ["John Doe", "Jane Doe"])
模型：您的航班已预订！
```

在调用`bookFlight`工具之前调用了`lookupContacts`工具，以确保预订航班时应用上下文中已有乘客详细信息。这样，模型可以减少用户所需的步骤，并利用其调用工具的能力来填充上下文，并利用这些信息完成预订流程。

现在，引入另一个名为`lookupBooking`的工具，它可以通过接收乘客姓名作为参数来显示预订详情。该工具可以与现有工具组合，提供更完整的用户体验。

```txt highlight="2-4"
用户：我妻子即将乘坐的航班状态如何？
工具：lookupContacts() -> ["John Doe", "Jane Doe"]
工具：lookupBooking("Jane Doe") -> "BA123 已确认"
工具：lookupFlight("BA123") -> "BA123航班计划于12月12日起飞。"
模型：您妻子的BA123航班已确认，计划于12月12日起飞。
```

在此示例中，`lookupBooking`工具用于向用户提供其妻子即将乘坐航班的状态。通过将该工具与现有工具组合，模型能够生成包含预订状态和航班起飞日期的响应，而无需用户提供额外信息。

因此，你设计的可组合工具越多，应用就能变得越复杂、越强大。
