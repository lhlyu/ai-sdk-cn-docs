# 安全 URL 获取

许多提供商会在**响应体中返回 URL**——生成的图片、音频或视频供下载，或用于检查任务状态的轮询 URL。AI SDK 会在服务器端获取这些 URL，并将结果返回给你的代码。由于该 URL 来自外部服务，恶意或被入侵的提供商（或任何能够篡改响应的人）都可能将其指向内部地址，例如云元数据端点（`http://169.254.169.254/…`）、私有主机（`http://10.0.0.5/…`）或 `localhost`。

为防止这种情况，SDK 在获取每个响应提供的 URL 之前都会进行验证。此过程在提供商包内自动完成——你无需进行任何配置。

## SDK 防护的内容

当 SDK 获取来自提供商响应的 URL 时，它会：

- **拒绝私有、回环和链路本地目标**——IPv4（`10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16`、CGNAT、组播等）及对应的 IPv6 范围，以及 `localhost` 和 `.local`。非 `http(s)` 协议也会被拒绝。
- **重新验证每次重定向跳转**——通过验证但随后重定向到内部地址的 URL 会被阻止；重定向不会被盲目跟随。
- **在 Node.js 上于连接时验证 DNS**——每个解析出的地址都会被检查，并且套接字会固定到已验证的 DNS 结果，因此 DNS 重绑定无法在验证和连接之间引入不同的地址。
- **剥离有风险的请求头**——代理转发、云元数据和 Cookie 头会在请求前被移除。
- **跨源丢弃凭据**——调用方头（`Authorization`、`Cookie` 以及提供商特定的 API 密钥头）不会发送到与提供商不同源的宿主；跨源重定向会丢弃除用户代理之外的所有这些头。

被阻止的 URL 会以 `DownloadError` 形式呈现。

## 自托管和本地端点

与**你配置的**提供商端点同源的 URL（例如指向自托管或 `localhost` 部署的自定义 `baseURL`）不受这些检查限制——它们的目标正是你告诉 SDK 通信的主机。任何偏离该源的重定向仍会被验证。

## 各运行时中的 DNS 验证

在 Node.js 上，默认的已验证下载获取使用 `node:dns` 和 `undici` 连接器钩子在连接时验证每个解析出的地址。连接器使用这些精确结果，同时封堵了主机名到私有 IP 和 DNS 重绑定两种绕过方式。

如果你注入或全局替换 `fetch`，则需要负责等效的 DNS 验证和连接固定。其他运行时不暴露 Node 的 DNS/套接字钩子，因此这些运行时上的服务器部署应限制网络出口到私有、回环、链路本地和云元数据范围。

## 加固你的部署

如果你的服务器获取提供商提供的 URL，并且你想封堵 DNS 漏洞，请使用以下方法之一（理想情况下两者都使用）：

### 1. 在网络层限制出站流量

拒绝服务器对 `169.254.0.0/16`、RFC-1918 范围和回环地址的网络出口。这是最稳健的控制措施，且独立于应用程序代码。

### 2. 加固注入的 `fetch`

Node.js 默认实现已固定。如果你注入或全局替换 `fetch`，请使用 `undici` 的 `Agent` 作为其后端，其 `connect.lookup` 会验证解析出的 IP，并仅允许套接字连接到安全地址——同时封堵主机名到私有地址和 DNS 重绑定两个窗口：

```ts
import { Agent, fetch as undiciFetch } from 'undici';
import { lookup } from 'node:dns';

// 你自己的检查函数，对私有/回环/链路本地地址返回 true。
declare function isUnsafeAddress(ip: string): boolean;

const safeLookup: typeof lookup = (hostname, options, callback) => {
  lookup(hostname, options as any, (err, address, family) => {
    if (!err && typeof address === 'string' && isUnsafeAddress(address)) {
      callback(new Error(`拒绝连接到 ${address}`), '', 0);
      return;
    }
    (callback as any)(err, address, family);
  });
};

const safeDispatcher = new Agent({ connect: { lookup: safeLookup } });

const safeFetch: typeof fetch = (input, init) =>
  undiciFetch(input, { ...init, dispatcher: safeDispatcher }) as any;
```

```ts
import { createFal } from '@ai-sdk/fal';

const fal = createFal({ fetch: safeFetch });
```

SDK 的 URL 验证和你自定义 fetch 的连接时固定是互补的——请同时保留两者。
