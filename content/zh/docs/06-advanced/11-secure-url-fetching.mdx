# 安全的 URL 获取

许多提供商会在**响应体中返回一个 URL**——一个可下载的生成图像、音频或视频，或者一个用于检查任务状态的轮询 URL。AI SDK 会在服务端获取这些 URL，并将结果返回给你的代码。由于该 URL 来自外部服务，恶意或被攻陷的提供商（或任何能够篡改响应的人）可能会将其指向内部地址，例如云元数据端点（`http://169.254.169.254/…`）、私有主机（`http://10.0.0.5/…`）或 `localhost`。

为防止这种情况，SDK 会在获取之前验证每个由响应提供的 URL。这会在提供商包内部自动进行——你无需配置任何内容。

对于需要认证的任务状态轮询，提供商可以基于配置的 API 端点构造第一个 URL。SDK 信任该配置的来源用于初始请求，但会手动跟随并验证每一个离开该来源的重定向。MiniMax、Kling AI 和 ByteDance 视频轮询使用此受保护路径。

## SDK 防护的内容

当 SDK 获取来自提供商响应的 URL 时，它会：

- **拒绝私有、回环和链路本地目标**——IPv4（`10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16`、CGNAT、多播等）以及等效的 IPv6 范围，还有 `localhost` 和 `.local`。非 `http(s)` 协议也会被拒绝。
- **重新验证每一个重定向跳转**——一个通过验证但随后重定向到内部地址的 URL 会被阻止；重定向绝不会被盲目跟随。
- **在 Node.js 上于连接时验证 DNS**——每个解析出的地址都会被检查，并且套接字会固定到已验证的 DNS 结果，因此 DNS 重绑定无法在验证与连接之间引入不同的地址。
- **剥离有风险的请求头**——代理转发、云元数据和 cookie 头会在请求前被移除。
- **跨来源丢弃凭据**——调用方头（`Authorization`、`Cookie` 以及提供商特定的 API 密钥头）不会被发送到与提供商不同来源的主机；跨来源的重定向会丢弃所有这些头，只保留 user-agent。

被阻止的 URL 会以 `DownloadError` 的形式暴露。

## 自托管和本地端点

与**你配置的**提供商端点同源的 URL（例如指向自托管或 `localhost` 部署的自定义 `baseURL`）不受这些检查约束——它们的目标正是你告诉 SDK 要通信的主机。这也适用于任务状态轮询。任何离开该来源的重定向在发送重定向请求之前仍会被验证。

## 跨运行时的 DNS 验证

在 Node.js 上，默认的已验证下载获取使用 `node:dns` 和一个 `undici` 连接器 Hook，在连接时验证每个解析出的地址。该连接器使用这些确切的结果，从而同时封堵主机名到私有 IP 和 DNS 重绑定的绕过途径。

包装或替换全局 `fetch` 不会禁用此保护：默认的 Node.js 下载传输独立于全局 `fetch`。

Bun、Deno、Cloudflare Workers 和框架边缘运行时使用其平台 fetch，即使它们暴露了 Node 兼容的 `process` 对象。

如果你显式注入自定义 `fetch`，则由它负责等效的 DNS 验证和连接固定。其他运行时不会暴露 Node 的 DNS/套接字 Hook，因此在这些运行时上的服务端部署应将网络出口限制在私有、回环、链路本地和云元数据范围之外。

## 加固你的部署

如果你的服务器获取由提供商提供的 URL，并且你想封堵 DNS 缺口，请使用以下方法之一（最好两者都用）：

### 1. 在网络层限制出站出口

拒绝你的服务器向 `169.254.0.0/16`、RFC-1918 范围以及回环地址的网络出口。这是最稳健的控制手段，且独立于应用代码。

### 2. 加固注入的 `fetch`

Node.js 默认已经固定。如果你显式注入自定义 `fetch`，请用 `undici` 的 `Agent` 支撑它，其 `connect.lookup` 会验证解析出的 IP，并仅允许套接字连接到安全地址——从而同时封堵主机名到私有地址和 DNS 重绑定的窗口：

```ts
import { Agent, fetch as undiciFetch } from 'undici';
import { lookup } from 'node:dns';

// Your own check that returns true for private/loopback/link-local addresses.
declare function isUnsafeAddress(ip: string): boolean;

const safeLookup: typeof lookup = (hostname, options, callback) => {
  lookup(hostname, options as any, (err, address, family) => {
    if (!err && typeof address === 'string' && isUnsafeAddress(address)) {
      callback(new Error(`Refusing to connect to ${address}`), '', 0);
      return;
    }
    (callback as any)(err, address, family);
  });
};

const safeDispatcher = new Agent({ connect: { lookup: safeLookup } });

const safeFetch: typeof fetch = (input, init) =>
  undiciFetch(input, { ...init, dispatcher: safeDispatcher }) as any;
```

```ts
import { createFal } from '@ai-sdk/fal';

const fal = createFal({ fetch: safeFetch });
```

SDK 的 URL 验证和你自定义 fetch 的连接时固定是互补的——两者都要保留。
