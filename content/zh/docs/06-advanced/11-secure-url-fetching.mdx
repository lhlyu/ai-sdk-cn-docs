# 安全 URL 获取

许多提供商会在其响应体中返回一个 **URL** —— 用于下载生成的图像、音频或视频，或用于检查任务状态的轮询 URL。AI SDK 会在服务器端获取这些 URL，并将结果返回给你的代码。由于该 URL 来自外部服务，恶意或被攻破的提供商（或任何能够篡改响应的人）可能会将其指向内部地址，例如云元数据端点（`http://169.254.169.254/…`）、私有主机（`http://10.0.0.5/…`）或 `localhost`。

为防止这种情况，SDK 在获取每个响应提供的 URL 之前会对其进行验证。这会在提供商包内部自动完成 —— 你无需进行任何配置。

## SDK 防范的内容

当 SDK 获取来自提供商响应的 URL 时，它会：

- **拒绝私有、回环和链路本地目标** —— IPv4（`10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16`、CGNAT、组播等）以及等效的 IPv6 范围，外加 `localhost` 和 `.local`。非 `http(s)` 方案也会被拒绝。
- **重新验证每个重定向跳转** —— 一个通过验证但随后重定向到内部地址的 URL 会被阻止；重定向不会被盲目跟随。
- **剥离有风险的请求头** —— 代理转发、云元数据和 cookie 头会在请求前被移除。
- **跨源丢弃凭据** —— 调用方头（`Authorization`、`Cookie` 以及提供商特定的 API 密钥头）不会发送到与提供商不同源的 host；跨源重定向会丢弃除 user-agent 之外的所有头。

被阻止的 URL 会以 `DownloadError` 形式呈现。

## 自托管和本地端点

与你**配置的**提供商端点同源的 URL（例如，指向自托管或 `localhost` 部署的自定义 `baseURL`）不受这些检查的限制 —— 它们的目标正是你告诉 SDK 要通信的 host。任何离开该源的重定向仍会被验证。

## 限制：DNS 解析和 DNS 重绑定

内置防护将 URL **作为字符串**进行检查。它特意**不解析 DNS**，因此在此层有两个攻击不在范围内：

1. **解析为私有 IP 的主机名** —— 一个看似公开但 DNS 记录指向内部地址的字面主机。
2. **DNS 重绑定** —— 一个在验证时解析为公开 IP，但片刻后当套接字实际连接时解析为私有 IP 的主机（检查时间/使用时间窗口）。

### 为何不内置此功能

要堵住这些漏洞，需要在**连接时**解析 DNS 并固定解析后的 IP —— 这需要 Node 独有的能力（`node:dns`、自定义 `undici` 调度器）。SDK 的提供商工具是**跨运行时**的：它们运行在边缘、浏览器以及 Bun/Deno 上，没有 Node 独有的依赖，因此这些 API 在那里不可用。该威胁也特指**服务器端** —— 在边缘和浏览器中，出站 `fetch` 一开始就无法访问主机的内部网络或元数据端点。因此，连接时 IP 固定仅在 Node 服务器上有意义且可用 —— 而这正是你可以自行添加的地方。

## 加固你的部署

如果你的服务器获取提供商提供的 URL，并且你想要堵住 DNS 漏洞，请使用以下方法之一（最好两者都用）：

### 1. 在网络层限制出站流量

拒绝你的服务器网络出站到 `169.254.0.0/16`、RFC-1918 范围和回环地址。这是最稳健的控制措施，且独立于应用程序代码。

### 2. 注入一个加固的 `fetch`

每个提供商都接受自定义的 `fetch`。在 Node 上，使用 `undici` 的 `Agent` 作为其后端，其 `connect.lookup` 会验证解析后的 IP，并仅允许套接字连接到安全地址 —— 从而堵住主机名到私有地址以及 DNS 重绑定窗口：

```ts
import { Agent, fetch as undiciFetch } from 'undici';
import { lookup } from 'node:dns';

// 你自己的检查函数，对私有/回环/链路本地地址返回 true。
declare function isUnsafeAddress(ip: string): boolean;

const safeLookup: typeof lookup = (hostname, options, callback) => {
  lookup(hostname, options as any, (err, address, family) => {
    if (!err && typeof address === 'string' && isUnsafeAddress(address)) {
      callback(new Error(`拒绝连接到 ${address}`), '', 0);
      return;
    }
    (callback as any)(err, address, family);
  });
};

const safeDispatcher = new Agent({ connect: { lookup: safeLookup } });

const safeFetch: typeof fetch = (input, init) =>
  undiciFetch(input, { ...init, dispatcher: safeDispatcher }) as any;
```

```ts
import { createFal } from '@ai-sdk/fal';

const fal = createFal({ fetch: safeFetch });
```

SDK 的内置验证和你自己的连接时 IP 固定是互补的 —— 请同时保留两者。
