# 停止流

取消正在进行的流通常是必要的。
例如，当用户意识到响应不是他们想要的内容时，可能希望停止流。

AI SDK 的不同部分以不同方式支持取消流。

## AI SDK Core

AI SDK 函数有一个 `abortSignal` 参数，可用于取消流。
如果你希望从服务器端向 LLM API 取消流，例如通过转发请求中的 `abortSignal`，就可以使用它。

```tsx highlight="10,11,12-16"
import { createTextStreamResponse, streamText, toTextStream } from 'ai';
__PROVIDER_IMPORT__;

export async function POST(req: Request) {
  const { prompt } = await req.json();

  const result = streamText({
    model: __MODEL__,
    prompt,
    // forward the abort signal:
    abortSignal: req.signal,
    onAbort: ({ steps }) => {
      // Handle cleanup when stream is aborted
      console.log('Stream aborted after', steps.length, 'steps');
      // Persist partial results to database
    },
  });

  return createTextStreamResponse({
    stream: toTextStream({ stream: result.stream }),
  });
}
```

## AI SDK UI

这些 Hook，例如 `useChat` 或 `useCompletion`，提供了一个 `stop` 辅助函数，可用于取消流。
这会中止来自客户端的 HTTP 请求。若还要停止服务器上的模型请求，你的服务器运行时必须将客户端断开连接传播到请求的 `AbortSignal`，并且你的路由必须像上面所示那样将该信号转发给 AI SDK Core 调用。

<Note type="warning">
  流中止功能与流恢复不兼容。如果你在 `useChat` 中使用 `resume: true`，中止功能会破坏恢复机制。请选择中止或恢复功能，但不要同时使用两者。
</Note>

```tsx file="app/page.tsx" highlight="6,11-14"
'use client';

import { useCompletion } from '@ai-sdk/react';

export default function Chat() {
  const { input, completion, stop, status, handleSubmit, handleInputChange } =
    useCompletion();

  return (
    <div>
      {(status === 'submitted' || status === 'streaming') && (
        <button type="button" onClick={() => stop()}>
          Stop
        </button>
      )}
      {completion}
      <form onSubmit={handleSubmit}>
        <input value={input} onChange={handleInputChange} />
      </form>
    </div>
  );
}
```

### Vercel

在 Vercel 上，[请求取消](https://vercel.com/docs/functions/functions-api-reference#cancel-requests)仅在 Node.js 运行时中受支持，并且必须为每个需要它的函数启用。在 `vercel.json` 中为函数配置添加 `supportsCancellation`：

```json filename="vercel.json"
{
  "functions": {
    "app/api/chat/route.ts": {
      "supportsCancellation": true
    }
  }
}
```

启用取消后，调用 `stop()` 会中止客户端请求，Vercel 会中止 `req.signal`，而将 `req.signal` 作为 `abortSignal` 转发会取消模型请求。

<Note type="warning">
  如果没有 `supportsCancellation`，`stop()` 仍会停止客户端流，但服务器端生成可能会继续。
</Note>

## 处理流中止清理

当流被中止时，你可能需要执行清理操作，例如持久化部分结果或清理资源。`onAbort` 回调提供了一种在服务器端处理这些场景的方式。

与在流正常完成时调用的 `onEnd` 不同，`onAbort` 专门在流通过 `AbortSignal` 被中止时调用。这种区别允许你以不同方式处理正常完成和中止的流。

<Note>
  对于 UI 消息流（`toUIMessageStreamResponse`），`onEnd` 回调还会接收一个 `isAborted` 参数，用于指示流是否被中止。这允许你在单个回调中同时处理完成和中止场景。
</Note>

```tsx highlight="8-12"
import { streamText } from 'ai';
__PROVIDER_IMPORT__;

const result = streamText({
  model: __MODEL__,
  prompt: 'Write a long story...',
  abortSignal: controller.signal,
  onAbort: ({ steps }) => {
    // Called when stream is aborted - persist partial results
    await savePartialResults(steps);
    await logAbortEvent(steps.length);
  },
  onEnd: ({ steps, totalUsage }) => {
    // Called when stream completes normally
    await saveFinalResults(steps, totalUsage);
  },
});
```

`onAbort` 回调接收：

- `steps`：中止发生前所有已完成步骤的数组

这对于以下场景特别有用：

- 将部分对话历史持久化到数据库
- 保存部分进度以便稍后继续
- 清理服务器端资源或连接
- 记录中止事件以进行分析

你也可以使用 `abort` 流部分直接在流中处理中止事件：

```tsx highlight="6-9"
for await (const part of result.stream) {
  switch (part.type) {
    case 'text-delta':
      // Handle text delta content
      break;
    case 'abort':
      // Handle abort event directly in stream
      console.log('Stream was aborted');
      break;
    // ... other cases
  }
}
```

## UI 消息流

使用 `toUIMessageStream` 时，你需要以略有不同的方式处理流中止。`onEnd` 回调会接收一个 `isAborted` 参数，并且你应该将 `consumeStream` 传递给 `createUIMessageStreamResponse`，以确保正确处理中止：

```tsx highlight="3,21,24-30,34"
import { openai } from '@ai-sdk/openai';
import {
  consumeStream,
  convertToModelMessages,
  createUIMessageStreamResponse,
  streamText,
  toUIMessageStream,
  UIMessage,
} from 'ai';
__PROVIDER_IMPORT__;

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
    abortSignal: req.signal,
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({
      stream: result.stream,
      onEnd: async ({ isAborted }) => {
        if (isAborted) {
          console.log('Stream was aborted');
          // Handle abort-specific cleanup
        } else {
          console.log('Stream completed normally');
          // Handle normal completion
        }
      },
    }),
    consumeSseStream: consumeStream,
  });
}
```

`consumeStream` 函数对于 UI 消息流中的正确处理中止是必要的。它确保即使在中止时流也会被正确消费，从而防止潜在的内存泄漏或挂起连接。

`onEnd` 回调会区分消费者取消和观察到的中止。当消费者在结果声明之前取消 UI 消息流时，例如在客户端断开连接期间，`isCancelled` 为 `true`，`outcome.status` 保持为 `'unknown'`，而 `isAborted` 保持为 `false`。当流先观察到 `abort` 部分时，`outcome.status` 为 `'aborted'`，`isAborted` 为 `true`，并且 `isCancelled` 不存在。当两种情况都应运行相同的清理逻辑时，请同时检查这两个标志。

## AI SDK RSC

<Note type="warning">
  AI SDK RSC 目前不支持停止流。
</Note>
