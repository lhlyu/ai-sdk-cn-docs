# 生成式用户界面

由于语言模型可以在生成过程中渲染用户界面，因此生成的模型输出被称为生成式用户界面。

在本节中，我们将进一步了解生成式用户界面及其对 AI 应用构建方式的影响。

## 确定性路由与概率性路由

生成式用户界面本质上并非确定性，因为它们依赖于模型的生成输出。由于这些生成过程具有概率性，每个用户查询都可能产生不同的用户界面。

用户期望在使用你的应用时获得可预测的体验，因此非确定性的用户界面乍听起来可能是个糟糕的主意。然而，语言模型可以通过函数调用能力来限制其生成输出，使其限定在特定输出集合内。

当语言模型获得一组函数定义，并被指示根据用户查询执行其中任一函数时，它们会执行以下操作之一：

- 执行与用户查询最相关的函数。
- 如果用户查询超出可用函数集合的范围，则不执行任何函数。

```tsx filename='app/actions.ts'
const sendMessage = (prompt: string) =>
  generateText({
    model: __MODEL__,
    instructions: '你是一个友好的天气助手！',
    prompt,
    tools: {
      getWeather: {
        description: '获取某个位置的天气',
        inputSchema: z.object({
          location: z.string().describe('要获取天气的位置'),
        }),
        execute: async ({ location }: { location: string }) => ({
          location,
          temperature: 72 + Math.floor(Math.random() * 21) - 10,
        }),
      },
    },
  });

sendMessage('旧金山的天气怎么样？'); // 调用 getWeather
sendMessage('纽约的天气怎么样？'); // 调用 getWeather
sendMessage('伦敦有什么活动？'); // 不调用任何函数
```

通过这种方式，可以确保生成结果具有确定性输出，而模型所做的选择仍然是概率性的。

语言模型展现出的这种根据用户查询选择是否执行函数的新兴能力，被认为是模型在模拟"推理"。

因此，语言模型既能推理执行哪个函数，又能同时渲染用户界面，这种组合使你能够构建将语言模型用作路由器的应用。

## 语言模型作为路由器

过去，开发者必须编写路由逻辑，将应用的不同部分连接起来，使用户能够导航并完成特定任务。

在当今的 Web 应用中，大多数路由逻辑以路由形式呈现：

- `/login` 会导航到包含登录表单的页面。
- `/user/john` 会导航到显示 John 个人资料详情的页面。
- `/api/events?limit=5` 会显示事件数据库中最近的五个事件。

虽然路由有助于构建将应用不同部分连接成无缝用户体验的 Web 应用，但随着应用复杂度的增长，管理路由也可能成为负担。

Next.js 通过引入以下功能，降低了使用路由开发的复杂性：

- 基于文件的路由系统
- 动态路由
- API 路由
- 中间件
- 应用路由器等……

随着语言模型在推理能力上的提升，我们相信未来开发者只需编写核心应用特定组件，而模型会根据用户在应用中的状态负责路由这些组件。

借助生成式用户界面，语言模型会根据用户在应用中的状态决定渲染哪个用户界面，让用户能够以对话方式与应用交互，而非浏览一系列预定义路由。

### 按参数路由

对于像这样的路由：

- `/profile/[username]`
- `/search?q=[query]`
- `/media/[id]`

其中包含依赖动态数据的片段，语言模型可以生成正确的参数并渲染用户界面。

例如，在搜索应用中，你可以要求语言模型搜索不同艺术家的作品。语言模型会以艺术家姓名作为参数调用搜索函数，并渲染搜索结果。

### 按顺序路由

对于需要通过导航不同路由来完成一系列步骤的操作，语言模型可以生成正确的路由顺序，以完成用户的请求。

例如，在日历应用中，你可以要求语言模型安排与朋友共度欢乐时光的夜晚。语言模型会理解你的请求，并执行正确的[工具调用](/docs/ai-sdk-core/tools-and-tool-calling)顺序：

1. 查看你的日历
2. 查看你朋友的日历
3. 确定对每个人都最合适的时间
4. 搜索附近的欢乐时光场所
5. 创建活动并向朋友发送邀请
