# `toolSearch()`

创建一个工具，用于搜索当前生成上下文中的延迟工具，默认使用关键词匹配，也可使用自定义搜索回调。可与 `generateText`、`streamText`、`ToolLoopAgent` 或来自 `@ai-sdk/workflow` 的 `WorkflowAgent` 一起使用。`WorkflowAgent` 支持直接工具调用。其他 API 还支持通过 `toolDiscovery: 'conversation'` 配置的代码模式。

```ts
import { toolSearch } from 'ai';

const search = toolSearch();
```

有关直接调用和代码模式的示例，包括代码模式如何保留工具定义缓存，请参阅[工具搜索指南](/docs/ai-sdk-core/tool-search)。

## 选项

传入一个可选的配置对象来控制结果数量上限：

```ts
const search = toolSearch({ maxResults: 10 });
```

`maxResults` 是每次搜索返回和发现的匹配工具的最大数量。默认值为 `5`，且必须是正的安全整数。无效值会在创建搜索工具时抛出 `InvalidArgumentError`。面向模型的描述会反映所配置的上限。

该上限同时适用于默认关键词搜索和自定义搜索回调，且不会改变它们的匹配或排序方式。已发现的工具会在多次搜索之间累积，因此这不是对一次生成过程中加载的工具总数的限制。

传入 `search` 回调，使用你的应用程序的搜索逻辑来选择和排序工具。该回调可以同步或异步返回：

```ts
const search = toolSearch({
  search: ({ query, tools }) => {
    const preferred = /\bgmail\b/i.test(query)
      ? ['gmail_list_messages', 'gmail_get_message']
      : [];
    return preferred.filter(name => tools.some(tool => tool.name === name));
  },
});
```

该回调的签名如下：

```ts
search?: (options: {
  query: string;
  tools: Array<{ name: string; description?: string }>;
}) => string[] | PromiseLike<string[]>;
```

`tools` 包含所有符合条件的延迟工具，是在关键词匹配或排序之前。是否符合条件取决于 `activeTools` 和调用方路由。描述使用当前工具上下文和沙箱解析；不包含 schema。

按排序后的顺序返回工具名称。SDK 会忽略未知或不符合条件的名称，在保留顺序的同时去除重复项，并保留前 `maxResults` 个有效名称（默认五个）。返回的描述来自 SDK 的候选目录。返回空数组表示不发现任何工具。回调错误遵循正常的工具执行错误处理；SDK 不会回退到关键词搜索。

如果没有回调，`toolSearch()` 使用下文描述的默认关键词搜索。

## 模型输入

模型向搜索工具提供以下输入：

```json
{ "query": "weather forecast" }
```

`query` 是必填的非空字符串。默认情况下，搜索是本地且不区分大小写的，会匹配工具名称和描述中的单词。驼峰式名称会被拆分为单词。名称匹配的排名高于描述匹配；分数相同时保留注册顺序。函数描述使用当前工具上下文和沙箱解析。默认搜索不使用嵌入服务或额外的模型调用。自定义回调可以两者都用。

## 输出

```ts
{
  tools: [
    { name: 'getForecast', description: 'Get the weather forecast for a city.' },
  ],
}
```

结果最多包含 `maxResults` 个匹配工具（默认五个），以及它们的名称和可选描述。不包含 schema。没有匹配项时返回 `{ tools: [] }`。
每个返回的匹配项都会被排队等待发现。新发现的工具只能在其定义被提供之后的下一步模型步骤中调用。与搜索处于同一响应中的并行调用无法使用新发现的工具。对于代码模式，请完成当前执行并等待能力更新。

## 发现生命周期

在下一步模型步骤之前，SDK 会通过已配置的调用方使已发现的工具可用：

- **直接调用：** 提供商收到更新后的工具定义。
- **代码模式：** SDK 追加一条包含更新后能力目录的用户消息。提供商可见的代码模式定义保持不变。现有目录保留在对话中；最新目录描述当前可用的完整工具集。

实际的提示词缓存复用取决于提供商。代码模式搜索仍然需要 `toolDiscovery: 'conversation'`；不支持描述发现和提供商调用方。

已发现的工具在本次生成的剩余过程中保持加载，受 `activeTools` 约束。搜索无法发现被 `activeTools` 排除的工具。发现状态在多次生成调用之间相互隔离，包括复用同一智能体或工具实例的调用。

为 `generateText` 和 `streamText` 设置多步骤的 `stopWhen` 条件，以便模型可以搜索、使用已发现的工具并作答。
