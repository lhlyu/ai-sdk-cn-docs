# `createUIMessageStream`

`createUIMessageStream` 函数允许你创建用于 UI 消息的可读流，并具备消息合并、错误处理和完成回调等高级功能。

## 导入

<Snippet text={`import { createUIMessageStream } from "ai"`} prompt={false} />

## 示例

```tsx
const existingMessages: UIMessage[] = [
  /* ... */
];

const stream = createUIMessageStream({
  async execute({ writer }) {
    // 开始一条文本消息
    // 注意：text-start、text-delta 和 text-end 步骤中的 id 必须保持一致
    // 这样系统才能正确识别它们属于同一个文本块
    writer.write({
      type: 'text-start',
      id: 'example-text',
    });

    // 写入消息块
    writer.write({
      type: 'text-delta',
      id: 'example-text',
      delta: 'Hello',
    });

    // 结束文本消息
    writer.write({
      type: 'text-end',
      id: 'example-text',
    });

    // 合并来自 streamText 的另一个流
    const result = streamText({
      model: __MODEL__,
      prompt: '写一首关于 AI 的俳句',
    });

    writer.merge(
      toUIMessageStream({
        stream: result.stream,
        onEnd: ({ outcome }) => {
          // 组合器决定模型流的输出结果也是
          // 聚合流的输出结果。
          writer.setOutcome(outcome);
        },
      }),
    );
  },
  onError: error => `自定义错误：${error.message}`,
  originalMessages: existingMessages,
  onEnd: ({ messages, isContinuation, outcome, responseMessage }) => {
    console.log('流结束，消息为：', messages);
    console.log('流输出结果：', outcome.status);
  },
});
```

`setOutcome` 记录组合器的策略，而不会写入块或关闭流。通过 `setOutcome` 声明的第一个输出结果会被保留，但致命的执行、合并、错误处理或下游处理失败会使最终的 `onEnd` 输出结果为 `failed`。单独的 `error` 块本身不会改变输出结果。当合并多个子流时，请聚合它们的输出结果并仅调用一次 `setOutcome`。

### 返回值

`ReadableStream<UIMessageChunk>`

一个发出 UI 消息块的可读流。该流会自动处理错误传播、多个流的合并，并在所有操作完成时进行适当的清理。
