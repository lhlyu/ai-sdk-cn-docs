# `experimental_useRealtime()`

<Note type="warning">
  `experimental_useRealtime` 是一项实验性功能。
</Note>

创建一个浏览器端的实时会话，用于与实时提供商模型进行双向音频和文本对话。

该 Hook 支持基于令牌的提供商 WebSocket、应用自有的 WebSocket 中继，以及在模型声明支持时可选的 WebRTC。它提供采集和播放控制，以及基于轮次的文本输入和工具输出。基于轮次的对话消息使用 `UIMessage[]`；连续的转录片段保留在 `session` 中。

```tsx
import { openai } from '@ai-sdk/openai';
import { experimental_useRealtime } from '@ai-sdk/react';

const model = openai.experimental_realtime('gpt-realtime');

function Conversation() {
  const realtime = experimental_useRealtime({
    model,
    api: { token: '/api/realtime/setup' },
  });
  return <button onClick={realtime.connect}>Connect</button>;
}
```

对于 AI Gateway，将 `gateway.experimental_realtime(...)` 作为模型传入，并将 `api.token` 指向一个服务端设置端点，该端点调用 `gateway.experimental_realtime.getToken()`。

请保持模型和会话配置在多次渲染之间稳定，可使用模块作用域或 `useMemo`。替换任一对象都会替换该 Hook 的会话。

## 连续对话

对于 OpenAI Live，使用 `openai.experimental_realtime('gpt-live-1')` 和应用自有的 WebSocket 中继。该中继提供服务器凭据并转发提供商的原始文本帧；它必须在接受连接之前对客户端进行身份验证。在生产环境中使用 `wss:`，将提供商凭据保留在服务端，并对中继连接应用你的应用程序的身份验证。

```tsx
import {
  openai,
  type Experimental_OpenAIRealtimeModelLiveOptions,
} from '@ai-sdk/openai';
import { experimental_useRealtime } from '@ai-sdk/react';

const model = openai.experimental_realtime('gpt-live-1');
const sessionConfig = {
  instructions: 'Be a concise, friendly assistant.',
  providerOptions: {
    openai: {
      delegation: { type: 'client' },
    } satisfies Experimental_OpenAIRealtimeModelLiveOptions,
  },
};

function LiveConversation() {
  const realtime = experimental_useRealtime({
    model,
    api: { websocket: 'wss://your-app.example/live' },
    sessionConfig,
  });
  return (
    <>
      <button onClick={realtime.connect}>Connect microphone</button>
      <button onClick={() => realtime.close()}>End conversation</button>
      <p>
        {realtime.status}: {realtime.session?.usage?.seconds} seconds
      </p>
    </>
  );
}
```

当前的连续浏览器运行时支持 JSON/PCM16 WebSocket 中继媒体配置文件。仅凭连续对话语义并不能保证支持所有编解码器或传输方式。拥有自己音频管道的应用程序可以使用底层提供商来支持其他受支持的编解码器。OpenAI 特定的设置位于 `providerOptions.openai` 下，使用 camelCase 字段；提供商会将它们转换为传输名称。

### 应用处理的客户端委托

Live 通过 `session.delegations` 和规范化事件报告客户端委托元数据。应用程序负责所有文本对话、智能体上下文、工具执行和结果验证。SDK 不会为 Live 运行通用智能体执行器，Live 委托也不会调用 `onToolCall`。

使用 `sendEvent` 追加上下文或结果。将 `delegationId` 设置为当前会话中已知的客户端委托，或设置为 `null` 表示会话范围的上下文：

```tsx
await realtime.sendEvent({
  type: 'context-append',
  delegationId: null,
  content: 'The application has confirmed that the appointment is at 3 PM.',
  providerOptions: { openai: { channel: 'commentary' } },
});
```

该示例使用应用程序提供的内容，而非从委托元数据推断的任务参数。OpenAI 的上下文通道为 `commentary`、`thinking` 和 `instructions`；请将 `instructions` 保留给受信任的应用程序指令。发送成功仅确认本地提交，而非提供商接受或可听送达。

### 可选的 WebRTC

对于浏览器直连的 Live 音频，将 `api.websocket` 替换为 `api: { session: '/api/realtime-live' }`。该 Hook 向该应用程序端点发送 JSON `{ sdp, sessionConfig }`，并期望返回 JSON `{ sdp, sessionId }`。在服务端，对应用程序用户进行身份验证，并验证 offer 和允许的设置。

使用通过应用程序会话 cookie 进行身份验证的同源代理。内置的设置请求使用浏览器的默认同源凭据；`api.session` 不接受自定义授权头、自定义 fetch 或跨源凭据选项。因此，仅使用 bearer 令牌或跨源 cookie 的代理需要在其前面放置一个应用自有的同源端点。应答必须包含非空的 `sdp` 和 `sessionId` 字符串（验证时需去除首尾空白），且 JSON 响应正文限制为 1 MiB。

使用服务端持有的提供商密钥交换 SDP：

```ts
const answer = await openai
  .experimental_realtime('gpt-live-1')
  .doCreateWebRTCSession({
    sdp,
    sessionConfig: {
      providerOptions: {
        openai: {
          delegation: { type: 'client' },
          client: {
            dataChannel: {
              allowedClientEvents: ['session.close', 'session.thinking.append'],
              allowedServerEvents: [
                { type: 'session.started' },
                { type: 'session.closed' },
                { type: 'session.usage.updated' },
                { type: 'session.delegation.created' },
                { type: 'session.input_transcript.delta' },
                { type: 'session.output_transcript.delta' },
                { type: 'session.thinking.appended' },
                { type: 'error' },
              ],
            },
          },
        },
      },
    },
  });
// Return Response.json(answer) from the application endpoint.
```

权限由服务端拥有；覆盖浏览器提供的委托和数据通道策略。允许你的 UI 所需的生命周期、字幕、委托、命令确认和错误事件。`examples/ai-e2e-next` 中可运行的 `/realtime-live` 示例添加了协议静音和全部三个上下文通道。

WebRTC 通过 SDP 协商音频，因此请省略固定音频格式和仅限 PCM 的 `maxPlaybackBufferSeconds`。音频以媒体形式传输，而非 JSON 音频命令。`connect({ capture: false })` 在不进行麦克风采集的情况下启动，并保留一个可复用的音频发送器；`resumeAudioCapture()` 可以在之后附加麦克风。麦克风访问需要浏览器权限和安全上下文。自动播放可能需要用户手势，随后调用 `resumePlayback()`。

每次附加仅选择一个实时音频轨道，优先选择已启用且未静音的轨道。`isCapturing` 跟随该发送器轨道，包括静音和结束事件；它绝不会自动切换轨道。调用方拥有的轨道会被分离，但不会被停止或禁用。采集控制会串行化发送器变更；只有在分离成功或对端关闭后才会报告停止。如果分离失败，则关闭对端以停止传输，同时保持借用的轨道不受影响。无论使用哪种传输方式，客户端委托仍由应用程序处理，且 Live 会话更新仍不受支持。

## 生命周期和故障处理

使用 `status === 'connected'` 作为就绪信号；`connect()` 并不承诺等待提供商就绪。运行时的启动错误通过 `onError` 和 `status` 报告；保留了旧有的 resolve-and-report 行为。

`close()` 停止本地采集和提交，然后排空事件，直到提供商确认最终用量或关闭截止时间到期。关闭命令发送失败时，使用较短的已接受事件排空，而不是等待对未发送命令的确认。请读取 `session.finalization`：已完成的 close promise 本身并不确认用量。`disconnect()` 和卸载会立即释放资源。

Hook 控制项在多次渲染和提供商事件之间保持稳定的标识。保留的控制项针对当前**已提交**的会话，包括在模型或端点更改之后。未提交的渲染无法替换活动会话或其回调。仅回调的更新在提交时生效，无需重新连接。

卸载后，`connect`、`close`、`resumeAudioCapture` 和 `resumePlayback` 会以已挂载 Hook 错误拒绝。其他控制项会同步抛出该错误，包括 `sendEvent`，它保留同步验证，并为已接受的提交返回一个 promise。保留的控制项无法重新打开已卸载的会话。

命令拒绝和播放失败是可恢复的，不会将健康的协议连接标记为失败。不可恢复的传输故障和协议队列溢出会停止提交和采集，排空已接受的事件前缀，并进行清理。在继续使用不可靠状态时，事件绝不会被任意丢弃。在替换连接上，不会透明地重放任何命令或具有副作用的工具。

连续 Live WebSocket 会话具有 128 KiB 的出站线帧限制和 128 KiB 的组合缓冲发送预算，包括下一帧和 JSON/base64 编码开销。过大的控制消息会被拒绝，而不会被静默拆分为多个命令。请将 Live 上下文提交保持在此预算内；示例中继的 128 KiB `maxPayload` 与帧限制一致。这些字节上限不适用于保留其 Live 之前无限制字节策略的旧版基于轮次的会话，也不适用于可选的 WebRTC 传输。

连续 WebSocket PCM 播放预算限制了本地延迟和内存。溢出时，过期的排队音频会被丢弃，播放暂停，`onError` 报告可听见的间隙。连接保持存活；`resumePlayback()` 从实时边缘的新音频恢复。字幕和委托工作的完成并不能证明相应的音频已被听到。

## 工具调用

对于诸如 `gpt-realtime` 之类的基于轮次的模型，工具执行由客户端驱动。使用 `onToolCall` 处理工具调用并返回工具输出。在回调更新之间保持模型稳定：

```tsx
const model = openai.experimental_realtime('gpt-realtime');

function WeatherConversation() {
  const realtime = experimental_useRealtime({
    model,
    api: { token: '/api/realtime/setup' },
    onToolCall: async ({ toolCall }) => {
      if (toolCall.toolName === 'getWeather') {
        const response = await fetch('/api/weather', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(toolCall.args),
        });

        return response.json();
      }
    },
  });
  return <button onClick={realtime.connect}>Connect</button>;
}
```

对于需要用户交互的工具，从 `onToolCall` 返回 `undefined`，并在之后调用 `addToolOutput`。

基于轮次的提供商保留其自动继续行为。Live 使用上述应用程序处理的客户端委托流程，而非这些工具回调或轮次控制项。

未完成的命令与保留的最近 ID 历史独立受限。已完成的工作不会施加生命周期命令配额。请使用新的 ID，并在应用程序中保持持久操作去重；有界历史并不承诺会话级的恰好一次执行。

## 采集所有权

SDK 获取的轨道会在本地采集停止或清理时被停止。调用方自有的 Live 轨道会被分离，但不会被停止或禁用。`stopAudioCapture()` 控制本地硬件采集；提供商 `input-audio-mute` 控制远程音频处理，并通过其确认进行跟踪。这些是独立的操作：协议静音不会释放麦克风，恢复本地采集也不会取消提供商输入的静音。使用 `resumeAudioCapture()` 复用调用方提供的流或获取新的 SDK 自有麦克风，而无需重新连接。应用程序仍负责在使用完毕后停止自己的轨道。

`isCapturing` 反映 SDK 采集控制项和所选音频轨道上的事件；它不会持续观察调用方自有的媒体。设置 `track.enabled` 不会发出事件，调用 `track.stop()` 也不会发出 `ended` 事件。在外部更改借用轨道后，调用 `startAudioCapture(stream)` 或 `resumeAudioCapture()` 以刷新采集状态并按需重新附加。如果轨道已被停止，请提供一个带有活动音频轨道的流；已停止的轨道无法重新启动。SDK 不会轮询外部轨道状态。

## 实验性兼容性

本次更新添加了显式中继选项，并将实验性的 `sendEvent` 更改为返回 promise。现有的令牌设置和无参数 `connect` 调用仍然受支持。新的会话状态使用 `session`，而非提供商品牌的 state 对象。通用实时模型的使用者必须在调用可选连接方法之前检查它们。模型接口和事件联合类型是实验性的；详尽的外部 switch 可能需要处理新增的事件。OpenAI 对 Realtime 和 Live 模型都使用 `experimental_realtime`，并为未知或早期访问的 Live 模型 ID 提供特定于提供商的 `{ api: 'live' }` 覆盖。此工厂选项选择提供商 API；Hook 的 `api.websocket` 选项选择应用程序的传输端点。OpenAI Live 启动选项导出为 `Experimental_OpenAIRealtimeModelLiveOptions`。

有关带有服务端支持的应用程序特定工具端点的完整示例，请参阅 [Realtime](/docs/ai-sdk-core/realtime#tool-calling)。
