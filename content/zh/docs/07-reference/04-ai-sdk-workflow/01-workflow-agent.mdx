# `WorkflowAgent`

创建一个持久、可恢复的 AI 智能体，用于在工作流内部使用。`WorkflowAgent` 负责处理智能体循环、跨工作流步骤边界的工具 schema 序列化，以及内置的工具审批流程。

与 `ai` 包中的 [`ToolLoopAgent`](/docs/reference/ai-sdk-core/tool-loop-agent) 不同，`WorkflowAgent` 旨在在进程重启后继续存活、暂停以等待人工审批，并与 Workflow DevKit 的步骤机制集成。

`WorkflowAgent` 支持用于共享智能体状态的 `runtimeContext` 以及用于每个工具上下文的 `toolsContext`。由于这些值可能跨越工作流和步骤边界，请保持它们为可序列化的持久数据。与 `ToolLoopAgent` 不同，不要在上下文中放置函数、类实例、symbol、数据库客户端或 SDK 客户端；请传递标识符或配置，并在步骤函数内部重新创建不可序列化的资源。

```ts
import { WorkflowAgent } from '@ai-sdk/workflow';
import { tool } from 'ai';
import { z } from 'zod';

const agent = new WorkflowAgent({
  model: 'anthropic/claude-sonnet-5.5',
  instructions: 'You are a helpful assistant.',
  tools: {
    weather: tool({
      description: 'Get the weather in a location',
      inputSchema: z.object({
        location: z.string(),
      }),
      execute: async ({ location }) => ({
        location,
        temperature: 72,
      }),
    }),
  },
});

const result = await agent.stream({
  messages: [
    {
      role: 'user',
      content: [{ type: 'text', text: 'What is the weather in NYC?' }],
    },
  ],
});

console.log(result.messages);
```

### 工作流中的 `repairToolCall`

`repairToolCall` 在模型步骤内部运行。当你在工作流中使用它时，
请将回调定义为带有 `'use step'` 指令的函数。你可以在构造函数上设置它，
或将其传递给 `stream()`。

Workflow 会保存对已注册函数的引用，并在模型步骤内部加载其
实现。请保持该函数捕获的任何值可序列化。普通的行内回调在跨越此步骤边界时
会导致序列化错误。

该回调可以是异步的。返回修复后的工具调用，如果无法完成修复则返回 `null`。
有关修复策略，请参阅[工具调用修复](/docs/ai-sdk-core/tools-and-tool-calling#tool-call-repair)。

### 工作流中的 `experimental_transform`

将一个转换工厂或工厂数组传递给 `stream()`。
为每个工厂标记 `'use step'`，以便 Workflow 能在模型
步骤内部加载它。该工厂必须同步返回一个 `TransformStream`。请保持捕获的任何值可序列化。

```ts
import type { LanguageModelV4StreamPart } from '@ai-sdk/provider';
import { WorkflowAgent } from '@ai-sdk/workflow';
import { getWritable } from 'workflow';

function uppercaseText() {
  'use step';

  return new TransformStream<
    LanguageModelV4StreamPart,
    LanguageModelV4StreamPart
  >({
    transform(part, controller) {
      controller.enqueue(
        part.type === 'text-delta'
          ? { ...part, delta: part.delta.toUpperCase() }
          : part,
      );
    },
  });
}

export async function uppercaseWorkflow() {
  'use workflow';

  const agent = new WorkflowAgent({ model: 'openai/gpt-5' });

  return agent.stream({
    messages: [{ role: 'user', content: 'Write a short greeting.' }],
    writable: getWritable(),
    experimental_transform: uppercaseText,
  });
}
```

## Utilities

### `createModelCallToUIChunkTransform(options?)`

创建一个 `TransformStream`，将原始的 `ModelCallStreamPart` 块（由智能体写入 `writable` 流）转换为适合客户端消费的 `UIMessageChunk` 对象。

```ts
import { createModelCallToUIChunkTransform } from '@ai-sdk/workflow';

return createUIMessageStreamResponse({
  stream: run.readable.pipeThrough(createModelCallToUIChunkTransform()),
});
```

当使用 `WorkflowChatTransport` 游标恢复时，从索引 `0` 开始重放原始工作流
流，并将非负的 UI 块索引传递给转换：

```ts
const readable = run
  .getReadable({ startIndex: 0 })
  .pipeThrough(createModelCallToUIChunkTransform({ uiStartIndex: startIndex }));
```

`uiStartIndex` 必须是非负的安全整数。原始模型流块与
UI 消息块并非一一对应，因此不要将 UI 块索引传递给
`getReadable`。负的尾部索引要求持久流已经
存储了 `UIMessageChunk` 对象。

### `toUIMessageChunk()`

将单个 `ModelCallStreamPart` 转换为 `UIMessageChunk`。对于不映射到 UI 块的块，返回 `undefined`。

```ts
import { toUIMessageChunk } from '@ai-sdk/workflow';

const uiChunk = toUIMessageChunk(modelCallPart);
```

## Types

### `ActiveTools`

```ts
type ActiveTools<TTools extends ToolSet> =
  | ReadonlyArray<keyof TTools & string>
  | undefined;
```

将工作流智能体调用限制为列出的工具名称。`undefined` 表示不应用工具限制。

### `InferWorkflowAgentUIMessage`

推断 `WorkflowAgent` 实例的 UI 消息类型。可选地接受第二个类型参数用于自定义消息元数据。

```ts
import { WorkflowAgent, InferWorkflowAgentUIMessage } from '@ai-sdk/workflow';

const agent = new WorkflowAgent({
  model: 'anthropic/claude-sonnet-5.5',
  tools: { weather: weatherTool },
});

type MyAgentUIMessage = InferWorkflowAgentUIMessage<typeof agent>;
```

### `InferWorkflowAgentTools`

推断 `WorkflowAgent` 实例的工具集类型。

```ts
import { WorkflowAgent, InferWorkflowAgentTools } from '@ai-sdk/workflow';

type MyTools = InferWorkflowAgentTools<typeof myAgent>;
```

### 工作流中带持久工具的智能体

```ts filename="workflow/agent-chat.ts"
import { WorkflowAgent, type ModelCallStreamPart } from '@ai-sdk/workflow';
import { convertToModelMessages, tool, type UIMessage } from 'ai';
import { getWritable } from 'workflow';
import { z } from 'zod';

// Tool execute functions marked with 'use step' become durable workflow steps
// with automatic retries and persistence
async function searchFlightsStep(input: {
  origin: string;
  destination: string;
}) {
  'use step';
  const response = await fetch(`https://api.flights.example/search?...`);
  return response.json();
}

export async function chat(messages: UIMessage[]) {
  'use workflow';

  const modelMessages = await convertToModelMessages(messages);

  const agent = new WorkflowAgent({
    model: 'anthropic/claude-sonnet-5.5',
    instructions: 'You are a flight booking assistant.',
    tools: {
      searchFlights: tool({
        description: 'Search for available flights',
        inputSchema: z.object({
          origin: z.string(),
          destination: z.string(),
        }),
        execute: searchFlightsStep,
      }),
    },
  });

  const result = await agent.stream({
    messages: modelMessages,
    writable: getWritable<ModelCallStreamPart>(),
  });

  return { messages: result.messages };
}
```

### 带工具审批的智能体

对于 `WorkflowAgent`，工具审批在工具定义上通过
`needsApproval` 配置。对于 `generateText`、`streamText` 和 `ToolLoopAgent`，请改用
`toolApproval`。

```ts
import { WorkflowAgent } from '@ai-sdk/workflow';
import { tool } from 'ai';
import { z } from 'zod';

const agent = new WorkflowAgent({
  model: 'anthropic/claude-sonnet-5.5',
  experimental_toolApprovalSecret: {
    environmentVariable: 'TOOL_APPROVAL_SECRET',
  },
  tools: {
    bookFlight: tool({
      description: 'Book a flight',
      inputSchema: z.object({
        flightId: z.string(),
        passengerName: z.string(),
      }),
      needsApproval: true, // Pauses the agent until user approves
      execute: bookFlightStep,
    }),
  },
});
```

当配置了 `experimental_toolApprovalSecret` 时，每个审批请求都会
基于其审批 ID、工具调用 ID、工具名称和经过验证的输入进行签名。
签名缺失或无效的重放审批不会执行工具。
签名会保留在持久流和 UI 消息历史中，而
只有环境变量名会跨越工作流边界。签名和
验证步骤会从其本地环境读取原始密钥，不会
将其序列化。流级别的引用会覆盖构造函数的值。
