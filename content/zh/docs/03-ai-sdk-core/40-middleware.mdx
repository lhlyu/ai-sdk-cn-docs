# 语言模型中间件

语言模型中间件是一种通过拦截和修改对语言模型的调用来增强语言模型行为的方式。

它可以用于以与语言模型无关的方式添加护栏、RAG、缓存和日志记录等功能。此类中间件可以独立于其所应用的语言模型进行开发和分发。

## 使用语言模型中间件

你可以使用 `wrapLanguageModel` 函数来使用语言模型中间件。它接收一个语言模型和一个语言模型中间件，并返回一个包含该中间件的新的语言模型。

```ts
import { wrapLanguageModel, streamText } from 'ai';

const wrappedLanguageModel = wrapLanguageModel({
  model: yourModel,
  middleware: yourLanguageModelMiddleware,
});
```

包装后的语言模型可以像任何其他语言模型一样使用，例如在 `streamText` 中：

```ts highlight="2"
const result = streamText({
  model: wrappedLanguageModel,
  prompt: '美国有哪些城市？',
});
```

## 多个中间件

你可以向 `wrapLanguageModel` 函数提供多个中间件。这些中间件将按照提供的顺序依次应用。

```ts
const wrappedLanguageModel = wrapLanguageModel({
  model: yourModel,
  middleware: [firstMiddleware, secondMiddleware],
});

// 应用顺序为：firstMiddleware(secondMiddleware(yourModel))
```

## 内置中间件

AI SDK 附带几个内置中间件，你可以使用它们来配置语言模型：

- `extractReasoningMiddleware`：从生成的文本中提取推理信息，并将其作为结果上的 `reasoning` 属性公开。
- `extractJsonMiddleware`：通过去除 Markdown 代码围栏从文本内容中提取 JSON。当使用 `Output.object()` 且模型将 JSON 响应包裹在代码块中时非常有用。
- `simulateStreamingMiddleware`：使用非流式语言模型的响应模拟流式传输行为。
- `defaultInstructionsMiddleware`：当调用未提供自己的指令时应用默认指令。
- `defaultSettingsMiddleware`：为语言模型应用默认设置。
- `addToolInputExamplesMiddleware`：为不支持 `inputExamples` 属性的提供商将工具输入示例添加到工具描述中。

### 提取推理

某些提供商和模型使用特殊标签（例如 &lt;think&gt; 和 &lt;/think&gt;）在生成的文本中公开推理信息。

`extractReasoningMiddleware` 函数可用于提取此推理信息，并将其作为结果上的 `reasoning` 属性公开。

```ts
import { wrapLanguageModel, extractReasoningMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: extractReasoningMiddleware({ tagName: 'think' }),
});
```

然后你可以在 `generateText` 和 `streamText` 等函数中使用该增强模型。

`extractReasoningMiddleware` 函数还包含一个 `startWithReasoning` 选项。当设置为 `true` 时，推理标签将前置到生成的文本中。这对于响应开头不包含推理标签的模型非常有用。有关更多详细信息，请参阅 [DeepSeek R1 指南](/cookbook/guides/r1#deepseek-r1-middleware)。

### 提取 JSON

某些模型即使在你请求结构化输出时，也会将 JSON 响应包裹在 Markdown 代码围栏中（例如 ` ```json ... ``` `）。

`extractJsonMiddleware` 函数会从响应中去除这些代码围栏，使其与 `Output.object()` 兼容。

```ts
import {
  wrapLanguageModel,
  extractJsonMiddleware,
  Output,
  generateText,
} from 'ai';
import { z } from 'zod';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: extractJsonMiddleware(),
});

const result = await generateText({
  model,
  output: Output.object({
    schema: z.object({
      name: z.string(),
      ingredients: z.array(z.string()),
    }),
  }),
  prompt: '生成一个食谱。',
});
```

你还可以为使用不同格式的模型提供自定义转换函数：

```ts
const model = wrapLanguageModel({
  model: yourModel,
  middleware: extractJsonMiddleware({
    transform: text => text.replace(/^PREFIX/, '').replace(/SUFFIX$/, ''),
  }),
});
```

### 模拟流式传输

`simulateStreamingMiddleware` 函数可用于使用非流式语言模型的响应模拟流式传输行为。当你希望保持一致的流式传输接口，即使使用仅提供完整响应的模型时，这非常有用。

```ts
import { wrapLanguageModel, simulateStreamingMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: simulateStreamingMiddleware(),
});
```

### 默认设置

`defaultSettingsMiddleware` 函数可用于为语言模型应用默认设置。

```ts
import { wrapLanguageModel, defaultSettingsMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: defaultSettingsMiddleware({
    settings: {
      temperature: 0.5,
      maxOutputTokens: 800,
      providerOptions: { openai: { store: false } },
    },
  }),
});
```

### 默认指令

`defaultInstructionsMiddleware` 函数将指令应用于尚未包含系统消息的调用。直接在调用上提供的指令优先于默认指令。

```ts
import { wrapLanguageModel, defaultInstructionsMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: defaultInstructionsMiddleware({
    instructions: '你是一位简洁的技术助手。',
  }),
});
```

`instructions` 选项还接受 `SystemModelMessage` 或 `SystemModelMessage` 对象数组，当你需要在指令上设置提供商选项时。

<Note>
  中间件将规范化提示词中的任何系统消息视为调用级指令，并且不会添加默认指令。仅对可信的消息历史启用 `allowSystemInMessages`，因为该历史中的系统消息可能会覆盖这些默认指令。
</Note>

### 添加工具输入示例

`addToolInputExamplesMiddleware` 函数将工具输入示例添加到工具描述中。这对于不支持工具上 `inputExamples` 属性的提供商非常有用。中间件将示例序列化到工具的描述文本中，以便模型仍然可以从查看示例输入中受益。

```ts
import { wrapLanguageModel, addToolInputExamplesMiddleware } from 'ai';

const model = wrapLanguageModel({
  model: yourModel,
  middleware: addToolInputExamplesMiddleware({
    prefix: '输入示例：',
  }),
});
```

当你使用 `inputExamples` 定义工具时，中间件会将它们追加到工具的描述中：

```ts
import { generateText, tool } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model, // 上面的包装模型
  tools: {
    weather: tool({
      description: '获取某个地点的天气',
      inputSchema: z.object({
        location: z.string(),
      }),
      inputExamples: [
        { input: { location: '旧金山' } },
        { input: { location: '伦敦' } },
      ],
    }),
  },
  prompt: '东京的天气怎么样？',
});
```

工具描述将被转换为：

```
获取某个地点的天气

输入示例：
{"location":"旧金山"}
{"location":"伦敦"}
```

#### 选项

- `prefix`（可选）：在示例之前添加的前缀文本。默认值：`'输入示例：'`。
- `format`（可选）：每个示例的自定义格式化函数。接收示例对象及其索引。默认值：`JSON.stringify(example.input)`。
- `remove`（可选）：是否在将示例添加到描述后从工具中移除 `inputExamples` 属性。默认值：`true`。

```ts
const model = wrapLanguageModel({
  model: yourModel,
  middleware: addToolInputExamplesMiddleware({
    prefix: '输入示例：',
    format: (example, index) =>
      `${index + 1}. ${JSON.stringify(example.input)}`,
    remove: true,
  }),
});
```

## 社区中间件

AI SDK 提供了语言模型中间件规范。社区成员可以开发符合此规范的中间件，使其与 AI SDK 生态系统兼容。

以下是一些你可以探索的社区中间件：

### 自定义工具调用解析器

[自定义工具调用解析器](https://github.com/minpeter/ai-sdk-tool-call-middleware)中间件将工具调用能力扩展到不支持 OpenAI 风格 `tools` 参数的模型。这包括许多缺乏原生函数调用功能的自托管和第三方模型。

<Note>
  在支持原生函数调用的模型上使用此中间件可能会导致意外的性能下降，因此在决定使用之前，请检查你的模型是否支持原生函数调用。
</Note>

此中间件通过将函数模式转换为提示词指令并将模型的响应解析为结构化函数调用来启用函数调用功能。它的工作原理是将 JSON 函数定义转换为模型可以理解的自然语言指令，然后分析生成的文本以提取函数调用尝试。这种方法允许开发人员在不同的模型提供商之间使用相同的函数调用 API，即使使用不原生支持 OpenAI 风格函数调用格式的模型，也能提供一致的函数调用体验，无论底层模型实现如何。

`@ai-sdk-tool/parser` 包提供了三种中间件变体：

- `createToolMiddleware`：用于创建针对特定模型定制的自定义工具调用中间件的灵活函数
- `hermesToolMiddleware`：适用于 Hermes 和 Qwen 格式函数调用的即用型中间件
- `gemmaToolMiddleware`：为 Gemma 3 模型系列函数调用格式预配置的中间件

以下是你如何为不原生支持函数调用的 Gemma 模型启用函数调用：

```ts
import { wrapLanguageModel } from 'ai';
import { gemmaToolMiddleware } from '@ai-sdk-tool/parser';

const model = wrapLanguageModel({
  model: openrouter('google/gemma-3-27b-it'),
  middleware: gemmaToolMiddleware,
});
```

在此[链接](https://github.com/minpeter/ai-sdk-tool-call-middleware/tree/main/examples/core/src)中查找更多示例。

## 实现语言模型中间件

<Note>
  实现语言模型中间件是高级功能，需要对[语言模型规范](https://github.com/vercel/ai/blob/main/packages/provider/src/language-model/v4/language-model-v4.ts)有扎实的理解。
</Note>

你可以实现以下三个函数中的任何一个来修改语言模型的行为：

1. `transformParams`：在参数传递给语言模型之前转换参数，适用于 `doGenerate` 和 `doStream`。
2. `wrapGenerate`：包装[语言模型](https://github.com/vercel/ai/blob/main/packages/provider/src/language-model/v4/language-model-v4.ts)的 `doGenerate` 方法。你可以修改参数、调用语言模型并修改结果。
3. `wrapStream`：包装[语言模型](https://github.com/vercel/ai/blob/main/packages/provider/src/language-model/v4/language-model-v4.ts)的 `doStream` 方法。你可以修改参数、调用语言模型并修改结果。

以下是一些如何实现语言模型中间件的示例：

## 示例

<Note>
  这些示例不适用于生产环境。它们仅用于展示如何使用中间件来增强语言模型的行为。
</Note>

### 日志记录

此示例展示如何记录语言模型调用的参数和生成的文本。

```ts
import type {
  LanguageModelV4Middleware,
  LanguageModelV4StreamPart,
} from '@ai-sdk/provider';

export const yourLogMiddleware: LanguageModelV4Middleware = {
  wrapGenerate: async ({ doGenerate, params }) => {
    console.log('doGenerate called');
    console.log(`params: ${JSON.stringify(params, null, 2)}`);

    const result = await doGenerate();
    const generatedText = result.content
      .filter(part => part.type === 'text')
      .map(part => part.text)
      .join('');

    console.log('doGenerate finished');
    console.log(`generated text: ${generatedText}`);

    return result;
  },

  wrapStream: async ({ doStream, params }) => {
    console.log('doStream called');
    console.log(`params: ${JSON.stringify(params, null, 2)}`);

    const { stream, ...rest } = await doStream();

    let generatedText = '';
    const textBlocks = new Map<string, string>();

    const transformStream = new TransformStream<
      LanguageModelV4StreamPart,
      LanguageModelV4StreamPart
    >({
      transform(chunk, controller) {
        switch (chunk.type) {
          case 'text-start': {
            textBlocks.set(chunk.id, '');
            break;
          }
          case 'text-delta': {
            const existing = textBlocks.get(chunk.id) || '';
            textBlocks.set(chunk.id, existing + chunk.delta);
            generatedText += chunk.delta;
            break;
          }
          case 'text-end': {
            console.log(
              `Text block ${chunk.id} completed:`,
              textBlocks.get(chunk.id),
            );
            break;
          }
        }

        controller.enqueue(chunk);
      },

      flush() {
        console.log('doStream finished');
        console.log(`generated text: ${generatedText}`);
      },
    });

    return {
      stream: stream.pipeThrough(transformStream),
      ...rest,
    };
  },
};
```

### 缓存

此示例展示如何为语言模型调用生成的文本构建一个简单的缓存。

```ts
import type { LanguageModelV4Middleware } from '@ai-sdk/provider';

const cache = new Map<string, any>();

export const yourCacheMiddleware: LanguageModelV4Middleware = {
  wrapGenerate: async ({ doGenerate, params }) => {
    const cacheKey = JSON.stringify(params);

    if (cache.has(cacheKey)) {
      return cache.get(cacheKey);
    }

    const result = await doGenerate();

    cache.set(cacheKey, result);

    return result;
  },

  // 在这里你将实现流式传输的缓存逻辑
};
```

### 检索增强生成（RAG）

此示例展示如何将 RAG 用作中间件。

<Note>
  像 `getLastUserMessageText` 和 `findSources` 这样的辅助函数不属于 AI SDK。它们仅在此示例中用于说明 RAG 的概念。
</Note>

```ts
import type { LanguageModelV4Middleware } from '@ai-sdk/provider';

export const yourRagMiddleware: LanguageModelV4Middleware = {
  transformParams: async ({ params }) => {
    const lastUserMessageText = getLastUserMessageText({
      prompt: params.prompt,
    });

    if (lastUserMessageText == null) {
      return params; // 不使用 RAG（发送未修改的参数）
    }

    const instruction =
      '使用以下信息回答问题：\n' +
      findSources({ text: lastUserMessageText })
        .map(chunk => JSON.stringify(chunk))
        .join('\n');

    return addToLastUserMessage({ params, text: instruction });
  },
};
```

### 护栏

护栏是确保语言模型调用生成的文本安全且适当的一种方式。此示例展示如何将护栏用作中间件。

```ts
import type { LanguageModelV4Middleware } from '@ai-sdk/provider';

export const yourGuardrailMiddleware: LanguageModelV4Middleware = {
  wrapGenerate: async ({ doGenerate }) => {
    const result = await doGenerate();

    // 过滤方法，例如用于 PII 或其他敏感信息：
    const content = result.content.map(part =>
      part.type === 'text'
        ? { ...part, text: part.text.replace(/badword/g, '<REDACTED>') }
        : part,
    );

    return { ...result, content };
  },

  // 在这里你将实现流式传输的护栏逻辑
  // 注意：流式传输护栏难以实现，因为
  // 在流结束之前你不知道流的完整内容。
};
```

## 配置每请求自定义元数据

要在中间件中发送和访问自定义元数据，你可以使用 `providerOptions`。这在构建日志记录中间件时非常有用，因为你希望传递额外的上下文，如用户 ID、时间戳或其他有助于跟踪和调试的上下文数据。

```ts
import { generateText, wrapLanguageModel } from 'ai';
__PROVIDER_IMPORT__;
import type { LanguageModelV4Middleware } from '@ai-sdk/provider';

export const yourLogMiddleware: LanguageModelV4Middleware = {
  wrapGenerate: async ({ doGenerate, params }) => {
    console.log('METADATA', params?.providerMetadata?.yourLogMiddleware);
    const result = await doGenerate();
    return result;
  },
};

const { text } = await generateText({
  model: wrapLanguageModel({
    model: __MODEL__,
    middleware: yourLogMiddleware,
  }),
  prompt: '发明一个新的节日并描述其传统。',
  providerOptions: {
    yourLogMiddleware: {
      hello: 'world',
    },
  },
});

console.log(text);
```
