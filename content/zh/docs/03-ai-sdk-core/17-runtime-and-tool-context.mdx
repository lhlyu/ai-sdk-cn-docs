# 运行时与工具上下文

上下文让你可以在一次生成或智能体循环中传递服务端状态，而无需将该状态放入提示词中。AI SDK 将共享的运行时状态与每个工具的执行状态分离，这样智能体可以跟踪自己的工作，而工具只接收它们所需的值。

将上下文用于租户信息、功能标志、会话数据、请求 ID、API 凭据、访问令牌或其他应影响执行的应用程序状态等值。

## 上下文类型

| 概念                              | 定义位置                                                                        | 读取位置                                                                                        | 用途                                                          |
| --------------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `runtimeContext`                  | `generateText` 或 `streamText` 调用；`ToolLoopAgent` 设置或 `prepareCall`       | `prepareStep`、生命周期回调、步骤结果和遥测                                                     | 共享的生成或智能体状态                                        |
| `toolsContext`                    | `generateText` 或 `streamText` 调用；`ToolLoopAgent` 设置或 `prepareCall`       | `prepareStep`、审批回调、工具上下文解析和工具描述函数                                           | 以工具名称为键的每个工具上下文值的映射                        |
| 工具 `context`                    | 每个工具的 `toolsContext` 条目，由其 `contextSchema` 验证                       | 工具描述函数、工具 `execute`、`needsApproval` 和工具输入生命周期回调                           | 单个工具所需的值                                              |
| `toolContext`                     | 从单个工具的上下文派生                                                        | 工具审批回调和工具执行事件                                                                      | 单个工具上下文的事件/回调名称                                 |
| `telemetry.includeRuntimeContext` | 生成调用或 `ToolLoopAgent` 设置                                                 | 遥测过滤                                                                                        | 要包含在遥测中的顶层 `runtimeContext` 属性                    |
| `telemetry.includeToolsContext`   | 生成调用或 `ToolLoopAgent` 设置                                                 | 遥测过滤                                                                                        | 要包含在遥测中的顶层工具上下文属性                            |

在智能体中，`runtimeContext` 是智能体的共享运行时状态。它流经整个循环，可以在模型调用之间的 `prepareStep` 中读取或更新。工具特定的数据保留在 `toolsContext` 中，每个工具只接收自己经过验证的 `context`。

```txt
generateText / streamText / ToolLoopAgent settings
  -> runtimeContext
       -> prepareStep, lifecycle callbacks, step results
       -> telemetry, filtered by telemetry.includeRuntimeContext
  -> toolsContext
       -> prepareStep
       -> one tool's context / toolContext
            -> execute, approval callbacks, tool events
            -> telemetry, filtered by telemetry.includeToolsContext
```

## 运行时上下文

当你需要整个生成或智能体循环的共享状态时，传入 `runtimeContext`。它不会自动添加到模型提示词中。用它来配置步骤准备、跟踪服务端状态或关联生命周期事件。

```ts
const result = await generateText({
  model: __MODEL__,
  prompt: 'Help the user plan their trip.',
  runtimeContext: {
    tenantId: 'tenant_123',
    plan: 'enterprise',
    requestId: 'req_abc',
  },
  prepareStep: async ({ runtimeContext }) => {
    if (runtimeContext.plan === 'enterprise') {
      return { temperature: 0.2 };
    }

    return {};
  },
});
```

`prepareStep` 可以返回新的 `runtimeContext`。新值会影响当前步骤和所有后续步骤，这使其成为在循环各轮次之间更新智能体状态的合适位置。

## 工具上下文

将 `toolsContext` 用于属于特定工具的值。每个工具通过 `contextSchema` 声明它期望的上下文；匹配的 `toolsContext` 条目会被验证并作为 `context` 传递给工具。

```ts highlight="9-12,25-30"
import { generateText, tool } from 'ai';
import { z } from 'zod';

const weatherTool = tool({
  description: 'Get the weather in a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  contextSchema: z.object({
    weatherApiKey: z.string(),
    defaultUnit: z.enum(['celsius', 'fahrenheit']),
  }),
  execute: async ({ location }, { context }) => {
    return fetchWeather({
      location,
      apiKey: context.weatherApiKey,
      unit: context.defaultUnit,
    });
  },
});

const result = await generateText({
  model: __MODEL__,
  tools: { weather: weatherTool },
  toolsContext: {
    weather: {
      weatherApiKey: process.env.WEATHER_API_KEY!,
      defaultUnit: 'fahrenheit',
    },
  },
  prompt: 'What is the weather in San Francisco?',
});
```

当至少一个工具声明了 `contextSchema` 时，需要上下文的工具就必须提供 `toolsContext`。工具只接收自己的上下文，而不是完整的 `toolsContext` 映射。工具描述函数在每次模型调用前接收相同的类型化 `context`，因此描述可以随当前工具上下文而变化。

将工具上下文视为工具内部不可变。如果你需要在步骤之间更改工具上下文，请在 `prepareStep` 中检查上一步并返回更新后的 `toolsContext`。

对于 `ToolLoopAgent`，在构造函数中设置上下文。对于每次调用都会变化的上下文，使用 `callOptionsSchema` 和 `prepareCall`。参见[配置调用选项](/docs/agents/configuring-call-options)。

## 遥测上下文过滤

上下文通常包含在应用程序内部有用但不应该发送给遥测提供商的值。使用 `telemetry.includeRuntimeContext` 将选定的顶层运行时上下文属性包含在遥测中，使用 `telemetry.includeToolsContext` 按工具包含选定的顶层工具上下文属性。

```ts
import { ToolLoopAgent, tool } from 'ai';
import { z } from 'zod';

const customerLookup = tool({
  description: 'Look up customer account details',
  inputSchema: z.object({
    customerId: z.string(),
  }),
  contextSchema: z.object({
    apiKey: z.string(),
    region: z.string(),
  }),
  execute: async ({ customerId }, { context }) => {
    return lookupCustomer({
      customerId,
      apiKey: context.apiKey,
      region: context.region,
    });
  },
});

const agent = new ToolLoopAgent({
  model: __MODEL__,
  tools: { customerLookup },
  runtimeContext: {
    requestId: 'req_abc',
    tenantId: 'tenant_123',
    userId: 'user_123',
  },
  telemetry: {
    includeRuntimeContext: {
      requestId: true,
    },
    includeToolsContext: {
      customerLookup: {
        region: true,
      },
    },
  },
  toolsContext: {
    customerLookup: {
      apiKey: process.env.CUSTOMER_API_KEY!,
      region: 'us',
    },
  },
});

const result = await agent.generate({
  prompt: 'Check whether customer cust_123 is eligible for priority support.',
});
```

在此示例中，遥测接收到的 `runtimeContext` 仅包含 `requestId`，`customerLookup` 上下文仅包含 `region`。

<Note>
  上下文过滤器仅影响遥测集成，包括 OpenTelemetry 集成。工具执行、生命周期回调和返回结果仍然接收完整的上下文值。
</Note>

上下文遥测过滤是浅层的。对于 `telemetry.includeRuntimeContext`，配置后仅发送标记为 `true` 的顶层属性；如果省略，则不发送任何运行时上下文属性。对于 `telemetry.includeToolsContext`，配置后仅发送标记为 `true` 的顶层工具上下文属性；如果省略，则不发送任何工具上下文属性。

## 上下文可用的位置

| 位置                              | `runtimeContext`                              | `toolsContext`                              | 工具 `context` / `toolContext`                           |
| --------------------------------- | --------------------------------------------- | ------------------------------------------- | -------------------------------------------------------- |
| `prepareStep`                     | 读取和更新                                    | 读取和更新                                  | 不直接可用                                               |
| 工具描述函数                      | 不直接传递                                    | 不直接传递                                  | 读取单个工具经过验证的 `context`                         |
| 工具 `execute`                    | 不直接传递                                    | 不直接传递                                  | 读取单个工具经过验证的 `context`                         |
| 工具审批                          | 在通用和每个工具的回调中读取                  | 在通用回调中读取                            | 在每个工具的回调中作为 `toolContext` 读取                |
| 工具执行事件                      | 不包含                                        | 不包含                                      | 作为 `toolContext` 读取                                  |
| 步骤结果和完成回调                | 读取最终或每步状态                            | 读取最终或每步状态                          | 通过 `toolsContext` 中的每个工具条目可用                 |
| 遥测                              | 由 `telemetry.includeRuntimeContext` 过滤     | 由 `telemetry.includeToolsContext` 过滤     | 由 `telemetry.includeToolsContext` 过滤                  |

## 选择合适的上下文

- 将 `runtimeContext` 用于整个生成或智能体循环共享的状态，例如请求元数据、租户设置、功能标志或智能体进度。
- 将 `toolsContext` 和 `contextSchema` 用于特定工具所需的值，例如 API 密钥、作用域客户端、用户权限或默认工具设置。
- 将提示词消息用于模型应推理或在其回答中提及的信息。
- 使用 `telemetry.includeRuntimeContext` 和 `telemetry.includeToolsContext` 来减少遥测暴露，而不是作为通用的安全边界。
