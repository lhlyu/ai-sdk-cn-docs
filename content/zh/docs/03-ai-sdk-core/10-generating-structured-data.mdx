# 生成结构化数据

虽然文本生成可能很有用，但您的用例很可能需要生成结构化数据。
例如，您可能希望从文本中提取信息、对数据进行分类或生成合成数据。

许多语言模型能够生成结构化数据，通常定义为使用“JSON 模式”或“工具”。
但是，您需要手动提供模式，然后验证生成的数据，因为 LLM 可能会生成不正确或不完整的结构化数据。

AI SDK 标准化了跨模型提供商的结构化对象生成，
使用 [`generateText`](/docs/reference/ai-sdk-core/generate-text)
和 [`streamText`](/docs/reference/ai-sdk-core/stream-text) 上的 `output` 属性。
您可以使用 [Zod 模式](/docs/reference/ai-sdk-core/zod-schema)、[Valibot](/docs/reference/ai-sdk-core/valibot-schema) 或 [JSON 模式](/docs/reference/ai-sdk-core/json-schema) 来指定所需数据的形状，
AI 模型将生成符合该结构的数据。

<Note>
  结构化输出生成是 `generateText` 和 `streamText`
  流程的一部分。这意味着您可以在同一请求中将其与工具调用结合使用。
</Note>

## 生成结构化输出

使用带有 `Output.object()` 的 `generateText` 从提示词生成结构化数据。
该模式还用于验证生成的数据，确保类型安全和正确性。

```ts
import { generateText, Output } from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

const { output } = await generateText({
  model: __MODEL__,
  output: Output.object({
    schema: z.object({
      recipe: z.object({
        name: z.string(),
        ingredients: z.array(
          z.object({ name: z.string(), amount: z.string() }),
        ),
        steps: z.array(z.string()),
      }),
    }),
  }),
  prompt: 'Generate a lasagna recipe.',
});
```

<Note>
  结构化输出生成在 AI SDK 的多轮执行模型中计为一步（每次模型调用或工具执行即为一步）。当与工具结合使用时，请在 `stopWhen` 配置中考虑这一点。
</Note>

### 访问响应头和响应体

有时您需要访问模型提供商的完整响应，
例如访问某些提供商特定的头或正文内容。

您可以使用 `response` 属性访问原始响应头和响应体：

```ts
import { generateText, Output } from 'ai';

const result = await generateText({
  // ...
  output: Output.object({ schema }),
});

console.log(JSON.stringify(result.response.headers, null, 2));
console.log(JSON.stringify(result.response.body, null, 2));
```

## 流式传输结构化输出

考虑到返回结构化数据的额外复杂性，模型响应时间对于您的交互式用例来说可能不可接受。
使用 `streamText` 和 `output`，您可以在生成模型的结构化响应时对其进行流式传输。

```ts
import { streamText, Output } from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

const { partialOutputStream } = streamText({
  model: __MODEL__,
  output: Output.object({
    schema: z.object({
      recipe: z.object({
        name: z.string(),
        ingredients: z.array(
          z.object({ name: z.string(), amount: z.string() }),
        ),
        steps: z.array(z.string()),
      }),
    }),
  }),
  prompt: 'Generate a lasagna recipe.',
});

// use partialOutputStream as an async iterable
for await (const partialObject of partialOutputStream) {
  console.log(partialObject);
}
```

您可以在客户端使用 [`useObject`](/docs/reference/ai-sdk-ui/use-object) Hook 消费结构化输出。

### 流中的错误处理

`streamText` 会立即开始流式传输。当流式传输过程中发生错误时，它们会成为流的一部分，而不是抛出异常（以防止流崩溃）。

要处理错误，请提供 `onError` 回调：

```tsx highlight="6-8"
import { streamText, Output } from 'ai';

const result = streamText({
  // ...
  output: Output.object({ schema }),
  onError({ error }) {
    console.error(error); // log to your error tracking service
  },
});
```

有关使用 `generateText` 的非流式错误处理，请参阅下面的 [错误处理](#错误处理) 部分。

## 输出类型

AI SDK 支持通过 `Output` 对象以多种方式指定生成数据的预期结构。您可以从各种结构化/文本生成和验证策略中进行选择。

### `Output.text()`

使用 `Output.text()` 从模型生成纯文本。此选项不对结果强制执行任何模式：您只需将模型的文本作为字符串接收。这是未指定 `output` 时的默认行为。

```ts
import { generateText, Output } from 'ai';

const { output } = await generateText({
  // ...
  output: Output.text(),
  prompt: 'Tell me a joke.',
});
// output will be a string (the joke)
```

### `Output.object()`

使用 `Output.object({ schema })` 基于模式（例如，Zod 模式）生成结构化对象。输出经过类型验证，以确保返回的结果与模式匹配。

```ts
import { generateText, Output } from 'ai';
import { z } from 'zod';

const { output } = await generateText({
  // ...
  output: Output.object({
    schema: z.object({
      name: z.string(),
      age: z.number().nullable(),
      labels: z.array(z.string()),
    }),
  }),
  prompt: 'Generate information for a test user.',
});
// output will be an object matching the schema above
```

<Note>
  通过 `streamText` 流式传输的部分输出无法根据您提供的模式进行验证，因为不完整的数据可能尚不符合预期的结构。
</Note>

### `Output.array()`

使用 `Output.array({ element })` 指定您期望从模型中获得一个类型化对象数组，其中每个元素应符合一个模式（在 `element` 属性中定义）。

```ts
import { generateText, Output } from 'ai';
import { z } from 'zod';

const { output } = await generateText({
  // ...
  output: Output.array({
    element: z.object({
      location: z.string(),
      temperature: z.number(),
      condition: z.string(),
    }),
  }),
  prompt: 'List the weather for San Francisco and Paris.',
});
// output will be an array of objects like:
// [
//   { location: 'San Francisco', temperature: 70, condition: 'Sunny' },
//   { location: 'Paris', temperature: 65, condition: 'Cloudy' },
// ]
```

使用 `streamText` 流式传输数组时，您可以使用 `elementStream` 在生成每个完整元素时接收它：

```ts
import { streamText, Output } from 'ai';
import { z } from 'zod';

const { elementStream } = streamText({
  // ...
  output: Output.array({
    element: z.object({
      name: z.string(),
      class: z.string(),
      description: z.string(),
    }),
  }),
  prompt: 'Generate 3 hero descriptions for a fantasy role playing game.',
});

for await (const hero of elementStream) {
  console.log(hero); // Each hero is complete and validated
}
```

<Note>
  `elementStream` 发出的每个元素都是完整的，并根据您的元素模式进行了验证。这与 `partialOutputStream` 不同，后者会流式传输整个部分数组，包括不完整的元素。
</Note>

### `Output.choice()`

当您期望模型从一组特定的字符串选项中进行选择时，例如用于分类或固定枚举答案，请使用 `Output.choice({ options })`。

```ts
import { generateText, Output } from 'ai';

const { output } = await generateText({
  // ...
  output: Output.choice({
    options: ['sunny', 'rainy', 'snowy'],
  }),
  prompt: 'Is the weather sunny, rainy, or snowy today?',
});
// output will be one of: 'sunny', 'rainy', or 'snowy'
```

您可以提供任何一组字符串选项，输出将始终是与指定选项之一匹配的单个字符串值。AI SDK 会验证结果是否与您的选项之一匹配，如果模型返回无效内容，则会抛出错误。

这对于生成分类风格的输出或为 API 兼容性强制有效值特别有用。

### `Output.json()`

当您想从模型生成和解析非结构化的 JSON 值，而不强制执行特定模式时，请使用 `Output.json()`。如果您想捕获任意对象、灵活的结构，或者当您想依赖模型的自然输出而不是严格的验证时，这很有用。

```ts
import { generateText, Output } from 'ai';

const { output } = await generateText({
  // ...
  output: Output.json(),
  prompt:
    'For each city, return the current temperature and weather condition as a JSON object.',
});

// output could be any valid JSON, for example:
// {
//   "San Francisco": { "temperature": 70, "condition": "Sunny" },
//   "Paris": { "temperature": 65, "condition": "Cloudy" }
// }
```

使用 `Output.json`，AI SDK 仅检查响应是否为有效的 JSON；它不验证值的结构或类型。如果您需要模式验证，请改用 `.object` 或 `.array` 输出。

有关更高级的验证或不同的结构，请参阅 [Output API 参考](/docs/reference/ai-sdk-core/output)。

## 使用工具生成结构化输出

将结构化输出与 `generateText` 和 `streamText` 结合使用的关键优势之一是能够将其与工具调用相结合。

```ts
import { generateText, Output, tool, isStepCount } from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

const { output } = await generateText({
  model: __MODEL__,
  tools: {
    weather: tool({
      description: 'Get the weather for a location',
      inputSchema: z.object({ location: z.string() }),
      execute: async ({ location }) => {
        // fetch weather data
        return { temperature: 72, condition: 'sunny' };
      },
    }),
  },
  output: Output.object({
    schema: z.object({
      summary: z.string(),
      recommendation: z.string(),
    }),
  }),
  stopWhen: isStepCount(5),
  prompt: 'What should I wear in San Francisco today?',
});
```

<Note>
  将工具与结构化输出结合使用时，请记住生成结构化输出计为一步。配置 `stopWhen` 以允许足够的步骤来完成工具执行和输出生成。
</Note>

## 属性描述

您可以向各个模式属性添加 `.describe("...")`，以向模型提示每个属性的用途。这有助于提高生成的结构化数据的质量和准确性：

```ts highlight="9,16,19-20"
import { generateText, Output } from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

const { output } = await generateText({
  model: __MODEL__,
  output: Output.object({
    schema: z.object({
      name: z.string().describe('The name of the recipe'),
      ingredients: z
        .array(
          z.object({
            name: z.string(),
            amount: z
              .string()
              .describe('The amount of the ingredient (grams or ml)'),
          }),
        )
        .describe('List of ingredients with amounts'),
      steps: z.array(z.string()).describe('Step-by-step cooking instructions'),
    }),
  }),
  prompt: 'Generate a lasagna recipe.',
});
```

属性描述对于以下情况特别有用：

- 澄清模糊的属性名称
- 指定预期的格式或约定
- 为复杂的嵌套结构提供上下文

## 输出名称和描述

您可以选择为输出指定 `name` 和 `description`。某些提供商使用这些信息进行额外的 LLM 指导，例如通过工具或模式名称。

```ts highlight="8-9"
import { generateText, Output } from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

const { output } = await generateText({
  model: __MODEL__,
  output: Output.object({
    name: 'Recipe',
    description: 'A recipe for a dish.',
    schema: z.object({
      name: z.string(),
      ingredients: z.array(z.object({ name: z.string(), amount: z.string() })),
      steps: z.array(z.string()),
    }),
  }),
  prompt: 'Generate a lasagna recipe.',
});
```

这适用于所有支持结构化生成的输出类型：

- `Output.object({ name, description, schema })`
- `Output.array({ name, description, element })`
- `Output.choice({ name, description, options })`
- `Output.json({ name, description })`

## 访问推理过程

您可以通过结果上的 `reasoning` 属性访问语言模型用于生成对象的推理过程。如果可用，此属性包含一个字符串，其中包含模型的思考过程。

```ts
import { generateText, Output } from 'ai';
__PROVIDER_IMPORT__;
import { z } from 'zod';

const result = await generateText({
  model: __MODEL__, // must be a reasoning model
  output: Output.object({
    schema: z.object({
      recipe: z.object({
        name: z.string(),
        ingredients: z.array(
          z.object({
            name: z.string(),
            amount: z.string(),
          }),
        ),
        steps: z.array(z.string()),
      }),
    }),
  }),
  prompt: 'Generate a lasagna recipe.',
});

console.log(result.reasoningText);
```

## 错误处理

`generateText` 可以通过两种方式报告结构化输出失败：

- 如果模型响应无法根据模式进行解析或验证，
  `generateText` 会以
  [`AI_NoObjectGeneratedError`](/docs/reference/ai-sdk-errors/ai-no-object-generated-error) 拒绝。
- 如果 `generateText` 返回的结果没有输出，访问 `result.output`
  会抛出
  [`AI_NoOutputGeneratedError`](/docs/reference/ai-sdk-errors/ai-no-output-generated-error)。
  当最后一步不是以 `stop` 原因结束时，可能会发生这种情况，例如当它以 `tool-calls` 结束时。

`output` 属性是一个 getter，因此解构它也会触发此访问。

`NoObjectGeneratedError` 保留以下信息以帮助您记录问题：

- `text`：模型生成的文本。根据对象生成模式，这可以是原始文本或工具调用文本。
- `response`：关于语言模型响应的元数据，包括响应 ID、时间戳和模型。
- `usage`：请求的令牌使用情况。
- `cause`：错误的原因（例如 JSON 解析错误）。您可以使用它进行更详细的错误处理。

```ts
import {
  generateText,
  NoObjectGeneratedError,
  NoOutputGeneratedError,
  Output,
} from 'ai';

try {
  const result = await generateText({
    model,
    output: Output.object({ schema }),
    prompt,
  });

  console.log(result.output);
} catch (error) {
  if (NoObjectGeneratedError.isInstance(error)) {
    console.log('NoObjectGeneratedError');
    console.log('Cause:', error.cause);
    console.log('Text:', error.text);
    console.log('Response:', error.response);
    console.log('Usage:', error.usage);
  } else if (NoOutputGeneratedError.isInstance(error)) {
    console.log('NoOutputGeneratedError');
  }
}
```
