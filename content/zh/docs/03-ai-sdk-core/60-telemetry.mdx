# 遥测

AI SDK 使用 [OpenTelemetry](https://opentelemetry.io/) 收集遥测数据。
OpenTelemetry 是一个开源可观测性框架，旨在提供标准化的插桩能力，用于收集遥测数据。

查看 [AI SDK 可观测性集成](/providers/observability)，
了解为 AI SDK 应用提供监控和追踪的提供商。

## 启用遥测

### 步骤 1：注册 OpenTelemetry 集成

OpenTelemetry span 收集需要 `@ai-sdk/otel` 包。安装它，并在应用启动时注册一次集成：

```bash
pnpm install @ai-sdk/otel
```

```ts
import { registerTelemetry } from 'ai';
import { OpenTelemetry } from '@ai-sdk/otel';

registerTelemetry(new OpenTelemetry());
```

#### Next.js

对于 Next.js 应用，在项目根目录创建 `instrumentation.ts` 文件，并在设置 OpenTelemetry 提供商的同时注册 AI SDK 遥测集成：

```ts filename="instrumentation.ts"
import { registerOTel } from '@vercel/otel';
import { registerTelemetry } from 'ai';
import { OpenTelemetry } from '@ai-sdk/otel';

export function register() {
  registerOTel({
    serviceName: 'my-ai-app',
  });

  registerTelemetry(new OpenTelemetry());
}
```

有关在 Next.js 中设置 OpenTelemetry 的更多详细信息，请参阅 [Next.js OpenTelemetry 指南](https://nextjs.org/docs/app/building-your-application/optimizing/open-telemetry)。

对于 Node.js 应用（不使用 Next.js），在入口文件的顶层注册集成。

### 步骤 2：启用遥测

一旦注册了遥测集成，受支持的 AI SDK 调用默认会发出遥测事件。
这包括文本和对象生成、嵌入、重排序、语音生成，以及非流式传输和流式传输转写。
你仍然可以传入 `telemetry` 来附加元数据（例如 `functionId`），或选择退出特定调用：

```ts highlight="4-6"
const result = await generateText({
  model: __MODEL__,
  prompt: 'Write a short story about a cat.',
  telemetry: {
    functionId: `story-agent`,
  },
});
```

默认情况下，输入和输出都会被记录。你可以通过将 `recordInputs` 和 `recordOutputs` 选项设置为 `false` 来禁用它们。

出于隐私、数据传输和性能方面的考虑，禁用输入和输出的记录可能很有用。
例如，如果输入包含敏感信息，你可能希望禁用输入记录。

对于 `generateSpeech`，输入遥测包含源文本，输出遥测包含生成的音频字节长度、媒体类型和格式。
对于 `transcribe` 和 `experimental_streamTranscribe`，遥测包含输入音频字节长度和媒体类型，以及输出转写文本。原始音频永远不会包含在遥测事件中。流式传输转写会在音频流被消费且转写完成时报告其最终字节长度。

自定义集成通过 `onStart` 和 `onEnd` 接收稳定的 `generateSpeech` 和 `transcribe` 操作。为了保持实验性 API 的隔离，`experimental_streamTranscribe` 使用 `experimental_onStreamTranscriptionStart` 和 `experimental_onStreamTranscriptionEnd`；所有三个操作都通过 `onError` 报告失败。

包装或委托给另一个集成的集成必须显式转发实验性流式传输转写回调。仅转发稳定的 `onStart` 和 `onEnd` 回调不会观察到 `experimental_streamTranscribe`。

内置的 OpenTelemetry 集成默认记录数值型提供商用量，并保留每个报告的单元。现代集成使用诸如 `gen_ai.usage.characters`、`gen_ai.usage.seconds` 和 `gen_ai.usage.input_tokens` 等属性；`LegacyOpenTelemetry` 使用对应的 `ai.usage.*` 属性。提供商原生用量对象仍然可供回调使用，也可以通过启用 `usage: true` 将其作为补充的 `ai.response.usage` 属性包含在内。

### 选择退出

遥测是选择退出的。要为特定调用禁用遥测，请设置 `isEnabled: false`：

```ts
const result = await generateText({
  model: __MODEL__,
  prompt: 'Write a short story about a cat.',
  telemetry: { isEnabled: false },
});
```

要全局禁用遥测，请不要通过 `registerTelemetry()` 函数注册任何遥测集成。

## 遥测元数据

你可以提供 `functionId` 来标识遥测数据所属的函数，
并提供 `runtimeContext` 来在遥测数据中包含额外信息。
有关更广泛的上下文模型，请参阅
[运行时与工具上下文](/docs/ai-sdk-core/runtime-and-tool-context)。

```ts highlight="4-10"
const result = await generateText({
  model: __MODEL__,
  prompt: 'Write a short story about a cat.',
  runtimeContext: {
    userId: 'user_123',
    requestId: 'req_abc',
  },
  telemetry: {
    functionId: 'my-awesome-function',
  },
});
```

### 运行时上下文遥测包含

`runtimeContext` 可能包含在你的应用内部有用但不应该发送给遥测提供商的值，例如用户标识符、租户 ID 或凭据。使用 `telemetry.includeRuntimeContext` 来标记应包含在遥测中的顶层 `runtimeContext` 属性：

```ts highlight="8-10"
const result = await generateText({
  model: __MODEL__,
  prompt: 'Write a short story about a cat.',
  runtimeContext: {
    userId: 'user_123',
    requestId: 'req_abc',
  },
  telemetry: {
    includeRuntimeContext: {
      requestId: true,
    },
  },
});
```

在此示例中，遥测集成接收到的 `runtimeContext` 为 `{ requestId: 'req_abc' }`。设置为 `false` 或省略的属性会被排除。如果省略 `telemetry.includeRuntimeContext`，则不会包含任何运行时上下文属性。`telemetry.includeRuntimeContext` 受 `generateText`、`streamText`、`ToolLoopAgent`、`embed`、`embedMany`、`rerank` 和 `experimental_evaluate` 支持。

<Note>
  `telemetry.includeRuntimeContext` 仅过滤遥测集成，
  包括 OpenTelemetry 集成。生命周期回调和返回结果
  仍然接收完整的 `runtimeContext`。
</Note>

### 工具上下文

工具特定的上下文也可能包含在执行期间有用但不应该发送给遥测提供商的值，例如 API 密钥或访问令牌。
使用 `telemetry.includeToolsContext` 来在遥测中包含工具的 `context` 中选定的顶层属性：

```ts highlight="16-20,23-28"
const weatherTool = tool({
  inputSchema: z.object({
    location: z.string(),
  }),
  contextSchema: z.object({
    weatherApiKey: z.string(),
    defaultUnit: z.enum(['celsius', 'fahrenheit']),
  }),
  execute: async ({ location }, { context }) =>
    fetchWeather(location, context.weatherApiKey, context.defaultUnit),
});

const result = await generateText({
  model: __MODEL__,
  tools: { weather: weatherTool },
  toolsContext: {
    weather: {
      weatherApiKey: 'weather-123',
      defaultUnit: 'fahrenheit',
    },
  },
  prompt: 'What is the weather in San Francisco?',
  telemetry: {
    includeToolsContext: {
      weather: {
        defaultUnit: true,
      },
    },
  },
});
```

在此示例中，遥测集成接收到的 `toolsContext.weather` 和工具执行遥测事件 `toolContext` 为 `{ defaultUnit: 'fahrenheit' }`。
设置为 `false` 或省略的属性会被排除。如果省略 `telemetry.includeToolsContext`，则不会包含任何工具上下文属性。`telemetry.includeToolsContext` 受 `generateText`、`streamText` 和 `ToolLoopAgent` 支持。

<Note>
  `telemetry.includeToolsContext` 仅过滤遥测集成，包括
  OpenTelemetry 集成。工具执行、生命周期回调和返回
  结果仍然接收完整的工具上下文。有关工具执行上下文与遥测事件上下文之间的区别，请参阅[运行时与工具
  上下文](/docs/ai-sdk-core/runtime-and-tool-context)。
</Note>

## 自定义 Tracer

如果你希望你的 trace 使用 `@opentelemetry/api` 单例提供的 `TracerProvider` 之外的 `TracerProvider`，请向 `OpenTelemetry` 构造函数传入自定义 `Tracer`：

```ts highlight="6-8"
import { registerTelemetry } from 'ai';
import { OpenTelemetry } from '@ai-sdk/otel';

const tracerProvider = new NodeTracerProvider();
registerTelemetry(
  new OpenTelemetry({
    tracer: tracerProvider.getTracer('gen_ai'),
  }),
);
```

## 遥测集成

遥测集成让你可以挂接到生成生命周期，以构建自定义可观测性——日志、分析、DevTools 或任何其他监控系统。你无需在每次调用时逐个连接回调，而是实现一次 `Telemetry`，然后全局注册它，或通过 `telemetry.integrations` 传入。

来自 `@ai-sdk/otel` 的 `OpenTelemetry` 和 `LegacyOpenTelemetry` 是用于收集 OpenTelemetry span 的内置集成（请参阅上文的[启用遥测](#enabling-telemetry)）。

### 全局注册集成

使用 `registerTelemetry` 为所有 AI SDK 调用注册一次集成：

```ts
import { registerTelemetry } from 'ai';
import { OpenTelemetry } from '@ai-sdk/otel';

registerTelemetry(new OpenTelemetry());
```

你也可以在单次调用中通过将它们作为附加参数传入来注册多个集成。它们都会接收相同的生命周期事件：

```ts
import { registerTelemetry } from 'ai';
import { OpenTelemetry } from '@ai-sdk/otel';
import { DevToolsTelemetry } from '@ai-sdk/devtools';

registerTelemetry(new OpenTelemetry(), DevToolsTelemetry());
```

### 每次调用的集成

你也可以向单个 `generateText` 或 `streamText` 调用传入一个或多个集成。当提供每次调用的集成时，它们会替换该调用中全局注册的集成：

```ts highlight="6-8"
import { streamText } from 'ai';
import { DevToolsTelemetry } from '@ai-sdk/devtools';

const result = streamText({
  model: openai('gpt-6-astra'),
  prompt: 'Hello!',
  telemetry: {
    integrations: [DevToolsTelemetry()],
  },
});
```

你可以组合多个集成——它们都会接收相同的生命周期事件：

```ts
telemetry: {
  integrations: [DevToolsTelemetry(), customLogger()],
},
```

集成内部的错误会被捕获，不会中断生成流程。

### 追踪通道

在 Node.js 中，AI SDK 遥测生命周期和执行事件也会在
`ai:telemetry` [追踪通道](https://nodejs.org/api/diagnostics_channel.html#diagnostics_channeltracingchannelnameorchannels)上进行追踪。
这让可观测性提供商可以订阅 AI SDK 遥测事件，而无需
用户注册单独的遥测集成，并在提供商调用和工具执行之间绑定异步
上下文。

```ts
import { tracingChannel } from 'node:diagnostics_channel';
import {
  AI_SDK_TELEMETRY_TRACING_CHANNEL,
  type TelemetryTracingChannelMessage,
} from 'ai';

tracingChannel(AI_SDK_TELEMETRY_TRACING_CHANNEL).subscribe({
  start(message) {
    const telemetryMessage = message as TelemetryTracingChannelMessage;

    if (telemetryMessage.type === 'onStart') {
      // Inspect telemetryMessage.event and forward it to your provider.
    }
  },
});
```

追踪通道事件遵循与其他遥测集成相同的每次调用遥测设置。
设置 `telemetry: { isEnabled: false }` 会为该调用同时禁用
已注册的集成和追踪通道事件。

### 构建自定义集成

实现来自 `ai` 包的 `Telemetry` 接口。所有方法都是可选的——只实现你关心的生命周期事件：

```ts
import type { Telemetry } from 'ai';

class MyIntegration implements Telemetry {
  async onStart(event) {
    console.log('Generation started:', event.modelId);
  }

  async onStepEnd(event) {
    console.log(
      `Step ${event.stepNumber} done:`,
      event.usage.totalTokens,
      'tokens',
    );
  }

  async onToolExecutionEnd(event) {
    if (event.toolOutput.type === 'tool-result') {
      console.log(
        `Tool "${event.toolCall.toolName}" took ${event.toolExecutionMs}ms`,
      );
    } else {
      console.error(
        `Tool "${event.toolCall.toolName}" failed:`,
        event.toolOutput.error,
      );
    }
  }

  async onEnd(event) {
    console.log('Done. Total tokens:', event.usage.totalTokens);
  }

  async onAbort(event) {
    console.log('Stream aborted after', event.steps.length, 'finished steps');
  }

  async onError(event) {
    console.error('Generation failed:', event.callId, event.error);
  }
}

export function myIntegration(): Telemetry {
  return new MyIntegration();
}
```

## 收集的数据

`@ai-sdk/otel` 包提供两个发出不同 span 格式的集成。
`OpenTelemetry` 遵循 [OpenTelemetry GenAI 语义约定](https://opentelemetry.io/docs/specs/semconv/gen-ai/)，是推荐的集成。
`LegacyOpenTelemetry` 集成发出旧版 AI SDK 特定的 span。

### GenAI 语义约定

`OpenTelemetry` 发出的 span 遵循 [OpenTelemetry GenAI 语义约定](https://opentelemetry.io/docs/specs/semconv/gen-ai/)。
默认情况下，属性使用 `gen_ai.*` 前缀。提供商名称会映射到众所周知的值（例如 `openai`、`anthropic`、`gcp.vertex_ai`）。

#### generateText / streamText

对于 `generateText` 和 `streamText`，该集成记录 3 种类型的 span：

- **`invoke_agent {modelId}`**（根 span，`INTERNAL`）：覆盖包括所有步骤和工具调用在内的完整操作。

  初始属性：
  - `gen_ai.operation.name`：`"invoke_agent"`
  - `gen_ai.provider.name`：提供商（例如 `"openai"`、`"anthropic"`）
  - `gen_ai.request.model`：请求的模型 ID
  - `gen_ai.agent.name`：来自遥测设置的 `functionId`
  - `gen_ai.system_instructions`：格式化为 JSON 部件数组的系统指令（当启用 `recordInputs` 时）
  - `gen_ai.input.messages`：[GenAI SemConv 消息格式](#genai-message-format)的输入消息（当启用 `recordInputs` 时）
  - `gen_ai.request.temperature`：temperature 设置
  - `gen_ai.request.max_tokens`：最大输出 token 数
  - `gen_ai.request.top_p`：topP 设置
  - `gen_ai.request.top_k`：topK 设置
  - `gen_ai.request.frequency_penalty`：频率惩罚
  - `gen_ai.request.presence_penalty`：存在惩罚
  - `gen_ai.request.stop_sequences`：停止序列
  - `gen_ai.request.seed`：种子值

  完成时设置的属性：
  - `gen_ai.response.finish_reasons`：完成原因数组（例如 `["stop"]`、`["tool_call"]`）
  - `gen_ai.usage.input_tokens`：使用的输入 token 数
  - `gen_ai.usage.output_tokens`：使用的输出 token 数
  - `gen_ai.usage.cache_read.input_tokens`：读取的缓存输入 token 数
  - `gen_ai.usage.cache_creation.input_tokens`：创建的缓存输入 token 数
  - `gen_ai.output.messages`：[GenAI SemConv 消息格式](#genai-message-format)的输出（当启用 `recordOutputs` 时）

- **`chat {modelId}`**（步骤 span，`CLIENT`）：每次 LLM 提供商调用一个 span，嵌套在根 span 下。

  初始属性：
  - `gen_ai.operation.name`：`"chat"`
  - `gen_ai.provider.name`：提供商
  - `gen_ai.request.model`：请求的模型 ID
  - `gen_ai.request.temperature`、`gen_ai.request.max_tokens`、`gen_ai.request.top_p`、`gen_ai.request.top_k`、`gen_ai.request.frequency_penalty`、`gen_ai.request.presence_penalty`、`gen_ai.request.stop_sequences`：请求参数
  - `gen_ai.system_instructions`：与聊天历史分开提供的指令，格式化为 JSON 部件数组（当启用 `recordInputs` 时）
  - `gen_ai.input.messages`：[GenAI SemConv 消息格式](#genai-message-format)的提示词消息，包括作为聊天历史一部分的系统消息，按原始顺序排列（当启用 `recordInputs` 时）
  - `gen_ai.tool.definitions`：字符串化 JSON 的工具定义（当启用 `recordInputs` 时）

  完成时设置的属性：
  - `gen_ai.response.finish_reasons`：完成原因数组
  - `gen_ai.response.id`：来自提供商的响应 ID
  - `gen_ai.response.model`：生成响应的模型（可能与请求的模型不同）
  - `gen_ai.usage.input_tokens`：此步骤中使用的输入 token 数
  - `gen_ai.usage.output_tokens`：此步骤中使用的输出 token 数
  - `gen_ai.usage.cache_read.input_tokens`：读取的缓存输入 token 数
  - `gen_ai.usage.cache_creation.input_tokens`：创建的缓存输入 token 数
  - `gen_ai.client.operation.duration`：提供商调用持续时间，以秒为单位
  - `gen_ai.client.operation.time_to_first_chunk`：到第一个流式输出块的时间，以秒为单位（仅流式传输调用）
  - `gen_ai.client.operation.time_per_output_chunk`：流式输出块之间的平均时间，以秒为单位（仅具有多个输出块的流式传输调用）
  - `gen_ai.output.messages`：[GenAI SemConv 消息格式](#genai-message-format)的输出（当启用 `recordOutputs` 时）

- **`execute_tool {toolName}`**（工具 span，`INTERNAL`）：每次工具执行一个 span，嵌套在步骤 span 下。有关详细信息，请参阅 [GenAI 工具调用 span](#genai-tool-call-spans)。

#### 已弃用的对象 API（generateObject / streamObject）

<Note type="warning">
  `generateObject` 和 `streamObject` 已弃用。请改用带有 `output` 属性的
  `generateText` 和 `streamText`。
</Note>

已弃用的对象 API 发出与 `generateText`/`streamText` 相同的 span 层次结构，并在根 span 上带有以下附加属性：

- `gen_ai.output.type`：`"json"`

步骤 span 也包含 `gen_ai.output.type: "json"`，并且 `gen_ai.output.messages` 将生成的对象作为文本部件包含在内。

#### embed / embedMany

对于 `embed` 和 `embedMany`，该集成记录 `CLIENT` 类型的 span：

- **`embeddings {modelId}`**（根 span）：覆盖完整的嵌入操作。

  初始属性：
  - `gen_ai.operation.name`：`"embeddings"`
  - `gen_ai.provider.name`：提供商
  - `gen_ai.request.model`：请求的模型 ID

- **`embeddings {modelId}`**（内部 span）：每次提供商请求一个 span，
  嵌套在根 span 下。`embed` 创建一个内部 span。`embedMany`
  为每个提供商批处理调用创建一个内部 span。

  初始属性：
  - `gen_ai.operation.name`：`"embeddings"`
  - `gen_ai.provider.name`：提供商
  - `gen_ai.request.model`：模型 ID

  完成时设置的属性：
  - `gen_ai.usage.input_tokens`：使用的 token 数

用量仅记录在内部提供商请求 span 上。对于 `embedMany`，将
内部 span 的用量相加即可得到该操作的总用量。

#### rerank

对于 `rerank`，该集成记录 `CLIENT` 类型的 span：

- **`rerank {modelId}`**（根 span）：覆盖完整的重排序操作。

  初始属性：
  - `gen_ai.operation.name`：`"rerank"`
  - `gen_ai.provider.name`：提供商
  - `gen_ai.request.model`：请求的模型 ID

- **`rerank {modelId}`**（内部 span）：每次提供商重排序调用一个 span，嵌套在根 span 下。

  初始属性：
  - `gen_ai.operation.name`：`"rerank"`
  - `gen_ai.provider.name`：提供商
  - `gen_ai.request.model`：模型 ID

#### generateSpeech / transcribe / experimental_streamTranscribe

每次调用记录一个名为 `{operationId} {modelId}` 的 `CLIENT` span，其中
`operationId` 为 `ai.generateSpeech`、`ai.transcribe` 或 `ai.streamTranscribe`。

- `gen_ai.output.type`：语音生成为 `"speech"`，转写为 `"text"`。
- `gen_ai.request.stream`：流式传输转写为 `true`，否则为 `false`。
- `gen_ai.input.messages`：当启用 `recordInputs` 时，语音生成输入文本作为带有文本部件的用户消息。
- `gen_ai.output.messages`：当启用 `recordOutputs` 时，完成的转写文本作为带有文本部件的助手消息。流式传输转写会在完成时记录一次。

现有的 `ai.request.text` 和 `ai.response.text` 属性也会保留。
音频字节长度、媒体类型和输出格式保留在
`ai.request.audio.*` 和 `ai.response.audio.*` 属性中，受相应的输入/输出记录控制。原始音频不会被捕获，因此
转写输入和语音输出不会用音频内容或占位音频部件填充消息属性。

#### experimental_evaluate

对于 `experimental_evaluate`，该集成记录两个 `CLIENT`
类型的 span：一个用于整个操作的 **`evaluate {modelId}`** 根 span，以及一个
用于评估模型工作（包括重试）的 **`evaluate {modelId}`** 子 span。两者都包含提供商和请求的模型，并带有
`gen_ai.operation.name: "evaluate"`。Token
用量记录在子 span 上。当启用评估属性时，
答案会记录在两个 span 上，因此操作 span 包含其输出。

`evaluate` 是 AI SDK 定义的自定义操作名称，不是众所周知的
OpenTelemetry GenAI 操作。当没有众所周知的值描述该操作时，
OpenTelemetry 允许自定义操作名称。

OpenTelemetry 的 `gen_ai.evaluation.result` 事件描述评估 GenAI 输出质量或其他特征的结果。相比之下，
`experimental_evaluate` 可以评估任意 JSON 状态，用于分类、
路由、评分和类似任务。因此该集成不会发出
`gen_ai.evaluation.result` 事件。

评估状态、问题和答案也没有适用的 GenAI
语义约定属性。启用 `experimental_evaluation`
补充选项，将它们记录在 AI SDK 特定的
`ai.evaluation.*` 属性下。

#### GenAI span 详情

##### GenAI 消息格式

`gen_ai.input.messages` 和 `gen_ai.output.messages` 属性遵循 [OpenTelemetry GenAI 语义约定消息格式](https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-spans/)。
消息是带有 `role` 和 `parts` 数组的对象的 JSON 数组。每个部件都有一个 `type` 和特定于类型的字段：

- `text`：`{ type: "text", content: "..." }`
- `reasoning`：`{ type: "reasoning", content: "..." }`
- `tool_call`：`{ type: "tool_call", id: "...", name: "...", arguments: ... }`
- `tool_call_response`：`{ type: "tool_call_response", id: "...", response: ... }`
- `blob`：`{ type: "blob", modality: "image"|"video"|"audio", mime_type: "...", content: "..." }`（base64 编码）
- `uri`：`{ type: "uri", modality: "image"|"video"|"audio", mime_type: "...", uri: "..." }`（用于基于 URL 的文件）

输出消息还包含 `finish_reason` 字段（例如 `"stop"`、`"tool_call"`、`"length"`、`"content_filter"`）。

通过 `instructions`（或已弃用的 `system` 选项）提供的指令会单独记录在 `gen_ai.system_instructions` 中，作为 `{ type: "text", content: "..." }` 部件的 JSON 数组。通过 `allowSystemInMessages` 作为聊天历史提供的系统消息会保留在 `gen_ai.input.messages` 中的原始位置。

##### GenAI 工具调用 span

工具调用 span（`execute_tool {toolName}`）嵌套在步骤 span 下，并包含：

- `gen_ai.operation.name`：`"execute_tool"`
- `gen_ai.tool.name`：工具的名称
- `gen_ai.tool.call.id`：工具调用 ID
- `gen_ai.tool.type`：`"function"`
- `gen_ai.tool.call.arguments`：输入参数（字符串化 JSON，当启用 `recordInputs` 时）
- `gen_ai.execute_tool.duration`：工具执行持续时间，以秒为单位
- `gen_ai.tool.call.result`：输出结果（字符串化 JSON，当启用 `recordOutputs` 时）。仅在工具调用成功时设置。

### 自定义 OpenTelemetry span 属性

使用 `enrichSpan` 向 `OpenTelemetry` 集成创建的 span 添加自定义属性。当可观测性后端需要
AI SDK 自有语义之外的供应商特定属性时，这很有用。

```ts
import { registerTelemetry } from 'ai';
import { OpenTelemetry } from '@ai-sdk/otel';

registerTelemetry(
  new OpenTelemetry({
    enrichSpan: ({ spanType, operationId, callId, runtimeContext }) => {
      return {
        ...getCustomAttributes(runtimeContext, spanType),
        'my_app.operation_id': operationId,
        'my_app.call_id': callId,
      };
    },
  }),
);
```

该回调在每个 span 创建时运行，并接收：

- `spanType`：正在创建的 span 类型（`operation`、`step`、`languageModel`、`tool`、`embedding`、`reranking` 或 `experimental_evaluation`）。
- `operationId`：当前调用的 AI SDK 操作 ID，例如 `ai.generateText` 或 `ai.streamText`。
- `callId`：当前 AI SDK 调用的唯一 ID。
- `runtimeContext`：用于文本生成、嵌入、重排序和评估 span 的经过遥测过滤的运行时上下文。文本生成 span 也会反映来自 `prepareStep` 的更新。

自定义属性会与 span 上的 AI SDK 属性合并。当自定义属性使用相同的键时，
AI SDK 自有属性优先。

`telemetry.includeRuntimeContext` 在遥测集成接收
`runtimeContext` 之前应用，因此自定义 span 增强只会接收显式设置为 `true` 的顶层运行时上下文
属性。如果省略该选项，则不会包含任何运行时上下文
属性。

嵌入和重排序操作可以与文本生成共享相同的运行时上下文，以将其 span 归属到同一个应用请求：

```ts
await embed({
  model: 'openai/text-embedding-3-small',
  value: 'sunny day at the beach',
  runtimeContext: {
    requestId: 'req_abc',
    userId: 'user_123',
  },
  telemetry: {
    includeRuntimeContext: { requestId: true },
  },
});
```

全局注册的 `OpenTelemetry({ enrichSpan })` 集成会为操作 span 及其嵌入模型 span 接收
`{ requestId: 'req_abc' }`。
这同样适用于 `embedMany` 中的每个块，以及 `rerank` 中的操作和模型
span。`onStart` 和 `onEnd` 回调接收完整上下文。

### OpenTelemetry span 上的补充 AI SDK 属性

GenAI 语义约定涵盖核心模型、提示词、响应、工具调用和用量数据。你可以选择启用额外的 AI SDK 特定属性，用于 GenAI 语义未表示的数据：

```ts
import { registerTelemetry } from 'ai';
import { OpenTelemetry } from '@ai-sdk/otel';

registerTelemetry(
  new OpenTelemetry({
    usage: true,
    providerMetadata: true,
    runtimeContext: true,
  }),
);
```

这不会创建额外的 AI SDK 特定 span，例如 `ai.generateText`、`ai.generateText.doGenerate` 或 `ai.toolCall`。相反，它只会将选定的补充属性添加到 `OpenTelemetry` 发出的 span 中，例如 `invoke_agent {modelId}`、`step {n}`、`chat {modelId}` 和 `execute_tool {toolName}`。

所有补充属性默认禁用。只启用你想要收集的数据：

```ts
registerTelemetry(
  new OpenTelemetry({
    usage: true,
    providerMetadata: true,
    embedding: true,
    reranking: true,
    experimental_evaluation: true,
    runtimeContext: true,
    headers: true,
    toolChoice: true,
    schema: true,
  }),
);
```

可用的选项有：

- `usage`：GenAI 用量属性未涵盖的详细用量属性，例如未缓存输入 token 和输出文本/推理 token 详情。
- `providerMetadata`：操作、步骤和模型调用 span 上的 `ai.response.providerMetadata`。
- `embedding`：嵌入输入和输出。
- `reranking`：重排序输入文档和排名输出。
- `experimental_evaluation`：实验性评估状态、问题和答案。
- `runtimeContext`：`ai.settings.context.*`。
- `headers`：`ai.request.headers.*`。
- `toolChoice`：`ai.prompt.toolChoice`。
- `schema`：对象生成 schema 和输出模式属性。

对于补充输入和输出属性，`recordInputs` 和 `recordOutputs` 遥测选项仍然会被遵循。

### 旧版 AI SDK Span（`LegacyOpenTelemetry`）

`LegacyOpenTelemetry` 集成使用 AI SDK 特定的 `ai.*` 前缀属性发出 span。

#### generateText 函数

`generateText` 记录 3 种类型的 span：

- `ai.generateText`（span）：generateText 调用的完整长度。它包含 1 个或多个 `ai.generateText.doGenerate` span。
  它包含[基本 LLM span 信息](#basic-llm-span-information)以及以下属性：
  - `operation.name`：`ai.generateText` 以及通过 `telemetry.functionId` 设置的 functionId
  - `ai.operationId`：`"ai.generateText"`
  - `ai.prompt`：调用 `generateText` 时使用的提示词
  - `ai.response.text`：生成的文本
  - `ai.response.toolCalls`：作为生成一部分进行的工具调用（字符串化 JSON）
  - `ai.response.finishReason`：生成完成的原因
  - `ai.settings.maxOutputTokens`：设置的最大输出 token 数

- `ai.generateText.doGenerate`（span）：提供商 doGenerate 调用。它可以包含 `ai.toolCall` span。
  它包含[调用 LLM span 信息](#call-llm-span-information)以及以下属性：
  - `operation.name`：`ai.generateText.doGenerate` 以及通过 `telemetry.functionId` 设置的 functionId
  - `ai.operationId`：`"ai.generateText.doGenerate"`
  - `ai.prompt.messages`：传入提供商的消息
  - `ai.prompt.tools`：字符串化工具定义的数组。序列化的工具可以是 `function` 或 `provider` 类型。
    函数工具包括 `FunctionTool` 和 `DynamicTool` 定义，并具有 `name`、`description`（可选）和 `inputSchema`（JSON schema）。
    提供商工具包括 `ProviderDefinedTool` 和 `ProviderExecutedTool` 定义，并具有 `name`、`id` 和 `args`（Record）。
  - `ai.prompt.toolChoice`：字符串化的工具选择设置（JSON）。它有一个 `type` 属性
    （`auto`、`none`、`required`、`tool`），如果类型是 `tool`，则还有一个带有特定工具的 `toolName` 属性。
  - `ai.response.text`：生成的文本
  - `ai.response.toolCalls`：作为生成一部分进行的工具调用（字符串化 JSON）
  - `ai.response.finishReason`：生成完成的原因

- `ai.toolCall`（span）：作为 generateText 调用一部分进行的工具调用。有关详细信息，请参阅[旧版工具调用 span](#legacy-tool-call-spans)。

  它包含[基本 LLM span 信息](#basic-llm-span-information)以及以下属性：

- `ai.streamText.doStream`（span）：提供商 doStream 调用。
  此 span 包含一个 `ai.stream.firstChunk` 事件和 `ai.toolCall` span。
  它包含[调用 LLM span 信息](#call-llm-span-information)以及以下属性：
  - `operation.name`：`ai.streamText.doStream` 以及通过 `telemetry.functionId` 设置的 functionId
  - `ai.operationId`：`"ai.streamText.doStream"`
  - `ai.prompt.messages`：传入提供商的消息
  - `ai.prompt.tools`：字符串化工具定义的数组。序列化的工具可以是 `function` 或 `provider` 类型。
    函数工具包括 `FunctionTool` 和 `DynamicTool` 定义，并具有 `name`、`description`（可选）和 `inputSchema`（JSON schema）。
    提供商工具包括 `ProviderDefinedTool` 和 `ProviderExecutedTool` 定义，并具有 `name`、`id` 和 `args`（Record）。
  - `ai.prompt.toolChoice`：字符串化的工具选择设置（JSON）。它有一个 `type` 属性

  - `ai.response.text`：生成的文本
  - `ai.response.toolCalls`：作为生成一部分进行的工具调用（字符串化 JSON）
  - `ai.response.msToFirstChunk`：接收第一个块所花费的时间，以毫秒为单位
  - `ai.response.msToFinish`：接收 LLM 流的完成部分所花费的时间，以毫秒为单位

  - `ai.response.msToFirstChunk`：接收第一个块所花费的时间
