# 设置

大型语言模型（LLM）通常提供各种设置来增强其输出。

除了模型、[提示词](/docs/foundations/prompts)以及提供商特定的额外设置之外，所有 AI SDK 函数都支持以下通用设置：

```ts highlight="3-6"
const result = await generateText({
  model: __MODEL__,
  maxOutputTokens: 512,
  temperature: 0.3,
  maxRetries: 5,
  timeout: 10000,
  prompt: 'Invent a new holiday and describe its traditions.',
});
```

<Note>
  某些提供商不支持所有通用设置。如果你对不支持某个设置的提供商使用该设置，将会生成一条警告。你可以检查结果对象中的 `warnings` 属性，查看是否生成了任何警告。
</Note>

## 语言模型调用选项

语言模型调用选项（`LanguageModelCallOptions`）是影响语言模型如何生成响应的设置——token 限制、采样行为、惩罚、停止序列、种子和推理。它们会被转发到底层模型。

### `maxOutputTokens`

要生成的最大 token 数量。

### `temperature`

温度设置。

该值会传递给提供商。范围取决于提供商和模型。
对于大多数提供商，`0` 表示几乎确定性的结果，值越高表示随机性越大。

建议设置 `temperature` 或 `topP` 中的其中一个，但不要同时设置两者。

<Note>在 AI SDK 5.0 中，temperature 不再默认设置为 `0`。</Note>

### `topP`

核采样。

该值会传递给提供商。范围取决于提供商和模型。
对于大多数提供商，核采样是 0 到 1 之间的数字。
例如，0.1 表示只考虑概率质量排名前 10% 的 token。

建议设置 `temperature` 或 `topP` 中的其中一个，但不要同时设置两者。

### `topK`

仅从每个后续 token 的前 K 个选项中进行采样。

用于去除“长尾”低概率响应。
仅推荐用于高级用例。通常你只需要使用 `temperature`。

### `presencePenalty`

存在惩罚会影响模型重复提示词中已有信息的可能性。

该值会传递给提供商。范围取决于提供商和模型。
对于大多数提供商，`0` 表示无惩罚。

### `frequencyPenalty`

频率惩罚会影响模型重复使用相同单词或短语的可能性。

该值会传递给提供商。范围取决于提供商和模型。
对于大多数提供商，`0` 表示无惩罚。

### `stopSequences`

用于停止文本生成的停止序列。

如果设置了该选项，当生成其中一个停止序列时，模型将停止生成文本。
提供商可能会对停止序列的数量有所限制。

### `seed`

用于随机采样的种子（整数）。
如果设置且模型支持，调用将生成确定性的结果。

### `reasoning`

控制模型在生成响应之前执行多少推理。

| 值                   | 行为                                             |
| -------------------- | ------------------------------------------------ |
| `'provider-default'` | 使用提供商的默认推理行为（省略时的默认值）       |
| `'none'`             | 禁用推理                                         |
| `'minimal'`          | 最低限度的推理                                   |
| `'low'`              | 快速、简洁的推理                                 |
| `'medium'`           | 均衡的推理                                       |
| `'high'`             | 全面的推理                                       |
| `'xhigh'`            | 超高推理                                         |
| `'max'`              | 最大推理                                         |

提供商特定的设置优先于从 `reasoning` 派生的对应字段。部分配置仍可使用可移植推理来填充缺失字段；摘要和显示选项可以与其一起使用。例如，Bedrock 会保留显式的思考预算，同时从可移植推理中派生缺失的启用类型。

有关各提供商映射以及从 `providerOptions` 迁移的详细信息，请参阅[推理指南](/docs/ai-sdk-core/reasoning)。

## 请求选项

请求选项（`RequestOptions`）是影响传输、重试、取消和超时的设置——而非模型生成行为。它们控制 SDK 如何与提供商的 API 通信。

### `maxRetries`

最大重试次数。设置为 0 以禁用重试。默认值：`2`。

### `abortSignal`

一个可选的中止信号，可用于取消调用。

中止信号可以从用户界面转发以取消调用，
或使用 `AbortSignal.timeout` 定义超时。

#### 示例：AbortSignal.timeout

```ts
const result = await generateText({
  model: __MODEL__,
  prompt: 'Invent a new holiday and describe its traditions.',
  abortSignal: AbortSignal.timeout(5000), // 5 seconds
});
```

### `timeout`

可选的超时时间（以毫秒为单位）。如果调用耗时超过指定时长，将被中止。

这是一个便捷参数，会在内部创建一个中止信号。它可以与 `abortSignal` 一起使用——如果同时提供两者，则满足任一条件时调用将被中止。

你可以将超时指定为数字（毫秒）或具有以下属性的对象：

- `totalMs`：整个调用的总超时时间，包括所有步骤。
- `stepMs`：每个完整步骤的超时时间，包括模型生成、重试和本地工具执行。该预算在步骤内的各提供商尝试之间累积。
- `firstChunkMs`：每个步骤直到第一个携带内容的输出的超时时间（仅限流式传输）。文本增量、推理增量、工具输入增量、生成的文件和工具调用可满足该超时。响应元数据、流开始、空增量、原始块和传输活动不会满足或重置该超时。
- `chunkMs`：输出开始后，有意义模型输出块之间的超时时间（仅限流式传输）。它从第一个有意义的输出开始计时；它不限制对第一个输出的等待。非内容块不会重置它。这对于检测生成开始后停滞的流非常有用。
- `toolMs`：所有工具执行的默认超时时间。如果某个工具耗时更长，它将中止并返回工具错误，以便模型可以响应或重试。
- `tools`：使用 `{toolName}Ms` 键的按工具超时覆盖（例如 `weatherMs`、`slowApiMs`）。优先于 `toolMs`。工具名称会进行类型检查以支持自动补全。

当模型响应完成、出错、关闭或被取消时，`firstChunkMs` 和 `chunkMs` 计时器会停止。每次提供商重试或后续模型调用都会获得新的输出超时预算。重试退避和本地工具执行不在这些预算范围内。提供商执行的工具仍处于模型响应范围内。`stepMs` 和 `totalMs` 预算在重试和本地工具执行期间保持有效。

#### 示例：5 秒超时（数字格式）

```ts
const result = await generateText({
  model: __MODEL__,
  prompt: 'Invent a new holiday and describe its traditions.',
  timeout: 5000, // 5 seconds
});
```

#### 示例：5 秒总超时（对象格式）

```ts
const result = await generateText({
  model: __MODEL__,
  prompt: 'Invent a new holiday and describe its traditions.',
  timeout: { totalMs: 5000 }, // 5 seconds
});
```

#### 示例：10 秒步骤超时

```ts
const result = await generateText({
  model: __MODEL__,
  prompt: 'Invent a new holiday and describe its traditions.',
  timeout: { stepMs: 10000 }, // 10 seconds per step
});
```

#### 示例：组合总超时和步骤超时

```ts
const result = await generateText({
  model: __MODEL__,
  prompt: 'Invent a new holiday and describe its traditions.',
  timeout: {
    totalMs: 60000, // 60 seconds total
    stepMs: 10000, // 10 seconds per step
  },
});
```

#### 示例：流式传输的按块超时（仅限 streamText）

```ts
const result = streamText({
  model: __MODEL__,
  prompt: 'Invent a new holiday and describe its traditions.',
  timeout: { chunkMs: 5000 }, // abort if content stalls for 5 seconds
});
```

#### 示例：流式传输的首个内容超时（仅限 streamText）

```ts
const result = streamText({
  model: __MODEL__,
  prompt: 'Invent a new holiday and describe its traditions.',
  timeout: {
    firstChunkMs: 10000, // 10 seconds for first content in each step
  },
});
```

#### 示例：工具执行超时

```ts
const result = await generateText({
  model: __MODEL__,
  tools: { weather: weatherTool, slowApi: slowApiTool },
  timeout: {
    toolMs: 5000, // 5 seconds default for all tools
  },
  prompt: 'What is the weather in San Francisco?',
});
```

#### 示例：按工具超时覆盖

```ts
const result = await generateText({
  model: __MODEL__,
  tools: { weather: weatherTool, slowApi: slowApiTool },
  timeout: {
    toolMs: 5000, // default for all tools
    tools: {
      weatherMs: 3000, // 3 seconds for weather tool
      slowApiMs: 10000, // 10 seconds for slow API tool
    },
  },
  prompt: 'What is the weather in San Francisco?',
});
```

### `headers`

随请求发送的额外 HTTP 头。仅适用于基于 HTTP 的提供商。

你可以使用请求头向提供商提供额外信息，
具体取决于提供商支持的内容。例如，一些可观测性提供商支持
诸如 `Prompt-Id` 之类的头。

```ts
import { generateText } from 'ai';
__PROVIDER_IMPORT__;

const result = await generateText({
  model: __MODEL__,
  prompt: 'Invent a new holiday and describe its traditions.',
  headers: {
    'Prompt-Id': 'my-prompt-id',
  },
});
```

<Note>
  `headers` 设置用于请求特定的头。你也可以在提供商配置中设置
  `headers`。这些头将随提供商发出的每个请求一起发送。
</Note>
