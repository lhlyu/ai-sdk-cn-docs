# 推理

许多语言模型在生成响应之前支持一个内部的“推理”阶段（有时也称为“思考”）。AI SDK 在 [`generateText`](/docs/reference/ai-sdk-core/generate-text) 和 [`streamText`](/docs/reference/ai-sdk-core/stream-text) 上提供了一个顶层 `reasoning` 参数，通过一个单一、可移植的设置来控制各提供商的这一行为。

## 基本用法

```ts
import { generateText } from 'ai';

const { text, reasoning, reasoningText } = await generateText({
  model: 'anthropic/claude-sonnet-5.5',
  reasoning: 'medium',
  prompt: 'How many people will live in the world in 2040?',
});
```

`reasoning` 参数接受以下值：

| 值                   | 行为                                                             |
| -------------------- | -------------------------------------------------------------------- |
| `'provider-default'` | 使用提供商的默认推理行为（省略时的默认值） |
| `'none'`             | 禁用推理                                                    |
| `'minimal'`          | 最低限度的推理                                               |
| `'low'`              | 快速、简洁的推理                                              |
| `'medium'`           | 均衡的推理                                                   |
| `'high'`             | 全面的推理                                                   |
| `'xhigh'`            | 超高推理                                                 |
| `'max'`              | 最大推理                                                    |

## 流式传输

`reasoning` 参数在 `streamText` 中的工作方式相同：

```ts
import { streamText } from 'ai';

const result = streamText({
  model: 'google/gemini-3.8-flash',
  reasoning: 'high',
  prompt: 'Explain the Riemann hypothesis in simple terms.',
});

for await (const part of result.stream) {
  if (part.type === 'reasoning') {
    process.stdout.write(part.textDelta);
  } else if (part.type === 'text-delta') {
    process.stdout.write(part.textDelta);
  }
}
```

## 优先级规则

提供商特定的设置优先于从 `reasoning` 派生的相应字段。部分配置仍可使用可移植的推理来填充缺失的字段；摘要和显示设置可以与其一起使用。

```ts
import { generateText } from 'ai';
import { openai } from '@ai-sdk/openai';

const { text } = await generateText({
  model: openai.responses('gpt-6-astra'),
  reasoning: 'low', // ignored because providerOptions.openai.reasoningEffort is set
  providerOptions: {
    openai: {
      reasoningEffort: 'high', // this wins
    },
  },
  prompt: 'Explain quantum entanglement.',
});
```

这种设计让你默认使用可移植的 `reasoning` 参数，仅在需要提供商特定功能（如精确的 token 预算）时才回退到 `providerOptions`。

## 提供商支持

`reasoning` 参数受到包括 OpenAI、Anthropic、Google、xAI、Groq、DeepSeek、Moonshot AI、Fireworks、Amazon Bedrock、Mistral、Cohere、Alibaba、Open Responses、OpenAI Compatible 和 Perplexity 在内的提供商支持。每个提供商都会将该值转换为其原生的推理 API。

具有独特原生最高档位的提供商，例如受支持的 OpenAI、Anthropic、DeepSeek 和 Moonshot AI 模型，会直接接收 `'max'`。Amazon Bedrock 为其 Anthropic 和 OpenAI 的 effort 映射保留 `'max'`，而 Amazon Nova 2 会将 `'xhigh'` 和 `'max'` 映射为 `'high'` 并发出兼容性警告。最高原生档位较低的提供商会将 `'max'` 强制转换为其最接近的受支持档位，并在其适配器支持警告传播时发出兼容性警告。OpenAI 兼容和 Open Responses 端点会直接接收 `'max'`，以便兼容的服务器可以解释它。

一些提供商使用数字 token 预算而非枚举来控制推理。在这些情况下，`'max'` 默认映射为模型最大输出 token 的 95%，并受提供商的推理预算最小和最大限制约束。

最大推理可能会大幅增加 token 使用量、延迟、成本以及达到请求或输出限制的可能性。当模型额外的推理深度值得这些权衡时，请使用它。

不支持推理配置的提供商和模型会发出 `unsupported` 警告并忽略该参数。

## 从 `providerOptions` 迁移

如果你目前通过 `providerOptions` 控制推理，可以迁移到顶层 `reasoning` 参数，以实现跨提供商的可移植性。

### 之前（Anthropic）

```ts
const { text } = await generateText({
  model: anthropic('claude-opus-5-5'),
  providerOptions: {
    anthropic: {
      thinking: { type: 'adaptive' },
      effort: 'high',
    },
  },
  prompt: 'How many people will live in the world in 2040?',
});
```

### 之后（Anthropic）

```ts
const { text } = await generateText({
  model: anthropic('claude-opus-5-5'),
  reasoning: 'high',
  prompt: 'How many people will live in the world in 2040?',
});
```

### 之前（使用较旧模型的 Anthropic）

```ts
const { text } = await generateText({
  model: anthropic('claude-sonnet-4-20250514'),
  providerOptions: {
    anthropic: {
      thinking: { type: 'enabled', budgetTokens: 12000 },
    },
  },
  prompt: 'How many people will live in the world in 2040?',
});
```

### 之后（使用较旧模型的 Anthropic）

```ts
const { text } = await generateText({
  model: anthropic('claude-sonnet-4-20250514'),
  reasoning: 'medium',
  prompt: 'How many people will live in the world in 2040?',
});
```

如果你需要强制使用精确的 token 预算（例如恰好 12000 个 token），请继续使用 `providerOptions` 而非顶层 `reasoning` 参数。

### 之前（使用 `includeThoughts` 的 Google）

```ts
const { text } = await generateText({
  model: google('gemini-3.8-flash'),
  providerOptions: {
    google: {
      thinkingConfig: { thinkingLevel: 'high', includeThoughts: true },
    },
  },
  prompt: 'Explain the Riemann hypothesis in simple terms.',
});
```

### 之后（使用 `includeThoughts` 的 Google）

```ts
const { text } = await generateText({
  model: google('gemini-3.8-flash'),
  reasoning: 'high',
  providerOptions: {
    google: { thinkingConfig: { includeThoughts: true } },
  },
  prompt: 'Explain the Riemann hypothesis in simple terms.',
});
```

### 之前（使用 `reasoningSummary` 的 OpenAI）

```ts
const { text } = await generateText({
  model: openai.responses('gpt-6-astra'),
  providerOptions: {
    openai: { reasoningEffort: 'high', reasoningSummary: 'auto' },
  },
  prompt: 'Explain quantum entanglement.',
});
```

### 之后（使用 `reasoningSummary` 的 OpenAI）

```ts
const { text } = await generateText({
  model: openai.responses('gpt-6-astra'),
  reasoning: 'high',
  providerOptions: {
    openai: { reasoningSummary: 'auto' },
  },
  prompt: 'Explain quantum entanglement.',
});
```

你可以将 `providerOptions` 与 `reasoning` 结合使用，以实现提供商特定功能，例如推理摘要或显示设置。显式的 effort 或预算值会覆盖相应的映射字段；部分配置仍可使用可移植的推理来填充缺失的字段。详情请参阅[优先级规则](#precedence-rules)。
