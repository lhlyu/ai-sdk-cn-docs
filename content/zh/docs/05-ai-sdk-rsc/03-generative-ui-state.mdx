# 管理生成式 UI 状态

<Note type="warning">
  AI SDK RSC 目前处于实验阶段。生产环境建议使用 [AI SDK
  UI](/docs/ai-sdk-ui/overview)。如需从 RSC 迁移到 UI，请参阅我们的[迁移指南](/docs/ai-sdk-rsc/migrating-to-ui)。
</Note>

状态是任何应用的核心组成部分。在 AI 应用中，状态尤为重要，因为它会在每次请求时传递给大语言模型 (LLM)，确保模型拥有必要的上下文来生成优质内容。传统聊天机器人基于文本，其结构与普通聊天应用类似。

例如，在聊天机器人中，状态是一个 `messages` 数组，每条 `message` 包含：

- `id`：唯一标识符
- `role`：消息发送者（用户/助手/系统/工具）
- `content`：消息内容

这种状态可以直接在 UI 中渲染，并无需修改即可发送给模型。

而在生成式 UI 中，模型可以返回 React 组件，而非纯文本消息。客户端可以正常渲染该组件，但由于 React 组件不可序列化，这种状态无法回传给模型。那么，该如何解决呢？

**解决方案是将状态一分为二，其中一种状态（AI 状态）作为另一种状态（UI 状态）的代理**。

可以通过乐高积木来理解这个概念。想象一个由 10,000 块积木拼成的模型，拼好后因结构脆弱而难以搬运。将模型拆解后，可以轻松搬运，再按照说明书中的步骤重新拼装。这样，说明书就成了实体结构的代理。同理，AI 状态提供了 UI 的可序列化 (JSON) 表示，可以在模型之间来回传递。

## 什么是 AI 状态和 UI 状态？

RSC API 简化了 AI 状态和 UI 状态的管理，提供了一种稳健的方式，使它们在数据库、服务器和客户端之间保持同步。

### AI 状态

AI 状态是指应用状态的可序列化格式，用于服务器端，并可共享给语言模型。

对于聊天应用，AI 状态是用户与助手之间的对话历史（消息）。模型生成的组件会以 JSON 格式表示为工具，并附带必要的属性。AI 状态还可用于存储其他值和元信息，例如每条消息的 `createdAt` 和每次对话的 `chatId`。LLM 读取此历史记录以生成下一条消息。该状态是当前应用状态的唯一真实来源。

<Note>
  **注意**：AI 状态可在服务器端和客户端访问/修改。
</Note>

### UI 状态

UI 状态是指在客户端渲染的应用状态。它是一种完全客户端的状态（类似于 `useState`），可以存储从 JavaScript 值到 React 元素的任何内容。UI 状态是在客户端渲染的实际 UI 元素列表。

<Note>**注意**：UI 状态只能在客户端访问。</Note>

## 使用 AI / UI 状态

### 创建 AI 上下文

AI SDK RSC 通过提供多个 Hook 简化了跨应用的 AI 和 UI 状态管理。这些 Hook 底层由 [React 上下文](https://react.dev/reference/react/hooks#context-hooks) 驱动。

这意味着您无需为每次请求显式地将消息历史传递给服务器。您还可以在上下文提供者的任何子组件中访问和更新应用状态。在构建[多步骤生成式界面](/docs/ai-sdk-rsc/multistep-interfaces)时，这将特别有用。

要使用 `@ai-sdk/rsc` 管理应用中的 AI 和 UI 状态，您可以通过 [`createAI`](/docs/reference/ai-sdk-rsc/create-ai) 创建 React 上下文：

```tsx filename='app/actions.tsx'
// 定义 AI 状态和 UI 状态类型
export type ServerMessage = {
  role: 'user' | 'assistant';
  content: string;
};

export type ClientMessage = {
  id: string;
  role: 'user' | 'assistant';
  display: ReactNode;
};

export const sendMessage = async (input: string): Promise<ClientMessage> => {
  "use server"
  ...
}
```

```tsx filename='app/ai.ts'
import { createAI } from '@ai-sdk/rsc';
import { ClientMessage, ServerMessage, sendMessage } from './actions';

export type AIState = ServerMessage[];
export type UIState = ClientMessage[];

// 使用初始状态和允许的操作创建 AI 提供者
export const AI = createAI<AIState, UIState>({
  initialAIState: [],
  initialUIState: [],
  actions: {
    sendMessage,
  },
});
```

<Note>您必须将 Server Actions 传递给 `actions` 对象。</Note>

在此示例中，您分别定义了 AI 状态和 UI 状态的类型。

接下来，用新创建的上下文包裹您的应用。这样，您就可以在整个应用中获取和设置 AI 及 UI 状态。

```tsx filename='app/layout.tsx'
import { type ReactNode } from 'react';
import { AI } from './ai';

export default function RootLayout({
  children,
}: Readonly<{ children: ReactNode }>) {
  return (
    <AI>
      <html lang="en">
        <body>{children}</body>
      </html>
    </AI>
  );
}
```

## 在客户端读取 UI 状态

UI 状态可以在客户端组件中通过 RSC API 提供的 [`useUIState`](/docs/reference/ai-sdk-rsc/use-ui-state) Hook 访问。该 Hook 返回当前的 UI 状态和一个更新 UI 状态的函数，类似于 React 的 `useState`。

```tsx filename='app/page.tsx'
'use client';

import { useUIState } from '@ai-sdk/rsc';

export default function Page() {
  const [messages, setMessages] = useUIState();

  return (
    <ul>
      {messages.map(message => (
        <li key={message.id}>{message.display}</li>
      ))}
    </ul>
  );
}
```

## 在客户端读取 AI 状态

AI 状态可以在客户端组件中通过 RSC API 提供的 [`useAIState`](/docs/reference/ai-sdk-rsc/use-ai-state) Hook 访问。该 Hook 返回当前的 AI 状态。

```tsx filename='app/page.tsx'
'use client';

import { useAIState } from '@ai-sdk/rsc';

export default function Page() {
  const [messages, setMessages] = useAIState();

  return (
    <ul>
      {messages.map(message => (
        <li key={message.id}>{message.content}</li>
      ))}
    </ul>
  );
}
```

## 在服务器端读取 AI 状态

AI 状态可以在传递给 `createAI` 上下文的任何 Server Action 中通过 [`getAIState`](/docs/reference/ai-sdk-rsc/get-ai-state) 函数访问。它返回当前的 AI 状态作为只读值：

```tsx filename='app/actions.ts'
import { getAIState } from '@ai-sdk/rsc';

export async function sendMessage(message: string) {
  'use server';

  const history = getAIState();

  const response = await generateText({
    model: __MODEL__,
    messages: [...history, { role: 'user', content: message }],
  });

  return response;
}
```

<Note>
  请记住，您只能在已传递给 `createAI` 上下文中 `actions` 键的操作内访问状态。
</Note>

## 在服务器端更新 AI 状态

AI 状态还可以通过 [`getMutableAIState`](/docs/reference/ai-sdk-rsc/get-mutable-ai-state) 函数在 Server Action 中更新。此函数与 `getAIState` 类似，但它返回带有读取和更新方法的状态：

```tsx filename='app/actions.ts'
import { getMutableAIState } from '@ai-sdk/rsc';

export async function sendMessage(message: string) {
  'use server';

  const history = getMutableAIState();

  // 使用新的用户消息更新 AI 状态。
  history.update([...history.get(), { role: 'user', content: message }]);

  const response = await generateText({
    model: __MODEL__,
    messages: history.get(),
  });

  // 使用模型的响应再次更新 AI 状态。
  history.done([...history.get(), { role: 'assistant', content: response }]);

  return response;
}
```

<Note>
  使用 `.update()` 和 `.done()` 更新 AI 状态以添加新响应，对于保持对话历史同步非常重要。
</Note>

## 从客户端调用 Server Actions

要从客户端调用 `sendMessage` 操作，您可以使用 [`useActions`](/docs/reference/ai-sdk-rsc/use-actions) Hook。该 Hook 返回所有提供给 `createAI` 的可用操作：

```tsx filename='app/page.tsx'
'use client';

import { useActions, useUIState } from '@ai-sdk/rsc';
import { AI } from './ai';

export default function Page() {
  const { sendMessage } = useActions<typeof AI>();
  const [messages, setMessages] = useUIState();

  const handleSubmit = async event => {
    event.preventDefault();

    setMessages([
      ...messages,
      { id: Date.now(), role: 'user', display: event.target.message.value },
    ]);

    const response = await sendMessage(event.target.message.value);

    setMessages([
      ...messages,
      { id: Date.now(), role: 'assistant', display: response },
    ]);
  };

  return (
    <>
      <ul>
        {messages.map(message => (
          <li key={message.id}>{message.display}</li>
        ))}
      </ul>
      <form onSubmit={handleSubmit}>
        <input type="text" name="message" />
        <button type="submit">发送</button>
      </form>
    </>
  );
}
```

当用户提交消息时，`sendMessage` 操作会被调用，并传入消息内容。操作的响应随后被添加到 UI 状态中，更新显示的消息列表。

<Note>
  重要！调用 Server Action 后，不要忘记更新 UI 状态，否则流式组件将不会在 UI 中显示。
</Note>

要了解更多信息，请查看此[示例](/examples/next-app/state-management/ai-ui-states)，了解如何使用 `@ai-sdk/rsc` 管理 AI 和 UI 状态。
