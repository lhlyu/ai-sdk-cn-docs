# 工具集工具

工具集有两个工具层面：

- 底层工具集运行时暴露的内置工具，例如文件读取、编辑、Shell 命令和网络搜索。
- 通过 `tools` 设置传递给 `HarnessAgent` 的 AI SDK 工具。

本页介绍工具集特定的行为。有关 AI SDK 工具的一般概念、模式、工具结果和 `tool()` 用法，请参阅[工具](/docs/foundations/tools)。

## 内置工具

每个适配器声明其运行时可以原生调用的内置工具。`HarnessAgent` 将这些内置工具与你定义的主机工具合并，并通过 `agent.tools` 暴露组合后的工具集。

```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
});

agent.tools.bash;
agent.tools.read;
agent.tools.write;
```

内置调用由工具集运行时执行，而不是由你的应用程序进程执行。当运行时已经执行了调用时，流部分使用 `providerExecuted: true`。

适配器尽可能使用通用名称：

- `read`
- `write`
- `edit`
- `bash`
- `grep`
- `glob`
- `webSearch`

某些运行时还暴露了没有通用跨工具集名称的原生工具。这些工具以其原生名称出现。

## 主机执行工具

将 AI SDK 工具传递给 `HarnessAgent` 的方式与传递给 `ToolLoopAgent` 相同：

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { claudeCode } from '@ai-sdk/harness-claude-code';
import { createVercelSandbox } from '@ai-sdk/sandbox-vercel';
import { tool } from 'ai';
import { z } from 'zod';

const weather = tool({
  description: '获取指定城市的当前温度。',
  inputSchema: z.object({
    city: z.string(),
  }),
  execute: async ({ city }) => {
    const temperatures: Record<string, number> = {
      Paris: 12,
      Tokyo: 18,
      Reykjavik: 3,
    };

    return { city, celsius: temperatures[city] ?? 20 };
  },
});

const agent = new HarnessAgent({
  harness: claudeCode,
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
  tools: { weather },
});
```

当工具集调用 `weather` 时，`HarnessAgent` 在你的主机进程中执行该工具，然后将结果提交回工具集运行时。

## 工具过滤

在 `HarnessAgent` 上使用 `activeTools` 或 `inactiveTools` 来控制工具集可以调用哪些工具。这两个设置都接受来自组合工具集的工具名称：工具集适配器声明的内置工具和通过 `tools` 传递的 AI SDK 工具。

`activeTools` 是一个允许列表：

```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
  tools: { weather },
  activeTools: ['weather'],
});
```

`inactiveTools` 是一个拒绝列表：

```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
  tools: { weather },
  inactiveTools: ['bash', 'write'],
});
```

传递 `activeTools` 或 `inactiveTools` 之一，不能同时传递两者。TypeScript 设置类型阻止了它们的组合，并且 `HarnessAgent` 在同时指定两者时也会在运行时抛出错误。

对于主机执行工具，非活动工具不会传递给底层工具集运行时。如果运行时仍然尝试调用其中一个，`HarnessAgent` 会返回一个执行被拒绝的工具结果。

对于内置工具，支持取决于工具集适配器。某些适配器可以原生过滤内置工具。其他适配器通过其内置工具批准机制来强制执行过滤，即在执行前拒绝非活动的内置调用，而不发出批准请求或响应流部分。不支持这两种机制的适配器在过滤内置工具时会抛出错误。

## 工具执行中的沙箱

主机执行工具通过 AI SDK 工具在其他地方使用的相同 `experimental_sandbox` 执行选项接收会话沙箱。该值是一个受限的沙箱会话，因此工具可以读取、写入和运行命令，而无法停止网络沙箱或更改其网络策略。

```ts
const inspectFile = tool({
  description: '从工具集工作区读取文件。',
  inputSchema: z.object({
    path: z.string(),
  }),
  execute: async ({ path }, { experimental_sandbox }) => {
    return {
      content: await experimental_sandbox?.readTextFile({ path }),
    };
  },
});
```

## 工具批准

工具集区分内置工具权限和主机执行工具批准。

对适配器原生的内置工具使用 `permissionMode`：

```ts
const agent = new HarnessAgent({
  harness: pi,
  sandbox: createVercelSandbox({ runtime: 'node24' }),
  permissionMode: 'allow-edits',
});
```

可用的值有：

- `allow-all`：允许内置读取、编辑和 Shell 命令。这是默认值。
- `allow-edits`：允许读取和编辑，但当适配器支持内置批准时，请求批准 Shell 命令。
- `allow-reads`：允许读取，但当适配器支持内置批准时，请求批准编辑和 Shell 命令。

对主机执行工具使用 `toolApproval`：

```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
  tools: { weather },
  toolApproval: {
    weather: 'user-approval',
  },
});
```

`toolApproval` 接受与 AI SDK 工具批准状态对象相同的状态值：`not-applicable`、`approved`、`user-approval` 和 `denied`。

当需要批准时，流会在 `tool-approval-request` 后暂停。通过发送工具批准响应消息来继续同一会话。在 UI 流程中，当你添加批准结果时，`useChat` 会为你发送这些消息。在直接代理代码中，在下一次 `stream()` 或 `generate()` 调用中将批准响应作为 `messages` 传递。

## 内置批准支持

大多数适配器可以暂停内置工具调用以进行批准。不支持此功能的适配器在指定了不支持的批准模式时会报错。

主机执行工具批准由 `HarnessAgent` 处理，因此它们跨适配器工作。

## 文件更改和压缩

某些工具集事件不是普通的工具调用。为了 UI 兼容性，`HarnessAgent` 将它们投影为动态的、由提供商执行的工具部分：

- `fileChange`：为不透明的工作区文件更改发出。
- `compaction`：当运行时压缩上下文时发出。

在假设工具部分属于你的类型化工具集之前，请检查 `part.dynamic`。
