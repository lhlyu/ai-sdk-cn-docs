# AI SDK 工具集

AI SDK 工具集抽象层让你能够通过统一的 AI SDK 接口运行成熟的智能体工具集。工具集是一个完整的智能体运行时，例如 Claude Code、Codex 或 Pi。它拥有超越模型调用的能力：工作空间访问、内置编码工具、原生会话状态、压缩、权限流程以及运行时特定的配置。此外，所有 AI SDK 智能体工具集都在沙箱中运行，确保宿主环境的安全。

AI SDK 工具集抽象层与提供商/模型抽象层是分离的。提供商向 AI SDK 核心函数（如 `generateText` 和 `streamText`）暴露模型。工具集则向 `HarnessAgent` 暴露智能体运行时。

使用工具集并不意味着放弃定制化。`HarnessAgent` 允许你提供自己的指令、技能、AI SDK 工具、权限设置、沙箱设置 Hook 以及适配器特定的配置，同时保留使每个工具集功能强大的运行时行为。

这两个抽象层是解耦的，但它们在可能的情况下使用兼容的原语。工具集的输出会被投影到 AI SDK 的流和响应类型中，因此消费 AI SDK 模型流的界面也可以消费工具集流。例如，你可以将 `HarnessAgent` 流传递给 `toUIMessageStream`，并使用 `useChat` 渲染它。该 API 的设计旨在让 AI SDK 用户感到熟悉，但工具集运行时与底层语言模型有不同的概念。配置在适用时遵循 AI SDK 的模式，在工具集运行时行为不同时则有所偏离。

<Note>
  工具集包是**实验性的**。随着这个早期 API 的进一步完善，预计版本之间会有破坏性变更。
</Note>

## 何时使用工具集

当你希望由现有的智能体运行时驱动任务时，请使用工具集：

- 能够检查并修改沙箱工作空间的编码智能体。
- 拥有自己内置工具和权限模型的智能体运行时。
- 由运行时负责管理对话历史的多轮会话。
- 应保留原生工具集行为而非通过工具循环重新创建的工作流。

当你希望直接控制模型调用、工具循环、模型设置、结构化输出或自定义智能体架构时，请使用提供商和模型。

## 核心概念

工具集有四个主要部分：

- `HarnessAgent`：你在应用程序代码中使用的 AI SDK 智能体实现。
- 工具集适配器：连接到运行时的包，例如 `@ai-sdk/harness-claude-code`。
- 沙箱提供商：工具集运行的隔离文件系统和进程环境。
- 会话：工具集运行的实时对话和工作空间状态。

## 兼容的流

`HarnessAgent.generate()` 返回一个 AI SDK 的 `GenerateTextResult`。
`HarnessAgent.stream()` 返回一个 AI SDK 的 `StreamTextResult`。

这意味着你可以使用熟悉的字段：

- `result.text`
- `result.stream`
- `result.steps`
- `result.usage`
- `result.responseMessages`

工具集特定的事件会被转换为兼容的流部分。文本、推理、工具调用、工具结果、使用情况和完成原因在可能的情况下使用相同的 AI SDK 形状。没有一等 AI SDK 部分的事件，例如工作空间文件更改和压缩，会作为动态的提供商执行工具部分呈现。

## 会话很重要

与语言模型调用不同，工具集会话拥有状态。会话携带工具集运行时、沙箱、工作目录、原生对话历史以及待处理的审批。

在运行轮次之前创建会话：

```ts
const session = await agent.createSession();

try {
  const result = await agent.generate({
    session,
    prompt: '检查仓库并总结测试设置。',
  });

  console.log(result.text);
} finally {
  await session.destroy();
}
```

对于服务器路由，请使用稳定的 `sessionId`，并持久化由 `session.detach()` 或 `session.stop()` 返回的恢复状态。
