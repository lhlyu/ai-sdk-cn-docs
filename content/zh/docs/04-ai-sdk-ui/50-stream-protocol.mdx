# 流协议

AI SDK UI 函数（如 `useChat` 和 `useCompletion`）同时支持文本流和数据流。
流协议定义了数据如何在 HTTP 协议之上流式传输到前端。

本页介绍这两种协议，以及如何在后端和前端中使用它们。

你可以利用这些信息为你的用例开发自定义后端和前端，例如，
提供用其他语言（如 Python）实现的兼容 API 端点。

例如，下面是一个使用 [FastAPI](https://github.com/vercel/ai/tree/main/examples/next-fastapi) 作为后端的示例。

## 文本流协议

文本流包含纯文本形式的块，这些块会被流式传输到前端。
每个块随后被拼接在一起，形成完整的文本响应。

`useChat`、`useCompletion` 和 `useObject` 均支持文本流。
要启用文本流式传输，请在 `useChat` 中使用 `TextStreamChatTransport`，或在 `useCompletion` 中将
`streamProtocol` 选项设置为 `text`。

你可以在后端使用 `streamText` 生成文本流。
将结果的 `stream` 传给 `toTextStream`，并通过
`createTextStreamResponse` 返回，以创建流式 HTTP 响应。

<Note>
  文本流仅支持基本的文本数据。如果你需要流式传输其他类型
  的数据（例如工具调用），请使用数据流。
</Note>

### 文本流示例

以下是一个使用文本流协议的 Next.js 示例：

```tsx filename='app/page.tsx'
'use client';

import { useChat } from '@ai-sdk/react';
import { TextStreamChatTransport } from 'ai';
import { useState } from 'react';

export default function Chat() {
  const [input, setInput] = useState('');
  const { messages, sendMessage } = useChat({
    transport: new TextStreamChatTransport({ api: '/api/chat' }),
  });

  return (
    <div className="flex flex-col w-full max-w-md py-24 mx-auto stretch">
      {messages.map(message => (
        <div key={message.id} className="whitespace-pre-wrap">
          {message.role === 'user' ? 'User: ' : 'AI: '}
          {message.parts.map((part, i) => {
            switch (part.type) {
              case 'text':
                return <div key={`${message.id}-${i}`}>{part.text}</div>;
            }
          })}
        </div>
      ))}

      <form
        onSubmit={e => {
          e.preventDefault();
          sendMessage({ text: input });
          setInput('');
        }}
      >
        <input
          className="fixed dark:bg-zinc-900 bottom-0 w-full max-w-md p-2 mb-8 border border-zinc-300 dark:border-zinc-800 rounded shadow-xl"
          value={input}
          placeholder="Say something..."
          onChange={e => setInput(e.currentTarget.value)}
        />
      </form>
    </div>
  );
}
```

```ts filename='app/api/chat/route.ts'
import {
  convertToModelMessages,
  createTextStreamResponse,
  streamText,
  toTextStream,
  UIMessage,
} from 'ai';
__PROVIDER_IMPORT__;

// Allow streaming responses up to 30 seconds
export const maxDuration = 30;

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
  });

  return createTextStreamResponse({
    stream: toTextStream({ stream: result.stream }),
  });
}
```

## 数据流协议

数据流遵循 AI SDK 提供的特殊协议，用于向前端发送信息。

数据流协议使用 Server-Sent Events (SSE) 格式，以提高标准化程度、通过 ping 实现保活、支持重连能力，并改善缓存处理。

<Note>
  当你从自定义后端提供数据流时，需要将
  `x-vercel-ai-ui-message-stream` 请求头设置为 `v1`。
</Note>

目前支持以下流部件：

### 消息开始部件

表示一条带有元数据的新消息的开始。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"start","messageId":"..."}

```

### 文本部件

文本内容使用 start/delta/end 模式进行流式传输，每个文本块都有唯一 ID。

#### 文本开始部件

表示一个文本块的开始。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"text-start","id":"msg_68679a454370819ca74c8eb3d04379630dd1afb72306ca5d"}

```

#### 文本增量部件

包含该文本块的增量文本内容。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"text-delta","id":"msg_68679a454370819ca74c8eb3d04379630dd1afb72306ca5d","delta":"Hello"}

```

#### 文本结束部件

表示一个文本块的完成。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"text-end","id":"msg_68679a454370819ca74c8eb3d04379630dd1afb72306ca5d"}

```

### 推理部件

推理内容使用 start/delta/end 模式进行流式传输，每个推理块都有唯一 ID。

#### 推理开始部件

表示一个推理块的开始。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"reasoning-start","id":"reasoning_123"}

```

#### 推理增量部件

包含该推理块的增量推理内容。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"reasoning-delta","id":"reasoning_123","delta":"This is some reasoning"}

```

#### 推理结束部件

表示一个推理块的完成。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"reasoning-end","id":"reasoning_123"}

```

### 推理文件部件

推理文件部件包含对推理过程中生成的文件（例如推理过程中产生的图像）的引用。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"reasoning-file","url":"data:image/png;base64,iVBOR...","mediaType":"image/png"}

```

### 来源部件

来源部件提供对外部内容来源的引用。

#### 来源 URL 部件

对外部 URL 的引用。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"source-url","sourceId":"https://example.com","url":"https://example.com"}

```

#### 来源文档部件

对文档或文件的引用。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"source-document","sourceId":"https://example.com","mediaType":"file","title":"Title"}

```

### 文件部件

文件部件包含对文件及其媒体类型的引用。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"file","url":"https://example.com/file.png","mediaType":"image/png"}

```

### 自定义部件

自定义部件表示无法归入标准部件类型的提供商特定内容。`kind` 字段以 `{provider}.{provider-type}` 格式标识具体的自定义内容类型。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"custom","kind":"openai.compaction","providerMetadata":{"openai":{"itemId":"cmp_123"}}}

```

### 数据部件

自定义数据部件允许流式传输任意结构化数据，并进行类型特定处理。

格式：包含 JSON 对象的 Server-Sent Event，其中类型包含自定义后缀

示例：

```
data: {"type":"data-weather","data":{"location":"SF","temperature":100}}

```

`data-*` 类型模式允许你定义前端可以专门处理的自定义数据类型。

### 错误部件

错误部件在收到时会被追加到消息中。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"error","errorText":"error message"}

```

### 工具输入开始部件

表示工具输入流式传输的开始。

可选的 `inputEncoding` 字段指定如何解释后续的输入
增量。当省略或设置为 `'json'` 时，UI 会将累积的文本解析为
部分 JSON。设置为 `'text'` 时，UI 会直接将累积的文本用作
字符串输入。对于原始自定义工具输入（如代码或 HTML），请使用 `'text'`。
该编码也会保留在持久化的 `input-streaming` 工具部件上，以便
流式传输能够正确恢复。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"tool-input-start","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","toolName":"getWeatherInformation"}

```

### 工具输入增量部件

工具输入生成过程中的增量块。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"tool-input-delta","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","inputTextDelta":"San Francisco"}

```

### 工具输入可用部件

表示工具输入已完成，可以执行。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"tool-input-available","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","toolName":"getWeatherInformation","input":{"city":"San Francisco"}}

```

### 工具审批请求部件

表示工具调用需要审批，或记录审批决定是自动做出的。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"tool-approval-request","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","approvalId":"approval_123","approvalDescriptor":{"scope":"account:delete"},"reason":"Requires operator review"}

```

当省略 `isAutomatic` 时，该请求期望客户端给出明确的审批响应。
`reason` 是可选的，用于解释工具调用为什么需要审批。
`approvalDescriptor` 是可选的审批不透明元数据。
当流被处理为 UI 消息时，它可通过
`part.approval.descriptor` 访问，并在后续审批状态中保留。

### 工具审批响应部件

记录工具调用的审批决定。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"tool-approval-response","approvalId":"approval_123","approved":false,"reason":"User denied the request"}

```

对于由提供商执行的工具，响应还可以包含 `providerExecuted: true`。

### 工具输出可用部件

包含工具执行的结果。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"tool-output-available","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","output":{"city":"San Francisco","weather":"sunny"}}

```

### 工具输出被拒绝部件

表示在审批流程完成后工具执行被拒绝。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"tool-output-denied","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar"}

```

### 开始步骤部件

表示一个步骤开始的部件。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"start-step"}

```

### 完成步骤部件

表示一个步骤（即后端中的一次 LLM API 调用）已完成的部件。

该部件对于正确处理多个拼接的助手调用是必要的，例如在后端调用工具，
同时在 `useChat` 中使用步骤时。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"finish-step"}

```

### 重置步骤部件

移除自最近一次 `start-step` 部件以来收到的所有消息部件。如果
没有步骤边界，则移除当前消息中的所有部件。当流式步骤被重试，
且失败尝试的部分输出必须在发送替换输出之前失效时，这很有用。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"reset-step"}

```

### 完成消息部件

表示一条消息完成的部件。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"finish"}

```

### 中止部件

表示流已被中止。

格式：包含 JSON 对象的 Server-Sent Event

示例：

```
data: {"type":"abort","reason":"user cancelled"}

```

### 流终止

流以一个特殊的 `[DONE]` 标记结束。

格式：包含字面量 `[DONE]` 的 Server-Sent Event

示例：

```
data: [DONE]

```

数据流协议在前端由 `useChat` 和 `useCompletion` 支持，并且默认使用。
`useCompletion` 仅支持 `text` 和 `data` 流部件。

在后端，你可以将 `streamText` 结果流传给 `toUIMessageStream`，并通过 `createUIMessageStreamResponse` 返回。

以下是一个使用 UI 消息流协议的 Next.js 示例：
