# 流式协议

AI SDK UI 函数（如 `useChat` 和 `useCompletion`）同时支持文本流和数据流。
流式协议定义了数据如何在 HTTP 协议之上流式传输到前端。

本页介绍这两种协议以及如何在后端和前端使用它们。

你可以利用这些信息为你的用例开发自定义后端和前端，例如，
提供用其他语言（如 Python）实现的兼容 API 端点。

例如，这里有一个使用 [FastAPI](https://github.com/vercel/ai/tree/main/examples/next-fastapi) 作为后端的示例。

## 文本流协议

文本流包含以纯文本形式流式传输到前端的块。
每个块随后被拼接在一起，形成完整的文本响应。

`useChat`、`useCompletion` 和 `useObject` 支持文本流。
当你使用 `useChat` 或 `useCompletion` 时，你需要通过将 `streamProtocol` 选项设置为 `text` 来启用文本流。

你可以在后端使用 `streamText` 生成文本流。
将结果的 `stream` 传递给 `toTextStream`，并使用 `createTextStreamResponse` 返回它，以创建流式 HTTP 响应。

<Note>
  文本流仅支持基本的文本数据。如果你需要流式传输其他类型的数据（如工具调用），请使用数据流。
</Note>

### 文本流示例

以下是一个使用文本流协议的 Next.js 示例：

```tsx filename='app/page.tsx'
'use client';

import { useChat } from '@ai-sdk/react';
import { TextStreamChatTransport } from 'ai';
import { useState } from 'react';

export default function Chat() {
  const [input, setInput] = useState('');
  const { messages, sendMessage } = useChat({
    transport: new TextStreamChatTransport({ api: '/api/chat' }),
  });

  return (
    <div className="flex flex-col w-full max-w-md py-24 mx-auto stretch">
      {messages.map(message => (
        <div key={message.id} className="whitespace-pre-wrap">
          {message.role === 'user' ? '用户: ' : 'AI: '}
          {message.parts.map((part, i) => {
            switch (part.type) {
              case 'text':
                return <div key={`${message.id}-${i}`}>{part.text}</div>;
            }
          })}
        </div>
      ))}

      <form
        onSubmit={e => {
          e.preventDefault();
          sendMessage({ text: input });
          setInput('');
        }}
      >
        <input
          className="fixed dark:bg-zinc-900 bottom-0 w-full max-w-md p-2 mb-8 border border-zinc-300 dark:border-zinc-800 rounded shadow-xl"
          value={input}
          placeholder="说点什么..."
          onChange={e => setInput(e.currentTarget.value)}
        />
      </form>
    </div>
  );
}
```

```ts filename='app/api/chat/route.ts'
import {
  convertToModelMessages,
  createTextStreamResponse,
  streamText,
  toTextStream,
  UIMessage,
} from 'ai';
__PROVIDER_IMPORT__;

// 允许流式响应最长 30 秒
export const maxDuration = 30;

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: __MODEL__,
    messages: await convertToModelMessages(messages),
  });

  return createTextStreamResponse({
    stream: toTextStream({ stream: result.stream }),
  });
}
```

## 数据流协议

数据流遵循 AI SDK 提供的特殊协议，用于向前端发送信息。

数据流协议使用服务器发送事件（SSE）格式，以实现更好的标准化、通过 ping 保持连接、支持重连以及更好的缓存处理。

<Note>
  当你从自定义后端提供数据流时，需要将 `x-vercel-ai-ui-message-stream` 头设置为 `v1`。
</Note>

目前支持以下流部分：

### 消息开始部分

指示带有元数据的新消息的开始。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"start","messageId":"..."}

```

### 文本部分

文本内容使用开始/增量/结束模式进行流式传输，每个文本块具有唯一 ID。

#### 文本开始部分

指示文本块的开始。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"text-start","id":"msg_68679a454370819ca74c8eb3d04379630dd1afb72306ca5d"}

```

#### 文本增量部分

包含文本块的增量文本内容。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"text-delta","id":"msg_68679a454370819ca74c8eb3d04379630dd1afb72306ca5d","delta":"你好"}

```

#### 文本结束部分

指示文本块的完成。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"text-end","id":"msg_68679a454370819ca74c8eb3d04379630dd1afb72306ca5d"}

```

### 推理部分

推理内容使用开始/增量/结束模式进行流式传输，每个推理块具有唯一 ID。

#### 推理开始部分

指示推理块的开始。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"reasoning-start","id":"reasoning_123"}

```

#### 推理增量部分

包含推理块的增量推理内容。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"reasoning-delta","id":"reasoning_123","delta":"这是一些推理"}

```

#### 推理结束部分

指示推理块的完成。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"reasoning-end","id":"reasoning_123"}

```

### 推理文件部分

推理文件部分包含对推理过程中生成的文件（例如推理过程中产生的图像）的引用。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"reasoning-file","url":"data:image/png;base64,iVBOR...","mediaType":"image/png"}

```

### 来源部分

来源部分提供对外部内容来源的引用。

#### 来源 URL 部分

对外部 URL 的引用。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"source-url","sourceId":"https://example.com","url":"https://example.com"}

```

#### 来源文档部分

对文档或文件的引用。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"source-document","sourceId":"https://example.com","mediaType":"file","title":"标题"}

```

### 文件部分

文件部分包含对带有媒体类型的文件的引用。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"file","url":"https://example.com/file.png","mediaType":"image/png"}

```

### 自定义部分

自定义部分表示不适合标准部分类型的提供商特定内容。`kind` 字段以 `{provider}.{provider-type}` 格式标识特定的自定义内容类型。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"custom","kind":"openai.compaction","providerMetadata":{"openai":{"itemId":"cmp_123"}}}

```

### 数据部分

自定义数据部分允许流式传输具有类型特定处理的任意结构化数据。

格式：包含 JSON 对象的服务器发送事件，其中类型包含自定义后缀

示例：

```
data: {"type":"data-weather","data":{"location":"旧金山","temperature":100}}

```

`data-*` 类型模式允许你定义前端可以专门处理的自定义数据类型。

### 错误部分

错误部分在收到时被附加到消息中。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"error","errorText":"错误消息"}

```

### 工具输入开始部分

指示工具输入流式传输的开始。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"tool-input-start","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","toolName":"getWeatherInformation"}

```

### 工具输入增量部分

工具输入生成时的增量块。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"tool-input-delta","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","inputTextDelta":"旧金山"}

```

### 工具输入可用部分

指示工具输入已完成并准备好执行。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"tool-input-available","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","toolName":"getWeatherInformation","input":{"city":"旧金山"}}

```

### 工具审批请求部分

指示工具调用需要审批，或记录审批决定是自动做出的。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"tool-approval-request","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","approvalId":"approval_123","approvalDescriptor":{"scope":"account:delete"},"reason":"需要操作员审查"}

```

当省略 `isAutomatic` 时，请求期望客户端给出明确的审批响应。`reason` 是可选的，解释为什么工具调用需要审批。`approvalDescriptor` 是用于审批的可选不透明元数据。当流被处理为 UI 消息时，它可作为 `part.approval.descriptor` 使用，并在后续审批状态中保留。

### 工具审批响应部分

记录工具调用的审批决定。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"tool-approval-response","approvalId":"approval_123","approved":false,"reason":"用户拒绝了请求"}

```

对于提供商执行的工具，响应还可以包含 `providerExecuted: true`。

### 工具输出可用部分

包含工具执行的结果。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"tool-output-available","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar","output":{"city":"旧金山","weather":"晴朗"}}

```

### 工具输出被拒部分

指示在审批流程完成后工具执行被拒绝。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"tool-output-denied","toolCallId":"call_fJdQDqnXeGxTmr4E3YPSR7Ar"}

```

### 步骤开始部分

指示步骤开始的部分。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"start-step"}

```

### 步骤结束部分

指示步骤（即后端中的一次 LLM API 调用）已完成的部分。

此部分对于正确处理多个拼接的助手调用是必要的，例如在后端调用工具，同时在 `useChat` 中使用步骤时。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"finish-step"}

```

### 步骤重置部分

移除自最近的 `start-step` 部分以来收到的所有消息部分。如果没有步骤边界，它将移除当前消息中的所有部分。当流式步骤被重试，并且必须使失败尝试的部分输出失效，然后再发送替换输出时，这很有用。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"reset-step"}

```

### 消息结束部分

指示消息完成的部分。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"finish"}

```

### 中止部分

指示流已被中止。

格式：包含 JSON 对象的服务器发送事件

示例：

```
data: {"type":"abort","reason":"用户取消"}

```

### 流终止

流以特殊的 `[DONE]` 标记结束。

格式：包含字面量 `[DONE]` 的服务器发送事件

示例：

```
data: [DONE]

```

数据流协议在前端由 `useChat` 和 `useCompletion` 支持，并默认使用。
`useCompletion` 仅支持 `text` 和 `data` 流部分。

在后端，你可以将 `streamText` 结果流传递给 `toUIMessageStream`，并使用 `createUIMessageStreamResponse` 返回它。
