# 聊天机器人消息持久化

能够存储和加载聊天消息对大多数 AI 聊天机器人来说至关重要。
在本指南中，我们将展示如何使用 `useChat` 和 `streamText` 实现消息持久化。

<Note>
  本指南不涉及授权、错误处理或其他实际应用中的考虑事项。它旨在作为一个简单的示例，展示如何实现消息持久化。
</Note>

## 开始新聊天

当用户在没有提供聊天 ID 的情况下导航到聊天页面时，
我们需要创建一个新聊天，并重定向到带有新聊天 ID 的聊天页面。

```tsx filename="app/chat/page.tsx"
import { redirect } from 'next/navigation';
import { createChat } from '@util/chat-store';

export default async function Page() {
  const id = await createChat(); // create a new chat
  redirect(`/chat/${id}`); // redirect to chat page, see below
}
```

我们的示例聊天存储实现使用文件来存储聊天消息。
在实际应用中，你会使用数据库或云存储服务，
并从数据库中获取聊天 ID。
话虽如此，这些函数接口的设计使其可以轻松替换为其他实现。

```tsx filename="util/chat-store.ts"
import { generateId } from 'ai';
import { existsSync, mkdirSync } from 'fs';
import { writeFile } from 'fs/promises';
import path from 'path';

// Treat chat IDs as opaque tokens before using them in file paths.
const chatIdRegex = /^[A-Za-z0-9_-]+$/;

export async function createChat(): Promise<string> {
  const id = generateId(); // generate a unique chat ID
  await writeFile(getChatFile(id), '[]'); // create an empty chat file
  return id;
}

function getChatFile(id: string): string {
  if (!chatIdRegex.test(id)) {
    throw new Error('Invalid chat ID');
  }

  const chatDir = path.resolve(process.cwd(), '.chats');
  const chatFile = path.resolve(chatDir, `${id}.json`);

  // Defense in depth: keep the resolved file inside the chat directory.
  if (!chatFile.startsWith(`${chatDir}${path.sep}`)) {
    throw new Error('Invalid chat ID');
  }

  if (!existsSync(chatDir)) mkdirSync(chatDir, { recursive: true });
  return chatFile;
}
```

聊天 ID 可能来自 URL 或请求体，因此在将其用于文件路径之前，
应将其作为不透明令牌进行验证。解析后的路径检查可确保
文件保留在预期的 `.chats` 目录内。

## 加载现有聊天

当用户带着聊天 ID 导航到聊天页面时，我们需要从存储中加载聊天消息。

我们基于文件的聊天存储中的 `loadChat` 函数实现如下：

```tsx filename="util/chat-store.ts"
import { UIMessage } from 'ai';
import { readFile } from 'fs/promises';

export async function loadChat(id: string): Promise<UIMessage[]> {
  return JSON.parse(await readFile(getChatFile(id), 'utf8'));
}
```

## 在服务器端验证消息

在服务器端处理包含工具调用、自定义元数据或数据部分的消息时，你应该在将它们发送给模型之前使用 `validateUIMessages` 进行验证。

### 迁移已弃用的工具 `rawInput`

处于 `output-error` 状态的旧持久化工具部分可能包含 `rawInput`。
该字段已弃用，将在下一个主版本中移除。请将
工具参数存储在 `input` 中。当 `validateUIMessages`、`safeValidateUIMessages` 或 `convertToModelMessages`
遇到已定义的 `rawInput` 值时，AI SDK 会发出弃用警告。UI 流处理在
重建带有 `rawInput` 的静态 `output-error` 部分时也会发出警告。

当 `input` 为 `null` 或 `undefined` 时，通过将 `rawInput` 复制到 `input` 来迁移每个旧版部分，
然后移除 `rawInput`。这样可以保留当前的向后兼容转换行为：

```ts
import { isToolUIPart } from 'ai';

const migratedParts = message.parts.map(part => {
  if (
    !isToolUIPart(part) ||
    part.state !== 'output-error' ||
    !('rawInput' in part) ||
    part.rawInput === undefined
  ) {
    return part;
  }

  const { rawInput, ...partWithoutRawInput } = part;

  return {
    ...partWithoutRawInput,
    input: part.input ?? rawInput,
  };
});
```

### 使用工具进行验证

当你的消息包含工具调用时，请根据工具定义对它们进行验证：

```tsx filename="app/api/chat/route.ts" highlight="7-8,14-27,35-45"
import {
  convertToModelMessages,
  createUIMessageStreamResponse,
  streamText,
  toUIMessageStream,
  UIMessage,
  validateUIMessages,
  tool,
} from 'ai';
import { z } from 'zod';
import { loadChat, saveChat } from '@util/chat-store';
import { dataPartsSchema, metadataSchema } from '@util/schemas';

// Define your tools
const tools = {
  weather: tool({
    description: 'Get weather information',
    inputSchema: z.object({
      location: z.string(),
      units: z.enum(['celsius', 'fahrenheit']),
    }),
    execute: async ({ location, units }) => {
      /* tool implementation */
    },
  }),
  // other tools
};

export async function POST(req: Request) {
  const { message, id } = await req.json();

  // Load previous messages from database
  const previousMessages = await loadChat(id);

  // Append new message to previousMessages messages
  const messages = [...previousMessages, message];

  // Validate loaded messages against
  // tools, data parts schema, and metadata schema
  const validatedMessages = await validateUIMessages({
    messages,
    tools, // Ensures tool calls in messages match current schemas
    dataPartsSchema,
    metadataSchema,
  });

  const result = streamText({
    model: 'openai/gpt-6-luna',
    messages: convertToModelMessages(validatedMessages),
    tools,
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({
      stream: result.stream,
      originalMessages: messages,
      onEnd: ({ messages }) => {
        saveChat({ chatId: id, messages });
      },
    }),
  });
}
```

### 处理验证错误

当来自数据库的消息与当前 schema 不匹配时，请优雅地处理验证错误：

```tsx filename="app/api/chat/route.ts" highlight="3,10-24"
import {
  convertToModelMessages,
  streamText,
  validateUIMessages,
  TypeValidationError,
} from 'ai';
import { type MyUIMessage } from '@/types';

export async function POST(req: Request) {
  const { message, id } = await req.json();

  // Load and validate messages from database
  let validatedMessages: MyUIMessage[];

  try {
    const previousMessages = await loadMessagesFromDB(id);
    validatedMessages = await validateUIMessages({
      // append the new message to the previous messages:
      messages: [...previousMessages, message],
      tools,
      metadataSchema,
    });
  } catch (error) {
    if (error instanceof TypeValidationError) {
      // Log validation error for monitoring
      console.error('Database messages validation failed:', error);
      // Could implement message migration or filtering here
      // For now, start with empty history
      validatedMessages = [];
    } else {
      throw error;
    }
  }

  // Continue with validated messages...
}
```

## 显示聊天

一旦从存储中加载了消息，你就可以在聊天 UI 中显示它们。以下是如何设置页面组件和聊天显示：

```tsx filename="app/chat/[id]/page.tsx"
import { loadChat } from '@util/chat-store';
import Chat from '@ui/chat';

export default async function Page(props: { params: Promise<{ id: string }> }) {
  const { id } = await props.params;
  const messages = await loadChat(id);
  return <Chat id={id} initialMessages={messages} />;
}
```

聊天组件使用 `useChat` Hook 来管理对话：

```tsx filename="ui/chat.tsx" highlight="10-16"
'use client';

import { UIMessage, useChat } from '@ai-sdk/react';
import { DefaultChatTransport } from 'ai';
import { useState } from 'react';

export default function Chat({
  id,
  initialMessages,
}: { id?: string | undefined; initialMessages?: UIMessage[] } = {}) {
  const [input, setInput] = useState('');
  const { sendMessage, messages } = useChat({
    id, // use the provided chat ID
    messages: initialMessages, // load initial messages
    transport: new DefaultChatTransport({
      api: '/api/chat',
    }),
  });

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    if (input.trim()) {
      sendMessage({ text: input });
      setInput('');
    }
  };

  // simplified rendering code, extend as needed:
  return (
    <div>
      {messages.map(m => (
        <div key={m.id}>
          {m.role === 'user' ? 'User: ' : 'AI: '}
          {m.parts
            .map(part => (part.type === 'text' ? part.text : ''))
            .join('')}
        </div>
      ))}

      <form onSubmit={handleSubmit}>
        <input
          value={input}
          onChange={e => setInput(e.target.value)}
          placeholder="Type a message..."
        />
        <button type="submit">Send</button>
      </form>
    </div>
  );
}
```

## 存储消息

`useChat` 会将聊天 ID 和消息发送到后端。

<Note>
  `useChat` 的消息格式与 `ModelMessage` 格式不同。`useChat` 的消息格式
  是为前端显示而设计的，包含诸如 `id` 和 `createdAt` 之类的
  附加字段。我们建议以 `useChat` 的消息格式存储消息。

当从存储中加载包含工具、元数据或自定义数据部分的消息时，请在处理之前
使用 `validateUIMessages` 进行验证（参见上文的
[验证部分](#validating-messages-on-the-server)）。

</Note>

消息的存储是在 `toUIMessageStream` 函数的 `onEnd` 回调中完成的。
`onEnd` 接收包含新 AI 响应的完整消息，类型为 `UIMessage[]`。

```tsx filename="app/api/chat/route.ts" highlight="12,17-25"
import { openai } from '@ai-sdk/openai';
import { saveChat } from '@util/chat-store';
import {
  convertToModelMessages,
  createUIMessageStreamResponse,
  streamText,
  toUIMessageStream,
  UIMessage,
} from 'ai';

export async function POST(req: Request) {
  const { messages, chatId }: { messages: UIMessage[]; chatId: string } =
    await req.json();

  const result = streamText({
    model: 'openai/gpt-6-luna',
    messages: await convertToModelMessages(messages),
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({
      stream: result.stream,
      originalMessages: messages,
      onEnd: ({ messages }) => {
        saveChat({ chatId, messages });
      },
    }),
  });
}
```

消息的实际存储是在 `saveChat` 函数中完成的，在我们基于文件的聊天存储中
其实现如下：

```tsx filename="util/chat-store.ts"
import { UIMessage } from 'ai';
import { writeFile } from 'fs/promises';

export async function saveChat({
  chatId,
  messages,
}: {
  chatId: string;
  messages: UIMessage[];
}): Promise<void> {
  const content = JSON.stringify(messages, null, 2);
  await writeFile(getChatFile(chatId), content);
}

// ... rest of the file
```

## 消息 ID

除了聊天 ID 之外，每条消息都有一个 ID。
你可以使用此消息 ID 来例如操作单条消息。

### 客户端与服务器端 ID 生成

默认情况下，消息 ID 在客户端生成：

- 用户消息 ID 由客户端的 `useChat` Hook 生成
- AI 响应消息 ID 由服务器端的 `streamText` 生成

对于没有持久化的应用，客户端 ID 生成完全可以正常工作。
然而，**对于持久化，你应该使用在消息存储之前就稳定的 ID**，
以确保跨会话的一致性，并防止消息恢复时出现 ID 冲突。

下面的服务器端选项控制生成的助手响应消息的 ID。
用户消息 ID 由 `useChat` 在请求发送到你的 API 路由之前创建，
因此在保存传入的请求消息时，请保留这些客户端生成的 ID，或者在发送/存储之前
生成并持久化你自己的用户消息 ID。

### 设置服务器端 ID 生成

在实现持久化时，你有两种选择来为助手响应消息生成服务器端 ID：

1. **在 `toUIMessageStream` 中使用 `generateMessageId`**
2. **使用 `createUIMessageStream` 在起始消息部分中设置 ID**

#### 选项 1：在 `toUIMessageStream` 中使用 `generateMessageId`

你可以通过使用 [`createIdGenerator()`](/docs/reference/ai-sdk-core/create-id-generator) 提供 ID 生成器来控制 ID 格式：

```tsx filename="app/api/chat/route.ts" highlight="18-22"
import {
  createIdGenerator,
  createUIMessageStreamResponse,
  streamText,
  toUIMessageStream,
} from 'ai';

export async function POST(req: Request) {
  // ...
  const result = streamText({
    // ...
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({
      stream: result.stream,
      originalMessages: messages,
      // Generate consistent server-side IDs for persistence:
      generateMessageId: createIdGenerator({
        prefix: 'msg',
        size: 16,
      }),
      onEnd: ({ messages }) => {
        saveChat({ chatId, messages });
      },
    }),
  });
}
```

#### 选项 2：使用 `createUIMessageStream` 设置 ID

或者，你可以使用 `createUIMessageStream` 通过写入起始消息部分来控制消息 ID：

```tsx filename="app/api/chat/route.ts" highlight="14-18,25-27"
import {
  generateId,
  streamText,
  createUIMessageStream,
  createUIMessageStreamResponse,
  toUIMessageStream,
} from 'ai';

export async function POST(req: Request) {
  const { messages, chatId } = await req.json();

  const stream = createUIMessageStream({
    execute: ({ writer }) => {
      // Write start message part with custom ID
      writer.write({
        type: 'start',
        messageId: generateId(), // Generate server-side ID for persistence
      });

      const result = streamText({
        model: 'openai/gpt-6-luna',
        messages: await convertToModelMessages(messages),
      });

      writer.merge(
        toUIMessageStream({ stream: result.stream, sendStart: false }),
      ); // omit start message part
    },
    originalMessages: messages,
    onEnd: ({ responseMessage }) => {
      // save your chat here
    },
  });

  return createUIMessageStreamResponse({ stream });
}
```

<Note>
  对于不需要持久化的客户端应用，你仍然可以自定义客户端 ID 生成：

```tsx filename="ui/chat.tsx"
import { createIdGenerator } from 'ai';
import { useChat } from '@ai-sdk/react';

const { ... } = useChat({
  generateId: createIdGenerator({
    prefix: 'msgc',
    size: 16,
  }),
  // ...
});
```

</Note>

## 仅发送最后一条消息

一旦实现了消息持久化，你可能希望只将最后一条消息发送到服务器。
这可以减少每次请求发送到服务器的数据量，并可能提升性能。

为此，你可以为 transport 提供一个 `prepareSendMessagesRequest` 函数。
该函数接收消息和聊天 ID，并返回要发送到服务器的请求体。

```tsx filename="ui/chat.tsx" highlight="7-12"
import { useChat } from '@ai-sdk/react';
import { DefaultChatTransport } from 'ai';

const {
  // ...
} = useChat({
  // ...
  transport: new DefaultChatTransport({
    api: '/api/chat',
    // only send the last message to the server:
    prepareSendMessagesRequest({ messages, id }) {
      return { body: { message: messages[messages.length - 1], id } };
    },
  }),
});
```

在服务器端，你可以加载之前的消息，并将新消息追加到之前的消息中。如果你的消息包含工具、元数据或自定义数据部分，你应该对它们进行验证：

```tsx filename="app/api/chat/route.ts" highlight="18-24"
import {
  convertToModelMessages,
  createUIMessageStreamResponse,
  toUIMessageStream,
  UIMessage,
  validateUIMessages,
} from 'ai';
// import your tools and schemas

export async function POST(req: Request) {
  // get the last message from the client:
  const { message, id } = await req.json();

  // load the previous messages from the server:
  const previousMessages = await loadChat(id);

  // validate messages if they contain tools, metadata, or data parts:
  const validatedMessages = await validateUIMessages({
    // append the new message to the previous messages:
    messages: [...previousMessages, message],
    tools, // if using tools
    metadataSchema, // if using custom metadata
    dataSchemas, // if using custom data parts
  });

  const result = streamText({
    // ...
    messages: convertToModelMessages(validatedMessages),
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({
      stream: result.stream,
      originalMessages: validatedMessages,
      onEnd: ({ messages }) => {
        saveChat({ chatId: id, messages });
      },
    }),
  });
}
```

## 处理客户端断开连接

默认情况下，AI SDK 的 `streamText` 函数会对语言模型提供商使用背压，以防止
消耗尚未被请求的 token。

然而，这意味着当客户端断开连接时（例如关闭浏览器标签页或由于网络问题），
来自 LLM 的流将被中止，对话可能会处于损坏状态。

假设你已经有了[存储方案](#storing-messages)，你可以使用 `consumeStream` 方法在后端消费该流，
然后像往常一样保存结果。
`consumeStream` 有效地移除了背压，
这意味着即使客户端已经断开连接，结果也会被存储。

```tsx filename="app/api/chat/route.ts" highlight="19-21"
import {
  convertToModelMessages,
  createUIMessageStreamResponse,
  streamText,
  toUIMessageStream,
  UIMessage,
} from 'ai';
import { saveChat } from '@util/chat-store';

export async function POST(req: Request) {
  const { messages, chatId }: { messages: UIMessage[]; chatId: string } =
    await req.json();

  const result = streamText({
    model,
    messages: await convertToModelMessages(messages),
  });

  // consume the stream to ensure it runs to completion & triggers onEnd
  // even when the client response is aborted:
  result.consumeStream(); // no await

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({
      stream: result.stream,
      originalMessages: messages,
      onEnd: ({ messages }) => {
        saveChat({ chatId, messages });
      },
    }),
  });
}
```

当客户端在断开连接后重新加载页面时，聊天将从存储方案中恢复。

<Note>
  在生产应用中，你还应该在存储的消息中跟踪请求的状态（进行中、已完成），
  并在客户端使用它来处理客户端在断开连接后重新加载页面、但
  流式传输尚未完成的情况。
</Note>

为了更稳健地处理断开连接，你可能需要添加断开连接时的可恢复性。查看 [聊天机器人恢复流](/docs/ai-sdk-ui/chatbot-resume-streams) 文档以了解更多信息。
