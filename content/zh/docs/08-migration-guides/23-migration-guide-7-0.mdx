# 迁移 AI SDK 6.x 到 7.0

使用以下命令添加迁移技能：

```bash
npx skills add vercel/ai --skill migrate-ai-sdk-v6-to-v7
```

然后询问你的智能体：

```txt
使用 migrate-ai-sdk-v6-to-v7 技能，将我的应用从 AI SDK v6 迁移到 v7。
```

## 推荐的迁移流程

1. 备份你的项目。如果你使用版本控制系统，请确保所有之前的版本都已提交。
1. 升级到 AI SDK 7.0。
1. 遵循下面的重大变更指南。
1. 验证你的项目按预期工作。
1. 提交你的更改。

一个示例升级命令如下：

```
pnpm install ai @ai-sdk/react @ai-sdk/openai @ai-sdk/otel
```

## Codemod

AI SDK 提供了 Codemod 转换，以帮助你在某个功能被弃用、移除或以其他方式更改时升级你的代码库。

Codemod 是自动在你的代码库上运行的转换。它们允许你轻松地应用许多更改，而无需手动处理每个文件。

你可以通过从项目根目录运行以下命令来运行所有 v7 codemod（v6 -> v7 迁移）：

```sh
npx @ai-sdk/codemod v7
```

可以通过指定 codemod 的名称来运行单个 codemod：

```sh
npx @ai-sdk/codemod <codemod-name> <path>
```

例如，要运行一个特定的 v7 codemod：

```sh
npx @ai-sdk/codemod v7/rename-system-to-instructions src/
```

<Note>
  Codemod 旨在作为帮助你完成升级过程的工具。它们可能无法涵盖你需要进行的所有更改。你可能需要手动进行额外的更改。
</Note>

## 所有包

### 最低 Node.js 版本

AI SDK 7.0 需要 **Node.js 22** 或更高版本。该 SDK 已在 Node.js **22**、**24** 和 **26** 上测试。

Node.js 18 和 20 不再受支持。Node.js 22 已于 **2026 年 4 月 30 日** 结束维护；对于生产工作负载，建议使用 **Node.js 24 (LTS)** 或 **Node.js 26**。有关当前状态和支持时间线，请参阅 [Node.js 发布计划](https://nodejs.org/en/about/previous-releases)。

如果你强制执行最低 Node.js 版本，请更新 `package.json` 中的 `engines` 字段：

```json filename="package.json"
{
  "engines": {
    "node": ">=22"
  }
}
```

### 仅 ESM — 移除了 CommonJS 支持

所有 AI SDK 包现在仅支持 ESM。不再支持 `require()` 函数。

如果你的项目使用 CommonJS (`require()`)，请切换到 ESM `import` 语法：

```tsx filename="之前 (CommonJS)"
const { generateText } = require('ai');
const { openai } = require('@ai-sdk/openai');
```

```tsx filename="之后 (ESM)"
import { generateText } from 'ai';
import { openai } from '@ai-sdk/openai';
```

如果你的 `package.json` 尚未包含 `"type": "module"`，请添加它，或将你的文件重命名为使用 `.mjs` 扩展名。

## AI SDK Core

### Core API 重命名和移除

#### 提供商管理：移除已弃用的 `experimental_customProvider`

已弃用的 `experimental_customProvider` 导出已在 AI SDK 7 中移除。请将其替换为 `customProvider`。

```tsx filename="AI SDK 6"
import { experimental_customProvider } from 'ai';

export const myProvider = experimental_customProvider({
  languageModels: {
    // ...
  },
});
```

```tsx filename="AI SDK 7"
import { customProvider } from 'ai';

export const myProvider = customProvider({
  languageModels: {
    // ...
  },
});
```

这只是一个导入和符号重命名。`customProvider` 的选项和行为未更改。

#### 移除已弃用的 `experimental_generateImage` 导出

已弃用的 `experimental_generateImage` 导出已在 AI SDK 7 中移除。请将其替换为 `generateImage`。

已弃用的 `Experimental_GenerateImageResult` 类型导出也已移除。请将其替换为 `GenerateImageResult`。

```tsx filename="AI SDK 6"
import {
  experimental_generateImage,
  type Experimental_GenerateImageResult,
} from 'ai';

const result: Experimental_GenerateImageResult =
  await experimental_generateImage({
    model: yourImageModel,
    prompt: '一只吃竹子的小熊猫',
  });
```

```tsx filename="AI SDK 7"
import { generateImage, type GenerateImageResult } from 'ai';

const result: GenerateImageResult = await generateImage({
  model: yourImageModel,
  prompt: '一只吃竹子的小熊猫',
});
```

#### `experimental_transcribe` 重命名为 `transcribe`

转录 API 已从实验状态毕业，并已重命名为 `transcribe`。`Experimental_TranscriptionResult` 类型也已重命名为 `TranscriptionResult`。

```tsx filename="AI SDK 6"
import {
  experimental_transcribe as transcribe,
  type Experimental_TranscriptionResult,
} from 'ai';

const result: Experimental_TranscriptionResult = await transcribe({
  model: yourTranscriptionModel,
  audio,
});
```

```tsx filename="AI SDK 7"
import { transcribe, type TranscriptionResult } from 'ai';

const result: TranscriptionResult = await transcribe({
  model: yourTranscriptionModel,
  audio,
});
```

旧名称在 AI SDK 7 中继续作为已弃用的别名工作，并将在未来的主要版本中移除。

#### `experimental_generateSpeech` 重命名为 `generateSpeech`

语音生成函数已从实验状态毕业，并已重命名为 `generateSpeech`。`Experimental_SpeechResult` 类型也已重命名为 `SpeechResult`。

```tsx filename="AI SDK 6"
import { experimental_generateSpeech as generateSpeech } from 'ai';

const result = await generateSpeech({
  model: yourSpeechModel,
  text: '你好',
});
```

```tsx filename="AI SDK 7"
import { generateSpeech } from 'ai';

const result = await generateSpeech({
  model: yourSpeechModel,
  text: '你好',
});
```

旧的 `experimental_generateSpeech` 和 `Experimental_SpeechResult` 导出在 AI SDK 7 中继续作为已弃用的别名工作，并将在未来的主要版本中移除。

#### 结构化输出：移除已弃用的 `experimental_output` 选项和结果

已弃用的 `experimental_output` 选项已在 AI SDK 7 中移除。将所有剩余用法替换为 `output`。

已弃用的 `generateText()` 结果属性 `experimental_output` 也已移除。请改为读取 `result.output`。

此名称在 AI SDK 6 中已被弃用，因此如果你已经迁移到 `output`，则无需更改。否则，请同时更新调用选项和任何结果访问：

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  experimental_output: Output.object({
    schema: recipeSchema,
  }),
  prompt: '生成一个食谱。',
});

console.log(result.experimental_output);
```

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  output: Output.object({
    schema: recipeSchema,
  }),
  prompt: '生成一个食谱。',
});

console.log(result.output);
```

#### `CallSettings` 重命名为 `LanguageModelCallOptions` 和 `RequestOptions`

`CallSettings` 已拆分为 `LanguageModelCallOptions`（面向模型的选项）和 `RequestOptions`（传输选项）。在自定义包装器或辅助函数中替换用法：

- `CallSettings` → `LanguageModelCallOptions & Omit<RequestOptions, 'timeout'>`（注意：`CallSettings` 从未包含 `timeout`）

已弃用的 `CallSettings` 类型在 AI SDK 7 中仍然可用。

#### 停止条件辅助函数重命名：`stepCountIs` -> `isStepCount`

在工具循环停止条件中重命名导入和用法：

```tsx filename="之前"
import { stepCountIs } from 'ai';

stopWhen: stepCountIs(3);
```

```tsx filename="之后"
import { isStepCount } from 'ai';

stopWhen: isStepCount(3);
```

### 提示词和步骤准备

#### `system` 重命名为 `instructions`

用于系统指令的顶级提示词选项已从 `system` 重命名为 `instructions`。

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  system: '你是一个乐于助人的助手。',
  prompt: '你好！',
});
```

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  instructions: '你是一个乐于助人的助手。',
  prompt: '你好！',
});
```

这适用于接受 `prompt` 或 `messages` 的 AI SDK 函数，包括 `generateText`、`streamText`、`generateObject`、`streamObject` 和 `streamUI`。

相同的重命名适用于 `generateText` 和 `streamText` 的 `prepareStep` 结果，以及传递给 `experimental_repairToolCall` 的选项：

```tsx filename="AI SDK 6"
const result = streamText({
  model: yourModel,
  prompt: '你好！',
  prepareStep: () => ({
    system: '此步骤使用简洁的答案。',
  }),
});
```

```tsx filename="AI SDK 7"
const result = streamText({
  model: yourModel,
  prompt: '你好！',
  prepareStep: () => ({
    instructions: '此步骤使用简洁的答案。',
  }),
});
```

`system` 选项仍然作为已弃用的后备选项被接受。当同时提供 `instructions` 和 `system` 时，`instructions` 优先。

#### `prepareStep` 指令向前传递

在 AI SDK 7 中，从 `prepareStep` 返回的指令将在后续步骤中使用，直到 `prepareStep` 返回另一个 `instructions` 或 `system` 覆盖。这与 `prepareStep` 返回的 `messages` 向前传递的方式相匹配。

在 AI SDK 6 中，`prepareStep` 指令覆盖仅适用于当前步骤。后续步骤回退到顶级 `system` 指令，除非它们返回自己的覆盖。

如果你的 `prepareStep` 逻辑依赖于仅一步的指令覆盖，请为每个步骤显式返回所需的指令：

```tsx filename="AI SDK 7"
const result = streamText({
  model: yourModel,
  instructions: '使用默认行为。',
  prompt: '你好！',
  prepareStep: ({ stepNumber, initialInstructions }) => ({
    instructions:
      stepNumber === 0
        ? '对第一步使用特殊指令。'
        : initialInstructions,
  }),
});
```

`prepareStep` 回调接收 `instructions`（当前步骤的指令状态）和 `initialInstructions`（原始调用中的顶级指令值）。

如果你的工具调用修复函数将当前系统指令转发给另一个模型调用，请读取并传递 `instructions` 而不是 `system`：

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  tools,
  prompt: '你好！',
  experimental_repairToolCall: async ({ system, messages }) => {
    return repairWithModel({ system, messages });
  },
});
```

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  tools,
  prompt: '你好！',
  experimental_repairToolCall: async ({ instructions, messages }) => {
    return repairWithModel({ instructions, messages });
  },
});
```

`generateText`、`streamText` 和智能体的生命周期回调事件也使用 `instructions` 而不是 `system`：

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  experimental_onStart: ({ system }) => {
    console.log(system);
  },
});
```

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  onStart: ({ instructions }) => {
    console.log(instructions);
  },
});
```

#### 提示消息：默认拒绝 `prompt` 或 `messages` 中的系统消息

AI SDK 7 默认拒绝 `prompt` 或 `messages` 字段中的系统消息。系统指令通常应通过顶级 `instructions` 选项传递。

这可能会破坏包含 `{ role: 'system' }` 消息的旧持久化聊天或自定义提示数组：

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  messages: [
    { role: 'system', content: '你是一个乐于助人的助手。' },
    { role: 'user', content: '你好！' },
  ],
});
```

尽可能将系统指令移动到 `instructions` 选项：

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  instructions: '你是一个乐于助人的助手。',
  messages: [{ role: 'user', content: '你好！' }],
});
```

如果你需要保留已包含系统消息的现有聊天历史记录，请使用 `allowSystemInMessages: true` 选择加入以前的行为：

<Note type="warning">
  仅对受信任的消息使用 `allowSystemInMessages`。如果用户可以提交或编辑这些消息，他们可能会注入一条系统消息，从而覆盖或设置系统提示词。在大多数情况下，系统指令应仅通过受信任的服务器端代码使用 `instructions` 属性设置。
</Note>

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  allowSystemInMessages: true,
  messages: persistedMessages,
});
```

这适用于接受 `prompt` 或 `messages` 的 AI SDK 函数，包括 `generateText`、`streamText`、`generateObject`、`streamObject` 和 `streamUI`。

#### 移除已弃用的 `experimental_prepareStep` 选项

已弃用的 `experimental_prepareStep` 选项已在 AI SDK 7 中移除。将所有剩余用法替换为 `prepareStep`。

此选项在 AI SDK 5 中已被弃用，因此如果你已经迁移到 `prepareStep`，则无需更改。否则，请更新 `generateText` 调用：

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  tools: { weather },
  experimental_prepareStep: ({ stepNumber }) => {
    console.log('准备步骤', stepNumber);
    return {
      activeTools: ['weather'],
    };
  },
});
```

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  tools: { weather },
  prepareStep: ({ stepNumber }) => {
    console.log('准备步骤', stepNumber);
    return {
      activeTools: ['weather'],
    };
  },
});
```

#### `prepareStep` 消息覆盖向前传递

当 `prepareStep` 返回 `messages` 时，这些消息现在将用作后续步骤的基础。下一步将接收这些消息加上上一步的响应消息。

在 AI SDK 6 中，`messages` 覆盖仅适用于当前步骤。要保留该行为，请在 `prepareStep` 内部从 `initialMessages` 和 `responseMessages` 重建当前步骤的消息：

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  tools: { weather },
  prepareStep: ({ initialMessages, responseMessages }) => {
    return {
      messages: [
        ...initialMessages,
        ...responseMessages,
        // 在此处添加任何仅一步的消息更改
      ],
    };
  },
});
```

### 生命周期事件

#### `experimental_onStart` 重命名为 `onStart`

`generateText`、`streamText` 和智能体的生成开始回调已从 `experimental_onStart` 重命名为 `onStart`。

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  experimental_onStart: () => {
    console.log('生成已开始');
  },
});
```

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  onStart: () => {
    console.log('生成已开始');
  },
});
```

#### `experimental_onStepStart` 重命名为 `onStepStart`

`generateText`、`streamText` 和智能体的每步开始回调已从 `experimental_onStepStart` 重命名为 `onStepStart`。

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  experimental_onStepStart: ({ stepNumber }) => {
    console.log(`步骤 ${stepNumber} 已开始`);
  },
});
```

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  onStepStart: ({ stepNumber }) => {
    console.log(`步骤 ${stepNumber} 已开始`);
  },
});
```

#### `onFinish` 重命名为 `onEnd`

`generateText`、`streamText` 和智能体的最终生命周期回调已从 `onFinish` 重命名为 `onEnd`。

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  onFinish: ({ text }) => {
    console.log(text);
  },
});
```

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  onEnd: ({ text }) => {
    console.log(text);
  },
});
```

相同的重命名适用于 `streamText`、`Agent.generate()`、`Agent.stream()` 和 `ToolLoopAgent` 设置。`onFinish` 选项仍然作为已弃用的别名被接受。当同时提供 `onEnd` 和 `onFinish` 时，`onEnd` 优先。

#### `onStepFinish` 重命名为 `onStepEnd`

每步生命周期回调已从 `onStepFinish` 重命名为 `onStepEnd`。

```tsx filename="AI SDK 6"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  onStepFinish: ({ stepNumber, usage }) => {
    console.log(`步骤 ${stepNumber} 使用了 ${usage.totalTokens} 个令牌`);
  },
});
```

```tsx filename="AI SDK 7"
const result = await generateText({
  model: yourModel,
  prompt: '你好！',
  onStepEnd: ({ stepNumber, usage }) => {
    console.log(`步骤 ${stepNumber} 使用了 ${usage.totalTokens} 个令牌`);
  },
});
```

这适用于 `generateText`、`streamText`、`generateObject`、`streamObject`、智能体、工作流智能体和 UI 消息流辅助函数。遥测集成应实现 `onStepEnd`。

### 遥测

#### OpenTelemetry 移至 `@ai-sdk/otel`

OpenTelemetry span 收集不再内置于 `ai` 包中。要继续接收 OpenTelemetry 追踪，你必须安装新的 `@ai-sdk/otel` 包并全局注册 `OpenTelemetry` 实例。

### 结果消息更改

#### 步骤响应消息不再累积

在 AI SDK 7 中，每个 `StepResult` 上的 `step.response.messages` 仅包含该特定步骤产生的响应消息。

在 AI SDK 6 中，`step.response.messages` 累积了所有先前步骤的响应消息。如果你的应用程序从中间或最终步骤读取 `step.response.messages` 并期望完整的助手/工具消息历史记录，请改用顶级 `result.responseMessages`。

```tsx filename="AI SDK 7"
const result = await generateText({

  prompt: '如果需要，请使用工具',
  tools,
  stopWhen: isStepCount(5),
});

// 来自所有步骤的累积响应消息：
const responseMessages = result.responseMessages;

// 每个单独步骤产生的响应消息：
const stepMessages = result.steps.map(step => step.response.messages);
```

如果你特别需要从步骤结果重建响应消息，请展平每步消息：

```tsx filename="AI SDK 7"
const responseMessages = result.steps.flatMap(step => step.response.messages);
```

当你想要完整的响应消息历史记录时，首选 `result.responseMessages`。它还包括在第一个模型步骤之前产生的响应消息，例如来自输入消息中已批准工具调用的工具结果。

#### 上下文：`experimental_context` 变为工具 `context`，共享运行时数据移至 `runtimeContext`

在 AI SDK 7 中，以前作为 `experimental_context` 公开的工具回调选项已重命名为 `context`，并且现已稳定。

更大的行为变化是 AI SDK 现在区分了：

- 工具特定的 `context`，通过 `toolsContext` 传递给工具回调
- 共享的生成/智能体运行时数据，通过 `runtimeContext` 流动

在 AI SDK 6 中，工具通常从一个通用的运行时上下文对象中读取。在 AI SDK 7 中，每个工具都有自己的作用域 `context`，你通过 `toolsContext` 提供这些值，以工具名称作为键。

`tool()` 从其 `contextSchema` 推断工具 `context` 的类型，因此每个工具只能看到为该特定工具声明的字段。

在 AI SDK 6 中，工具代码通常访问 `experimental_context` 并必须手动转换它：

```tsx filename="AI SDK 6"
const weather = tool({
  inputSchema: z.object({
    location: z.string(),
  }),
  execute: async ({ location }, { experimental_context }) => {
    const { weatherApiKey } = experimental_context as {
      weatherApiKey: string;
    };

    return getWeather(location, weatherApiKey);
  },
});
```

在 AI SDK 7 中，将 `experimental_context` 重命名为 `context`，使用 `contextSchema` 声明工具特定的上下文，并通过 `toolsContext` 传递每个工具的值。然后，`execute` 回调、批准回调和工具输入生命周期钩子会自动接收一个类型化的 `context`：

```tsx filename="AI SDK 7"
const weather = tool({
  inputSchema: z.object({
    location: z.string(),
  }),
  contextSchema: z.object({
    apiKey: z.string(),
  }),
  execute: async ({ location }, { context: { apiKey } }) => {
    return getWeather(location, apiKey);
  },
});

const result = await generateText({
  model: yourModel,
  tools: { weather },
  runtimeContext: {
    requestId: 'req-123',
  },
  toolsContext: {
    weather: {
      apiKey: process.env.WEATHER_API_KEY!,
    },
  },
  prepareStep: async ({ runtimeContext, toolsContext }) => {
    console.log(runtimeContext.requestId);
    console.log(toolsContext.weather.apiKey);

    return {};
  },
});
```

使用 `runtimeContext` 存储应在 `prepareStep`、事件和步骤结果中可见的共享生成或智能体状态。工具回调不再从该共享对象中读取。工具的 `context` 现在来自其在 `toolsContext` 中的条目，因此它仅限于该工具在 `contextSchema` 中声明的字段。

潜在的破坏性问题：

- 如果你仍在工具回调中解构 `experimental_context`，请将其重命名为 `context`。
- 如果你以前为编排和工具传递一个共享的运行时对象，请将其拆分为 `runtimeContext` 和 `toolsContext`。
- 将工具特定的值移动到 `toolsContext` 下匹配的工具名称。
- 在 `generateText`、`streamText` 和 `ToolLoopAgent` 中，将共享的顶级 `context` 用法重命名为 `runtimeContext`。
- 将 `prepareStep` 用法从 `context` 重命名为 `runtimeContext`。
- 如果工具回调访问了未在其 `contextSchema` 中声明的字段，TypeScript 现在会报告错误。将这些字段添加到该工具的 schema 中。
- 如果你有假设 `experimental_context` 或 `context` 是 `unknown` 的辅助类型或包装器，请更新它们以接受泛型 `CONTEXT` 类型。
- 如果至少有一个工具声明了 `contextSchema`，则 `toolsContext` 变为必需，并且仅包含实际声明了上下文数据的工具。
- 如果你依赖每个工具回调看到相同的完整运行时对象，请将共享步骤数据移动到 `runtimeContext`，或者显式地在每个工具的 `toolsContext` 条目中提供所需的每个工具数据。

#### 迁移已弃用的 `needsApproval` 到 `toolApproval`

`tool()` 和 `dynamicTool()` 上的 `needsApproval` 属性在 AI SDK 7 中对于 `generateText`、`streamText` 和 `ToolLoopAgent` 已弃用。

将批准逻辑移动到调用或智能体上的 `toolApproval` 设置。这使批准策略靠近生成或智能体配置，并允许你根据请求而变化。

```tsx filename="AI SDK 6"
const deleteFile = tool({
  inputSchema: z.object({
    path: z.string(),
  }),
  needsApproval: async ({ path }) => !path.startsWith('/tmp/'),
  execute: async ({ path }) => {
    await removeFile(path);
    return { success: true };
  },
});

await streamText({
  model: yourModel,
  tools: { deleteFile },
});
```

```tsx filename="AI SDK 7"
const deleteFile = tool({

    path: z.string(),
  }),
  execute: async ({ path }) => {
    await removeFile(path);
    return { success: true };
  },
});

await streamText({
  model: yourModel,
  tools: { deleteFile },
  toolApproval: {
    deleteFile: async ({ path }) =>
      path.startsWith('/tmp/') ? undefined : 'user-approval',
  },
});
```

如果你使用 `needsApproval: true`，请将其迁移到 `toolApproval: { myTool: 'user-approval' }`。如果你使用 `needsApproval` 函数，请将该逻辑移动到每个工具的 `SingleToolApprovalFunction` 或通用的 `toolApproval` 回调中。此指南适用于 `generateText`、`streamText` 和 `ToolLoopAgent`。

#### 移除已弃用的 `ToolCallOptions` 类型

已弃用的 `ToolCallOptions` 类型已在 AI SDK 7 中移除。将所有剩余用法替换为 `ToolExecutionOptions`。

如果你在 AI SDK 6 中已经迁移离开了已弃用的名称，则无需更改。否则，请更新导入和类型引用：


### 工具和消息内容部分

#### 移除已弃用的 `media` 内容部分类型

已弃用的 `{ type: 'media' }` 工具结果内容部分已在 AI SDK 7 中移除。

对所有内联文件内容（包括图像）使用 `{ type: 'file-data' }`。

#### 工具结果内容：从 `image-*` 和 `file-*` 变体迁移到 `file`

所有用于 `toModelOutput` 结果的 `image-*` 和旧版 `file-*` 内容部分类型在 AI SDK 7 中已弃用，取而代之的是单个规范化的 `file` 变体，该变体镜像了顶级 `FilePart` 形状。在运行时自动应用迁移，因此现有的工具输出无需代码更改即可继续工作。但是，建议更新为新形状。

新形状带有一个标记的 `data` 判别联合，并且始终具有 `mediaType`：

- `{ type: 'file-data', data, mediaType, filename? }` → `{ type: 'file', mediaType, filename, data: { type: 'data', data } }`
- `{ type: 'file-url', url, mediaType }` → `{ type: 'file', mediaType, data: { type: 'url', url: new URL(url) } }`
- `{ type: 'file-reference', providerReference }` → `{ type: 'file', mediaType, data: { type: 'reference', reference: providerReference } }`

图像只是具有图像媒体类型的文件，因此 `image-*` 别名折叠成相同的形状——改为传递 `mediaType: 'image'`（或更具体的 `image/*` 子类型）：

- `{ type: 'image-data', data, mediaType }` → `{ type: 'file', mediaType, data: { type: 'data', data } }`
- `{ type: 'image-url', url }` → `{ type: 'file', mediaType: 'image', data: { type: 'url', url: new URL(url) } }`
- `{ type: 'image-file-reference', providerReference }` → `{ type: 'file', mediaType: 'image', data: { type: 'reference', reference: providerReference } }`

`-id` 内容部分类型（`file-id` 和 `image-file-id`）通常也已弃用，取而代之的是 `reference` 数据形状，它携带一个完整的 `ProviderReference`（一个提供商到文件 ID 的映射，如 `{ openai: 'file_123', anthropic: 'file_abc' }`），允许跨提供商重用相同的逻辑文件。单 ID `-id` 变体要求运行时知道 ID 属于哪个提供商；显式的引用形状消除了这种歧义：

- `{ type: 'file-id', fileId }` → `{ type: 'file', mediaType, data: { type: 'reference', reference: { [provider]: fileId } } }`
- `{ type: 'image-file-id', fileId }` → `{ type: 'file', mediaType: 'image', data: { type: 'reference', reference: { [provider]: fileId } } }`

新 `file` 变体上的 `mediaType` 接受完整的 IANA 类型（例如 `'image/png'`）或仅顶级段（例如 `'image'`、`'audio'`、`'video'`、`'text'`）。当仅提供顶级段时，子类型会尽可能从内联字节中自动检测。更新解析/验证和判别联合以处理单个规范化的 `file` 变体。

#### 消息部分：从已弃用的 `image` 部分迁移

`{ type: 'image', image, mediaType? }` 用户消息内容部分已弃用。请使用带有图像 `mediaType` 的 `{ type: 'file', data, mediaType }`。

```tsx filename="AI SDK 6"
{ type: 'image', image: bytes }
```

```tsx filename="AI SDK 7"
{ type: 'file', mediaType: 'image', data: bytes }
```

`FilePart` 上的 `mediaType` 现在接受完整的 IANA 类型（例如 `'image/png'`）或仅顶级段（例如 `'image'`）。当仅提供顶级段时，子类型会尽可能从内联字节中自动检测。

#### 消息部分：处理新的 `reasoning-file` 内容类型

某些模型现在可以返回文件作为其推理跟踪的一部分，与常规输出文件分开。这些文件以前使用 `file` 类型，现在位于一个不同的 `reasoning-file` 类型中。

更新所有详尽的部分处理（TypeScript 联合、`switch` 语句、运行时验证器、渲染器、序列化器）以支持 `type: 'reasoning-file'`。

同时审计任何从 `result.files` 或 `step.files` 读取生成文件的代码：推理中引用的文件现在在 `content` / `reasoning` 中表示为 `reasoning-file` 部分。实际上，这很少需要更新，因为模型通常在其推理中引用相同的文件，然后将其作为常规内容输出。在支持 `reasoning-file` 作为独立类型之前，这会导致相同的文件作为重复项出现在 `result.files` 或 `step.files` 中。

### 推理

#### 推理配置：移除重叠设置

新的顶级 `reasoning` 选项是控制推理努力的提供商无关方式。

在迁移到顶级 `reasoning` 选项时，从 `providerOptions` 中移除重叠的推理设置。

如果两者都存在，`providerOptions` 中的提供商特定推理设置优先，这可能会静默绕过你的新顶级 `reasoning` 配置。

## MCP 包

### MCP 传输：`redirect` 默认值从 `'follow'` 更改为 `'error'`

`MCPTransportConfig` 上的 `redirect` 选项（由 HTTP 和 SSE 传输使用）现在默认为 `'error'` 而不是 `'follow'`。这意味着默认拒绝 HTTP 重定向，以防止 MCP 服务器可能将请求重定向到意外主机的服务器端请求伪造 (SSRF) 攻击。

如果你的 MCP 服务器依赖 HTTP 重定向，请在传输配置中显式设置 `redirect: 'follow'`：

```tsx filename="AI SDK 6"
const mcpClient = await createMCPClient({
  transport: {
    type: 'http',
    url: 'https://your-server.com/mcp',
  },
});
```

```tsx filename="AI SDK 7"
const mcpClient = await createMCPClient({
  transport: {
    type: 'http',
    url: 'https://your-server.com/mcp',
    redirect: 'follow',
  },
});
```

如果你使用的 MCP 服务器不发出重定向，则无需更改——新的默认值更安全。

## Vue 包

### `Chat` 类已弃用，推荐使用 `useChat` 组合式函数

从 `@ai-sdk/vue` 导出的 `Chat` 类在 AI SDK 7 中已弃用，推荐使用新的 `useChat` 组合式函数。`useChat` 为 `messages`、`status` 和 `error` 公开了响应式引用，并在其初始化对象更改时自动重新创建底层聊天——因此响应式输入（路由参数、选定的模型等）无需手动编排即可流动。

```tsx filename="AI SDK 6"
const chat = new Chat({});
</script>

<template>
  <div v-for="m in chat.messages" :key="m.id">
    <!-- ... -->
  </div>
  <button @click="chat.sendMessage({ text: 'hi' })">发送</button>
</template>
```

```tsx filename="AI SDK 7"

import { useChat } from '@ai-sdk/vue';

const { messages, sendMessage } = useChat({
  id: chatId,

    api: `/api/chats/${chatId}`,
    body: { model: model.value },
  }),
});
</script>

<template>
  <div v-for="m in messages" :key="m.id">
    <!-- ... -->
  </div>
  <button @click="sendMessage({ text: 'hi' })">发送</button>

```

```tsx filename="AI SDK 7"

  id: chatId.value,
  transport: new DefaultChatTransport({
    api: `/api/chats/${chatId.value}`,
    body: { model: model.value },
  }),
}));
```

`Chat` 类继续作为已弃用的导出工作，因此你可以逐步迁移。
