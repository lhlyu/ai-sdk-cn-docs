# 自然语言 Postgres 指南

在本指南中，你将学习如何构建一个使用 AI 以自然语言与 PostgreSQL 数据库交互的应用。

该应用将：

- 从自然语言输入生成 SQL 查询
- 用通俗易懂的英语解释查询组件
- 创建图表以可视化查询结果

你可以在 [natural-language-postgres.vercel.app](https://natural-language-postgres.vercel.app) 找到该项目的完整版本。

## 项目设置

本项目使用以下技术栈：

- [Next.js](https://nextjs.org)（App Router）
- [AI SDK](/docs)
- [OpenAI](https://openai.com)
- [Zod](https://zod.dev)
- [Postgres](https://www.postgresql.org/) 与 [通过 Vercel Marketplace 的 Neon](https://vercel.com/marketplace/neon)
- [shadcn-ui](https://ui.shadcn.com) 和 [TailwindCSS](https://tailwindcss.com) 用于样式
- [Recharts](https://recharts.org) 用于数据可视化

## 生成 SQL 查询

### 提供上下文

为了让模型生成准确的 SQL 查询，它需要关于你的数据库模式、表和关系的上下文。你将通过一个提示词来传达这些信息，该提示词应包括：

1. 模式信息
2. 示例数据格式
3. 可用的 SQL 操作
4. 查询结构的最佳实践
5. 针对特定字段的细致建议

让我们编写一个包含所有这些信息的提示词：

```txt
你是一名 SQL（postgres）和数据可视化专家。你的工作是帮助用户编写 SQL 查询以检索他们需要的数据。表结构如下：

unicorns (
  id SERIAL PRIMARY KEY,
  company VARCHAR(255) NOT NULL UNIQUE,
  valuation DECIMAL(10, 2) NOT NULL,
  date_joined DATE,
  country VARCHAR(255) NOT NULL,
  city VARCHAR(255) NOT NULL,
  industry VARCHAR(255) NOT NULL,
  select_investors TEXT NOT NULL
);

只允许检索查询。

对于行业、公司名称和其他字符串字段，请使用 ILIKE 运算符，并使用 LOWER() 函数将搜索词和字段都转换为小写。例如：LOWER(industry) ILIKE LOWER('%search_term%')。

注意：select_investors 是一个逗号分隔的投资者列表。请修剪空白以确保正确分组。注意，某些字段可能为 null 或只有一个值。
当回答关于特定字段的问题时，请确保选择标识列（例如，Vercel 的估值是多少将选择 company 和 valuation）。

可用的行业有：
- healthcare & life sciences
- consumer & retail
- financial services
- enterprise tech
- insurance
- media & entertainment
- industrials
- health

如果用户要求的类别不在列表中，请根据上述列表进行推断。

注意：估值以十亿美元为单位，因此 10b 应为 10.0。
注意：如果用户要求比率，请将其作为小数返回。例如，0.1 表示 10%。

如果用户要求“随时间变化”的数据，请按年份返回。

当搜索 UK 或 USA 时，请分别写出 United Kingdom 或 United States。

每个查询都应返回可以在图表上绘制的定量数据！应始终至少有两列。如果用户要求单列，请返回该列及其计数。如果用户要求比率，请将比率作为小数返回。例如，0.1 表示 10%。
```

这个提示词有几个重要元素：

- 模式描述帮助模型准确理解要处理的数据字段
- 包含基于常见 SQL 模式处理查询的规则——例如，始终使用 ILIKE 进行不区分大小写的字符串匹配
- 解释如何处理数据集中的边缘情况，例如处理逗号分隔的投资者字段并确保正确处理空白
- 不是让模型猜测行业类别，而是提供数据中存在的确切列表，有助于避免不匹配
- 提示词有助于标准化数据转换——例如知道将“10b”解释为“10.0”十亿美元，或比率应为小数值
- 清晰的规则确保查询输出对图表友好，始终包含至少两列可绘制的数据

这种提示词结构为查询生成提供了坚实的基础，但你应该根据你的具体需求和你使用的模型进行实验和迭代。

### 创建 Server Action

提示词完成后，让我们创建一个 Server Action。

打开 `app/actions.ts`。你应该会看到一个已定义的操作（`runGeneratedSQLQuery`）。

添加一个新操作。此操作应为异步的，并接受一个参数——自然语言查询。

```ts filename="app/actions.ts"
/* ...文件其余部分... */

export const generateQuery = async (input: string) => {};
```

在此操作中，你将使用 AI SDK 中的 `generateText` 函数和 `Output`，这允许你将模型的输出约束为预定义的模式。这个过程有时称为结构化输出，确保模型仅返回 SQL 查询，而不包含任何需要手动解析的额外前缀、解释或格式。

```ts filename="app/actions.ts"
/* ...其他导入... */
import { generateText, Output } from 'ai';
import { z } from 'zod';

/* ...文件其余部分... */

export const generateQuery = async (input: string) => {
  'use server';
  try {
    const result = await generateText({
      model: 'openai/gpt-4o',
      instructions: `你是一名 SQL（postgres）...`, // 上述系统提示词 - 为简洁起见省略
      prompt: `生成检索用户所需数据所需的查询：${input}`,
      output: Output.object({
        schema: z.object({
          query: z.string(),
        }),
      }),
    });
    return result.output.query;
  } catch (e) {
    console.error(e);
    throw new Error('生成查询失败');
  }
};
```

注意，你使用 `zod`（一个 TypeScript 模式验证库）将输出约束为名为 `query` 的单个字符串字段。这将确保模型仅返回 SQL 查询本身。然后返回结果输出。

### 更新前端

有了 Server Action，你现在可以更新前端，在用户提交自然语言查询时调用此操作。在根页面（`app/page.tsx`）中，你应该会看到一个在用户提交查询时调用的 `handleSubmit` 函数。

导入 `generateQuery` 函数并使用用户的输入调用它。

```typescript filename="app/page.tsx" highlight="21"
/* ...其他导入... */
import { runGeneratedSQLQuery, generateQuery } from './actions';

/* ...文件其余部分... */

const handleSubmit = async (suggestion?: string) => {
  clearExistingData();

  const question = suggestion ?? inputValue;
  if (inputValue.length === 0 && !suggestion) return;

  if (question.trim()) {
    setSubmitted(true);
  }

  setLoading(true);
  setLoadingStep(1);
  setActiveQuery('');

  try {
    const query = await generateQuery(question);

    if (query === undefined) {
      toast.error('发生错误。请重试。');
      setLoading(false);
      return;
    }

    setActiveQuery(query);
    setLoadingStep(2);

    const companies = await runGeneratedSQLQuery(query);
    const columns = companies.length > 0 ? Object.keys(companies[0]) : [];
    setResults(companies);
    setColumns(columns);

    setLoading(false);
  } catch (e) {
    toast.error('发生错误。请重试。');
    setLoading(false);
  }
};

/* ...文件其余部分... */
```

现在，当用户提交自然语言查询（例如“有多少独角兽来自旧金山？”）时，该问题将被发送到你新创建的 Server Action。Server Action 将调用模型，传入你的系统提示词和用户的查询，并以结构化格式返回生成的 SQL 查询。然后，此查询被传递给 `runGeneratedSQLQuery` 操作以针对你的数据库运行。结果随后保存在本地状态中并显示给用户。

保存文件，确保开发服务器正在运行，然后在浏览器中前往 `localhost:3000`。尝试提交一个自然语言查询，查看生成的 SQL 查询和结果。你应该会看到在输入字段下方生成并显示一个 SQL 查询。你还应该看到查询结果以表格形式显示在输入字段下方。

尝试点击 SQL 查询以查看完整查询（如果太长无法在输入字段中显示）。你应该会看到输入字段右侧有一个带问号图标的按钮。点击此按钮目前没有任何作用，但你将在下一步中为其添加“解释查询”功能。

## 解释 SQL 查询

接下来，让我们添加用通俗易懂的英语解释 SQL 查询的功能。此功能通过将生成的 SQL 查询分解为逻辑部分，帮助用户理解其工作原理。
与 SQL 查询生成一样，你需要一个提示词来指导模型解释查询。

让我们为解释查询功能编写一个提示词：

```txt
你是一名 SQL（postgres）专家。你的工作是向用户解释你编写的用于检索他们要求的数据的 SQL 查询。表结构如下：
unicorns (
  id SERIAL PRIMARY KEY,
  company VARCHAR(255) NOT NULL UNIQUE,
  valuation DECIMAL(10, 2) NOT NULL,
  date_joined DATE,
  country VARCHAR(255) NOT NULL,
  city VARCHAR(255) NOT NULL,
  industry VARCHAR(255) NOT NULL,
  select_investors TEXT NOT NULL
);

当你解释时，你必须取查询的一部分，然后对其进行解释。每个“部分”都应该是唯一的。因此，在像“SELECT * FROM unicorns limit 20”这样的查询中，部分可以是“SELECT *”、“FROM UNICORNS”、“LIMIT 20”。
如果某个部分没有解释，请包含它，但将解释留空。
```

与生成 SQL 查询的提示词一样，你向模型提供数据库的模式。此外，你提供一个示例，说明查询的每个部分可能是什么样子。这有助于模型理解查询的结构以及如何将其分解为逻辑部分。

### 创建 Server Action

添加一个新的 Server Action 来为 SQL 查询生成解释。

此操作接受两个参数——原始自然语言输入和生成的 SQL 查询。

```ts filename="app/actions.ts"
/* ...文件其余部分... */

export const explainQuery = async (input: string, sqlQuery: string) => {
  'use server';
  try {
    const result = await generateText({
      model: 'openai/gpt-4o',
      instructions: `你是一名 SQL（postgres）专家。...`, // 上述系统提示词 - 为简洁起见省略
      prompt: `解释你为检索用户想要的数据而生成的 SQL 查询。假设用户不是 SQL 专家。将查询分解为步骤。要简洁。

      用户查询：
      ${input}

      生成的 SQL 查询：
      ${sqlQuery}`,
    });
    return result.text;
  } catch (e) {
    console.error(e);
    throw new Error('生成查询失败');
  }
};
```

此操作使用 `generateText` 函数。但是，你尚未定义输出模式。让我们在另一个文件中定义它，以便它也可以在你的组件中用作类型。

更新你的 `lib/types.ts` 文件以包含解释的模式：

```ts filename="lib/types.ts"
import { z } from 'zod';

/* ...文件其余部分... */

export const explanationSchema = z.object({
  section: z.string(),
  explanation: z.string(),
});

export type QueryExplanation = z.infer<typeof explanationSchema>;
```

此模式定义了模型将生成的解释的结构。每个解释将有一个 `section` 和一个 `explanation`。`section` 是被解释的查询部分，`explanation` 是该部分的通俗英语解释。回到你的 `actions.ts` 文件，导入并使用 `explanationSchema`：

```ts filename="app/actions.ts" highlight="2,19,20"
// 其他导入
import { explanationSchema } from '@/lib/types';

/* ...文件其余部分... */

export const explainQuery = async (input: string, sqlQuery: string) => {
  'use server';
  try {
    const result = await generateText({
      model: 'openai/gpt-4o',
      instructions: `你是一名 SQL（postgres）专家。...`, // 上述系统提示词 - 为简洁起见省略
      prompt: `解释你为检索用户想要的数据而生成的 SQL 查询。假设用户不是 SQL 专家。将查询分解为步骤。要简洁。

      用户查询：
      ${input}

      生成的 SQL 查询：
      ${sqlQuery}`,
      output: Output.array({ element: explanationSchema }),
    });
    return result.output;
  } catch (e) {
    console.error(e);
    throw new Error('生成查询失败');
  }
};
```

<Note>
  你可以使用 `Output.array()` 向模型指示你期望返回一个符合模式的对象数组。
</Note>

## 可视化查询结果

最后，让我们在图表中可视化查询结果。有两种方法可以采用：

1. 将查询和数据都发送给模型，并要求其以可视化就绪的格式返回数据。虽然这提供了对可视化的完全控制，但它要求模型发回所有数据，这会显著增加延迟和成本。

2. 将查询和数据发送给模型，并要求其生成一个图表配置（固定大小且 token 不多），适当地映射你的数据。此配置指定如何可视化信息，同时传递来自你自然语言查询的见解。重要的是，这不需要模型返回完整数据集。

由于你事先不知道 SQL 查询或数据形状，让我们使用第二种方法，根据查询结果和用户意图动态生成图表配置。

### 生成图表配置

对于此功能，你将创建一个 Server Action，该操作接受查询结果和用户的原始自然语言查询，以确定最佳可视化方法。你的应用已经设置为使用 `shadcn` 图表（底层使用 [`Recharts`](https://recharts.org/en-US/)），因此模型需要生成：

- 图表类型（条形图、折线图、面积图或饼图）
- 轴映射
- 视觉样式

让我们首先在 `lib/types.ts` 中定义图表配置的模式：

```ts filename="lib/types.ts"
/* ...文件其余部分... */
```

### 更新图表组件

有了操作，你需要在收到查询结果后自动触发它。这确保可视化在数据加载后几乎立即出现。

```typescript filename="app/page.tsx" highlight="38,39"
/* ...其他导入... */
import { getCompanies, generateQuery, generateChartConfig } from './actions';

/* ...文件其余部分... */
const handleSubmit = async (suggestion?: string) => {
  clearExistingData();

  const question = suggestion ?? inputValue;
  if (inputValue.length === 0 && !suggestion) return;

  if (question.trim()) {
    setSubmitted(true);
  }

  setLoading(true);
  setLoadingStep(1);
  setActiveQuery('');

  try {
    const query = await generateQuery(question);

    if (query === undefined) {
      toast.error('发生错误。请重试。');
      setLoading(false);
      return;
    }

    setActiveQuery(query);
    setLoadingStep(2);

    const companies = await runGeneratedSQLQuery(query);
    const columns = companies.length > 0 ? Object.keys(companies[0]) : [];
    setResults(companies);
    setColumns(columns);

    setLoading(false);

    const { config } = await generateChartConfig(companies, question);
    setChartConfig(config);
  } catch (e) {
    toast.error('发生错误。请重试。');
    setLoading(false);
  }
};
```

4. 允许在表格和图表视图之间切换
