# 自然语言 Postgres 指南

在本指南中，你将学习如何构建一个使用 AI 通过自然语言与 PostgreSQL 数据库交互的应用。

该应用将：

- 从自然语言输入生成 SQL 查询
- 用通俗易懂的英语解释查询组件
- 创建图表以可视化查询结果

你可以在 [natural-language-postgres.vercel.app](https://natural-language-postgres.vercel.app) 找到该项目的完整版本。

## 项目设置

本项目使用以下技术栈：

- [Next.js](https://nextjs.org)（App Router）
- [AI SDK](/docs)
- [OpenAI](https://openai.com)
- [Zod](https://zod.dev)
- [Postgres](https://www.postgresql.org/) 与 [通过 Vercel Marketplace 的 Neon](https://vercel.com/marketplace/neon)
- [shadcn-ui](https://ui.shadcn.com) 和 [TailwindCSS](https://tailwindcss.com) 用于样式
- [Recharts](https://recharts.org) 用于数据可视化

## 生成 SQL 查询

### 提供上下文

为了让模型生成准确的 SQL 查询，它需要关于你的数据库模式、表和关系的上下文。你将通过一个提示词来传达这些信息，该提示词应包括：

1. 模式信息
2. 示例数据格式
3. 可用的 SQL 操作
4. 查询结构的最佳实践
5. 针对特定字段的细致建议

让我们编写一个包含所有这些信息的提示词：

```txt
You are a SQL (postgres) and data visualization expert. Your job is to help the user write a SQL query to retrieve the data they need. The table schema is as follows:

unicorns (
  id SERIAL PRIMARY KEY,
  company VARCHAR(255) NOT NULL UNIQUE,
  valuation DECIMAL(10, 2) NOT NULL,
  date_joined DATE,
  country VARCHAR(255) NOT NULL,
  city VARCHAR(255) NOT NULL,
  industry VARCHAR(255) NOT NULL,
  select_investors TEXT NOT NULL
);

Only retrieval queries are allowed.

For things like industry, company names and other string fields, use the ILIKE operator and convert both the search term and the field to lowercase using LOWER() function. For example: LOWER(industry) ILIKE LOWER('%search_term%').

Note: select_investors is a comma-separated list of investors. Trim whitespace to ensure you're grouping properly. Note, some fields may be null or have only one value.
When answering questions about a specific field, ensure you are selecting the identifying column (ie. what is Vercel's valuation would select company and valuation').

The industries available are:
- healthcare & life sciences
- consumer & retail
- financial services
- enterprise tech
- insurance
- media & entertainment
- industrials
- health

If the user asks for a category that is not in the list, infer based on the list above.

Note: valuation is in billions of dollars so 10b would be 10.0.
Note: if the user asks for a rate, return it as a decimal. For example, 0.1 would be 10%.

If the user asks for 'over time' data, return by year.

When searching for UK or USA, write out United Kingdom or United States respectively.

EVERY QUERY SHOULD RETURN QUANTITATIVE DATA THAT CAN BE PLOTTED ON A CHART! There should always be at least two columns. If the user asks for a single column, return the column and the count of the column. If the user asks for a rate, return the rate as a decimal. For example, 0.1 would be 10%.
```

这个提示词有几个重要元素：

- 模式描述帮助模型准确理解要处理的数据字段
- 包含基于常见 SQL 模式处理查询的规则 - 例如，始终使用 ILIKE 进行不区分大小写的字符串匹配
- 解释如何处理数据集中的边缘情况，例如处理逗号分隔的投资者字段并确保正确处理空白
- 不是让模型猜测行业类别，而是提供数据中存在的确切列表，有助于避免不匹配
- 提示词有助于标准化数据转换 - 例如知道将 "10b" 解释为 "10.0" 亿美元，或比率应为十进制值
- 清晰的规则确保查询输出对图表友好，始终包含至少两列可绘制的数据

这种提示词结构为查询生成提供了坚实的基础，但你应该根据你的具体需求和你使用的模型进行实验和迭代。

### 创建 Server Action

提示词完成后，让我们创建一个 Server Action。

打开 `app/actions.ts`。你应该会看到一个已定义的操作（`runGeneratedSQLQuery`）。

添加一个新操作。此操作应为异步并接受一个参数 - 自然语言查询。

```ts filename="app/actions.ts"
/* ...rest of the file... */

export const generateQuery = async (input: string) => {};
```

在此操作中，你将使用 AI SDK 中的 `generateText` 函数和 `Output`，它允许你将模型的输出限制为预定义的模式。这个过程有时称为结构化输出，确保模型只返回 SQL 查询，而不包含任何需要手动解析的额外前缀、解释或格式。

```ts filename="app/actions.ts"
/* ...other imports... */
import { generateText, Output } from 'ai';
import { z } from 'zod';

/* ...rest of the file... */

export const generateQuery = async (input: string) => {
  'use server';
  try {
    const result = await generateText({
      model: 'openai/gpt-4o',
      system: `You are a SQL (postgres) ...`, // SYSTEM PROMPT AS ABOVE - OMITTED FOR BREVITY
      prompt: `Generate the query necessary to retrieve the data the user wants: ${input}`,
      output: Output.object({
        schema: z.object({
          query: z.string(),
        }),
      }),
    });
    return result.output.query;
  } catch (e) {
    console.error(e);
    throw new Error('Failed to generate query');
  }
};
```

注意，你使用 `zod`（一个 TypeScript 模式验证库）将输出限制为名为 `query` 的单个字符串字段。这将确保模型只返回 SQL 查询本身。然后返回结果输出。

### 更新前端

有了 Server Action，你现在可以更新前端，在用户提交自然语言查询时调用此操作。在根页面（`app/page.tsx`）中，你应该会看到一个 `handleSubmit` 函数，在用户提交查询时被调用。

导入 `generateQuery` 函数并使用用户的输入调用它。

```typescript filename="app/page.tsx" highlight="21"
/* ...other imports... */
import { runGeneratedSQLQuery, generateQuery } from './actions';

/* ...rest of the file... */

const handleSubmit = async (suggestion?: string) => {
  clearExistingData();

  const question = suggestion ?? inputValue;
  if (inputValue.length === 0 && !suggestion) return;

  if (question.trim()) {
    setSubmitted(true);
  }

  setLoading(true);
  setLoadingStep(1);
  setActiveQuery('');

  try {
    const query = await generateQuery(question);

    if (query === undefined) {
      toast.error('An error occurred. Please try again.');
      setLoading(false);
      return;
    }

    setActiveQuery(query);
    setLoadingStep(2);

    const companies = await runGeneratedSQLQuery(query);
    const columns = companies.length > 0 ? Object.keys(companies[0]) : [];
    setResults(companies);
    setColumns(columns);

    setLoading(false);
  } catch (e) {
    toast.error('An error occurred. Please try again.');
    setLoading(false);
  }
};

/* ...rest of the file... */
```

现在，当用户提交自然语言查询（例如 "有多少独角兽来自旧金山？"）时，该问题将被发送到你新创建的 Server Action。Server Action 将调用模型，传入你的系统提示词和用户的查询，并以结构化格式返回生成的 SQL 查询。然后，此查询被传递给 `runGeneratedSQLQuery` 操作，以针对你的数据库运行查询。结果随后保存在本地状态中并显示给用户。

保存文件，确保开发服务器正在运行，然后在浏览器中前往 `localhost:3000`。尝试提交一个自然语言查询，查看生成的 SQL 查询和结果。你应该会看到在输入字段下方生成并显示一个 SQL 查询。你还应该看到查询结果以表格形式显示在输入字段下方。

尝试点击 SQL 查询以查看完整查询（如果太长而无法在输入字段中显示）。你应该会看到输入字段右侧有一个带问号图标的按钮。点击此按钮目前没有任何作用，但你将在下一步中为其添加 "解释查询" 功能。

## 解释 SQL 查询

接下来，让我们添加用通俗易懂的英语解释 SQL 查询的功能。此功能通过将生成的 SQL 查询分解为逻辑部分，帮助用户理解其工作原理。
与 SQL 查询生成一样，你需要一个提示词来指导模型解释查询。

让我们为解释查询功能编写一个提示词：

```txt
You are a SQL (postgres) expert. Your job is to explain to the user the SQL query you wrote to retrieve the data they asked for. The table schema is as follows:
unicorns (
  id SERIAL PRIMARY KEY,
  company VARCHAR(255) NOT NULL UNIQUE,
  valuation DECIMAL(10, 2) NOT NULL,
  date_joined DATE,
  country VARCHAR(255) NOT NULL,
  city VARCHAR(255) NOT NULL,
  industry VARCHAR(255) NOT NULL,
  select_investors TEXT NOT NULL
);

When you explain you must take a section of the query, and then explain it. Each "section" should be unique. So in a query like: "SELECT * FROM unicorns limit 20", the sections could be "SELECT *", "FROM UNICORNS", "LIMIT 20".
If a section doesn't have any explanation, include it, but leave the explanation empty.
```

与生成 SQL 查询的提示词一样，你向模型提供数据库的模式。此外，你提供一个示例，说明查询的每个部分可能是什么样子。这有助于模型理解查询的结构以及如何将其分解为逻辑部分。

### 创建 Server Action

添加一个新的 Server Action 来为 SQL 查询生成解释。

此操作接受两个参数 - 原始自然语言输入和生成的 SQL 查询。

```ts filename="app/actions.ts"
/* ...rest of the file... */

export const explainQuery = async (input: string, sqlQuery: string) => {
  'use server';
  try {
    const result = await generateText({
      model: 'openai/gpt-4o',
      system: `You are a SQL (postgres) expert. ...`, // SYSTEM PROMPT AS ABOVE - OMITTED FOR BREVITY
      prompt: `Explain the SQL query you generated to retrieve the data the user wanted. Assume the user is not an expert in SQL. Break down the query into steps. Be concise.

      User Query:
      ${input}

      Generated SQL Query:
      ${sqlQuery}`,
    });
    return result.text;
  } catch (e) {
    console.error(e);
    throw new Error('Failed to generate query');
  }
};
```

此操作使用 `generateText` 函数。但是，你尚未定义输出模式。让我们在另一个文件中定义它，以便它也可以在你的组件中用作类型。

更新你的 `lib/types.ts` 文件以包含解释的模式：

```ts filename="lib/types.ts"
import { z } from 'zod';

/* ...rest of the file... */

export const explanationSchema = z.object({
  section: z.string(),
  explanation: z.string(),
});

export type QueryExplanation = z.infer<typeof explanationSchema>;
```

此模式定义了模型将生成的解释的结构。每个解释将有一个 `section` 和一个 `explanation`。`section` 是被解释的查询部分，`explanation` 是该部分的通俗英语解释。回到你的 `actions.ts` 文件，导入并使用 `explanationSchema`：

```ts filename="app/actions.ts" highlight="2,19,20"
// other imports
import { explanationSchema } from '@/lib/types';

/* ...rest of the file... */

export const explainQuery = async (input: string, sqlQuery: string) => {
  'use server';
  try {
    const result = await generateText({
      model: 'openai/gpt-4o',
      system: `You are a SQL (postgres) expert. ...`, // SYSTEM PROMPT AS ABOVE - OMITTED FOR BREVITY
      prompt: `Explain the SQL query you generated to retrieve the data the user wanted. Assume the user is not an expert in SQL. Break down the query into steps. Be concise.

      User Query:
      ${input}

      Generated SQL Query:
      ${sqlQuery}`,
      output: Output.array({ element: explanationSchema }),
    });
    return result.output;
  } catch (e) {
    console.error(e);
    throw new Error('Failed to generate query');
  }
};
```

<Note>
  你可以使用 `Output.array()` 向模型指示你期望返回一个与模式匹配的对象数组。
</Note>

## 可视化查询结果

最后，让我们在图表中可视化查询结果。你可以采用两种方法：

1. 将查询和数据都发送给模型，并要求其以可视化就绪格式返回数据。虽然这提供了对可视化的完全控制，但它要求模型发回所有数据，这显著增加了延迟和成本。

2. 将查询和数据发送给模型，并要求其生成一个图表配置（固定大小且 token 不多），适当地映射你的数据。此配置指定如何可视化信息，同时传递来自自然语言查询的见解。重要的是，这不需要模型返回完整数据集。

由于你事先不知道 SQL 查询或数据形状，让我们使用第二种方法，根据查询结果和用户意图动态生成图表配置。

### 生成图表配置

对于此功能，你将创建一个 Server Action，它接受查询结果和用户的原始自然语言查询，以确定最佳可视化方法。你的应用已经设置为使用 `shadcn` 图表（底层使用 [`Recharts`](https://recharts.org/en-US/)），因此模型需要生成：

- 图表类型（条形图、折线图、面积图或饼图）
- 轴映射
- 视觉样式

让我们首先在 `lib/types.ts` 中定义图表配置的模式：

```ts filename="lib/types.ts"
/* ...rest of the file... */

export const configSchema = z
  .object({
    description: z
      .string()
      .describe(
        'Describe the chart. What is it showing? What is interesting about the way the data is displayed?',
      ),
    takeaway: z.string().describe('What is the main takeaway from the chart?'),
    type: z.enum(['bar', 'line', 'area', 'pie']).describe('Type of chart'),
    title: z.string(),
    xKey: z.string().describe('Key for x-axis or category'),
    yKeys: z
      .array(z.string())
      .describe(
        'Key(s) for y-axis values this is typically the quantitative column',
      ),
    multipleLines: z
      .boolean()
      .describe(
        'For line charts only: whether the chart is comparing groups of data.',
      )
      .optional(),
    measurementColumn: z
      .string()
      .describe(
        'For line charts only: key for quantitative y-axis column to measure against (eg. values, counts etc.)',
      )
      .optional(),
    lineCategories: z
      .array(z.string())
      .describe(
        'For line charts only: Categories used to compare different lines or data series. Each category represents a distinct line in the chart.',
      )
      .optional(),
    colors: z
      .record(
        z.string().describe('Any of the yKeys'),
        z.string().describe('Color value in CSS format (e.g., hex, rgb, hsl)'),
      )
      .describe('Mapping of data keys to color values for chart elements')
      .optional(),
    legend: z.boolean().describe('Whether to show legend'),
  })
  .describe('Chart configuration object');

export type Config = z.infer<typeof configSchema>;
```

<Note>
  用新的类型替换现有的 `export type Config = any;` 类型。
</Note>

此模式广泛使用 Zod 的 `.describe()` 函数，为模型提供关于你期望在图表配置中的每个键的额外上下文。这将帮助模型理解每个键的用途并生成更准确的结果。

另一个值得注意的重要技术是，你定义了 `description` 和 `takeaway` 字段。这不仅有助于用户快速理解图表的含义以及他们应该从中获得什么，而且还迫使模型在尝试生成轴和列等配置属性之前，首先生成数据的描述。这将帮助模型生成更准确和相关的图表配置。

### 创建 Server Action

在 `app/actions.ts` 中创建一个新操作：

```ts
/* ...other imports... */
import { Config, configSchema, explanationsSchema, Result } from '@/lib/types';

/* ...rest of the file... */

export const generateChartConfig = async (
  results: Result[],
  userQuery: string,
) => {
  'use server';

  try {
    const { output: config } = await generateText({
      model: 'openai/gpt-4o',
      system: 'You are a data visualization expert.',
      prompt: `Given the following data from a SQL query result, generate the chart config that best visualises the data and answers the users query.
      For multiple groups use multi-lines.

      Here is an example complete config:
      export const chartConfig = {
        type: "pie",
        xKey: "month",
        yKeys: ["sales", "profit", "expenses"],
        colors: {
          sales: "#4CAF50",    // Green for sales
          profit: "#2196F3",   // Blue for profit
          expenses: "#F44336"  // Red for expenses
        },
        legend: true
      }

      User Query:
      ${userQuery}

      Data:
      ${JSON.stringify(results, null, 2)}`,
      output: Output.object({ schema: configSchema }),
    });

    // Override with shadcn theme colors
    const colors: Record<string, string> = {};
    config.yKeys.forEach((key, index) => {
      colors[key] = `hsl(var(--chart-${index + 1}))`;
    });

    const updatedConfig = { ...config, colors };
    return { config: updatedConfig };
  } catch (e) {
    console.error(e);
    throw new Error('Failed to generate chart suggestion');
  }
};
```

### 更新图表组件

有了操作，你需要在收到查询结果后自动触发它。这确保了可视化在数据加载后几乎立即出现。

更新根页面（`app/page.tsx`）中的 `handleSubmit` 函数，在运行查询后生成并设置图表配置：

```typescript filename="app/page.tsx" highlight="38,39"
/* ...other imports... */
import { getCompanies, generateQuery, generateChartConfig } from './actions';

/* ...rest of the file... */
const handleSubmit = async (suggestion?: string) => {
  clearExistingData();

  const question = suggestion ?? inputValue;
  if (inputValue.length === 0 && !suggestion) return;

  if (question.trim()) {
    setSubmitted(true);
  }

  setLoading(true);
  setLoadingStep(1);
  setActiveQuery('');

  try {
    const query = await generateQuery(question);

    if (query === undefined) {
      toast.error('An error occurred. Please try again.');
      setLoading(false);
      return;
    }

    setActiveQuery(query);
    setLoadingStep(2);

    const companies = await runGeneratedSQLQuery(query);
    const columns = companies.length > 0 ? Object.keys(companies[0]) : [];
    setResults(companies);
    setColumns(columns);

    setLoading(false);

    const { config } = await generateChartConfig(companies, question);
    setChartConfig(config);
  } catch (e) {
    toast.error('An error occurred. Please try again.');
    setLoading(false);
  }
};

/* ...rest of the file... */
```

现在，当用户提交查询时，应用将：

1. 生成并运行 SQL 查询
2. 显示表格结果
3. 为结果生成图表配置
4. 允许在表格和图表视图之间切换

回到浏览器，用几个查询测试应用。你应该会看到表格结果后出现图表可视化。
