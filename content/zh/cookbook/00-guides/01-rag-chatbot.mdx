在深入之前，让我们先了解一下什么是 RAG，以及为什么要使用它。

### 什么是 RAG？

RAG 代表检索增强生成。简单来说，RAG 就是为大语言模型（LLM）提供与提示词相关的特定信息的过程。

### 为什么 RAG 很重要？

虽然 LLM 很强大，但它们能够推理的信息仅限于训练时所使用的数据。当向 LLM 询问其训练数据之外的信息时，这个问题就会显现出来，比如专有数据或模型训练截止日期之后发生的常识。RAG 通过获取与提示词相关的信息，然后将其作为上下文传递给模型来解决这个问题。

用一个简单的例子来说明，想象一下向模型询问你最喜欢的食物：

```txt
**input**
What is my favorite food?

**generation**
I don't have access to personal information about individuals, including their
favorite foods.
```

不出所料，模型并不知道。但想象一下，在提示词之外，模型还收到了一些额外的上下文：

```txt
**input**
Respond to the user's prompt using only the provided context.
user prompt: 'What is my favorite food?'
context: user loves chicken nuggets

**generation**
Your favorite food is chicken nuggets!
```

就这样，你通过为查询提供相关信息增强了模型的生成。假设模型拥有适当的信息，它现在极有可能对用户的查询返回准确的响应。但它如何检索相关信息呢？答案依赖于一个叫做嵌入的概念。

<Note>
  你可以为你的 RAG 应用获取任何上下文（例如 Google 搜索）。嵌入和向量数据库只是实现语义搜索的一种特定检索方法。
</Note>

### 嵌入

[嵌入](/docs/ai-sdk-core/embeddings)是一种将单词、短语或图像表示为高维空间中向量的方法。在这个空间中，相似的词彼此靠近，词之间的距离可以用来衡量它们的相似度。

在实践中，这意味着如果你嵌入 `cat` 和 `dog` 这两个词，你会期望它们在向量空间中被绘制在彼此附近。计算两个向量之间相似度的过程称为“余弦相似度”，值为 1 表示高度相似，值为 -1 表示高度对立。

<Note>
  如果这看起来很复杂，不用担心。高层次的了解就足以让你入门了！如需更深入地了解嵌入，请查看[这份指南](https://jalammar.github.io/illustrated-word2vec/)。
</Note>

如上所述，嵌入是一种表示**单词和短语**语义含义的方法。这里的含义是，嵌入的输入越大，嵌入的质量就越低。那么，你如何处理比简单短语更长的内容的嵌入呢？

### 分块

分块是指将特定源材料分解成更小片段的过程。分块有许多不同的方法，值得进行实验，因为最有效的方法可能因用例而异。一种简单且常见的分块方法（也是本指南中将使用的方法）是按句子分隔书面内容。

一旦你的源材料被适当地分块，你就可以嵌入每一块，然后将嵌入和块一起存储在数据库中。嵌入可以存储在任何支持向量的数据库中。在本教程中，你将使用 [Postgres](https://www.postgresql.org/) 以及 [pgvector](https://github.com/pgvector/pgvector) 插件。

### 创建嵌入表

目前，你的应用程序有一个表（`resources`），它有一个列（`content`）用于存储内容。记住，每个 `resource`（源材料）都必须被分块、嵌入，然后存储。让我们创建一个名为 `embeddings` 的表来存储这些块。

创建一个新文件（`lib/db/schema/embeddings.ts`）并添加以下代码：

```tsx filename="lib/db/schema/embeddings.ts"
import { nanoid } from '@/lib/utils';
import { index, pgTable, text, varchar, vector } from 'drizzle-orm/pg-core';
import { resources } from './resources';

export const embeddings = pgTable(
  'embeddings',
  {
    id: varchar('id', { length: 191 })
      .primaryKey()
      .$defaultFn(() => nanoid()),
    resourceId: varchar('resource_id', { length: 191 }).references(
      () => resources.id,
      { onDelete: 'cascade' },
    ),
    content: text('content').notNull(),
    embedding: vector('embedding', { dimensions: 1536 }).notNull(),
  },
  table => ({
    embeddingIndex: index('embeddingIndex').using(
      'hnsw',
      table.embedding.op('vector_cosine_ops'),
    ),
  }),
);
```

这个表有四列：

- `id` - 唯一标识符
- `resourceId` - 指向完整源材料的外键关系
- `content` - 纯文本块
- `embedding` - 纯文本块的向量表示

要执行相似度搜索，你还需要在此列上包含一个索引（[HNSW](https://github.com/pgvector/pgvector?tab=readme-ov-file#hnsw) 或 [IVFFlat](https://github.com/pgvector/pgvector?tab=readme-ov-file#ivfflat)）以获得更好的性能。

要将此更改推送到数据库，请运行以下命令：

<Snippet text="pnpm db:push" />

### 生成块

记住，要创建嵌入，你将从一段源材料（长度未知）开始，将其分解成更小的块，嵌入每个块，然后将块保存到数据库。让我们从创建一个将源材料分解成小块的函数开始。

```tsx filename="lib/ai/embedding.ts"
const generateChunks = (input: string): string[] => {
  return input
    .trim()
    .split('.')
    .filter(i => i !== '');
};
```

这个函数将接受一个输入字符串并按句号分割，过滤掉任何空项。这将返回一个字符串数组。在你的项目中值得尝试不同的分块技术，因为最佳技术会有所不同。

### 生成嵌入

让我们添加一个函数来生成嵌入。将以下代码复制到你的 `lib/ai/embedding.ts` 文件中。

```tsx filename="lib/ai/embedding.ts" highlight="1,3,12-21"
import { embedMany } from 'ai';

const embeddingModel = 'openai/text-embedding-ada-002';

const generateChunks = (input: string): string[] => {
  return input
    .trim()
    .split('.')
    .filter(i => i !== '');
};

export const generateEmbeddings = async (
  value: string,
): Promise<Array<{ embedding: number[]; content: string }>> => {
  const chunks = generateChunks(value);
  const { embeddings } = await embedMany({
    model: embeddingModel,
    values: chunks,
  });
  return embeddings.map((e, i) => ({ content: chunks[i], embedding: e }));
};
```

在这段代码中，你首先定义要用于嵌入的模型。在这个例子中，你使用的是 OpenAI 的 `text-embedding-ada-002` 嵌入模型。

接下来，你创建一个名为 `generateEmbeddings` 的异步函数。这个函数将接受源材料（`value`）作为输入，并返回一个对象数组的 promise，每个对象包含一个嵌入和内容。在函数内部，你首先为输入生成块。然后，你将这些块传递给从 AI SDK 导入的 [`embedMany`](/docs/reference/ai-sdk-core/embed-many) 函数，该函数将返回你传入的块的嵌入。最后，你映射并返回嵌入，格式已准备好保存到数据库。

### 更新 Server Action

打开 `lib/actions/resources.ts` 文件。这个文件有一个函数 `createResource`，顾名思义，它允许你创建一个资源。

```tsx filename="lib/actions/resources.ts"
'use server';

import {
  NewResourceParams,
  insertResourceSchema,
  resources,
} from '@/lib/db/schema/resources';
import { db } from '../db';

export const createResource = async (input: NewResourceParams) => {
  try {
    const { content } = insertResourceSchema.parse(input);

    const [resource] = await db
      .insert(resources)
      .values({ content })
      .returning();

    return 'Resource successfully created.';
  } catch (e) {
    if (e instanceof Error)
      return e.message.length > 0 ? e.message : 'Error, please try again.';
  }
};
```

这个函数是一个 [Server Action](https://nextjs.org/docs/app/building-your-application/data-fetching/server-actions-and-mutations#with-client-components)，由文件顶部的 `“use server”;` 指令表示。这意味着它可以在你的 Next.js 应用程序中的任何地方被调用。这个函数将接受一个输入，通过 [Zod](https://zod.dev) schema 运行以确保它符合正确的 schema，然后在数据库中创建一个新资源。这是生成和存储新创建资源的嵌入的理想位置。

使用以下代码更新文件：

```tsx filename="lib/actions/resources.ts" highlight="9-10,21-27,29"
'use server';

import {
  NewResourceParams,
  insertResourceSchema,
  resources,
} from '@/lib/db/schema/resources';
import { db } from '../db';
import { generateEmbeddings } from '../ai/embedding';
import { embeddings as embeddingsTable } from '../db/schema/embeddings';

export const createResource = async (input: NewResourceParams) => {
  try {
    const { content } = insertResourceSchema.parse(input);

    const [resource] = await db
      .insert(resources)
      .values({ content })
      .returning();

    const embeddings = await generateEmbeddings(content);
    await db.insert(embeddingsTable).values(
      embeddings.map(embedding => ({
        resourceId: resource.id,
        ...embedding,
      })),
    );

    return 'Resource successfully created and embedded.';
  } catch (error) {
    return error instanceof Error && error.message.length > 0
      ? error.message
      : 'Error, please try again.';
  }
};
```

首先，你调用上一步创建的 `generateEmbeddings` 函数，传入源材料（`content`）。一旦你有了源材料的嵌入（`e`），你就可以将它们保存到数据库，同时将 `resourceId` 与每个嵌入一起传递。

### 创建根页面

太好了！让我们构建前端。AI SDK 的 [`useChat`](/docs/reference/ai-sdk-ui/use-chat) hook 允许你轻松地为你的智能体创建对话式用户界面。

将你的根页面（`app/page.tsx`）替换为以下代码。

```tsx filename="app/page.tsx"
'use client';

import { useChat } from '@ai-sdk/react';
import { useState } from 'react';

export default function Chat() {
  const [input, setInput] = useState('');
  const { messages, sendMessage } = useChat();
  return (
    <div className="flex flex-col w-full max-w-md py-24 mx-auto stretch">
      <div className="space-y-4">
        {messages.map(m => (
          <div key={m.id} className="whitespace-pre-wrap">
            <div>
              <div className="font-bold">{m.role}</div>
              {m.parts.map(part => {
                switch (part.type) {
                  case 'text':
                    return <p>{part.text}</p>;
                }
              })}
            </div>
          </div>
        ))}
      </div>

      <form
        onSubmit={e => {
          e.preventDefault();
          sendMessage({ text: input });
          setInput('');
        }}
      >
        <input
          className="fixed bottom-0 w-full max-w-md p-2 mb-8 border border-gray-300 rounded shadow-xl"
          value={input}
          placeholder="Say something..."
          onChange={e => setInput(e.currentTarget.value)}
        />
      </form>
    </div>
  );
}
```

`useChat` hook 支持从你的 AI 提供商（你将通过 Vercel AI Gateway 使用 OpenAI）流式传输聊天消息，并在收到新消息时自动更新 UI。在你的组件中管理聊天输入状态。

运行以下命令启动 Next.js 开发服务器：

<Snippet text="pnpm run dev" />

前往 [http://localhost:3000](http://localhost:3000/)。你应该会看到一个空白屏幕，底部浮动着一个输入栏。尝试发送一条消息。消息会在 UI 中显示一瞬间然后消失。这是因为你还没有设置相应的 API 路由来调用模型！默认情况下，`useChat` 会向 `/api/chat` 端点发送一个 POST 请求，并将 `messages` 作为请求体。

<Note>你可以在 useChat 配置对象中自定义端点</Note>

### 创建 API 路由

在 Next.js 中，你可以使用 [Route Handlers](https://nextjs.org/docs/app/building-your-application/routing/route-handlers) 为给定路由创建自定义请求处理器。Route Handlers 在 `route.ts` 文件中定义，可以导出 `GET`、`POST`、`PUT`、`PATCH` 等 HTTP 方法。

通过运行以下命令在 `app/api/chat/route.ts` 创建一个文件：

<Snippet text="mkdir -p app/api/chat && touch app/api/chat/route.ts" />

打开文件并添加以下代码：

```tsx filename="app/api/chat/route.ts"
import {
  convertToModelMessages,
  createUIMessageStreamResponse,
  streamText,
  toUIMessageStream,
  UIMessage,
} from 'ai';

// Allow streaming responses up to 30 seconds
export const maxDuration = 30;

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: 'openai/gpt-6-astra',
    messages: await convertToModelMessages(messages),
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

在这段代码中，你声明并导出了一个名为 POST 的异步函数。你从请求体中检索 `messages`，然后将它们与你想要使用的模型一起传递给从 AI SDK 导入的 [`streamText`](/docs/reference/ai-sdk-core/stream-text) 函数。最后，你以 `UIMessageStreamResponse` 格式返回模型的响应。

回到浏览器再次尝试发送消息。你应该会看到模型的响应直接流式传输进来！

### 优化你的提示词

虽然你现在有了一个可用的智能体，但它并没有做任何特别的事情。

让我们添加系统指令来优化和限制模型的行为。在这种情况下，你希望模型只使用它检索到的信息来生成响应。使用以下代码更新你的路由处理器：

```tsx filename="app/api/chat/route.ts" highlight="18-20"
import {
  convertToModelMessages,
  createUIMessageStreamResponse,
  streamText,
  toUIMessageStream,
  UIMessage,
} from 'ai';

// Allow streaming responses up to 30 seconds
export const maxDuration = 30;

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: 'openai/gpt-6-astra',
    instructions: `You are a helpful assistant. Check your knowledge base before answering any questions.
    Only respond to questions using information from tool calls.
    if no relevant information is found in the tool calls, respond, "Sorry, I don't know."`,

  });

```

以目前的形式，你的智能体现在，嗯，没什么用。你如何给模型添加和查询信息的能力？

### 使用工具

[工具](/docs/foundations/tools)是一个可以被模型调用以执行特定任务的函数。你可以把工具想象成你给模型的一个程序，它可以在认为必要时运行。

让我们看看如何创建一个工具，让模型能够创建、嵌入并将资源保存到你的智能体知识库中。

### 添加资源工具

使用以下代码更新你的路由处理器：

```tsx filename="app/api/chat/route.ts" highlight="25-36"
import { createResource } from '@/lib/actions/resources';
import {
  convertToModelMessages,
  createUIMessageStreamResponse,
  streamText,
  tool,
  toUIMessageStream,
  UIMessage,
} from 'ai';
import { z } from 'zod';

// Allow streaming responses up to 30 seconds
export const maxDuration = 30;

export async function POST(req: Request) {
  const { messages }: { messages: UIMessage[] } = await req.json();

  const result = streamText({
    model: 'openai/gpt-6-astra',
    instructions: `You are a helpful assistant. Check your knowledge base before answering any questions.
    Only respond to questions using information from tool calls.
    if no relevant information is found in the tool calls, respond, "Sorry, I don't know."`,
    messages: await convertToModelMessages(messages),
    tools: {
      addResource: tool({
        description: `add a resource to your knowledge base.
          If the user provides a random piece of knowledge unprompted, use this tool without asking for confirmation.`,
        inputSchema: z.object({
          content: z
            .string()
            .describe('the content or resource to add to the knowledge base'),
        }),
        execute: async ({ content }) => createResource({ content }),
      }),
    },
  });

  return createUIMessageStreamResponse({
    stream: toUIMessageStream({ stream: result.stream }),
  });
}
```

在这段代码中，你定义了一个名为 `addResource` 的工具。这个工具有三个元素：

- **description**：工具的描述，将影响工具何时被选择。
- **inputSchema**：[Zod schema](/docs/foundations/tools#schema-specification-and-validation-with-zod)，定义工具运行所需的输入。
- **execute**：一个异步函数，使用工具调用的参数进行调用。

简单来说，在每次生成时，模型将决定是否应该调用该工具。如果它认为应该调用该工具，它将提取输入，然后向 `messages` 数组追加一个类型为 `tool-call` 的新 `message`。然后 AI SDK 将使用 `tool-call` 消息提供的参数运行 `execute` 函数。

回到浏览器，告诉模型你最喜欢的食物。你应该会在 UI 中看到一个空响应。发生了什么吗？让我们看看。在新的终端窗口中运行以下命令。

让我们在 UI 中做一些更改，以便在工具被调用时通知用户。回到你的根页面（`app/page.tsx`）并添加以下代码：


### 使用多步调用改善用户体验

如果模型也能总结操作就好了。然而，从技术上讲，一旦模型调用了一个工具，它就已经完成了生成，因为它“生成”了一个工具调用。你如何实现这种期望的行为呢？

AI SDK 有一个名为 [`stopWhen`](/docs/ai-sdk-core/tools-and-tool-calling#multi-step-calls) 的功能，它允许在模型生成工具调用时设置停止条件。如果这些停止条件尚未满足，AI SDK 将自动将工具调用结果发送回模型！

打开你的路由处理器（`app/api/chat/route.ts`）并将以下键添加到 `streamText` 配置对象中：


### 检索资源工具

模型现在可以向你的知识库添加和嵌入任意信息。但是，它仍然无法查询它。让我们创建一个新工具，让模型能够通过在知识库中查找相关信息来回答问题。

要查找相似内容，你需要嵌入用户的查询，在数据库中搜索语义相似性，然后将这些项与查询一起作为上下文传递给模型。为了实现这一点，让我们更新你的嵌入逻辑文件（`lib/ai/embedding.ts`）：

```tsx filename="lib/ai/embedding.ts" highlight="1-3,26-48"
import { embed, embedMany } from 'ai';
import { db } from '../db';
import { cosineDistance, desc, gt, sql } from 'drizzle-orm';
import { embeddings } from '../db/schema/embeddings';

const embeddingModel = 'openai/text-embedding-ada-002';

const generateChunks = (input: string): string[] => {
  return input
    .trim()
    .split('.')
    .filter(i => i !== '');
};

export const generateEmbeddings = async (
  value: string,
): Promise<Array<{ embedding: number[]; content: string }>> => {
  const chunks = generateChunks(value);
  const { embeddings } = await embedMany({
    model: embeddingModel,
    values: chunks,
  });
  return embeddings.map((e, i) => ({ content: chunks[i], embedding: e }));
};

export const generateEmbedding = async (value: string): Promise<number[]> => {
  const input = value.replaceAll('\\n', ' ');
  const { embedding } = await embed({
    model: embeddingModel,
    value: input,
  });
  return embedding;
};

export const findRelevantContent = async (userQuery: string) => {
  const userQueryEmbedded = await generateEmbedding(userQuery);
  const similarity = sql<number>`1 - (${cosineDistance(
    embeddings.embedding,
    userQueryEmbedded,
  )})`;
  const similarGuides = await db
    .select({ name: embeddings.content, similarity })
    .from(embeddings)
    .where(gt(similarity, 0.5))
    .orderBy(t => desc(t.similarity))
    .limit(4);
  return similarGuides;
};
```

在这段代码中，你添加了两个函数：

- `generateEmbedding`：从输入字符串生成单个嵌入
- `findRelevantContent`：嵌入用户的查询，在数据库中搜索相似项，然后返回相关项

完成这些后，就进入最后一步：创建工具。

回到你的路由处理器（`app/api/chat/route.ts`）并添加一个名为 `getInformation` 的新工具：
