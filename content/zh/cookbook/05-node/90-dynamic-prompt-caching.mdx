# 动态提示词缓存

在构建智能体时，随着对话的增长，API 成本会迅速累积。许多提供商都提供提示词缓存功能，允许你缓存对话前缀，从而显著降低重复上下文的成本。

本示例展示了一种模式，你可以将其复制到项目中，并根据具体的提供商和缓存策略进行自定义。示例实现开箱即用地涵盖了 Anthropic 推荐的方法，但你可以根据需要扩展它以支持其他提供商。

这种模式在以下场景中特别有用：

1. **构建长对话智能体** - 多轮智能体交互会累积上下文，而这些上下文会在每次请求时被重新发送。
2. **大量使用工具** - 工具调用和结果会带来显著的 token 开销，缓存可以从中受益。

对于非 Anthropic 模型，消息会原样传递，因此可以安全地用于与提供商无关的代码中。

## 实现

该工具会向你的消息添加 Anthropic 的 `cacheControl` 指令，将最后一条消息标记为 `{ type: "ephemeral" }`。这会告诉 Anthropic 缓存到该点为止的所有内容，因此后续请求只需为新内容支付全价。

### 工作原理

该函数会检测模型提供商并应用相应的缓存策略。在此实现中，它通过检查提供商名称和模型 ID 来识别 Anthropic 模型。当找到 Anthropic 模型时，它会向数组中的最后一条消息添加 `providerOptions`，并设置 `cacheControl: { type: "ephemeral" }`。根据 Anthropic 的文档：“将最后一条消息的最后一个块标记为 cache_control，以便对话可以被增量缓存。”

对于非 Anthropic 模型，该函数会原样返回你的消息。你可以通过添加检测逻辑和提供商特定的选项，将此模式扩展为支持其他提供商。

### 消息级与块级缓存控制

你可能会注意到，此实现是在**消息级**添加 `providerOptions`，而 Anthropic 的 API 期望 `cache_control` 位于**内容块级**。AI SDK 会自动处理这种转换。

当你在消息上设置 `providerOptions` 时，SDK 会在构建 API 请求时将其应用到最后一个内容块。例如：

```ts
// What you write (message-level)
{
  role: 'user',
  content: [
    { type: 'text', text: 'First part' },
    { type: 'text', text: 'Second part' },
  ],
  providerOptions: {
    anthropic: { cacheControl: { type: 'ephemeral' } },
  },
}

// What the SDK sends to Anthropic (block-level)
{
  "role": "user",
  "content": [
    { "type": "text", "text": "First part" },
    { "type": "text", "text": "Second part", "cache_control": { "type": "ephemeral" } }
  ]
}
```

这种行为是有意为之的，并且在用户消息、助手消息和工具结果中保持一致。如果你需要更精细的控制，也可以直接在单个内容部分上设置 `providerOptions`，其优先级高于消息级设置。

### 工具函数

```ts
import type { ModelMessage, JSONValue, LanguageModel } from 'ai';

function isAnthropicModel(model: LanguageModel): boolean {
  if (typeof model === 'string') {
    return model.includes('anthropic') || model.includes('claude');
  }
  return (
    model.provider === 'anthropic' ||
    model.provider.includes('anthropic') ||
    model.modelId.includes('anthropic') ||
    model.modelId.includes('claude')
  );
}

export function addCacheControlToMessages({
  messages,
  model,
  providerOptions = {
    anthropic: { cacheControl: { type: 'ephemeral' } },
  },
}: {
  messages: ModelMessage[];
  model: LanguageModel;
  providerOptions?: Record<string, Record<string, JSONValue>>;
}): ModelMessage[] {
  if (messages.length === 0) return messages;
  if (!isAnthropicModel(model)) return messages;

  return messages.map((message, index) => {
    if (index === messages.length - 1) {
      return {
        ...message,
        providerOptions: {
          ...message.providerOptions,
          ...providerOptions,
        },
      };
    }
    return message;
  });
}
```

## 使用该工具

使用 `prepareStep` 回调，结合 `generateText` 和 `stopWhen`，将该工具集成到你的智能体中：

```ts
import { anthropic } from '@ai-sdk/anthropic';
import { generateText, tool, isStepCount } from 'ai';
import { z } from 'zod';
import { addCacheControlToMessages } from './add-cache-control-to-messages';

async function main() {
  const result = await generateText({
    model: anthropic('claude-sonnet-5'),
    prompt: 'Help me analyze this codebase and suggest improvements.',
    stopWhen: isStepCount(10),
    tools: {
      // your tools here
      analyzeFile: tool({
        description: 'Analyze a file in the codebase',
        inputSchema: z.object({
          path: z.string().describe('Path to the file'),
        }),
        execute: async ({ path }) => {
          // implementation
          return { analysis: `Analysis of ${path}` };
        },
      }),
    },
    prepareStep: ({ messages, model }) => ({
      messages: addCacheControlToMessages({ messages, model }),
    }),
  });

  console.log(result.text);
}

main().catch(console.error);
```

如果需要，你也可以自定义缓存控制选项：

```ts
prepareStep: ({ messages, model }) => ({
  messages: addCacheControlToMessages({
    messages,
    model,
    providerOptions: {
      anthropic: { cacheControl: { type: "ephemeral" } },
    },
  }),
}),
```

## 注意事项

使用此工具时，请记住以下几点：

1. **提供商特定行为** - 此实现针对 Anthropic 模型。对于其他提供商，消息会原样传递。你可以扩展此模式以支持更多提供商。
2. **最小 token 阈值** - Anthropic 要求达到最小 token 数量后缓存才会激活。短对话可能无法受益。其他提供商可能有类似的要求。
3. **缓存生命周期** - Anthropic 的临时缓存 TTL 为 5 分钟。不活跃的对话会丢失其缓存。请查看你的提供商文档以了解缓存持续时间详情。
4. **成本结构** - 使用 Anthropic 时，缓存 token 的成本为输入 token 的 10%，但缓存写入的成本要高出 25%。当缓存命中超过缓存未命中时，你就能节省费用。成本结构因提供商而异。
