# SigNoz 可观测性

[SigNoz](https://signoz.io/) 是一款满足你所有监控和可观测性需求的单一工具。以下是选择 SigNoz 的几个理由：

- 用于可观测性（日志、指标和追踪）的单一工具
- 构建于 [OpenTelemetry](https://opentelemetry.io/) 之上，这一开源标准让你摆脱任何形式的供应商锁定
- 关联的日志、指标和追踪，在调试时提供更丰富的上下文
- 使用 ClickHouse（Uber 和 Cloudflare 等公司也在使用）作为数据存储——一种极其快速且高度优化的可观测性数据存储
- DIY 查询构建器、PromQL 和 ClickHouse 查询，满足你围绕可观测性数据查询的所有用例

# 设置

- 创建 [SigNoz Cloud 账户](https://signoz.io/teams/)
- 生成 SigNoz 摄取密钥

## 为你的 Next.js 应用添加埋点

查看详细说明，了解如何在 Next.js 应用中设置 OpenTelemetry 埋点，并在 SigNoz 中查看应用追踪，请点击[此处](https://signoz.io/docs/instrumentation/opentelemetry-nextjs/)。

## 将追踪直接发送到 SigNoz Cloud

**步骤 1.** 安装 OpenTelemetry 包

```bash
npm install @vercel/otel @opentelemetry/api @ai-sdk/otel
```

**步骤 2.** 更新 **`next.config.mjs`** 以包含 instrumentationHook

> 仅在使用 NextJs 14 及以下版本时才需要此步骤

```jsx
/** @type {import('next').NextConfig} */
const nextConfig = {
  // include instrumentationHook experimental feature
  experimental: {
    instrumentationHook: true,
  },
};
export default nextConfig;
```

**步骤 3.** 创建 **`instrumentation.ts`** 文件（位于项目根目录）

```jsx
import { registerTelemetry } from 'ai';
import { LegacyOpenTelemetry } from '@ai-sdk/otel';
import { registerOTel, OTLPHttpJsonTraceExporter } from '@vercel/otel';
// Add otel logging
import { diag, DiagConsoleLogger, DiagLogLevel } from '@opentelemetry/api';
diag.setLogger(new DiagConsoleLogger(), DiagLogLevel.ERROR); // set diag log level to DEBUG when debugging

registerTelemetry(new LegacyOpenTelemetry());

export function register() {
  registerOTel({
    serviceName: '<service_name>',
    traceExporter: new OTLPHttpJsonTraceExporter({
      url: 'https://ingest.<region>.signoz.cloud:443/v1/traces',
      headers: { 'signoz-ingestion-key': '<your-ingestion-key>' },
    }),
  });
}
```

- **`<service_name>`** 是你的服务名称
- 将 **`<region>`** 设置为与你的 SigNoz Cloud [**区域**](https://signoz.io/docs/ingestion/signoz-cloud/overview/#endpoint)匹配
- 将 **`<your-ingestion-key>`** 替换为你的 SigNoz [**摄取密钥**](https://signoz.io/docs/ingestion/signoz-cloud/keys/)

> instrumentation 文件应位于项目根目录，而不是 app 或 pages 目录内。如果你使用 src 文件夹，则将文件放在 src 内，与 pages 和 app 并列。

你的 Next.js 应用现在应该已正确添加埋点。

## 为 Vercel AI SDK 启用遥测

Vercel AI SDK 使用 [OpenTelemetry](https://signoz.io/blog/what-is-opentelemetry/) 收集遥测数据。OpenTelemetry 是一个开源可观测性框架，旨在为收集遥测数据提供标准化的埋点。

## 启用遥测

查看有关 Vercel AI SDK 遥测选项的更详细信息，请访问[此处](https://ai-sdk.dev/docs/ai-sdk-core/telemetry#telemetry)。

安装 `@ai-sdk/otel` 并将 `registerTelemetry` 添加到你的 `instrumentation.ts`（参见上面的步骤 3）后，每次 AI SDK 调用都会自动捕获遥测数据：

```jsx
const result = await generateText({
  model: openai('gpt-6-luna'),
  prompt: 'Write a short story about a cat.',
});
```

你还可以控制是否记录函数的输入值和输出值。默认情况下，两者均已启用。你可以通过将 `recordInputs` 和 `recordOutputs` 选项设置为 `false` 来禁用它们。

```jsx
telemetry: { recordInputs: false, recordOutputs: false }
```

出于隐私、数据传输和性能方面的考虑，禁用输入和输出的记录可能会很有用。例如，如果输入包含敏感信息，你可能希望禁用输入记录。

## 遥测元数据

你可以提供 `functionId` 来标识遥测数据所属的函数，并提供 `context` 以在遥测数据中包含附加信息。

```jsx
const result = await generateText({
  model: openai('gpt-6-luna'),
  prompt: 'Write a short story about a cat.',
  context: {
    something: 'custom',
    someOtherThing: 'other-value',
  },
  telemetry: {
    functionId: 'my-awesome-function',
  },
});
```

## 自定义 Tracer

如果你希望追踪使用 `@opentelemetry/api` 单例提供的 `TracerProvider` 之外的 `TracerProvider`，请将自定义 `Tracer` 传递给 `LegacyOpenTelemetry` 构造函数：

```jsx
import { registerTelemetry, generateText } from 'ai';
import { LegacyOpenTelemetry } from '@ai-sdk/otel';

const tracerProvider = new NodeTracerProvider();
registerTelemetry(
  new LegacyOpenTelemetry({
    tracer: tracerProvider.getTracer('ai'),
  }),
);

const result = await generateText({
  model: openai('gpt-6-luna'),
  prompt: 'Write a short story about a cat.',
});
```

你的 Vercel AI SDK 命令现在应该会自动发出追踪、span 和事件。你可以在[此处](https://ai-sdk.dev/docs/ai-sdk-core/telemetry#collected-data)找到有关生成的 span 和事件类型的更多详细信息。

最后，你应该能够在 Signoz Cloud 的 traces 标签页下查看这些数据。
