# TypeSafe 提供商

[TypeSafe](https://typesafe.ai) 提供商支持实验性决策 API，原生支持 Choice、Score 和 Boolean 答案。它会在一次请求中针对同一状态发送所有问题。

## 设置

安装提供商：

```sh
pnpm add @ai-sdk/typesafe-ai
```

设置 `TYPESAFE_AI_API_KEY` 环境变量。导入默认提供商或配置一个实例：

```ts
import { createTypeSafeAi, typeSafeAi } from '@ai-sdk/typesafe-ai';

const customTypeSafe = createTypeSafeAi({
  apiKey: 'your-api-key',
});
```

`createTypeSafeAi` 接受以下参数：

| 设置      | 描述                                                                   |
| --------- | ---------------------------------------------------------------------- |
| `apiKey`  | API 密钥；默认为 `TYPESAFE_AI_API_KEY`。                               |
| `baseURL` | 默认为 `TYPESAFE_AI_BASE_URL`，然后是 `https://api.typesafe.ai/v1`。   |
| `headers` | 额外的请求头。                                                         |
| `fetch`   | 自定义 fetch 实现。                                                    |

使用 `TYPESAFE_AI_BASE_URL` 将默认的 `typeSafeAi` 实例路由到受信任的代理或自托管的 TypeSafe 兼容服务器：

```sh
TYPESAFE_AI_BASE_URL=http://127.0.0.1:8766/v1
```

传递给 `createTypeSafeAi` 的显式 `baseURL` 优先于环境变量。配置的服务器会接收 API 密钥和决策状态，并且必须实现 TypeSafe 的 `POST /systemone` API。

## 决策

```ts
import { typeSafeAi } from '@ai-sdk/typesafe-ai';
import { experimental_decide } from 'ai';

const result = await experimental_decide({
  model: typeSafeAi.decisionModel('jev-latest'),
  state: {
    message: 'I was charged twice. Please refund the duplicate.',
  },
  questions: {
    department: {
      type: 'choice',
      instructions: 'Which team should handle this?',
      criteria: {
        billing: { includes: ['Charges', 'Invoices', 'Refunds'] },
        technical: ['Bugs', 'Outages'],
        other: null,
      },
    },
    severity: {
      type: 'score',
      instructions: 'How severe is the issue?',
      criteria: ['Cosmetic', 'Workaround exists', 'Blocking; no workaround'],
    },
    requestsRefund: {
      type: 'boolean',
      instructions: 'Is the customer requesting money back?',
    },
  },
});

console.log(result.answers.department.choice);
console.log(result.answers.severity.score);
console.log(result.answers.requestsRefund.probability);
console.log(result.usage);
```

使用 `jev-latest` 或其他 TypeSafe 模型 ID。响应中包含实际的模型 ID，例如别名背后解析出的版本。使用模型实例、自定义别名或已注册的提供商。当 `typeSafeAi` 被显式配置为 `globalThis.AI_SDK_DEFAULT_PROVIDER` 时，你可以直接传入 `model: 'jev-latest'`。参见[模型别名与注册表](/docs/ai-sdk-core/decisions#model-aliases-and-registries)。

该提供商包含以下模型 ID 和别名：

| 模型 ID       | 描述                                              |
| ------------- | ------------------------------------------------- |
| `jev-1.13.0`  | Jev 1.13 版本。                                   |
| `jev-1.14.0`  | Jev 1.14 版本。                                   |
| `jev-latest`  | 最新稳定版本的别名。                              |
| `jev-preview` | 最新版本的别名，包括预览版。                      |

| 问题类型  | 原生 TypeSafe 原语 | 限制与语义                                                           |
| --------- | ------------------ | -------------------------------------------------------------------- |
| `choice`  | Choice             | 1–255 个选项；选中的选项和完整概率。                                 |
| `score`   | Score              | 2–10 个有序评分等级；分数值和完整概率。                              |
| `boolean` | Noul               | 必需的模型估计为 true 的概率。                                       |

状态、指令和描述除了字符串外，还接受 JSON 对象和数组。描述可以为 `null`。布尔 true/false 条件是可选的。SDK 使用中性名称 `boolean`，并将其映射到 TypeSafe 的 `noul` 字段。

### 长上下文

默认情况下，Jev 允许每次请求 64k token（状态加上所有问题），每个问题 32k token（状态加上一个问题）。设置 `longContext: true` 可将两个限制都提高到 262k token：

```ts
providerOptions: {
  typesafe: {
    longContext: true,
  },
},
```

仅当启用此选项时，提供商才会发送 `TypeSafe-Danger-Zone-Long-Context: true`。默认值为 `false`。Jev 1.13 和 1.14 都支持它。TypeSafe 对长上下文收取相同的按 token 价格，但表示它比保持在默认限制内更慢且准确性更低。仅在需要时启用；提供商不会估算 token 数量或自动启用它。参见 [TypeSafe 的上下文文档](https://docs.typesafe.ai/models#context-length)。

`TypeSafeAiDecisionModelOptions` 类型从 `@ai-sdk/typesafe-ai` 导出，用于为请求级选项提供类型。

### 图像输入

将 PNG 或 JPEG 图像作为文件部分与文本或 JSON 状态一起传递：

```ts
import { readFileSync } from 'node:fs';

const result = await experimental_decide({
  model: typeSafeAi.decisionModel('jev-latest'),
  state: [
    { type: 'text', text: 'Inspect the animal in this picture.' },
    {
      type: 'file',
      mediaType: 'image/png',
      data: readFileSync('cat.png'),
      providerOptions: {
        typesafe: { reference: '[animal-photo]' },
      },
    },
  ],
  questions: {
    cat: { type: 'boolean', instructions: 'Does [animal-photo] show a cat?' },
  },
});
```

提供商将图像作为二进制文件上传到 multipart 请求中，并在存在图像时自动添加 `TypeSafe-Danger-Zone-Images: true`。TypeSafe 目前认为图像支持是实验性的。仅支持 PNG 和 JPEG；其他文件格式会被拒绝。有关图像大小和尺寸限制，参见 [TypeSafe 的图像文档](https://docs.typesafe.ai/images)。

在文件部分上设置 `providerOptions.typesafe.reference` 以选择其资源引用。你可以在状态文本、问题指令或条件中使用该引用。提供商还会将其插入到状态中文件的位置。省略时，提供商会生成一个随机引用。

引用必须非空、包含非空白字符，并且在请求中的图像之间唯一。TypeSafe 会在字符串值中的任何位置替换引用，因此请选择独特的名称（如 `[animal-photo]`）以避免意外匹配。每次出现都会再次插入图像。文件的 `filename` 不影响其引用。

`TypeSafeAiFilePartProviderOptions` 类型从 `@ai-sdk/typesafe-ai` 导出，用于为文件级选项提供类型。

### 舍入值与置信度

TypeSafe 返回舍入到两位小数的分数和概率。`result.rounding` 报告此精度，以便 SDK 在检查分布总和和加权平均值时考虑舍入。返回的值保持不变；舍入意味着概率可能不会精确地加起来等于一。

置信度是单独的 TypeSafe 统计量，可在 `result.providerMetadata.typesafe.confidence[questionId]` 下获取，适用于 Choice 和 Score 答案。布尔概率始终表示 P(true)，而不是对任一结果的置信度。在应用程序代码中选择决策阈值。

### 错误与重试

提供商失败使用 `APICallError`，包括验证和身份验证错误。核心会根据 `maxRetries`（默认值：2）重试瞬时故障，例如 `429` 和 `529`。`abortSignal`、请求头和自定义 fetch 会被转发。没有提供商端的重试循环。

`providerOptions.typesafe` 下的未知请求级条目会产生不支持的选项警告。语言、嵌入和图像模型工厂会抛出 `NoSuchModelError`。

决策模型支持工作流序列化。自定义 fetch 函数不会被序列化；恢复的模型使用默认 fetch 实现。
