# TypeSafe 提供商

[TypeSafe](https://typesafe.ai) 提供商支持实验性决策 API，原生支持 Choice、Score 和 Boolean 答案。它会在一次请求中针对同一状态发送所有问题。

## 设置

安装提供商：

```sh
pnpm add @ai-sdk/typesafe-ai
```

设置 `TYPESAFE_AI_API_KEY` 环境变量。导入默认提供商或配置一个实例：

```ts
import { createTypeSafeAi, typeSafeAi } from '@ai-sdk/typesafe-ai';

const customTypeSafe = createTypeSafeAi({
  apiKey: 'your-api-key',
});
```

`createTypeSafeAi` 接受以下参数：

| 设置      | 描述                                                                   |
| --------- | ---------------------------------------------------------------------- |
| `apiKey`  | API 密钥；默认为 `TYPESAFE_AI_API_KEY`。                               |
| `baseURL` | 默认为 `TYPESAFE_AI_BASE_URL`，然后是 `https://api.typesafe.ai/v1`。   |
| `headers` | 额外的请求头。                                                         |
| `fetch`   | 自定义 fetch 实现。                                                    |

使用 `TYPESAFE_AI_BASE_URL` 将默认的 `typeSafeAi` 实例路由到受信任的代理或自托管的 TypeSafe 兼容服务器：

```sh
TYPESAFE_AI_BASE_URL=http://127.0.0.1:8766/v1
```

传递给 `createTypeSafeAi` 的显式 `baseURL` 优先于环境变量。配置的服务器会接收 API 密钥和决策状态，并且必须实现 TypeSafe 的 `POST /systemone` API。

## 决策

```ts
import { typeSafeAi } from '@ai-sdk/typesafe-ai';
import { experimental_decide } from 'ai';

const result = await experimental_decide({
  model: typeSafeAi.decisionModel('jev-latest'),
  state: {
    message: 'I was charged twice. Please refund the duplicate.',
  },
  questions: {
    department: {
      type: 'choice',
      instructions: 'Which team should handle this?',
      criteria: {
        billing: { includes: ['Charges', 'Invoices', 'Refunds'] },
        technical: ['Bugs', 'Outages'],
        other: null,
      },
    },
    severity: {
      type: 'score',
      instructions: 'How severe is the issue?',
      criteria: ['Cosmetic', 'Workaround exists', 'Blocking; no workaround'],
    },
    requestsRefund: {
      type: 'boolean',
      instructions: 'Is the customer requesting money back?',
    },
  },
});

console.log(result.answers.department.choice);
console.log(result.answers.severity.score);
console.log(result.answers.requestsRefund.probability);
console.log(result.usage);
```

使用 `jev-latest` 或其他 TypeSafe 模型 ID。响应中包含实际的模型 ID，例如别名背后解析出的版本。可以使用模型实例、自定义别名或已注册的提供商。当 `typeSafeAi` 被显式配置为 `globalThis.AI_SDK_DEFAULT_PROVIDER` 时，可以直接传入 `model: 'jev-latest'`。参见[模型别名和注册表](/docs/ai-sdk-core/decisions#model-aliases-and-registries)。

| 问题类型  | 原生 TypeSafe 原语 | 限制和语义                                                           |
| --------- | ------------------ | -------------------------------------------------------------------- |
| `choice`  | Choice             | 1–255 个选项；选中的选项和完整概率分布。                             |
| `score`   | Score              | 2–10 个有序评分等级；分数值和完整概率分布。                          |
| `boolean` | Noul               | 必需由模型估计为 true 的概率。                                       |

状态、指令和描述除了字符串外，还接受 JSON 对象和数组。描述可以为 `null`。布尔 true/false 标准是可选的。SDK 使用中性名称 `boolean`，并将其映射到 TypeSafe 的 `noul` 字段。

### 舍入值和置信度

TypeSafe 返回的分数和概率会舍入到两位小数。`result.rounding` 会报告此精度，以便 SDK 在检查分布总和和加权均值时考虑舍入。返回的值保持不变；舍入意味着概率相加可能不恰好等于一。

置信度是 TypeSafe 的一个独立统计量，可在 `result.providerMetadata.typesafe.confidence[questionId]` 下获取，适用于 Choice 和 Score 答案。布尔概率始终表示 P(true)，而不是对任一结果的置信度。请在应用程序代码中选择决策阈值。

### 错误和重试

提供商故障使用 `APICallError`，包括验证和身份验证错误。核心会根据 `maxRetries`（默认值：2）重试瞬时故障，例如 `429` 和 `529`。`abortSignal`、请求头和自定义 fetch 会被转发。没有提供商端的重试循环。

目前未定义提供商特定的选项。`providerOptions.typesafe` 下的未知条目会产生不支持的选项警告。语言、嵌入和图像模型工厂会抛出 `NoSuchModelError`。

决策模型支持工作流序列化。自定义 fetch 函数不会被序列化；恢复的模型使用默认 fetch 实现。
