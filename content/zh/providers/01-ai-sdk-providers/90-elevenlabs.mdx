# ElevenLabs 提供商

[ElevenLabs](https://elevenlabs.io/) 提供商包含对 ElevenLabs 转录和语音生成 API 的语言模型支持。
ElevenLabs 模型目前无法通过 [AI Gateway](https://vercel.com/ai-gateway/models) 使用，因此开头的示例直接使用 `@ai-sdk/elevenlabs`。有关支持的替代方案，请参阅下方的[使用 AI Gateway](#using-ai-gateway)。

```ts
import { generateSpeech } from 'ai';
import { elevenLabs } from '@ai-sdk/elevenlabs';
import { writeFile } from 'node:fs/promises';

const { audio } = await generateSpeech({
  model: elevenLabs.speech('eleven_multilingual_v2'),
  text: 'Hello, world!',
  outputFormat: 'mp3',
  voice: '21m00Tcm4TlvDq8ikWAM',
});

await writeFile('speech.mp3', audio.uint8Array);
```

## 使用 AI Gateway

当前的 [AI Gateway 模型目录](https://vercel.com/ai-gateway/models)未列出 ElevenLabs 模型。请使用 `@ai-sdk/elevenlabs` 访问本页所述的 API。如需通过 Gateway 使用其他语音模型，请安装 `ai` 并配置 Gateway API 密钥：

<InstallPackages packages="ai" />

在环境中设置 [AI Gateway API 密钥](https://vercel.com/docs/ai-gateway/getting-started)：

```bash
export AI_GATEWAY_API_KEY=your_api_key_here
```

Vercel 部署还可以使用 [OIDC 身份验证](/providers/ai-sdk-providers/ai-gateway#oidc-authentication-vercel-deployments)。
有关支持的模型和 API，请参阅 [Gateway 文档](/providers/ai-sdk-providers/ai-gateway)。

## 使用 `@ai-sdk/elevenlabs`

如需直接访问 ElevenLabs，请安装 `ai` 和 `@ai-sdk/elevenlabs`：

<InstallPackages packages="ai @ai-sdk/elevenlabs" />

在 `ELEVENLABS_API_KEY` 环境变量中设置你的 ElevenLabs API 凭据：

```bash
export ELEVENLABS_API_KEY=your_api_key_here
```

<Note>
  以下各节介绍直接使用 `@ai-sdk/elevenlabs` 提供商的内容，
  包括其模型工厂和设置。Gateway 的模型和功能
  可用性可能有所不同。
</Note>

## 提供商实例

你可以从 `@ai-sdk/elevenlabs` 导入默认提供商实例 `elevenLabs`：

```ts
import { elevenLabs } from '@ai-sdk/elevenlabs';
```

如果需要自定义设置，可以从 `@ai-sdk/elevenlabs` 导入 `createElevenLabs`，并使用你的设置创建提供商实例：

```ts
import { createElevenLabs } from '@ai-sdk/elevenlabs';

const elevenLabs = createElevenLabs({
  // custom settings, e.g.
  fetch: customFetch,
});
```

你可以使用以下可选设置来自定义 ElevenLabs 提供商实例：

- **apiKey** _string_

  通过 `xi-api-key` 请求头发送的 API 密钥。
  默认使用 `ELEVENLABS_API_KEY` 环境变量。

- **headers** _Record&lt;string,string&gt;_

  要包含在请求中的自定义请求头。

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。
  默认为全局 `fetch` 函数。
  你可以将其用作中间件来拦截请求，
  或为测试等场景提供自定义 fetch 实现。

- **webSocket** _WebSocketConstructor_

  用于实时转录的自定义 WebSocket 实现。在原生 WebSocket
  构造函数无法发送 `xi-api-key` 身份验证请求头的运行时中，
  需要使用支持请求头的实现。

## 语音模型

你可以使用 `.speech()` 工厂方法创建调用 [ElevenLabs 语音 API](https://elevenlabs.io/text-to-speech) 的模型。

第一个参数是模型 ID，例如 `eleven_multilingual_v2`。

```ts
const model = elevenLabs.speech('eleven_multilingual_v2');
```

`voice` 参数可以设置为 [ElevenLabs 语音库](https://elevenlabs.io/app/voice-library)中的语音 ID。
你可以在语音库中选择一个语音并复制其 ID 来查找语音 ID。

```ts highlight="6"
import { generateSpeech } from 'ai';
import { elevenLabs } from '@ai-sdk/elevenlabs';

const result = await generateSpeech({
  model: elevenLabs.speech('eleven_multilingual_v2'),
  text: 'Hello, world!',
  voice: '21m00Tcm4TlvDq8ikWAM', // Rachel voice
});
```

你还可以使用 `providerOptions` 参数传递额外的提供商特定选项：

```ts highlight="7-9"
import { generateSpeech } from 'ai';
import {
  elevenLabs,
  type ElevenLabsSpeechModelOptions,
} from '@ai-sdk/elevenlabs';

const result = await generateSpeech({
  model: elevenLabs.speech('eleven_multilingual_v2'),
  text: 'Hello, world!',
  voice: '21m00Tcm4TlvDq8ikWAM',
  providerOptions: {
    elevenlabs: {
      voiceSettings: {
        stability: 0.5,
        similarityBoost: 0.75,
      },
    } satisfies ElevenLabsSpeechModelOptions,
  },
});
```

- **languageCode** _string or null_  
  可选。用于强制模型使用某种语言的语言代码（ISO 639-1）。目前只有 Turbo v2.5 和 Flash v2.5 支持语言强制。对于其他模型，提供语言代码将导致错误。

- **voiceSettings** _object or null_  
  可选。覆盖给定语音已存储设置的语音设置。这些设置仅应用于当前请求。
  - **stability** _double or null_  
    可选。决定语音的稳定程度以及每次生成之间的随机性。较低的值会带来更广泛的情感范围；较高的值会产生更单调的语音。
  - **useSpeakerBoost** _boolean or null_  
    可选。增强与原始说话者的相似度。会增加计算负载和延迟。
  - **similarityBoost** _double or null_  
    可选。控制 AI 应多大程度地贴近原始语音。
  - **style** _double or null_  
    可选。放大原始说话者的风格。如果设置为大于 0 的值，可能会增加延迟。

- **pronunciationDictionaryLocators** _array of objects or null_  
  可选。要按顺序应用于文本的发音词典定位器列表。每个请求最多 3 个定位器。  
  每个定位器对象：
  - **pronunciationDictionaryId** _string_（必填）  
    发音词典的 ID。
  - **versionId** _string or null_（可选）  
    词典的版本 ID。如果未提供，则使用最新版本。

- **seed** _integer or null_  
  可选。如果指定，系统将尝试进行确定性采样。必须在 0 到 4294967295 之间。不保证确定性。

- **previousText** _string or null_  
  可选。当前请求文本之前的文本。在拼接生成内容时可以提高连续性，或影响当前生成的连续性。

- **nextText** _string or null_  
  可选。当前请求文本之后的文本。在拼接生成内容时可以提高连续性，或影响当前生成的连续性。

- **previousRequestIds** _array of strings or null_  
  可选。在此样本之前生成的样本的请求 ID 列表。在拆分大型任务时提高连续性。最多 3 个 ID。如果同时发送 `previousText` 和 `previousRequestIds`，则忽略 `previousText`。

- **nextRequestIds** _array of strings or null_  
  可选。在此样本之后生成的样本的请求 ID 列表。在重新生成样本时有助于保持连续性。最多 3 个 ID。如果同时发送 `nextText` 和 `nextRequestIds`，则忽略 `nextText`。

- **applyTextNormalization** _enum_  
  可选。控制文本规范化。  
  允许值：`'auto'`（默认）、`'on'`、`'off'`。
  - `'auto'`：系统决定是否应用规范化（例如，拼写出数字）。
  - `'on'`：始终应用规范化。
  - `'off'`：从不应用规范化。  
    对于 `eleven_turbo_v2_5` 和 `eleven_flash_v2_5`，只能在 Enterprise 计划中启用。

- **applyLanguageTextNormalization** _boolean_  
  可选。默认为 `false`。控制语言文本规范化，这有助于在某些支持的语言（目前仅日语）中实现正确发音。可能会显著增加延迟。

- **enableLogging** _boolean_  
  可选。是否为此 API 调用启用请求日志记录。默认为账户级设置。

## 转录模型

你可以使用 `.transcription()` 工厂方法创建调用 [ElevenLabs 转录 API](https://elevenlabs.io/speech-to-text) 的模型。

第一个参数是模型 ID，例如 `scribe_v2`。

```ts
const model = elevenLabs.transcription('scribe_v2');
```

你还可以使用 `providerOptions` 参数传递额外的提供商特定选项。例如，如果事先知道输入语言，以 ISO-639-1（例如 `en`）格式提供输入语言有时可以提高转录性能。

```ts highlight="10-14"
import { transcribe } from 'ai';
import {
  elevenLabs,
  type ElevenLabsTranscriptionModelOptions,
} from '@ai-sdk/elevenlabs';

const result = await transcribe({
  model: elevenLabs.transcription('scribe_v2'),
  audio: new Uint8Array([1, 2, 3, 4]),
  providerOptions: {
    elevenlabs: {
      languageCode: 'en',
    } satisfies ElevenLabsTranscriptionModelOptions,
  },
});
```

以下提供商选项可用：

- **languageCode** _string_

  与音频文件语言对应的 ISO-639-1 或 ISO-639-3 语言代码。
  如果事先知道，有时可以提高转录性能。
  默认为 `null`，此时会自动预测语言。

- **tagAudioEvents** _boolean_

  是否在转录中标记音频事件，例如（笑声）、（脚步声）等。
  默认为 `true`。

- **numSpeakers** _integer_

  上传文件中说话者的最大数量。
  有助于预测谁在何时说话。
  可预测的最大说话者数量为 32。
  默认为 `null`，此时说话者数量设置为模型支持的最大值。

- **timestampsGranularity** _enum_

  转录中时间戳的粒度。
  默认为 `'word'`。
  允许值：`'none'`、`'word'`、`'character'`。

- **diarize** _boolean_

  是否标注上传文件中当前正在说话的说话者。
  默认为 `true`。

- **fileFormat** _enum_

  输入音频的格式。
  默认为 `'other'`。
  允许值：`'pcm_s16le_16'`、`'other'`。
  对于 `'pcm_s16le_16'`，输入音频必须是 16 位 PCM、16kHz 采样率、单声道（mono）和小端字节序。
  延迟将低于传递编码波形。

## 流式转录模型

<Note type="warning">流式转录是一项实验性功能。</Note>

Scribe v2 Realtime 通过 `experimental_streamTranscribe` 支持实时转录。它接受 8、16、22.05、24、44.1 或 48 kHz 的原始 PCM 音频，或 8 kHz mu-law 音频。

```ts
import {
  createElevenLabs,
  type ElevenLabsProviderSettings,
} from '@ai-sdk/elevenlabs';
import { experimental_streamTranscribe as streamTranscribe } from 'ai';
import { WebSocket } from 'ws';

const elevenLabs = createElevenLabs({
  webSocket: WebSocket as unknown as ElevenLabsProviderSettings['webSocket'],
});

const result = streamTranscribe({
  model: elevenLabs.transcription('scribe_v2_realtime'),
  audio,
  inputAudioFormat: { type: 'audio/pcm', rate: 16000 },
  providerOptions: {
    elevenlabs: {
      languageCode: 'en',
      streaming: {
        includeLanguageDetection: true,
        includeTimestamps: true,
      },
    },
  },
});

for await (const part of result.fullStream) {
  if (part.type === 'transcript-partial') {
    console.log('partial:', part.text);
  }

  if (part.type === 'transcript-final') {
    console.log('final:', part.text);
  }
}
```

ElevenLabs 实时端点使用 WebSocket 请求头进行身份验证。在原生 WebSocket 构造函数无法发送请求头的运行时中，请使用支持请求头的 WebSocket 实现，例如 `ws`。

`streaming` 提供商选项与 ElevenLabs 的实时转录设置相对应：`commitStrategy`、`enableLogging`、`filterBackgroundAudio`、`includeLanguageDetection`、`includeTimestamps`、`keyterms`、`minSilenceDurationMs`、`minSpeechDurationMs`、`noVerbatim`、`previousText`、`secondaryLanguages`、`vadSilenceThresholdSecs` 和 `vadThreshold`。

ElevenLabs 在其带时间戳的已提交事件中提供检测到的语言。启用 `includeLanguageDetection` 时，提供商会在内部请求该事件，但只有在同时启用 `includeTimestamps` 时才会返回时间戳分段。`filterBackgroundAudio` 不能与这两个选项中的任何一个组合使用。

有关流式转录的更多信息，请参阅[转录](/docs/ai-sdk-core/transcription)。
