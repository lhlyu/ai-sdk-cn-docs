# MiniMax 提供商

[MiniMax](https://www.minimax.io) 提供商通过 MiniMax API 提供对 MiniMax-M 系列语言模型的访问，包括具备推理能力的模型，以及通过 MiniMax-H 系列进行视频生成。你可以通过 [AI Gateway](/providers/ai-sdk-providers/ai-gateway)（推荐）使用 MiniMax 模型，或使用 `@ai-sdk/minimax` 直接连接。

```ts provider="minimax" model="minimax/minimax-m3"
import { generateText } from 'ai';
__PROVIDER_IMPORT__;

const { text } = await generateText({
  model: __MODEL__,
  prompt: 'Write a vegetarian lasagna recipe for 4 people.',
});

console.log(text);
```

## 使用 AI Gateway

AI SDK 默认对模型字符串使用 AI Gateway。Gateway 通过单个 API 密钥提供跨提供商的模型访问，并支持用量和成本跟踪。安装 `ai`：

<InstallPackages packages="ai" />

在环境中设置 [AI Gateway API 密钥](https://vercel.com/docs/ai-gateway/getting-started)：

```bash
export AI_GATEWAY_API_KEY=your_api_key_here
```

Vercel 部署还可以使用 [OIDC 身份验证](/providers/ai-sdk-providers/ai-gateway#oidc-authentication-vercel-deployments)。
有关配置信息，请参阅 [AI Gateway 提供商文档](/providers/ai-sdk-providers/ai-gateway)；有关可用模型，请参阅[模型目录](https://vercel.com/ai-gateway/models)。

Gateway 的功能和提供商选项支持取决于模型以及处理请求的提供商。请参阅 [Gateway 提供商选项](https://vercel.com/docs/ai-gateway/models-and-providers/provider-options)。

## 使用 `@ai-sdk/minimax`

如需直接访问 MiniMax，请安装 `ai` 和 `@ai-sdk/minimax`：

<InstallPackages packages="ai @ai-sdk/minimax" />

在 `MINIMAX_API_KEY` 环境变量中设置你的 MiniMax API 凭据：

```bash
export MINIMAX_API_KEY=your_api_key_here
```

AI Gateway 并未公开 `@ai-sdk/minimax` 中的每一个 API。如需使用提供商特定的 API 或自定义连接设置，请使用直接提供商。

<Note>
  以下各节介绍直接 `@ai-sdk/minimax` 提供商，包括其模型工厂和设置。Gateway
  的模型和功能可用性可能有所不同。
</Note>

API 密钥可从 [MiniMax 平台](https://platform.minimax.io)获取。

## 提供商实例

你可以从 `@ai-sdk/minimax` 导入默认提供商实例 `minimax`：

```ts
import { minimax } from '@ai-sdk/minimax';
```

如需自定义配置，可以导入 `createMiniMax` 并使用你的设置创建提供商实例：

```ts
import { createMiniMax } from '@ai-sdk/minimax';

const minimax = createMiniMax({
  apiKey: process.env.MINIMAX_API_KEY ?? '',
});
```

你可以使用以下可选设置来自定义 MiniMax 提供商实例：

- **baseURL** _string_

  为 API 调用使用不同的 URL 前缀。此提供商使用 MiniMax 的
  Anthropic 兼容协议，因此默认前缀是
  `https://api.minimax.io/anthropic/v1`，而不是 OpenAI 兼容的
  `https://api.minimax.io/v1`。

- **videoBaseURL** _string_

  为视频生成 API 调用使用不同的 URL 前缀。视频 API 使用
  MiniMax V2 原生端点（而非 Anthropic 兼容端点）。
  默认前缀是 `https://api.minimax.io`。

- **apiKey** _string_

  MiniMax API 的 API 密钥。默认使用 `MINIMAX_API_KEY` 环境
  变量。语言模型将其放在 `x-api-key` 请求头中（Anthropic 兼容协议）；
  视频模型将其作为 `Authorization: Bearer` 发送。

- **headers** _Record&lt;string,string&gt;_

  要包含在请求中的自定义请求头

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现

## 语言模型

你可以使用提供商实例创建语言模型：

```ts
import { minimax } from '@ai-sdk/minimax';
import { generateText } from 'ai';

const { text } = await generateText({
  model: minimax('minimax-m3'),
  prompt: 'Write a vegetarian lasagna recipe for 4 people.',
});
```

你也可以使用 `.chat()` 或 `.languageModel()` 工厂方法：

```ts
const model = minimax.chat('minimax-m3');
// or
const model = minimax.languageModel('minimax-m3');
```

MiniMax 语言模型可用于 `streamText` 函数
（请参阅 [AI SDK Core](/docs/ai-sdk-core)）。

### 采样参数

对于 MiniMax M3.1 及更高版本的模型 ID，`temperature` 接受 `0` 到 `2` 的值，
`topP` 接受 `0` 到 `1` 的值。当显式启用自适应思考或使用顶层
`reasoning` 设置时，两者都会被转发。
省略它们则使用 MiniMax 的默认值。

```ts
const { text } = await generateText({
  model: minimax('minimax-m3.1-flash'),
  temperature: 1.5,
  topP: 0.9,
  reasoning: 'low',
  maxOutputTokens: 16384,
  prompt: 'Invent three names for a café on the moon.',
});
```

### 提示词缓存

对于 MiniMax M3.1 及更高版本的模型 ID，使用
`providerOptions.minimax.cacheControl` 标记稳定文本。提供商会将其作为
`cache_control` 转发到对应的 API 内容块。你也可以在
系统消息上设置它，或在用户消息上设置以标记其最后一个内容块。

```ts
import { minimax, type MiniMaxCacheControlOptions } from '@ai-sdk/minimax';
import { generateText } from 'ai';

const result = await generateText({
  model: minimax('minimax-m3.1-flash'),
  reasoning: 'low',
  maxOutputTokens: 16384,
  messages: [
    {
      role: 'user',
      content: [
        {
          type: 'text',
          text: 'Long reference material reused across requests...',
          providerOptions: {
            minimax: {
              cacheControl: { type: 'ephemeral' },
            } satisfies MiniMaxCacheControlOptions,
          },
        },
        { type: 'text', text: 'Summarize the reference material.' },
      ],
    },
  ],
});

console.log(result.usage.inputTokenDetails.cacheReadTokens);
console.log(result.usage.inputTokenDetails.cacheWriteTokens);
```

保持稳定前缀不变，并将变化的问题放在其后。
缓存标记并不保证命中；请检查缓存读取 token 用量，以确认
缓存内容是否被复用。此选项不指定缓存生命周期。

现有的 `providerOptions.anthropic.cacheControl` 设置继续有效。
当两个命名空间在同一块上指定缓存控制时，`minimax` 优先。

### 图像和视频输入

MiniMax M3.1 及更高版本的模型 ID 在用户消息中接受图像和视频，`generateText`
和 `streamText` 均支持。传入文件字节、base64 数据或公开的 HTTP(S)
URL。URL 会直接发送给 MiniMax。

```ts
import { minimax, type MiniMaxVideoPartOptions } from '@ai-sdk/minimax';
import { generateText } from 'ai';

const { text } = await generateText({
  model: minimax('minimax-m3.1-flash'),
  maxOutputTokens: 16384,
  messages: [
    {
      role: 'user',
      content: [
        { type: 'text', text: 'Summarize this video.' },
        {
          type: 'file',
          mediaType: 'video/mp4',
          data: new URL('https://example.com/video.mp4'),
          providerOptions: {
            minimax: { fps: 1 } satisfies MiniMaxVideoPartOptions,
          },
        },
      ],
    },
  ],
});
```

在每个文件部分的 `providerOptions.minimax` 下设置媒体选项：

- **视频 `fps`** _number_：帧采样率，从 `0.2` 到 `5`。省略则使用
  服务器默认值。推荐的起始值为 `1`。
- **图像 `detail`** _'low' | 'default' | 'high'_：图像处理细节。更高的
  细节可能使用更多 token。此选项使用 `MiniMaxImagePartOptions`。

例如，图像部分可以指定
`providerOptions: { minimax: { detail: 'high' } }`，并设置 `mediaType: 'image/png'`。

对于已上传到 MiniMax 的视频，传入提供商引用：

```ts
const videoPart = {
  type: 'file' as const,
  mediaType: 'video/mp4',
  data: {
    type: 'reference' as const,
    reference: { minimax: 'your-uploaded-file-id' },
  },
  providerOptions: { minimax: { fps: 1 } },
};
```

该引用会变为 `mm_file://your-uploaded-file-id`。已经以
`mm_file://` 开头的引用也会被接受。请使用引用对象，而不是
将 `mm_file://` 字符串作为文件数据传入。上传通过
MiniMax Files API 单独管理；此提供商不会自动上传文件。

MiniMax 支持 JPEG、PNG、GIF 和 WebP 图像（最大 10 MB），以及 MP4、AVI、
MOV 和 MKV 视频（内联或 URL 输入最大 50 MB）。已上传的视频最大可达
512 MB。请求体限制为 64 MB，包括 base64 开销。不支持音频
输入。详情请参阅
[MiniMax API 文档](https://platform.minimax.io/docs/api-reference/text-anthropic-api)。

### 推理

MiniMax-M 模型可以在最终响应之前生成中间推理（“思考”）。你可以通过提供商选项控制此行为。推理
输出通过标准 AI SDK 推理部分进行流式传输。

```ts
import { minimax, type MiniMaxLanguageModelOptions } from '@ai-sdk/minimax';
import { generateText } from 'ai';

const { text, reasoningText } = await generateText({
  model: minimax('minimax-m3'),
  providerOptions: {
    minimax: {
      thinking: { type: 'adaptive' },
    } satisfies MiniMaxLanguageModelOptions,
  },
  prompt: 'How many "r"s are in the word "strawberry"?',
});

console.log(reasoningText);
console.log(text);
```

有关如何将推理集成到聊天机器人中的更多详细信息，请参阅 [AI SDK UI：聊天机器人](/docs/ai-sdk-ui/chatbot#reasoning)。

#### 推理强度

MiniMax M3.1 Flash 始终进行推理。使用 `effort` 控制推理深度：

```ts
import { minimax, type MiniMaxLanguageModelOptions } from '@ai-sdk/minimax';
import { generateText } from 'ai';

const { text, reasoningText } = await generateText({
  model: minimax('minimax-m3.1-flash'),
  maxOutputTokens: 16384,
  providerOptions: {
    minimax: {
      effort: 'low',
    } satisfies MiniMaxLanguageModelOptions,
  },
  prompt:
    'What is the smallest positive integer divisible by every integer from 1 to 10?',
});

console.log(reasoningText);
console.log(text);
```

输出 token 预算包括推理和最终答案。更高的
强度级别可能需要更大的预算。

你也可以在 MiniMax M3.1 及更高版本的模型 ID 上使用顶层 `reasoning` 设置：

```ts
const { text } = await generateText({
  model: minimax('minimax-m3.1-flash'),
  reasoning: 'high',
  maxOutputTokens: 16384,
  prompt:
    'What is the smallest positive integer divisible by every integer from 1 to 10?',
});
```

级别 `'low'`、`'medium'`、`'high'`、`'xhigh'` 和 `'max'` 直接映射到
MiniMax 的强度级别。`'minimal'` 映射到 `'low'`，并附带兼容性警告。
对于 M3.1 及更高版本的模型 ID，`'none'` 也映射到 `'low'`，并附带
兼容性警告。省略 `reasoning` 或将其设置为 `'provider-default'`
则保持服务器默认值不变。显式的 `providerOptions.minimax.effort`
优先于 `reasoning`。

### 提供商选项

MiniMax 语言模型提供以下可选提供商选项：

- **effort** _'low' | 'medium' | 'high' | 'xhigh' | 'max'_

  控制 MiniMax M3.1 及更高版本模型 ID 的推理深度。更高的级别可能使用更多
  推理 token 并增加延迟。映射到 MiniMax API 中的 `output_config.effort`。
  省略时，服务器使用其默认值（M3.1 Flash 为 `'max'`）。

- **thinking** _object_

  控制模型的推理（“思考”）行为。
  - **type** _'adaptive' | 'disabled'_
    - `'adaptive'`：模型自行决定何时推理（启用深度推理）
    - `'disabled'`：模型直接响应而不进行推理，以获得更高的
      吞吐量和更低的延迟

  省略时，模型使用其提供商侧默认值。

  <Note>
    思考控制仅在 `minimax-m3` 上受支持。M2.x 模型始终
    进行思考，因此 `'disabled'` 对它们无效。`MiniMax-M3.1-Flash` 始终
    进行思考，如果发送 `'disabled'` 会返回错误。
  </Note>

## 视频模型

你可以使用
[`experimental_generateVideo`](/docs/reference/ai-sdk-core/generate-video)
函数通过 MiniMax-H3 和 MiniMax-H3-Max 模型生成视频。MiniMax-H3-Max 是更快的变体：它以较低分辨率渲染，
并支持除参考生视频之外的所有模式。

```ts
import { minimax, type MiniMaxVideoModelOptions } from '@ai-sdk/minimax';
import { experimental_generateVideo as generateVideo } from 'ai';

const { video } = await generateVideo({
  model: minimax.video('MiniMax-H3'),
  prompt: 'A white kitten chases a butterfly across a sunlit garden.',
  aspectRatio: '16:9',
  duration: 5,
  providerOptions: {
    minimax: {
      resolution: '768P',
      pollTimeoutMs: 600000, // 10 minutes
    } satisfies MiniMaxVideoModelOptions,
  },
});
```

两个模型每次调用生成一个视频。生成是异步的——默认情况下，
模型创建一个任务并轮询直到完成，然后返回生成的
MP4 URL。
状态轮询对第一个请求信任配置的 MiniMax API 源，并在跟随重定向到其他源之前验证每个重定向。

`duration` 接受整数秒，默认值为 5。MiniMax-H3
支持 4 到 15 秒；MiniMax-H3-Max 支持 5 到 15 秒。小数
值会被四舍五入，超出范围的值会被限制，两者都会附带警告。
MiniMax-H3 支持 `768P` 和 `2K` 输出，而 MiniMax-H3-Max 支持 `480P`
和 `768P`。

API 接受命名档位而非帧尺寸，因此顶层 `resolution`
会与固定表进行匹配，该表为每个宽高比的每个档位提供一个帧尺寸：

| 档位   | 接受的 `resolution` 值                                                       |
| ------ | ---------------------------------------------------------------------------- |
| `480P` | `480x480`, `1120x480`, `854x480`, `640x480`, `480x854`, `480x640`            |
| `768P` | `768x768`, `1792x768`, `1366x768`, `1024x768`, `768x1366`, `768x1024`        |
| `2K`   | `2048x2048`, `2560x1080`, `2560x1440`, `2048x1536`, `1440x2560`, `1536x2048` |

表外的任何值，或所选模型不支持的档位，都会发出警告
并回退到模型默认值。`providerOptions.minimax.resolution` 精确指定
档位，并优先于顶层值，后者会被报告为已忽略。

对于**文生视频**，省略时 `aspectRatio` 默认为 `16:9`。MiniMax
API 要求纯文本请求使用具体比例，不接受
`adaptive`。对于**参考生视频**，省略 `aspectRatio` 时 API 默认为 `adaptive`。
对于使用帧图像的**图生视频**，宽高比
跟随输入图像。

<Note>
  结果 URL 有时间限制。生成后请及时将视频下载并持久化到你自己的
  存储中。
</Note>

### 异步生成

要让 SDK 管理启动/状态流程，请向 `generateVideo` 传入 `poll`：

```ts
import { minimax } from '@ai-sdk/minimax';
import { experimental_generateVideo as generateVideo } from 'ai';

const { video } = await generateVideo({
  model: minimax.video('MiniMax-H3'),
  prompt: 'A white kitten chases a butterfly across a sunlit garden.',
  poll: { intervalMs: 10000, timeoutMs: 600000 },
});
```

如果没有 `poll` 或 `webhook`，生成将继续使用提供商的
`pollIntervalMs` 和 `pollTimeoutMs` 选项。使用 `poll` 时，则应用 SDK 的轮询
设置。

MiniMax 未实现通用 webhook Hook。向
`generateVideo` 传入 `webhook` 会回退到 SDK 轮询，而不会调用工厂。MiniMax 的
挑战握手和进度通知需要协议感知的接收器，
与通用 SDK 和 Workflow webhook 接收器不兼容。

对于调用方管理的调度，使用 `experimental_startVideo` 提交一个任务
而不轮询，并使用 `experimental_getVideoStatus` 检查一次，返回
`pending`、`completed` 或 `error`。持久化 `experimental_startVideo` 返回的完整 JSON 可序列化
`operation`，并在具有相同配置的模型上将其原样传递给
`experimental_getVideoStatus`。
其 `resolvedInputs` 包含 `imageCount` 和 `referenceVideoIndices`：原始混合 `inputReferences`
数组中已接受的 URL 视频引用的从零开始的位置。内联视频计入上限，但不包含在索引中；
重复引用保留单独的索引。operation 和状态
元数据都不保留输入 URL、提示词、内联数据或 API 凭据。
状态元数据使用这些索引而非 `referenceVideoUrls`；不带 `poll` 或 `webhook` 的普通
`generateVideo` 调用保留现有的 URL 元数据。
请参阅
[启动/状态示例](https://github.com/vercel/ai/blob/main/examples/ai-functions/src/generate-video/minimax/start-status.ts)。

对于应用管理的回调，向
`experimental_startVideo` 传入显式的 `webhookUrl`：

```ts
import { minimax } from '@ai-sdk/minimax';
import {
  experimental_startVideo as startVideo,
  experimental_getVideoStatus as getVideoStatus,
} from 'ai';

const model = minimax.video('MiniMax-H3');
const { operation } = await startVideo({
  model,
  prompt: 'A white kitten chases a butterfly across a sunlit garden.',
  webhookUrl: 'https://example.com/api/minimax/callback',
});

// Persist operation, then check it from your application's callback handler.
const status = await getVideoStatus(model, { operation });
```

你的应用托管回调端点并处理 MiniMax 的回调
协议；适配器仅将 `webhookUrl` 作为 MiniMax 的 `callback_url` 转发。
端点必须在 3 秒内原样回显验证 `challenge`
并过滤掉 `queued`/`running` 进度更新。当
`task.status` 为 `succeeded`、`failed` 或 `cancelled` 时处理终端通知，然后使用
持久化的 operation 调用 `getVideoStatus` 以获取结果。挑战和进度更新都不表示完成。有关回调契约，请参阅
[MiniMax V2 API 参考](https://platform.minimax.io/docs/api-reference/video-generation-v2-create.md)。

### 生成模式

生成模式根据你传入的输入推断：

- **文生视频**——仅 `prompt`。
- **首帧图生视频**——传入 `image`（或带有
  `frameType: 'first_frame'` 的 `frameImages` 条目）以动画化起始图像。
- **首尾关键帧**——传入同时包含 `first_frame` 和
  `last_frame` 的 `frameImages` 以控制过渡。
- **参考生视频（仅 MiniMax-H3）**——传入 `inputReferences`（图像
  和/或视频，按媒体类型路由）以保持主体/风格或跟随运动。
  帧图像和引用互斥。MiniMax-H3-Max 不支持
  参考生视频输入。

提供帧图像时，宽高比跟随图像，任何
显式 `aspectRatio` 都会被忽略。

### 视频提供商选项

MiniMax 视频模型提供以下可选提供商选项：

- **resolution** _'480P' | '768P' | '2K'_

  输出分辨率。MiniMax-H3 支持 `'768P'` 和 `'2K'`（默认值）。
  MiniMax-H3-Max 支持 `'480P'` 和 `'768P'`（默认值）。

- **ratio** _'adaptive' | '21:9' | '16:9' | '4:3' | '1:1' | '3:4' | '9:16'_

  生成视频的宽高比。覆盖顶层 `aspectRatio`。

- **referenceAudioUrls** _string[]_

  用于 MiniMax-H3 参考生视频生成的参考音频 URL（或 `mm_file://` 句柄）。
  必须与至少一个参考图像或视频配对。最多 3 个。MiniMax-H3-Max 不支持参考音频。

- **aigcWatermark** _boolean_

  是否在输出中嵌入 AIGC 水印。默认为 `false`。

- **pollIntervalMs** _number_

  任务状态轮询之间的间隔（毫秒）。默认值：`10000`。

- **pollTimeoutMs** _number_

  超时前轮询的最长时间（毫秒）。默认值：`600000`。

<Note>
  MiniMax `mm_file://` 句柄仅对
  `referenceAudioUrls` 原样转发。它们不能用于 `image`、`frameImages` 或
  `inputReferences`：这些输入会经过 AI SDK 的文件处理，该处理会对任何不是 `http(s)://` 或 `data:` URL 的字符串进行 base64 解码。请改为将
  这些输入作为公开 URL、数据 URI 或二进制数据传入。
</Note>

### 视频提供商元数据

MiniMax 视频结果包含 `providerMetadata.minimax`：

- **taskId** _string_

  MiniMax 生成任务的 ID。

- **videoUrl** _string_

  MiniMax 托管的 MP4 URL（与 `video` 相同的 URL）。有时间限制。

- **resolvedInputs** _object_

  实际发送的输入，经过 H3 施加的上限和拒绝之后
  （警告会报告某个输入被丢弃，但不会报告有多少个保留下来）。
  - **imageCount** _number_——发送的图像数量（帧图像或参考
    图像）。
  - **referenceVideoUrls** _string[]_——发送的参考视频的 URL。
    内联视频数据被省略，因为它作为数据 URI 发送。

- **duration** _number_

  生成视频的时长（秒），由 API 报告时提供。

- **ratio** _string_

  生成视频的宽高比，由 API 报告时提供。

- **resolution** _string_

  生成视频的分辨率档位，由 API 报告时提供。

- **usage** _object_

  计费秒数，由 API 报告时提供：`totalSeconds`、`inputSeconds`
  和 `outputSeconds`。
