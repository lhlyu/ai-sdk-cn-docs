# Open Responses 提供商

[Open Responses](https://www.openresponses.org/) 提供商将 AI SDK Core 连接到实现了 Open Responses 兼容 `POST` 端点的语言模型服务器。Open Responses 是一个基于 OpenAI Responses API 的开放规范。

对于实现此协议的第三方或自托管端点（例如 LM Studio），请使用 `@ai-sdk/open-responses`。如果你直接调用 OpenAI 并且需要 OpenAI 特有的提供商选项或内置工具，请改用 [`@ai-sdk/openai` 提供商](/providers/ai-sdk-providers/openai)。

## 设置

Open Responses 提供商位于 `@ai-sdk/open-responses` 模块中。你可以使用以下命令安装：

<InstallPackages packages="@ai-sdk/open-responses" />

## 提供商实例

使用 `createOpenResponses` 创建 Open Responses 提供商实例：

```ts
import { createOpenResponses } from '@ai-sdk/open-responses';

const openResponses = createOpenResponses({
  name: 'lmstudio',
  url: 'http://localhost:1234/v1/responses',
});
```

`name` 和 `url` 选项是必填的：

- **name** _string_

  提供商名称。用于模型的提供商标识符，并作为提供商选项的键。

- **url** _string_

  Open Responses API `POST` 端点的完整 URL。请传入端点 URL，例如 `http://localhost:1234/v1/responses`，而不仅仅是其基础 URL。

你可以使用以下可选设置来自定义 Open Responses 提供商实例：

- **apiKey** _string_

  作为 bearer token 在 `Authorization` 请求头中发送的 API 密钥。

- **headers** _Record&lt;string,string&gt; | () => Record&lt;string,string&gt;_

  请求中包含的自定义请求头。当请求头需要针对每个请求延迟解析时，传入一个函数。

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。
  默认为全局 `fetch` 函数。

- **failedResponseHandler** _ResponseHandler&lt;APICallError&gt;_

  针对非成功 HTTP 响应的自定义处理器。当端点返回的错误封装与默认的 OpenAI 兼容 `{ error: { message, type, param, code } }` 结构不同时，请使用此选项。

- **getResponseErrorMetadata** _function_

  从响应错误对象中提取可选的 `statusCode` 和 `isRetryable` 元数据，包括端点特有的字段。适用于生成失败以及流式传输的 `response.failed` 和 `error` 事件。标准的 Open Responses 错误字段是 `code` 和 `message`；端点特有的状态字段需要此回调。当仅提供状态码时，SDK 会根据它推导可重试性。HTTP 失败由 `failedResponseHandler` 单独处理。

- **strictResponseInput** _boolean_

  使用严格的 OpenAI Responses 输入 schema 序列化助手历史记录。没有 item ID 的助手消息将作为简单输入消息发送，而具有真实提供商 item ID 的消息将作为完整输出项发送。默认为 `false`。

- **customToolId** _`${string}.${string}`_

  `provider.tools.customTool` 使用的提供商工具 ID。默认为 `open-responses.custom`。

- **structuredOutputs** _boolean_

  是否将 JSON 响应格式发送到端点。当为 `false` 时，结构化输出请求将被省略并给出不支持警告。默认为 `true`。

- **userAgentSuffix** _string_

  覆盖默认的 `ai-sdk/open-responses/<version>` user-agent 后缀。

### 端点示例

对于不需要身份验证的本地 LM Studio 服务器：

```ts
import { createOpenResponses } from '@ai-sdk/open-responses';

const lmstudio = createOpenResponses({
  name: 'lmstudio',
  url: 'http://localhost:1234/v1/responses',
});
```

对于 OpenAI Responses API：

```ts
import { createOpenResponses } from '@ai-sdk/open-responses';

const openAIResponses = createOpenResponses({
  name: 'openai',
  url: 'https://api.openai.com/v1/responses',
  apiKey: process.env.OPENAI_API_KEY,
});
```

你可以通过更改 `name`、`url`、身份验证和模型 ID，将相同的设置用于另一个兼容的服务。

## 语言模型

Open Responses 提供商实例是一个函数，你可以调用它来创建语言模型：

```ts
const model = openResponses('your-model-id');
```

模型 ID 会原样传递给端点。

你可以将 Open Responses 模型与 `generateText` 和 `streamText` 函数一起使用，它们支持使用 [`Output`](/docs/reference/ai-sdk-core/output) 生成结构化数据（参见 [AI SDK Core](/docs/ai-sdk-core)）。

### 生成文本

```ts
import { createOpenResponses } from '@ai-sdk/open-responses';
import { generateText } from 'ai';

const openResponses = createOpenResponses({
  name: 'lmstudio',
  url: 'http://localhost:1234/v1/responses',
});

const { text } = await generateText({
  model: openResponses('your-model-id'),
  prompt: 'Invent a new holiday and describe its traditions.',
});

console.log(text);
```

### 流式传输文本

```ts
import { createOpenResponses } from '@ai-sdk/open-responses';
import { streamText } from 'ai';

const openResponses = createOpenResponses({
  name: 'lmstudio',
  url: 'http://localhost:1234/v1/responses',
});

const result = streamText({
  model: openResponses('your-model-id'),
  prompt: 'Invent a new holiday and describe its traditions.',
});

for await (const textPart of result.textStream) {
  process.stdout.write(textPart);
}
```

## 推理与提供商选项

使用顶层的 [`reasoning`](/docs/ai-sdk-core/reasoning) 设置来控制推理强度。提供商会将支持的值映射到 Open Responses 的 `reasoning.effort` 字段。

提供商还通过 `providerOptions` 支持 `reasoningEffort` 和 `reasoningSummary`。提供商选项键必须与传递给 `createOpenResponses` 的 `name` 匹配：

```ts
import {
  createOpenResponses,
  type OpenResponsesLanguageModelOptions,
} from '@ai-sdk/open-responses';
import { generateText } from 'ai';

const lmstudio = createOpenResponses({
  name: 'lmstudio',
  url: 'http://localhost:1234/v1/responses',
});

const { text, reasoningText } = await generateText({
  model: lmstudio('your-reasoning-model-id'),
  reasoning: 'high',
  providerOptions: {
    lmstudio: {
      reasoningEffort: 'max',
      reasoningSummary: 'detailed',
    } satisfies OpenResponsesLanguageModelOptions,
  },
  prompt: 'Explain why the sky appears blue.',
});

console.log(reasoningText);
console.log(text);
```

`reasoningEffort` 接受任意字符串，并原样传递给端点的 `reasoning.effort` 字段。可将其用于不属于顶层 `reasoning` 设置的端点原生值，例如 `'max'`。当两者都设置时，`providerOptions` 的 `reasoningEffort` 优先于顶层 `reasoning` 值。

`reasoningSummary` 接受 `'auto'`、`'concise'` 或 `'detailed'`，并且可以与任一推理强度设置组合使用。推理支持以及接受的强度值取决于端点和模型；不支持的值可能会被端点拒绝或忽略。

## 自定义工具

支持 OpenAI 兼容自定义工具的端点可以使用原始字符串输入调用工具，并可选地受正则表达式或 Lark 语法约束。这些工具在你的应用程序中执行：

```ts
import { generateText, isStepCount } from 'ai';

const result = await generateText({
  model: openResponses('your-model-id'),
  prompt: 'Write a SQL query that lists active users.',
  tools: {
    write_sql: openResponses.tools.customTool({
      description: 'Return a SQL SELECT query.',
      format: {
        type: 'grammar',
        syntax: 'regex',
        definition: 'SELECT .+',
      },
      execute: async sql => runReadOnlyQuery(sql),
    }),
  },
  stopWhen: isStepCount(3),
});
```

端点必须支持 OpenAI 兼容的 `custom` 工具、`custom_tool_call` 和 `custom_tool_call_output` 传输类型，正如 OpenAI 和 QuiverAI 所做的那样。这些是兼容性扩展，不属于 Open Responses 2026-04-24 规范。在端点支持的情况下，自定义工具结果可以包含文本、图像和文件。

## 文件输入

提供商支持用户消息中的图像和非图像文件输入。图像作为 `input_image` 部分发送，而其他媒体类型（例如 PDF）作为 `input_file` 部分发送。

你可以将文件作为内联数据提供：

```ts
import { createOpenResponses } from '@ai-sdk/open-responses';
import { readFileSync } from 'node:fs';
import { generateText } from 'ai';

const openResponses = createOpenResponses({
  name: 'lmstudio',
  url: 'http://localhost:1234/v1/responses',
});

const { text } = await generateText({
  model: openResponses('your-file-capable-model-id'),
  messages: [
    {
      role: 'user',
      content: [
        {
          type: 'text',
          text: 'Summarize this document.',
        },
        {
          type: 'file',
          data: readFileSync('./document.pdf'),
          mediaType: 'application/pdf',
          filename: 'document.pdf',
        },
      ],
    },
  ],
});

console.log(text);
```

你也可以将 `data` 设置为 `URL`。端点和模型必须支持该文件的媒体类型。此提供商不支持提供商文件引用（例如 OpenAI 文件 ID）以及 `{ type: 'text', text: '...' }` 格式的文件数据。

## 实验性扩展

Open Responses 实现可以添加带命名空间的工具、项和流式传输事件。使用 `Experimental_OpenResponsesExtension` 来编码和解码实现的扩展传输格式。未注册的提供商工具将从请求中省略，并给出 `unsupported` 警告。

此 API 是实验性的，可能会在未来版本中更改。

AI SDK 提供商工具 ID 使用点号表示法（`acme.document_search`），而 Open Responses 传输类型使用冒号表示法（`acme:document_search`）。`id` 中的命名空间必须与每个已注册传输类型中的命名空间匹配。

```ts
import {
  createOpenResponses,
  type Experimental_OpenResponsesExtension,
} from '@ai-sdk/open-responses';
import { generateText, tool } from 'ai';
import { z } from 'zod';

const documentSearchExtension: Experimental_OpenResponsesExtension = {
  id: 'acme.document_search',
  toolType: 'acme:document_search',
  itemTypes: ['acme:document_search_receipt'],
  encodeTool: ({ name, args }) => ({
    name,
    index: args.index as string,
  }),

  decodeItem: ({ item }) => [
    {
      type: 'tool-call',
      toolCallId: item.call_id as string,
      toolName: item.name as string,
      input: JSON.stringify(item.query),
      providerExecuted: true,
    },
    {
      type: 'tool-result',
      toolCallId: item.call_id as string,
      toolName: item.name as string,
      result: item.result!,
    },
  ],
};

const acme = createOpenResponses({
  name: 'acme',
  url: 'https://api.acme.example/v1/responses',
  experimental_extensions: [documentSearchExtension],
});

const documentSearch = tool({
  type: 'provider',
  id: 'acme.document_search',
  args: { index: 'documentation' },
  isProviderExecuted: true,
  inputSchema: z.object({ text: z.string() }),
  outputSchema: z.object({
    documents: z.array(
      z.object({
        id: z.string(),
        title: z.string(),
      }),
    ),
  }),
});

const result = await generateText({
  model: acme('your-model-id'),
  prompt: 'Find the extension documentation.',
  tools: { documentSearch },
});
```

在每个解码后的 `tool-call` 或 `tool-input-start` 部分上设置 `providerExecuted`。它可以因项或事件而异。

扩展编解码器可以定义：

- `encodeTool`：编码提供商工具。返回 `undefined` 将省略该工具并给出 `unsupported` 警告。选择被省略工具的 `toolChoice` 也会被省略。
- `encodeToolChoice`：编码特定的 `toolChoice`。默认为 `{ type: toolType }`。
- `decodeItem`：将已完成的项映射到 AI SDK 内容部分。`mode` 为 `'generate'` 或 `'stream'`。
- `encodeInputItem`：当原始传输项不可用时，编码工具调用或工具结果历史记录。返回的项必须包含 `id`、`status` 和已注册的带命名空间 `type`。
- `decodeEvent`：将流式传输事件映射到 AI SDK 流部分。其 `state` 映射持续一个响应流。

工具、项和事件能力是相互独立的。例如，仅项的扩展定义 `itemTypes` 和 `decodeItem`，而不定义 `toolType` 或 `encodeTool`。能力字段必须成对提供。

每个解码后的项都会添加一个 `open-responses.extension-replay` 自定义部分，将原始 JSON 存储在提供商元数据中。其他解码部分引用该自定义部分，而不是复制该项。将 `result.response.messages` 传递给后续调用会重放一次原始项，包括不透明字段。这也会保留仅解码为仅响应源部分的项。

适配器仅验证扩展判别字段。在返回 AI SDK 部分之前，请在编解码器中验证其他项和事件字段。原始项存储在提供商元数据中，可能会出现在持久化消息、遥测、日志或 UI 负载中。

扩展回调无法跨工作流步骤边界序列化。请在工作流步骤内创建提供商。序列化配置了扩展的模型会抛出 `SerializationError`。

## 限制

- 不支持停止序列、`topK` 和 `seed`，它们会被忽略并给出警告。
- 提供商仅支持语言模型。它不提供嵌入或图像生成模型。
- 支持 AI SDK 函数工具和已注册的 Open Responses 扩展。其他提供商特有的工具和选项需要专用的提供商实现。
