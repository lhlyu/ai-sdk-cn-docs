# OpenAI 提供商

[OpenAI](https://openai.com/) 提供商支持 OpenAI 的响应、聊天和补全 API 的语言模型，以及 OpenAI 嵌入 API 的嵌入模型。

## 安装

OpenAI 提供商位于 `@ai-sdk/openai` 模块中。你可以通过以下方式安装：

## 提供商实例

你可以从 `@ai-sdk/openai` 导入默认的提供商实例 `openai`：

```ts
import { openai } from '@ai-sdk/openai';
```

如果你需要自定义设置，可以从 `@ai-sdk/openai` 导入 `createOpenAI` 并使用你的设置创建提供商实例：

```ts
import { createOpenAI } from '@ai-sdk/openai';

const openai = createOpenAI({
  // 自定义设置，例如
  headers: {
    'header-name': 'header-value',
  },
});
```

你可以使用以下可选设置来自定义 OpenAI 提供商实例：

- **baseURL** _string_

  为 API 调用使用不同的 URL 前缀，例如使用代理服务器。
  默认前缀是 `https://api.openai.com/v1`。
  默认的 OpenAI 模型工厂 (`openai('model-id')`) 使用 Responses
  API。如果你的自定义 baseURL 只支持 Chat Completions API，请改用
  `openai.chat('model-id')` 创建聊天模型，或使用
  [OpenAI 兼容提供商](/providers/openai-compatible-providers)。

- **apiKey** _string_

  通过 `Authorization` 标头发送的 API 密钥。
  默认为 `OPENAI_API_KEY` 环境变量。

- **name** _string_

  提供商名称。在使用 OpenAI 兼容提供商时，你可以设置此项
  以更改模型提供商属性。默认为 `openai`。

- **organization** _string_

  OpenAI 组织。

- **project** _string_

  OpenAI 项目。

- **headers** _Record&lt;string,string&gt;_

  包含在请求中的自定义标头。

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。
  默认为全局 `fetch` 函数。
  你可以将其用作拦截请求的中间件，
  或为测试等提供自定义 fetch 实现。

## 语言模型

OpenAI 提供商实例是一个函数，你可以调用它来创建语言模型：

```ts
const model = openai('gpt-5');
```

它会根据模型 ID 自动选择正确的 API。
你还可以在第二个参数中传递其他设置：

```ts
const model = openai('gpt-5', {
  // 其他设置
});
```

可用的选项取决于为模型自动选择的 API（见下文）。
如果你想显式选择特定的模型 API，可以使用 `.responses`、`.chat` 或 `.completion`。

<Note>
  自 AI SDK 5 起，默认调用 OpenAI responses API（除非你指定了例如 'openai.chat'）。
</Note>

### 示例

你可以使用 OpenAI 语言模型通过 `generateText` 函数生成文本：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text } = await generateText({
  model: openai('gpt-5'),
  prompt: '写一份供 4 人食用的素食千层面食谱。',
});
```

OpenAI 语言模型也可以在 `streamText` 函数中使用，
并支持使用 [`Output`](/docs/reference/ai-sdk-core/output) 进行结构化数据生成
（参见 [AI SDK Core](/docs/ai-sdk-core)）。

### Responses 模型

你可以使用 `openai(modelId)` 或 `openai.responses(modelId)` 工厂方法调用 OpenAI responses API。这是 OpenAI 提供商使用的默认 API（自 AI SDK 5 起）。

```ts
const model = openai('gpt-5');
```

可以使用 OpenAI 提供商选项进行进一步配置。
你可以使用 `OpenAILanguageModelResponsesOptions` 类型验证提供商选项。

```ts
import { openai, OpenAILanguageModelResponsesOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-5'), // 或 openai.responses('gpt-5')
  providerOptions: {
    openai: {
      parallelToolCalls: false,
      store: false,
      user: 'user_123',
      // ...
    } satisfies OpenAILanguageModelResponsesOptions,
  },
  // ...
});
```

以下提供商选项可用：

- **parallelToolCalls** _boolean_
  是否使用并行工具调用。默认为 `true`。

- **store** _boolean_

  是否存储生成结果。默认为 `true`。

- **passThroughUnsupportedFiles** _boolean_

  是否将非图像文件类型作为通用输入文件传递。默认为 `false`，这将内联文件输入限制为图像和 PDF。当目标 OpenAI Responses 模型支持其他文件媒体类型时启用此选项。

- **maxToolCalls** _integer_
  在单个响应中可以处理的内置工具调用的最大总数。
  此最大数量适用于所有内置工具调用，而非单个工具。
  模型任何进一步的工具调用尝试都将被忽略。

- **metadata** _Record&lt;string, string&gt;_
  与生成结果一起存储的附加元数据。

- **conversation** _string_
  要继续的 OpenAI Conversation 的 ID。
  你必须先通过 [OpenAI API](https://platform.openai.com/docs/api-reference/conversations/create) 创建一个 conversation。
  不能与 `previousResponseId` 同时使用。
  默认为 `undefined`。

- **previousResponseId** _string_
  上一个响应的 ID。你可以使用它来继续对话。默认为 `undefined`。

- **instructions** _string_
  模型的指令。
  当使用 `previousResponseId` 选项继续对话时，它们可用于更改系统或开发者消息。
  默认为 `undefined`。

- **logprobs** _boolean | number_
  返回 token 的对数概率。包含 logprobs 会增加响应大小并可能减慢响应时间。但是，它有助于更好地理解模型的行为。设置为 `true` 返回生成的 token 的对数概率。设置为数字 (1-20) 返回生成的前 n 个 token 的对数概率。

- **user** _string_
  代表最终用户的唯一标识符，可帮助 OpenAI 监控和检测滥用。默认为 `undefined`。

- **reasoningEffort** _'none' | 'minimal' | 'low' | 'medium' | 'high' | 'xhigh'_
  推理模型的推理努力程度。默认为 `medium`。如果你使用 `providerOptions` 设置 `reasoningEffort` 选项，则此模型设置将被忽略。

<Note>
  'none' 类型的 `reasoningEffort` 仅适用于 OpenAI 的 GPT-5.1 模型。此外，'xhigh' 类型的 `reasoningEffort` 仅适用于 OpenAI 的 GPT-5.1-Codex-Max 模型。在不支持的模型上将 `reasoningEffort` 设置为 'none' 或 'xhigh' 会导致错误。
</Note>

- **reasoningSummary** _'auto' | 'detailed'_
  控制模型是否返回其推理过程。设置为 `'auto'` 获取精简摘要，`'detailed'` 获取更全面的推理。默认为 `undefined`（无推理摘要）。启用后，推理摘要会在流中以类型为 `'reasoning'` 的事件形式出现，在非流式响应中则出现在 `reasoning` 字段内。

- **strictJsonSchema** _boolean_
  是否使用严格的 JSON schema 验证。默认为 `true`。

<Note type="warning">
  OpenAI 结构化输出存在一些
  [限制](https://openai.com/index/introducing-structured-outputs-in-the-api)，
  特别是关于 [支持的 schemas](https://platform.openai.com/docs/guides/structured-outputs/supported-schemas)，
  因此是选择加入的。例如，不支持可选的 schema 属性。
  你需要将 Zod 的 `.nullish()` 和 `.optional()` 更改为
  `.nullable()`。
</Note>

- **serviceTier** _'auto' | 'flex' | 'priority' | 'default'_
  请求的服务层级。设置为 'flex' 可获得 50% 更便宜的处理，
  但会增加延迟（适用于 o3、o4-mini 和 gpt-5 模型）。
  设置为 'priority' 可获得更快的处理速度和 Enterprise 访问权限（适用于 gpt-4、gpt-5、gpt-5-mini、o3、o4-mini；不支持 gpt-5-nano）。

  默认为 'auto'。

- **textVerbosity** _'low' | 'medium' | 'high'_
  控制模型响应的详细程度。较低的值会产生更简洁的响应，
  而较高的值会产生更详细的响应。默认为 `'medium'`。

- **include** _Array&lt;string&gt;_
  指定要包含在响应中的附加内容。支持的值：
  `['file_search_call.results']` 用于在响应中包含文件搜索结果。
  `['message.output_text.logprobs']` 用于 logprobs。
  默认为 `undefined`。

- **truncation** _string_
  用于模型响应的截断策略。
  - Auto：如果此响应的输入超过模型的上下文窗口大小，模型将通过从对话开头删除项目来截断响应以适合上下文窗口。
  - disabled（默认）：如果输入大小将超过模型的上下文窗口大小，请求将失败并返回 400 错误。

- **promptCacheKey** _string_
  用于手动提示缓存控制的缓存键。OpenAI 使用它来缓存相似请求的响应，以优化你的缓存命中率。

- **promptCacheRetention** _'in_memory' | '24h'_
  提示缓存的保留策略。设置为 `'24h'` 以启用扩展提示缓存，该缓存使缓存的前缀保持活动状态长达 24 小时。默认为 `'in_memory'` 用于标准提示缓存。注意：`'24h'` 目前仅适用于 5.1 系列模型。

- **safetyIdentifier** _string_
  一个稳定的标识符，用于帮助检测可能违反 OpenAI 使用政策的应用程序用户。ID 应是一个唯一标识每个用户的字符串。

- **systemMessageMode** _'system' | 'developer' | 'remove'_
  控制发出请求时系统消息的角色。默认情况下（省略时），对于支持推理的模型，`system` 消息会自动转换为 `developer` 消息。将 `systemMessageMode` 设置为 `system` 会将系统消息作为系统级指令传递；`developer` 将其作为开发者消息传递；`remove` 会从请求中省略系统消息。

- **forceReasoning** _boolean_
  强制将此模型视为推理模型。这对于“隐身”推理模型（例如通过自定义 baseURL）很有用，其中模型 ID 未被 SDK 的允许列表识别。启用后，SDK 会应用推理模型参数兼容性规则，并将 `systemMessageMode` 默认为 `developer`，除非被覆盖。

- **contextManagement** _Array&lt;object&gt;_
  启用服务端上下文管理（压缩）。配置后，当 token 使用量超过指定阈值时，服务器会自动压缩对话上下文。数组中的每个对象应具有：
  - `type`：`'compaction'`
  - `compactThreshold`：_number_ — 触发压缩的 token 数量

OpenAI responses 提供商还会返回提供商特定的元数据：

对于 Responses 模型，你可以使用 `OpenaiResponsesProviderMetadata` 类型来输入此元数据：

```ts
import { openai, type OpenaiResponsesProviderMetadata } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-5'),
});

const providerMetadata = result.providerMetadata as
  | OpenaiResponsesProviderMetadata
  | undefined;

const { responseId, logprobs, serviceTier } = providerMetadata?.openai ?? {};

// responseId 可用于继续对话 (previousResponseId)。
console.log(responseId);
```

以下 OpenAI 特定的元数据可能会返回：

- **responseId** _string | null | undefined_
  响应的 ID。可用于继续对话。
- **logprobs** _(可选)_
  输出 token 的对数概率（启用时）。
- **serviceTier** _(可选)_
  API 返回的服务层级信息。

#### 推理输出

对于像 `gpt-5` 这样的推理模型，你可以启用推理摘要来查看模型的思考过程。不同的模型支持不同的摘要器——例如，`o4-mini` 支持详细摘要。设置 `reasoningSummary: "auto"` 以自动接收可用的最丰富级别。当 `reasoningEffort` 设置为非 `'none'` 的值时，OpenAI Responses 提供商将 `reasoningSummary` 默认为 `'detailed'`；设置 `reasoningSummary: null` 以省略推理摘要。

```ts highlight="8-9,16"
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { streamText } from 'ai';

const result = streamText({
  model: openai('gpt-5'),
  prompt: '告诉我关于旧金山 Mission 卷饼的争论。',
  providerOptions: {
    openai: {
      reasoningSummary: 'detailed', // 'auto' 用于精简，'detailed' 用于全面
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});

for await (const part of result.stream) {
  if (part.type === 'reasoning') {
    console.log(`推理: ${part.textDelta}`);
  } else if (part.type === 'text-delta') {
    process.stdout.write(part.textDelta);
  }
}
```

对于使用 `generateText` 的非流式调用，推理摘要可在响应的 `reasoning` 字段中找到：

```ts highlight="8-9,13"
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-5'),
  prompt: '告诉我关于旧金山 Mission 卷饼的争论。',
  providerOptions: {
    openai: {
      reasoningSummary: 'auto',
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
console.log('推理:', result.reasoning);
```

在 [OpenAI 文档](https://platform.openai.com/docs/guides/reasoning?api-mode=responses#reasoning-summaries) 中了解更多关于推理摘要的信息。

#### WebSocket 传输

OpenAI 的 [WebSocket API](https://developers.openai.com/api/docs/guides/websocket-mode) 保持持久连接打开，这可以显著减少在具有许多工具调用的智能体工作流中的首字节时间 (TTFB)。
在初始连接之后，后续请求完全跳过 TCP/TLS/HTTP 协商。

[`ai-sdk-openai-websocket-fetch`](https://www.npmjs.com/package/ai-sdk-openai-websocket-fetch)
包提供了一个即插即用的 `fetch` 替代方案，它通过持久 WebSocket 连接路由流式请求。

<Tabs items={['pnpm', 'npm', 'yarn', 'bun']}>
  <Tab>
    <Snippet text="pnpm add ai-sdk-openai-websocket-fetch" dark />
  </Tab>
  <Tab>
    <Snippet text="npm install ai-sdk-openai-websocket-fetch" dark />
  </Tab>
  <Tab>
    <Snippet text="yarn add ai-sdk-openai-websocket-fetch" dark />
  </Tab>
  <Tab>
    <Snippet text="bun add ai-sdk-openai-websocket-fetch" dark />
  </Tab>
</Tabs>

通过 `fetch` 选项将 WebSocket fetch 传递给 `createOpenAI`：

```ts highlight="2,6-7,15"
import { createOpenAI } from '@ai-sdk/openai';
import { createWebSocketFetch } from 'ai-sdk-openai-websocket-fetch';
import { streamText } from 'ai';

// 创建一个 WebSocket 支持的 fetch 实例
const wsFetch = createWebSocketFetch();
const openai = createOpenAI({ fetch: wsFetch });

const result = streamText({
  model: openai('gpt-4.1-mini'),
  prompt: '你好！',
  tools: {
    // ...
  },
  onFinish: () => wsFetch.close(), // 完成后关闭 WebSocket
});
```

第一个请求会较慢，因为它必须建立 WebSocket 连接
（DNS + TCP + TLS + WebSocket 升级）。之后，在多步骤工具调用循环中的后续步骤会重用打开的连接，从而降低每一步的 TTFB。

<Note>
  WebSocket 传输仅通过 WebSocket 路由对 OpenAI Responses API 的流式请求（`POST /responses` 且 `stream: true`）。所有其他请求（非流式、嵌入等）会回退到标准的 `fetch` 实现。
</Note>

你可以在 [演示应用](https://github.com/vercel-labs/ai-sdk-openai-websocket) 中查看 HTTP 与 WebSocket 流式性能的实时并排比较。

#### 详细程度控制

你可以使用 `textVerbosity` 参数控制模型响应的长度和详细程度：

```ts
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-5-mini'),
  prompt: '写一首关于一个男孩和他的第一只宠物狗的诗。',
  providerOptions: {
    openai: {
      textVerbosity: 'low', // 'low' 简洁，'medium'（默认），或 'high' 详细
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

`textVerbosity` 参数在不改变底层提示词的情况下缩放输出长度：

- `'low'`：产生简短、最少的响应
- `'medium'`：平衡的详细程度（默认）
- `'high'`：包含全面细节的详细响应

#### 命名空间函数调用

OpenAI 支持将相关的函数工具分组到
[命名空间](https://developers.openai.com/api/docs/guides/function-calling#defining-namespaces) 中。
当 Responses API 返回带有 `namespace` 的 `function_call` 时，OpenAI 提供商
会在生成的 `tool-call` 部分上通过
`providerMetadata.openai.namespace` 暴露此值。

```ts
for (const part of result.content) {
  if (part.type === 'tool-call') {
    console.log(part.providerMetadata?.openai?.namespace);
  }
}
```

当使用 `streamText` 时，命名空间在 `tool-input-end` 事件和最终的 `tool-call` 事件上可用：

```ts
for await (const part of result.stream) {
  if (part.type === 'tool-input-end' || part.type === 'tool-call') {
    console.log(part.providerMetadata?.openai?.namespace);
  }
}
```

如果你为后续轮次持久化或重建消息，请保留工具调用部分上的 OpenAI 提供商元数据。SDK 使用 `providerMetadata.openai.namespace` 或 `providerOptions.openai.namespace` 在后续请求中将命名空间往返回 OpenAI。

#### 网络搜索工具

OpenAI responses API 通过 `openai.tools.webSearch` 工具支持网络搜索。

```ts
const result = await generateText({
  model: openai('gpt-5'),
  prompt: '上周旧金山发生了什么？',
  tools: {
    web_search: openai.tools.webSearch({
      // 可选配置：
      externalWebAccess: true,
      searchContextSize: 'high',
      userLocation: {
        type: 'approximate',
        city: 'San Francisco',
        region: 'California',
      },
      filters: {
        allowedDomains: ['sfchronicle.com', 'sfgate.com'],
      },
    }),
  },
  // 强制使用网络搜索工具（可选）：
  toolChoice: { type: 'tool', toolName: 'web_search' },
});

// 来自 `results` 的 URL 来源
const sources = result.sources;

// 或从工具结果访问来源
for (const toolResult of result.toolResults) {
  if (toolResult.toolName === 'web_search') {
    console.log('查询:', toolResult.output.action.query);
    console.log('来源:', toolResult.output.sources);
    // `sources` 是一个对象数组：{ type: 'url', url: string }
  }
}
```

网络搜索工具支持以下配置选项：

- **externalWebAccess** _boolean_ - 是否使用外部网络访问来获取实时内容。默认为 `true`。
- **searchContextSize** _'low' | 'medium' | 'high'_ - 控制搜索使用的上下文量。较高的值提供更全面的结果，但可能具有更高的延迟和成本。
- **userLocation** - 可选的位置信息，用于提供地理相关的结果。包括 `type`（始终为 `'approximate'`）、`country`、`city`、`region` 和 `timezone`。
- **filters** - 可选的过滤器配置，用于限制搜索结果。
  - **allowedDomains** _string[]_ - 允许搜索的域名数组。提供的域名的子域会自动包含在内。

有关配置选项的详细信息，请参阅 [OpenAI 网络搜索工具文档](https://platform.openai.com/docs/guides/tools-web-search?api-mode=responses)。

#### 文件搜索工具

OpenAI responses API 通过 `openai.tools.fileSearch` 工具支持文件搜索。

你可以通过将 `toolChoice` 参数设置为 `{ type: 'tool', toolName: 'file_search' }` 来强制使用文件搜索工具。

```ts
const result = await generateText({
  model: openai('gpt-5'),
  prompt: '文档中关于用户身份验证说了什么？',
  tools: {
    file_search: openai.tools.fileSearch({
      vectorStoreIds: ['vs_123'],
      // 以下配置是可选的：
      maxNumResults: 5,
      filters: {
        key: 'author',
        type: 'eq',
        value: 'Jane Smith',
      },
      ranking: {
        ranker: 'auto',
        scoreThreshold: 0.5,
      },
    }),
  },
  providerOptions: {
    openai: {
      // 可选：包含结果
      include: ['file_search_call.results'],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

文件搜索工具支持使用比较过滤器和复合过滤器进行过滤：

**比较过滤器** - 按单个属性过滤：

- `eq` - 等于
- `ne` - 不等于
- `gt` - 大于
- `gte` - 大于或等于
- `lt` - 小于
- `lte` - 小于或等于
- `in` - 值在数组中
- `nin` - 值不在数组中

```ts
// 单个比较过滤器
filters: { key: 'year', type: 'gte', value: 2023 }

// 带数组值的过滤器
filters: { key: 'status', type: 'in', value: ['published', 'reviewed'] }
```

**复合过滤器** - 使用 `and` 或 `or` 组合多个过滤器：

```ts
// 使用 AND 的复合过滤器
filters: {
  type: 'and',
  filters: [
    { key: 'author', type: 'eq', value: 'Jane Smith' },
    { key: 'year', type: 'gte', value: 2023 },
  ],
}

// 使用 OR 的复合过滤器
filters: {
  type: 'or',
  filters: [
    { key: 'department', type: 'eq', value: 'Engineering' },
    { key: 'department', type: 'eq', value: 'Research' },
  ],
}
```

#### MCP 工具

OpenAI responses API 支持通过 `openai.tools.mcp` 工具连接到 [模型上下文协议 (MCP)](https://modelcontextprotocol.io/) 服务器。这允许模型调用由远程 MCP 服务器或服务连接器暴露的工具。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-5'),
  prompt: '搜索网络，查找关于 AI 发展的最新新闻',
  tools: {
    mcp: openai.tools.mcp({
      serverLabel: 'web-search',
      serverUrl: 'https://mcp.exa.ai/mcp',
      serverDescription: '一个用于 AI 智能体的网络搜索 API',
    }),
  },
});
```

MCP 工具可以配置为：

- **serverLabel** _string_ (必需)

  用于标识 MCP 服务器的标签。此标签在工具调用中用于区分多个 MCP 服务器。

- **serverUrl** _string_ (如果未提供 `connectorId` 则为必需)

  MCP 服务器的 URL。必须提供 `serverUrl` 或 `connectorId` 之一。

- **connectorId** _string_ (如果未提供 `serverUrl` 则为必需)

  服务连接器的标识符。必须提供 `serverUrl` 或 `connectorId` 之一。

- **serverDescription** _string_ (可选)

  MCP 服务器的可选描述，帮助模型理解其用途。

- **allowedTools** _string[] | object_ (可选)

  控制 MCP 服务器上的哪些工具可用。可以是：
  - 工具名称数组：`['tool1', 'tool2']`
  - 带有过滤器的对象：
    ```ts
    {
      readOnly: true, // 只允许只读工具
      toolNames: ['tool1', 'tool2'] // 特定的工具名称
    }
    ```

- **authorization** _string_ (可选)

  用于向 MCP 服务器或连接器进行身份验证的 OAuth 访问令牌。

- **headers** _Record&lt;string, string&gt;_ (可选)

  包含在向 MCP 服务器发出的请求中的可选 HTTP 标头。

- **requireApproval** _'always' | 'never' | object_ (可选)

  控制哪些 MCP 工具调用在执行前需要用户批准。可以是：
  - `'always'`：所有 MCP 工具调用都需要批准
  - `'never'`：没有 MCP 工具调用需要批准（默认）
  - 带有过滤器的对象：
    ```ts
    {
      never: {
        toolNames: ['safe_tool', 'another_safe_tool']; // 跳过这些工具的批准
      }
    }
    ```

  当需要批准时，模型将返回一个 `tool-approval-request` 内容部分，你可以使用它来提示用户批准。有关实现批准工作流的更多详细信息，请参阅 [人在回路中](/cookbook/next/human-in-the-loop)。

<Note>
  当未设置 `requireApproval` 时，工具调用默认被批准。请确保只连接到你信任的 MCP 服务器，并且你信任它们共享你的数据。
</Note>

<Note>
  OpenAI MCP 工具不同于 [MCP 工具](/docs/ai-sdk-core/mcp-tools) 中记录的一般 MCP 客户端方法。OpenAI MCP 工具是一个内置的提供商定义工具，允许 OpenAI 模型直接连接到 MCP 服务器，而一般 MCP 客户端要求你首先将 MCP 工具转换为 AI SDK 工具。
</Note>

#### Shell 工具

OpenAI Responses API 通过 `openai.tools.shell` 工具支持 shell 工具。
shell 工具允许运行 bash 命令并与命令行交互。
模型提出 shell 命令；你的集成执行它们并返回输出。

<Note type="warning">
  运行任意的 shell 命令可能很危险。在将命令转发到系统 shell 之前，始终使用沙箱执行或添加严格的允许/拒绝列表。
</Note>

shell 工具支持三种环境模式，用于控制命令的执行位置：

##### 本地执行（默认）

当未指定 `environment`（或使用 `type: 'local'`）时，命令通过你的 `execute` 回调在本地执行：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-5.2'),
  tools: {
    shell: openai.tools.shell({
      execute: async ({ action }) => {
        // ... 你的实现，例如沙箱访问 ...
        return { output: results };
      },
    }),
  },
  prompt: '列出当前目录中的文件并显示磁盘使用情况。',
});
```

##### 托管容器（自动）

将 `environment.type` 设置为 `'containerAuto'` 以在 OpenAI 托管的容器中运行命令。不需要 `execute` 回调——OpenAI 在服务端处理执行：

```ts
const result = await generateText({
  model: openai('gpt-5.2'),
  tools: {
    shell: openai.tools.shell({
      environment: {
        type: 'containerAuto',
        // 可选配置：
        memoryLimit: '4g',
        fileIds: ['file-abc123'],
        networkPolicy: {
          type: 'allowlist',
          allowedDomains: ['example.com'],
        },
      },
    }),
  },
  prompt: '安装 numpy 并计算 3x3 矩阵的特征值。',
});
```

`containerAuto` 环境支持：

- **fileIds** _string[]_ - 要在容器中提供的文件 ID
- **memoryLimit** _'1g' | '4g' | '16g' | '64g'_ - 容器的内存限制
- **networkPolicy** - 网络访问策略：
  - `{ type: 'disabled' }` — 无网络访问
  - `{ type: 'allowlist', allowedDomains: string[], domainSecrets?: Array<{ domain, name, value }> }` — 允许特定域，并可选择包含密钥

##### 现有容器引用

将 `environment.type` 设置为 `'containerReference'` 以使用现有容器（通过 ID）：

```ts
const result = await generateText({
  model: openai('gpt-5.2'),
  tools: {
    shell: openai.tools.shell({
      environment: {
        type: 'containerReference',
        containerId: 'cntr_abc123',
      },
    }),
  },
  prompt: '检查正在运行的进程的状态。',
});
```

##### Execute 回调

对于本地执行（默认或 `type: 'local'`），你的 execute 函数必须返回一个包含每个命令结果的输出数组：

- **stdout** _string_ - 命令的标准输出
- **stderr** _string_ - 命令的标准错误
- **outcome** - 可以是 `{ type: 'timeout' }` 或 `{ type: 'exit', exitCode: number }`

##### 技能

[技能](https://platform.openai.com/docs/guides/tools-skills) 是带有 `SKILL.md` 清单的版本化文件包，用于扩展 shell 工具的功能。它们可以附加到 `containerAuto` 和 `local` 环境。

**容器技能** 支持两种格式——按引用（适用于上传到 OpenAI 的技能）或内联（作为 base64 编码的 zip）：

```ts
const result = await generateText({
  model: openai('gpt-5.2'),
  tools: {
    shell: openai.tools.shell({
      environment: {
        type: 'containerAuto',
        skills: [
          // 按引用：
          { type: 'skillReference', skillId: 'skill_abc123' },
          // 或内联：
          {
            type: 'inline',
            name: 'my-skill',
            description: '此技能的作用',
            source: {
              type: 'base64',
              mediaType: 'application/zip',
              data: readFileSync('./my-skill.zip').toString('base64'),
            },
          },
        ],
      },
    }),
  },
  prompt: '使用此技能解决这个问题。',
});
```

**本地技能** 指向磁盘上包含 `SKILL.md` 文件的目录：

```ts
const result = await generateText({
  model: openai('gpt-5.2'),
  tools: {
    shell: openai.tools.shell({
      execute: async ({ action }) => {
        // ... 你的本地执行实现 ...
        return { output: results };
      },
      environment: {
        type: 'local',
        skills: [
          {
            name: 'my-skill',
            description: '此技能的作用',
            path: resolve('path/to/skill-directory'),
          },
        ],
      },
    }),
  },
  prompt: '使用此技能解决这个问题。',
  stopWhen: isStepCount(5),
});
```

有关创建技能的更多详细信息，请参阅 [OpenAI 技能文档](https://platform.openai.com/docs/guides/tools-skills)。

#### 应用补丁工具

OpenAI Responses API 通过 `openai.tools.applyPatch` 工具支持 GPT-5.1 模型的应用补丁工具。
应用补丁工具允许模型使用结构化差异创建、更新和删除代码库中的文件。
模型不是仅仅建议编辑，而是发出补丁操作，你的应用程序应用这些操作并报告结果，
从而实现迭代的多步骤代码编辑工作流。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, isStepCount } from 'ai';

const result = await generateText({
  model: openai('gpt-5.1'),
  tools: {
    apply_patch: openai.tools.applyPatch({
      execute: async ({ callId, operation }) => {
        // ... 你用于应用差异的实现。
      },
    }),
  },
  prompt: '创建一个计算数字阶乘的 Python 文件',
  stopWhen: isStepCount(5),
});
```

你的 execute 函数必须返回：

- **status** _'completed' | 'failed'_ - 补丁是否成功应用
- **output** _string_ (可选) - 人类可读的日志文本（例如，结果或错误消息）

#### 工具搜索

工具搜索允许模型根据需要动态搜索并将工具加载到上下文中，
而不是预先加载所有工具定义。当你有很多工具时，这可以减少 token 使用量、成本和延迟。
在工具的 `providerOptions` 中使用 `deferLoading: true` 标记你想要使其可搜索的工具。

有两种执行模式：

- **服务端执行（托管）：** OpenAI 搜索请求中声明的延迟工具，并在同一响应中返回加载的子集。不需要额外的往返。
- **客户端执行：** 模型发出 `tool_search_call`，你的应用程序执行查找，并通过 `execute` 回调返回匹配的工具。

##### 服务端执行（托管）工具搜索

当候选工具在请求时已知时，使用托管工具搜索。
添加不带参数的 `openai.tools.toolSearch()`，并用 `deferLoading: true` 标记你的工具：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, tool, isStepCount } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: openai.responses('gpt-5.4'),
  prompt: '旧金山的天气怎么样？',
  stopWhen: isStepCount(10),
  tools: {
    toolSearch: openai.tools.toolSearch(),

    get_weather: tool({
      description: '获取特定位置的当前天气',
      inputSchema: z.object({
        location: z.string(),
        unit: z.enum(['celsius', 'fahrenheit']),
      }),
      execute: async ({ location, unit }) => ({
        location,
        temperature: unit === 'celsius' ? 18 : 64,
      }),
      providerOptions: {
        openai: { deferLoading: true },
      },
    }),

    search_files: tool({
      description: '在工作区中搜索文件',
      inputSchema: z.object({ query: z.string() }),
      execute: async ({ query }) => ({
        results: [`找到 3 个匹配 "${query}" 的文件`],
      }),
      providerOptions: {
        openai: { deferLoading: true },
      },
    }),
  },
});
```

在托管模式下，模型在内部搜索延迟工具，加载相关的工具，并继续调用它们——所有这些都在单个响应中完成。`tool_search_call` 和 `tool_search_output` 项会出现在响应中，并带有 `execution: 'server'` 和 `call_id: null`。

##### 命名空间

使用 `providerOptions.openai.namespace` 为 OpenAI 分组相关的函数工具。
SDK 保持每个工具作为普通的 AI SDK 工具可执行，但将分组的工具序列化为请求中的 OpenAI `namespace` 条目：

```ts
const crmNamespace = {
  name: 'crm',
  description: '用于客户查找和订单管理的 CRM 工具。',
};

const result = await generateText({
  model: openai.responses('gpt-5.4'),
  prompt: '列出客户 cust_123 的未结订单。',
  tools: {
    toolSearch: openai.tools.toolSearch(),

    get_customer_profile: tool({
      description: '通过客户 ID 获取客户资料。',
      inputSchema: z.object({ customer_id: z.string() }),
      execute: async ({ customer_id }) => ({ customer_id }),
      providerOptions: {
        openai: { namespace: crmNamespace },
      },
    }),

    list_open_orders: tool({
      description: '列出客户 ID 的未结订单。',
      inputSchema: z.object({ customer_id: z.string() }),
      execute: async ({ customer_id }) => ({ customer_id, orders: [] }),
      providerOptions: {
        openai: {
          namespace: crmNamespace,
          deferLoading: true,
        },
      },
    }),
  },
});
```

同一命名空间中的工具必须使用相同的命名空间 `name` 和 `description`。
为了获得最佳的工具搜索结果，请保持命名空间描述简洁，并将详细的使用指南放在各个函数工具上。

##### 客户端执行工具搜索

当工具发现依赖于运行时状态时——例如，因租户、项目或外部系统而异的工具——使用客户端执行工具搜索。传递 `execution: 'client'` 以及 `description`、`parameters` schema 和 `execute` 回调：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, tool, isStepCount } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: openai.responses('gpt-5.4'),
  prompt: '旧金山的天气怎么样？',
  stopWhen: isStepCount(10),
  tools: {
    toolSearch: openai.tools.toolSearch({
      execution: 'client',
      description: '根据用户需要搜索可用工具。',
      parameters: {
        type: 'object',
        properties: {
          goal: {
            type: 'string',
            description: '用户试图完成什么',
          },
        },
        required: ['goal'],
        additionalProperties: false,
      },
      execute: async ({ arguments: args }) => {
        // 你自定义的工具发现逻辑在此。
        // 返回与搜索目标匹配的工具。
        return {
          tools: [
            {
              type: 'function',
              name: 'get_weather',
              description: '获取特定位置的当前天气',
              deferLoading: true,
              parameters: {
                type: 'object',
                properties: {
                  location: { type: 'string' },
                },
                required: ['location'],
                additionalProperties: false,
              },
            },
          ],
        };
      },
    }),

    get_weather: tool({
      description: '获取特定位置的当前天气',
      inputSchema: z.object({ location: z.string() }),
      execute: async ({ location }) => ({
        location,
        temperature: 64,
        condition: 'Partly cloudy',
      }),
      providerOptions: {
        openai: { deferLoading: true },
      },
    }),
  },
});
```

在客户端模式下，流程跨越两个步骤：

1. **步骤 1：** 模型发出一个带有 `execution: 'client'` 和非空 `call_id` 的 `tool_search_call`。SDK 使用搜索参数调用你的 `execute` 回调。你的回调返回发现的工具。
2. **步骤 2：** SDK 将 `tool_search_output`（带有匹配的 `call_id`）发送回模型。模型现在可以像普通函数调用一样调用加载的工具。

有关更多详细信息，请参阅 [OpenAI 工具搜索文档](https://platform.openai.com/docs/guides/tools-tool-search)。

#### 自定义工具

OpenAI Responses API 通过 `openai.tools.customTool` 工具支持
[自定义工具](https://developers.openai.com/api/docs/guides/function-calling/#custom-tools)。
自定义工具返回原始字符串而不是 JSON，可选择受语法（正则表达式或 Lark 语法）约束。这使得它们对于生成结构化文本（如 SQL 查询、代码片段或任何必须匹配特定模式的输出）非常有用。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, isStepCount } from 'ai';

const result = await generateText({
  model: openai.responses('gpt-5.2-codex'),
  tools: {
    write_sql: openai.tools.customTool({
      description: '编写一个 SQL SELECT 查询来回答用户的问题。',
      format: {
        type: 'grammar',
        syntax: 'regex',
        definition: 'SELECT .+',
      },
      execute: async input => {
        // input 是一个匹配语法的原始字符串，例如 "SELECT * FROM users WHERE age > 25"
        const rows = await db.query(input);
        return JSON.stringify(rows);
      },
    }),
  },
  toolChoice: 'required',
  prompt: '编写一个 SQL 查询来获取所有年龄大于 25 的用户。',
  stopWhen: isStepCount(3),
});
```

自定义工具也可以与 `streamText` 一起使用：

```ts
import { openai } from '@ai-sdk/openai';
import { streamText } from 'ai';

const result = streamText({
  model: openai.responses('gpt-5.2-codex'),
  tools: {
    write_sql: openai.tools.customTool({
      description: '编写一个 SQL SELECT 查询来回答用户的问题。',
      format: {
        type: 'grammar',
        syntax: 'regex',
        definition: 'SELECT .+',
      },
    }),
  },
  toolChoice: 'required',
  prompt: '编写一个 SQL 查询来获取所有年龄大于 25 的用户。',
});

for await (const chunk of result.stream) {
  if (chunk.type === 'tool-call') {
    console.log(`工具: ${chunk.toolName}`);
    console.log(`输入: ${chunk.input}`);
  }
}
```

自定义工具可以配置为：

- **description** _string_ (可选) - 工具功能的描述，帮助模型理解何时使用它。
- **format** _object_ (可选) - 输出格式约束。省略以进行无约束的文本输出。
  - **type** _'grammar' | 'text'_ - 格式类型。使用 `'grammar'` 进行约束输出，或使用 `'text'` 进行显式无约束文本。
  - **syntax** _'regex' | 'lark'_ - (仅语法) 语法语法。使用 `'regex'` 进行正则表达式模式，或使用 `'lark'` 进行 [Lark 解析器语法](https://lark-parser.readthedocs.io/)。
  - **definition** _string_ - (仅语法) 语法定义字符串（正则表达式模式或 Lark 语法）。
- **execute** _function_ (可选) - 一个异步函数，接收原始字符串输入并返回字符串结果。启用多轮工具调用。

#### 文本部分中的类型化 providerMetadata

当使用 OpenAI Responses API 时，SDK 会通过 `providerMetadata` 将 OpenAI 特定的元数据附加到输出部分。

此元数据可以在客户端用于诸如渲染引用或下载由代码解释器生成的文件等任务。
为了启用此元数据的类型安全处理，AI SDK 导出了专用的 TypeScript 类型。

对于文本部分，当 `part.type === 'text'` 时，`providerMetadata` 以 `OpenaiResponsesTextProviderMetadata` 的形式提供。

此元数据包括以下字段：

- `itemId`
  Responses API 中输出项的 ID。
- `annotations` (可选)
  由模型生成的注释对象数组。
  如果没有注释，此属性本身可能被省略 (`undefined`)。

  `annotations` 中的每个元素都是一个带有必需 `type` 字段的判别联合。支持的类型包括，例如：
  - `url_citation`
  - `file_citation`
  - `container_file_citation`
  - `file_path`

  这些注释直接对应于 Responses API 定义的注释对象，可用于内联引用渲染或输出分析。
  有关详细信息，请参阅官方 OpenAI 文档：
  [Responses API – 输出文本注释](https://platform.openai.com/docs/api-reference/responses/object?lang=javascript#responses-object-output-output_message-content-output_text-annotations)。

```ts
import {
  openai,
  type OpenaiResponsesTextProviderMetadata,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-4.1-mini'),
  prompt:
    '创建一个程序，生成五个介于 1 和 100 之间、保留两位小数的随机数，并向我展示执行结果。同时将结果保存到一个文件中。',
  tools: {
    code_interpreter: openai.tools.codeInterpreter(),
    web_search: openai.tools.webSearch(),
    file_search: openai.tools.fileSearch({ vectorStoreIds: ['vs_1234'] }), // 需要一个已配置的向量存储
  },
});

for (const part of result.content) {
  if (part.type === 'text') {
    const providerMetadata = part.providerMetadata as
      | OpenaiResponsesTextProviderMetadata
      | undefined;
    if (!providerMetadata) continue;
    const { itemId: _itemId, annotations } = providerMetadata.openai;

    if (!annotations) continue;
    for (const annotation of annotations) {
      switch (annotation.type) {
        case 'url_citation':
          // url_citation 从 web_search 返回，并提供：
          // 属性：type, url, title, start_index 和 end_index
          break;
        case 'file_citation':
          // file_citation 从 file_search 返回，并提供：
          // 属性：type, file_id, filename 和 index
          break;
        case 'container_file_citation':
          // container_file_citation 从 code_interpreter 返回，并提供：
          // 属性：type, container_id, file_id, filename, start_index 和 end_index
          break;
        case 'file_path':
          // file_path 提供：
          // 属性：type, file_id 和 index
          break;
        default: {
          const _exhaustiveCheck: never = annotation;
          throw new Error(
            `未处理的注释: ${JSON.stringify(_exhaustiveCheck)}`,
          );
        }
      }
    }
  }
}
```

<Note>
  当实现由代码解释器生成的文件的文件下载时，`providerMetadata` 中可用的 `container_id` 和 `file_id` 可用于检索文件内容。有关详细信息，请参阅 [检索容器文件内容](https://platform.openai.com/docs/api-reference/container-files/retrieveContainerFileContent) API。
</Note>

#### 推理部分中的类型化 providerMetadata

当使用 OpenAI Responses API 时，推理输出部分可以包含提供商元数据。
为了以类型安全的方式处理此元数据，请使用 `OpenaiResponsesReasoningProviderMetadata`。

对于推理部分，当 `part.type === 'reasoning'` 时，`providerMetadata` 以 `OpenaiResponsesReasoningProviderMetadata` 的形式提供。

此元数据包括以下字段：

- `itemId`  
  Responses API 中推理项的 ID。
- `reasoningEncryptedContent` (可选)  
  加密的推理内容（仅当通过 `include: ['reasoning.encrypted_content']` 请求时返回）。

```ts
import {
  openai,
  type OpenaiResponsesReasoningProviderMetadata,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-5'),
  prompt: '"strawberry" 这个词中有多少个 "r"？',
  providerOptions: {
    openai: {
      store: false,
      include: ['reasoning.encrypted_content'],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});

for (const part of result.content) {
  if (part.type === 'reasoning') {
    const providerMetadata = part.providerMetadata as
      | OpenaiResponsesReasoningProviderMetadata
      | undefined;

    const { itemId, reasoningEncryptedContent } =
      providerMetadata?.openai ?? {};
    console.log(itemId, reasoningEncryptedContent);
  }
}
```

#### 源文档部分中的类型化 providerMetadata

对于源文档部分，当 `part.type === 'source'` 且 `sourceType === 'document'` 时，`providerMetadata` 以 `OpenaiResponsesSourceDocumentProviderMetadata` 的形式提供。

此元数据也是一个带有必需 `type` 字段的判别联合。支持的类型包括：

- `file_citation`
- `container_file_citation`
- `file_path`

每种类型都包含使用所引用资源所需的标识符，例如 `fileId` 和 `containerId`。

```ts
import {
  openai,
  type OpenaiResponsesSourceDocumentProviderMetadata,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-4.1-mini'),
  prompt:
    '创建一个程序，生成五个介于 1 和 100 之间、保留两位小数的随机数，并向我展示执行结果。同时将结果保存到一个文件中。',
  tools: {
    code_interpreter: openai.tools.codeInterpreter(),
    web_search: openai.tools.webSearch(),
    file_search: openai.tools.fileSearch({ vectorStoreIds: ['vs_1234'] }), // 需要一个已配置的向量存储
  },
});

for (const part of result.content) {
  if (part.type === 'source') {
    if (part.sourceType === 'document') {
      const providerMetadata = part.providerMetadata as
        | OpenaiResponsesSourceDocumentProviderMetadata
        | undefined;
      if (!providerMetadata) continue;
      const annotation = providerMetadata.openai;
      switch (annotation.type) {
        case 'file_citation':
          // file_citation 从 file_search 返回，并提供：
          // 属性：type, fileId 和 index
          // 文件名可以通过 part.filename 访问。
          break;
        case 'container_file_citation':
          // container_file_citation 从 code_interpreter 返回，并提供：
          // 属性：type, containerId 和 fileId
          // 文件名可以通过 part.filename 访问。
          break;
        case 'file_path':
          // file_path 提供：
          // 属性：type, fileId 和 index
          break;
        default: {
          const _exhaustiveCheck: never = annotation;
          throw new Error(
            `未处理的注释: ${JSON.stringify(_exhaustiveCheck)}`,
          );
        }
      }
    }
  }
}
```

<Note>
  文本部分中的注释遵循 OpenAI Responses API 规范，因此使用蛇形命名法属性（例如 `file_id`、`container_id`）。相比之下，源文档部分的 `providerMetadata` 由 SDK 规范化为驼峰命名法（例如 `fileId`、`containerId`）。依赖于原始文本内容的字段，如 `start_index` 和 `end_index`，会被省略，同样，像 `filename` 这样直接在源对象上可用的字段也会被省略。
</Note>

#### 压缩

OpenAI Responses API 支持服务端上下文压缩。启用后，当 token 使用量超过配置的阈值时，服务器会自动压缩对话上下文。这对于长时间运行的对话或智能体循环非常有用，在这些场景中，你希望保持在 token 限制内，而无需手动管理上下文。

服务器返回的压缩项是不透明且加密的——它使用更少的 token 将关键的先前状态和推理带入下一轮。AI SDK 会自动处理此问题：压缩项作为带有特殊 `providerMetadata` 的文本部分返回，并且在后续请求中传回时，它们会作为压缩输入项发送。

```ts highlight="7-11"
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai.responses('gpt-5.2'),
  messages: conversationHistory,
  providerOptions: {
    openai: {
      store: false,
      contextManagement: [{ type: 'compaction', compactThreshold: 50000 }],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

**配置：**

- **type** — 必须为 `'compaction'`
- **compactThreshold** — 触发压缩的 token 数量。当渲染的输入 token 数量超过此阈值时，服务器会在继续推理之前运行一次压缩。

<Note>
  当你在请求中设置 `store: false` 时，服务端压缩是 ZDR 友好的。
</Note>

##### 在流中检测压缩

当使用 `streamText` 时，你可以通过检查 `text-start` 和 `text-end` 事件上的 `providerMetadata` 来检测压缩：

```ts
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { streamText } from 'ai';

const result = streamText({
  model: openai.responses('gpt-5.2'),
  messages: conversationHistory,
  providerOptions: {
    openai: {
      store: false,
      contextManagement: [{ type: 'compaction', compactThreshold: 50000 }],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});

for await (const part of result.stream) {
  switch (part.type) {
    case 'text-start': {
      const isCompaction = part.providerMetadata?.openai?.type === 'compaction';
      if (isCompaction) {
        // ... 你的逻辑
      }
      break;
    }
    case 'text-end': {
      const isCompaction = part.providerMetadata?.openai?.type === 'compaction';
      if (isCompaction) {
        // ... 你的逻辑
      }
      break;
    }
    case 'text-delta': {
      process.stdout.write(part.text);
      break;
    }
  }
}
```

##### UI 应用中的压缩

当使用 `useChat` 或其他 UI Hook 时，压缩项会作为带有 `providerMetadata` 的文本部分出现。你可以在 UI 中检测它们并应用不同的样式：

```tsx
{
  message.parts.map((part, index) => {
    if (part.type === 'text') {
      const isCompaction =
        (part.providerMetadata?.openai as { type?: string } | undefined)
          ?.type === 'compaction';

      if (isCompaction) {
        return (
          <div
            key={index}
            className="bg-yellow-100 border-l-4 border-yellow-500 p-2"
          >
            <span className="font-bold">[上下文已压缩]</span>
            <p className="text-sm text-yellow-700">
              服务器压缩了对话上下文以减少 token 使用量。
            </p>
          </div>
        );
      }
      return <div key={index}>{part.text}</div>;
    }
  });
}
```

元数据包括以下字段：

- **type** — 始终为 `'compaction'`
- **itemId** _string_ — Responses API 中压缩项的 ID
- **encryptedContent** _string_ (可选) — 加密的压缩状态。当消息包含在后续请求中时，它会自动发送回 API。

### 聊天模型

你可以使用 `.chat()` 工厂方法创建调用 [OpenAI 聊天 API](https://platform.openai.com/docs/api-reference/chat) 的模型。
第一个参数是模型 ID，例如 `gpt-4`。
OpenAI 聊天模型支持工具调用，并且一些模型具有多模态能力。
当自定义 `baseURL` 指向实现 Chat Completions 但不实现 Responses API 的 OpenAI 兼容端点时，请使用此工厂。

```ts
const model = openai.chat('gpt-5');
```

OpenAI 聊天模型也支持一些不属于 [标准调用设置](/docs/ai-sdk-core/settings) 的模型特定提供商选项。
你可以在 `providerOptions` 参数中传递它们：

```ts
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';

const model = openai.chat('gpt-5');

await generateText({
  model,
  providerOptions: {
    openai: {
      logitBias: {
        // 特定 token 的可选可能性
        '50256': -100,
      },
      user: 'test-user', // 可选的唯一用户标识符
    } satisfies OpenAILanguageModelChatOptions,
  },
});
```

以下可选的提供商选项可用于 OpenAI 聊天模型：

- **logitBias** _Record&lt;number, number&gt;_

  修改指定 token 出现在补全中的可能性。

  接受一个 JSON 对象，该对象将 token（由其 token ID 在 GPT 分词器中指定）映射到 -100 到 100 之间的关联偏差值。你可以使用此分词器工具将文本转换为 token ID。从数学上讲，偏差会在采样之前添加到模型生成的 logits 中。确切效果因模型而异，但 -1 到 1 之间的值应降低或增加选择的可能性；像 -100 或 100 这样的值应导致禁止或独占选择相关 token。

  例如，你可以传递 `{"50256": -100}` 来阻止生成该 token。

- **logprobs** _boolean | number_

  返回 token 的对数概率。包含 logprobs 会增加响应大小并可能减慢响应时间。但是，它有助于更好地理解模型的行为。

  设置为 true 将返回生成的 token 的对数概率。

  设置为数字将返回生成的前 n 个 token 的对数概率。

- **parallelToolCalls** _boolean_

  是否在工具使用期间启用并行函数调用。默认为 `true`。

- **user** _string_

  代表最终用户的唯一标识符，可帮助 OpenAI 监控和检测滥用。[了解更多](https://platform.openai.com/docs/guides/safety-best-practices/end-user-ids)。

- **reasoningEffort** _'minimal' | 'low' | 'medium' | 'high' | 'xhigh'_

  推理模型的推理努力程度。默认为 `medium`。如果你使用 `providerOptions` 设置 `reasoningEffort` 选项，则此模型设置将被忽略。

- **maxCompletionTokens** _number_

  要生成的最大补全 token 数。对推理模型有用。

- **store** _boolean_

  是否在 Responses API 中启用持久化。

- **metadata** _Record&lt;string, string&gt;_

  要与请求关联的元数据。

- **prediction** _Record&lt;string, any&gt;_

  预测模式的参数。

- **serviceTier** _'auto' | 'flex' | 'priority' | 'default'_

  请求的服务层级。设置为 'flex' 可获得 50% 更便宜的处理，但会增加延迟（适用于 o3、o4-mini 和 gpt-5 模型）。设置为 'priority' 可获得更快的处理速度和 Enterprise 访问权限（适用于 gpt-4、gpt-5、gpt-5-mini、o3、o4-mini；不支持 gpt-5-nano）。

  默认为 'auto'。

- **strictJsonSchema** _boolean_

  是否使用严格的 JSON schema 验证。
  默认为 `true`。

- **textVerbosity** _'low' | 'medium' | 'high'_

  控制模型响应的详细程度。较低的值会产生更简洁的响应，而较高的值会产生更详细的响应。

- **promptCacheKey** _string_

  用于手动提示缓存控制的缓存键。OpenAI 使用它来缓存相似请求的响应，以优化你的缓存命中率。

- **promptCacheRetention** _'in_memory' | '24h'_

  提示缓存的保留策略。设置为 `'24h'` 以启用扩展提示缓存，该缓存使缓存的前缀保持活动状态长达 24 小时。默认为 `'in_memory'` 用于标准提示缓存。注意：`'24h'` 目前仅适用于 5.1 系列模型。

- **safetyIdentifier** _string_

  一个稳定的标识符，用于帮助检测可能违反 OpenAI 使用政策的应用程序用户。ID 应是一个唯一标识每个用户的字符串。

- **systemMessageMode** _'system' | 'developer' | 'remove'_

  覆盖此模型的系统消息模式。如果未指定，则根据模型自动确定模式。`system` 对系统消息使用 'system' 角色（大多数模型的默认值）；`developer` 使用 'developer' 角色（由推理模型使用）；`remove` 完全删除系统消息。

- **forceReasoning** _boolean_

  强制将此模型视为推理模型。这对于“隐身”推理模型（例如通过自定义 baseURL）很有用，其中模型 ID 未被 SDK 的允许列表识别。启用后，SDK 会应用推理模型参数兼容性规则，并将 `systemMessageMode` 默认为 `developer`，除非被覆盖。

#### 推理

OpenAI 推出了 `o1`、`o3` 和 `o4` 系列的 [推理模型](https://platform.openai.com/docs/guides/reasoning)。
目前，`o4-mini`、`o3`、`o3-mini` 和 `o1` 可通过聊天和 responses API 使用。模型 `gpt-5.1-codex-mini` 仅可通过 [responses API](#responses-models) 使用。

推理模型目前仅生成文本，有一些限制，并且仅支持使用 `generateText` 和 `streamText`。

它们支持额外的设置和响应元数据：

- 你可以使用 `providerOptions` 设置
  - `reasoningEffort` 选项（或替代的 `reasoningEffort` 模型设置），它决定模型执行的推理量。

- 你可以使用响应 `usage` 通过 `usage.outputTokenDetails.reasoningTokens` 访问模型生成的推理 token 数量。

```ts highlight="4,7-11,17"
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text, usage } = await generateText({
  model: openai.chat('gpt-5'),
  prompt: '发明一个新的节日并描述其传统。',
  providerOptions: {
    openai: {
      reasoningEffort: 'low',
    } satisfies OpenAILanguageModelChatOptions,
  },
});

console.log(text);
console.log('推理 token:', usage.outputTokenDetails.reasoningTokens);
```

<Note>
  对于推理模型，系统消息会在支持时自动转换为 OpenAI 开发者消息。
</Note>

- 你可以通过 providerOptions `systemMessageMode` 控制系统消息的处理方式：
  - `developer`：将提示词视为开发者消息（推理模型的默认值）。
  - `system`：将系统消息保留为系统级指令。
  - `remove`：从消息中删除系统消息。

```ts highlight="12"
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai.chat('gpt-5'),
  messages: [
    { role: 'system', content: '你是一个有用的助手。' },
    { role: 'user', content: '给我讲个笑话。' },
  ],
  providerOptions: {
    openai: {
      systemMessageMode: 'system',
    } satisfies OpenAILanguageModelChatOptions,
  },
});
```

<Note>
  推理模型在生成响应之前需要额外的运行时推理来完成其推理阶段。这与其他模型相比引入了更长的延迟。
</Note>

<Note>
  `maxOutputTokens` 会自动映射到推理模型的 `max_completion_tokens`。
</Note>

#### 严格结构化输出

默认情况下启用严格结构化输出。
你可以通过将 `strictJsonSchema` 选项设置为 `false` 来禁用它。

```ts highlight="7"
import { openai, OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText, Output } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: openai.chat('gpt-4o-2024-08-06'),
  providerOptions: {
    openai: {
      strictJsonSchema: false,
    } satisfies OpenAILanguageModelChatOptions,
  },
  output: Output.object({
    schema: z.object({
      name: z.string(),
      ingredients: z.array(
        z.object({
          name: z.string(),
          amount: z.string(),
        }),
      ),
      steps: z.array(z.string()),
    }),
    schemaName: 'recipe',
    schemaDescription: '一份千层面食谱。',
  }),
  prompt: '生成一份千层面食谱。',
});

console.log(JSON.stringify(result.output, null, 2));
```

<Note type="warning">
  OpenAI 结构化输出存在一些
  [限制](https://openai.com/index/introducing-structured-outputs-in-the-api)，
  特别是关于 [支持的 schemas](https://platform.openai.com/docs/guides/structured-outputs/supported-schemas)，
  因此是选择加入的。

例如，不支持可选的 schema 属性。
你需要将 Zod 的 `.nullish()` 和 `.optional()` 更改为 `.nullable()`。

</Note>

```ts highlight="15-18"
const result = streamText({
```

```ts highlight="11"
const openaiMetadata = (await result.providerMetadata)?.openai;
```

#### 提示缓存

OpenAI 已为支持的模型（包括 `gpt-4o` 和 `gpt-4o-mini`）引入了 [提示缓存](https://platform.openai.com/docs/guides/prompt-caching)。

- 当提示词为 1024 个 token 或更长时，这些模型会自动启用提示缓存。无需显式启用。
- 你可以使用响应 `usage` 通过 `usage.inputTokenDetails.cacheReadTokens` 访问缓存命中的提示 token 数量。
- 请注意，缓存行为取决于 OpenAI 基础设施的负载。提示前缀通常在 5-10 分钟不活动后从缓存中逐出，但在非高峰时段，它们可能持续长达一小时。

```ts highlight="11"
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text, usage } = await generateText({
  model: openai.chat('gpt-4o-mini'),
  prompt: `一个 1024 token 或更长的提示词...`,
});

console.log('缓存的 token:', usage.inputTokenDetails.cacheReadTokens);
```

为了提高缓存命中率，你可以使用 `promptCacheKey` 选项手动控制缓存：

```ts highlight="7-11"
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text, usage } = await generateText({
  model: openai.chat('gpt-5'),
  prompt: `一个 1024 token 或更长的提示词...`,
  providerOptions: {
    openai: {
      promptCacheKey: 'my-custom-cache-key-123',
    } satisfies OpenAILanguageModelChatOptions,
  },
});

console.log('缓存的 token:', usage.inputTokenDetails.cacheReadTokens);
```

对于 GPT-5.1 模型，你可以启用扩展提示缓存，使缓存的前缀保持活动状态长达 24 小时：

```ts highlight="7-12"
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text, usage } = await generateText({
  model: openai.chat('gpt-5.1'),
  prompt: `一个 1024 token 或更长的提示词...`,
  providerOptions: {
    openai: {
      promptCacheKey: 'my-custom-cache-key-123',
      promptCacheRetention: '24h', // GPT-5.1 的扩展缓存
    } satisfies OpenAILanguageModelChatOptions,
  },
});

console.log('缓存的 token:', usage.inputTokenDetails.cacheReadTokens);
```

### 补全模型

你可以使用 `.completion()` 工厂方法创建调用 [OpenAI 补全 API](https://platform.openai.com/docs/api-reference/completions) 的模型。
第一个参数是模型 ID。
目前仅支持 `gpt-3.5-turbo-instruct`。

```ts
const model = openai.completion('gpt-3.5-turbo-instruct');
```

OpenAI 补全模型也支持一些不属于 [标准调用设置](/docs/ai-sdk-core/settings) 的模型特定设置。
你可以将它们作为选项参数传递：

```ts
const model = openai.completion('gpt-3.5-turbo-instruct');

await model.doGenerate({
  providerOptions: {
    openai: {
      echo: true, // 可选，在补全之外回显提示词
      logitBias: {
        // 特定 token 的可选可能性
        '50256': -100,
      },
      suffix: 'some text', // 可选，在插入文本的补全之后出现的后缀
      user: 'test-user', // 可选的唯一用户标识符
    } satisfies OpenAILanguageModelCompletionOptions,
  },
});
```

以下可选的提供商选项可用于 OpenAI 补全模型：

- **echo**: _boolean_

  在补全之外回显提示词。

- **logitBias** _Record&lt;number, number&gt;_

  修改指定 token 出现在补全中的可能性。

  接受一个 JSON 对象，该对象将 token（由其 token ID 在 GPT 分词器中指定）映射到 -100 到 100 之间的关联偏差值。你可以使用此分词器工具将文本转换为 token ID。从数学上讲，偏差会在采样之前添加到模型生成的 logits 中。确切效果因模型而异，但 -1 到 1 之间的值应降低或增加选择的可能性；像 -100 或 100 这样的值应导致禁止或独占选择相关 token。

  例如，你可以传递 `{"50256": -100}` 来阻止生成 &lt;|endoftext|&gt; token。

- **logprobs** _boolean | number_

  返回 token 的对数概率。包含 logprobs 会增加响应大小并可能减慢响应时间。但是，它有助于更好地理解模型的行为。

  设置为 true 将返回生成的 token 的对数概率。

  设置为数字将返回生成的前 n 个 token 的对数概率。

- **suffix** _string_

  在插入文本的补全之后出现的后缀。

- **user** _string_

  代表最终用户的唯一标识符，可帮助 OpenAI 监控和检测滥用。[了解更多](https://platform.openai.com/docs/guides/safety-best-practices/end-user-ids)。

```ts
  prompt: {
    text: '把猫变成狗，但保留原始图像的风格',
    images: [imageBuffer],
  },
});
```

#### 带遮罩的修复

使用遮罩编辑图像的特定部分。遮罩中的透明区域指示应编辑图像的位置：

```ts
const image = readFileSync('./input-image.png');
const mask = readFileSync('./mask.png'); // 透明区域 = 编辑区域

const { images } = await generateImage({
  model: openai.image('gpt-image-2'),
  prompt: {
    text: '一个阳光明媚的室内休息区，带有一个包含火烈鸟的游泳池',
    images: [image],
    mask: mask,
  },
});
```

#### 背景移除

通过将 `background` 设置为 `transparent` 来移除图像的背景（在支持透明背景的模型上）：

```ts
import { openai, type OpenAIImageModelEditOptions } from '@ai-sdk/openai';
import { generateImage } from 'ai';

const imageBuffer = readFileSync('./input-image.png');

const { images } = await generateImage({
  model: openai.image('gpt-image-1.5'),
  prompt: {
    text: '不要改变任何东西',
    images: [imageBuffer],
  },
  providerOptions: {
    openai: {
      background: 'transparent',
      outputFormat: 'png',
    } satisfies OpenAIImageModelEditOptions,
  },
});
```

#### 多图像组合

将多个参考图像组合成一个输出。`gpt-image-*` 模型支持最多 16 个输入图像：

```ts
const cat = readFileSync('./cat.png');
const dog = readFileSync('./dog.png');
const owl = readFileSync('./owl.png');
const bear = readFileSync('./bear.png');

const { images } = await generateImage({
  model: openai.image('gpt-image-2'),
  prompt: {
    text: '将这些动物组合成一张合影，保留原始风格',
    images: [cat, dog, owl, bear],
  },
});
```

<Note>
  输入图像可以作为 `Buffer`、`ArrayBuffer`、`Uint8Array` 或 base64 编码的字符串提供。对于 `gpt-image-*` 模型，每个图像应为小于 50MB 的 `png`、`webp` 或 `jpg` 文件。
</Note>

### 模型能力

| 模型                | 尺寸                           |
| ------------------ | ------------------------------- |
| `gpt-image-2`      | 1024x1024, 1536x1024, 1024x1536 |
| `gpt-image-1.5`    | 1024x1024, 1536x1024, 1024x1536 |
| `gpt-image-1-mini` | 1024x1024, 1536x1024, 1024x1536 |
| `gpt-image-1`      | 1024x1024, 1536x1024, 1024x1536 |
| `dall-e-3`         | 1024x1024, 1792x1024, 1024x1792 |
| `dall-e-2`         | 256x256, 512x512, 1024x1024     |

你可以向图像模型传递可选的 `providerOptions`。这些选项可能被 OpenAI 更改，并且依赖于模型。例如，`gpt-image-*` 模型支持 `quality` 选项：

```ts
import { openai, type OpenAIImageModelGenerationOptions } from '@ai-sdk/openai';
import { generateImage } from 'ai';

const { image, providerMetadata } = await generateImage({
  model: openai.image('gpt-image-2'),
  prompt: '塞舌尔森林池塘中，日出时的一只蝾螈。',
  providerOptions: {
    openai: { quality: 'high' } satisfies OpenAIImageModelGenerationOptions,
  },
});
```

有关 `generateImage()` 的更多信息，请参阅 [图像生成](/docs/ai-sdk-core/image-generation)。

OpenAI 的图像模型会在响应中返回额外的元数据，可以通过 `providerMetadata.openai` 访问。以下 OpenAI 特定的元数据可用：

- **images** _Array&lt;object&gt;_

  图像特定元数据的数组。每个图像对象可能包含：
  - `revisedPrompt` _string_ - 实际用于生成图像的修订后提示词（OpenAI 可能会出于安全或清晰目的修改你的提示词）
  - `created` _number_ - 图像创建时的 Unix 时间戳（以秒为单位）
  - `size` _string_ - 生成图像的大小。可以是 `1024x1024`、`1024x1536` 或 `1536x1024` 之一
  - `quality` _string_ - 生成图像的质量。可以是 `low`、`medium` 或 `high` 之一
  - `background` _string_ - 用于图像生成的背景参数。可以是 `transparent` 或 `opaque`
  - `outputFormat` _string_ - 生成图像的输出格式。可以是 `png`、`webp` 或 `jpeg` 之一

有关可用 OpenAI 图像模型选项的更多信息，请参阅 [OpenAI API 参考](https://platform.openai.com/docs/api-reference/images/create)。

## 转录模型

你可以使用 `.transcription()` 工厂方法创建调用 [OpenAI 转录 API](https://platform.openai.com/docs/api-reference/audio/transcribe) 的模型。

第一个参数是模型 ID，例如 `whisper-1`。

```ts
const model = openai.transcription('whisper-1');
```

你也可以使用 `providerOptions` 参数传递额外的提供商特定选项。例如，以 ISO-639-1 格式（例如 `en`）提供输入语言将提高准确性和延迟。

```ts highlight="6"
import { transcribe } from 'ai';
import { openai, type OpenAITranscriptionModelOptions } from '@ai-sdk/openai';

const result = await transcribe({
  model: openai.transcription('whisper-1'),
  audio: new Uint8Array([1, 2, 3, 4]),
  providerOptions: {
    openai: { language: 'en' } satisfies OpenAITranscriptionModelOptions,
  },
});
```

要获取词级时间戳，请指定粒度：

```ts highlight="8-9"
import { transcribe } from 'ai';
import { openai, type OpenAITranscriptionModelOptions } from '@ai-sdk/openai';

const result = await transcribe({
  model: openai.transcription('whisper-1'),
  audio: new Uint8Array([1, 2, 3, 4]),
  providerOptions: {
    openai: {
      //timestampGranularities: ['word'],
      timestampGranularities: ['segment'],
    } satisfies OpenAITranscriptionModelOptions,
  },
});

// 访问词级时间戳
console.log(result.segments); // 包含 startSecond/endSecond 的片段数组
```

以下提供商选项可用：

- **timestampGranularities** _string[]_
  转录中时间戳的粒度。
  默认为 `['segment']`。
  可能的值是 `['word']`、`['segment']` 和 `['word', 'segment']`。
  注意：片段时间戳没有额外的延迟，但生成词时间戳会产生额外的延迟。

- **language** _string_
  输入音频的语言。以 ISO-639-1 格式（例如 'en'）提供输入语言将提高准确性和延迟。
  可选。

- **prompt** _string_
  一个可选的文本，用于指导模型的风格或继续之前的音频片段。提示词应与音频语言匹配。
  可选。

- **temperature** _number_
  采样温度，介于 0 和 1 之间。较高的值（如 0.8）会使输出更随机，而较低的值（如 0.2）会使输出更集中和确定。如果设置为 0，模型将使用对数概率自动提高温度，直到达到某些阈值。
  默认为 0。
  可选。

- **include** _string[]_
  要包含在转录响应中的附加信息。

## 语音模型

你可以使用 `.speech()` 工厂方法创建调用 [OpenAI 语音 API](https://platform.openai.com/docs/api-reference/audio/speech) 的模型。

第一个参数是模型 ID，例如 `tts-1`。

```ts
const model = openai.speech('tts-1');
```

`voice` 参数可以设置为 OpenAI 可用的语音之一：`alloy`、`ash`、`coral`、`echo`、`fable`、`onyx`、`nova`、`sage` 或 `shimmer`。

```ts highlight="6"
import { generateSpeech } from 'ai';
import { openai } from '@ai-sdk/openai';

const result = await generateSpeech({
  model: openai.speech('tts-1'),
  text: '你好，世界！',
  voice: 'alloy', // OpenAI 语音 ID
});
```

你也可以使用 `providerOptions` 参数传递额外的提供商特定选项：

```ts highlight="7-9"
import { generateSpeech } from 'ai';
import { openai, type OpenAISpeechModelOptions } from '@ai-sdk/openai';

const result = await generateSpeech({
  model: openai.speech('tts-1'),
  text: '你好，世界！',
  voice: 'alloy',
  providerOptions: {
    openai: {
      speed: 1.2,
    } satisfies OpenAISpeechModelOptions,
  },
});
```

- **instructions** _string_
  通过附加指令控制生成音频的声音，例如“用缓慢而稳定的语调说话”。
  不适用于 `tts-1` 或 `tts-1-hd`。
  可选。

- **speed** _number_
  生成音频的速度。
  选择 0.25 到 4.0 之间的值。
  默认为 1.0。
  可选。

| `gpt-4o-mini-tts` | <Check size={18} /> |
