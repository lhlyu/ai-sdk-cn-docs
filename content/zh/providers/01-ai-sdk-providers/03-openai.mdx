# OpenAI 提供商

[OpenAI](https://openai.com/) 提供商包含对 OpenAI responses、chat 和 completion API 的语言模型支持，以及对 OpenAI embeddings API 的嵌入模型支持。

## 设置

OpenAI 提供商位于 `@ai-sdk/openai` 模块中。你可以使用以下命令安装：

<InstallPackages packages="@ai-sdk/openai" />

## 提供商实例

你可以从 `@ai-sdk/openai` 导入默认提供商实例 `openai`：

```ts
import { openai } from '@ai-sdk/openai';
```

如果你需要自定义设置，可以从 `@ai-sdk/openai` 导入 `createOpenAI` 并使用你的设置创建提供商实例：

```ts
import { createOpenAI } from '@ai-sdk/openai';

const openai = createOpenAI({
  // custom settings, e.g.
  headers: {
    'header-name': 'header-value',
  },
});
```

你可以使用以下可选设置来自定义 OpenAI 提供商实例：

- **baseURL** _string_

  为 API 调用使用不同的 URL 前缀，例如使用代理服务器。
  它默认为 `OPENAI_BASE_URL` 环境变量，然后是
  `https://api.openai.com/v1`。
  默认的 OpenAI 模型工厂（`openai('model-id')`）使用 Responses
  API。如果你的自定义 base URL 仅支持 Chat Completions API，请改用
  `openai.chat('model-id')` 创建 chat 模型，或使用
  [OpenAI 兼容提供商](/providers/openai-compatible-providers)。

- **apiKey** _string_

  通过 `Authorization` 请求头发送的 API 密钥。
  它默认为 `OPENAI_API_KEY` 环境变量。

- **name** _string_

  提供商名称。你可以在使用 OpenAI 兼容提供商时设置它，
  以更改模型提供商属性。默认为 `openai`。

- **organization** _string_

  OpenAI 组织。

- **project** _string_

  OpenAI 项目。

- **headers** _Record&lt;string,string&gt;_

  要包含在请求中的自定义请求头。

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。
  默认为全局 `fetch` 函数。
  你可以将其用作中间件来拦截请求，
  或为测试等场景提供自定义 fetch 实现。

## 语言模型

OpenAI 提供商实例是一个函数，你可以调用它来创建语言模型：

```ts
const model = openai('gpt-6-astra');
```

它会根据模型 id 自动选择正确的 API。
你也可以在第二个参数中传递其他设置：

```ts
const model = openai('gpt-6-astra', {
  // additional settings
});
```

可用的选项取决于为模型自动选择的 API（见下文）。
如果你想显式选择特定的模型 API，可以使用 `.responses`、`.chat` 或 `.completion`。

<Note>
  自 AI SDK 5 起，默认调用 OpenAI responses API（除非你
  指定例如 'openai.chat'）
</Note>

### 示例

你可以使用 OpenAI 语言模型通过 `generateText` 函数生成文本：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text } = await generateText({
  model: openai('gpt-6-astra'),
  prompt: 'Write a vegetarian lasagna recipe for 4 people.',
});
```

OpenAI 语言模型也可用于 `streamText` 函数，
并支持使用 [`Output`](/docs/reference/ai-sdk-core/output) 生成结构化数据
（参见 [AI SDK Core](/docs/ai-sdk-core)）。

### Responses 模型

你可以使用 `openai(modelId)` 或 `openai.responses(modelId)` 工厂方法使用 OpenAI responses API。它是 OpenAI 提供商默认使用的 API（自 AI SDK 5 起）。

```ts
const model = openai('gpt-6-astra');
```

可以使用 OpenAI 提供商选项进行进一步配置。
你可以使用 `OpenAILanguageModelResponsesOptions` 类型验证提供商选项。

```ts
import { openai, OpenAILanguageModelResponsesOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-astra'), // or openai.responses('gpt-6-astra')
  providerOptions: {
    openai: {
      parallelToolCalls: false,
      store: false,
      user: 'user_123',
      // ...
    } satisfies OpenAILanguageModelResponsesOptions,
  },
  // ...
});
```

以下提供商选项可用：

- **parallelToolCalls** _boolean_
  是否使用并行工具调用。默认为 `true`。

- **store** _boolean_

  是否存储生成结果。默认为 `true`。

- **passThroughUnsupportedFiles** _boolean_

  是否将非图像文件类型作为通用输入文件传递。默认为 `false`，这会将内联文件输入限制为图像和 PDF。当目标 OpenAI Responses 模型支持其他文件媒体类型时，请启用此选项。

- **maxToolCalls** _integer_
  一次响应中可以处理的内置工具调用总数上限。
  此上限适用于所有内置工具调用，而非单个工具。
  模型进一步尝试调用工具将被忽略。

- **metadata** _Record&lt;string, string&gt;_
  随生成结果存储的附加元数据。

- **conversation** _string_
  要继续的 OpenAI Conversation 的 ID。
  你必须先通过 [OpenAI API](https://platform.openai.com/docs/api-reference/conversations/create) 创建一个对话。
  不能与 `previousResponseId` 一起使用。
  默认为 `undefined`。

- **previousResponseId** _string_
  上一个响应的 ID。你可以使用它来继续对话。默认为 `undefined`。

- **instructions** _string_
  模型的指令。
  当使用 `previousResponseId` 选项继续对话时，它们可用于更改系统或开发者消息。
  默认为 `undefined`。

- **logprobs** _boolean | number_
  返回 token 的对数概率。包含 logprobs 会增加响应大小并可能减慢响应时间。但是，它有助于更好地理解模型的行为。设置为 `true` 会返回所生成 token 的对数概率。设置为数字（1-20）会返回所生成的前 n 个 token 的对数概率。

- **user** _string_
  代表最终用户的唯一标识符，可帮助 OpenAI 监控和检测滥用行为。默认为 `undefined`。

- **reasoningEffort** _'none' | 'minimal' | 'low' | 'medium' | 'high' | 'xhigh' | 'max'_
  推理模型的推理强度。默认为 `medium`。如果你使用 `providerOptions` 设置 `reasoningEffort` 选项，此模型设置将被忽略。

<Note>
  支持的推理强度因模型而异。GPT-5.6 和 GPT-6 支持 `'none'`、
  `'low'`、`'medium'`、`'high'`、`'xhigh'` 和 `'max'`。GPT-6 Astra 不
  支持 `'none'`。
</Note>

<Note type="warning">
  GPT-6 及更高版本的模型不支持 `temperature`、`topP`、`logprobs` 或
  旧版 `promptCacheRetention` 选项。提供商会移除这些设置
  并返回警告。GPT-6 工具调用请使用 Responses API。
</Note>

- **reasoningEffortUpdate** _'low' | 'medium' | 'high' | 'xhigh' | 'max'_
  从当前响应开始为 GPT-6 及更高版本的模型更新推理强度，
  而不更改请求级别的强度。将此与
  `previousResponseId` 一起使用，以保留原始提示词前缀用于缓存。
  配置更新需要标准、单智能体模式，并且不能
  与自动压缩或自动截断组合使用。

- **reasoningMode** _'standard' | 'pro'_
  控制 GPT-5.6 在返回最终答案之前执行多少模型工作。`'standard'` 是默认值。对于质量比延迟和 token 用量更重要的困难任务，请使用 `'pro'`。

- **reasoningContext** _'auto' | 'current_turn' | 'all_turns'_
  控制 GPT-5.6 可以复用哪些可用的推理项。`'auto'` 使用模型默认值，`'current_turn'` 排除较早轮次的推理，`'all_turns'` 使兼容的较早推理可用。有效上下文以 `providerMetadata.openai.reasoningContext` 返回。

- **reasoningSummary** _'auto' | 'detailed'_
  控制模型是否返回其推理过程。设置为 `'auto'` 获取精简摘要，设置为 `'detailed'` 获取更全面的推理。默认为 `undefined`（无推理摘要）。启用后，推理摘要会在流中以类型为 `'reasoning'` 的事件出现，并在非流式响应中出现在 `reasoning` 字段内。

- **strictJsonSchema** _boolean_
  是否使用严格 JSON schema 验证。默认为 `true`。

<Note type="warning">
  OpenAI 结构化输出有几个
  [限制](https://openai.com/index/introducing-structured-outputs-in-the-api)，
  特别是关于[支持的
  schema](https://platform.openai.com/docs/guides/structured-outputs/supported-schemas)，
  因此需要选择启用。例如，不支持可选的 schema 属性。你需要将 Zod 的 `.nullish()` 和 `.optional()` 改为
  `.nullable()`。
</Note>

- **serviceTier** _'auto' | 'flex' | 'priority' | 'fast' | 'ultrafast' | 'default'_
  请求的服务层级。设置为 'flex' 可获得便宜 50% 的处理，
  代价是延迟增加（适用于 o3、o4-mini 和 gpt-5 模型）。
  设置为 'priority' 可通过 Enterprise 访问获得更快的处理（适用于 gpt-4、gpt-5、gpt-5-mini、o3、o4-mini；不支持 gpt-5-nano）。
  'fast' 是 OpenAI 对 'priority' 层级的新名称；两者可互换，来自
  gpt-5.6 及更早版本的响应对于两者都报告 `serviceTier: 'priority'`。
  设置为 'ultrafast' 可获得访问控制的 Ultrafast 处理（仅适用于 gpt-5.6-sol）。

  默认为 'auto'。

- **textVerbosity** _'low' | 'medium' | 'high'_
  控制模型响应的详细程度。较低的值会产生更简洁的响应，
  而较高的值会产生更详细的响应。默认为 `'medium'`。

- **include** _Array&lt;string&gt;_
  指定要包含在响应中的附加内容。支持的值：
  `['file_search_call.results']` 用于在响应中包含文件搜索结果。
  `['message.output_text.logprobs']` 用于 logprobs。
  默认为 `undefined`。

- **truncation** _string_
  用于模型响应的截断策略。
  - Auto：如果对此 Response 的输入超过模型的上下文窗口大小，模型将通过从对话开头丢弃项目来截断响应以适应上下文窗口。
  - disabled（默认）：如果输入大小将超过模型的上下文窗口大小，请求将失败并返回 400 错误。

- **promptCacheKey** _string_
  用于手动提示词缓存控制的缓存键。OpenAI 使用它来缓存相似请求的响应，以优化你的缓存命中率。

- **promptCacheOptions** _object_
  为 GPT-5.6 及更高版本的模型配置提示词缓存。`mode` 可以是 `'implicit'` 或 `'explicit'`，`ttl` 目前仅支持 `'30m'`。在显式模式下，只有标记了提示词缓存断点的内容块才会被缓存。

- **promptCacheRetention** _'in_memory' | '24h'_
  GPT-5.6 之前模型的旧版保留策略。设置为 `'24h'` 可在支持的模型上启用扩展提示词缓存。对于 GPT-5.6 及更高版本的模型，请改用 `promptCacheOptions.ttl`。

- **safetyIdentifier** _string_
  用于帮助检测可能违反 OpenAI 使用政策的应用程序用户的稳定标识符。这些 ID 应该是唯一标识每个用户的字符串。

- **systemMessageMode** _'system' | 'developer' | 'remove'_
  控制发出请求时系统消息的角色。默认情况下（省略时），对于支持推理的模型，`system` 消息会自动转换为 `developer` 消息。将 `systemMessageMode` 设置为 `system` 会将系统消息作为系统级指令传递；`developer` 将其作为开发者消息传递；`remove` 会从请求中省略系统消息。

- **forceReasoning** _boolean_
  强制将此模型视为推理模型。这对于“隐身”推理模型（例如通过自定义 baseURL）很有用，因为 SDK 的允许列表无法识别其模型 ID。启用后，SDK 会应用推理模型参数兼容规则，并将 `systemMessageMode` 默认为 `developer`，除非被覆盖。

- **contextManagement** _Array&lt;object&gt;_
  启用服务器端上下文管理（压缩）。配置后，当 token 用量超过指定阈值时，服务器会自动压缩对话上下文。数组中的每个对象应包含：
  - `type`：`'compaction'`
  - `compactThreshold`：_number_ — 触发压缩的 token 数量

- **compactionTrigger** _boolean_
  请求显式服务器端压缩。当为 `true` 时，提供商会向 Responses 输入追加一个终止项 `{ type: 'compaction_trigger' }`。支持情况取决于所配置的 Responses 兼容端点和模型。

OpenAI responses 提供商还会返回提供商特定的元数据：

对于 Responses 模型，你可以使用 `OpenaiResponsesProviderMetadata` 为此元数据指定类型：

```ts
import { openai, type OpenaiResponsesProviderMetadata } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-astra'),
});

const providerMetadata = result.providerMetadata as
  | OpenaiResponsesProviderMetadata
  | undefined;

const { responseId, logprobs, serviceTier, reasoningContext } =
  providerMetadata?.openai ?? {};

// responseId can be used to continue a conversation (previousResponseId).
console.log(responseId);
```

可能会返回以下 OpenAI 特定的元数据：

- **responseId** _string | null | undefined_
  响应的 ID。可用于继续对话。
- **logprobs** _（可选）_
  输出 token 的对数概率（启用时）。
- **serviceTier** _（可选）_
  API 返回的服务层级信息。
- **reasoningContext** _（可选）_
  GPT-5.6 返回的有效持久化推理上下文（`'current_turn'` 或 `'all_turns'`）。

#### 在对话中途更改推理强度

GPT-6 及更高版本的模型可以在响应之间更改推理强度，而无需
更改请求级别的 `reasoning` 设置。提供商会将
`reasoningEffortUpdate` 作为 OpenAI `configuration_update` 输入项发送，
位于下一条用户消息之前。保持请求级别的强度不变可保留
原始提示词前缀用于提示词缓存。

```ts highlight="8,26,32"
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
  type OpenaiResponsesProviderMetadata,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const first = await generateText({
  model: openai.responses('gpt-6-astra'),
  reasoning: 'low',
  prompt: 'Draft a database migration plan.',
});

const metadata = first.finalStep.providerMetadata as
  | OpenaiResponsesProviderMetadata
  | undefined;
const previousResponseId = metadata?.openai.responseId;

if (!previousResponseId) {
  throw new Error('OpenAI did not return a response ID.');
}

const second = await generateText({
  model: openai.responses('gpt-6-astra'),
  reasoning: 'low',
  prompt: 'Analyze the failure modes and propose rollback steps.',
  providerOptions: {
    openai: {
      previousResponseId,
      reasoningEffortUpdate: 'high',
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

响应元数据继续报告请求级别的推理强度，
而不是 `reasoningEffortUpdate` 选择的有效强度。配置
更新不支持与 `reasoningMode: 'pro'`、
`contextManagement` 或 `truncation: 'auto'` 一起使用。使用
`compactionTrigger` 的显式压缩仍然受支持；当强度需要再次更改时，在
压缩后发送新的 `reasoningEffortUpdate`。

#### 推理输出

对于像 `gpt-6-astra` 这样的推理模型，你可以启用推理摘要来查看模型的思考过程。不同的模型支持不同的摘要器——例如，`o4-mini` 支持详细摘要。设置 `reasoningSummary: "auto"` 可自动接收可用的最丰富级别。当 `reasoningEffort` 设置为 `'none'` 以外的值时，OpenAI Responses 提供商会将 `reasoningSummary` 默认为 `'detailed'`；设置 `reasoningSummary: null` 可省略推理摘要。

```ts highlight="10-14,17-23"
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { streamText } from 'ai';

const result = streamText({
  model: openai('gpt-6-astra'),
  prompt: 'Tell me about the Mission burrito debate in San Francisco.',
  providerOptions: {
    openai: {
      reasoningSummary: 'detailed', // 'auto' for condensed or 'detailed' for comprehensive
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});

for await (const part of result.stream) {
  if (part.type === 'reasoning') {
    console.log(`Reasoning: ${part.textDelta}`);
  } else if (part.type === 'text-delta') {
    process.stdout.write(part.textDelta);
  }
}
```

对于使用 `generateText` 的非流式调用，推理摘要可在响应的 `reasoning` 字段中获取：

```ts highlight="8-9,13"
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-astra'),
  prompt: 'Tell me about the Mission burrito debate in San Francisco.',
  providerOptions: {
    openai: {
      reasoningSummary: 'auto',
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
console.log('Reasoning:', result.reasoning);
```

在 [OpenAI 文档](https://platform.openai.com/docs/guides/reasoning?api-mode=responses#reasoning-summaries)中了解有关推理摘要的更多信息。

#### WebSocket 传输

OpenAI 的 [WebSocket API](https://developers.openai.com/api/docs/guides/websocket-mode) 保持持久连接打开，这可以显著
减少具有许多工具调用的智能体工作流中的首字节时间（TTFB）。
在初始连接之后，后续请求完全跳过 TCP/TLS/HTTP 协商。

[`ai-sdk-openai-websocket-fetch`](https://www.npmjs.com/package/ai-sdk-openai-websocket-fetch)
包提供了一个可直接替换的 `fetch`，它通过持久 WebSocket 连接路由流式请求。

<InstallPackages packages="ai-sdk-openai-websocket-fetch" />

通过 `fetch` 选项将 WebSocket fetch 传递给 `createOpenAI`：

```ts highlight="2,6-7,15"
import { createOpenAI } from '@ai-sdk/openai';
import { createWebSocketFetch } from 'ai-sdk-openai-websocket-fetch';
import { streamText } from 'ai';

// Create a WebSocket-backed fetch instance
const wsFetch = createWebSocketFetch();
const openai = createOpenAI({ fetch: wsFetch });

const result = streamText({
  model: openai('gpt-6-luna'),
  prompt: 'Hello!',
  tools: {
    // ...
  },
  onFinish: () => wsFetch.close(), // close the WebSocket when done
});
```

第一个请求会较慢，因为它必须建立 WebSocket 连接
（DNS + TCP + TLS + WebSocket 升级）。之后，多步工具调用循环中的
后续步骤会复用打开的连接，从而降低每一步的 TTFB。

<Note>
  WebSocket 传输仅通过 WebSocket 将流式请求路由到 OpenAI Responses
  API（`POST /responses` 且 `stream: true`）。所有其他
  请求（非流式、嵌入等）会回退到标准
  `fetch` 实现。
</Note>

你可以在[演示应用](https://github.com/vercel-labs/ai-sdk-openai-websocket)中查看 HTTP 与 WebSocket 流式性能的实时并排比较。

#### 详细程度控制

你可以使用 `textVerbosity` 参数控制模型响应的长度和详细程度：

```ts
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-luna'),
  prompt: 'Write a poem about a boy and his first pet dog.',
  providerOptions: {
    openai: {
      textVerbosity: 'low', // 'low' for concise, 'medium' (default), or 'high' for verbose
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

`textVerbosity` 参数在不更改底层提示词的情况下调整输出长度：

- `'low'`：生成简洁、最小的响应
- `'medium'`：平衡的细节（默认）
- `'high'`：包含全面细节的详细响应

#### 命名空间函数调用

OpenAI 支持将相关函数工具分组到
[命名空间](https://developers.openai.com/api/docs/guides/function-calling#defining-namespaces)中。
当 Responses API 返回带有 `namespace` 的 `function_call` 时，OpenAI 提供商
会在生成的 `tool-call` 部分上将此值公开为
`providerMetadata.openai.namespace`。

```ts
for (const part of result.content) {
  if (part.type === 'tool-call') {
    console.log(part.providerMetadata?.openai?.namespace);
  }
}
```

使用 `streamText` 时，命名空间可在 `tool-input-end` 事件和
最终的 `tool-call` 事件上获取：

```ts
for await (const part of result.stream) {
  if (part.type === 'tool-input-end' || part.type === 'tool-call') {
    console.log(part.providerMetadata?.openai?.namespace);
  }
}
```

如果你为后续轮次持久化或重建消息，请保留工具调用部分上的 OpenAI 提供商
元数据。SDK 使用 `providerMetadata.openai.namespace` 或
`providerOptions.openai.namespace` 在后续请求中将命名空间往返传回 OpenAI。

#### 异步工具调用

GPT-6 Astra 及更高版本的 Responses 模型支持
[异步工具调用](https://developers.openai.com/api/docs/guides/async-tool-calling)。
异步工具允许模型在发出调用后继续生成独立输出，
而不是等待其结果。你的应用程序仍然执行该
工具，并在后续请求中使用原始工具调用 ID 发送其结果。

使用 `providerOptions.openai.async` 在函数工具上启用异步调用：

```ts
import { openai, type OpenAIToolOptions } from '@ai-sdk/openai';
import { generateText, tool } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: openai.responses('gpt-6-astra'),
  tools: {
    getWeather: tool({
      description: 'Get the weather for a city.',
      inputSchema: z.object({ city: z.string() }),
      outputSchema: z.object({
        city: z.string(),
        temperatureC: z.number(),
      }),
      providerOptions: {
        openai: { async: true } satisfies OpenAIToolOptions,
      },
    }),
  },
  prompt:
    'Start the weather lookup for Paris, then list three general packing essentials without waiting.',
});
```

生成的工具调用会将提供商标记公开为
`providerMetadata.openai.async`。使用 `providerMetadata.openai.responseId` 作为
下一个请求的 `previousResponseId`，并在工具消息中使用
原始 `toolCallId` 提交结果。

使用 `streamText` 时，OpenAI 可以在完成的
`tool-call` 部分之后继续流式传输文本。使用工具的 `onInputAvailable` 回调在该部分到达时
立即开始工作。如果 `execute` 返回同一个已在运行的 promise，工具
执行会与模型流的其余部分重叠。当任务
应比当前生成存活更久并在后续请求中提交其结果时，省略 `execute`。

异步调用适用于直接调用的函数和自定义工具。它不
适用于托管工具，也不应与程序化工具调用组合使用。

#### 程序化工具调用

OpenAI 程序化工具调用允许支持的 Responses 模型生成并运行
托管 JavaScript，以协调客户端函数工具。使用 `openai.tools.programmaticToolCalling()` 添加托管工具，
然后通过 `allowedCallers` 让每个符合条件的函数选择加入
程序化调用。

```ts
import { openai, type OpenAIToolOptions } from '@ai-sdk/openai';
import { generateText, isStepCount, tool } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: openai('gpt-6-astra'),
  stopWhen: isStepCount(10),
  prompt: 'Compare inventory with demand for sku_123.',
  tools: {
    program: openai.tools.programmaticToolCalling(),
    getInventory: tool({
      description: 'Get available inventory for a SKU.',
      inputSchema: z.object({ sku: z.string() }),
      execute: async ({ sku }) => ({ sku, availableUnits: 42 }),
      providerOptions: {
        openai: {
          allowedCallers: ['programmatic'],
          outputSchema: {
            type: 'object',
            properties: {
              sku: { type: 'string' },
              availableUnits: { type: 'number' },
            },
            required: ['sku', 'availableUnits'],
            additionalProperties: false,
          },
        } satisfies OpenAIToolOptions,
      },
    }),
  },
});
```

`allowedCallers` 支持：

- `['direct']`（或省略）：仅直接模型工具调用
- `['programmatic']`：仅来自托管 JavaScript 的调用
- `['direct', 'programmatic']`：两种调用模式

使用 `outputSchema` 描述函数返回的 JSON 值。此 schema
会作为 `output_schema` 发送给 OpenAI，以便生成的 JavaScript 可以安全地使用
返回的字段。它不会替代工具的 AI SDK 输出验证或执行
逻辑。

提供商会跨 `generateText` 和 `streamText` 工具循环保留程序代码、重放指纹、程序输出和嵌套
函数调用者元数据，
包括使用 `store: false` 的无状态请求。程序化调用
目前支持 AI SDK 函数工具；其他 OpenAI 工具类型通过此集成仍仅支持直接调用。

将生成的程序和工具参数视为不受信任。在每个工具内部强制执行授权和
审批，除非操作是幂等的，否则避免对具有副作用的工具进行程序化访问，并设置明确的步骤限制。

#### Web 搜索工具

OpenAI responses API 通过 `openai.tools.webSearch` 工具支持 Web 搜索。

```ts
const result = await generateText({
  model: openai('gpt-6-astra'),
  prompt: 'What happened in San Francisco last week?',
  tools: {
    web_search: openai.tools.webSearch({
      // optional configuration:
      externalWebAccess: true,
      searchContextSize: 'high',
      userLocation: {
        type: 'approximate',
        city: 'San Francisco',
        region: 'California',
      },
      filters: {
        allowedDomains: ['sfchronicle.com', 'sfgate.com'],
        blockedDomains: ['example.com'],
      },
    }),
  },
  // Force web search tool (optional):
  toolChoice: { type: 'tool', toolName: 'web_search' },
});

// URL sources directly from `results`
const sources = result.sources;

// Or access sources from tool results
for (const toolResult of result.toolResults) {
  if (toolResult.toolName === 'web_search') {
    console.log('Query:', toolResult.output.action.query);
    console.log('Sources:', toolResult.output.sources);
    // `sources` is an array of object: { type: 'url', url: string }
  }
}
```

Web 搜索工具支持以下配置选项：

- **externalWebAccess** _boolean_ - 是否使用外部 Web 访问来获取实时内容。默认为 `true`。
- **searchContextSize** _'low' | 'medium' | 'high'_ - 控制用于搜索的上下文量。较高的值提供更全面的结果，但可能具有更高的延迟和成本。
- **userLocation** - 可选的位置信息，用于提供地理相关的结果。包括 `type`（始终为 `'approximate'`）、`country`、`city`、`region` 和 `timezone`。
- **filters** - 可选的过滤器配置，用于限制搜索结果。
  - **allowedDomains** _string[]_ - 搜索最多允许 100 个域。
  - **blockedDomains** _string[]_ - 搜索最多阻止 100 个域。

从域过滤器中省略 HTTP 或 HTTPS 前缀。所配置域的子域会自动包含或排除。

有关配置选项的详细信息，请参阅 [OpenAI Web 搜索工具文档](https://platform.openai.com/docs/guides/tools-web-search?api-mode=responses)。

#### 文件搜索工具

OpenAI responses API 通过 `openai.tools.fileSearch` 工具支持文件搜索。

你可以通过将 `toolChoice` 参数设置为 `{ type: 'tool', toolName: 'file_search' }` 来强制使用文件搜索工具。

```ts
const result = await generateText({
  model: openai('gpt-6-astra'),
  prompt: 'What does the document say about user authentication?',
  tools: {
    file_search: openai.tools.fileSearch({
      vectorStoreIds: ['vs_123'],
      // configuration below is optional:
      maxNumResults: 5,
      filters: {
        key: 'author',
        type: 'eq',
        value: 'Jane Smith',
      },
      ranking: {
        ranker: 'auto',
        scoreThreshold: 0.5,
      },
    }),
  },
  providerOptions: {
    openai: {
      // optional: include results
      include: ['file_search_call.results'],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

文件搜索工具支持使用比较过滤器和复合过滤器进行过滤：

**比较过滤器** - 按单个属性过滤：

- `eq` - 等于
- `ne` - 不等于
- `gt` - 大于
- `gte` - 大于或等于
- `lt` - 小于
- `lte` - 小于或等于
- `in` - 值在数组中
- `nin` - 值不在数组中

```ts
// Single comparison filter
filters: { key: 'year', type: 'gte', value: 2023 }

// Filter with array values
filters: { key: 'status', type: 'in', value: ['published', 'reviewed'] }
```

**复合过滤器** - 使用 `and` 或 `or` 组合多个过滤器：

```ts
// Compound filter with AND
filters: {
  type: 'and',
  filters: [
    { key: 'author', type: 'eq', value: 'Jane Smith' },
    { key: 'year', type: 'gte', value: 2023 },
  ],
}

// Compound filter with OR
filters: {
  type: 'or',
  filters: [
    { key: 'department', type: 'eq', value: 'Engineering' },
    { key: 'department', type: 'eq', value: 'Research' },
  ],
}
```

#### 图像生成工具

OpenAI 的 Responses API 支持将多模态图像生成作为提供商定义的工具。
可用性仅限于特定模型（例如 `gpt-5` 变体）。

你可以将图像工具与 `generateText` 或 `streamText` 一起使用：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-astra'),
  prompt:
    'Generate an image of an echidna swimming across the Mozambique channel.',
  tools: {
    image_generation: openai.tools.imageGeneration({ outputFormat: 'webp' }),
  },
});

for (const toolResult of result.staticToolResults) {
  if (toolResult.toolName === 'image_generation') {
    const base64Image = toolResult.output.result;
  }
}
```

```ts
import { openai } from '@ai-sdk/openai';
import { streamText } from 'ai';

const result = streamText({
  model: openai('gpt-6-astra'),
  prompt:
    'Generate an image of an echidna swimming across the Mozambique channel.',
  tools: {
    image_generation: openai.tools.imageGeneration({
      outputFormat: 'webp',
      quality: 'low',
    }),
  },
});

for await (const part of result.stream) {
  if (part.type == 'tool-result' && !part.dynamic) {
    const base64Image = part.output.result;
  }
}
```

<Note>
  当你设置 `store: false` 时，之前生成的图像将无法
  被模型访问。我们建议使用图像生成工具时不要
  设置 `store: false`。
</Note>

要使用 `xhigh` 或 `max` 质量，请选择 `gpt-image-2.5-flare` 或
`gpt-image-2.5-sunburst` 作为图像生成工具的模型：

```ts
openai.tools.imageGeneration({
  model: 'gpt-image-2.5-flare',
  quality: 'xhigh',
});
```

有关模型可用性、图像质量控制、支持的尺寸和工具特定参数的完整详细信息，
请参阅 OpenAI 文档：

- 图像生成概述和模型：[OpenAI Image Generation](https://platform.openai.com/docs/guides/image-generation)
- 图像生成工具参数（background、size、quality、format 等）：[Image Generation Tool Options](https://platform.openai.com/docs/guides/tools-image-generation#tool-options)

#### MCP 工具

OpenAI responses API 通过 `openai.tools.mcp` 工具支持连接到 [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) 服务器。这允许模型调用远程 MCP 服务器或服务连接器公开的工具。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-astra'),
  prompt: 'Search the web for the latest news about AI developments',
  tools: {
    mcp: openai.tools.mcp({
      serverLabel: 'web-search',
      serverUrl: 'https://mcp.exa.ai/mcp',
      serverDescription: 'A web-search API for AI agents',
    }),
  },
});
```

MCP 工具可以配置为：

- **serverLabel** _string_（必需）

  用于标识 MCP 服务器的标签。此标签在工具调用中用于区分多个 MCP 服务器。

- **serverUrl** _string_（如果未提供 `connectorId` 则必需）

  MCP 服务器的 URL。必须提供 `serverUrl` 或 `connectorId` 之一。

- **connectorId** _string_（如果未提供 `serverUrl` 则必需）

  服务连接器的标识符。必须提供 `serverUrl` 或 `connectorId` 之一。

- **serverDescription** _string_（可选）

  MCP 服务器的可选描述，帮助模型理解其用途。

- **allowedTools** _string[] | object_（可选）

  控制 MCP 服务器中哪些工具可用。可以是：
  - 工具名称数组：`['tool1', 'tool2']`
  - 带有过滤器的对象：
    ```ts
    {
      readOnly: true, // Only allow read-only tools
      toolNames: ['tool1', 'tool2'] // Specific tool names
    }
    ```

- **authorization** _string_（可选）

  用于向 MCP 服务器或连接器进行身份验证的 OAuth 访问令牌。

- **headers** _Record&lt;string, string&gt;_（可选）

  要包含在向 MCP 服务器发出的请求中的可选 HTTP 请求头。

- **requireApproval** _'always' | 'never' | object_（可选）

  控制哪些 MCP 工具调用在执行前需要用户批准。可以是：
  - `'always'`：所有 MCP 工具调用都需要批准
  - `'never'`：没有 MCP 工具调用需要批准（默认）
  - 带有过滤器的对象：
    ```ts
    {
      never: {
        toolNames: ['safe_tool', 'another_safe_tool']; // Skip approval for these tools
      }
    }
    ```

  当需要批准时，模型会返回一个 `tool-approval-request` 内容部分，你可以用它来提示用户批准。有关实现批准工作流的更多详细信息，请参阅 [Human in the Loop](/cookbook/next/human-in-the-loop)。

<Note>
  当未设置 `requireApproval` 时，工具调用默认会被批准。请务必
  仅连接到受信任的 MCP 服务器，即你信任其共享数据的服务器。
</Note>

<Note>
  OpenAI MCP 工具不同于 [MCP Tools](/docs/ai-sdk-core/mcp-tools) 中记录的
  通用 MCP 客户端方法。OpenAI MCP 工具是
  一个内置的提供商定义工具，允许 OpenAI 模型直接连接到
  MCP 服务器，而通用 MCP 客户端需要你先将 MCP 工具
  转换为 AI SDK 工具。
</Note>

#### 计算机工具

OpenAI Responses API 通过
`openai.tools.computer` 支持 GA 计算机工具。模型返回一组有序的浏览器或
桌面操作供你的应用程序执行，你的应用程序返回
更新后的截图。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, isStepCount } from 'ai';
import { captureScreenshot, executeComputerAction } from '@/utils/computer-use';

const result = await generateText({
  model: openai.responses('gpt-6-astra'),
  tools: {
    computer: openai.tools.computer({
      needsApproval: ({ pendingSafetyChecks }) =>
        pendingSafetyChecks.length > 0,

      execute: async ({ actions, pendingSafetyChecks }) => {
        for (const action of actions) {
          await executeComputerAction(action);
        }

        return {
          output: {
            type: 'computer_screenshot',
            imageUrl: `data:image/png;base64,${await captureScreenshot()}`,
            detail: 'original',
          },
          acknowledgedSafetyChecks: pendingSafetyChecks,
        };
      },
    }),
  },
  prompt: 'Open the settings page and enable dark mode.',
  stopWhen: isStepCount(10),
});
```

execute 回调接收：

- **actions** - 一个有序数组，包含 `click`、`double_click`、`drag`、
  `keypress`、`move`、`screenshot`、`scroll`、`type` 和 `wait` 操作。
  在捕获下一张截图之前按顺序执行每个操作。
- **pendingSafetyChecks** - OpenAI 返回的安全检查。在继续之前查看这些
  检查，并将接受的检查包含在
  `acknowledgedSafetyChecks` 中。
- **status** - 计算机调用状态。

操作联合类型也导出为 `OpenAIComputerAction`。操作特定的
字段为：

| 操作           | 字段                                                 |
| -------------- | ---------------------------------------------------- |
| `click`        | `button`、`x`、`y`、可选的 `keys`                    |
| `double_click` | `x`、`y`、可选的 `keys`                              |
| `drag`         | 包含 `{ x, y }` 点的 `path`、可选的 `keys`            |
| `keypress`     | `keys`                                               |
| `move`         | `x`、`y`、可选的 `keys`                              |
| `screenshot`   | 无附加字段                                           |
| `scroll`       | `x`、`y`、`scrollX`、`scrollY`、可选的 `keys`        |
| `type`         | `text`                                               |
| `wait`         | 无附加字段                                           |

安全检查使用导出的 `OpenAIComputerSafetyCheck` 类型。

返回 `computer_screenshot`，可以是：

- **imageUrl** - 完全限定的 URL 或图像数据 URL。
- **fileId** - 已上传截图文件的 ID。

`detail` 可以是 `auto`、`low`、`high` 或 `original`。`original` 保留
捕获的分辨率，当准确的坐标很重要时推荐使用。

在使用 `store`、`previousResponseId` 或
OpenAI 对话时，计算机调用和 `computer_call_output` 截图结果会在多步生成中
传递。你也可以设置 `store: false`；提供商会
将完整的调用和截图结果序列化到每个后续请求中。

<Note type="warning">
  在隔离的浏览器或 VM 中运行计算机使用。限制可访问的域、
  账户、凭据、环境变量和文件系统访问。将
  屏幕上的内容视为不受信任的提示词注入输入，在重要操作之前立即要求确认，并避免在截图中
  暴露敏感信息。
</Note>

#### Shell 工具

OpenAI Responses API 通过 `openai.tools.shell` 工具支持 shell 工具。
shell 工具允许运行 bash 命令并与命令行交互。
模型提出 shell 命令；你的集成执行它们并返回输出。

<Note type="warning">
  运行任意 shell 命令可能很危险。在将命令转发到系统 shell 之前，始终对执行进行沙箱化或
  添加严格的允许/拒绝列表。
</Note>

shell 工具支持三种环境模式，用于控制命令的执行位置：

##### 本地执行（默认）

当未指定 `environment`（或使用 `type: 'local'`）时，命令通过你的 `execute` 回调在本地执行：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-astra'),
  tools: {
    shell: openai.tools.shell({
      execute: async ({ action }) => {
        // ... your implementation, e.g. sandbox access ...
        return { output: results };
      },
    }),
  },
  prompt: 'List the files in the current directory and show disk usage.',
});
```

##### 托管容器（自动）

将 `environment.type` 设置为 `'containerAuto'`，以在 OpenAI 托管的容器中运行命令。不需要 `execute` 回调——OpenAI 在服务器端处理执行：

```ts
const result = await generateText({
  model: openai('gpt-6-astra'),
  tools: {
    shell: openai.tools.shell({
      environment: {
        type: 'containerAuto',
        // optional configuration:
        memoryLimit: '4g',
        fileIds: ['file-abc123'],
        networkPolicy: {
          type: 'allowlist',
          allowedDomains: ['example.com'],
        },
      },
    }),
  },
  prompt: 'Install numpy and compute the eigenvalues of a 3x3 matrix.',
});
```

`containerAuto` 环境支持：

- **fileIds** _string[]_ - 要在容器中提供的文件 ID
- **memoryLimit** _'1g' | '4g' | '16g' | '64g'_ - 容器的内存限制
- **networkPolicy** - 网络访问策略：
  - `{ type: 'disabled' }` — 无网络访问
  - `{ type: 'allowlist', allowedDomains: string[], domainSecrets?: Array<{ domain, name, value }> }` — 允许特定域并可选择提供密钥

##### 现有容器引用

将 `environment.type` 设置为 `'containerReference'`，以按 ID 使用现有容器：

```ts
const result = await generateText({
  model: openai('gpt-6-astra'),
  tools: {
    shell: openai.tools.shell({
      environment: {
        type: 'containerReference',
        containerId: 'cntr_abc123',
      },
    }),
  },
  prompt: 'Check the status of running processes.',
});
```

##### Execute 回调

对于本地执行（默认或 `type: 'local'`），你的 execute 函数必须返回一个输出数组，其中包含每个命令的结果：

- **stdout** _string_ - 命令的标准输出
- **stderr** _string_ - 命令的标准错误
- **outcome** - `{ type: 'timeout' }` 或 `{ type: 'exit', exitCode: number }`

##### 技能

[技能](https://platform.openai.com/docs/guides/tools-skills)是带有 `SKILL.md` 清单的版本化文件包，可扩展 shell 工具的能力。它们可以附加到 `containerAuto` 和 `local` 环境。

**容器技能**支持两种格式——按引用（用于上传到 OpenAI 的技能）或内联（作为 base64 编码的 zip）：

```ts
const result = await generateText({
  model: openai('gpt-6-astra'),
  tools: {
    shell: openai.tools.shell({
      environment: {
        type: 'containerAuto',
        skills: [
          // By reference:
          { type: 'skillReference', skillId: 'skill_abc123' },
          // Or inline:
          {
            type: 'inline',
            name: 'my-skill',
            description: 'What this skill does',
            source: {
              type: 'base64',
              mediaType: 'application/zip',
              data: readFileSync('./my-skill.zip').toString('base64'),
            },
          },
        ],
      },
    }),
  },
  prompt: 'Use the skill to solve this problem.',
});
```

**本地技能**指向磁盘上包含 `SKILL.md` 文件的目录：

```ts
const result = await generateText({
  model: openai('gpt-6-astra'),
  tools: {
    shell: openai.tools.shell({
      execute: async ({ action }) => {
        // ... your local execution implementation ...
        return { output: results };
      },
      environment: {
        type: 'local',
        skills: [
          {
            name: 'my-skill',
            description: 'What this skill does',
            path: resolve('path/to/skill-directory'),
          },
        ],
      },
    }),
  },
  prompt: 'Use the skill to solve this problem.',

});
```

有关创建技能的更多详细信息，请参阅 [OpenAI Skills 文档](https://platform.openai.com/docs/guides/tools-skills)。

#### 应用补丁工具

OpenAI Responses API 通过 `openai.tools.applyPatch` 工具支持 GPT-5.1 模型的应用补丁工具。
应用补丁工具允许模型使用结构化 diff 在你的代码库中创建、更新和删除文件。
模型不只是建议编辑，而是发出补丁操作，由你的应用程序应用并报告结果，
从而实现迭代式、多步代码编辑工作流。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, isStepCount } from 'ai';

const result = await generateText({
  model: openai('gpt-6-astra'),
  tools: {
    apply_patch: openai.tools.applyPatch({
      execute: async ({ callId, operation }) => {
        // ... your implementation for applying the diffs.
      },
    }),
  },
  prompt: 'Create a python file that calculates the factorial of a number',
  stopWhen: isStepCount(5),
});
```

你的 execute 函数必须返回：

- **status** _'completed' | 'failed'_ - 补丁是否成功应用
- **output** _string_（可选）- 人类可读的日志文本（例如结果或错误消息）

#### 工具搜索

工具搜索允许模型根据需要动态搜索工具并将其加载到上下文中，
而不是预先加载所有工具定义。当你有很多工具时，这可以减少 token 用量、成本和延迟。
在工具的 `providerOptions` 中使用 `deferLoading: true` 标记你希望使其可搜索的工具。

有两种执行模式：

- **服务器执行（托管）：** OpenAI 在请求中声明的延迟工具中搜索，并在同一响应中返回加载的子集。不需要额外的往返。
- **客户端执行：** 模型发出 `tool_search_call`，你的应用程序执行查找，然后你通过 `execute` 回调返回匹配的工具。

##### 服务器执行（托管）工具搜索

当候选工具在请求时已知时，使用托管工具搜索。
添加不带参数的 `openai.tools.toolSearch()`，并使用 `deferLoading: true` 标记你的工具：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, tool, isStepCount } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: openai.responses('gpt-6-astra'),
  prompt: 'What is the weather in San Francisco?',
  stopWhen: isStepCount(10),
  tools: {
    toolSearch: openai.tools.toolSearch(),

    get_weather: tool({
      description: 'Get the current weather at a specific location',
      inputSchema: z.object({
        location: z.string(),
        unit: z.enum(['celsius', 'fahrenheit']),
      }),
      execute: async ({ location, unit }) => ({
        location,
        temperature: unit === 'celsius' ? 18 : 64,
      }),
      providerOptions: {
        openai: { deferLoading: true },
      },
    }),

    search_files: tool({
      description: 'Search through files in the workspace',
      inputSchema: z.object({ query: z.string() }),
      execute: async ({ query }) => ({
        results: [`Found 3 files matching "${query}"`],
      }),
      providerOptions: {
        openai: { deferLoading: true },
      },
    }),
  },
});
```

在托管模式下，模型在内部搜索延迟工具，加载相关工具，然后
继续调用它们——所有这些都在单个响应中完成。`tool_search_call` 和
`tool_search_output` 项会出现在响应中，带有 `execution: 'server'` 和 `call_id: null`。

##### 命名空间

使用 `providerOptions.openai.namespace` 为 OpenAI 分组相关函数工具。
SDK 保持每个工具作为普通 AI SDK 工具可执行，但会将分组的
工具序列化为请求中的 OpenAI `namespace` 条目：

```ts
const crmNamespace = {
  name: 'crm',
  description: 'CRM tools for customer lookup and order management.',
};

const result = await generateText({
  model: openai.responses('gpt-6-astra'),
  prompt: 'List open orders for customer cust_123.',
  tools: {
    toolSearch: openai.tools.toolSearch(),

    get_customer_profile: tool({
      description: 'Fetch a customer profile by customer ID.',
      inputSchema: z.object({ customer_id: z.string() }),
      execute: async ({ customer_id }) => ({ customer_id }),
      providerOptions: {
        openai: { namespace: crmNamespace },
      },
    }),

    list_open_orders: tool({
      description: 'List open orders for a customer ID.',
      inputSchema: z.object({ customer_id: z.string() }),
      execute: async ({ customer_id }) => ({ customer_id, orders: [] }),
      providerOptions: {
        openai: {
          namespace: crmNamespace,
          deferLoading: true,
        },
      },
    }),
  },
});
```

同一命名空间中的工具必须使用相同的命名空间 `name` 和 `description`。
为了在工具搜索中获得最佳结果，请保持命名空间描述简洁，并将
详细的使用指南放在各个函数工具上。

##### 客户端执行工具搜索

当工具发现取决于运行时状态时（例如，
因租户、项目或外部系统而异的工具），使用客户端执行工具搜索。传递 `execution: 'client'` 以及
`description`、`parameters` schema 和 `execute` 回调：

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, tool, isStepCount } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: openai.responses('gpt-6-astra'),
  prompt: 'What is the weather in San Francisco?',
  stopWhen: isStepCount(10),
  tools: {
    toolSearch: openai.tools.toolSearch({
      execution: 'client',
      description: 'Search for available tools based on what the user needs.',
      parameters: {
        type: 'object',
        properties: {
          goal: {
            type: 'string',
            description: 'What the user is trying to accomplish',
          },
        },
        required: ['goal'],
        additionalProperties: false,
      },
      execute: async ({ arguments: args }) => {
        // Your custom tool discovery logic here.
        // Return the tools that match the search goal.
        return {
          tools: [
            {
              type: 'function',
              name: 'get_weather',
              description: 'Get the current weather at a specific location',
              deferLoading: true,
              parameters: {
                type: 'object',
                properties: {
                  location: { type: 'string' },
                },
                required: ['location'],
                additionalProperties: false,
              },
            },
          ],
        };
      },
    }),

    get_weather: tool({
      description: 'Get the current weather at a specific location',
      inputSchema: z.object({ location: z.string() }),
      execute: async ({ location }) => ({
        location,
        temperature: 64,
        condition: 'Partly cloudy',
      }),
      providerOptions: {
        openai: { deferLoading: true },
      },
    }),
  },
});
```

在客户端模式下，流程跨越两个步骤：

1. **步骤 1：** 模型发出带有 `execution: 'client'` 和非空 `call_id` 的 `tool_search_call`。SDK 使用搜索参数调用你的 `execute` 回调。你的回调返回发现的工具。
2. **步骤 2：** SDK 将 `tool_search_output`（带有匹配的 `call_id`）发送回模型。模型现在可以像普通函数调用一样调用已加载的工具。

有关更多详细信息，请参阅 [OpenAI Tool Search 文档](https://platform.openai.com/docs/guides/tools-tool-search)。

#### 自定义工具

OpenAI Responses API 通过 `openai.tools.customTool` 工具支持
[自定义工具](https://developers.openai.com/api/docs/guides/function-calling/#custom-tools)。
自定义工具返回原始字符串而不是 JSON，可选地受语法约束
（regex 或 Lark 语法）。这使它们对于生成结构化文本（如
SQL 查询、代码片段或任何必须匹配特定模式的输出）非常有用。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText, isStepCount } from 'ai';

const result = await generateText({
  model: openai.responses('gpt-6-sol'),
  tools: {
    write_sql: openai.tools.customTool({
      description: 'Write a SQL SELECT query to answer the user question.',
      format: {
        type: 'grammar',
        syntax: 'regex',
        definition: 'SELECT .+',
      },
      execute: async input => {
        // input is a raw string matching the grammar, e.g. "SELECT * FROM users WHERE age > 25"
        const rows = await db.query(input);
        return JSON.stringify(rows);
      },
    }),
  },
  toolChoice: 'required',
  prompt: 'Write a SQL query to get all users older than 25.',
  stopWhen: isStepCount(3),
});
```

自定义工具也可与 `streamText` 一起使用：

```ts
import { openai } from '@ai-sdk/openai';
import { streamText } from 'ai';

const result = streamText({
  model: openai.responses('gpt-6-sol'),
  tools: {
    write_sql: openai.tools.customTool({
      description: 'Write a SQL SELECT query to answer the user question.',
      format: {
        type: 'grammar',
        syntax: 'regex',
        definition: 'SELECT .+',
      },
    }),
  },
  toolChoice: 'required',
  prompt: 'Write a SQL query to get all users older than 25.',
});

for await (const chunk of result.stream) {
  if (chunk.type === 'tool-call') {
    console.log(`Tool: ${chunk.toolName}`);
    console.log(`Input: ${chunk.input}`);
  }
}
```

自定义工具可以配置为：

- **description** _string_（可选）- 工具功能的描述，帮助模型理解何时使用它。
- **format** _object_（可选）- 输出格式约束。省略以获得不受约束的文本输出。
  - **type** _'grammar' | 'text'_ - 格式类型。使用 `'grammar'` 获得受约束的输出，或使用 `'text'` 获得显式不受约束的文本。
  - **syntax** _'regex' | 'lark'_ -（仅语法）语法语法。使用 `'regex'` 表示正则表达式模式，或使用 `'lark'` 表示 [Lark 解析器语法](https://lark-parser.readthedocs.io/)。
  - **definition** _string_ -（仅语法）语法定义字符串（正则表达式模式或 Lark 语法）。
- **execute** _function_（可选）- 一个异步函数，接收原始字符串输入并返回字符串结果。启用多轮工具调用。

#### 限制可调用工具

`allowedTools` 提供商选项限制你声明的工具中模型允许
调用哪些工具，同时仍将完整的 `tools` 列表发送给 OpenAI。由于工具列表在
各请求之间保持字节级一致，提示词缓存得以保留——这与 `activeTools` 不同，后者会从
请求中移除工具，并在允许列表更改时使缓存失效。

`allowedTools` 仅受 Responses API 支持，并且它会覆盖请求级别的 `toolChoice`。

```ts
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai.responses('gpt-6-astra'),
  tools: {
    weather: weatherTool,
    cityAttractions: cityAttractionsTool,
    search: openai.tools.webSearch(),
  },
  providerOptions: {
    openai: {
      allowedTools: { toolNames: ['weather', 'search'], mode: 'auto' },
    },
  },
  prompt: 'What is the weather in San Francisco?',
});
```

- **toolNames** _string[]_ - 模型可以调用的工具，以你在 `tools` 中声明的名称命名。对于
  提供商定义的工具，你也可以使用规范的 OpenAI 名称（例如 `web_search`）。
- **mode** _'auto' | 'required'_（可选）- `'auto'`（默认）让模型从允许的
  工具中选择一个，或用消息回答；`'required'` 强制它至少调用其中一个。

函数工具和提供商定义的工具都可以加入允许列表，包括 Web 搜索、文件搜索、
图像生成、代码解释器、计算机、应用补丁、shell、程序化工具调用、自定义
工具和 MCP 服务器。

如果某个名称同时匹配你声明的工具和另一个工具的规范 OpenAI 名称，则以你声明的
该名称下的工具为准，并会发出警告报告此歧义。如果多个工具共享相同的
规范名称——例如两个 MCP 服务器——该名称存在歧义，因此会被丢弃并发出警告；
请改为按你声明的方式命名这些工具。

<Note>
  有三类工具无法加入允许列表，因为 OpenAI 的 `allowed_tools`
  只能看到预先加载的工具列表：[工具搜索工具](#tool-search)、
  标记了 `deferLoading` 的工具，以及分组到命名空间中的工具。在
  `allowedTools` 中命名其中之一会将其从允许列表中移除并发出
  警告；如果这样导致没有任何工具，请求将失败并报错，
  而不是静默地发送无限制请求。
</Note>

<Note>
  MCP 服务器作为整体加入允许列表：条目携带服务器标签，
  因此该服务器上的每个工具都可调用。要限制模型可以调用服务器上的哪些工具，
  请使用 MCP 工具自身的 `allowedTools` 参数。
</Note>

#### 文本部分中的类型化 providerMetadata

使用 OpenAI Responses API 时，SDK 会通过 `providerMetadata` 将 OpenAI 特定的元数据附加到输出部分。

此元数据可在客户端用于渲染引用或下载 Code Interpreter 生成的文件等任务。
为了实现此元数据的类型安全处理，AI SDK 导出了专用的 TypeScript 类型。

对于文本部分，当 `part.type === 'text'` 时，`providerMetadata` 以 `OpenaiResponsesTextProviderMetadata` 的形式提供。

此元数据包含以下字段：

- `itemId`
  Responses API 中输出项的 ID。
- `annotations`（可选）
  模型生成的注解对象数组。
  如果不存在注解，此属性本身可能被省略（`undefined`）。

  `annotations` 中的每个元素都是带有必需 `type` 字段的可辨识联合。支持的类型包括例如：
  - `url_citation`
  - `file_citation`
  - `container_file_citation`
  - `file_path`

  这些注解直接对应于 Responses API 定义的注解对象，可用于内联引用渲染或输出分析。
  有关详细信息，请参阅官方 OpenAI 文档：
  [Responses API – output text annotations](https://platform.openai.com/docs/api-reference/responses/object?lang=javascript#responses-object-output-output_message-content-output_text-annotations)。

```ts
import {
  openai,
  type OpenaiResponsesTextProviderMetadata,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-luna'),
  prompt:
    'Create a program that generates five random numbers between 1 and 100 with two decimal places, and show me the execution results. Also save the result to a file.',
  tools: {
    code_interpreter: openai.tools.codeInterpreter(),
    web_search: openai.tools.webSearch(),
    file_search: openai.tools.fileSearch({ vectorStoreIds: ['vs_1234'] }), // requires a configured vector store
  },
});

for (const part of result.content) {
  if (part.type === 'text') {
    const providerMetadata = part.providerMetadata as
      | OpenaiResponsesTextProviderMetadata
      | undefined;
    if (!providerMetadata) continue;
    const { itemId: _itemId, annotations } = providerMetadata.openai;

    if (!annotations) continue;
    for (const annotation of annotations) {
      switch (annotation.type) {
        case 'url_citation':
          // url_citation is returned from web_search and provides:
          // properties: type, url, title, start_index and end_index
          break;
        case 'file_citation':
          // file_citation is returned from file_search and provides:
          // properties: type, file_id, filename and index
          break;
        case 'container_file_citation':
          // container_file_citation is returned from code_interpreter and provides:
          // properties: type, container_id, file_id, filename, start_index and end_index
          break;
        case 'file_path':
          // file_path provides:
          // properties: type, file_id and index
          break;
        default: {
          const _exhaustiveCheck: never = annotation;
          throw new Error(
            `Unhandled annotation: ${JSON.stringify(_exhaustiveCheck)}`,
          );
        }
      }
    }
  }
}
```

<Note>
  为 Code Interpreter 生成的文件实现文件下载时，
  可以使用 `providerMetadata` 中提供的 `container_id` 和 `file_id`
  来检索文件内容。有关详细信息，请参阅 [Retrieve container file
  content](https://platform.openai.com/docs/api-reference/container-files/retrieveContainerFileContent)
  API。
</Note>

#### 推理部分中的类型化 providerMetadata

使用 OpenAI Responses API 时，推理输出部分可以包含提供商元数据。
要以类型安全的方式处理此元数据，请使用 `OpenaiResponsesReasoningProviderMetadata`。

对于推理部分，当 `part.type === 'reasoning'` 时，`providerMetadata` 以 `OpenaiResponsesReasoningProviderMetadata` 的形式提供。

此元数据包含以下字段：

- `itemId`  
  Responses API 中推理项的 ID。
- `reasoningEncryptedContent`（可选）  
  加密的推理内容（仅在通过 `include: ['reasoning.encrypted_content']` 请求时返回）。

```ts
import {
  openai,
  type OpenaiResponsesReasoningProviderMetadata,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-astra'),
  prompt: 'How many "r"s are in the word "strawberry"?',
  providerOptions: {
    openai: {
      store: false,
      include: ['reasoning.encrypted_content'],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});

for (const part of result.content) {
  if (part.type === 'reasoning') {
    const providerMetadata = part.providerMetadata as
      | OpenaiResponsesReasoningProviderMetadata
      | undefined;

    const { itemId, reasoningEncryptedContent } =
      providerMetadata?.openai ?? {};
    console.log(itemId, reasoningEncryptedContent);
  }
}
```

#### 源文档部分中的类型化 providerMetadata

对于源文档部分，当 `part.type === 'source'` 且 `sourceType === 'document'` 时，`providerMetadata` 以 `OpenaiResponsesSourceDocumentProviderMetadata` 的形式提供。

此元数据也是带有必需 `type` 字段的可辨识联合。支持的类型包括：

- `file_citation`
- `container_file_citation`
- `file_path`

每种类型都包含处理所引用资源所需的标识符，例如 `fileId` 和 `containerId`。

```ts
import {
  openai,
  type OpenaiResponsesSourceDocumentProviderMetadata,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai('gpt-6-luna'),
  prompt:
    'Create a program that generates five random numbers between 1 and 100 with two decimal places, and show me the execution results. Also save the result to a file.',
  tools: {
    code_interpreter: openai.tools.codeInterpreter(),
    web_search: openai.tools.webSearch(),
    file_search: openai.tools.fileSearch({ vectorStoreIds: ['vs_1234'] }), // requires a configured vector store
  },
});

for (const part of result.content) {
  if (part.type === 'source') {
    if (part.sourceType === 'document') {
      const providerMetadata = part.providerMetadata as
        | OpenaiResponsesSourceDocumentProviderMetadata
        | undefined;
      if (!providerMetadata) continue;
      const annotation = providerMetadata.openai;
      switch (annotation.type) {
        case 'file_citation':
          // file_citation is returned from file_search and provides:
          // properties: type, fileId and index
          // The filename can be accessed via part.filename.
          break;
        case 'container_file_citation':
          // container_file_citation is returned from code_interpreter and provides:
          // properties: type, containerId and fileId
          // The filename can be accessed via part.filename.
          break;
        case 'file_path':
          // file_path provides:
          // properties: type, fileId and index
          break;
        default: {
          const _exhaustiveCheck: never = annotation;
          throw new Error(
            `Unhandled annotation: ${JSON.stringify(_exhaustiveCheck)}`,
          );
        }
      }
    }
  }
}
```

<Note>
  文本部分中的注解遵循 OpenAI Responses API 规范，
  因此使用 snake_case 属性（例如 `file_id`、`container_id`）。相
  反，源文档部分的 `providerMetadata` 由
  SDK 规范化为 camelCase（例如 `fileId`、`containerId`）。依赖
  原始文本内容的字段（如 `start_index` 和 `end_index`）会被省略，
  直接可在源对象上获取的字段（如 `filename`）也会被省略。
</Note>

#### 压缩

OpenAI Responses API 支持服务器端上下文压缩。启用后，当 token 用量超过配置的阈值时，服务器会自动压缩对话上下文。这对于长时间运行的对话或智能体循环非常有用，你希望在不手动管理上下文的情况下保持在 token 限制内。

服务器返回的压缩项是不透明且加密的——它使用更少的 token 将关键先前状态和推理延续到下一轮。AI SDK 会自动处理这一点：压缩项作为带有特殊 `providerMetadata` 的文本部分返回，当在后续请求中传回时，它们会作为压缩输入项发送。

```ts highlight="7-11"
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai.responses('gpt-6-astra'),
  messages: conversationHistory,
  providerOptions: {
    openai: {
      store: false,
      contextManagement: [{ type: 'compaction', compactThreshold: 50000 }],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

**配置：**

- **type** — 必须为 `'compaction'`
- **compactThreshold** — 触发压缩的 token 数量。当渲染的输入 token 数量超过此阈值时，服务器会在继续推理之前运行压缩过程。

<Note>
  当你在请求上设置 `store: false` 时，服务器端压缩对 ZDR 友好。
</Note>

##### 显式压缩

对于支持显式压缩的 Responses 兼容端点，设置
`compactionTrigger: true`。提供商会将所有转换后的消息
和输入项之后追加所需的
`{ type: 'compaction_trigger' }` 请求控制项。

```ts highlight="9"
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai.responses('gpt-5.3-codex'),
  messages: conversationHistory,
  providerOptions: {
    openai: {
      store: false,
      compactionTrigger: true,
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

这与 `contextManagement` 不同，后者配置自动的、
基于阈值的压缩。当省略或为 `false` 时，`compactionTrigger` 不会
添加输入项。生成的压缩输出使用现有的
`openai.compaction` 自定义部分表示。端点和模型支持可能
有所不同。

##### 在流中检测压缩

使用 `streamText` 时，你可以通过检查 `text-start` 和 `text-end` 事件上的 `providerMetadata` 来检测压缩：

```ts
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { streamText } from 'ai';

const result = streamText({
  model: openai.responses('gpt-6-astra'),
  messages: conversationHistory,
  providerOptions: {
    openai: {
      store: false,
      contextManagement: [{ type: 'compaction', compactThreshold: 50000 }],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});

for await (const part of result.stream) {
  switch (part.type) {
    case 'text-start': {
      const isCompaction = part.providerMetadata?.openai?.type === 'compaction';
      if (isCompaction) {
        // ... your logic
      }
      break;
    }
    case 'text-end': {
      const isCompaction = part.providerMetadata?.openai?.type === 'compaction';
      if (isCompaction) {
        // ... your logic
      }
      break;
    }
    case 'text-delta': {
      process.stdout.write(part.text);
      break;
    }
  }
}
```

##### UI 应用程序中的压缩

使用 `useChat` 或其他 UI Hook 时，压缩项会作为带有 `providerMetadata` 的文本部分出现。你可以在 UI 中以不同方式检测和设置它们的样式：

```tsx
{
  message.parts.map((part, index) => {
    if (part.type === 'text') {
      const isCompaction =
        (part.providerMetadata?.openai as { type?: string } | undefined)
          ?.type === 'compaction';

      if (isCompaction) {
        return (
          <div
            key={index}
            className="bg-yellow-100 border-l-4 border-yellow-500 p-2"
          >
            <span className="font-bold">[Context Compacted]</span>
            <p className="text-sm text-yellow-700">
              The server compressed the conversation context to reduce token
              usage.
            </p>
          </div>
        );
      }
      return <div key={index}>{part.text}</div>;
    }
  });
}
```

元数据包含以下字段：

- **type** — 始终为 `'compaction'`
- **itemId** _string_ — Responses API 中压缩项的 ID
- **encryptedContent** _string_（可选）— 加密的压缩状态。当消息包含在后续请求中时，它会自动发送回 API。

### Chat 模型

你可以使用 `.chat()` 工厂方法创建调用 [OpenAI chat API](https://platform.openai.com/docs/api-reference/chat) 的模型。
第一个参数是模型 id，例如 `gpt-6-astra`。
OpenAI chat 模型支持工具调用，并且一些具有多模态能力。
当自定义 `baseURL` 指向实现了 Chat Completions 但不实现 Responses API 的 OpenAI 兼容端点时，请使用此工厂。

```ts
const model = openai.chat('gpt-6-astra');
```

OpenAI chat 模型还支持一些不属于[标准调用设置](/docs/ai-sdk-core/settings)的模型特定提供商选项。
你可以在 `providerOptions` 参数中传递它们：

```ts
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';

const model = openai.chat('gpt-5');

await generateText({
  model,
  providerOptions: {
    openai: {
      logitBias: {
        // optional likelihood for specific tokens
        '50256': -100,
      },
      user: 'test-user', // optional unique user identifier
    } satisfies OpenAILanguageModelChatOptions,
  },
});
```

以下可选提供商选项可用于 OpenAI chat 模型：

- **logitBias** _Record&lt;number, number&gt;_

  修改指定 token 出现在补全中的可能性。

  接受一个 JSON 对象，将 token（由其在
  GPT 分词器中的 token ID 指定）映射到 -100 到 100 之间的关联偏置值。你可以
  使用此分词器工具将文本转换为 token ID。在数学上，
  偏置会在采样之前添加到模型生成的 logits 中。
  确切效果因模型而异，但 -1 到 1 之间的值应该
  降低或增加被选中的可能性；像 -100 或 100 这样的值
  应该导致相关 token 被禁止或独占选择。

  例如，你可以传递 `{"50256": -100}` 来阻止该 token 被生成。

- **logprobs** _boolean | number_

  返回 token 的对数概率。包含 logprobs 会增加
  响应大小并可能减慢响应时间。但是，它
  有助于更好地理解模型的行为。

  设置为 true 将返回所生成 token 的
  对数概率。

  设置为数字将返回所生成的前 n 个
  token 的对数概率。

- **parallelToolCalls** _boolean_

  是否在工具使用期间启用并行函数调用。默认为 `true`。

- **user** _string_

  代表最终用户的唯一标识符，可帮助 OpenAI
  监控和检测滥用行为。[了解更多](https://platform.openai.com/docs/guides/safety-best-practices/end-user-ids)。

- **reasoningEffort** _'none' | 'minimal' | 'low' | 'medium' | 'high' | 'xhigh' | 'max'_

  推理模型的推理强度。默认为 `medium`。如果你使用
  `providerOptions` 设置 `reasoningEffort` 选项，此
  模型设置将被忽略。

  支持的推理强度因模型而异。GPT-5.6 支持 `'none'`、`'low'`、`'medium'`、`'high'`、`'xhigh'` 和 `'max'`。

- **maxCompletionTokens** _number_

  要生成的最大补全 token 数。对推理模型很有用。

- **store** _boolean_

  是否在 Responses API 中启用持久化。

- **metadata** _Record&lt;string, string&gt;_

  要与请求关联的元数据。

- **prediction** _Record&lt;string, any&gt;_

  预测模式的参数。

- **serviceTier** _'auto' | 'flex' | 'priority' | 'fast' | 'ultrafast' | 'default'_

  请求的服务层级。设置为 'flex' 可获得便宜 50% 的处理，
  代价是延迟增加（适用于 o3、o4-mini 和 gpt-5 模型）。
  设置为 'priority' 可通过 Enterprise 访问获得更快的处理（适用于 gpt-4、gpt-5、gpt-5-mini、o3、o4-mini；不支持 gpt-5-nano）。
  'fast' 是 OpenAI 对 'priority' 层级的新名称；两者可互换，来自
  gpt-5.6 及更早版本的响应对于两者都报告 `serviceTier: 'priority'`。
  设置为 'ultrafast' 可获得访问控制的 Ultrafast 处理（仅适用于 gpt-5.6-sol）。

  默认为 'auto'。

- **strictJsonSchema** _boolean_

  是否使用严格 JSON schema 验证。
  默认为 `true`。

- **textVerbosity** _'low' | 'medium' | 'high'_

  控制模型响应的详细程度。较低的值会产生更简洁的响应，而较高的值会产生更详细的响应。

- **promptCacheKey** _string_

  用于手动提示词缓存控制的缓存键。OpenAI 使用它来缓存相似请求的响应，以优化你的缓存命中率。

- **promptCacheOptions** _object_

  为 GPT-5.6 及更高版本的模型配置提示词缓存。`mode` 可以是 `'implicit'` 或 `'explicit'`，`ttl` 目前仅支持 `'30m'`。在显式模式下，只有标记了提示词缓存断点的内容块才会被缓存。

- **promptCacheRetention** _'in_memory' | '24h'_

  GPT-5.6 之前模型的旧版保留策略。设置为 `'24h'` 可在支持的模型上启用扩展提示词缓存。对于 GPT-5.6 及更高版本的模型，请改用 `promptCacheOptions.ttl`。

- **safetyIdentifier** _string_

  用于帮助检测可能违反 OpenAI 使用政策的应用程序用户的稳定标识符。这些 ID 应该是唯一标识每个用户的字符串。

- **systemMessageMode** _'system' | 'developer' | 'remove'_

  覆盖此模型的系统消息模式。如果未指定，模式会根据模型自动确定。`system` 对系统消息使用 'system' 角色（大多数模型的默认值）；`developer` 使用 'developer' 角色（推理模型使用）；`remove` 完全移除系统消息。

- **forceReasoning** _boolean_

  强制将此模型视为推理模型。这对于“隐身”推理模型（例如通过自定义 baseURL）很有用，因为 SDK 的允许列表无法识别其模型 ID。启用后，SDK 会应用推理模型参数兼容规则，并将 `systemMessageMode` 默认为 `developer`，除非被覆盖。

#### 推理

OpenAI 推出了 `o1`、`o3` 和 `o4` 系列[推理模型](https://platform.openai.com/docs/guides/reasoning)。
目前，`o4-mini`、`o3`、`o3-mini` 和 `o1` 可通过 chat 和 responses API 使用。
模型 `gpt-5.1-codex-mini` 仅通过 [responses API](#responses-models) 提供。

推理模型目前仅生成文本，有几个限制，并且仅支持使用 `generateText` 和 `streamText`。

它们支持附加设置和响应元数据：

- 你可以使用 `providerOptions` 设置
  - `reasoningEffort` 选项（或 `reasoningEffort` 模型设置），它决定模型执行的推理量。

- 你可以使用响应 `usage` 通过 `usage.outputTokenDetails.reasoningTokens` 访问模型生成的推理 token 数量。

```ts highlight="4,7-11,15"
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text, usage } = await generateText({
  model: openai.chat('gpt-6-astra'),
  prompt: 'Invent a new holiday and describe its traditions.',
  providerOptions: {
    openai: {
      reasoningEffort: 'low',
    } satisfies OpenAILanguageModelChatOptions,
  },
});

console.log(text);
console.log('Reasoning tokens:', usage.outputTokenDetails.reasoningTokens);
```

<Note>
  在支持的情况下，系统消息会自动转换为推理模型的 OpenAI 开发者消息。
</Note>

- 你可以通过 providerOptions `systemMessageMode` 控制系统消息的处理方式：
  - `developer`：将提示词视为开发者消息（推理模型的默认值）。
  - `system`：将系统消息保留为系统级指令。
  - `remove`：从消息中移除系统消息。

```ts highlight="12"
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const result = await generateText({
  model: openai.chat('gpt-6-astra'),
  messages: [
    { role: 'system', content: 'You are a helpful assistant.' },
    { role: 'user', content: 'Tell me a joke.' },
  ],
  providerOptions: {
    openai: {
      systemMessageMode: 'system',
    } satisfies OpenAILanguageModelChatOptions,
  },
});
```

<Note>
  推理模型需要额外的运行时推理来完成其
  推理阶段，然后才能生成响应。与其他模型相比，这会引入更长的延迟。
</Note>

<Note>
  对于推理模型，`maxOutputTokens` 会自动映射到 `max_completion_tokens`。
</Note>

#### 严格结构化输出

严格结构化输出默认启用。
你可以通过将 `strictJsonSchema` 选项设置为 `false` 来禁用它们。

```ts highlight="7"
import { openai, OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText, Output } from 'ai';
import { z } from 'zod';

const result = await generateText({
  model: openai.chat('gpt-6-astra'),
  providerOptions: {
    openai: {
      strictJsonSchema: false,
    } satisfies OpenAILanguageModelChatOptions,
  },
  output: Output.object({
    schema: z.object({
      name: z.string(),
      ingredients: z.array(
        z.object({
          name: z.string(),
          amount: z.string(),
        }),
      ),
      steps: z.array(z.string()),
    }),
    schemaName: 'recipe',
    schemaDescription: 'A recipe for lasagna.',
  }),
  prompt: 'Generate a lasagna recipe.',
});

console.log(JSON.stringify(result.output, null, 2));
```

<Note type="warning">
  OpenAI 结构化输出有几个
  [限制](https://openai.com/index/introducing-structured-outputs-in-the-api)，
  特别是关于[支持的 schema](https://platform.openai.com/docs/guides/structured-outputs/supported-schemas)，
  因此需要选择启用。

例如，不支持可选的 schema 属性。
你需要将 Zod 的 `.nullish()` 和 `.optional()` 改为 `.nullable()`。

</Note>

import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';

#### 预测输出

OpenAI 为 `gpt-4o` 和 `gpt-4o-mini` 支持[预测输出](https://platform.openai.com/docs/guides/latency-optimization#use-predicted-outputs)。
预测输出通过允许你指定模型应修改的基础文本，帮助你减少延迟。
你可以通过将 `prediction` 选项添加到 `providerOptions.openai` 对象来启用预测输出：

```ts highlight="15-18"
const result = streamText({
  model: openai.chat('gpt-4o'),
  messages: [
    {
      role: 'user',
      content: 'Replace the Username property with an Email property.',
    },
    {
      role: 'user',
      content: existingCode,
    },
  ],
  providerOptions: {
    openai: {
      prediction: {
        type: 'content',
        content: existingCode,
      },
    } satisfies OpenAILanguageModelChatOptions,
  },
});
```

OpenAI 为预测输出提供使用信息（`acceptedPredictionTokens` 和 `rejectedPredictionTokens`）。
你可以在 `providerMetadata` 对象中访问它。

```ts highlight="3-4"
const openaiMetadata = (await result.providerMetadata)?.openai;

const acceptedPredictionTokens = openaiMetadata?.acceptedPredictionTokens;
const rejectedPredictionTokens = openaiMetadata?.rejectedPredictionTokens;
```

<Note type="warning">
  OpenAI 预测输出有几个
  [限制](https://platform.openai.com/docs/guides/predicted-outputs#limitations)，
  例如不支持的 API 参数和不支持工具调用。
</Note>

#### 图像细节

你可以使用 `openai` 提供商选项将[图像输入细节](https://platform.openai.com/docs/guides/images-vision?api-mode=responses#specify-image-input-detail-level)设置为 `high`、`low`、`original` 或 `auto`：

```ts highlight="13-16"
const result = await generateText({
  model: openai.chat('gpt-6-astra'),
  messages: [
    {
      role: 'user',
      content: [
        { type: 'text', text: 'Describe the image in detail.' },
        {
          type: 'file',
          mediaType: 'image',
          data: 'https://github.com/vercel/ai/blob/main/examples/ai-functions/data/comic-cat.png?raw=true',

          // OpenAI specific options - image detail:
          providerOptions: {
            openai: { imageDetail: 'low' },
          },
        },
      ],
    },
  ],
});
```

对于 GPT-5.6，`original` 保留输入尺寸，不会调整到补丁预算或像素尺寸限制。`auto` 和省略细节设置使用与 `original` 相同的尺寸行为，这可能会增加大图像的输入 token 用量。

<Note type="warning">
  由于 `UIMessage` 类型（由 `useChat` 等 AI SDK UI Hook 使用）不
  支持 `providerOptions` 属性，你可以先使用 `convertToModelMessages`
  再将消息传递给 `generateText` 或
  `streamText` 等函数。有关 `providerOptions` 用法的更多详细信息，请参阅
  [此处](/docs/foundations/prompts#provider-options)。
</Note>

#### 蒸馏

OpenAI 为某些模型支持模型蒸馏。

这会将生成结果保存到 OpenAI 平台，以便稍后用于蒸馏。

```typescript highlight="9-16"
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';

        metadata: {
          custom: 'value',
        },

    },
  });

  console.log(text);
  console.log();
  console.log('Usage:', usage);
}

main().catch(console.error);
```

#### 提示词缓存

OpenAI 为支持的模型引入了[提示词缓存](https://platform.openai.com/docs/guides/prompt-caching)，
包括 `gpt-4o` 和 `gpt-4o-mini`。

- 当提示词为 1024 个 token 或更长时，这些模型会自动启用提示词缓存。它
  不需要显式启用。
- 你可以使用响应 `usage` 通过 `usage.inputTokenDetails.cacheReadTokens` 访问缓存命中的提示词 token 数量。
- 对于 GPT-5.6 及更高版本的模型，`usage.inputTokenDetails.cacheWriteTokens` 报告写入缓存的 token。
- 对于 GPT-5.6 及更高版本的模型，`promptCacheOptions.ttl` 设置 30 分钟的最小缓存生存时间。较早的模型通常在 5-10 分钟不活动期间保留内存中的前缀，最长可达一小时。

```ts highlight="9"
import { openai } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text, usage } = await generateText({
  model: openai.chat('gpt-6-luna'),
  prompt: `A 1024-token or longer prompt...`,
});

console.log('Cached tokens:', usage.inputTokenDetails.cacheReadTokens);
```

为了提高缓存命中率，你可以使用 `promptCacheKey` 选项手动控制缓存：

```ts highlight="7-11"
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text, usage } = await generateText({
  model: openai.chat('gpt-6-astra'),
  prompt: `A 1024-token or longer prompt...`,
  providerOptions: {
    openai: {
      promptCacheKey: 'my-custom-cache-key-123',
    } satisfies OpenAILanguageModelChatOptions,
  },
});

console.log('Cached tokens:', usage.inputTokenDetails.cacheReadTokens);
```

GPT-5.6 及更高版本的模型支持在文本、图像和文件内容块上设置显式缓存断点。设置请求级缓存键，并使用 `promptCacheBreakpoint` 标记每个可复用前缀的末尾：

```ts highlight="9-12,20-28"
import {
  openai,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/openai';
import { generateText } from 'ai';

const { usage } = await generateText({
  model: openai('gpt-6-astra'),
  providerOptions: {
    openai: {
      promptCacheKey: 'tenant:acme:support-v1',
      promptCacheOptions: { mode: 'explicit', ttl: '30m' },
    } satisfies OpenAILanguageModelResponsesOptions,
  },
  messages: [
    {
      role: 'user',
      content: [
        {
          type: 'text',
          text: `A stable prefix of at least 1024 tokens...`,
          providerOptions: {
            openai: {
              promptCacheBreakpoint: { mode: 'explicit' },
            },
          },
        },
        { type: 'text', text: 'What should I do next?' },
      ],
    },
  ],
});

console.log('Cache reads:', usage.inputTokenDetails.cacheReadTokens);
console.log('Cache writes:', usage.inputTokenDetails.cacheWriteTokens);
```

在 `'implicit'` 模式下，OpenAI 会在最新消息上放置自动断点，并且也会遵循显式断点。在 `'explicit'` 模式下，只有标记的内容块才有资格被缓存；没有任何显式断点的请求不会使用提示词缓存。

对于支持扩展缓存的 GPT-5.6 之前的模型，你可以让缓存前缀保持活跃长达 24 小时：

```ts highlight="7-12"
import { openai, type OpenAILanguageModelChatOptions } from '@ai-sdk/openai';
import { generateText } from 'ai';

const { text, usage } = await generateText({
  model: openai.chat('gpt-6-astra'),
  prompt: `A 1024-token or longer prompt...`,
  providerOptions: {
    openai: {
      promptCacheKey: 'my-custom-cache-key-123',
      promptCacheRetention: '24h',
    } satisfies OpenAILanguageModelChatOptions,
  },
});

console.log('Cached tokens:', usage.inputTokenDetails.cacheReadTokens);
```

### Completion 模型

你可以使用 `.completion()` 工厂方法创建调用 [OpenAI completions API](https://platform.openai.com/docs/api-reference/completions) 的模型。
第一个参数是模型 id。
目前仅支持 `gpt-3.5-turbo-instruct`。

```ts
const model = openai.completion('gpt-3.5-turbo-instruct');
```

OpenAI completion 模型还支持一些不属于[标准调用设置](/docs/ai-sdk-core/settings)的模型特定设置。
你可以将它们作为选项参数传递：

```ts
const model = openai.completion('gpt-3.5-turbo-instruct');

await model.doGenerate({
  providerOptions: {
    openai: {
      echo: true, // optional, echo the prompt in addition to the completion
      logitBias: {
        // optional likelihood for specific tokens
        '50256': -100,
      },
      suffix: 'some text', // optional suffix that comes after a completion of inserted text
      user: 'test-user', // optional unique user identifier
    } satisfies OpenAILanguageModelCompletionOptions,
  },
});
```

以下可选提供商选项可用于 OpenAI completion 模型：

- **echo**：_boolean_

  在补全之外回显提示词。

- **logitBias** _Record&lt;number, number&gt;_

  修改指定 token 出现在补全中的可能性。

  接受一个 JSON 对象，将 token（由其在
  GPT 分词器中的 token ID 指定）映射到 -100 到 100 之间的关联偏置值。你可以
  使用此分词器工具将文本转换为 token ID。在数学上，
  偏置会在采样之前添加到模型生成的 logits 中。
  确切效果因模型而异，但 -1 到 1 之间的值应该
  降低或增加被选中的可能性；像 -100 或 100 这样的值
  应该导致相关 token 被禁止或独占选择。

  例如，你可以传递 `{"50256": -100}` 来阻止 &lt;|endoftext|&gt;
  token 被生成。

- **logprobs** _boolean | number_

  返回 token 的对数概率。包含 logprobs 会增加
  响应大小并可能减慢响应时间。但是，它
  有助于更好地理解模型的行为。

  设置为 true 将返回所生成 token 的
  对数概率。

  设置为数字将返回所生成的前 n 个
  token 的对数概率。

- **suffix** _string_

  插入文本补全之后的后缀。

- **user** _string_

  代表最终用户的唯一标识符，可帮助 OpenAI
  监控和检测滥用行为。[了解更多](https://platform.openai.com/docs/guides/safety-best-practices/end-user-ids)。

## 实时模型

<Note type="warning">实时是实验性功能。</Note>

使用 `.experimental_realtime()` 处理 [OpenAI Realtime](https://platform.openai.com/docs/guides/realtime)
和 [OpenAI Live](https://developers.openai.com/api/docs/guides/live) 模型。

```ts
import { openai } from '@ai-sdk/openai';

const model = openai.experimental_realtime('gpt-realtime');
const liveModel = openai.experimental_realtime('gpt-live-1');

// Select the API explicitly for an early-access or otherwise unknown model ID.
const earlyAccessModel = openai.experimental_realtime('not-yet-released', {
  api: 'live',
});
```

OpenAI 独有的 `api` 选项接受 `'live'` 或 `'realtime'`，并且优先于
模型 ID 选择。没有它时，已知的 `gpt-live-1` ID 使用 Live，其他
ID 保留 Realtime 默认值。提供商在请求失败后不会切换 API。两个模型实现都使用现有的实验性实时接口。

Live 支持**通过应用程序拥有的中继进行浏览器 WSS 会话，并带有客户端
委托**，使用 `experimental_useRealtime` 作为浏览器运行时，以及可选的
浏览器直接 WebRTC。你的应用程序拥有智能体和工具执行；Live
委托不会调用 `onToolCall`。对于低级服务器适配器，使用 `liveModel.getServerWebSocketConfig()` 获取仅服务器连接
设置，并使用
`liveModel.serializeClientEvent()` 序列化命令。使用
`liveModel.createServerEventParser()` 为每个连接创建一个解析器，并将传入的 JSON 传递给返回的函数。它返回规范化事件的数组，并在 `raw` 中保留每个原始事件。

对于基于 token 的 **Realtime API** 会话，在你的
服务器上使用 `openai.experimental_realtime.getToken()` 创建一个短期 token：

```ts
const token = await openai.experimental_realtime.getToken({
  model: 'gpt-realtime',
});
```

Live 不使用 Realtime 客户端密钥铸造。为已知
Live 模型或使用 `api: 'live'` 调用 `getToken` 会在铸造请求之前被拒绝。Live 的 WebSocket
连接在受信任的服务器上进行身份验证；请将提供商 API 密钥排除在
浏览器代码之外。API 选择器选择的是协议，而不是同一模型的不同身份验证
能力。

对应用程序拥有的中继进行浏览器身份验证与 OpenAI
身份验证是分开的。使用你的应用程序的会话或短期
凭据保护该中继；仅进行来源检查不是用户身份验证。中继在上游使用其
服务器持有的 OpenAI 密钥。选择 Live 模型不会使 Realtime
客户端密钥端点与 Live API 兼容。

对于浏览器直接 Live WebRTC，经过身份验证的应用程序端点通过 `liveModel.doCreateWebRTCSession({ sdp, sessionConfig, abortSignal })`
使用服务器的项目密钥执行
SDP 交换。浏览器接收
会话连接应答，而不是项目密钥或 Realtime 客户端密钥。此
设置端点仍然需要应用程序身份验证。有关 `api.session` 设置契约和可运行示例，请参阅
[`experimental_useRealtime` 参考](/docs/reference/ai-sdk-ui/use-realtime)。

### Live 会话选项

通过 `sessionConfig.providerOptions.openai` 配置 Live 特定设置，
类型为 `Experimental_OpenAIRealtimeModelLiveOptions`。例如：

```ts
import type { Experimental_OpenAIRealtimeModelLiveOptions as OpenAIRealtimeModelLiveOptions } from '@ai-sdk/openai';

const sessionConfig = {
  instructions: 'Be concise. Delegate questions that need research or tools.',
  providerOptions: {
    openai: {
      delegation: { type: 'client' },
    } satisfies OpenAIRealtimeModelLiveOptions,
  },
};
```

- `delegation`：使用 `{ type: 'client' }` 处理应用程序拥有的工作。省略或
  `null` 也会选择客户端模式。不支持其他委托模式。
- `input`：具有 developer、user 或 assistant 角色的先前文本消息。
- `voice`：授权的自定义语音引用 `{ id }`，与
  普通的 `sessionConfig.voice` 字符串互斥。
- `store`：请求提供商端会话存储；可用性取决于
  OpenAI 项目配置。
- `client.dataChannel`：WebRTC 启动权限策略，带有
  `allowedClientEvents` 和 `allowedServerEvents`。在应用程序服务器上设置它，
  而不是来自看起来可信的浏览器输入。省略会保留提供商默认值；
  `[]` 不允许任何事件，`'all'` 允许所有事件。响应事件选择器使用
  `{ type: 'response.event', responseEvent: 'response.completed' }` 来选择
  原生嵌套事件，这些事件保持为原始 `custom` 事件，而不是托管的 SDK
  响应。对于你的应用程序启用的会话功能，保持就绪状态、错误和终端用量可观察。

使用 `session-start` 发送初始 WebSocket 配置；WebRTC 在 SDP 设置期间启动
会话，并通过 SDP 协商音频格式。Live 启动设置是
不可变的：`session-update` 会被拒绝。使用 `input-audio-mute` 和
`input-audio-unmute` 进行远程输入处理；这些命令不会释放
本地麦克风。通过
`context-append` 返回应用程序上下文，使用来自 `delegation-created` 的不透明 `delegationId`，或
使用 `null` 表示没有委托的上下文。其 `providerOptions.openai.channel`
接受 `instructions`、`thinking`（默认值）或 `commentary`。

对于优雅关闭，在发送 `session-close` 之前安装 `session-closed` 监听器；
该事件确认最终语音用量。`session-usage` 包含累计秒数，
因此请替换较早的快照，而不是相加。

有关浏览器集成，请参阅
[`experimental_useRealtime` 参考](/docs/reference/ai-sdk-ui/use-realtime#continuous-conversations)。
它涵盖 JSON/PCM16 WebSocket 中继运行时、可选的 WebRTC 设置和权限
策略、麦克风和播放所有权、`session.delegations`、用于
应用程序上下文的 `sendEvent`，以及用于有界最终化的 `close()`。在生产
中继中使用 `wss:`。连续对话语义并不意味着浏览器支持每个
提供商编解码器或传输。[Realtime 指南](/docs/ai-sdk-core/realtime)涵盖
旧版基于 token 的、基于轮次的会话。

### 图像编辑

OpenAI 的 `gpt-image-*` 模型支持强大的图像编辑能力。通过 `prompt.images` 传递输入图像，以转换、组合或编辑现有图像。

#### 基本图像编辑

使用文本提示词转换现有图像：

```ts
const imageBuffer = readFileSync('./input-image.png');

const { images } = await generateImage({
  model: openai.image('gpt-image-2.5-sunburst'),
  prompt: {
    text: 'Turn the cat into a dog but retain the style of the original image',
    images: [imageBuffer],
  },
});
```

#### 使用蒙版进行修复

使用蒙版编辑图像的特定部分。蒙版中的透明区域表示应编辑图像的位置：

```ts
const image = readFileSync('./input-image.png');
const mask = readFileSync('./mask.png'); // Transparent areas = edit regions

const { images } = await generateImage({
  model: openai.image('gpt-image-2.5-sunburst'),
  prompt: {
    text: 'A sunlit indoor lounge area with a pool containing a flamingo',
    images: [image],
    mask: mask,
  },
});
```

#### 背景移除

在支持透明背景的模型上将 `background` 设置为 `transparent`，以移除图像的背景：

```ts
import { openai, type OpenAIImageModelEditOptions } from '@ai-sdk/openai';
import { generateImage } from 'ai';

const imageBuffer = readFileSync('./input-image.png');

const { images } = await generateImage({
  model: openai.image('gpt-image-1.5'),
  prompt: {
    text: 'do not change anything',
    images: [imageBuffer],
  },
  providerOptions: {
    openai: {
      background: 'transparent',
      outputFormat: 'png',
    } satisfies OpenAIImageModelEditOptions,
  },
});
```

#### 多图像组合

将多个参考图像组合成单个输出。`gpt-image-*` 模型支持最多 16 个输入图像：

```ts
const cat = readFileSync('./cat.png');
const dog = readFileSync('./dog.png');
const owl = readFileSync('./owl.png');
const bear = readFileSync('./bear.png');

const { images } = await generateImage({
  model: openai.image('gpt-image-2.5-sunburst'),
  prompt: {
    text: 'Combine these animals into a group photo, retaining the original style',
    images: [cat, dog, owl, bear],
  },
});
```

<Note>
  输入图像可以提供为 `Buffer`、`ArrayBuffer`、`Uint8Array` 或
  base64 编码字符串。对于 `gpt-image-*` 模型，每个图像应为
  `png`、`webp` 或 `jpg` 文件，且小于 50MB。
</Note>

### 模型能力

| 模型                     | 尺寸                                   |
| ------------------------ | -------------------------------------- |
| `gpt-image-2.5-flare`    | 标准预设和自定义尺寸                   |
| `gpt-image-2.5-sunburst` | 标准预设和自定义尺寸                   |
| `gpt-image-2`            | 1024x1024, 1536x1024, 1024x1536        |
| `gpt-image-1.5`          | 1024x1024, 1536x1024, 1024x1536        |
| `gpt-image-1-mini`       | 1024x1024, 1536x1024, 1024x1536        |
| `gpt-image-1`            | 1024x1024, 1536x1024, 1024x1536        |
| `dall-e-3`               | 1024x1024, 1792x1024, 1024x1792        |
| `dall-e-2`               | 256x256, 512x512, 1024x1024            |

使用 `gpt-image-2.5-flare` 进行快速、通用的图像生成，当编辑精度和指令遵循
是优先事项时使用
`gpt-image-2.5-sunburst`。两个模型都接受自定义 `WIDTHxHEIGHT` 尺寸，其尺寸
为 16 的倍数，宽高比从 1:3 到 3:1，任何边不超过
3840 像素，总面积从 655,360 到 8,294,400 像素。
高于 2560x1440 的分辨率是实验性的。

你可以向图像模型传递可选的 `providerOptions`。这些容易由 OpenAI 更改，并且取决于模型。例如，`gpt-image-*` 模型支持 `quality` 选项：

```ts
import { openai, type OpenAIImageModelGenerationOptions } from '@ai-sdk/openai';
import { generateImage } from 'ai';

const { image, providerMetadata } = await generateImage({
  model: openai.image('gpt-image-2.5-flare'),
  prompt: 'A salamander at sunrise in a forest pond in the Seychelles.',
  providerOptions: {
    openai: { quality: 'high' } satisfies OpenAIImageModelGenerationOptions,
  },
});
```

`gpt-image-2.5-flare` 和 `gpt-image-2.5-sunburst` 模型还支持
`quality: 'xhigh'` 和 `quality: 'max'`，用于图像生成和编辑：

```ts
const { image } = await generateImage({
  model: openai.image('gpt-image-2.5-sunburst'),
  prompt: 'A salamander at sunrise in a forest pond in the Seychelles.',
  providerOptions: {
    openai: { quality: 'max' } satisfies OpenAIImageModelGenerationOptions,
  },
});
```

有关 `generateImage()` 的更多信息，请参阅[图像生成](/docs/ai-sdk-core/image-generation)。

OpenAI 的图像模型在响应中返回附加元数据，可通过
`providerMetadata.openai` 访问。以下 OpenAI 特定的元数据
可用：

- **images** _Array&lt;object&gt;_

  图像特定元数据的数组。每个图像对象可能包含：
  - `revisedPrompt` _string_ - 实际用于生成图像的修订提示词（OpenAI 可能出于安全或清晰度修改你的提示词）
  - `created` _number_ - 图像创建时的 Unix 时间戳（以秒为单位）
  - `size` _string_ - 生成图像的尺寸。`1024x1024`、`1024x1536` 或 `1536x1024` 之一
  - `quality` _string_ - 生成图像的质量。`low`、`medium`、`high`、`xhigh` 或 `max` 之一
  - `background` _string_ - 用于图像生成的 background 参数。`transparent` 或 `opaque`
  - `outputFormat` _string_ - 生成图像的输出格式。`png`、`webp` 或 `jpeg` 之一

有关可用 OpenAI 图像模型选项的更多信息，请参阅 [OpenAI API 参考](https://platform.openai.com/docs/api-reference/images/create)。

## 转录模型

你可以使用 `.transcription()` 工厂方法创建调用 [OpenAI transcription API](https://platform.openai.com/docs/api-reference/audio/transcribe)
的模型。

第一个参数是模型 id，例如 `gpt-4o-transcribe`。

```ts
const model = openai.transcription('gpt-4o-transcribe');
```

你还可以使用 `providerOptions` 参数传递其他提供商特定的选项。例如，以 ISO-639-1（例如 `en`）格式提供输入语言将提高准确性和延迟。

```ts highlight="6"
import { transcribe } from 'ai';
import { openai, type OpenAITranscriptionModelOptions } from '@ai-sdk/openai';

const result = await transcribe({
  model: openai.transcription('gpt-4o-transcribe'),
  audio: new Uint8Array([1, 2, 3, 4]),
  providerOptions: {
    openai: { language: 'en' } satisfies OpenAITranscriptionModelOptions,
  },
});
```

要获取词级时间戳，请指定粒度：

```ts highlight="8-9"
import { transcribe } from 'ai';
import { openai, type OpenAITranscriptionModelOptions } from '@ai-sdk/openai';

const result = await transcribe({
  model: openai.transcription('whisper-1'),
  audio: new Uint8Array([1, 2, 3, 4]),
  providerOptions: {
    openai: {
      //timestampGranularities: ['word'],
      timestampGranularities: ['segment'],
    } satisfies OpenAITranscriptionModelOptions,
  },
});

// Access word-level timestamps
console.log(result.segments); // Array of segments with startSecond/endSecond
```

`gpt-4o-transcribe-diarize` 识别录音中的说话者。它默认为
`diarized_json` 响应格式和自动分块：

```ts
import { transcribe } from 'ai';
import { openai } from '@ai-sdk/openai';

const result = await transcribe({
  model: openai.transcription('gpt-4o-transcribe-diarize'),
  audio: new Uint8Array([1, 2, 3, 4]),
});

console.log(result.providerMetadata.openai.segments);
```

以下提供商选项可用：

- **timestampGranularities** _string[]_
  转录中时间戳的粒度。
  默认为 `['segment']`。
  可能的值是 `['word']`、`['segment']` 和 `['word', 'segment']`。
  注意：段级时间戳没有额外延迟，但生成词级时间戳会产生额外延迟。

- **language** _string_
  输入音频的语言。以 ISO-639-1 格式（例如 'en'）提供输入语言将提高准确性和延迟。
  可选。

- **prompt** _string_
  用于指导模型风格或延续先前音频片段的可选文本。提示词应与音频语言匹配。
  可选。

- **temperature** _number_
  采样温度，介于 0 和 1 之间。较高的值如 0.8 会使输出更随机，而较低的值如 0.2 会使其更聚焦和确定。如果设置为 0，模型将使用对数概率自动提高温度，直到达到某些阈值。
  默认为 0。
  可选。

- **include** _string[]_
  要包含在转录响应中的附加信息。

- **responseFormat** _'json' | 'verbose_json' | 'diarized_json'_
  转录响应的格式。`gpt-4o-transcribe-diarize` 默认为 `diarized_json`。

- **chunkingStrategy** _'auto' | object_
  控制音频如何分割成块。`gpt-4o-transcribe-diarize` 默认为 `'auto'`；提供此选项以覆盖默认值。对象形式使用 `type: 'server_vad'` 和可选的 `threshold`、`prefixPaddingMs` 和 `silenceDurationMs` 字段配置 OpenAI 服务器端 VAD。

- **streaming** _object_
  用于流式转录模型（如 `gpt-realtime-whisper`）的选项。
  与 `experimental_streamTranscribe` 一起使用。
  - **delay** _'minimal' | 'low' | 'medium' | 'high' | 'xhigh'_
    实时转录的延迟/准确性权衡。

  - **include** _string[]_
    要包含在实时转录事件中的附加字段，例如 `item.input_audio_transcription.logprobs`。

| 模型                        | 转录       | 流式传输   | 时长       | 分段       | 语言       |

| `whisper-1`                 | <Check />  | <Cross />  | <Check />  | <Check />  | <Check />  |

## 翻译模型

<Note type="warning">语音翻译是实验性功能。</Note>

你可以使用 `.translation()` 工厂方法创建通过 OpenAI Realtime
translations WebSocket 翻译实时语音的模型。翻译
模型仅支持流式传输，并与
[`experimental_streamTranslate`](/docs/reference/ai-sdk-core/stream-translate) 一起使用。

第一个参数是模型 id，例如 `gpt-realtime-translate`。

```ts
const model = openai.translation('gpt-realtime-translate');
```

```ts
import { experimental_streamTranslate as streamTranslate } from 'ai';
import { openai } from '@ai-sdk/openai';

const result = streamTranslate({
  model: openai.translation('gpt-realtime-translate'),
  audio: audioStream, // ReadableStream<Uint8Array | string>
  inputAudioFormat: { type: 'audio/pcm', rate: 24000 },
  targetLanguage: 'es',
});

for await (const part of result.fullStream) {
  if (part.type === 'output-text-delta') {
    process.stdout.write(part.delta);
  }
}
```

OpenAI Realtime 翻译 API 自动检测源语言
（不支持 `sourceLanguage`），接受 24kHz 16 位 PCM 输入，并始终
输出 24kHz 16 位 PCM 音频（不支持 `outputAudioFormat`）。
不支持的源和输出设置会以调用警告的形式出现。

### 模型能力

| 模型                     | 翻译音频   | 翻译文本   | 源转录     |
| ------------------------ | ---------- | ---------- | ---------- |
| `gpt-realtime-translate` | <Check />  | <Check />  | <Check />  |

## 语音模型

你可以使用 `.speech()` 工厂方法创建调用 [OpenAI speech API](https://platform.openai.com/docs/api-reference/audio/speech)
的模型。

第一个参数是模型 id，例如 `gpt-4o-mini-tts`。

```ts
const model = openai.speech('gpt-4o-mini-tts');
```

`voice` 参数可以设置为 OpenAI 可用语音之一：`alloy`、`ash`、`coral`、`echo`、`fable`、`onyx`、`nova`、`sage` 或 `shimmer`。

```ts highlight="6"
import { generateSpeech } from 'ai';
import { openai } from '@ai-sdk/openai';

const result = await generateSpeech({
  model: openai.speech('gpt-4o-mini-tts'),
  text: 'Hello, world!',
  voice: 'alloy', // OpenAI voice ID
});
```

你还可以使用 `providerOptions` 参数传递其他提供商特定的选项：

```ts highlight="7-9"
import { generateSpeech } from 'ai';
import { openai, type OpenAISpeechModelOptions } from '@ai-sdk/openai';

const result = await generateSpeech({
  model: openai.speech('gpt-4o-mini-tts'),
  text: 'Hello, world!',
  voice: 'alloy',
  providerOptions: {
    openai: {
      speed: 1.2,
    } satisfies OpenAISpeechModelOptions,
  },
});
```

- **instructions** _string_
  使用附加指令控制生成音频的语音，例如“以缓慢而稳定的语气说话”。
  不适用于 `tts-1` 或 `tts-1-hd`。
  可选。

- **speed** _number_
  生成音频的速度。
  选择 0.25 到 4.0 之间的值。
  默认为 1.0。
  可选。

### 模型能力

| 模型              | 指令       |
| ----------------- | ---------- |
| `tts-1`           | <Check />  |
| `tts-1-hd`        | <Check />  |
| `gpt-4o-mini-tts` | <Check />  |

## 评估模型

使用 `openai.evaluationModel(modelId)` 创建实验性评估模型。
它使用带有结构化输出的 Responses API 来回答 Choice、Score 和
Boolean 问题。选择一个支持结构化输出的模型，例如 `gpt-6-luna`。

```ts
import { openai } from '@ai-sdk/openai';
import { experimental_evaluate } from 'ai';

const { answers } = await experimental_evaluate({
  model: openai.evaluationModel('gpt-6-luna'),
  state: 'I was charged twice.',
  questions: {
    requestsRefund: {
      type: 'boolean',
      instructions: 'Is the customer requesting money back?',
    },
    department: {
      type: 'choice',
      instructions: 'Which team should handle this?',
      criteria: { billing: 'Charges and refunds', support: 'Other requests' },
    },
  },
});
```

分数是有序评分标准上的有限小数位置。Choice 标签
按提供的方式原样返回。这些是模型判断：Choice 或 Score 不会返回概率
分布。Boolean 答案包含 P(true) 的提示词估计，经过验证为有限且位于 `[0, 1]` 内。这些估计
不保证经过校准。在应用程序代码中应用阈值，例如
`answers.requestsRefund.probability >= 0.5`。

该工厂遵循 `createOpenAI` 设置，包括自定义 fetch 和 base URL。
通过 `providerOptions.openai` 传递 Responses 选项。用量、警告、
响应信息和提供商元数据都会被保留。拒绝、截断
输出或无效答案会使整个调用失败。请参阅[评估](/docs/ai-sdk-core/evaluation)。

评估模型也可以通过 `customProvider` 别名或
`createProviderRegistry().evaluationModel('provider:model')` 访问。直接字符串 ID
默认使用 Gateway，或使用显式配置的默认提供商（带有
`evaluationModel` 方法）。请参阅
[模型别名和注册表](/docs/ai-sdk-core/evaluation#model-aliases-and-registries)。
