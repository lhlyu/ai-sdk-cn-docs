# Amazon Bedrock 提供商

适用于 [AI SDK](/docs) 的 Amazon Bedrock 提供商包含对 [Amazon Bedrock](https://aws.amazon.com/bedrock) API 的语言模型支持。

## 设置

Bedrock 提供商在 `@ai-sdk/amazon-bedrock` 模块中可用。您可以通过以下方式安装它：

<InstallPackages packages="@ai-sdk/amazon-bedrock" />

### 先决条件

默认情况下，访问 Amazon Bedrock 基础模型的权限并非自动授予。为了获得基础模型的访问权限，具有足够权限的 IAM 用户需要通过控制台请求访问。一旦模型访问权限被授予，该账户中的所有用户均可使用。

有关更多信息，请参阅 [模型访问文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。

### 身份验证

Amazon Bedrock 提供商支持两种身份验证方法，并具有自动回退机制：API 密钥身份验证（推荐）和使用 IAM 凭证或 AWS SDK 凭证链的 AWS SigV4 身份验证。

#### 使用 API 密钥（推荐）

与 AWS SigV4 身份验证相比，API 密钥身份验证提供了更简单的设置。当提供 API 密钥时，它优先于任何 SigV4 凭证。

从 [AWS 控制台](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html) 生成一个 bedrock API 密钥，然后将其设置为 `AWS_BEARER_TOKEN_BEDROCK` 环境变量：

```bash
AWS_BEARER_TOKEN_BEDROCK=your-api-key-here
```

或直接将其传递给 `createAmazonBedrock`：

```ts
import { createAmazonBedrock } from '@ai-sdk/amazon-bedrock';

const amazonBedrock = createAmazonBedrock({
  apiKey: 'your-api-key-here',
  region: 'us-east-1',
});
```

当省略 `apiKey` 时，提供商将回退到 `AWS_BEARER_TOKEN_BEDROCK`，如果两者均未设置，则回退到 SigV4 身份验证。

#### 使用 IAM 访问密钥和秘密密钥

**步骤 1：创建 AWS 访问密钥和秘密密钥**

首先，您需要创建一个 AWS 访问密钥和秘密密钥。操作方法如下：

**登录 AWS 管理控制台**

- 前往 [AWS 管理控制台](https://console.aws.amazon.com/) 并使用您的 AWS 账户凭证登录。

**创建 IAM 用户**

- 导航到 [IAM 仪表板](https://console.aws.amazon.com/iam/home)，然后点击左侧导航菜单中的“用户”。
- 点击“创建用户”并填写所需详细信息以创建新的 IAM 用户。
- 确保选择“编程访问”作为访问类型。
- 用户账户需要附加 `AmazonBedrockFullAccess` 策略。

**创建访问密钥**

- 点击“安全凭证”选项卡，然后点击“创建访问密钥”。
- 点击“创建访问密钥”以生成新的访问密钥对。
- 下载包含访问密钥 ID 和秘密访问密钥的 `.csv` 文件。

**步骤 2：配置访问密钥和秘密密钥**

在您的项目中，如果还没有 `.env` 文件，请添加一个。此文件将用于将访问密钥和秘密密钥设置为环境变量。将以下行添加到 `.env` 文件中：

```makefile
AWS_ACCESS_KEY_ID=YOUR_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY=YOUR_SECRET_ACCESS_KEY
AWS_REGION=YOUR_REGION
```

<Note>
  许多框架（如 [Next.js](https://nextjs.org/)）会自动加载 `.env` 文件。
  如果您使用的是不同的框架，则可能需要使用诸如
  [`dotenv`](https://github.com/motdotla/dotenv) 之类的包手动加载 `.env` 文件。
</Note>

请务必将 `YOUR_ACCESS_KEY_ID`、`YOUR_SECRET_ACCESS_KEY` 和 `YOUR_REGION` 替换为您 AWS 账户中的实际值。

#### 使用 AWS SDK 凭证链（实例配置文件、实例角色、ECS 角色、EKS 服务账户等）

使用 AWS SDK 时，SDK 将自动使用凭证链来确定要使用的凭证。这包括实例配置文件、实例角色、ECS 角色、EKS 服务账户等。使用 AI SDK 时，可以通过不在提供商设置中指定 `accessKeyId` 和 `secretAccessKey`、`sessionToken` 属性，而是传递 `credentialProvider` 属性来实现类似行为。

_用法：_

`@aws-sdk/credential-providers` 包提供了一组凭证提供程序，可用于创建凭证提供程序链。

<InstallPackages packages="@aws-sdk/credential-providers" />

```ts
import { createAmazonBedrock } from '@ai-sdk/amazon-bedrock';
import { fromNodeProviderChain } from '@aws-sdk/credential-providers';

const amazonBedrock = createAmazonBedrock({
  region: 'us-east-1',
  credentialProvider: fromNodeProviderChain(),
});
```

## 提供商实例

您可以从 `@ai-sdk/amazon-bedrock` 导入默认提供商实例 `amazonBedrock`：

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
```

如果您需要自定义设置，可以从 `@ai-sdk/amazon-bedrock` 导入 `createAmazonBedrock` 并使用您的设置创建提供商实例：

```ts
import { createAmazonBedrock } from '@ai-sdk/amazon-bedrock';

const amazonBedrock = createAmazonBedrock({
  region: 'us-east-1',
  accessKeyId: 'xxxxxxxxx',
  secretAccessKey: 'xxxxxxxxx',
  sessionToken: 'xxxxxxxxx',
});
```

<Note>
  省略的选项使用以下环境变量。当 **同时** 将 `accessKeyId` 和 `secretAccessKey` 设置为字符串时，SigV4 仅使用 **您传入的 `sessionToken`** - 而不是来自环境的 `AWS_SESSION_TOKEN` - 因此静态密钥不会与工作负载令牌（例如 EKS IRSA）混合。
</Note>

您可以使用以下可选设置来自定义 Amazon Bedrock 提供商实例：

- **region** _string_

  您希望用于 API 调用的 AWS 区域。
  默认使用 `AWS_REGION` 环境变量。

- **accessKeyId** _string_

  您希望用于 API 调用的 AWS 访问密钥 ID。
  默认使用 `AWS_ACCESS_KEY_ID` 环境变量。

- **secretAccessKey** _string_

  您希望用于 API 调用的 AWS 秘密访问密钥。
  默认使用 `AWS_SECRET_ACCESS_KEY` 环境变量。

- **sessionToken** _string_

  可选。用于临时凭证。当 **同时** 将两个访问密钥设置为字符串时，
  如果需要，请在此处传递令牌；不使用来自环境的 `AWS_SESSION_TOKEN`。
  如果任一密钥来自环境，则省略 `sessionToken` 允许使用 `AWS_SESSION_TOKEN`。

- **credentialProvider** _() =&gt; Promise&lt;&#123; accessKeyId: string; secretAccessKey: string; sessionToken?: string; &#125;&gt;_

  可选。您希望用于 API 调用的 AWS 凭证提供程序链。
  默认使用指定的凭证。

- **apiKey** _string_

  可选。用于使用 Bearer 令牌身份验证对请求进行身份验证的 API 密钥。
  提供后，将使用它代替 AWS SigV4 身份验证。
  默认使用 `AWS_BEARER_TOKEN_BEDROCK` 环境变量。

- **baseURL** _string_

  可选。用于 Bedrock API 调用的基础 URL。
  对于自定义端点或代理配置很有用。

- **headers** _Record&lt;string, string&gt;_

  可选。要包含在请求中的自定义标头。

- **fetch** _(input: RequestInfo, init?: RequestInit) =&gt; Promise&lt;Response&gt;_

  可选。自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。
  您可以将其用作中间件来拦截请求，
  或提供自定义 fetch 实现，例如用于测试。

## 语言模型

您可以使用提供商实例创建调用 Bedrock API 的模型。
第一个参数是模型 ID，例如 `meta.llama3-70b-instruct-v1:0`。

```ts
const model = amazonBedrock('meta.llama3-70b-instruct-v1:0');
```

Amazon Bedrock 模型还支持一些不属于 [标准调用设置](/docs/ai-sdk-core/settings) 的特定于模型的提供商选项。
您可以在 `providerOptions` 参数中传递它们：

```ts
const model = amazonBedrock('anthropic.claude-3-sonnet-20240229-v1:0');

await generateText({
  model,
  providerOptions: {
    anthropic: {
      additionalModelRequestFields: { top_k: 350 },
    },
  },
});
```

有关基于所选模型的附加设置文档，请参阅 [Amazon Bedrock 推理参数文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters.html)。

您可以使用 Amazon Bedrock 语言模型通过 `generateText` 函数生成文本：

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

const { text } = await generateText({
  model: amazonBedrock('meta.llama3-70b-instruct-v1:0'),
  prompt: 'Write a vegetarian lasagna recipe for 4 people.',
});
```

Amazon Bedrock 语言模型也可以在 `streamText` 函数中使用
（请参阅 [AI SDK Core](/docs/ai-sdk-core)）。

### 结构化输出

对于 Anthropic 模型，您可以使用 `structuredOutputMode` 提供商选项来选择 Amazon Bedrock 生成结构化输出的方式：

- `"outputFormat"`：使用 Bedrock 原生的 `output_config.format` 参数。
- `"jsonTool"`：使用带有必需工具选择的特殊 `json` 工具。
- `"auto"`：在支持时使用原生结构化输出，否则回退到 JSON 工具。这是默认值。

在 `"auto"` 模式下，Claude Sonnet 4.6 和 Claude Haiku 4.5 使用 JSON 工具回退，因为原生结构化输出在不同工作负载和 Bedrock 账户中可能不可靠。您可以设置 `"outputFormat"` 以在您的账户和工作负载适用时选择原生结构化输出，或使用 `"jsonTool"` 强制任何模型使用回退：

```ts
import {
  amazonBedrock,
  type AmazonBedrockLanguageModelChatOptions,
} from '@ai-sdk/amazon-bedrock';
import { generateText, Output } from 'ai';
import { z } from 'zod';

const { output } = await generateText({
  model: amazonBedrock('eu.anthropic.claude-sonnet-4-6'),
  output: Output.object({
    schema: z.object({
      summary: z.string(),
      findings: z.array(z.string()),
    }),
  }),
  prompt: 'Summarize the inspection report.',
  providerOptions: {
    amazonBedrock: {
      structuredOutputMode: 'jsonTool',
    } satisfies AmazonBedrockLanguageModelChatOptions,
  },
});
```

旧的 `providerOptions.bedrock` 键仍然受支持。为了与 Anthropic 提供商保持一致，`providerOptions.anthropic.structuredOutputMode` 在 Bedrock 上的 Anthropic 模型中也会被识别。当两者都提供时，`amazonBedrock` 或旧的 `bedrock` 值优先。

### 文件输入

<Note type="warning">
  Amazon Bedrock 支持将文件输入与特定模型结合使用，例如
  `anthropic.claude-3-haiku-20240307-v1:0`。
</Note>

Amazon Bedrock 提供商支持文件输入，例如 PDF 文件。

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

const result = await generateText({
  model: amazonBedrock('anthropic.claude-3-haiku-20240307-v1:0'),
  messages: [
    {
      role: 'user',
      content: [
        { type: 'text', text: 'Describe the pdf in detail.' },
        {
          type: 'file',
          data: readFileSync('./data/ai.pdf'),
          mediaType: 'application/pdf',
        },
      ],
    },
  ],
});
```

### 防护机制

您可以使用 `bedrock` 提供商选项来利用 [Amazon Bedrock 防护机制](https://aws.amazon.com/bedrock/guardrails/)：

```ts
import { type AmazonBedrockLanguageModelChatOptions } from '@ai-sdk/amazon-bedrock';

const result = await generateText({
  model: amazonBedrock('anthropic.claude-3-sonnet-20240229-v1:0'),
  prompt: 'Write a story about space exploration.',
  providerOptions: {
    bedrock: {
      guardrailConfig: {
        guardrailIdentifier: '1abcd2ef34gh',
        guardrailVersion: '1',
        trace: 'enabled' as const,
        streamProcessingMode: 'async',
      },
    } satisfies AmazonBedrockLanguageModelChatOptions,
  },
});
```

如果您启用了跟踪，跟踪信息将在提供商元数据中返回。

```ts
if (result.providerMetadata?.bedrock.trace) {
  // ...
}
```

有关更多信息，请参阅 [Amazon Bedrock 防护机制文档](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)。

#### 防护内容

您可以使用部件本身的 `providerOptions` 将单个文本或图像部件标记为防护内容。这会将部件包装在 [`guardContent`](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_GuardrailConverseContentBlock.html) 块中，告诉 Bedrock 防护机制专门评估该内容。

对于文本部件，您还可以指定 `guardContentQualifiers` 以指示防护机制应如何处理内容（例如，作为基础来源、查询或防护内容）：

```ts
const result = await generateText({
  model: bedrock('anthropic.claude-3-sonnet-20240229-v1:0'),
  providerOptions: {
    bedrock: {
      guardrailConfig: {
        guardrailIdentifier: '1abcd2ef34gh',
        guardrailVersion: '1',
      },
    },
  },
  messages: [
    {
      role: 'user',
      content: [
        {
          type: 'text',
          text: 'London is the capital of UK. Tokyo is the capital of Japan.',
          providerOptions: {
            bedrock: {
              guardContent: true,
              guardContentQualifiers: ['grounding_source'],
            },
          },
        },
        {
          type: 'text',
          text: 'Some additional background information.',
        },
        {
          type: 'text',
          text: 'What is the capital of Japan?',
          providerOptions: {
            bedrock: {
              guardContent: true,
              guardContentQualifiers: ['query'],
            },
          },
        },
      ],
    },
  ],
});
```

图像部件也可以标记为防护内容：

```ts
{
  type: 'file',
  data: {
    type: 'data',
    data: imageBase64,
  },
  mediaType: 'image/png',
  providerOptions: {
    bedrock: {
      guardContent: true,
    },
  },
}
```

可用的 `guardContentQualifiers` 有：

- `'grounding_source'` — 用作防护机制基础来源的内容
- `'query'` — 视为要评估的查询的内容
- `'guard_content'` — 要由防护机制评估的内容

有关更多信息，请参阅 [Amazon Bedrock 防护机制与 Converse API 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-use-converse-api.html)。

### 引用

Amazon Bedrock 支持兼容模型对基于文档的输入的引用。启用后：

- 某些模型可以通过视觉理解读取文档，而不仅仅是提取文本
- 模型可以引用您提供的文档的特定部分，从而更容易将信息追溯到其来源（尚不支持）

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { generateText, Output } from 'ai';
import { z } from 'zod';
import fs from 'fs';

const result = await generateText({
  model: amazonBedrock('apac.anthropic.claude-sonnet-4-20250514-v1:0'),
  output: Output.object({
    schema: z.object({
      summary: z.string().describe('Summary of the PDF document'),
      keyPoints: z.array(z.string()).describe('Key points from the PDF'),
    }),
  }),
  messages: [
    {
      role: 'user',
      content: [
        {
          type: 'text',
          text: 'Summarize this PDF and provide key points.',
        },
        {
          type: 'file',
          data: readFileSync('./document.pdf'),
          mediaType: 'application/pdf',
          providerOptions: {
            bedrock: {
              citations: { enabled: true },
            },
          },
        },
      ],
    },
  ],
});

console.log('Response:', result.output);
```

### 缓存点

<Note>
  Amazon Bedrock 提示缓存目前处于预览版。要请求
  访问权限，请访问 [Amazon Bedrock 提示缓存
  页面](https://aws.amazon.com/bedrock/prompt-caching/)。
</Note>

在消息中，您可以使用 `providerOptions` 属性来设置缓存点。将 `providerOptions` 对象中的 `bedrock` 属性设置为 `{ cachePoint: { type: 'default' } }` 以创建缓存点。

您还可以使用 `ttl` 属性为缓存点指定 TTL（生存时间）。支持的值是 `'5m'`（5 分钟，默认）和 `'1h'`（1 小时）。1 小时 TTL 仅由 Claude Opus 4.5、Claude Haiku 4.5 和 Claude Sonnet 4.5 支持。

```ts
providerOptions: {
  bedrock: { cachePoint: { type: 'default', ttl: '1h' } },
}
```

<Note>
  当使用具有不同 TTL 的多个缓存点时，具有较长 TTL 的缓存条目必须出现在较短 TTL 之前（即，1 小时缓存条目必须位于 5 分钟缓存条目之前）。
</Note>

缓存使用信息在 `providerMetadata` 对象中返回。请参阅下面的示例。

<Note>
  缓存点具有特定于模型的最小令牌数和限制。例如，
  Claude 3.5 Sonnet v2 要求缓存点至少 1,024 个令牌，并且
  最多允许 4 个缓存点。有关支持的模型、区域和限制的详细信息，请参阅 [Amazon Bedrock 提示缓存
  文档](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)。
</Note>

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

const cyberpunkAnalysis =
  '... literary analysis of cyberpunk themes and concepts ...';

const result = await generateText({
  model: amazonBedrock('anthropic.claude-3-5-sonnet-20241022-v2:0'),
  messages: [
    {
      role: 'system',
      content: `You are an expert on William Gibson's cyberpunk literature and themes. You have access to the following academic analysis: ${cyberpunkAnalysis}`,
      providerOptions: {
        bedrock: { cachePoint: { type: 'default' } },
      },
    },
    {
      role: 'user',
      content:
        'What are the key cyberpunk themes that Gibson explores in Neuromancer?',
    },
  ],
});

console.log(result.text);
console.log(result.providerMetadata?.bedrock?.usage);
// Shows cache read/write token usage, e.g.:
// {
//   cacheReadInputTokens: 1337,
//   cacheWriteInputTokens: 42,
// }
```

缓存点也适用于流式响应：

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { streamText } from 'ai';

const cyberpunkAnalysis =
  '... literary analysis of cyberpunk themes and concepts ...';

const result = streamText({
  model: amazonBedrock('anthropic.claude-3-5-sonnet-20241022-v2:0'),
  messages: [
    {
      role: 'assistant',
      content: [
        { type: 'text', text: 'You are an expert on cyberpunk literature.' },
        { type: 'text', text: `Academic analysis: ${cyberpunkAnalysis}` },
      ],
      providerOptions: { bedrock: { cachePoint: { type: 'default' } } },
    },
    {
      role: 'user',
      content:
        'How does Gibson explore the relationship between humanity and technology?',
    },
  ],
});

for await (const textPart of result.textStream) {
  process.stdout.write(textPart);
}

console.log(
  'Cache token usage:',
  (await result.providerMetadata)?.bedrock?.usage,
);
// Shows cache read/write token usage, e.g.:
// {
//   cacheReadInputTokens: 1337,
//   cacheWriteInputTokens: 42,
// }
```

### 提供商元数据

以下 Bedrock 特定的元数据可能会在 `providerMetadata.bedrock` 中返回：

- **trace** _(可选)_
  防护机制跟踪信息（启用跟踪时）。
- **performanceConfig** _(可选)_
  性能配置，例如 `{ latency: 'optimized' }`。
- **serviceTier** _(可选)_
  服务层级信息，例如 `{ type: 'on-demand' }`。
- **usage** _(可选)_
  缓存令牌使用详情，包括 `cacheWriteInputTokens` 和 `cacheDetails`。
- **stopSequence** _string | null_
  触发停止的停止序列（如果有）。

## 推理

Amazon Bedrock 支持特定于模型创建者的推理功能：

- Anthropic（例如 `claude-sonnet-4-5-20250929`）：通过 `reasoningConfig` 提供商选项并指定思考预算（以令牌为单位）（最小值：`1024`，最大值：`64000`）来启用。
- Amazon（例如 `us.amazon.nova-2-lite-v1:0`）：通过 `reasoningConfig` 提供商选项并指定最大推理努力级别（`'low' | 'medium' | 'high'`）来启用。

```ts
import {
  amazonBedrock,
  type AmazonBedrockLanguageModelChatOptions,
} from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

// Anthropic example
const anthropicResult = await generateText({
  model: amazonBedrock('us.anthropic.claude-sonnet-4-5-20250929-v1:0'),
  prompt: 'How many people will live in the world in 2040?',
  providerOptions: {
    bedrock: {
      reasoningConfig: { type: 'enabled', budgetTokens: 1024 },
    } satisfies AmazonBedrockLanguageModelChatOptions,
  },
});

console.log(anthropicResult.reasoningText); // reasoning text
console.log(anthropicResult.text); // text response

// Nova 2 example
const amazonResult = await generateText({
  model: amazonBedrock('us.amazon.nova-2-lite-v1:0'),
  prompt: 'How many people will live in the world in 2040?',
  providerOptions: {
    bedrock: {
      reasoningConfig: { type: 'enabled', maxReasoningEffort: 'medium' },
    } satisfies AmazonBedrockLanguageModelChatOptions,
  },
});

console.log(amazonResult.reasoningText); // reasoning text
console.log(amazonResult.text); // text response
```

对于 Anthropic 模型，Bedrock 的 `maxTokens` 限制包括思考和最终文本。因此，提供商在设置 `maxTokens` 时将 `budgetTokens` 添加到 `maxOutputTokens`。当省略 `maxOutputTokens` 时，提供商将 `budgetTokens` 添加到默认值 `4096`。

有关如何将推理集成到聊天机器人中的更多详细信息，请参阅 [AI SDK UI：聊天机器人](/docs/ai-sdk-ui/chatbot#reasoning)。

## 计算机使用

通过 Anthropic，Amazon Bedrock 提供了三个提供商定义的工具，可用于与外部系统交互：

1. **Bash 工具**：允许运行 bash 命令。
2. **文本编辑器工具**：提供查看和编辑文本文件的功能。
3. **计算机工具**：支持控制计算机上的键盘和鼠标操作。

它们可通过提供商实例的 `tools` 属性获得。

<Note>
  Amazon Bedrock 不支持工具定义的严格模式。设置
  工具上的 `strict: true` 将被忽略，并会发出警告。
</Note>

### Bash 工具

Bash 工具允许运行 bash 命令。以下是创建和使用它的方法：

```ts
const bashTool = amazonBedrock.tools.bash_20241022({
  execute: async ({ command, restart }) => {
    // Implement your bash command execution logic here
    // Return the result of the command execution
  },
});
```

参数：

- `command` (string)：要运行的 bash 命令。除非工具正在重启，否则为必填。
- `restart` (boolean, 可选)：指定 true 将重启此工具。

## 嵌入模型

您可以使用 `.embedding()` 工厂方法创建调用 Bedrock API [Bedrock API](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html) 的模型。

```ts
const model = amazonBedrock.embedding('amazon.titan-embed-text-v1');
```

Bedrock Titan 嵌入模型 amazon.titan-embed-text-v2:0 支持多项附加设置。
您可以将它们作为选项参数传递：

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { type AmazonBedrockEmbeddingModelOptions } from '@ai-sdk/amazon-bedrock';
import { embed } from 'ai';

const model = amazonBedrock.embedding('amazon.titan-embed-text-v2:0');

const { embedding } = await embed({
  model,
  value: 'sunny day at the beach',
  providerOptions: {
    bedrock: {
      dimensions: 512, // optional, number of dimensions for the embedding
      normalize: true, // optional, normalize the output embeddings
    } satisfies AmazonBedrockEmbeddingModelOptions,
  },
});
```

以下可选的提供商选项可用于 Bedrock Titan 嵌入模型：

- **dimensions**：_number_

  输出嵌入应具有的维度数。接受以下值：1024（默认）、512、256。

- **normalize** _boolean_

  指示是否对输出嵌入进行归一化的标志。默认为 true。

### Nova 嵌入模型

Amazon Nova 嵌入模型支持额外的提供商选项：

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
```

以下可选的提供商选项可用于 Nova 嵌入模型：

- **embeddingDimension** _number_

  输出嵌入的维度数。支持的值：256、384、1024（默认）、3072。

- **embeddingPurpose** _string_

  嵌入的目的。接受：`GENERIC_INDEX`（默认）、`TEXT_RETRIEVAL`、`IMAGE_RETRIEVAL`、`VIDEO_RETRIEVAL`、`DOCUMENT_RETRIEVAL`、`AUDIO_RETRIEVAL`、`GENERIC_RETRIEVAL`、`CLASSIFICATION`、`CLUSTERING`。

  `eu-west-1` 和 `ap-northeast-1` 区域可用。
</Note>

```ts
const model = amazonBedrock.image('amazon.nova-canvas-v1:0');
```

然后您可以使用 `generateImage` 函数生成图像：

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { generateImage } from 'ai';

const { image } = await generateImage({
  model: amazonBedrock.image('amazon.nova-canvas-v1:0'),
  prompt: 'A beautiful sunset over a calm ocean',
  size: '512x512',
  seed: 42,
});
```

您还可以将 `providerOptions` 对象传递给 `generateImage` 函数以自定义生成行为。使用 `AmazonBedrockImageModelOptions` 类型来验证 Amazon Bedrock 图像提供商选项。首选的提供商选项键是 `providerOptions.amazonBedrock`；为了向后兼容，旧的 `providerOptions.bedrock` 键仍然受支持：

```ts
import {
  amazonBedrock,
  type AmazonBedrockImageModelOptions,
} from '@ai-sdk/amazon-bedrock';
import { generateImage } from 'ai';

const { image } = await generateImage({
  model: amazonBedrock.image('amazon.nova-canvas-v1:0'),
  prompt: 'A beautiful sunset over a calm ocean',
  size: '512x512',
  seed: 42,
  providerOptions: {
    amazonBedrock: {
      quality: 'premium',
      negativeText: 'blurry, low quality',
      cfgScale: 7.5,
      style: 'PHOTOREALISM',
    } satisfies AmazonBedrockImageModelOptions,
  },
});
```

以下可选的提供商选项可用于 Amazon Nova Canvas：

- **quality** _string_

  图像生成的质量级别。接受 `'standard'` 或 `'premium'`。

- **negativeText** _string_

  描述您不希望在生成的图像中出现的内容的文本。

- **cfgScale** _number_

  控制生成的图像与提示词的贴合程度。较高的值会导致图像与提示词更紧密地对齐。

- **style** _string_

  用于图像生成的预定义视觉风格。
  接受以下之一：
  `3D_ANIMATED_FAMILY_FILM` · `DESIGN_SKETCH` · `FLAT_VECTOR_ILLUSTRATION` ·
  `GRAPHIC_NOVEL_ILLUSTRATION` · `MAXIMALISM` · `MIDCENTURY_RETRO` ·
  `PHOTOREALISM` · `SOFT_DIGITAL_PAINTING`。

有关附加设置的文档，请参阅 [Amazon Bedrock
Amazon Nova 用户指南
文档](https://docs.aws.amazon.com/nova/latest/userguide/image-gen-req-resp-structure.html)。

### 图像编辑

Amazon Nova Canvas 支持多种图像编辑任务类型。当您通过 `prompt.images` 提供输入图像时，模型会自动检测适当的编辑模式，或者您可以在提供商选项中显式指定 `taskType`。

#### 图像变体

创建现有图像的变体，同时保持其核心特征：

```ts
const imageBuffer = readFileSync('./input-image.png');

const { images } = await generateImage({
  model: amazonBedrock.image('amazon.nova-canvas-v1:0'),
  prompt: {
    text: 'Modernize the style, photo-realistic, 8k, hdr',
    images: [imageBuffer],
  },
  providerOptions: {
    amazonBedrock: {
      taskType: 'IMAGE_VARIATION',
      similarityStrength: 0.7, // 0.2-1.0, higher = closer to original
      negativeText: 'bad quality, low resolution',
    } satisfies AmazonBedrockImageModelOptions,
  },
});
```

- **similarityStrength** _number_

  控制输出与输入图像的相似程度。值范围从 0.2 到 1.0，其中较高的值产生更接近原始图像的结果。

#### 内绘

编辑图像的特定部分。您可以使用掩码图像或文本提示词来定义要修改的区域：

**使用掩码提示词（基于文本的选择）：**

```ts
const imageBuffer = readFileSync('./input-image.png');

const { images } = await generateImage({
  model: amazonBedrock.image('amazon.nova-canvas-v1:0'),
  prompt: {
    text: 'a cute corgi dog in the same style',
    images: [imageBuffer],
  },
  providerOptions: {
    amazonBedrock: {
      maskPrompt: 'cat', // Describe what to replace
    } satisfies AmazonBedrockImageModelOptions,
  },
  seed: 42,
});
```

**使用掩码图像：**

```ts
const image = readFileSync('./input-image.png');
const mask = readFileSync('./mask.png'); // White pixels = area to change

const { images } = await generateImage({
  model: amazonBedrock.image('amazon.nova-canvas-v1:0'),
  prompt: {
    text: 'A sunlit indoor lounge area with a pool containing a flamingo',
    images: [image],
    mask: mask,
  },
});
```

- **maskPrompt** _string_

  要修改区域的文本描述。模型将自动识别并屏蔽所描述的区域。

#### 外绘

将图像扩展到其原始边界之外：

```ts
const imageBuffer = readFileSync('./input-image.png');

const { images } = await generateImage({
  model: amazonBedrock.image('amazon.nova-canvas-v1:0'),
  prompt: {
    text: 'A beautiful sunset landscape with mountains',
    images: [imageBuffer],
  },
  providerOptions: {
    amazonBedrock: {
      taskType: 'OUTPAINTING',
      maskPrompt: 'background',
      outPaintingMode: 'DEFAULT', // or 'PRECISE'
    } satisfies AmazonBedrockImageModelOptions,
  },
});
```

- **outPaintingMode** _string_

  控制外绘的执行方式。接受 `'DEFAULT'` 或 `'PRECISE'`。

#### 背景移除

从图像中移除背景：

```ts
const imageBuffer = readFileSync('./input-image.png');

const { images } = await generateImage({
  model: amazonBedrock.image('amazon.nova-canvas-v1:0'),
  prompt: {
    images: [imageBuffer],
  },
  providerOptions: {
    amazonBedrock: {
      taskType: 'BACKGROUND_REMOVAL',
    } satisfies AmazonBedrockImageModelOptions,
  },
});
```

<Note>
  背景移除不需要文本提示词 - 只需要输入图像。
</Note>

#### 图像编辑提供商选项

以下额外的提供商选项可用于图像编辑：

- **taskType** _string_

  显式设置编辑任务类型。接受 `'TEXT_IMAGE'`（纯文本的默认值）、`'IMAGE_VARIATION'`、`'INPAINTING'`、`'OUTPAINTING'` 或 `'BACKGROUND_REMOVAL'`。当提供图像但未指定显式 taskType 时，模型默认为 `'IMAGE_VARIATION'`（如果提供了掩码，则为 `'INPAINTING'`）。

- **maskPrompt** _string_

  要修改区域的文本描述（用于内绘/外绘）。提供掩码图像的替代方案。

- **similarityStrength** _number_

  对于 `IMAGE_VARIATION`：控制与原始图像的相似度（0.2-1.0）。

- **outPaintingMode** _string_

  对于 `OUTPAINTING`：控制外绘行为（`'DEFAULT'` 或 `'PRECISE'`）。

### 图像模型设置

您可以使用可选选项自定义生成行为：

```ts
await generateImage({
  model: amazonBedrock.image('amazon.nova-canvas-v1:0'),
  prompt: 'A beautiful sunset over a calm ocean',
  size: '512x512',
  seed: 42,
  maxImagesPerCall: 1, // Maximum number of images to generate per API call
});
```

- **maxImagesPerCall** _number_

  覆盖每次 API 调用生成的图像最大数量。默认值可能因模型而异，通常默认为 5。

### 模型能力

Amazon Nova Canvas 模型支持自定义尺寸，约束如下：

- 每边必须在 320-4096 像素之间（含）。
- 每边必须能被 16 整除。
- 宽高比必须在 1:4 和 4:1 之间。也就是说，一边的长度不能超过另一边的 4 倍。
- 总像素数必须小于 4,194,304。

有关更多信息，请参阅 [图像生成访问和
用法](https://docs.aws.amazon.com/nova/latest/userguide/image-gen-access.html)。

| 模型                     | 尺寸                                                                                                 |
| ------------------------- | ----------------------------------------------------------------------------------------------------- |
| `amazon.nova-canvas-v1:0` | 自定义尺寸：每边 320-4096px（必须能被 16 整除），宽高比 1:4 到 4:1，最大 4.2M 像素 |

## Bedrock Anthropic 提供商用法

Bedrock Anthropic 提供商通过 Amazon Bedrock 的原生 InvokeModel API 提供对 Anthropic 的 Claude 模型的支持。这提供了与 [Anthropic API](https://platform.claude.com/docs/en/build-with-claude/overview) 的完整功能对等性，包括可能无法通过 Converse API 使用的功能（例如流式响应中的 `stop_sequence`）。

有关 Amazon Bedrock 上可用的 Claude 模型的更多信息，请参阅 [Claude on Amazon Bedrock](https://platform.claude.com/docs/en/build-with-claude/claude-on-amazon-bedrock)。

### 提供商实例

您可以从 `@ai-sdk/amazon-bedrock/anthropic` 导入默认提供商实例 `bedrockAnthropic`：

```typescript
import { bedrockAnthropic } from '@ai-sdk/amazon-bedrock/anthropic';
```

如果您需要自定义设置，可以从 `@ai-sdk/amazon-bedrock/anthropic` 导入 `createBedrockAnthropic` 并使用您的设置创建提供商实例：

```typescript
import { createBedrockAnthropic } from '@ai-sdk/amazon-bedrock/anthropic';

const bedrockAnthropic = createBedrockAnthropic({
  region: 'us-east-1', // optional
  accessKeyId: 'xxxxxxxxx', // optional
  secretAccessKey: 'xxxxxxxxx', // optional
  sessionToken: 'xxxxxxxxx', // optional
});
```

#### 提供商设置

您可以使用以下可选设置来自定义 Bedrock Anthropic 提供商实例：

- **region** _string_

  您希望用于 API 调用的 AWS 区域。
  默认使用 `AWS_REGION` 环境变量。

- **accessKeyId** _string_

  您希望用于 API 调用的 AWS 访问密钥 ID。
  默认使用 `AWS_ACCESS_KEY_ID` 环境变量。

- **secretAccessKey** _string_

  您希望用于 API 调用的 AWS 秘密访问密钥。
  默认使用 `AWS_SECRET_ACCESS_KEY` 环境变量。

- **sessionToken** _string_

  可选。用于临时凭证。当 **同时** 将两个访问密钥设置为字符串时，
  如果需要，请在此处传递令牌；不使用来自环境的 `AWS_SESSION_TOKEN`。
  如果任一密钥来自环境，则省略 `sessionToken` 允许使用 `AWS_SESSION_TOKEN`。

- **apiKey** _string_

  用于使用 Bearer 令牌身份验证对请求进行身份验证的 API 密钥。
  提供后，将使用它代替 AWS SigV4 身份验证。
  默认使用 `AWS_BEARER_TOKEN_BEDROCK` 环境变量。

- **baseURL** _string_

  用于 Bedrock API 调用的基础 URL。
  对于自定义端点或代理配置很有用。

- **headers** _Resolvable&lt;Record&lt;string, string | undefined&gt;&gt;_

  要包含在请求中的标头。

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。
  您可以将其用作中间件来拦截请求，
  或提供自定义 fetch 实现，例如用于测试。

- **credentialProvider** _() => PromiseLike&lt;BedrockCredentials&gt;_

  用于 Bedrock 提供商的 AWS 凭证提供程序，以获取类似于 AWS SDK 的动态凭证。在此处设置提供程序将导致其凭证值被使用，而不是 `accessKeyId`、`secretAccessKey` 和 `sessionToken` 设置。

  - `userId` _string_ - 最终用户的外部标识符。

### 缓存控制

在消息和消息部件中，您可以使用 `providerOptions` 属性来设置缓存控制断点。
您需要将 `providerOptions` 对象中的 `anthropic` 属性设置为 `{ cacheControl: { type: 'ephemeral' } }` 以设置缓存控制断点。

```ts
      role: 'system',
      content: 'You are an expert assistant.',
      providerOptions: {
        anthropic: { cacheControl: { type: 'ephemeral' } },
      },
    },
    {
      role: 'user',
      content: 'Explain quantum computing.',
    },
  ],
});
```

<Note>
  缓存控制要求在缓存检查点之前至少有 1024 个令牌。
  有关支持的模型和限制的详细信息，请参阅 [Amazon Bedrock 提示缓存
  文档](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)。

### 计算机使用

### 推理

Anthropic 在 Bedrock 上为 Claude 3.7 和 Claude 4 模型提供推理支持，包括：

- `us.anthropic.claude-opus-4-8`
- `us.anthropic.claude-opus-4-7`
- `us.anthropic.claude-opus-4-6-v1`
- `us.anthropic.claude-opus-4-5-20251101-v1:0`
- `us.anthropic.claude-sonnet-4-5-20250929-v1:0`
- `us.anthropic.claude-opus-4-20250514-v1:0`
- `us.anthropic.claude-sonnet-4-20250514-v1:0`
- `us.anthropic.claude-opus-4-1-20250805-v1:0`
- `us.anthropic.claude-haiku-4-5-20251001-v1:0`

您可以使用 `thinking` 提供商选项并指定思考预算（以令牌为单位）来启用它。

```ts
import { bedrockAnthropic } from '@ai-sdk/amazon-bedrock/anthropic';
import { generateText } from 'ai';

const { text, reasoningText, reasoning } = await generateText({
  model: bedrockAnthropic('us.anthropic.claude-sonnet-4-5-20250929-v1:0'),
  prompt: 'How many people will live in the world in 2040?',
  providerOptions: {
    anthropic: {
      thinking: { type: 'enabled', budgetTokens: 12000 },
    },
  },
});

console.log(reasoningText); // reasoning text
console.log(reasoning); // reasoning details including redacted reasoning
console.log(text); // text response
```

Anthropic 的 `max_tokens` 限制包括思考和最终文本。为了同时为两者预留空间，提供商在设置 `max_tokens` 时将 `budgetTokens` 添加到 `maxOutputTokens`。对于已知模型，组合值以模型的最大输出令牌限制为上限。

有关如何将推理集成到聊天机器人中的更多详细信息，请参阅 [AI SDK UI：聊天机器人](/docs/ai-sdk-ui/chatbot#reasoning)。

## Bedrock Mantle 提供商用法

Bedrock Mantle 提供商通过 Amazon Bedrock 的 Mantle API 在 `https://bedrock-mantle.{region}.api.aws/v1` 提供对 OpenAI 兼容模型的访问。此端点支持 Chat Completions API 和 Responses API，并提供对可能仅通过 Mantle 端点可用的模型（例如 `openai.gpt-oss-120b`）的访问。

### 提供商实例

您可以从 `@ai-sdk/amazon-bedrock/mantle` 导入默认提供商实例 `bedrockMantle`：

```typescript
import { bedrockMantle } from '@ai-sdk/amazon-bedrock/mantle';
```

如果您需要自定义设置，可以从 `@ai-sdk/amazon-bedrock/mantle` 导入 `createBedrockMantle` 并使用您的设置创建提供商实例：

```typescript
import { createBedrockMantle } from '@ai-sdk/amazon-bedrock/mantle';

const bedrockMantle = createBedrockMantle({
  region: 'us-east-1', // optional
  accessKeyId: 'xxxxxxxxx', // optional
  secretAccessKey: 'xxxxxxxxx', // optional
  sessionToken: 'xxxxxxxxx', // optional
});
```

#### 提供商设置

您可以使用以下可选设置来自定义 Bedrock Mantle 提供商实例：

- **region** _string_

  您希望用于 API 调用的 AWS 区域。
  默认使用 `AWS_REGION` 环境变量。

- **accessKeyId** _string_

  您希望用于 API 调用的 AWS 访问密钥 ID。
  默认使用 `AWS_ACCESS_KEY_ID` 环境变量。

- **secretAccessKey** _string_

  您希望用于 API 调用的 AWS 秘密访问密钥。
  默认使用 `AWS_SECRET_ACCESS_KEY` 环境变量。

- **sessionToken** _string_

  可选。您希望用于 API 调用的 AWS 会话令牌。
  默认使用 `AWS_SESSION_TOKEN` 环境变量。

- **apiKey** _string_

  用于使用 Bearer 令牌身份验证对请求进行身份验证的 API 密钥。
  提供后，将使用它代替 AWS SigV4 身份验证。
  默认使用 `AWS_BEARER_TOKEN_BEDROCK` 环境变量。

- **baseURL** _string_

  用于 Bedrock Mantle API 调用的基础 URL。
  默认为 `https://bedrock-mantle.{region}.api.aws/v1`。

- **headers** _Record&lt;string, string | undefined&gt;_

  要包含在请求中的标头。

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。
  您可以将其用作中间件来拦截请求，
  或提供自定义 fetch 实现，例如用于测试。

- **credentialProvider** _() => PromiseLike&lt;BedrockCredentials&gt;_

  用于 Bedrock 提供商的 AWS 凭证提供程序，以获取类似于 AWS SDK 的动态凭证。在此处设置提供程序将导致其凭证值被使用，而不是 `accessKeyId`、`secretAccessKey` 和 `sessionToken` 设置。

### 语言模型

您可以使用 Mantle 提供商实例创建模型。默认情况下，提供商使用 Chat Completions API 创建模型，该 API 在 Mantle 上拥有最广泛的模型支持：

```ts
const model = bedrockMantle('openai.gpt-oss-120b');
```

您还可以显式选择 Chat Completions API 或 Responses API：

```ts
const chatModel = bedrockMantle.chat('openai.gpt-oss-120b');
const responsesModel = bedrockMantle.responses('openai.gpt-oss-120b');
```

请注意，并非所有 Mantle 模型都支持 Responses API。请参阅下面的模型能力表。

您可以使用 Bedrock Mantle 语言模型通过 `generateText` 函数生成文本：

```ts
import { bedrockMantle } from '@ai-sdk/amazon-bedrock/mantle';
import { generateText } from 'ai';

const { text } = await generateText({
  model: bedrockMantle('openai.gpt-oss-120b'),
  prompt: 'Invent a new holiday and describe its traditions.',
});
```

或使用 `streamText` 函数流式传输文本：

```ts
import { bedrockMantle } from '@ai-sdk/amazon-bedrock/mantle';
import { streamText } from 'ai';

const result = streamText({
  model: bedrockMantle('openai.gpt-oss-120b'),
  prompt: 'Invent a new holiday and describe its traditions.',
});

for await (const textPart of result.textStream) {
  process.stdout.write(textPart);
}
```

### 提供商选项

由于 Mantle API 与 OpenAI 兼容，提供商选项在 `openai` 命名空间下传递：

```ts
import { bedrockMantle } from '@ai-sdk/amazon-bedrock/mantle';
import { generateText } from 'ai';

const { text } = await generateText({
  model: bedrockMantle('openai.gpt-oss-120b'),
  prompt: 'Hello!',
  providerOptions: {
    openai: {
      // OpenAI-compatible provider options
    },
  },
});
```

### 模型能力

| 模型                           | Chat Completions | Responses API |
| ------------------------------- | ---------------- | ------------- |
| `openai.gpt-oss-20b`            | <Check />        | <Check />     |
| `openai.gpt-oss-120b`           | <Check />        | <Check />     |
| `openai.gpt-oss-safeguard-20b`  | <Check />        | <Cross />     |
| `openai.gpt-oss-safeguard-120b` | <Check />        | <Cross />     |

<Note>
  Bedrock Mantle 提供商使用与 OpenAI 兼容的 API 格式。通过 Mantle 端点可用的模型可能与通过 Bedrock Converse API 可用的模型不同。使用 Mantle 端点的模型列表 API 来发现所有可用的模型。
</Note>

## 迁移到 `@ai-sdk/amazon-bedrock` 2.x

Amazon Bedrock 提供商在 2.x 版本中进行了重写，以移除对 `@aws-sdk/client-bedrock-runtime` 包的依赖。

先前可用的 `bedrockOptions` 提供商设置已被移除。如果您正在使用 `bedrockOptions` 对象，您现在应该直接使用 `region`、`accessKeyId`、`secretAccessKey` 和 `sessionToken` 设置。

静态 IAM 用户密钥不需要 `sessionToken`。
