# Amazon Bedrock 提供商

用于 [AI SDK](/docs) 的 Amazon Bedrock 提供商包含对 [Amazon Bedrock](https://aws.amazon.com/bedrock) API 的语言模型支持。

## 设置

Bedrock 提供商在 `@ai-sdk/amazon-bedrock` 模块中可用。你可以通过以下方式安装：

### 前提条件

默认情况下，访问 Amazon Bedrock 基础模型的权限并非自动授予。为了获得对基础模型的访问权限，具有足够权限的 IAM 用户需要通过控制台请求访问权限。一旦为某个模型授予了访问权限，该账户中的所有用户都可以使用它。

有关更多信息，请参阅 [模型访问文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。

### 身份验证

Amazon Bedrock 提供商支持两种身份验证方法，并具有自动回退机制：API 密钥身份验证（推荐）和使用 IAM 凭证或 AWS SDK 凭证链的 AWS SigV4 身份验证。

#### 使用 API 密钥（推荐）

与 AWS SigV4 身份验证相比，API 密钥身份验证提供了更简单的设置。当提供 API 密钥时，它将优先于任何 SigV4 凭证。

从 [AWS 控制台](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html) 生成一个 bedrock API 密钥，然后将其设置为 `AWS_BEARER_TOKEN_BEDROCK` 环境变量：

```bash
AWS_BEARER_TOKEN_BEDROCK=your-api-key-here
```

或直接将其传递给 `createAmazonBedrock`：

```ts
import { createAmazonBedrock } from '@ai-sdk/amazon-bedrock';

const amazonBedrock = createAmazonBedrock({
  apiKey: 'your-api-key-here',
  region: 'us-east-1',
});
```

当省略 `apiKey` 时，提供商将回退到 `AWS_BEARER_TOKEN_BEDROCK`，如果两者都未设置，则回退到 SigV4 身份验证。

#### 使用 IAM 访问密钥和秘密密钥

**步骤 1：创建 AWS 访问密钥和秘密密钥**

首先，你需要创建一个 AWS 访问密钥和秘密密钥。具体步骤如下：

**登录 AWS 管理控制台**

- 前往 [AWS 管理控制台](https://console.aws.amazon.com/) 并使用你的 AWS 账户凭证登录。

**创建 IAM 用户**

- 导航到 [IAM 仪表板](https://console.aws.amazon.com/iam/home)，然后点击左侧导航菜单中的“用户”。
- 点击“创建用户”并填写所需详细信息以创建新的 IAM 用户。
- 确保选择“编程访问”作为访问类型。
- 用户账户需要附加 `AmazonBedrockFullAccess` 策略。

**创建访问密钥**

- 点击“安全凭证”选项卡，然后点击“创建访问密钥”。
- 点击“创建访问密钥”以生成新的访问密钥对。
- 下载包含访问密钥 ID 和秘密访问密钥的 `.csv` 文件。

**步骤 2：配置访问密钥和秘密密钥**

在你的项目中，如果还没有 `.env` 文件，请添加一个。该文件将用于将访问密钥和秘密密钥设置为环境变量。将以下行添加到 `.env` 文件中：

```makefile
AWS_ACCESS_KEY_ID=YOUR_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY=YOUR_SECRET_ACCESS_KEY
AWS_REGION=YOUR_REGION
```

<Note>
  许多框架（如 [Next.js](https://nextjs.org/)）会自动加载 `.env` 文件。
  如果你使用的是不同的框架，可能需要使用像
  [`dotenv`](https://github.com/motdotla/dotenv) 这样的包手动加载 `.env` 文件。
</Note>

请务必将 `YOUR_ACCESS_KEY_ID`、`YOUR_SECRET_ACCESS_KEY` 和 `YOUR_REGION` 替换为你的 AWS 账户中的实际值。

#### 使用 AWS SDK 凭证链（实例配置文件、实例角色、ECS 角色、EKS 服务账户等）

使用 AWS SDK 时，SDK 将自动使用凭证链来确定要使用的凭证。这包括实例配置文件、实例角色、ECS 角色、EKS 服务账户等。使用 AI SDK 可以实现类似的行为，方法是不在提供商设置中指定 `accessKeyId` 和 `secretAccessKey`、`sessionToken` 属性，而是传递一个 `credentialProvider` 属性。

_用法：_

`@aws-sdk/credential-providers` 包提供了一组凭证提供程序，可用于创建凭证提供程序链。

## 提供商实例

你可以从 `@ai-sdk/amazon-bedrock` 导入默认的提供商实例 `amazonBedrock`：

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
```

如果你需要自定义设置，可以从 `@ai-sdk/amazon-bedrock` 导入 `createAmazonBedrock` 并使用你的设置创建提供商实例：

```ts
import { createAmazonBedrock } from '@ai-sdk/amazon-bedrock';

const amazonBedrock = createAmazonBedrock({
  region: 'us-east-1',
  accessKeyId: 'xxxxxxxxx',
  secretAccessKey: 'xxxxxxxxx',
  sessionToken: 'xxxxxxxxx',
});
```

<Note>
  省略的选项将使用下面的环境变量。当 **同时** 将 `accessKeyId` 和 `secretAccessKey` 设置为字符串时，SigV4 仅在你传递 `sessionToken` 时才使用它 - 而不是环境中的 `AWS_SESSION_TOKEN` - 因此静态密钥不会与工作负载令牌（例如 EKS IRSA）混合。
</Note>

你可以使用以下可选设置来自定义 Amazon Bedrock 提供商实例：

- **region** _string_

  你希望用于 API 调用的 AWS 区域。
  默认使用 `AWS_REGION` 环境变量。

- **accessKeyId** _string_

  你希望用于 API 调用的 AWS 访问密钥 ID。
  默认使用 `AWS_ACCESS_KEY_ID` 环境变量。

- **secretAccessKey** _string_

  你希望用于 API 调用的 AWS 秘密访问密钥。
  默认使用 `AWS_SECRET_ACCESS_KEY` 环境变量。

- **sessionToken** _string_

  可选。用于临时凭证。当 **同时** 将两个访问密钥设置为字符串时，如果需要，在此处传递令牌；环境中的 `AWS_SESSION_TOKEN` 不会被使用。如果任一密钥取自环境，则省略 `sessionToken` 将允许使用 `AWS_SESSION_TOKEN`。

- **credentialProvider** _() =&gt; Promise&lt;&#123; accessKeyId: string; secretAccessKey: string; sessionToken?: string; &#125;&gt;_

  可选。你希望用于 API 调用的 AWS 凭证提供程序链。
  默认使用指定的凭证。

- **apiKey** _string_

  可选。用于使用 Bearer 令牌身份验证进行请求身份验证的 API 密钥。
  提供时，将使用此密钥代替 AWS SigV4 身份验证。
  默认使用 `AWS_BEARER_TOKEN_BEDROCK` 环境变量。

- **baseURL** _string_

  可选。Bedrock API 调用的基础 URL。
  用于自定义端点或代理配置。

- **headers** _Record&lt;string, string&gt;_

  可选。要包含在请求中的自定义标头。

- **fetch** _(input: RequestInfo, init?: RequestInit) =&gt; Promise&lt;Response&gt;_

  可选。自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。
  你可以将其用作拦截请求的中间件，
  或为测试等提供自定义 fetch 实现。

## 语言模型

你可以使用提供商实例创建调用 Bedrock API 的模型。
第一个参数是模型 ID，例如 `meta.llama3-70b-instruct-v1:0`。

```ts
const model = amazonBedrock('meta.llama3-70b-instruct-v1:0');
```

Amazon Bedrock 模型还支持一些不属于 [标准调用设置](/docs/ai-sdk-core/settings) 的特定于模型的提供商选项。
你可以在 `providerOptions` 参数中传递它们：

```ts
const model = amazonBedrock('anthropic.claude-3-sonnet-20240229-v1:0');

await generateText({
  model,
  providerOptions: {
    anthropic: {
      additionalModelRequestFields: { top_k: 350 },
    },
  },
});
```

有关基于所选模型的其他设置的文档，可以在 [Amazon Bedrock 推理参数文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters.html) 中找到。

你可以使用 Amazon Bedrock 语言模型通过 `generateText` 函数生成文本：

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

const { text } = await generateText({
  model: amazonBedrock('meta.llama3-70b-instruct-v1:0'),
  prompt: '为 4 个人写一份素食千层面食谱。',
});
```

Amazon Bedrock 语言模型也可以在 `streamText` 函数中使用
（请参阅 [AI SDK Core](/docs/ai-sdk-core)）。

### 文件输入

<Note type="warning">
  Amazon Bedrock 支持与特定模型结合的文件输入，例如
  `anthropic.claude-3-haiku-20240307-v1:0`。
</Note>

Amazon Bedrock 提供商支持文件输入，例如 PDF 文件。

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

const result = await generateText({
  model: amazonBedrock('anthropic.claude-3-haiku-20240307-v1:0'),
  messages: [
    {
      role: 'user',
      content: [
        { type: 'text', text: '详细描述这个 PDF。' },
        {
          type: 'file',
          data: readFileSync('./data/ai.pdf'),
          mediaType: 'application/pdf',
        },
      ],
    },
  ],
});
```

### 护栏

你可以使用 `bedrock` 提供商选项来利用 [Amazon Bedrock 护栏](https://aws.amazon.com/bedrock/guardrails/)：

```ts
import { type AmazonBedrockLanguageModelChatOptions } from '@ai-sdk/amazon-bedrock';

const result = await generateText({
  model: amazonBedrock('anthropic.claude-3-sonnet-20240229-v1:0'),
  prompt: '写一个关于太空探索的故事。',
  providerOptions: {
    bedrock: {
      guardrailConfig: {
        guardrailIdentifier: '1abcd2ef34gh',
        guardrailVersion: '1',
        trace: 'enabled' as const,
        streamProcessingMode: 'async',
      },
    } satisfies AmazonBedrockLanguageModelChatOptions,
  },
});
```

如果你启用了追踪，追踪信息将在提供商元数据中返回。

```ts
if (result.providerMetadata?.bedrock.trace) {
  // ...
}
```

有关更多信息，请参阅 [Amazon Bedrock 护栏文档](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)。

### 引用

Amazon Bedrock 支持跨兼容模型的基于文档输入的引用。启用后：

- 某些模型可以通过视觉理解来读取文档，而不仅仅是提取文本
- 模型可以引用你提供的文档的特定部分，从而更容易将信息追溯回其来源（尚不支持）

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { generateText, Output } from 'ai';
import { z } from 'zod';
import fs from 'fs';

const result = await generateText({
  model: amazonBedrock('apac.anthropic.claude-sonnet-4-20250514-v1:0'),
  output: Output.object({
    schema: z.object({
      summary: z.string().describe('PDF 文档的摘要'),
      keyPoints: z.array(z.string()).describe('PDF 中的关键点'),
    }),
  }),
  messages: [
    {
      role: 'user',
      content: [
        {
          type: 'text',
          text: '总结这个 PDF 并提供关键点。',
        },
        {
          type: 'file',
          data: readFileSync('./document.pdf'),
          mediaType: 'application/pdf',
          providerOptions: {
            bedrock: {
              citations: { enabled: true },
            },
          },
        },
      ],
    },
  ],
});

console.log('响应:', result.output);
```

### 缓存点

<Note>
  Amazon Bedrock 提示词缓存目前处于预览发布阶段。要请求
  访问，请访问 [Amazon Bedrock 提示词缓存
  页面](https://aws.amazon.com/bedrock/prompt-caching/)。
</Note>

在消息中，你可以使用 `providerOptions` 属性来设置缓存点。将 `providerOptions` 对象中的 `bedrock` 属性设置为 `{ cachePoint: { type: 'default' } }` 以创建缓存点。

你还可以使用 `ttl` 属性为缓存点指定 TTL（生存时间）。支持的值是 `'5m'`（5 分钟，默认）和 `'1h'`（1 小时）。1 小时 TTL 仅由 Claude Opus 4.5、Claude Haiku 4.5 和 Claude Sonnet 4.5 支持。

```ts
providerOptions: {
  bedrock: { cachePoint: { type: 'default', ttl: '1h' } },
}
```

<Note>
  当使用具有不同 TTL 的多个缓存点时，具有较长 TTL 的缓存条目必须出现在较短 TTL 之前（即，1 小时缓存条目必须出现在 5 分钟缓存条目之前）。
</Note>

缓存使用信息在 `providerMetadata` 对象中返回。请参见下面的示例。

<Note>
  缓存点具有特定于模型的令牌最小值和限制。例如，
  Claude 3.5 Sonnet v2 需要至少 1,024 个令牌才能设置缓存点，并且
  最多允许 4 个缓存点。有关支持的模型、区域和限制的详细信息，请参阅 [Amazon Bedrock 提示词缓存
  文档](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)。
</Note>

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

const cyberpunkAnalysis =
  '... 关于赛博朋克主题和概念的文学分析 ...';

const result = await generateText({
  model: amazonBedrock('anthropic.claude-3-5-sonnet-20241022-v2:0'),
  messages: [
    {
      role: 'system',
      content: `你是威廉·吉布森赛博朋克文学和主题的专家。你可以访问以下学术分析：${cyberpunkAnalysis}`,
      providerOptions: {
        bedrock: { cachePoint: { type: 'default' } },
      },
    },
    {
      role: 'user',
      content:
        '吉布森在《神经漫游者》中探讨了哪些关键的赛博朋克主题？',
    },
  ],
});

console.log(result.text);
console.log(result.providerMetadata?.bedrock?.usage);
// 显示缓存读/写令牌使用情况，例如：
// {
//   cacheReadInputTokens: 1337,
//   cacheWriteInputTokens: 42,
// }
```

缓存点也适用于流式响应：

```ts
import { amazonBedrock } from '@ai-sdk/amazon-bedrock';
import { streamText } from 'ai';

const cyberpunkAnalysis =
  '... 关于赛博朋克主题和概念的文学分析 ...';

const result = streamText({
  model: amazonBedrock('anthropic.claude-3-5-sonnet-20241022-v2:0'),
  messages: [
    {
      role: 'assistant',
      content: [
        { type: 'text', text: '你是赛博朋克文学的专家。' },
        { type: 'text', text: `学术分析：${cyberpunkAnalysis}` },
      ],
      providerOptions: { bedrock: { cachePoint: { type: 'default' } } },
    },
    {
      role: 'user',
      content:
        '吉布森如何探讨人类与技术之间的关系？',
    },
  ],
});

for await (const textPart of result.textStream) {
  process.stdout.write(textPart);
}

console.log(
  '缓存令牌使用情况：',
  (await result.providerMetadata)?.bedrock?.usage,
);
// 显示缓存读/写令牌使用情况，例如：
// {
//   cacheReadInputTokens: 1337,
//   cacheWriteInputTokens: 42,
// }
```

### 提供商元数据

以下 Bedrock 特定的元数据可能会在 `providerMetadata.bedrock` 中返回：

- **trace** _(可选)_
  护栏追踪信息（当追踪启用时）。
- **performanceConfig** _(可选)_
  性能配置，例如 `{ latency: 'optimized' }`。
- **serviceTier** _(可选)_
  服务层级信息，例如 `{ type: 'on-demand' }`。
- **usage** _(可选)_
  缓存令牌使用详情，包括 `cacheWriteInputTokens` 和 `cacheDetails`。
- **stopSequence** _string | null_
  触发停止的停止序列（如果有）。

## 推理

Amazon Bedrock 支持特定于模型创建者的推理功能：

- Anthropic（例如 `claude-sonnet-4-5-20250929`）：通过 `reasoningConfig` 提供商选项启用，并指定思考预算（以令牌为单位）（最小值：`1024`，最大值：`64000`）。
- Amazon（例如 `us.amazon.nova-2-lite-v1:0`）：通过 `reasoningConfig` 提供商选项启用，并指定最大推理努力级别（`'low' | 'medium' | 'high'`）。

```ts
import {
  amazonBedrock,
  type AmazonBedrockLanguageModelChatOptions,
} from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

// Anthropic 示例
const anthropicResult = await generateText({
  model: amazonBedrock('us.anthropic.claude-sonnet-4-5-20250929-v1:0'),
  prompt: '2040 年世界上将有多少人居住？',
  providerOptions: {
    bedrock: {
      reasoningConfig: { type: 'enabled', budgetTokens: 1024 },
    } satisfies AmazonBedrockLanguageModelChatOptions,
  },
});

console.log(anthropicResult.reasoningText); // 推理文本
console.log(anthropicResult.text); // 文本响应

// Nova 2 示例
const amazonResult = await generateText({
  model: amazonBedrock('us.amazon.nova-2-lite-v1:0'),
  prompt: '2040 年世界上将有多少人居住？',
  providerOptions: {
    bedrock: {
      reasoningConfig: { type: 'enabled', maxReasoningEffort: 'medium' },
    } satisfies AmazonBedrockLanguageModelChatOptions,
  },
});

console.log(amazonResult.reasoningText); // 推理文本
console.log(amazonResult.text); // 文本响应
```

有关如何将推理集成到聊天机器人中的更多详细信息，请参阅 [AI SDK UI：聊天机器人](/docs/ai-sdk-ui/chatbot#reasoning)。

## 服务层级

Amazon Bedrock 支持通过 `serviceTier` 提供商选项为每个请求选择推理服务层级。

```ts
import {
  amazonBedrock,
  type AmazonBedrockLanguageModelChatOptions,
} from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

const result = await generateText({
  model: amazonBedrock('us.anthropic.claude-sonnet-4-20250514-v1:0'),
  prompt: '总结这个支持工单积压。',
  providerOptions: {
    bedrock: {
      serviceTier: 'priority',
    } satisfies AmazonBedrockLanguageModelChatOptions,
  },
});
```

支持的值有：

- `reserved`
- `priority`
- `default`
- `flex`

有关模型可用性和行为，请参阅 [Amazon Bedrock 服务层级文档](https://docs.aws.amazon.com/bedrock/latest/userguide/service-tiers-inference.html)。

## 扩展上下文窗口

Amazon Bedrock 上的 Claude Sonnet 4 模型在使用 `context-1m-2025-08-07` beta 功能时，支持最多 100 万个令牌的扩展上下文窗口。

```ts
import {
  amazonBedrock,
  type AmazonBedrockLanguageModelChatOptions,
} from '@ai-sdk/amazon-bedrock';
import { generateText } from 'ai';

const result = await generateText({
  model: amazonBedrock('us.anthropic.claude-sonnet-4-20250514-v1:0'),
  prompt: '分析这个大型文档...',
  providerOptions: {
    bedrock: {
      anthropicBeta: ['context-1m-2025-08-07'],
    } satisfies AmazonBedrockLanguageModelChatOptions,
  },
});
```

## 计算机使用

通过 Anthropic，Amazon Bedrock 提供了三个提供商定义的工具，可用于与外部系统交互：

1. **Bash 工具**：允许运行 bash 命令。
2. **文本编辑器工具**：提供查看和编辑文本文件的功能。
3. **计算机工具**：支持控制计算机上的键盘和鼠标操作。

它们可以通过提供商实例的 `tools` 属性获得。

<Note>
  Amazon Bedrock 不支持工具定义的严格模式。在工具上设置 `strict: true` 将被忽略，并会发出警告。
</Note>

### Bash 工具

Bash 工具允许运行 bash 命令。以下是创建和使用它的方法：

```ts
const bashTool = amazonBedrock.tools.bash_20241022({
  execute: async ({ command, restart }) => {
```

```ts
const textEditorTool = amazonBedrock.tools.textEditor_20241022({

    file_text,
    insert_line,
```

参数：

- `command` ('view' | 'create' | 'str_replace' | 'insert' | 'undo_edit')：要运行的命令。注意：`undo_edit` 仅在 Claude 3.5 Sonnet 及更早模型中可用。
- `path` (string)：文件或目录的绝对路径，例如 `/repo/file.py` 或 `/repo`。

### 计算机工具

计算机工具支持控制计算机上的键盘和鼠标操作：

```ts
const computerTool = amazonBedrock.tools.computer_20241022({
  displayWidthPx: 1920,
  displayHeightPx: 1080,
  displayNumber: 0, // 可选，适用于 X11 环境

  execute: async ({ action, coordinate, text }) => {
    // 在此处实现你的计算机控制逻辑
    // 返回操作的结果

    // 示例代码：
    switch (action) {
      case 'screenshot': {
        // 多部分结果：
        return {
          type: 'image',
          data: fs
            .readFileSync('./data/screenshot-editor.png')
            .toString('base64'),
        };
      }
      default: {
        console.log('操作:', action);
        console.log('坐标:', coordinate);
        console.log('文本:', text);
        return `已执行 ${action}`;
      }
    }
  },

  // 映射到工具结果内容以供 LLM 消费：
  toModelOutput({ output }) {
    return typeof output === 'string'
      ? [{ type: 'text', text: output }]
      : [{ type: 'file-data', data: output.data, mediaType: 'image/png' }];
  },
});
```

参数：

- `action` ('key' | 'type' | 'mouse_move' | 'left_click' | 'left_click_drag' | 'right_click' | 'middle_click' | 'double_click' | 'screenshot' | 'cursor_position')：要执行的操作。
- `coordinate` (number[], 可选)：`mouse_move` 和 `left_click_drag` 操作必需。指定 (x, y) 坐标。
- `text` (string, 可选)：`type` 和 `key` 操作必需。

这些工具可以与 `anthropic.claude-3-5-sonnet-20240620-v1:0` 模型结合使用，以实现更复杂的交互和任务。
