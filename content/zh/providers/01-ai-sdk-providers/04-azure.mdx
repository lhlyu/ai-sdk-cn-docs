# Azure OpenAI 提供商

[Azure OpenAI](https://azure.microsoft.com/zh-cn/products/ai-services/openai-service) 提供商为 Azure OpenAI 聊天 API 提供语言模型支持。

## 安装

Azure OpenAI 提供商位于 `@ai-sdk/azure` 模块中。你可以通过以下方式安装：

## 提供商实例

你可以从 `@ai-sdk/azure` 导入默认的提供商实例 `azure`：

```ts
import { azure } from '@ai-sdk/azure';
```

如果你需要自定义设置，可以从 `@ai-sdk/azure` 导入 `createAzure` 并使用你的设置创建提供商实例：

```ts
import { createAzure } from '@ai-sdk/azure';

const azure = createAzure({
  resourceName: 'your-resource-name', // Azure 资源名称
  apiKey: 'your-api-key',
});
```

对于 Microsoft Entra ID 认证，你可以提供一个令牌提供者。
如果你想使用其凭据辅助程序，请单独安装 `@azure/identity`：

```ts
import { createAzure } from '@ai-sdk/azure';
import {
  DefaultAzureCredential,
  getBearerTokenProvider,
} from '@azure/identity';

const credential = new DefaultAzureCredential();
const scope = 'https://cognitiveservices.azure.com/.default';
const tokenProvider = getBearerTokenProvider(credential, scope);

const azure = createAzure({
  resourceName: 'your-resource-name',
  tokenProvider,
});
```

你可以使用以下可选设置来自定义 OpenAI 提供商实例：

- **resourceName** _string_

  Azure 资源名称。
  默认为 `AZURE_RESOURCE_NAME` 环境变量。

  资源名称用于组装 URL：`https://{resourceName}.openai.azure.com/openai/v1{path}`。
  你可以使用 `baseURL` 来指定 URL 前缀。

- **apiKey** _string_

  通过 `api-key` 标头发送的 API 密钥。
  默认为 `AZURE_API_KEY` 环境变量。

- **tokenProvider** _() => Promise&lt;string&gt;_

  Microsoft Entra ID 令牌提供者，返回一个通过 `Authorization` 标头发送的访问令牌。
  提供时，将使用此令牌而不是 `apiKey`。

- **apiVersion** _string_

  设置自定义 [API 版本](https://learn.microsoft.com/zh-cn/azure/ai-services/openai/api-version-deprecation)。
  默认为 `v1`。

- **baseURL** _string_

  为 API 调用使用不同的 URL 前缀，例如使用代理服务器。

  可以设置此选项或 `resourceName`。
  当提供 baseURL 时，resourceName 将被忽略。

  使用 baseURL 时，解析后的 URL 为 `{baseURL}/v1{path}`。

- **headers** _Record&lt;string,string&gt;_

  要包含在请求中的自定义标头。

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/zh-CN/docs/Web/API/fetch) 实现。
  默认为全局 `fetch` 函数。
  你可以将其用作拦截请求的中间件，
  或为测试等场景提供自定义 fetch 实现。

- **useDeploymentBasedUrls** _boolean_

  对 API 调用使用基于部署的 URL。设置为 `true` 以使用旧版部署格式：
  `{baseURL}/deployments/{deploymentId}{path}?api-version={apiVersion}` 而不是
  `{baseURL}/v1{path}?api-version={apiVersion}`。
  默认为 `false`。

  此选项对于需要旧版端点格式的某些 Azure OpenAI 模型或部署的兼容性很有用。

## 语言模型

Azure OpenAI 提供商实例是一个函数，你可以调用它来创建语言模型：

```ts
const model = azure('your-deployment-name');
```

你需要将部署名称作为第一个参数传递。

### 推理模型

Azure 在生成的文本中使用 `<think>` 标签暴露 `DeepSeek-R1` 的思考过程。
你可以使用 `extractReasoningMiddleware` 来提取此推理过程，并将其作为结果的 `reasoning` 属性暴露：

```ts
import { azure } from '@ai-sdk/azure';
import { wrapLanguageModel, extractReasoningMiddleware } from 'ai';

const enhancedModel = wrapLanguageModel({
  model: azure('your-deepseek-r1-deployment-name'),
  middleware: extractReasoningMiddleware({ tagName: 'think' }),
});
```

然后，你可以在 `generateText` 和 `streamText` 等函数中使用该增强模型。

<Note>
  Azure 提供商默认调用 Responses API（除非你指定了例如
  `azure.chat`）。
</Note>

### 示例

你可以使用 OpenAI 语言模型通过 `generateText` 函数生成文本：

```ts
import { azure } from '@ai-sdk/azure';
import { generateText } from 'ai';

const { text } = await generateText({
  model: azure('your-deployment-name'),
  prompt: '写一份供 4 人食用的素食千层面食谱。',
});
```

OpenAI 语言模型也可以在 `streamText` 函数中使用，
并支持通过 [`Output`](/docs/reference/ai-sdk-core/output) 生成结构化数据
（参见 [AI SDK Core](/docs/ai-sdk-core)）。

<Note>
  Azure OpenAI 发送的数据块比 OpenAI 更大。这可能导致感觉
  响应速度较慢。请参阅 [故障排除：Azure OpenAI 流式传输缓慢](/docs/troubleshooting/common-issues/azure-stream-slow)
</Note>

### 提供商选项

在 Azure 上使用 OpenAI 语言模型时，你可以使用 `providerOptions.openai` 配置提供商特定的选项。更多可用配置选项的信息，请参见 [OpenAI 提供商页面](/providers/ai-sdk-providers/openai#language-models)。

```ts highlight="12-14,24-26"
import { azure, type OpenAILanguageModelResponsesOptions } from '@ai-sdk/azure';

const messages = [
  {
    role: 'user',
    content: [
      {
        type: 'text',
        text: '月球的首都是什么？',
      },
      {
        type: 'file',
        mediaType: 'image',
        data: 'https://example.com/image.png',
        providerOptions: {
          openai: { imageDetail: 'low' },
        },
      },
    ],
  },
];

const { text } = await generateText({
  model: azure('your-deployment-name'),
  providerOptions: {
    openai: {
      reasoningEffort: 'low',
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

### 聊天模型

<Note>
  调用 Azure 聊天模型的 URL 将按如下方式构建：
  `https://RESOURCE_NAME.openai.azure.com/openai/v1/chat/completions?api-version=v1`
</Note>

你可以使用 `.chat()` 工厂方法创建调用 Azure OpenAI 聊天补全 API 的模型：

```ts
const model = azure.chat('your-deployment-name');
```

Azure OpenAI 聊天模型还支持一些不属于[标准调用设置](/docs/ai-sdk-core/settings)的模型特定设置。
你可以将它们作为选项参数传递：

```ts
import { azure, type OpenAILanguageModelChatOptions } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure.chat('your-deployment-name'),
  prompt: '写一个关于机器人的短篇故事。',
  providerOptions: {
    openai: {
      logitBias: {
        // 特定令牌的可选可能性
        '50256': -100,
      },
      user: 'test-user', // 可选的唯一用户标识符
    } satisfies OpenAILanguageModelChatOptions,
  },
});
```

OpenAI 聊天模型提供以下可选的提供商选项：

- **logitBias** _Record&lt;number, number&gt;_

  修改指定令牌出现在补全中的可能性。

  接受一个 JSON 对象，该对象将令牌（由 GPT 分词器中的令牌 ID 指定）
  映射到 -100 到 100 之间的相关偏置值。你可以
  使用此分词器工具将文本转换为令牌 ID。从数学上讲，
  偏置值在采样前被添加到模型生成的 logits 中。
  具体效果因模型而异，但 -1 到 1 之间的值应
  降低或增加选择的可能性；像 -100 或 100 这样的值
  应导致禁止或独占选择相关令牌。

  例如，你可以传递 `{"50256": -100}` 来阻止生成该令牌。

- **logprobs** _boolean | number_

  返回令牌的对数概率。包含 logprobs 会增加
  响应大小并可能减慢响应时间。但是，它
  有助于更好地理解模型的行为。

  设置为 true 将返回已生成令牌的对数概率。

  设置为数字将返回已生成的前 n 个
  令牌的对数概率。

- **parallelToolCalls** _boolean_

  是否在工具使用期间启用并行函数调用。默认为 true。

- **user** _string_

  代表最终用户的唯一标识符，可以帮助 OpenAI
  监控和检测滥用。了解更多。

### DeepSeek 聊天模型

你可以使用 `.deepseek()` 工厂方法创建 Azure 托管的 DeepSeek 聊天模型：

```ts
const model = azure.deepseek('your-deepseek-deployment-name');
```

对支持 DeepSeek 聊天推理字段（例如 `deepseek-v4-pro` 和 `deepseek-v4-flash`）的 Azure DeepSeek 模型使用此工厂方法。该工厂将顶层的 `reasoning` 映射到 DeepSeek 的 `reasoning_effort` 请求设置，并将流式传输的 `reasoning_content` 解析为 AI SDK 推理部分。

```ts
import { azure, type AzureDeepSeekLanguageModelOptions } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = generateText({
  model: azure.deepseek('your-deepseek-deployment-name'),
  prompt: '单词 "strawberry" 中有多少个 "r"？',
  reasoning: 'high',
});
```

### 响应模型

Azure OpenAI 默认使用 `azure(deploymentName)` 工厂方法作为响应 API。

```ts
const model = azure('your-deployment-name');
```

可以使用 OpenAI 提供商选项进行进一步配置。
你可以使用 `OpenAILanguageModelResponsesOptions` 类型验证提供商选项。

<Note>
  在 Responses API 中，在 `providerOptions` 中使用 `azure` 作为提供商名称
  而不是 `openai`。`openai` 键仍然支持作为 `providerOptions`
  输入。
</Note>

```ts
import { azure, OpenAILanguageModelResponsesOptions } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('your-deployment-name'),
  providerOptions: {
    azure: {
      parallelToolCalls: false,
      store: false,
      user: 'user_123',
      // ...
    } satisfies OpenAILanguageModelResponsesOptions,
  },
  // ...
});
```

以下提供商选项可用：

- **parallelToolCalls** _boolean_
  是否使用并行工具调用。默认为 `true`。

- **store** _boolean_
  是否存储生成结果。默认为 `true`。

- **metadata** _Record&lt;string, string&gt;_
  与生成结果一起存储的附加元数据。

- **previousResponseId** _string_
  上一个响应的 ID。你可以使用它来继续对话。默认为 `undefined`。

- **instructions** _string_
  模型的指令。
  当使用 `previousResponseId` 选项继续对话时，它们可用于更改系统或开发者消息。
  默认为 `undefined`。

- **user** _string_
  代表最终用户的唯一标识符，可以帮助 OpenAI 监控和检测滥用。默认为 `undefined`。

- **reasoningEffort** _'low' | 'medium' | 'high'_
  推理模型的推理努力程度。默认为 `medium`。如果你使用 `providerOptions` 设置 `reasoningEffort` 选项，此模型设置将被忽略。

- **strictJsonSchema** _boolean_
  是否使用严格的 JSON Schema 验证。默认为 `false`。

Azure OpenAI 提供商还返回提供商特定的元数据：

对于响应模型（`azure(deploymentName)`），你可以使用 `AzureResponsesProviderMetadata` 类型化此元数据：

```ts
import { azure, type AzureResponsesProviderMetadata } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('your-deployment-name'),
});

const providerMetadata = result.providerMetadata as
  | AzureResponsesProviderMetadata
  | undefined;

const { responseId, logprobs, serviceTier } = providerMetadata?.azure ?? {};

// responseId 可用于继续对话（previousResponseId）。
console.log(responseId);
```

可能返回以下 Azure 特定的元数据：

- **responseId** _string | null | undefined_
  响应的 ID。可用于继续对话。
- **logprobs** _(可选)_
  输出令牌的对数概率（启用时）。
- **serviceTier** _(可选)_
  API 返回的服务层级信息。

<Note>
  providerMetadata 仅在默认的 responses API 中返回，并且
  在使用 'azure.chat' 或 'azure.completion' 时不支持。
</Note>

#### 网络搜索工具

Azure OpenAI responses API 通过 `azure.tools.webSearch` 工具支持网络搜索。

```ts
const result = await generateText({
  model: azure('gpt-5'),
  prompt: '上周旧金山发生了什么？',
  tools: {
    web_search: azure.tools.webSearch({
      // 可选配置：
      searchContextSize: 'high',
      userLocation: {
        type: 'approximate',
        city: 'San Francisco',
        region: 'California',
      },
      filters: {
        allowedDomains: ['sfchronicle.com', 'sfgate.com'],
      },
    }),
  },
  // 强制使用网络搜索工具（可选）：
  toolChoice: { type: 'tool', toolName: 'web_search' },
});

// 直接从 `results` 获取 URL 来源
const sources = result.sources;

// 或者从工具结果中访问来源
for (const toolResult of result.toolResults) {
  if (toolResult.toolName === 'web_search') {
    console.log('查询:', toolResult.output.action.query);
    console.log('来源:', toolResult.output.sources);
    // `sources` 是一个对象数组：{ type: 'url', url: string }
  }
}
```

网络搜索工具支持以下配置选项：

- **externalWebAccess** _boolean_ - 是否使用外部网络访问来获取实时内容。默认为 `true`。
- **searchContextSize** _'low' | 'medium' | 'high'_ - 控制用于搜索的上下文量。较高的值提供更全面的结果，但可能具有更高的延迟和成本。
- **userLocation** - 可选的用户位置信息，用于提供地理相关的结果。包括 `type`（始终为 `'approximate'`）、`country`、`city`、`region` 和 `timezone`。
- **filters** - 可选的过滤器配置，用于限制搜索结果。
  - **allowedDomains** _string[]_ - 允许搜索的域名数组。提供的域名的子域名会自动包含在内。

有关配置选项的详细信息，请参阅 [Azure OpenAI 网络搜索工具文档](https://learn.microsoft.com/zh-cn/azure/foundry/openai/how-to/web-search)。

<Note>
  在 Microsoft Foundry 环境中，不支持实时互联网访问。如果传递了
  `externalWebAccess` 参数，它将被忽略。
</Note>

#### 文件搜索工具

Azure OpenAI 提供商通过 `azure.tools.fileSearch` 工具支持文件搜索。

你可以通过将 `toolChoice` 参数设置为 `{ type: 'tool', toolName: 'file_search' }` 来强制使用文件搜索工具。

```ts
const result = await generateText({
  model: azure('gpt-5'),
  prompt: '文档中关于用户身份验证说了什么？',
  tools: {
    file_search: azure.tools.fileSearch({
      // 可选配置：
      vectorStoreIds: ['vs_123', 'vs_456'],
      maxNumResults: 10,
      ranking: {
        ranker: 'auto',
      },
    }),
  },
  // 强制使用文件搜索工具：
  toolChoice: { type: 'tool', toolName: 'file_search' },
});
```

<Note>
  使用 Azure OpenAI 的文件搜索功能时，工具必须命名为 `file_search`。此名称是 Azure OpenAI API 规范所要求的，无法自定义。
</Note>

<Note>
  'file_search' 工具仅在默认的 responses API 中支持，并且
  在使用 'azure.chat' 或 'azure.completion' 时不支持。
</Note>

#### 图像生成工具

Azure OpenAI 的 Responses API 支持多模态图像生成作为提供商定义的工具。
可用性仅限于特定模型（例如 `gpt-5` 变体）。

```ts
import { createAzure } from '@ai-sdk/azure';
import { generateText } from 'ai';

const azure = createAzure({
  headers: {
    'x-ms-oai-image-generation-deployment': 'gpt-image-2', // 使用你自己的图像模型部署
  },
});

const result = await generateText({
  model: azure('gpt-5'),
  prompt:
    '生成一张针鼹在莫桑比克海峡游泳的图片。',
  tools: {
    image_generation: azure.tools.imageGeneration({ outputFormat: 'png' }),
  },
});

for (const toolResult of result.staticToolResults) {
  if (toolResult.toolName === 'image_generation') {
    const base64Image = toolResult.output.result;
  }
}
```

<Note>
  使用 Azure OpenAI 的图像生成功能时，工具必须命名为 `image_generation`。此名称是 Azure OpenAI API 规范所要求的，无法自定义。
</Note>

<Note>
  'image_generation' 工具仅在默认的 responses API 中支持，
  并且在使用 'azure.chat' 或 'azure.completion' 时不支持。
</Note>

<Note>
  要使用 image_generation，你必须首先创建一个图像生成模型。你
  必须在标头 `x-ms-oai-image-generation-deployment` 中添加部署规范。请注意，Responses API
  模型和图像生成模型必须在同一资源中。
</Note>

<Note>
  当你设置 `store: false` 时，先前生成的图像将无法被
  模型访问。我们建议使用图像生成工具时不要设置 `store: false`。
</Note>

#### 代码解释器工具

Azure OpenAI 提供商通过 `azure.tools.codeInterpreter` 工具支持代码解释器。这允许模型编写和执行 Python 代码。

```ts
import { azure } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('gpt-5'),
  prompt: '编写并运行 Python 代码来计算 10 的阶乘',
  tools: {
    code_interpreter: azure.tools.codeInterpreter({
      // 可选配置：
      container: {
        fileIds: ['assistant-123', 'assistant-456'], // 可用的可选文件 ID
      },
    }),
  },
});
```

代码解释器工具可以配置为：

- **container**：可以是容器 ID 字符串，也可以是包含 `fileIds` 的对象，用于指定应提供给代码解释器的上传文件。

<Note>
  使用 Azure OpenAI 的代码解释器功能时，工具必须命名为 `code_interpreter`。此名称是 Azure OpenAI API 规范所要求的，无法自定义。
</Note>

<Note>
  'code_interpreter' 工具仅在默认的 responses API 中支持，
  并且在使用 'azure.chat' 或 'azure.completion' 时不支持。
</Note>

<Note>
  当处理由代码解释器生成的文件时，可以从 [文本部分中的注释](#typed-providermetadata-in-text-parts) 和 [源文档部分中的 `providerMetadata`](#typed-providermetadata-in-source-document-parts) 获取参考信息。
</Note>

#### PDF 支持

Azure OpenAI 提供商支持读取 PDF 文件。
你可以使用 `file` 类型将 PDF 文件作为消息内容的一部分传递：

```ts
const result = await generateText({
  model: azure('your-deployment-name'),
  messages: [
    {
      role: 'user',
      content: [
        {
          type: 'text',
          text: '什么是嵌入模型？',
        },
        {
          type: 'file',
          data: fs.readFileSync('./data/ai.pdf'),
          mediaType: 'application/pdf',
          filename: 'ai.pdf', // 可选
        },
      ],
    },
  ],
});
```

模型将能够访问 PDF 文件的内容并回答相关问题。
PDF 文件应使用 `data` 字段传递，
并且 `mediaType` 应设置为 `'application/pdf'`。

<Note>
  读取 PDF 文件仅在默认的 responses API 中支持，并且
  在使用 'azure.chat' 或 'azure.completion' 时不支持。
</Note>

#### 文本部分中的类型化 providerMetadata

使用 Azure OpenAI Responses API 时，SDK 会通过 `providerMetadata` 将 Azure OpenAI 特定的元数据附加到输出部分。

此元数据可以在客户端用于诸如渲染引用或下载由代码解释器生成的文件等任务。
为了启用此元数据的类型安全处理，AI SDK 导出了专用的 TypeScript 类型。

对于文本部分，当 `part.type === 'text'` 时，`providerMetadata` 以 `AzureResponsesTextProviderMetadata` 的形式提供。

此元数据包括以下字段：

- `itemId`  
  Responses API 中输出项的 ID。
- `annotations`（可选）
  模型生成的注释对象数组。
  如果没有注释，此属性本身可能被省略（`undefined`）。

  `annotations` 中的每个元素都是一个带标签的联合类型，具有必需的 `type` 字段。支持的类型包括，例如：
  - `url_citation`
  - `file_citation`
  - `container_file_citation`
  - `file_path`

  这些注释直接对应于 Responses API 定义的注释对象，可用于内联引用渲染或输出分析。
  有关详细信息，请参阅官方 OpenAI 文档：
  [Responses API – 输出文本注释](https://platform.openai.com/docs/api-reference/responses/object?lang=javascript#responses-object-output-output_message-content-output_text-annotations)。

```ts
import { azure, type AzureResponsesTextProviderMetadata } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('gpt-4.1-mini'),
  prompt:
    '创建一个程序，生成五个介于 1 到 100 之间、保留两位小数的随机数，并向我展示执行结果。同时将结果保存到一个文件中。',
  tools: {
    code_interpreter: azure.tools.codeInterpreter(),
    web_search_preview: azure.tools.webSearchPreview({}),
    file_search: azure.tools.fileSearch({ vectorStoreIds: ['vs_1234'] }), // 需要配置向量存储
  },
});

for (const part of result.content) {
  if (part.type === 'text') {
    const providerMetadata = part.providerMetadata as
      | AzureResponsesTextProviderMetadata
      | undefined;
    if (!providerMetadata) continue;
    const { itemId: _itemId, annotations } = providerMetadata.azure;

    if (!annotations) continue;
    for (const annotation of annotations) {
      switch (annotation.type) {
        case 'url_citation':
          // url_citation 由 web_search 返回，提供：
          // 属性：type, url, title, start_index 和 end_index
          break;
        case 'file_citation':
          // file_citation 由 file_search 返回，提供：
          // 属性：type, file_id, filename 和 index
          break;
        case 'container_file_citation':
          // container_file_citation 由 code_interpreter 返回，提供：
          // 属性：type, container_id, file_id, filename, start_index 和 end_index
          break;
        case 'file_path':
          // file_path 提供：
          // 属性：type, file_id 和 index
          break;
        default: {
          const _exhaustiveCheck: never = annotation;
          throw new Error(
            `未处理的注释：${JSON.stringify(_exhaustiveCheck)}`,
          );
        }
      }
    }
  }
}
```

<Note>
  当实现由代码解释器生成的文件的下载时，`providerMetadata` 中可用的 `container_id` 和 `file_id` 可用于检索文件内容。有关详细信息，请参阅 [检索容器文件内容](https://platform.openai.com/docs/api-reference/container-files/retrieveContainerFileContent) API。
</Note>

#### 推理部分中的类型化 providerMetadata

使用 Azure OpenAI Responses API 时，推理输出部分可以包含提供商元数据。
为了以类型安全的方式处理此元数据，请使用 `AzureResponsesReasoningProviderMetadata`。

对于推理部分，当 `part.type === 'reasoning'` 时，`providerMetadata` 以 `AzureResponsesReasoningProviderMetadata` 的形式提供。

此元数据包括以下字段：

- `itemId`  
  Responses API 中推理项的 ID。
- `reasoningEncryptedContent`（可选）  
  加密的推理内容（仅当通过 `include: ['reasoning.encrypted_content']` 请求时返回）。

```ts
import {
  azure,
  type AzureResponsesReasoningProviderMetadata,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('your-deployment-name'),
  prompt: '单词 "strawberry" 中有多少个 "r"？',
  providerOptions: {
    azure: {
      store: false,
      include: ['reasoning.encrypted_content'],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});

for (const part of result.content) {
  if (part.type === 'reasoning') {
    const providerMetadata = part.providerMetadata as
      | AzureResponsesReasoningProviderMetadata
      | undefined;

    const { itemId, reasoningEncryptedContent } = providerMetadata?.azure ?? {};
    console.log(itemId, reasoningEncryptedContent);
  }
}
```

#### 源文档部分中的类型化 providerMetadata

对于源文档部分，当 `part.type === 'source'` 且 `sourceType === 'document'` 时，`providerMetadata` 以 `AzureResponsesSourceDocumentProviderMetadata` 的形式提供。

此元数据也是一个带标签的联合类型，具有必需的 `type` 字段。支持的类型包括：

- `file_citation`
- `container_file_citation`
- `file_path`

每种类型都包含处理引用资源所需的标识符，例如 `fileId` 和 `containerId`。

```ts
import {
  azure,
  type AzureResponsesSourceDocumentProviderMetadata,
} from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('gpt-4.1-mini'),
  prompt:
    '创建一个程序，生成五个介于 1 到 100 之间、保留两位小数的随机数，并向我展示执行结果。同时将结果保存到一个文件中。',
  tools: {
    code_interpreter: azure.tools.codeInterpreter(),
    web_search_preview: azure.tools.webSearchPreview({}),
    file_search: azure.tools.fileSearch({ vectorStoreIds: ['vs_1234'] }), // 需要配置向量存储
  },
});

for (const part of result.content) {
  if (part.type === 'source') {
    if (part.sourceType === 'document') {
      const providerMetadata = part.providerMetadata as
        | AzureResponsesSourceDocumentProviderMetadata
        | undefined;
      if (!providerMetadata) continue;
      const annotation = providerMetadata.azure;
      switch (annotation.type) {
        case 'file_citation':
          // file_citation 由 file_search 返回，提供：
          // 属性：type, fileId 和 index
          // 文件名可以通过 part.filename 访问。
          break;
        case 'container_file_citation':
          // container_file_citation 由 code_interpreter 返回，提供：
          // 属性：type, containerId 和 fileId
          // 文件名可以通过 part.filename 访问。
          break;
        case 'file_path':
          // file_path 提供：
          // 属性：type, fileId 和 index
          break;
        default: {
          const _exhaustiveCheck: never = annotation;
          throw new Error(
            `未处理的注释：${JSON.stringify(_exhaustiveCheck)}`,
          );
        }
      }
    }
  }
}
```

<Note>
  文本部分中的注释遵循 OpenAI Responses API 规范，因此使用蛇形命名法属性（例如 `file_id`、`container_id`）。相比之下，源文档部分的 `providerMetadata` 由 SDK 规范化为驼峰命名法（例如 `fileId`、`containerId`）。依赖于原始文本内容的字段，例如 `start_index` 和 `end_index`，将被省略，像 `filename` 这样直接在源对象上可用的字段也会被省略。
</Note>

### 补全模型

你可以使用 `.completion()` 工厂方法创建调用补全 API 的模型。
第一个参数是模型 ID。
目前仅支持 `gpt-35-turbo-instruct`。

```ts
const model = azure.completion('your-gpt-35-turbo-instruct-deployment');
```

OpenAI 补全模型还支持一些不属于[标准调用设置](/docs/ai-sdk-core/settings)的模型特定设置。
你可以将它们作为选项参数传递：

```ts
import {
  azure,
  type OpenAILanguageModelCompletionOptions,
} from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure.completion('your-gpt-35-turbo-instruct-deployment'),
  prompt: '写一首关于编程的俳句。',
  providerOptions: {
    openai: {
      echo: true, // 可选，在补全之外回显提示词
      logitBias: {
        // 特定令牌的可选可能性
        '50256': -100,
      },
      suffix: '一些文本', // 可选，在插入文本的补全之后出现的后缀
      user: 'test-user', // 可选的唯一用户标识符
    } satisfies OpenAILanguageModelCompletionOptions,
  },
});
```

Azure OpenAI 补全模型提供以下可选的提供商选项：

- **echo**: _boolean_

  在补全之外回显提示词。

- **logitBias** _Record&lt;number, number&gt;_

  修改指定令牌出现在补全中的可能性。

  接受一个 JSON 对象，该对象将令牌（由 GPT 分词器中的令牌 ID 指定）
  映射到 -100 到 100 之间的相关偏置值。你可以
  使用此分词器工具将文本转换为令牌 ID。从数学上讲，
  偏置值在采样前被添加到模型生成的 logits 中。
  具体效果因模型而异，但 -1 到 1 之间的值应
  降低或增加选择的可能性；像 -100 或 100 这样的值
  应导致禁止或独占选择相关令牌。

  例如，你可以传递 `{"50256": -100}` 来阻止生成 &lt;|endoftext|&gt; 令牌。

- **logprobs** _boolean | number_

  返回令牌的对数概率。包含 logprobs 会增加
  响应大小并可能减慢响应时间。但是，它
  有助于更好地理解模型的行为。

  设置为 true 将返回已生成令牌的对数概率。

  设置为数字将返回已生成的前 n 个
  令牌的对数概率。

- **suffix** _string_

  在插入文本的补全之后出现的后缀。

- **user** _string_

  代表最终用户的唯一标识符，可以帮助 OpenAI
  监控和检测滥用。了解更多。

## 嵌入模型

const model = azure.embedding('your-embedding-deployment');

Azure OpenAI 嵌入模型支持多个附加设置。

```ts
import { azure, type OpenAIEmbeddingModelOptions } from '@ai-sdk/azure';
import { embed } from 'ai';

const { embedding } = await embed({

});
```

Azure OpenAI 嵌入模型提供以下可选的提供商选项：

- **dimensions**: _number_

  生成的输出嵌入应具有的维度数。
  仅在 text-embedding-3 及更高版本模型中支持。

- **user** _string_

  代表最终用户的唯一标识符，可以帮助 OpenAI
  监控和检测滥用。了解更多。

## 图像模型

你可以使用 `.image()` 工厂方法创建调用 Azure OpenAI 图像生成 API（DALL-E）的模型。第一个参数是 DALL-E 模型的部署名称。

```ts
const model = azure.image('your-dalle-deployment-name');
```

Azure OpenAI 图像模型支持多个附加设置。你可以在生成图像时将它们作为 `providerOptions.openai` 传递：

```ts
import { azure } from '@ai-sdk/azure';
import type { OpenAIImageModelGenerationOptions } from '@ai-sdk/openai';
import { generateImage } from 'ai';

await generateImage({
  model: azure.image('your-dalle-deployment-name'),
  prompt: '一张猫宇航员漂浮在太空中的逼真图像',
  size: '1024x1024', // DALL-E 3 支持 '1024x1024'、'1792x1024' 或 '1024x1792'
  providerOptions: {
    openai: {
      user: 'test-user', // 可选的唯一用户标识符
    } satisfies OpenAIImageModelGenerationOptions,
  },
});
```

### 示例

你可以使用 Azure OpenAI 图像模型通过 `generateImage` 函数生成图像：

```ts
import { azure } from '@ai-sdk/azure';
import { generateImage } from 'ai';

const { image } = await generateImage({
  model: azure.image('your-dalle-deployment-name'),
  prompt: '一张猫宇航员漂浮在太空中的逼真图像',
  size: '1024x1024', // DALL-E 3 支持 '1024x1024'、'1792x1024' 或 '1024x1792'
});

// image 包含生成图像的 URL 或 base64 数据
console.log(image);
```

### 模型能力

Azure OpenAI 通过部署支持 DALL-E 2 和 DALL-E 3 模型。能力取决于你的部署使用的模型版本：

| 模型版本 | 尺寸                           |
| --------- | ------------------------------- |
| DALL-E 3  | 1024x1024, 1792x1024, 1024x1792 |
| DALL-E 2  | 256x256, 512x512, 1024x1024     |

<Note>
  DALL-E 模型不支持 `aspectRatio` 参数。请改用 `size` 参数。
</Note>

<Note>
  创建 Azure OpenAI 部署时，请确保设置要使用的 DALL-E 模型版本。
</Note>
