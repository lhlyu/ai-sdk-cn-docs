# Azure OpenAI 提供商

[Azure OpenAI](https://azure.microsoft.com/en-us/products/ai-services/openai-service) 提供商包含对 Azure OpenAI 聊天 API 的语言模型支持。

## 设置

Azure OpenAI 提供商位于 `@ai-sdk/azure` 模块中。你可以使用以下命令安装它

<InstallPackages packages="@ai-sdk/azure" />

## 提供商实例

你可以从 `@ai-sdk/azure` 导入默认提供商实例 `azure`：

```ts
import { azure } from '@ai-sdk/azure';
```

如果你需要自定义设置，可以从 `@ai-sdk/azure` 导入 `createAzure`，并使用你的设置创建提供商实例：

```ts
import { createAzure } from '@ai-sdk/azure';

const azure = createAzure({
  resourceName: 'your-resource-name', // Azure resource name
  apiKey: 'your-api-key',
});
```

你也可以使用完整的 [Microsoft Foundry OpenAI v1 基础 URL](https://learn.microsoft.com/en-us/azure/foundry/openai/api-version-lifecycle#model-support)：

```ts
const azure = createAzure({
  baseURL: 'https://your-resource.services.ai.azure.com/openai/v1',
  apiKey: 'your-api-key',
});
```

对于 Microsoft Entra ID 身份验证，你可以提供令牌提供程序。
如果你想使用其凭据辅助工具，请单独安装 `@azure/identity`：

```ts
import { createAzure } from '@ai-sdk/azure';
import {
  DefaultAzureCredential,
  getBearerTokenProvider,
} from '@azure/identity';

const credential = new DefaultAzureCredential();
const scope = 'https://cognitiveservices.azure.com/.default';
const tokenProvider = getBearerTokenProvider(credential, scope);

const azure = createAzure({
  resourceName: 'your-resource-name',
  tokenProvider,
});
```

你可以使用以下可选设置来自定义 OpenAI 提供商实例：

- **resourceName** _string_

  Azure 资源名称。
  默认为 `AZURE_RESOURCE_NAME` 环境变量。

  资源名称用于组装 URL：`https://{resourceName}.openai.azure.com/openai/v1{path}`。
  它必须是单个 DNS 标签（字母、数字和连字符）。
  你可以改用 `baseURL` 来指定 URL 前缀。

- **apiKey** _string_

  使用 `api-key` 标头发送的 API 密钥。
  默认为 `AZURE_API_KEY` 环境变量。

- **tokenProvider** _() => Promise&lt;string&gt;_

  Microsoft Entra ID 令牌提供程序，返回使用 `Authorization` 标头发送的访问令牌。
  提供后，将使用它代替 `apiKey`。

- **apiVersion** _string_

  设置自定义 [API 版本](https://learn.microsoft.com/en-us/azure/ai-services/openai/api-version-deprecation)。
  默认为 `v1`。
  当提供商构造 v1 路径或使用基于部署的 URL 时，会应用此设置。完整的 v1 基础 URL 按原样使用。

- **baseURL** _string_

  为 API 调用使用不同的 URL 前缀，例如使用代理服务器。

  可以使用此项或 `resourceName`。
  提供 baseURL 时，resourceName 将被忽略。

  对于以 `.openai.azure.com`、`.services.ai.azure.com` 或 `.cognitiveservices.azure.com` 结尾的 Azure 托管 URL，你可以传入未版本化的 OpenAI 前缀（如 `https://your-resource.services.ai.azure.com/openai`）或完整的 v1 基础 URL（如 `https://your-resource.services.ai.azure.com/openai/v1`）。
  提供商会向未版本化的资源 URL 追加 `/v1` 和配置的 `api-version`。完整的 v1 URL 按原样使用。

  完整的 Microsoft Foundry 项目 v1 URL，例如
  `https://your-resource.services.ai.azure.com/api/projects/your-project/openai/v1`，
  也按原样使用。如果 Foundry 项目 URL 中省略了 `/v1`，提供商会追加它，但不添加 `api-version` 查询参数。

  对于非 Azure 自定义网关 baseURL，解析后的 URL 为 `{baseURL}{path}`；
  在此模式下，SDK 不会追加 `/v1` 或 `api-version` 查询参数。

- **headers** _Record&lt;string,string&gt;_

  要包含在请求中的自定义标头。

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。
  默认为全局 `fetch` 函数。
  你可以将其用作中间件来拦截请求，
  或为例如测试提供自定义 fetch 实现。

- **useDeploymentBasedUrls** _boolean_

  为 API 调用使用基于部署的 URL。设置为 `true` 以使用旧版部署格式：
  `{baseURL}/deployments/{deploymentId}{path}?api-version={apiVersion}`，而不是
  `{baseURL}/v1{path}?api-version={apiVersion}`。
  默认为 `false`。

  此选项对于与某些需要旧版端点格式的 Azure OpenAI 模型或部署兼容很有用。

- **speechBaseURL** _string_

  Azure Speech 请求（MAI-Transcribe 转录和 MAI-Voice 语音生成）的 URL 前缀，例如区域端点 `https://eastus.api.cognitive.microsoft.com`。
  默认为 `https://{resourceName}.cognitiveservices.azure.com`。
  Speech 请求不使用 `baseURL` 或 `apiVersion`。

- **maiBaseURL** _string_

  MAI 请求（MAI-Image 和 MAI-Transcribe-2-Streaming）的 URL 前缀。
  默认为 `https://{resourceName}.services.ai.azure.com/mai/v1`。

- **webSocket** _WebSocketConstructor_

  用于 MAI 流式转录的自定义 WebSocket 实现，例如 Node.js 中 `ws` 包的 `WebSocket` 导出。使用自定义实现时，API 密钥在 `api-key` 标头中发送；使用原生 `WebSocket` 时，它作为 `api-key` 查询参数发送。Microsoft Entra ID（`tokenProvider`）身份验证需要自定义实现；没有它，流式传输会在连接前失败并抛出 `InvalidArgumentError`。

## 语言模型

Azure OpenAI 提供商实例是一个函数，你可以调用它来创建语言模型：

```ts
const model = azure('your-deployment-name');
```

你需要将部署名称作为第一个参数传入。

### 推理模型

Azure 使用 `<think>` 标签在生成的文本中暴露 `DeepSeek-R1` 的思考过程。
你可以使用 `extractReasoningMiddleware` 提取此推理，并将其作为结果上的 `reasoning` 属性暴露：

```ts
import { azure } from '@ai-sdk/azure';
import { wrapLanguageModel, extractReasoningMiddleware } from 'ai';

const enhancedModel = wrapLanguageModel({
  model: azure('your-deepseek-r1-deployment-name'),
  middleware: extractReasoningMiddleware({ tagName: 'think' }),
});
```

然后你可以在 `generateText` 和 `streamText` 等函数中使用该增强模型。

<Note>
  Azure 提供商默认调用 Responses API（除非你指定例如
  `azure.chat`）。
</Note>

### 示例

你可以使用 OpenAI 语言模型通过 `generateText` 函数生成文本：

```ts
import { azure } from '@ai-sdk/azure';
import { generateText } from 'ai';

const { text } = await generateText({
  model: azure('your-deployment-name'),
  prompt: 'Write a vegetarian lasagna recipe for 4 people.',
});
```

OpenAI 语言模型也可用于 `streamText` 函数，
并支持使用 [`Output`](/docs/reference/ai-sdk-core/output) 生成结构化数据
（参见 [AI SDK Core](/docs/ai-sdk-core)）。

<Note>
  Azure OpenAI 发送的块比 OpenAI 更大。这可能导致响应较慢的感觉。参见[故障排除：Azure OpenAI 流式传输缓慢](/docs/troubleshooting/common-issues/azure-stream-slow)
</Note>

### 提供商选项

在 Azure 上使用 OpenAI 语言模型时，你可以使用 `providerOptions.openai` 配置提供商特定的选项。有关可用配置选项的更多信息，请参见 [OpenAI 提供商页面](/providers/ai-sdk-providers/openai#language-models)。

```ts highlight="12-14,24-26"
import { azure, type OpenAILanguageModelResponsesOptions } from '@ai-sdk/azure';

const messages = [
  {
    role: 'user',
    content: [
      {
        type: 'text',
        text: 'What is the capital of the moon?',
      },
      {
        type: 'file',
        mediaType: 'image',
        data: 'https://example.com/image.png',
        providerOptions: {
          openai: { imageDetail: 'low' },
        },
      },
    ],
  },
];

const { text } = await generateText({
  model: azure('your-deployment-name'),
  providerOptions: {
    openai: {
      reasoningEffort: 'low',
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});
```

### 聊天模型

<Note>
  调用 Azure 聊天模型的 URL 将按如下方式构造：
  `https://RESOURCE_NAME.openai.azure.com/openai/v1/chat/completions?api-version=v1`
</Note>

你可以使用 `.chat()` 工厂方法创建调用 Azure OpenAI 聊天补全 API 的模型：

```ts
const model = azure.chat('your-deployment-name');
```

Azure OpenAI 聊天模型还支持一些不属于[标准调用设置](/docs/ai-sdk-core/settings)的模型特定设置。
你可以将它们作为选项参数传入：

```ts
import { azure, type OpenAILanguageModelChatOptions } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure.chat('your-deployment-name'),
  prompt: 'Write a short story about a robot.',
  providerOptions: {
    openai: {
      logitBias: {
        // optional likelihood for specific tokens
        '50256': -100,
      },
      user: 'test-user', // optional unique user identifier
    } satisfies OpenAILanguageModelChatOptions,
  },
});
```

以下可选提供商选项可用于 OpenAI 聊天模型：

- **logitBias** _Record&lt;number, number&gt;_

  修改指定 token 出现在补全中的可能性。

  接受一个 JSON 对象，将 token（由其在 GPT 分词器中的 token ID 指定）映射到 -100 到 100 之间的关联偏置值。你可以使用此分词器工具将文本转换为 token ID。在数学上，偏置会在采样前添加到模型生成的 logits 中。
  确切效果因模型而异，但 -1 到 1 之间的值应该会降低或增加被选中的可能性；像 -100 或 100 这样的值应该会导致相关 token 被禁止或独占选择。

  例如，你可以传入 `{"50256": -100}` 来阻止生成该 token。

- **logprobs** _boolean | number_

  返回 token 的对数概率。包含 logprobs 会增加响应大小，并可能减慢响应时间。但是，它有助于更好地理解模型的行为。

  设置为 true 将返回所生成 token 的对数概率。

  设置为数字将返回所生成的前 n 个 token 的对数概率。

- **parallelToolCalls** _boolean_

  是否在工具使用期间启用并行函数调用。默认为 true。

- **user** _string_

  表示最终用户的唯一标识符，可以帮助 OpenAI 监控和检测滥用。了解更多。

### DeepSeek 聊天模型

你可以使用 `.deepseek()` 工厂方法创建 Azure 托管的 DeepSeek 聊天模型：

```ts
const model = azure.deepseek('your-deepseek-deployment-name');
```

对于支持 DeepSeek 聊天推理字段的 Azure DeepSeek 模型（如 `deepseek-v4-pro` 和 `deepseek-v4-flash`），请使用此工厂。该工厂将顶层 `reasoning` 映射到 DeepSeek `reasoning_effort` 请求设置，并将流式 `reasoning_content` 解析为 AI SDK 推理部分。

```ts
import { azure, type AzureDeepSeekLanguageModelOptions } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = generateText({
  model: azure.deepseek('your-deepseek-deployment-name'),
  prompt: 'How many "r"s are in the word "strawberry"?',
  reasoning: 'high',
});
```

### Responses 模型

Azure OpenAI 使用 `azure(deploymentName)` 工厂方法默认使用 responses API。

```ts
const model = azure('your-deployment-name');
```

可以使用 OpenAI 提供商选项进行进一步配置。
你可以使用 `OpenAILanguageModelResponsesOptions` 类型验证提供商选项。

<Note>
  在 Responses API 中，请在 `providerOptions` 中使用 `azure` 作为提供商名称，
  而不是 `openai`。`openai` 键仍支持用于 `providerOptions`
  输入。
</Note>

```ts
import { azure, OpenAILanguageModelResponsesOptions } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('your-deployment-name'),
  providerOptions: {
    azure: {
      parallelToolCalls: false,
      store: false,
      user: 'user_123',
      // ...
    } satisfies OpenAILanguageModelResponsesOptions,
  },
  // ...
});
```

以下提供商选项可用：

- **parallelToolCalls** _boolean_
  是否使用并行工具调用。默认为 `true`。

- **store** _boolean_
  是否存储生成内容。默认为 `true`。

- **metadata** _Record&lt;string, string&gt;_
  随生成内容存储的附加元数据。

- **previousResponseId** _string_
  上一个响应的 ID。你可以使用它继续对话。默认为 `undefined`。

- **instructions** _string_
  模型的指令。
  当使用 `previousResponseId` 选项继续对话时，它们可用于更改系统或开发者消息。
  默认为 `undefined`。

- **user** _string_
  表示最终用户的唯一标识符，可以帮助 OpenAI 监控和检测滥用。默认为 `undefined`。

- **reasoningEffort** _'low' | 'medium' | 'high'_
  推理模型的推理强度。默认为 `medium`。如果你使用 `providerOptions` 设置 `reasoningEffort` 选项，此模型设置将被忽略。

- **strictJsonSchema** _boolean_
  是否使用严格的 JSON schema 验证。默认为 `false`。

Azure OpenAI 提供商还返回提供商特定的元数据：

对于 Responses 模型（`azure(deploymentName)`），你可以使用 `AzureResponsesProviderMetadata` 为此元数据指定类型：

```ts
import { azure, type AzureResponsesProviderMetadata } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('your-deployment-name'),
});

const providerMetadata = result.providerMetadata as
  | AzureResponsesProviderMetadata
  | undefined;

const { responseId, logprobs, serviceTier } = providerMetadata?.azure ?? {};

// responseId can be used to continue a conversation (previousResponseId).
console.log(responseId);
```

可能返回以下 Azure 特定的元数据：

- **responseId** _string | null | undefined_
  响应的 ID。可用于继续对话。
- **logprobs** _（可选）_
  输出 token 的对数概率（启用时）。
- **serviceTier** _（可选）_
  API 返回的服务层级信息。

<Note>
  providerMetadata 仅在默认 responses API 下返回，在使用 'azure.chat' 或 'azure.completion' 时不支持
</Note>

#### 在对话中途更改推理强度

Azure Responses 模型支持通过
`providerOptions.azure.reasoningEffortUpdate` 进行消息级推理强度更新。当消息没有 `azure` 选项时，也接受 `openai` 命名空间。使用从 `@ai-sdk/azure` 导出的
`OpenAIResponsesSystemMessageOptions` 类型来验证这些选项：

```ts
import { azure, type OpenAIResponsesSystemMessageOptions } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  // Use the name of your GPT-6 deployment.
  model: azure.responses('gpt-6-astra'),
  reasoning: 'low',
  allowSystemInMessages: true,
  messages: [
    {
      role: 'system',
      content: '',
      providerOptions: {
        azure: {
          reasoningEffortUpdate: 'high',
        } satisfies OpenAIResponsesSystemMessageOptions,
      },
    },
    { role: 'user', content: 'Analyze the failure modes of this migration.' },
  ],
});
```

在整个对话过程中保持请求级 `reasoning` 不变，并在重新发送消息历史时保留先前的强度更新。这些更新也适用于 `streamText`。有关延续、压缩和配置限制，请参见 [OpenAI 推理强度指南](/providers/ai-sdk-providers/openai#changing-reasoning-effort-mid-conversation)。

<Note>
  SDK 从传递给 `azure.responses()` 的部署名称推断对强度更新的支持。该名称必须标识受支持的 GPT-6 或更高版本模型系列，例如 `gpt-6-astra`。像 `production` 这样的自定义名称不会被识别，即使底层部署运行的是 GPT-6。在这种情况下，消息级更新会抛出错误，请求级更新会被省略并发出警告。设置 `forceReasoning: true` 不会覆盖此能力检查。
</Note>

#### Web 搜索工具

Azure OpenAI responses API 通过 `azure.tools.webSearch` 工具支持 Web 搜索。

```ts
const result = await generateText({
  model: azure('gpt-5'),
  prompt: 'What happened in San Francisco last week?',
  tools: {
    web_search: azure.tools.webSearch({
      // optional configuration:
      searchContextSize: 'high',
      userLocation: {
        type: 'approximate',
        city: 'San Francisco',
        region: 'California',
      },
      filters: {
        allowedDomains: ['sfchronicle.com', 'sfgate.com'],
        blockedDomains: ['example.com'],
      },
    }),
  },
  // Force web search tool (optional):
  toolChoice: { type: 'tool', toolName: 'web_search' },
});

// URL sources directly from `results`
const sources = result.sources;

// Or access sources from tool results
for (const toolResult of result.toolResults) {
  if (toolResult.toolName === 'web_search') {
    console.log('Query:', toolResult.output.action.query);
    console.log('Sources:', toolResult.output.sources);
    // `sources` is an array of object: { type: 'url', url: string }
  }
}
```

Web 搜索工具支持以下配置选项：

- **externalWebAccess** _boolean_ - 是否使用外部 Web 访问来获取实时内容。默认为 `true`。
- **searchContextSize** _'low' | 'medium' | 'high'_ - 控制用于搜索的上下文量。较高的值提供更全面的结果，但可能具有更高的延迟和成本。
- **userLocation** - 可选的位置信息，用于提供地理相关的结果。包括 `type`（始终为 `'approximate'`）、`country`、`city`、`region` 和 `timezone`。
- **filters** - 可选的过滤器配置，用于限制搜索结果。
  - **allowedDomains** _string[]_ - 搜索允许的最多 100 个域。
  - **blockedDomains** _string[]_ - 搜索阻止的最多 100 个域。

从域过滤器中省略 HTTP 或 HTTPS 前缀。配置域的子域会自动包含或排除。

有关配置选项的详细信息，请参见 [Azure OpenAI Web 搜索工具文档](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/web-search)。

<Note>
  在 Microsoft Foundry 环境中，不支持实时互联网访问。如果传入 `externalWebAccess` 参数，它将被忽略。
</Note>

#### 文件搜索工具

Azure OpenAI 提供商通过 `azure.tools.fileSearch` 工具支持文件搜索。

你可以通过将 `toolChoice` 参数设置为 `{ type: 'tool', toolName: 'file_search' }` 来强制使用文件搜索工具。

```ts
const result = await generateText({
  model: azure('gpt-5'),
  prompt: 'What does the document say about user authentication?',
  tools: {
    file_search: azure.tools.fileSearch({
      // optional configuration:
      vectorStoreIds: ['vs_123', 'vs_456'],
      maxNumResults: 10,
      ranking: {
        ranker: 'auto',
      },
    }),
  },
  // Force file search tool:
  toolChoice: { type: 'tool', toolName: 'file_search' },
});
```

<Note>
  使用 Azure OpenAI 的文件搜索功能时，工具必须命名为 `file_search`。此名称是 Azure OpenAI 的 API 规范所要求的，无法自定义。
</Note>

<Note>
  'file_search' 工具仅在默认 responses API 下受支持，在使用 'azure.chat' 或 'azure.completion' 时不支持
</Note>

#### 图像生成工具

Azure OpenAI 的 Responses API 支持将多模态图像生成作为提供商定义的工具。
可用性仅限于特定模型（例如 `gpt-5` 变体）。

```ts
import { createAzure } from '@ai-sdk/azure';
import { generateText } from 'ai';

const azure = createAzure({
  headers: {
    'x-ms-oai-image-generation-deployment': 'gpt-image-2', // use your own image model deployment
  },
});

const result = await generateText({
  model: azure('gpt-5'),
  prompt:
    'Generate an image of an echidna swimming across the Mozambique channel.',
  tools: {
    image_generation: azure.tools.imageGeneration({ outputFormat: 'png' }),
  },
});

for (const toolResult of result.staticToolResults) {
  if (toolResult.toolName === 'image_generation') {
    const base64Image = toolResult.output.result;
  }
}
```

<Note>
  使用 Azure OpenAI 的图像生成功能时，工具必须命名为 `image_generation`。此名称是 Azure OpenAI 的 API 规范所要求的，无法自定义。
</Note>

<Note>
  'image_generation' 工具仅在默认 responses API 下受支持，在使用 'azure.chat' 或 'azure.completion' 时不支持
</Note>

<Note>
  要使用 image_generation，你必须先创建图像生成模型。你必须在标头 `x-ms-oai-image-generation-deployment` 中添加部署规范。请注意，Responses API 模型和图像生成模型必须位于同一资源中。
</Note>

<Note>
  当你设置 `store: false` 时，之前生成的图像将无法被模型访问。我们建议使用图像生成工具时不要设置 `store: false`。
</Note>

#### 代码解释器工具

Azure OpenAI 提供商通过 `azure.tools.codeInterpreter` 工具支持代码解释器工具。这允许模型编写和执行 Python 代码。

```ts
import { azure } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('gpt-5'),
  prompt: 'Write and run Python code to calculate the factorial of 10',
  tools: {
    code_interpreter: azure.tools.codeInterpreter({
      // optional configuration:
      container: {
        fileIds: ['assistant-123', 'assistant-456'], // optional file IDs to make available
      },
    }),
  },
});
```

代码解释器工具可以配置为：

- **container**：容器 ID 字符串，或带有 `fileIds` 的对象，用于指定应可供代码解释器使用的已上传文件

<Note>
  使用 Azure OpenAI 的代码解释器功能时，工具必须命名为 `code_interpreter`。此名称是 Azure OpenAI 的 API 规范所要求的，无法自定义。
</Note>

<Note>
  'code_interpreter' 工具仅在默认 responses API 下受支持，在使用 'azure.chat' 或 'azure.completion' 时不支持
</Note>

<Note>
  处理由代码解释器生成的文件时，可以从[文本部分中的注释](#typed-providermetadata-in-text-parts)和[源文档部分中的 `providerMetadata`](#typed-providermetadata-in-source-document-parts)获取引用信息。
</Note>

#### 文本部分中的类型化 providerMetadata

使用 Azure OpenAI Responses API 时，SDK 通过 `providerMetadata` 将 Azure OpenAI 特定的元数据附加到输出部分。

此元数据可在客户端用于渲染引用或下载代码解释器生成的文件等任务。
为了实现此元数据的类型安全处理，AI SDK 导出了专用的 TypeScript 类型。

对于文本部分，当 `part.type === 'text'` 时，`providerMetadata` 以 `AzureResponsesTextProviderMetadata` 的形式提供。

此元数据包含以下字段：

- `itemId`  
  Responses API 中输出项的 ID。
- `annotations`（可选）
  模型生成的注释对象数组。
  如果不存在注释，此属性本身可能被省略（`undefined`）。

  `annotations` 中的每个元素都是带有必需 `type` 字段的可辨识联合。支持的 type 包括，例如：
  - `url_citation`
  - `file_citation`
  - `container_file_citation`
  - `file_path`

  这些注释直接对应于 Responses API 定义的注释对象，可用于内联引用渲染或输出分析。
  有关详细信息，请参见 OpenAI 官方文档：
  [Responses API – output text annotations](https://platform.openai.com/docs/api-reference/responses/object?lang=javascript#responses-object-output-output_message-content-output_text-annotations)。

```ts
import { azure, type AzureResponsesTextProviderMetadata } from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('gpt-4.1-mini'),
  prompt:
    'Create a program that generates five random numbers between 1 and 100 with two decimal places, and show me the execution results. Also save the result to a file.',
  tools: {
    code_interpreter: azure.tools.codeInterpreter(),
    web_search_preview: azure.tools.webSearchPreview({}),
    file_search: azure.tools.fileSearch({ vectorStoreIds: ['vs_1234'] }), // requires a configured vector store
  },
});

for (const part of result.content) {
  if (part.type === 'text') {
    const providerMetadata = part.providerMetadata as
      | AzureResponsesTextProviderMetadata
      | undefined;
    if (!providerMetadata) continue;
    const { itemId: _itemId, annotations } = providerMetadata.azure;

    if (!annotations) continue;
    for (const annotation of annotations) {
      switch (annotation.type) {
        case 'url_citation':
          // url_citation is returned from web_search and provides:
          // properties: type, url, title, start_index and end_index
          break;
        case 'file_citation':
          // file_citation is returned from file_search and provides:
          // properties: type, file_id, filename and index
          break;
        case 'container_file_citation':
          // container_file_citation is returned from code_interpreter and provides:
          // properties: type, container_id, file_id, filename, start_index and end_index
          break;
        case 'file_path':
          // file_path provides:
          // properties: type, file_id and index
          break;
        default: {
          const _exhaustiveCheck: never = annotation;
          throw new Error(
            `Unhandled annotation: ${JSON.stringify(_exhaustiveCheck)}`,
          );
        }
      }
    }
  }
}
```

<Note>
  为实现代码解释器生成文件的下载，可以使用 `providerMetadata` 中提供的 `container_id` 和 `file_id` 来检索文件内容。有关详细信息，请参见 [Retrieve container file content](https://platform.openai.com/docs/api-reference/container-files/retrieveContainerFileContent) API。
</Note>

#### 推理部分中的类型化 providerMetadata

使用 Azure OpenAI Responses API 时，推理输出部分可以包含提供商元数据。
要以类型安全的方式处理此元数据，请使用 `AzureResponsesReasoningProviderMetadata`。

对于推理部分，当 `part.type === 'reasoning'` 时，`providerMetadata` 以 `AzureResponsesReasoningProviderMetadata` 的形式提供。

此元数据包含以下字段：

- `itemId`  
  Responses API 中推理项的 ID。
- `reasoningEncryptedContent`（可选）  
  加密的推理内容（仅在通过 `include: ['reasoning.encrypted_content']` 请求时返回）。

```ts
import {
  azure,
  type AzureResponsesReasoningProviderMetadata,
  type OpenAILanguageModelResponsesOptions,
} from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('your-deployment-name'),
  prompt: 'How many "r"s are in the word "strawberry"?',
  providerOptions: {
    azure: {
      store: false,
      include: ['reasoning.encrypted_content'],
    } satisfies OpenAILanguageModelResponsesOptions,
  },
});

for (const part of result.content) {
  if (part.type === 'reasoning') {
    const providerMetadata = part.providerMetadata as
      | AzureResponsesReasoningProviderMetadata
      | undefined;

    const { itemId, reasoningEncryptedContent } = providerMetadata?.azure ?? {};
    console.log(itemId, reasoningEncryptedContent);
  }
}
```

#### 源文档部分中的类型化 providerMetadata

对于源文档部分，当 `part.type === 'source'` 且 `sourceType === 'document'` 时，`providerMetadata` 以 `AzureResponsesSourceDocumentProviderMetadata` 的形式提供。

此元数据也是带有必需 `type` 字段的可辨识联合。支持的 type 包括：

- `file_citation`
- `container_file_citation`
- `file_path`

每种类型都包含处理所引用资源所需的标识符，例如 `fileId` 和 `containerId`。

```ts
import {
  azure,
  type AzureResponsesSourceDocumentProviderMetadata,
} from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure('gpt-4.1-mini'),
  prompt:
    'Create a program that generates five random numbers between 1 and 100 with two decimal places, and show me the execution results. Also save the result to a file.',
  tools: {
    code_interpreter: azure.tools.codeInterpreter(),
    web_search_preview: azure.tools.webSearchPreview({}),
    file_search: azure.tools.fileSearch({ vectorStoreIds: ['vs_1234'] }), // requires a configured vector store
  },
});

for (const part of result.content) {
  if (part.type === 'source') {
    if (part.sourceType === 'document') {
      const providerMetadata = part.providerMetadata as
        | AzureResponsesSourceDocumentProviderMetadata
        | undefined;
      if (!providerMetadata) continue;
      const annotation = providerMetadata.azure;
      switch (annotation.type) {
        case 'file_citation':
          // file_citation is returned from file_search and provides:
          // properties: type, fileId and index
          // The filename can be accessed via part.filename.
          break;
        case 'container_file_citation':
          // container_file_citation is returned from code_interpreter and provides:
          // properties: type, containerId and fileId
          // The filename can be accessed via part.filename.
          break;
        case 'file_path':
          // file_path provides:
          // properties: type, fileId and index
          break;
        default: {
          const _exhaustiveCheck: never = annotation;
          throw new Error(
            `Unhandled annotation: ${JSON.stringify(_exhaustiveCheck)}`,
          );
        }
      }
    }
  }
}
```

<Note>
  文本部分中的注释遵循 OpenAI Responses API 规范，因此使用 snake_case 属性（例如 `file_id`、`container_id`）。相比之下，源文档部分的 `providerMetadata` 由 SDK 规范化为 camelCase（例如 `fileId`、`containerId`）。依赖于原始文本内容的字段（如 `start_index` 和 `end_index`）会被省略，直接可在源对象上使用的字段（如 `filename`）也会被省略。
</Note>

### 补全模型

你可以使用 `.completion()` 工厂方法创建调用补全 API 的模型。
第一个参数是模型 ID。
目前仅支持 `gpt-35-turbo-instruct`。

```ts
const model = azure.completion('your-gpt-35-turbo-instruct-deployment');
```

OpenAI 补全模型还支持一些不属于[标准调用设置](/docs/ai-sdk-core/settings)的模型特定设置。
你可以将它们作为选项参数传入：

```ts
import {
  azure,
  type OpenAILanguageModelCompletionOptions,
} from '@ai-sdk/azure';
import { generateText } from 'ai';

const result = await generateText({
  model: azure.completion('your-gpt-35-turbo-instruct-deployment'),
  prompt: 'Write a haiku about coding.',
  providerOptions: {
    openai: {
      echo: true, // optional, echo the prompt in addition to the completion
      logitBias: {
        // optional likelihood for specific tokens
        '50256': -100,
      },
      suffix: 'some text', // optional suffix that comes after a completion of inserted text
      user: 'test-user', // optional unique user identifier
    } satisfies OpenAILanguageModelCompletionOptions,
  },
});
```

以下可选提供商选项可用于 Azure OpenAI 补全模型：

- **echo**：_boolean_

  在补全之外回显提示词。

- **logitBias** _Record&lt;number, number&gt;_

  修改指定 token 出现在补全中的可能性。

  接受一个 JSON 对象，将 token（由其在 GPT 分词器中的 token ID 指定）映射到 -100 到 100 之间的关联偏置值。你可以使用此分词器工具将文本转换为 token ID。在数学上，偏置会在采样前添加到模型生成的 logits 中。
  确切效果因模型而异，但 -1 到 1 之间的值应该会降低或增加被选中的可能性；像 -100 或 100 这样的值应该会导致相关 token 被禁止或独占选择。

  例如，你可以传入 `{"50256": -100}` 来阻止生成 &lt;|endoftext|&gt; token。

- **logprobs** _boolean | number_

  返回 token 的对数概率。包含 logprobs 会增加响应大小，并可能减慢响应时间。但是，它有助于更好地理解模型的行为。

  设置为 true 将返回所生成 token 的对数概率。

  设置为数字将返回所生成的前 n 个 token 的对数概率。

- **suffix** _string_

  插入文本补全之后的后缀。

- **user** _string_

  表示最终用户的唯一标识符，可以帮助 OpenAI 监控和检测滥用。了解更多。

### 模型能力

</Note>

### MAI-Image

MAI-Image 模型（`MAI-Image-2.6`、`MAI-Image-2.6-Flash`、`MAI-Image-2.5`、`MAI-Image-2.5-Flash`、`MAI-Image-2.5-Pro`）使用位于 `https://{resourceName}.services.ai.azure.com/mai/v1` 的 MAI 图像 API（可通过 `maiBaseURL` 覆盖）。以模型命名的部署会被自动检测，不区分大小写。对于其他部署名称，请将 `providerOptions.azure.api` 设置为 `'mai'`。

```ts
import { azure, type AzureImageModelOptions } from '@ai-sdk/azure';
import { generateImage } from 'ai';

const { image, usage } = await generateImage({
  model: azure.image('MAI-Image-2.6'),
  prompt: 'A watercolor of three flowers on a blue background',
  size: '1536x1024',
  providerOptions: {
    azure: {
      webGrounding: true,
    } satisfies AzureImageModelOptions,
  },
});
```

传入参考图像以编辑或组合它们（最多五张 JPEG 或 PNG 图像）。不支持蒙版。

```ts
const { image } = await generateImage({
  model: azure.image('MAI-Image-2.6-Flash'),
  prompt: {
    text: 'Put the product from the first image into the scene from the second',
    images: [productImage, sceneImage],
  },
});
```

每个请求返回一张 PNG 图像；`generateImage` 为每张图像发送一个请求。
`size` 作为 `width` 和 `height` 发送。每边必须至少为 768 像素，
对于 MAI-Image-2.6 模型，总像素数最多为 2,359,296，对于 MAI-Image-2.5 模型为 1,048,576。如果没有 `size`，`aspectRatio` 会映射到约一百万像素的尺寸；如果两者都没有，模型返回 1024x1024。
不支持 `seed`。Token 使用量在 `usage` 中返回，输入文本和图像 token 的拆分在 `providerMetadata.azure.images` 中。

以下提供商选项可用：

- **api** _'mai' | 'openai'_

  要使用的 API。对于 MAI-Image 模型默认为 `'mai'`，否则为 `'openai'`。

- **autoAspectRatio** _boolean_

  让模型根据提示词和参考图像选择输出宽高比。仅限 MAI-Image-2.6 模型。

- **webGrounding** _boolean_

  将生成基于 Bing Web 搜索结果。仅限 MAI-Image-2.6 模型。

### MAI-Transcribe

MAI-Transcribe 模型是来自 Microsoft AI 的多语言语音转文本模型，通过 Azure 提供服务。
以下模型 ID 使用 Azure Speech API。它们不区分大小写进行匹配，
并以其 Azure 模型名称发送到 Azure：

| 模型 ID              | Azure 模型           | 备注                                 |
| -------------------- | -------------------- | ------------------------------------ |
| `mai-transcribe-2`   | `MAI-Transcribe-2`   | 支持以下所有选项。                   |
| `mai-transcribe-1.5` | `MAI-Transcribe-1.5` | 支持 `locales` 和 `phraseList`。     |

`mai-transcribe-2-streaming` 使用 MAI 实时 API；参见
[MAI-Transcribe-2-Streaming](#mai-transcribe-2-streaming)。所有其他 ID 默认使用
OpenAI API，包括自定义部署名称。

```ts
import { azure, type AzureTranscriptionModelOptions } from '@ai-sdk/azure';
import { transcribe } from 'ai';
import { readFile } from 'fs/promises';

const result = await transcribe({
  model: azure.transcription('mai-transcribe-2'),
  audio: await readFile('audio.wav'),
  providerOptions: {
    azure: {
      timestamps: 'word',
      diarization: { enabled: true },
      transcribeStyle: 'clean',
    } satisfies AzureTranscriptionModelOptions,
  },
});
```

MAI-Transcribe 模型需要位于其可用区域的 Microsoft Foundry (Speech) 资源：
`centralindia`、`eastus`、`northeurope`、`southeastasia`、`westus` 或 `westus2`
（参见 [Speech 服务区域](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/regions?tabs=llmspeech)）。
其他区域的资源会拒绝请求。
将 `AZURE_RESOURCE_NAME` 和 `AZURE_API_KEY` 设置为该资源的名称和密钥，
或将 `resourceName` 和 `apiKey` 传递给 `createAzure`。也支持 `tokenProvider`、自定义标头和自定义 fetch。密钥作为 `Ocp-Apim-Subscription-Key` 发送。

Speech 请求使用 `https://{resourceName}.cognitiveservices.azure.com/speechtotext/transcriptions:transcribe`，API 版本为 `2025-10-15`。使用 `speechBaseURL` 提供不同的 Speech URL 前缀（不带 `/speechtotext/transcriptions:transcribe`），例如区域端点：

```ts
import { createAzure } from '@ai-sdk/azure';

const azure = createAzure({
  speechBaseURL: 'https://eastus.api.cognitive.microsoft.com',
  apiKey: process.env.AZURE_SPEECH_API_KEY,
});
```

Speech 请求不使用 `baseURL`、`apiVersion` 或 `useDeploymentBasedUrls`；
这些设置仅适用于 Azure OpenAI 模型。

以下选项可通过 `providerOptions.azure` 使用：

- **api** _'openai' | 'speech'_
  为此请求覆盖基于模型的 API 选择。
  对于以上述模型 ID 之一命名的 OpenAI 部署，设置为 `openai`；或将另一个模型 ID 发送到 Speech，设置为 `speech`。其他 Speech 模型 ID 原样发送。

- **timestamps** _'word' | 'segment' | 'none'_
  时间粒度。对于 MAI-Transcribe-2，AI SDK 默认为 `segment`，以便结果包含带时间戳的分段（Azure 自身的默认值为 `none`）。`segment` 为每个句子或说话人轮次返回一个分段，`word` 还会在提供商元数据中返回单词时间，`none` 返回跨越整个音频的单个分段。
  MAI-Transcribe-1.5 仅支持 `none`，因此 AI SDK 不会为其发送默认值。

- **transcribeStyle** _'verbatim' | 'clean'_
  `verbatim` 保留填充词和错误开头，`clean` 移除它们。默认为 `verbatim`。
  `clean` 需要 MAI-Transcribe-2。

- **locales** _string[]_
  恰好一个语言代码，例如 `['en']`。这是一个强提示；省略它以进行自动语言检测和代码切换。

- **diarization** _object_
  将 `enabled` 设置为 `true` 以识别说话人。说话人 ID 在提供商元数据中返回。需要 MAI-Transcribe-2。不支持 `maxSpeakers`。

- **phraseList** _object_
  将 `phrases` 设置为名称和领域术语的列表，以将识别偏向它们。

显式 `api` 优先于模型 ID。现有的 OpenAI 转录选项保留在 `providerOptions.openai` 下。仅 Speech 的 Azure 选项与 OpenAI API 一起使用时会发出警告。未知的 `providerOptions.azure` 键（例如 `diarization.maxSpeakers`）会在发送请求前被拒绝。
模型不支持的选项，例如 MAI-Transcribe-1.5 的 `timestamps: 'word'`，会原样发送，Azure 会拒绝请求并返回指明该选项的错误。

结果包括转录文本、带时间戳的分段、时长，以及当报告的短语区域设置标识单一语言时的 ISO-639-1 语言代码。混合语言结果，以及没有 ISO-639-1 代码的语言（如菲律宾语（`fil`）或粤语（`yue`）），会将 `language` 保留为 undefined。说话人 ID、确切区域设置和单词时间保留在 `providerMetadata.azure.phrases` 中；使用导出的 `AzureTranscriptionProviderMetadata` 类型来访问它们。短语时间在元数据中为毫秒，在规范化的 `segments` 中为秒。

MAI-Transcribe 模型是文件转录模型：它们接受短于 2 小时且小于 250 MB 的 WAV、MP3 或 FLAC 文件，不支持流式转录；使用 [MAI-Transcribe-2-Streaming](#mai-transcribe-2-streaming) 进行流式传输。
这些模型处于公开预览阶段。有关支持的语言和说话人分离限制，请参见
[Azure 的 MAI-Transcribe 指南](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/mai-transcribe)。

AI Gateway 会转发这些提供商选项，包括 `azure.api`。

### MAI-Transcribe-2-Streaming

MAI-Transcribe-2-Streaming 是来自 Microsoft AI 的低延迟流式语音转文本模型。
`azure.transcription('mai-transcribe-2-streaming')` 使用
[`experimental_streamTranscribe`](/docs/ai-sdk-core/transcription#streaming-transcription) 将音频流式传输到 MAI 实时 API
（`wss://{resourceName}.services.ai.azure.com/mai/v1/realtime`）。
模型 ID 作为 Foundry 部署名称发送到 Azure，因此请将模型部署为 `mai-transcribe-2-streaming`，或为其他部署名称设置 `api: 'mai'`。

```ts
import {
  createAzure,
  type AzureOpenAIProviderSettings,
  type AzureTranscriptionModelOptions,
} from '@ai-sdk/azure';
import { experimental_streamTranscribe as streamTranscribe } from 'ai';
import { WebSocket } from 'ws';

const azure = createAzure({
  // `ws`'s WebSocket type differs from the DOM-style WebSocketConstructor.
  webSocket: WebSocket as unknown as AzureOpenAIProviderSettings['webSocket'],
});

const result = streamTranscribe({
  model: azure.transcription('mai-transcribe-2-streaming'),
  audio, // ReadableStream of 16-bit mono PCM chunks
  inputAudioFormat: { type: 'audio/pcm', rate: 24000 },
  providerOptions: {
    azure: { language: 'en' } satisfies AzureTranscriptionModelOptions,
  },
});

for await (const part of result.fullStream) {
  if (part.type === 'transcript-delta') {
    process.stdout.write(part.delta);
  }
}
```

该模型需要位于受支持区域（如 `centralus`）的具有 MAI-Transcribe-2-Streaming 部署的 Microsoft Foundry 资源。
输入音频必须是 16000 或 24000 Hz 的 16 位单声道 PCM（`audio/pcm`）；默认为 24000 Hz。

流会为最终文本发出 `transcript-delta` 部分，并为最新 delta 之后的临时文本发出 `transcript-partial` 部分。MAI 不会在服务器端检测停顿，因此流会在输入音频结束时提交一次，然后发出 `transcript-final` 部分和完成的转录。`durationInSeconds` 根据流式音频计算。

以下选项可通过 `providerOptions.azure` 使用：

- **api** _'openai' | 'speech' | 'mai'_
  设置 `mai` 以使用具有不同名称的部署进行流式传输。

- **language** _string_
  语言提示，例如 `en`。省略以进行自动语言检测。

文件转录选项（如 `timestamps`）在流式传输时会产生警告。
MAI-Transcribe-2-Streaming 不支持文件转录。

### OpenAI 转录

<Note>
  如果你在使用转录模型时遇到 "DeploymentNotFound" 错误，
  请尝试启用基于部署的 URL：

```ts
const azure = createAzure({
  useDeploymentBasedUrls: true,
  apiVersion: '2025-04-01-preview',
});
```

这使用旧版端点格式，某些 Azure OpenAI 部署可能需要该格式。
使用 useDeploymentBasedUrls 时，默认 api-version 无效。你必须将其设置为 `2025-04-01-preview` 或更早的值。

</Note>

你还可以使用 `providerOptions` 参数传入额外的提供商特定选项。例如，以 ISO-639-1 格式（例如 `en`）提供输入语言将提高准确性和延迟。

```ts highlight="6"
import { transcribe } from 'ai';
import { azure, type OpenAITranscriptionModelOptions } from '@ai-sdk/azure';
import { readFile } from 'fs/promises';

const result = await transcribe({
  model: azure.transcription('whisper-1'),
  audio: await readFile('audio.mp3'),
  providerOptions: {
    openai: {
      language: 'en',
    } satisfies OpenAITranscriptionModelOptions,
  },
});
```

以下提供商选项可用：

- **timestampGranularities** _string[]_
  转录中时间戳的粒度。
  默认为 `['segment']`。
  可能的值为 `['word']`、`['segment']` 和 `['word', 'segment']`。
  注意：分段时间戳没有额外延迟，但生成单词时间戳会产生额外延迟。

- **language** _string_
  输入音频的语言。以 ISO-639-1 格式（例如 'en'）提供输入语言将提高准确性和延迟。
  可选。

- **prompt** _string_
  用于指导模型风格或延续先前音频片段的可选文本。提示词应与音频语言匹配。
  可选。

- **temperature** _number_
  采样温度，介于 0 和 1 之间。较高的值（如 0.8）会使输出更随机，而较低的值（如 0.2）会使其更集中和确定。如果设置为 0，模型将使用对数概率自动提高温度，直到达到某些阈值。
  默认为 0。
  可选。

- **include** _string[]_
  要包含在转录响应中的附加信息。

## 语音模型

你可以使用 `.speech()` 工厂方法创建调用 Azure OpenAI 语音 API 或 Azure Speech 文本转语音的模型。

第一个参数是文本转语音模型的部署名称（例如 `tts-1`），
或 [MAI-Voice](#mai-voice) 模型 ID。

```ts
const model = azure.speech('your-tts-deployment-name');
```

### 示例

```ts
import { azure } from '@ai-sdk/azure';
import { generateSpeech } from 'ai';

const result = await generateSpeech({
  model: azure.speech('your-tts-deployment-name'),
  text: 'Hello, world!',
  voice: 'alloy', // OpenAI voice ID
});
```

你还可以使用 `providerOptions` 参数传入额外的提供商特定选项：

```ts
import { azure, type OpenAISpeechModelOptions } from '@ai-sdk/azure';
import { generateSpeech } from 'ai';

const result = await generateSpeech({
  model: azure.speech('your-tts-deployment-name'),
  text: 'Hello, world!',
  voice: 'alloy',
  providerOptions: {
    openai: {
      speed: 1.2,
    } satisfies OpenAISpeechModelOptions,
  },
});
```

以下提供商选项可用：

- **instructions** _string_
  使用附加指令控制生成音频的语音，例如 "Speak in a slow and steady tone"。
  不适用于 `tts-1` 或 `tts-1-hd`。
  可选。

- **speed** _number_
  生成音频的速度。
  选择 0.25 到 4.0 之间的值。
  默认为 1.0。
  可选。

### MAI-Voice

MAI-Voice 模型是来自 Microsoft AI 的多语言文本转语音模型，通过 Azure 提供服务。
以下模型 ID 使用 Azure Speech API：

| 模型 ID               | 备注                                         |
| --------------------- | -------------------------------------------- |
| `mai-voice-2.1-flash` | 低延迟，适用于语音智能体和助手。             |
| `mai-voice-2.1`       | 最高保真度，适用于长篇旁白。                 |
| `mai-voice-2-flash`   | 低延迟，适用于语音智能体和助手。             |
| `mai-voice-2`         | 最高保真度，适用于长篇旁白。                 |

所有其他 ID 默认使用 OpenAI API，包括自定义部署名称。

```ts
import { azure, type AzureSpeechModelOptions } from '@ai-sdk/azure';
import { generateSpeech } from 'ai';

const result = await generateSpeech({
  model: azure.speech('mai-voice-2-flash'),
  text: 'Thanks for calling! Your order shipped this morning.',
  voice: 'en-US-Ethan',
  providerOptions: {
    azure: { style: 'excited' } satisfies AzureSpeechModelOptions,
  },
});
```

MAI-Voice 模型需要位于其可用区域的 Microsoft Foundry (Speech) 资源
（参见 [Speech 服务区域](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/regions)）。
它们使用与 [MAI-Transcribe](#mai-transcribe) 相同的设置：`resourceName`（或 `AZURE_RESOURCE_NAME`）、
`apiKey`（或 `AZURE_API_KEY`）、`tokenProvider` 和 `speechBaseURL`。

- **voice** 是包含其区域设置的预构建语音 ID，例如 `en-US-Harper`
  （默认值）、`de-DE-Mia` 或 `es-MX-Valeria`。语音区域设置选择语言。
  也接受完整的 Azure 语音名称，例如 `es-MX-Valeria:MAI-Voice-2`。可用
  语音因模型而异；参见
  [Azure 的 MAI-Voice 指南](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/mai-voices)。
- **language** 在未设置 `voice` 时选择默认语音（参见下表）。其他
  语言和 `auto` 使用 `en-US-Harper` 并发出警告。设置 `voice` 时，其区域设置
  选择语言，冲突的 `language` 会产生警告。
- **outputFormat** 接受 `mp3`（默认，24 kHz）、`wav`、`pcm`（无标头 24 kHz、16 位、单声道）、`opus`（Ogg），
  或任何 Azure `X-Microsoft-OutputFormat` 值，例如 `audio-48khz-192kbitrate-mono-mp3`。
  其他值回退到 `mp3` 并发出警告。Azure 将 `pcm` 等原始格式标记为 `audio/basic`。
- **speed** 是速率乘数，例如 `0.5` 表示半速，`2` 表示双速。
- 不支持 `instructions`，并会产生警告。

| 语言 | 默认语音        | 语言 | 默认语音      |
| ---- | --------------- | ---- | ------------- |
| `de` | `de-DE-Mia`     | `nl` | `nl-NL-Fleur` |
| `en` | `en-US-Harper`  | `pt` | `pt-BR-Luana` |
| `es` | `es-MX-Valeria` | `ro` | `ro-RO-Elena` |
| `fr` | `fr-FR-Soleil`  | `ru` | `ru-RU-Masha` |
| `hi` | `hi-IN-Kavya`   | `th` | `th-TH-Krit`  |
| `hu` | `hu-HU-Lilla`   | `tr` | `tr-TR-Elif`  |
| `it` | `it-IT-Rosa`    | `zh` | `zh-CN-Mei`   |
| `ko` | `ko-KR-Haena`   |      |               |

以下选项可通过 `providerOptions.azure` 使用：

- **api** _'openai' | 'speech'_
  为此请求覆盖基于模型的 API 选择。
  对于以上述模型 ID 之一命名的 OpenAI 部署，设置为 `openai`；或将另一个模型 ID 发送到 Speech，设置为 `speech`。

- **style** _string_
  说话风格，例如 `excited` 或 `whispering`。支持的风格因语音和模型而异。

- **styleDegree** _number_
  风格强度，从 0.01 到 2。Azure 默认为 1。需要 `style`。

文本始终作为纯文本朗读；不支持 SSML 输入。
这些模型处于公开预览阶段。AI Gateway 会转发这些提供商选项，包括 `azure.api`。
