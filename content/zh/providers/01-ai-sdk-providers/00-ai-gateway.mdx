# AI Gateway 提供商

[AI Gateway](https://vercel.com/docs/ai-gateway) 提供商通过单一接口将您连接到多个 AI 提供商的模型。您无需单独集成每个提供商，即可访问 OpenAI、Anthropic、Google、Meta、xAI 等提供商及其模型。

## 特性

- 无需安装额外的提供商模块/依赖项即可访问多个提供商的模型
- 在不同 AI 提供商之间使用相同的代码结构
- 轻松切换模型和提供商
- 在 Vercel 上部署时自动进行身份验证
- 查看各提供商的定价信息
- 通过 Vercel 仪表盘实现对 AI 模型使用情况的可观测性

## 设置

Vercel AI Gateway 提供商是 AI SDK 的一部分。

## 基本用法

对于大多数用例，您可以直接使用模型字符串与 AI Gateway：

```ts
// 使用全局提供商的纯模型字符串
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'openai/gpt-5.4',
  prompt: 'Hello world',
});
```

```ts
// 使用提供商实例（需要 5.0.36 或更高版本）
import { generateText, gateway } from 'ai';

const { text } = await generateText({
  model: gateway('openai/gpt-5.4'),
  prompt: 'Hello world',
});
```

当您以 `creator/model-name` 格式传递模型字符串时，AI SDK 会自动使用 AI Gateway。

## 提供商实例

<Note>
  `gateway` 提供商实例从 `ai` 包的 5.0.36 版本开始可用。
</Note>

您也可以从 `ai` 导入默认的提供商实例 `gateway`：

```ts
import { gateway } from 'ai';
```

当您需要以下情况时，可能需要创建自定义提供商实例：

- 设置自定义配置选项（API 密钥、Vercel 访问令牌、基础 URL、请求头）
- 在[提供商注册表](/docs/ai-sdk-core/provider-management)中使用该提供商
- 使用[中间件](/docs/ai-sdk-core/middleware)包装该提供商
- 为应用程序的不同部分使用不同的设置

要创建自定义提供商实例，请从 `ai` 导入 `createGateway`：

```ts
import { createGateway } from 'ai';

const gateway = createGateway({
  apiKey: process.env.AI_GATEWAY_API_KEY ?? '',
});
```

您可以使用以下可选设置来自定义 AI Gateway 提供商实例：

- **baseURL** _string_

  为 API 调用使用不同的 URL 前缀。默认前缀为 `https://ai-gateway.vercel.sh/v4/ai`。

- **apiKey** _string_

  通过 `Authorization` 请求头发送的 API 密钥或 Vercel 访问令牌。默认为 `AI_GATEWAY_API_KEY` 环境变量。支持 AI Gateway API 密钥、Vercel 个人访问令牌和 Vercel 应用访问令牌。

- **teamIdOrSlug** _string_

  使用多团队 Vercel 访问令牌进行身份验证时，用于限定模型请求范围的 Vercel 团队 ID 或 slug。

- **headers** _Record&lt;string,string&gt;_

  要包含在请求中的自定义请求头。

- **fetch** _(input: RequestInfo, init?: RequestInit) => Promise&lt;Response&gt;_

  自定义 [fetch](https://developer.mozilla.org/en-US/docs/Web/API/fetch) 实现。默认为全局 `fetch` 函数。您可以将其用作拦截请求的中间件，或为测试等目的提供自定义 fetch 实现。

- **metadataCacheRefreshMillis** _number_

  刷新元数据缓存的频率（以毫秒为单位）。默认为 5 分钟（300,000 毫秒）。

## 身份验证

Gateway 提供商支持以下身份验证方法：

### API 密钥身份验证

通过环境变量设置您的 API 密钥：

```bash
AI_GATEWAY_API_KEY=your_api_key_here
```

或直接将其传递给提供商：

```ts
import { createGateway } from 'ai';

const gateway = createGateway({
  apiKey: 'your_api_key_here',
});
```

### 用于模型请求的 Vercel 访问令牌身份验证

对于模型请求的动态运行时身份验证，请将 Vercel 个人访问令牌或 Vercel 应用访问令牌传递给自定义 Gateway 提供商实例：

```ts
import { createGateway } from 'ai';

const gateway = createGateway({
  apiKey: 'your_vercel_access_token_here',
  teamIdOrSlug: 'your-team', // 多团队令牌必需
});
```

`apiKey` 优先于 `AI_GATEWAY_API_KEY` 和 OIDC。

<Note>
  支持使用 `teamIdOrSlug` 的 Vercel 访问令牌进行模型请求。Gateway 辅助方法（如 `getCredits`、`getSpendReport` 和 `getGenerationInfo`）需要 AI Gateway API 密钥或 OIDC 身份验证。
</Note>

### OIDC 身份验证（Vercel 部署）

部署到 Vercel 时，AI Gateway 提供商支持使用 [OIDC（OpenID Connect）令牌](https://vercel.com/docs/oidc) 对模型请求进行身份验证，无需 API 密钥。

#### OIDC 身份验证的工作原理

1. **在生产/预览部署中**：
   - OIDC 身份验证会自动处理
   - 无需手动配置
   - 令牌会自动获取和刷新

2. **在本地开发中**：
   - 首先，安装并使用 [Vercel CLI](https://vercel.com/docs/cli) 进行身份验证
   - 运行 `vercel env pull` 在本地下载项目的 OIDC 令牌
   - 对于自动令牌管理：
     - 使用 `vercel dev` 启动您的开发服务器 - 这将自动处理令牌刷新
   - 对于手动令牌管理：
     - 如果不使用 `vercel dev`，请注意 OIDC 令牌在 12 小时后过期
     - 您需要在令牌过期前再次运行 `vercel env pull` 来刷新令牌

<Note>
  如果存在 API 密钥或 Vercel 访问令牌（无论是直接传递还是通过环境变量），即使无效，也始终会使用它而不是 OIDC。
</Note>

在 [Vercel AI Gateway 文档](https://vercel.com/docs/ai-gateway#using-the-ai-gateway-with-a-vercel-oidc-token) 中阅读有关使用 OIDC 令牌的更多信息。

## 自带密钥 (BYOK)

您可以连接自己的提供商凭据以与 Vercel AI Gateway 一起使用。这使您可以使用现有的提供商账户并访问私有资源。

要设置 BYOK，请在 Vercel 团队的 AI Gateway 设置中添加您的提供商凭据。配置完成后，AI Gateway 会自动使用您的凭据。无需更改代码。

对于 Azure 等允许使用自定义部署名称的提供商，您可以配置模型映射，将网关模型 slug 映射到您的部署名称。有关详细信息，请参阅[模型映射](https://vercel.com/docs/ai-gateway/byok#model-mappings)。

在 [BYOK 文档](https://vercel.com/docs/ai-gateway/byok) 中了解更多信息。

## 语言模型

您可以使用提供商实例创建语言模型。第一个参数是格式为 `creator/model-name` 的模型 ID：

```ts
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'openai/gpt-5.4',
  prompt: '用简单的术语解释量子计算',
});
```

AI Gateway 语言模型也可以在 `streamText` 函数中使用，并支持使用 [`Output`](/docs/reference/ai-sdk-core/output) 生成结构化数据（请参阅 [AI SDK Core](/docs/ai-sdk-core)）。

## 重排序模型

您可以使用提供商实例上的 `rerankingModel` 方法创建重排序模型：

```ts
import { rerank } from 'ai';
import { gateway } from '@ai-sdk/gateway';

const { ranking } = await rerank({
  model: gateway.rerankingModel('cohere/rerank-v3.5'),
  query: '法国的首都是哪里？',
  documents: [
    '巴黎是法国的首都。',
    '柏林是德国的首都。',
    '马德里是西班牙的首都。',
  ],
  topN: 2,
});

console.log(ranking);
// [
//   { originalIndex: 0, score: 0.89, document: '巴黎是法国的首都。' },
//   { originalIndex: 2, score: 0.15, document: '马德里是西班牙的首都。' },
// ]
```

重排序模型通过在对候选文档进行初始检索步骤后重新评分，有助于改进检索增强生成 (RAG) 管道中的搜索结果。

## 实时模型

<Note type="warning">
  实时支持是实验性的，API 可能在补丁版本中发生变化。
</Note>

您可以使用提供商实例上的 `experimental_realtime` 方法创建用于双向音频/文本 WebSocket 会话的实时模型。第一个参数是格式为 `creator/model-name` 的模型 ID：

```ts
import { gateway } from '@ai-sdk/gateway';

const model = gateway.experimental_realtime('openai/gpt-realtime-2');
```

Gateway 对实时模型进行标准化的方式与其对其他所有模态进行标准化的方式相同：您的客户端使用[标准化的 AI SDK 实时协议](/docs/ai-sdk-core/realtime)进行通信，而 Gateway 则在上游提供商服务器端进行双向转换。这意味着无论哪个提供商支持该模型，相同的客户端代码都能正常工作。

实时会话在浏览器中运行，并且需要一个在您的服务器上使用 `gateway.experimental_realtime.getToken()` 创建的短期 Gateway 客户端密钥。该方法使用您的 Gateway 凭据（`apiKey`、`AI_GATEWAY_API_KEY` 或 Vercel OIDC 令牌）来生成一个 `vcst_` 客户端密钥，并返回该模型的 WebSocket URL。

```ts filename='app/api/realtime/setup/route.ts'
import { gateway } from 'ai';

export async function POST() {
  const token = await gateway.experimental_realtime.getToken({
    model: 'openai/gpt-realtime-2',
    expiresAfterSeconds: 60 * 10,
  });

  return Response.json(token);
}
```

在浏览器中使用匹配的 Gateway 实时模型。在浏览器代码中创建模型是安全的；只有 `getToken()` 是服务器端操作。

```tsx filename='app/realtime/page.tsx'
'use client';

import { experimental_useRealtime } from '@ai-sdk/react';
import { gateway } from 'ai';

export default function RealtimePage() {
  const realtime = experimental_useRealtime({
    model: gateway.experimental_realtime('openai/gpt-realtime-2'),
    api: {
      token: '/api/realtime/setup',
    },
  });

  // ...
}
```

不要将您的 Gateway API 密钥或 OIDC 令牌暴露给浏览器客户端。仅返回来自 `getToken()` 的短期设置响应。

<Note>
  Gateway WebSocket 路由通过带版本的 `Sec-WebSocket-Protocol` 子协议传输短期身份验证令牌，并通过 `?ai-model-id=` 查询参数传输模型 ID——这是 HTTP 路由使用的 `Authorization` 和 `ai-model-id` 请求头的 WebSocket 传输方式。子协议值必须符合 WebSocket 令牌语法，并且完整的 `Sec-WebSocket-Protocol` 请求头应保持紧凑（在 8 KiB 的安全请求头预算内）。
</Note>

### 提供商选项

Gateway [提供商选项](#gateway-provider-options)——`tags`、`user`、`byok`、合规标志等——在**会话配置**中的 `providerOptions.gateway` 下设置，反映了它们在非实时路由上如何随请求体一起传输。将它们包含在您发送给 Gateway 的会话配置中，Gateway 会在服务器端应用它们：

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';

const gatewayOptions: GatewayProviderOptions = {
  tags: ['cooking-coach', 'v2'],
  user: 'user-123',
};

const sessionConfig = {
  instructions: '你是一个简洁的语音助手。',
  providerOptions: { gateway: gatewayOptions },
};
```

`GatewayProviderOptions` 类型从 `@ai-sdk/gateway` 导出，用于稳定的客户端面向字段。该类型也接受服务拥有的选项键，以便 Gateway 服务可以添加或更改服务器端选项，而无需为每个模式更改发布 SDK。运行时验证由 Gateway 服务负责。

<Note>
  提供商选项在套接字打开后的初始会话更新中发送，因此连接时的选项（如 `byok` 和配额选择）需要一个能够从该更新中解析它们的 Gateway。路由控制选项（如 `order` / `only`）不适用于实时模型，因为 Gateway 会选择支持 WebSocket 的提供商。
</Note>

## 可用模型

AI Gateway 支持来自 OpenAI、Anthropic、Google、Meta、xAI、Mistral、DeepSeek、Amazon Bedrock、Cohere、Perplexity、Alibaba 等提供商的模型。

有关可用模型的完整列表，请参阅 [AI Gateway 文档](https://vercel.com/docs/ai-gateway)。

## 动态模型发现

您可以通过编程方式发现可用模型：

```ts
import { gateway, generateText } from 'ai';

const availableModels = await gateway.getAvailableModels();

// 列出所有可用模型
availableModels.models.forEach(model => {
  console.log(`${model.id}: ${model.name}`);
  if (model.description) {
    console.log(`  描述: ${model.description}`);
  }
  if (model.pricing) {
    console.log(`  输入: $${model.pricing.input}/token`);
    console.log(`  输出: $${model.pricing.output}/token`);
    if (model.pricing.cachedInputTokens) {
      console.log(
        `  缓存输入（读取）: $${model.pricing.cachedInputTokens}/token`,
      );
    }
    if (model.pricing.cacheCreationInputTokens) {
      console.log(
        `  缓存创建（写入）: $${model.pricing.cacheCreationInputTokens}/token`,
      );
    }
  }
});

// 使用纯字符串使用任何发现的模型
const { text } = await generateText({
  model: availableModels.models[0].id, // 例如 'openai/gpt-5.4'
  prompt: 'Hello world',
});
```

## 信用额度使用情况

您可以检查团队的当前信用余额和使用情况：

```ts
import { gateway } from 'ai';

const credits = await gateway.getCredits();

console.log(`团队余额: ${credits.balance} 信用额度`);
console.log(`团队总使用量: ${credits.total_used} 信用额度`);
```

`getCredits()` 方法根据经过身份验证的 API 密钥或 OIDC 令牌返回您团队的信用信息：

- **balance** _number_ - 您团队当前可用的信用余额
- **total_used** _number_ - 您团队消耗的总信用额度

## 生成查询

通过 ID 查找特定生成的详细信息，包括成本、令牌使用量、延迟和提供商详细信息。生成 ID 可在 `generateText` 和 `streamText` 响应的 `providerMetadata.gateway.generationId` 中找到。

在流式传输时，生成 ID 会在第一个内容块中注入，因此您可以在流中尽早捕获它，而无需等待完成。这在网络中断或流中间错误可能导致您无法收到最终响应的情况下特别有用——因为网关会在服务器端记录最终状态，您可以稍后使用生成 ID 通过 `getGenerationInfo()` 查找结果（包括成本、令牌使用量和完成原因）。

```ts
import { gateway, generateText } from 'ai';

// 发起请求
const result = await generateText({
  model: gateway('anthropic/claude-sonnet-4'),
  prompt: '简要解释量子纠缠',
});

// 从提供商元数据中获取生成 ID
const generationId = result.providerMetadata?.gateway?.generationId;

// 查找详细的生成信息
const generation = await gateway.getGenerationInfo({ id: generationId });

console.log(`模型: ${generation.model}`);
console.log(`成本: $${generation.totalCost.toFixed(6)}`);
console.log(`延迟: ${generation.latency}ms`);
console.log(`提示词令牌数: ${generation.promptTokens}`);
console.log(`完成令牌数: ${generation.completionTokens}`);
```

使用 `streamText`，您可以通过 `stream` 从第一个块中捕获生成 ID：

```ts
import { gateway, streamText } from 'ai';

const result = streamText({
  model: gateway('anthropic/claude-sonnet-4'),
  prompt: '简要解释量子纠缠',
});

let generationId: string | undefined;

for await (const part of result.stream) {
  if (!generationId && part.providerMetadata?.gateway?.generationId) {
    generationId = part.providerMetadata.gateway.generationId as string;
    console.log(`生成 ID（早期）: ${generationId}`);
  }
}

// 在流完成后查找成本和用量
if (generationId) {
  const generation = await gateway.getGenerationInfo({ id: generationId });
  console.log(`成本: $${generation.totalCost.toFixed(6)}`);
  console.log(`完成原因: ${generation.finishReason}`);
}
```

`getGenerationInfo()` 方法接受：

- **id** _string_ - 要查找的生成 ID（格式：`gen_<ulid>`，必需）

它返回一个 `GatewayGenerationInfo` 对象，包含以下字段：

- **id** _string_ - 生成 ID
- **totalCost** _number_ - 总成本（美元）
- **upstreamInferenceCost** _number_ - 上游推理成本（美元，与 BYOK 相关）
- **usage** _number_ - 使用成本（美元，与 totalCost 相同）
- **createdAt** _string_ - 生成创建时的 ISO 8601 时间戳
- **model** _string_ - 使用的模型标识符
- **isByok** _boolean_ - 是否使用了自带密钥凭据
- **providerName** _string_ - 提供此生成的提供商
- **streamed** _boolean_ - 是否使用了流式传输
- **finishReason** _string_ - 完成原因（例如 `'stop'`）
- **latency** _number_ - 首令牌时间（毫秒）
- **generationTime** _number_ - 总生成时间（毫秒）
- **promptTokens** _number_ - 提示词令牌数
- **completionTokens** _number_ - 完成令牌数
- **reasoningTokens** _number_ - 使用的推理令牌数（如果适用）
- **cachedTokens** _number_ - 使用的缓存令牌数（如果适用）
- **cacheCreationTokens** _number_ - 缓存创建输入令牌数
- **billableWebSearchCalls** _number_ - 可计费的网络搜索调用次数

## 示例

### 基本文本生成

```ts
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4.6',
  prompt: '写一首关于编程的俳句',
});

console.log(text);
```

### 流式传输

```ts
import { streamText } from 'ai';

const { textStream } = await streamText({
  model: 'openai/gpt-5.4',
  prompt: '解释无服务器架构的优势',
});

for await (const textPart of textStream) {
  process.stdout.write(textPart);
}
```

### 工具使用

```ts
import { generateText, tool } from 'ai';
import { z } from 'zod';

const { text } = await generateText({
  model: 'xai/grok-4.5',
  prompt: '旧金山的天气怎么样？',
  tools: {
    getWeather: tool({
      description: '获取某个位置的当前天气',
      parameters: z.object({
        location: z.string().describe('要获取天气的位置'),
      }),
      execute: async ({ location }) => {
        // 您的天气 API 调用在此处
        return `${location} 天气晴朗`;
      },
    }),
  },
});
```

### 提供商执行的工具

一些提供商提供由其自身执行的工具，例如 [OpenAI 的网络搜索工具](/providers/ai-sdk-providers/openai#web-search-tool)。要通过 AI Gateway 使用这些工具，请导入提供商以访问工具定义：

```ts
import { generateText, isStepCount } from 'ai';
import { openai } from '@ai-sdk/openai';

const result = await generateText({
  model: 'openai/gpt-5.4-mini',
  prompt: '什么是 Vercel AI Gateway？',
  stopWhen: isStepCount(10),
  tools: {
    web_search: openai.tools.webSearch({}),
  },
});

console.dir(result.text);
```

<Note>
  某些提供商执行的工具需要特定于账户的配置（例如 Claude Agent Skills），并且可能无法通过 AI Gateway 工作。要使用这些工具，您必须直接向提供商提供自己的密钥 (BYOK)。
</Note>

### Gateway 工具

AI Gateway 提供商包含由网关本身执行的内置工具。这些工具可以通过网关与任何模型一起使用。

#### Perplexity 搜索

Perplexity 搜索工具使模型能够使用 [Perplexity 的搜索 API](https://docs.perplexity.ai/guides/search-quickstart) 搜索网络。此工具由 AI Gateway 执行，并返回模型可用于提供最新信息的网络搜索结果。

```ts
import { gateway, generateText } from 'ai';

const result = await generateText({
  model: 'openai/gpt-5.4-nano',
  prompt: '搜索 2025 年 1 月关于 AI 法规的新闻。',
  tools: {
    perplexity_search: gateway.tools.perplexitySearch(),
  },
});

console.log(result.text);
console.log('工具调用:', JSON.stringify(result.toolCalls, null, 2));
console.log('工具结果:', JSON.stringify(result.toolResults, null, 2));
```

您还可以使用可选参数配置搜索：

```ts
import { gateway, generateText } from 'ai';

const result = await generateText({
  model: 'openai/gpt-5.4-nano',
  prompt: '搜索 2025 年 1 月第一周关于 AI 法规的新闻。',
  tools: {
    perplexity_search: gateway.tools.perplexitySearch({
      maxResults: 5,
      searchLanguageFilter: ['en'],
      country: 'US',
      searchDomainFilter: ['reuters.com', 'bbc.com', 'nytimes.com'],
    }),
  },
});

console.log(result.text);
console.log('工具调用:', JSON.stringify(result.toolCalls, null, 2));
console.log('工具结果:', JSON.stringify(result.toolResults, null, 2));
```

Perplexity 搜索工具支持以下可选配置选项：

- **maxResults** _number_

  要返回的最大搜索结果数（1-20，默认：10）。

- **maxTokensPerPage** _number_

  每个搜索结果页面要提取的最大令牌数（256-2048，默认：2048）。

- **maxTokens** _number_

  所有搜索结果中的最大总令牌数（默认：25000，最大：1000000）。

- **searchLanguageFilter** _string[]_

  使用 ISO 639-1 语言代码按语言过滤搜索结果（例如，`['en']` 表示英语，`['en', 'es']` 表示英语和西班牙语）。

- **country** _string_

  使用 ISO 3166-1 alpha-2 国家代码按国家过滤搜索结果（例如，`'US'` 表示美国，`'GB'` 表示英国）。

- **searchDomainFilter** _string[]_

  将搜索结果限制在特定域名（例如，`['reuters.com', 'bbc.com']`）。这对于将结果限制在可信来源很有用。

- **searchRecencyFilter** _'day' | 'week' | 'month' | 'year'_

  按相对时间段过滤搜索结果。对于始终获取最新结果很有用（例如，'week' 表示过去一周的结果）。

该工具可与 `generateText` 和 `streamText` 一起使用：

```ts
import { gateway, streamText } from 'ai';

const result = streamText({
  model: 'openai/gpt-5.4-nano',
  prompt: '搜索关于 AI 法规的最新新闻。',
  tools: {
    perplexity_search: gateway.tools.perplexitySearch(),
  },
});

for await (const part of result.stream) {
  switch (part.type) {
    case 'text-delta':
      process.stdout.write(part.text);
      break;
    case 'tool-call':
      console.log('\n工具调用:', JSON.stringify(part, null, 2));
      break;
    case 'tool-result':
      console.log('\n工具结果:', JSON.stringify(part, null, 2));
      break;
  }
}
```

import { gateway, generateText } from 'ai';

const result = await generateText({

import { gateway, generateText } from 'ai';

const result = await generateText({

Exa 搜索工具支持以下可选配置选项：

- **type** _'auto' | 'fast' | 'instant'_

  搜索模式。`'auto'` 是速度和质量的默认平衡。

- **numResults** _number_

  要返回的最大结果数（1-100，默认：10）。

- **category** _'company' | 'people' | 'research paper' | 'news' | 'personal site' | 'financial report'_

  将结果集中在特定内容类型上。

- **includeDomains** / **excludeDomains** _string[]_

  按域名限制或排除搜索结果。

- **startPublishedDate** / **endPublishedDate** _string_

  按 ISO 8601 发布日期过滤结果。

- **contents** _object_

  控制结果提取和新鲜度：
  - `text` - 返回完整页面文本，可选择使用 `maxCharacters` 限制
  - `highlights` - 返回令牌高效的摘录
  - `maxAgeHours` - 控制缓存内容的新鲜度
  - `livecrawlTimeout` - 实时爬取超时时间（毫秒）
  - `subpages` / `subpageTarget` - 爬取相关的子页面
  - `extras.links` / `extras.imageLinks` - 从页面提取链接

该工具可与 `generateText` 和 `streamText` 一起使用。

此初始 Gateway 集成支持 Exa 的普通搜索模式和令牌高效的内容控制。深度合成模式和生成的摘要有意未公开，因为它们与标准搜索有不同的定价。

  - `'agentic'` - 针对多步骤智能体工作流优化的简洁、令牌高效的结果

- **fetchPolicy** _object_

  用于控制内容新鲜度的获取策略：
  - `maxAgeSeconds` - 缓存内容的最大年龄（秒），设置为 0 表示始终获取最新内容

### 自定义报告

跟踪每个最终用户的使用情况并使用标签对请求进行分类，然后通过报告 API 查询数据。

#### 使用用户和标签进行使用跟踪

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'openai/gpt-5.4',
  prompt: '总结这份文档...',
  providerOptions: {
    gateway: {
      user: 'user-abc-123', // 跟踪此特定最终用户的使用情况
      tags: ['document-summary', 'premium-feature'], // 为报告进行分类
    } satisfies GatewayProviderOptions,
  },
});
```

这使您能够：

- 在分析中查看按最终用户细分的使用情况和成本
- 使用标签按功能或用例过滤和分析支出
- 跟踪哪些用户或功能正在推动最多的 AI 使用

#### 查询支出报告

使用 `getSpendReport()` 方法以编程方式查询使用数据。报告 API 仅适用于 Vercel Pro 和 Enterprise 计划。有关定价，请参阅[自定义报告文档](https://vercel.com/docs/ai-gateway/capabilities/custom-reporting)。

```ts
import { gateway } from 'ai';

const report = await gateway.getSpendReport({
  startDate: '2026-03-01',
  endDate: '2026-03-25',
  groupBy: 'model',
});

for (const row of report.results) {
  console.log(`${row.model}: $${row.totalCost.toFixed(4)}`);
}
```

`getSpendReport()` 方法接受以下参数：

- **startDate** _string_ - `YYYY-MM-DD` 格式的开始日期（包含，必需）
- **endDate** _string_ - `YYYY-MM-DD` 格式的结束日期（包含，必需）
- **groupBy** _string_ - 聚合维度：`'day'`（默认）、`'user'`、`'model'`、`'tag'`、`'provider'` 或 `'credential_type'`
- **datePart** _string_ - 当 `groupBy` 为 `'day'` 时的时间粒度：`'day'` 或 `'hour'`
- **userId** _string_ - 过滤到特定用户
- **model** _string_ - 过滤到特定模型（例如 `'anthropic/claude-sonnet-4.5'`）
- **provider** _string_ - 过滤到特定提供商（例如 `'anthropic'`）
- **credentialType** _string_ - 按 `'byok'` 或 `'system'` 凭据过滤
- **tags** _string[]_ - 过滤到匹配这些标签的请求

`results` 中的每一行都包含一个分组字段（与您的 `groupBy` 选择匹配）和指标：

- **totalCost** _number_ - 总成本（美元）
- **marketCost** _number_ - 市场成本（美元）
- **inputTokens** _number_ - 输入令牌数
- **outputTokens** _number_ - 输出令牌数
- **cachedInputTokens** _number_ - 缓存输入令牌数
- **cacheCreationInputTokens** _number_ - 缓存创建输入令牌数
- **reasoningTokens** _number_ - 推理令牌数
- **requestCount** _number_ - 请求数

您可以结合跟踪和查询来分析您定义的标签的支出：

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { gateway, streamText } from 'ai';

// 1. 使用标签发起请求
const result = streamText({
  model: gateway('anthropic/claude-haiku-4.5'),
  prompt: '总结本季度的结果',
  providerOptions: {
    gateway: {
      tags: ['team:finance', 'feature:summaries'],
    } satisfies GatewayProviderOptions,
  },
});

// 2. 稍后，查询按这些标签过滤的支出
const report = await gateway.getSpendReport({
  startDate: '2026-03-01',
  endDate: '2026-03-31',
  groupBy: 'tag',
  tags: ['team:finance'],
});

for (const row of report.results) {
  console.log(`${row.tag}: $${row.totalCost.toFixed(4)} (${row.requestCount} 个请求)`);
}
```

## 提供商选项

AI Gateway 提供商接受控制路由行为和特定于提供商的配置的提供商选项。

### Gateway 提供商选项

您可以在 `providerOptions` 中使用 `gateway` 键来控制 AI Gateway 如何路由请求：

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4.6',
  prompt: '解释量子计算',
  providerOptions: {
    gateway: {
      order: ['vertex', 'anthropic'], // 先尝试 Vertex AI，然后是 Anthropic
      only: ['vertex', 'anthropic'], // 仅使用这些提供商
    } satisfies GatewayProviderOptions,
  },
});
```

以下 Gateway 提供商选项可用：

- **order** _string[]_

  指定路由请求时尝试提供商的顺序。网关将按指定顺序尝试提供商。如果某个提供商失败或不可用，它将移至列表中的下一个提供商。

  示例：`order: ['bedrock', 'anthropic']` 将首先尝试 Amazon Bedrock，然后回退到 Anthropic。

- **only** _string[]_

  将路由限制为仅指定的提供商。设置后，网关将永远不会路由到不在此列表中的提供商，即使它们在其他情况下可用。

  示例：`only: ['anthropic', 'vertex']` 将仅允许路由到 Anthropic 或 Vertex AI。

- **sort** _'cost' | 'ttft' | 'tps'_

  在路由之前按性能或成本指标对可用提供商进行排序。网关将首先尝试得分最高的提供商，然后按排序顺序回退到其余提供商。如果未指定，则使用网关的默认系统排名对提供商进行排序。
  - `'cost'` — 成本最低优先
  - `'ttft'` — 首令牌时间最短优先
  - `'tps'` — 每秒令牌数最高优先

  当与 `order` 结合使用时，用户指定的提供商会提升到前面，而其余提供商则遵循排序顺序。

  示例：`sort: 'ttft'` 将路由到首令牌时间最快的提供商。

  当 `sort` 激活时，响应的 `providerMetadata.gateway.routing.sort` 对象包含使用的排序选项、生成的执行顺序、每个提供商的指标值以及任何被降级的提供商。

- **models** _string[]_

  指定在主模型失败或不可用时使用的回退模型。网关将首先尝试主模型（在 `model` 参数中指定），然后按顺序尝试此数组中的每个模型，直到一个成功。

  示例：`models: ['openai/gpt-5.4-nano', 'gemini-3-flash-preview']` 将在主模型失败时按顺序尝试回退模型。

- **user** _string_

  代表其发起请求的最终用户的可选标识符。这用于支出跟踪和归因目的，允许您跟踪应用程序中每个最终用户的使用情况。

  示例：`user: 'user-123'` 将在使用报告中将此请求与最终用户 ID "user-123" 关联。

- **tags** _string[]_

  用于在报告中分类和过滤使用情况的可选标签数组。对于按功能、提示词版本或与您的应用程序相关的任何其他维度跟踪支出非常有用。

  示例：`tags: ['chat', 'v2']` 将使用 "chat" 和 "v2" 标记此请求，以便在使用分析中进行过滤。

- **byok** _Record&lt;string, Array&lt;Record&lt;string, unknown&gt;&gt;&gt;_

  用于此请求的请求范围 BYOK（自带密钥）凭据。提供时，网关系统中配置的任何缓存 BYOK 凭据将不被考虑。如果提供的凭据失败，请求仍可能回退到使用系统凭据。

  每个提供商可以有多个凭据（按顺序尝试）。结构是一个记录，其中键是提供商 slug，值是凭据对象数组。

  每个凭据可以选择性地包含一个 `modelMappings` 数组，用于将 AI Gateway 模型 slug 映射到您的部署名称（例如，自定义 Azure 部署名称）。如果 BYOK 请求失败，网关将使用默认模型名称回退到系统凭据。

  示例：
  - 单个提供商：`byok: { 'anthropic': [{ apiKey: 'sk-ant-...' }] }`
  - 多个凭据：`byok: { 'vertex': [{ project: 'proj-1', googleCredentials: { privateKey: '...', clientEmail: '...' } }, { project: 'proj-2', googleCredentials: { privateKey: '...', clientEmail: '...' } }] }`
  - 多个提供商：`byok: { 'anthropic': [{ apiKey: '...' }], 'bedrock': [{ accessKeyId: '...', secretAccessKey: '...' }] }`
  - 带模型映射：`byok: { 'azure': [{ apiKey: '...', resourceName: '...', modelMappings: [{ gatewayModelSlug: 'openai/gpt-5.4-nano', customModelId: 'my-deployment' }] }] }`

- **zeroDataRetention** _boolean_

  将路由限制为与 Vercel 就 AI Gateway 签订了零数据保留协议的提供商。BYOK 凭据默认被跳过，因为您的提供商协议与 Vercel 的不同。当此过滤器打开时，AI Gateway 仅路由到 Vercel 就该模型拥有 ZDR 协议的提供商。如果您有标记为 ZDR 的 BYOK 密钥，这些密钥会首先尝试，然后 AI Gateway 回退到其系统凭据。您负责该标记的准确性。适用于账户范围和请求级别的 ZDR。如果没有可用的符合 ZDR 条件的凭据，请求将失败。请求级别的 ZDR 仅适用于 Vercel Pro 和 Enterprise 计划。

- **disallowPromptTraining** _boolean_

  将路由限制为与 Vercel 就 AI Gateway 签订了不使用提示词进行模型训练协议的提供商。使用 BYOK 凭据时，不应用此过滤器。如果 BYOK 凭据失败并且请求回退到系统凭据，则仅使用不在提示词数据上进行训练的提供商。如果没有可用于该模型且不允许提示词训练的提供商，请求将失败。

- **hipaaCompliant** _boolean_

  将路由限制为与 Vercel 就 AI Gateway 的使用签订了 BAA 的提供商的模型和工具（需要 Vercel HIPAA BAA 附加组件）。当 `hipaaCompliant` 设置为 `true` 时，BYOK 凭据会被跳过，以确保请求仅路由到支持 HIPAA 合规性的提供商。

- **quotaEntityId** _string_

  针对其跟踪配额的实体的唯一标识符。用于配额管理和强制执行目的。

- **has** _Array&lt;'implicit-caching'&gt;_

  将路由限制为具有所有指定功能的提供商模型。目前支持 `'implicit-caching'`，它将路由限制为执行自动（隐式）提示词缓存的模型。适用于 BYOK 和系统凭据，因为该功能是模型的属性，而不是凭据的属性。如果没有满足这些功能的请求模型的提供商模型，请求将失败。不支持的值将被拒绝。

  示例：`has: ['implicit-caching']` 将仅路由到支持隐式缓存的模型。

- **providerTimeouts** _object_

  BYOK 凭据的每个提供商超时时间（毫秒）。控制等待提供商开始响应的时间，然后回退到下一个可用提供商。

  示例：`providerTimeouts: { byok: { openai: 5000, anthropic: 2000 } }`

  有关完整详细信息，请参阅[提供商超时](https://vercel.com/docs/ai-gateway/models-and-providers/provider-timeouts)。

- **serviceTier** _'flex' | 'priority'_

  统一的服务层级意图。网关将其转换为每个提供商期望的每个提供商选项，并覆盖也在每个提供商选项中设置的任何层级。留空以使用提供商默认值。有关层级语义、模型可用性和每个提供商的优雅降级行为，请参阅 [OpenAI](/providers/ai-sdk-providers/openai)、[Google Generative AI](/providers/ai-sdk-providers/google-generative-ai) 和 [Google Vertex AI](/providers/ai-sdk-providers/google-vertex) 提供商文档。

  ```ts
  import type { GatewayProviderOptions } from '@ai-sdk/gateway';
  import { generateText } from 'ai';

  const { text } = await generateText({
    model: 'openai/gpt-5-mini',
    prompt: 'Hello',
    providerOptions: {
      gateway: {
        serviceTier: 'priority',
      } satisfies GatewayProviderOptions,
    },
  });
  ```

您可以组合这些选项以对路由和跟踪进行精细控制：

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4.6',
  prompt: '写一首关于编程的俳句',
  providerOptions: {
    gateway: {
      order: ['vertex'], // 优先使用 Vertex AI
      only: ['anthropic', 'vertex'], // 仅允许这些提供商
    } satisfies GatewayProviderOptions,
  },
});
```

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'openai/gpt-5.4', // 主模型
  prompt: '写一首 TypeScript 俳句',
  providerOptions: {
    gateway: {
      models: ['openai/gpt-5.4-nano', 'gemini-3-flash-preview'], // 回退模型
    } satisfies GatewayProviderOptions,
  },
});

// 这将：
// 1. 首先尝试 openai/gpt-5.4
// 2. 如果失败，尝试 openai/gpt-5.4-nano
// 3. 如果也失败，尝试 gemini-3-flash-preview
// 4. 返回第一个成功模型的结果
```

#### 零数据保留示例

将 `zeroDataRetention` 设置为 true，以将请求路由到与 Vercel 就 AI Gateway 签订了零数据保留协议的提供商。BYOK 凭据默认被跳过，因为您的提供商协议与 Vercel 的不同。当此过滤器打开时，AI Gateway 仅路由到 Vercel 就该模型拥有 ZDR 协议的提供商。如果您有标记为 ZDR 的 BYOK 密钥，这些密钥会首先尝试，然后 AI Gateway 回退到其系统凭据。您负责该标记的准确性。适用于账户范围和请求级别的 ZDR。如果没有可用的符合 ZDR 条件的凭据，请求将失败。当 `zeroDataRetention` 为 `false` 或未指定时，不强制执行路由限制。请求级别的 ZDR 仅适用于 Vercel Pro 和 Enterprise 计划。

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4.6',
  prompt: '分析这份敏感文档...',
  providerOptions: {
    gateway: {
      zeroDataRetention: true,
    } satisfies GatewayProviderOptions,
  },
});
```

#### 禁止提示词训练示例

将 `disallowPromptTraining` 设置为 true，以将请求路由到与 Vercel 就 AI Gateway 签订了不使用提示词进行模型训练协议的提供商。使用 BYOK 凭据时，不应用此过滤器。如果 BYOK 凭据失败并且请求回退到系统凭据，则仅使用不在提示词数据上进行训练的提供商。如果没有可用于该模型且不允许提示词训练的提供商，请求将失败。当 `disallowPromptTraining` 为 `false` 或未指定时，不强制执行路由限制。

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4.6',
  prompt: '分析这份专有业务数据...',
  providerOptions: {
    gateway: {
      disallowPromptTraining: true,
    } satisfies GatewayProviderOptions,
  },
});
```

#### HIPAA 合规性示例

将 `hipaaCompliant` 设置为 true，以仅将请求路由到与 Vercel 就 AI Gateway 的使用签订了 BAA 的提供商的模型或工具。如果模型或工具没有符合 HIPAA 的提供商，请求将失败。当 `hipaaCompliant` 为 `false` 或未指定时，不强制执行路由限制。当 `hipaaCompliant` 设置为 `true` 时，BYOK 凭据会被跳过，以确保请求仅路由到支持 HIPAA 合规性的提供商。

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4.6',
  prompt: '分析这份患者数据...',
  providerOptions: {
    gateway: {
      hipaaCompliant: true,
    } satisfies GatewayProviderOptions,
  },
});
```

#### 配额实体 ID 示例

设置 `quotaEntityId` 以跟踪和强制执行针对特定实体的配额。这对于需要按实体级别（例如，按组织或团队）管理配额的多租户应用程序非常有用。

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4.6',
  prompt: '总结这份报告...',
  providerOptions: {
    gateway: {
      quotaEntityId: 'org-123',
    } satisfies GatewayProviderOptions,
  },
});
```

#### 按模型功能过滤

设置 `has` 以将路由限制为具有指定功能的提供商模型。这适用于 BYOK 和系统凭据，因为该功能是模型的属性，而不是凭据的属性。目前支持 `'implicit-caching'`，它将路由限制为执行自动提示词缓存的模型。如果没有满足这些功能的请求模型的提供商模型，请求将失败。

```ts
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'openai/gpt-5.5',
  prompt: '总结这份报告...',
  providerOptions: {
    gateway: {
      has: ['implicit-caching'],
    } satisfies GatewayProviderOptions,
  },
});
```

### 特定于提供商的选项

通过 AI Gateway 使用特定于提供商的选项时，请使用实际的提供商名称（例如 `anthropic`、`openai`，而不是 `gateway`）作为键：

```ts
import type { AnthropicLanguageModelOptions } from '@ai-sdk/anthropic';
import type { GatewayProviderOptions } from '@ai-sdk/gateway';
import { generateText } from 'ai';

const { text } = await generateText({
  model: 'anthropic/claude-sonnet-4.6',
  prompt: '解释量子计算',
  providerOptions: {
    gateway: {
      order: ['vertex', 'anthropic'],
    } satisfies GatewayProviderOptions,
    anthropic: {
      thinking: { type: 'enabled', budgetTokens: 12000 },
    } satisfies AnthropicLanguageModelOptions,
  },
});
```

这适用于 AI Gateway 支持的任何提供商。每个提供商都有自己的一组选项——有关特定于提供商的选项的详细信息，请参阅各个[提供商文档页面](/providers/ai-sdk-providers)。
