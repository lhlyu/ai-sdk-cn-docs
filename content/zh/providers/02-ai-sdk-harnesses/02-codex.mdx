# Codex Harness

Codex harness 适配器将 `HarnessAgent` 连接到 Codex app-server。
该适配器在沙箱内运行一个桥接程序，并通过沙箱暴露的 WebSocket 将 Codex 线程事件流式传输回主机。

<Note>
  Harness 包目前处于**实验阶段**。由于这一早期 API 仍在不断完善，各版本之间可能会出现破坏性变更。
</Note>

## 设置

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-codex @ai-sdk/sandbox-vercel" />

适配器会在第一个会话启动时，在沙箱内引导安装 Codex 桥接程序的依赖项。

## 导入

```ts
import { codex, createCodex } from '@ai-sdk/harness-codex';
```

`codex` 等同于使用默认配置的 `createCodex()`。

## 基本用法

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { codex } from '@ai-sdk/harness-codex';
import { createVercelNetworkSandboxSession } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: codex,
  model: 'gpt-5.6-luna',
});

const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  ports: [4000],
  template: await agent.getSandboxTemplate(),
});
const session = await agent.createSession({ sandboxSession });

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: 'Check the test failures and fix the production code.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
  process.exit(exitCode);
}
```

要使用此智能体，请确保环境变量中包含用于 Vercel Sandbox 的 `VERCEL_OIDC_TOKEN`，以及 [身份验证](#authentication) 下列出的适用于 Codex 的变量之一。

## 适配器设置

使用 `createCodex()` 配置运行时：

```ts
const harness = createCodex({
  reasoningEffort: 'high',
  webSearch: true,
  codexConfig: {
    model_verbosity: 'low',
  },
});
```

设置项：

- `auth`：身份验证模式（`auto`、`direct` 或 `ai-gateway`），或一个隔离的身份验证环境。
- `credentialForwarding`：可选的同步或异步回调，用于在 harness 适配器将每个凭据转发到沙箱进程之前立即对其进行自定义。它接收原本会被转发的凭据值（真实凭据或掩码值）以及用于暴露该凭据的环境变量名。此回调仅控制转发到沙箱进程中的值。它不会限制 harness 适配器在主机进程中能够发现、读取或以其他方式访问哪些凭据。
- `codexConfig`：额外的原生 Codex 配置。值会按原样传递，因此请使用 Codex `config.toml` 参考中的 snake_case 键。适配器管理的值优先于冲突的条目。
- `mcpServers`：以服务器名称为键的 MCP 服务器定义。
- `reasoningEffort`：`low`、`medium`、`high`、`xhigh` 或 `max`。
- `webSearch`：允许实时网络搜索。
- `port`：桥接端口覆盖。
- `startupTimeoutMs`：等待桥接程序启动的最长时间。
- `reconnect`：已建立的桥接 WebSocket 连接断开后的重连时机。`maxElapsedMs` 控制总重试窗口，包括连接建立和退避延迟，默认为 30 秒。`initialDelayMs` 默认为 50 毫秒，`maxDelayMs` 默认为 2 秒。这些重试使用指数退避，并且与 `startupTimeoutMs` 相互独立。当沙箱、桥接进程或桥接端点永久不可用时，它们无法恢复。
- `mintBridgeToken`：同步函数，接收沙箱 id 并返回桥接身份验证令牌。默认情况下，适配器会生成一个随机的 32 字节令牌。自定义实现必须返回一个足够保密的令牌。

## 内置工具过滤

Codex 支持针对 `bash`、`webSearch`、`apply_patch` 和 `view_image` 的 `activeTools` 和 `inactiveTools`。主机工具在发送到 Codex 之前会被过滤。原生 Codex 配置会分别禁用 `bash`、`view_image` 和 `webSearch`。当 `bash`、`apply_patch` 和 `view_image` 全部处于非活动状态时，适配器会禁用 Codex 环境，并显式禁用 `bash` 和 `view_image`。当 `apply_patch` 处于非活动状态但 `bash` 或 `view_image` 仍处于活动状态时，适配器会安装一个 Codex `PreToolUse` Hook，用于拒绝补丁执行。在开始每一轮之前，适配器会检查 Codex 是否已加载并信任该 Hook，如果没有，则使该轮失败。将 `webSearch` 包含在 `activeTools` 中并不会自行启用它；请在 `createCodex()` 上设置 `webSearch: true` 以允许实时搜索。

```ts
const agent = new HarnessAgent({
  harness: createCodex(),
  sandbox: createVercelSandbox({ runtime: 'node24', ports: [4000] }),
  inactiveTools: ['apply_patch'],
});
```

## 结构化输出

Codex 支持基于 schema 的 [`HarnessAgent` 结构化输出](/docs/ai-sdk-harnesses/harness-agent#generate-structured-output)。
适配器通过 Codex app-server 的 `turn/start` `outputSchema` 参数传递 JSON Schema。

## 身份验证

`auth` 设置用于选择如何从主机环境解析凭据：

- `auto`（默认）：在可用时使用 AI Gateway 凭据，然后回退到直接使用 OpenAI 凭据。
- `direct`：使用 OpenAI 凭据。
- `ai-gateway`：使用 AI Gateway 凭据。

当沙箱支持附加请求转换时，桥接程序会接收占位符，适配器会将凭据注入到匹配的出站请求中。不具备该能力的沙箱则保留直接凭据转发。

支持的环境变量：

- `VERCEL_OIDC_TOKEN`
- `AI_GATEWAY_API_KEY`
- `AI_GATEWAY_BASE_URL`
- `OPENAI_API_KEY`
- `CODEX_API_KEY`
- `OPENAI_BASE_URL`
- `OPENAI_ORGANIZATION`
- `OPENAI_PROJECT`

如果未设置适用的凭据环境变量，除非选择了 AI Gateway 身份验证，否则适配器会尝试从主机系统解析原生订阅。

当你不需要自动检测时，请选择特定的身份验证模式：

```ts
const directHarness = createCodex({ auth: 'direct' });
const gatewayHarness = createCodex({ auth: 'ai-gateway' });
```

传入一个身份验证环境，以使用以编程方式解析的凭据，而无需读取 `process.env`：

```ts
const harness = createCodex({
  auth: { OPENAI_API_KEY: await resolveOpenAIToken() },
});
```

提供的记录会替换用于身份验证发现的主机环境。只有被识别的身份验证变量会被转发。

对于 OpenAI 兼容端点，请选择 `direct` 并设置 `OPENAI_BASE_URL`。

## 沙箱

Codex 需要一个至少暴露一个端口的网络沙箱，例如 `@ai-sdk/sandbox-vercel`：

```ts
const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  ports: [4000],
  template: await agent.getSandboxTemplate(),
});
```

## 内置工具

适配器通过 `agent.tools` 暴露以下 Codex 内置工具：

- `bash` 和 `webSearch` 使用常见的跨 harness 工具名称。
- `apply_patch` 接受 Codex 的自由格式补丁字符串。
- `view_image` 接受本地图像 `path`，并可选带 `detail` 和 `environment_id` 字段。

Codex 文件变更也可能以动态 `fileChange` 工具部分的形式出现，因为某些 Codex 文件变更并非源自可见的、模型可调用的工具。

## 已知限制

Codex 目前不支持内置工具审批请求。请在此适配器中使用 `permissionMode: 'allow-all'`。由主机执行的 AI SDK 工具审批仍然有效。

当 app-server 必须冷恢复线程时，Codex 不会为 `apply_patch` 和 `view_image` 提供原始事件，因此对于该恢复的线程，这些工具调用和结果无法呈现。
