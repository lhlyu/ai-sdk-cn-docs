# OpenCode 工具链

OpenCode 工具链适配器通过 `@opencode-ai/sdk` 将 `HarnessAgent` 连接到 OpenCode。该适配器在沙箱内运行一个桥接器，在该沙箱中启动 OpenCode 服务器，并通过沙箱暴露的 WebSocket 将会话事件流式传输回主机。

<Note>
  工具链包为**实验性**。随着这个早期 API 的进一步完善，版本之间可能会有破坏性变更。
</Note>

## 设置

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-opencode @ai-sdk/sandbox-vercel" />

当第一个会话启动时，适配器会在沙箱内引导 OpenCode 桥接器依赖。桥接器包依赖于 `@opencode-ai/sdk` 和 `opencode-ai`。

## 导入

```ts
import { openCode, createOpenCode } from '@ai-sdk/harness-opencode';
```

`openCode` 等同于使用默认配置的 `createOpenCode()`。

## 基本用法

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { openCode } from '@ai-sdk/harness-opencode';
import { createVercelSandbox } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: openCode,
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
});

const session = await agent.createSession();

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: '检查测试失败并修复生产代码。',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  process.exit(exitCode);
}
```

要使用此智能体，请确保环境变量中包含 Vercel Sandbox 所需的 `VERCEL_OIDC_TOKEN`，以及 [认证](#认证) 下列出的 OpenCode 所需变量之一。

## 适配器设置

使用 `createOpenCode()` 配置运行时：

```ts
const harness = createOpenCode({
  model: 'anthropic/claude-sonnet-4-6',
  reasoningVariant: 'high',
});
```

设置：

- `auth`：Anthropic、OpenAI、OpenAI 兼容或 AI Gateway 认证设置。
- `mcpServers`：按服务器名称键控的 MCP 服务器定义。
- `model`：OpenCode 模型 ID。提供商前缀值（如 `anthropic/claude-sonnet-4-6`）会直接传递给 OpenCode。
- `provider`：与无前缀 `model` 一起使用的提供商 ID。
- `reasoningVariant`：受支持模型的 OpenCode 推理/思考变体，如 `low`、`medium` 或 `high`。
- `port`：桥接器端口覆盖。
- `startupTimeoutMs`：等待桥接器启动的最大时间。
- `mintBridgeToken`：接收沙箱 ID 并返回桥接器认证令牌的同步函数。默认情况下，适配器生成一个随机的 32 字节令牌。自定义实现必须返回足够机密的令牌。

## 认证

默认情况下，认证从主机环境解析并转发到沙箱桥接器。适配器会检查 AI Gateway、Anthropic 和 OpenAI 凭据。

支持的环境变量：

- `AI_GATEWAY_API_KEY`
- `AI_GATEWAY_BASE_URL`
- `VERCEL_OIDC_TOKEN`
- `ANTHROPIC_API_KEY`
- `ANTHROPIC_AUTH_TOKEN`
- `ANTHROPIC_BASE_URL`
- `OPENAI_API_KEY`
- `OPENAI_BASE_URL`
- `OPENAI_ORGANIZATION`
- `OPENAI_PROJECT`

您也可以传递显式的认证设置：

```ts
const harness = createOpenCode({
  auth: {
    gateway: {
      apiKey: process.env.AI_GATEWAY_API_KEY,
    },
  },
});
```

对于 OpenAI 兼容端点，请使用 `auth.openaiCompatible` 并将 `name` 设置为 OpenCode 提供商 ID。

## 沙箱

OpenCode 需要一个至少暴露一个端口的网络沙箱，例如 `@ai-sdk/sandbox-vercel`：

```ts
const sandbox = createVercelSandbox({
  runtime: 'node24',
  ports: [4000],
});
```

## 内置工具

适配器通过 `agent.tools` 暴露以下常见的 OpenCode 内置工具：

- `read`
- `write`
- `edit`
- `bash`
- `glob`
- `grep`
- `ls`
- `webfetch`
- `skill`
- `todowrite`
- `agent`

当其他 OpenCode 内置工具不符合常见工具形态时，它们也可能出现在 `agent.tools` 中。

当 `permissionMode` 为 `allow-reads` 或 `allow-edits` 时，OpenCode 支持内置工具审批请求。主机执行的 AI SDK 工具审批同样有效。
