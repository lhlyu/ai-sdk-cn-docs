# OpenCode Harness

OpenCode harness 适配器通过 `@opencode-ai/sdk` 将 `HarnessAgent` 连接到 OpenCode。该适配器在沙箱内运行一个桥接程序，在该沙箱中启动 OpenCode 服务器，并通过沙箱暴露的 WebSocket 将 OpenCode 会话事件流式传输回主机。

<Note>
  Harness 包目前处于**实验阶段**。随着这一早期 API 的进一步完善，各版本之间可能会出现破坏性变更。
</Note>

## 设置

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-opencode @ai-sdk/sandbox-vercel" />

适配器会在首次会话启动时，在沙箱内引导安装 OpenCode 桥接程序的依赖项。该桥接包依赖于 `@opencode-ai/sdk` 和 `opencode-ai`。

## 导入

```ts
import { openCode, createOpenCode } from '@ai-sdk/harness-opencode';
```

`openCode` 等同于使用默认配置的 `createOpenCode()`。

## 基本用法

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { openCode } from '@ai-sdk/harness-opencode';
import { createVercelSandbox } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: openCode,
  model: 'anthropic/claude-sonnet-4-6',
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
});

const session = await agent.createSession();

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: 'Check the test failures and fix the production code.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  process.exit(exitCode);
}
```

要使用此智能体，请确保环境变量中包含用于 Vercel Sandbox 的 `VERCEL_OIDC_TOKEN`，以及 [身份验证](#authentication) 下列出的用于 OpenCode 的变量之一。

## 适配器设置

使用 `createOpenCode()` 配置运行时：

```ts
const harness = createOpenCode({
  reasoningVariant: 'high',
  openCodeConfig: {
    agent: {
      general: {
        model: 'openai/gpt-5.4-mini',
      },
    },
  },
});
```

设置项：

- `auth`：身份验证模式（`auto`、`anthropic`、`openai` 或 `ai-gateway`），或一个隔离的身份验证环境。
- `credentialForwarding`：可选的同步或异步回调，用于在 harness 适配器将每个凭据转发到沙箱进程之前立即对其进行自定义。它会接收原本将被转发的凭据值（真实凭据或掩码值）以及用于暴露该凭据的环境变量名。此回调仅控制转发到沙箱进程中的值。它不会限制 harness 适配器在主机进程中能够发现、读取或以其他方式访问哪些凭据。
- `mcpServers`：以服务器名称为键的 MCP 服务器定义。
- `openCodeConfig`：额外的原生 OpenCode 配置。适配器管理的设置优先。智能体本地的 `permission` 和已弃用的 `tools` 设置会被忽略，因此它们无法绕过 harness 权限或内置工具过滤。
- `provider`：当 `HarnessAgent` 上的 `model` 未带前缀时使用的提供商 id。
- `reasoningVariant`：受支持模型的 OpenCode 推理/思考变体，例如 `low`、`medium` 或 `high`。
- `port`：桥接端口覆盖。
- `startupTimeoutMs`：等待桥接程序启动的最长时间。
- `mintBridgeToken`：同步函数，接收沙箱 id 并返回桥接身份验证令牌。默认情况下，适配器会生成一个随机的 32 字节令牌。自定义实现必须返回一个足够保密的令牌。

## 结构化输出

OpenCode 支持基于 schema 的 [`HarnessAgent` 结构化输出](/docs/ai-sdk-harnesses/harness-agent#generate-structured-output)。适配器使用 OpenCode 的 `json_schema` 提示词格式，并将经过验证的 `structured` 结果作为 JSON 文本返回。

## 身份验证

`auth` 设置用于选择如何从主机环境中解析凭据：

- `auto`（默认）：在可用时使用 AI Gateway 凭据，然后使用所选模型提供商的凭据。
- `anthropic`：使用 Anthropic 凭据。
- `openai`：使用 OpenAI 凭据。
- `ai-gateway`：使用 AI Gateway 凭据。

当沙箱支持附加请求转换时，桥接程序会接收占位符，适配器会将凭据注入到匹配的出站请求中。不支持该能力的沙箱则保留直接凭据转发。

支持的环境变量：

- `AI_GATEWAY_API_KEY`
- `AI_GATEWAY_BASE_URL`
- `VERCEL_OIDC_TOKEN`
- `ANTHROPIC_API_KEY`
- `ANTHROPIC_AUTH_TOKEN`
- `ANTHROPIC_BASE_URL`
- `OPENAI_API_KEY`
- `OPENAI_BASE_URL`
- `OPENAI_ORGANIZATION`
- `OPENAI_PROJECT`

如果未设置任何适用的凭据环境变量，除非选择了 AI Gateway 身份验证，否则适配器会尝试从主机系统解析原生订阅。

当你不想使用自动检测时，可选择特定的身份验证模式：

```ts
const anthropicHarness = createOpenCode({ auth: 'anthropic' });
const openAIHarness = createOpenCode({ auth: 'openai' });
const gatewayHarness = createOpenCode({ auth: 'ai-gateway' });
```

传入身份验证环境，以使用以编程方式解析的凭据，而无需读取 `process.env`：

```ts
const harness = createOpenCode({
  auth: { OPENAI_API_KEY: await resolveOpenAIToken() },
  provider: 'openai',
});
```

所提供的记录会替换用于身份验证发现的主机环境。只有可识别的身份验证变量会被转发。

对于 OpenAI 兼容的端点，请选择 `openai` 并设置 `OPENAI_BASE_URL`。

## 沙箱

OpenCode 需要一个至少暴露一个端口的网络沙箱，例如 `@ai-sdk/sandbox-vercel`：

```ts
const sandbox = createVercelSandbox({
  runtime: 'node24',
  ports: [4000],
});
```

## 内置工具

适配器通过 `agent.tools` 暴露以下常见的 OpenCode 内置工具：

- `read`
- `write`
- `edit`
- `bash`
- `glob`
- `grep`
- `ls`
- `webfetch`
- `skill`
- `todowrite`
- `agent`

当其他 OpenCode 内置工具不符合常见工具形态时，它们也可能出现在 `agent.tools` 中。

当 `permissionMode` 为 `allow-reads` 或 `allow-edits` 时，OpenCode 支持内置工具审批请求。主机执行的 AI SDK 工具审批同样可用。
