# Agent Client Protocol Harness

Agent Client Protocol（ACP）harness 适配器将 `HarnessAgent` 连接到任何兼容 ACP 版本 1 的 harness。通用适配器负责桥接、ACP 客户端、宿主工具中继、事件转换、审批和生命周期行为；内联配置描述如何安装和配置一个 ACP 运行时。

除了 ACP harness 适配器之外，你只需要一个可从 NPM 安装或通过可信 Bash 命令安装的 ACP 兼容实现。然后，你可以用几行代码配置 ACP harness 适配器。

<Note>
  Harness 包目前处于**实验阶段**。随着这一早期 API 的进一步完善，不同版本之间可能会出现破坏性变更。
</Note>

## 基本用法

定义一个 ACP harness 配置，例如下面[完整实现](#complete-acp-harness-implementations)中的某一个，并将其传递给 `HarnessAgent`：

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { createVercelNetworkSandboxSession } from '@ai-sdk/sandbox-vercel';
import { codexACPHarness } from './codex-acp-harness';

const agent = new HarnessAgent({
  harness: codexACPHarness,
});

const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  ports: [4000],
  template: await agent.getSandboxTemplate(),
});
const session = await agent.createSession({ sandboxSession });
try {
  const result = await agent.generate({
    session,
    prompt: 'Check the test failures and fix the production code.',
  });
  console.log(result.text);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
}
```

## 适配器设置

`createACP` 接受以下参数：

- `harnessId`：此配置的稳定 kebab-case 标识。
- `version`：ACP 协议版本。默认值为 `'v1'`，目前仅支持 `'v1'`。
- `source`：如何获取 ACP 智能体，可以是锁定的 NPM 安装，也可以是可信的 Bash 安装命令。
- `executable`：从已获取的智能体中启动的裸命令名。
- `args`：传递给可执行文件的可选参数。
- `forwardEnv`：要转发到沙箱中的非凭据宿主环境变量名。
- `credentialEnv`：宿主凭据环境变量名。请与 `credentialBrokering` 一起配置。
- `credentialBrokering`：该函数接收有效宿主运行时环境作为 `env`，以及转发到沙箱的环境作为 `sandboxEnv`，然后返回附加的出站请求转换。在精确请求头匹配中使用来自 `sandboxEnv` 的凭据，并在转换后的请求头中使用来自 `env` 的真实凭据。
- `credentialForwarding`：可选的同步或异步回调，在 harness 适配器将每个凭据转发到沙箱进程之前立即对其进行自定义。它接收原本会被转发的凭据值（真实凭据或掩码值）以及用于暴露该凭据的环境变量名。此回调仅控制转发到沙箱进程中的值。它不会限制 harness 适配器在宿主进程中能够发现、读取或以其他方式访问哪些凭据。
- `env`：在引导时写入的持久环境值。
- `builtinTools`：可选的本地工具定义，用于静态类型和精确名称匹配。
- `mcpServers`：以服务器名称为键的 MCP 服务器定义。
- `hostToolMcpTransport`：用于 harness 拥有的 MCP 服务器的传输方式，该服务器向 ACP 实现暴露宿主工具。默认值为 `'stdio'`。对于仅接受来自客户端的 HTTP 或 SSE MCP 服务器的实现，请将其设置为 `'http'`，这要求该实现声明 `agentCapabilities.mcpCapabilities.http`。
- `authentication`：声明的 ACP 认证方法、元数据和客户端能力。
- `nonTextContentTypes`：在 ACP 提示词和工具模型输出中支持的非文本图像内容。目前接受 `['image']`。当智能体声明 `agentCapabilities.promptCapabilities.image` 或此设置包含 `'image'` 时，支持图像提示词；当该能力标志缺失或不正确时，此设置可以主动启用。来自工具 `toModelOutput()` 回调的图像内容仅在此设置包含 `'image'` 时传递；否则会被省略并发出警告。默认为空列表。
- `auth`：下游提供商认证模式：
  - `auto`（默认）：当 Gateway 凭据和 `providerAuthentication` 配置可用时使用 AI Gateway；否则使用直接认证。
  - `direct`：始终使用直接认证，即使 Gateway 凭据可用。
  - `ai-gateway`：始终使用 AI Gateway，并在 Gateway 凭据不可用时抛出错误。这需要 `providerAuthentication` 配置。
  - 认证环境：从提供的记录中自动检测，而不是从宿主进程环境中检测。
- `providerAuthentication`：声明式运行时特定的 Gateway 环境。
- `modelMapping`：必需的静态映射，从传递给 `HarnessAgent` 的 `model` 映射到该实现使用的 ACP 操作。使用 `session-config-option` 并将其配置选项 ID 作为 `path`，或使用 `session-model` 并将 `session/set_model` 请求属性作为 `path`。
- `skillsDirectory`：相对于实现的有效 `$HOME` 的本地技能目录。默认值为 `.agents/skills`；对于使用不同位置的运行时，请覆盖此设置。
- `instructionMapping`：可选映射，从 `HarnessAgent` 指令映射到实现的本地系统或开发者提示词。使用 `session-meta` 表示 ACP 会话请求的 `_meta` 字段下的路径，使用 `launch-env-json` 表示 JSON 启动环境变量内的路径，或使用 `filesystem` 并指定相对 `path`，将指令写入实现的有效 `$HOME` 下的文件。省略时，指令会前置到第一个用户提示词。
- `outputSchemaMapping`：可选的实现特定映射，从结构化输出 JSON Schema 映射到 ACP `session/prompt` 请求的 `_meta` 字段下的路径。ACP 未标准化结构化输出，因此除非所选实现记录了该私有扩展，否则请省略此设置。
- `askUserQuestions`：可选的转换，在实现特定的 ACP 客户端问题请求和 Harness `askUserQuestions` 工具之间进行转换。仅当 ACP 实现暴露等待客户端响应的本地请求时才配置。
- `permissionModeMapping`：从全部三种 Harness 权限模式到声明的 ACP 会话模式或配置选项的映射。当 ACP 实现不支持该模式时，将对应条目设置为 `null`。省略时，适配器按工具类型将 `permissionMode` 应用于 ACP 权限请求。
- `session.meta`：用于会话创建和恢复的可序列化实现特定元数据。
- `port`：暴露的桥接端口覆盖。
- `startupTimeoutMs`：桥接启动超时。默认值为 120 秒。
- `reconnect`：已建立的桥接 WebSocket 连接断开后的重连时机。`maxElapsedMs` 控制总重试窗口，包括连接建立和退避延迟，默认值为 30 秒。`initialDelayMs` 默认值为 50 毫秒，`maxDelayMs` 默认值为 2 秒。这些重试使用指数退避，与 `startupTimeoutMs` 相互独立。当沙箱、桥接进程或桥接端点永久不可用时，它们无法恢复。
- `mintBridgeToken`：同步函数，接收沙箱 ID 并返回桥接认证令牌。默认情况下，适配器生成随机的 32 字节令牌。自定义实现必须返回具有足够保密性的令牌。
- `clientApp`：可选的客户端归属信息，包含 `name` 和 `version`。默认值为已安装的 `ai-sdk-harness-acp/<version>` 标识，并可用于 Gateway 环境占位符。

运行时特定的包名、环境变量、模式和会话元数据应放在内联配置中，而不是通用适配器中。

## 结构化输出

ACP 版本 1 未定义结构化输出能力。具有私有提示词元数据扩展的实现的配置可以显式启用：

```ts
const harness = createACP({
  harnessId: 'example-acp',
  source: {
    type: 'install-command',
    command: 'curl -fsSL https://example.com/install.sh | bash',
  },
  executable: 'example-acp',
  modelMapping: {
    type: 'session-config-option',
    path: 'model',
  },
  outputSchemaMapping: {
    type: 'session-prompt-meta',
    path: ['outputSchema'],
  },
});
```

对于配置了 `output` 的 `HarnessAgent`，这会将生成的 JSON Schema 写入 `session/prompt.params._meta.outputSchema`。没有此映射的配置会抛出 `HarnessCapabilityUnsupportedError`，而不是假设任意 ACP 实现都能理解该 schema；Codex ACP 不受支持，而 Grok Build harness 包含其经过验证的映射。

### 智能体来源

锁定来源会冻结完整安装。提供 `package.json` 及其 `pnpm-lock.yaml` 的内容：

```ts
const source = {
  type: 'npm-locked',
  packageJson: packageJsonContents,
  pnpmLockYaml: pnpmLockYamlContents,
  pnpmWorkspaceYaml: pnpmWorkspaceYamlContents,
} as const;
```

锁定来源使用 `pnpm install --frozen-lockfile` 安装提供的文件。`pnpmWorkspaceYaml` 是可选的；当锁定安装需要工作区级 pnpm 配置时提供它，例如为必需的依赖构建脚本设置精确版本的 `allowBuilds` 策略。

锁定的 `package.json` 还必须以相同版本声明 `@ai-sdk/harness-acp` 桥接清单（`dist/bridge/package.json`）的每个依赖项。

清单、锁文件和可选的工作区配置是持久化的引导产物，并参与生命周期标识。不要在这些字符串中包含凭据。

安装命令来源会运行可信的 Bash 命令：

```ts
const cursorSource = {
  type: 'install-command',
  command: 'curl https://cursor.com/install -fsS | bash',
} as const;

const fxSource = {
  type: 'install-command',
  command: 'curl -fsSL https://fx.sh/setup.sh | bash',
} as const;
```

该命令在 `set -euo pipefail` 和私有 `HOME` 下运行。所有持久安装文件必须保留在该 `HOME` 下。命令必须将 `executable` 安装到 `$HOME/.local/bin`；适配器会在不使用 shell 的情况下启动该确定性路径，并且不会回退到沙箱中已存在的命令。

安装命令不提供自动版本固定。成功的引导会被缓存，并且确切的命令参与引导和生命周期标识。请将该命令视为可执行配置，不要在其中嵌入凭据，因为引导配方会被持久化。

## 认证

当 `providerAuthentication` 定义了底层 ACP 实现如何接受 Gateway 配置时，支持 AI Gateway 认证。适配器读取以下环境变量：

- `VERCEL_OIDC_TOKEN`
- `AI_GATEWAY_API_KEY`
- `AI_GATEWAY_BASE_URL`

使用默认的 `auth: 'auto'` 时，当 `AI_GATEWAY_API_KEY` 或 `VERCEL_OIDC_TOKEN` 可用时，适配器使用 AI Gateway，否则使用直接认证。

在运行时解析凭据的应用程序可以传递这些凭据，而无需修改 `process.env`：

```ts
const harness = createACP({
  // ...implementation settings
  auth: {
    AI_GATEWAY_API_KEY: await resolveGatewayToken(),
    AI_GATEWAY_BASE_URL: 'https://ai-gateway.vercel.sh',
  },
});
```

提供的记录会替换用于认证发现的宿主环境。`credentialEnv` 从此记录读取，而 `forwardEnv` 继续从宿主读取非认证运行时配置。凭据值不包含在引导和生命周期标识中。

对于直接认证，请使用底层 ACP 实现读取的宿主环境变量名配置 `credentialEnv`，并使用 `credentialBrokering` 将其值映射到出站请求头。当网络沙箱支持附加请求转换时，ACP 进程看到的是来自 `sandboxEnv` 的值，默认情况下这些是临时占位符。真实值会在请求离开沙箱后注入，并且仅在请求包含精确预期值时注入。不支持该能力的沙箱保留转发真实值的旧行为。仅将 `forwardEnv` 用于非凭据运行时配置。

### Gateway 环境

将 `providerAuthentication.gateway.env` 设置为底层 ACP 实现用于其提供商端点、凭据和归属信息的环境变量。诸如 `gateway-api-key`、`gateway-base-url`、`gateway-authorization`、`client-app`、`client-app-name` 和 `client-app-version` 等配置值是占位符，适配器仅在选择了 Gateway 认证后才会解析它们。三个 client-app 占位符分别解析为组合的 `name/version` 标识、其名称和其版本。结构化启动环境值在解析其占位符后会被序列化为 JSON。解析后的 Gateway 环境会覆盖传递给 `credentialBrokering` 的环境中的同名直接值，因此一个回调可同时适用于两种认证模式。

## 沙箱

每个 ACP harness 都需要一个至少暴露一个端口的网络沙箱，例如 `@ai-sdk/sandbox-vercel`：

```ts
const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  ports: [4000],
  template: await agent.getSandboxTemplate(),
});
```

默认情况下，适配器使用第一个暴露的端口。在 `createACP` 上设置 `port` 以选择另一个暴露的端口。如果两者都不可用，会话启动会抛出 `HarnessCapabilityUnsupportedError`，并附带配置端口的说明。

桥接包、ACP 安装和重放状态位于会话项目之外的适配器拥有的目录中。技能会写入实现 `$HOME` 下配置的本地目录。会话工作区初始为空。

## 工具与审批

可选的 `builtinTools` 定义仅在智能体提供与工具键或 `nativeName` 匹配的程序化名称时，才对本地 ACP 工具进行分类。未匹配的本地和第三方 MCP 调用仍作为有效的提供商执行的动态工具。

宿主定义的 AI SDK 工具通过 harness 拥有的 MCP 服务器暴露，并在宿主中执行。其递归 JSON Schema 会被保留。没有 `execute` 的工具会暂停，等待调用方通过 `continueStream` 提供结果。

当 ACP 实现暴露本地权限控制时，映射全部三种 Harness 权限模式，并将不支持的模式设置为 `null`。选择 `null` 映射会抛出 `HarnessCapabilityUnsupportedError`。适配器会根据会话响应验证具体模式或配置选项。配置映射后，任何仍然发生的 ACP 权限请求都会成为 Harness 审批请求。没有映射时，适配器会自动为 `permissionMode` 允许的工具类型选择 `allow_once`，并对其余类型请求 Harness 审批。拒绝会选择 `reject_once`；持久选择永远不会被推断。宿主工具审批保持独立。

## 完整的 ACP Harness 实现

除非另有说明，这些配置通过下面显示的运行时特定环境变量支持直接认证，并通过 `AI_GATEWAY_API_KEY` 或 `VERCEL_OIDC_TOKEN` 支持 AI Gateway 认证。

### Codex ACP

Codex ACP 通过其启动环境接受 API 密钥和 JSON 会话配置。其 OpenAI 兼容端点必须以 `/v1` 结尾：

```ts
import { readFileSync } from 'node:fs';
import { createACP, type ACPPermissionModeMapping } from '@ai-sdk/harness-acp';
import { createCredentialRequestTransformation } from '@ai-sdk/harness/utils';
import { secureJsonParse } from '@ai-sdk/provider-utils';

export const codexACPHarness = createACP({
  harnessId: 'acp-codex',
  nonTextContentTypes: ['image'],
  // Define the runtime's built-in tool names and input schemas to expose
  // provider-executed calls as typed HarnessAgent tools.
  // builtinTools: { ... },
  source: {
    type: 'npm-locked',
    packageJson: readFileSync(
      new URL('./codex-acp/package.json', import.meta.url),
      'utf8',
    ),
    pnpmLockYaml: readFileSync(
      new URL('./codex-acp/pnpm-lock.yaml', import.meta.url),
      'utf8',
    ),
  },
  executable: 'codex-acp',
  modelMapping: {
    type: 'session-config-option',
    path: 'model',
  },
  forwardEnv: ['CODEX_CONFIG'],
  credentialEnv: ['CODEX_API_KEY', 'OPENAI_API_KEY'],
  credentialBrokering: ({ env, sandboxEnv }) => {
    const environmentVariableName = env.CODEX_API_KEY
      ? 'CODEX_API_KEY'
      : 'OPENAI_API_KEY';
    const credential = env[environmentVariableName];
    const sandboxCredential = sandboxEnv?.[environmentVariableName];
    if (!credential || !sandboxCredential) return [];
    const config =
      env.CODEX_CONFIG == null
        ? undefined
        : (secureJsonParse(env.CODEX_CONFIG) as {
            model_provider?: string;
            model_providers?: Record<string, { base_url?: string }>;
          });
    const baseUrl =
      config?.model_providers?.[config.model_provider ?? '']?.base_url ??
      'https://api.openai.com/v1';
    return [
      createCredentialRequestTransformation({
        matchUrl: baseUrl,
        matchHeaders: {
          Authorization: `Bearer ${sandboxCredential}`,
        },
        transformHeaders: { Authorization: `Bearer ${credential}` },
      }),
    ];
  },
  instructionMapping: {
    type: 'launch-env-json',
    variable: 'CODEX_CONFIG',
    path: ['developer_instructions'],
  },
  permissionModeMapping: {
    'allow-reads': null,
    'allow-edits': null,
    'allow-all': { type: 'session-mode', modeId: 'agent-full-access' },
  } as const satisfies ACPPermissionModeMapping,
  authentication: {
    methodId: 'api-key',
  },
  providerAuthentication: {
    gateway: {
      env: {
        CODEX_API_KEY: { $source: 'gateway-api-key' },
        CODEX_CONFIG: {
          model: 'openai/gpt-5.6-sol',
          model_provider: 'ai_gateway',
          model_providers: {
            ai_gateway: {
              name: 'AI Gateway',
              base_url: {
                $source: 'gateway-base-url',
                ensureSuffix: '/v1',
              },
              env_key: 'CODEX_API_KEY',
              wire_api: 'responses',
              supports_websockets: false,
              http_headers: {
                'User-Agent': { $source: 'client-app' },
                'x-client-app': { $source: 'client-app' },
              },
            },
          },
          model_supports_reasoning_summaries: true,
          preferred_auth_method: 'apikey',
        },
      },
    },
  },
});
```

Codex ACP 仅支持 `permissionMode: 'allow-all'`。其限制性会话模式会启用 Codex 的内部沙箱，而该沙箱不得在已提供给 `HarnessAgent` 的沙箱内运行。

`client-app` 占位符解析为带版本的 `ai-sdk-harness-acp/<version>` 标识，并同时作为 `User-Agent` 和 `x-client-app` 发送。
没有 Gateway 凭据时，此配置使用直接的 `CODEX_API_KEY` 或 `OPENAI_API_KEY` 认证。Gateway `env` 值仅在选择 Gateway 时添加到 ACP 进程，因此直接运行时配置保持不变。

### Cursor ACP

Cursor 通过 `agent acp` 暴露 ACP，并使用 Bash 安装程序而非 NPM 包安装其 CLI：

```ts
import { createACP } from '@ai-sdk/harness-acp';

export const cursorACPHarness = createACP({
  harnessId: 'cursor-acp',
  nonTextContentTypes: ['image'],
  source: {
    type: 'install-command',
    command: 'curl https://cursor.com/install -fsS | bash',
  },
  executable: 'agent',
  args: ['--disable-auto-update', 'acp'],
  modelMapping: {
    type: 'session-config-option',
    path: 'model',
  },
  clientCapabilities: {
    _meta: { parameterizedModelPicker: true },
  },
  credentialEnv: ['CURSOR_API_KEY'],
  credentialBrokering: ({ env, sandboxEnv }) => {
    if (!env.CURSOR_API_KEY || !sandboxEnv?.CURSOR_API_KEY) return [];
    return [
      {
        match: {
          host: 'api2.cursor.sh',
          path: { exact: '/auth/exchange_user_api_key' },
          method: ['POST'],
          headers: [
            {
              key: { exact: 'Authorization' },
              value: { exact: `Bearer ${sandboxEnv.CURSOR_API_KEY}` },
            },
          ],
        },
        transform: {
          headers: {
            Authorization: `Bearer ${env.CURSOR_API_KEY}`,
          },
        },
      },
    ];
  },
});
```

更新标志可防止缓存的安装在运行时自行更改。凭据代理仅限于 Cursor 的初始 API 密钥交换，因此后续请求会保留该交换返回的短期 Cursor 访问令牌。

Cursor 支持 AI Gateway。使用 AI Gateway 凭据配置 Cursor 的 OpenAI API 密钥，并将 **Override OpenAI Base URL** 设置为 `https://ai-gateway.vercel.sh/cursor/v1`。常规 Cursor CLI 继续使用 `CURSOR_API_KEY` 向 Cursor 认证；该登录与 Cursor 账户中配置的模型提供商和路由相互独立。

### Grok Build ACP

Grok Build 通过 `grok agent stdio` 直接暴露 ACP。它不会为其权限行为声明 ACP 会话模式，因此此配置省略了 `permissionModeMapping`：

```ts
import { createACP } from '@ai-sdk/harness-acp';
import { createCredentialRequestTransformation } from '@ai-sdk/harness/utils';

export const grokBuildACPHarness = createACP({
  harnessId: 'acp-grok-build',
  // Define the runtime's built-in tool names and input schemas to expose
  // provider-executed calls as typed HarnessAgent tools.
  // builtinTools: { ... },
  source: {
    type: 'install-command',
    command:
      'curl -fsSL https://x.ai/cli/install.sh | GROK_BIN_DIR="$HOME/.local/bin" bash',
  },
  executable: 'grok',
  args: ['agent', 'stdio'],
  modelMapping: {
    type: 'session-model',
    path: 'modelId',
  },
  credentialEnv: ['XAI_API_KEY'],
  credentialBrokering: ({ env, sandboxEnv }) => {
    if (!env.XAI_API_KEY || !sandboxEnv?.XAI_API_KEY) return [];
    return [
      createCredentialRequestTransformation({
        matchUrl: env.GROK_XAI_API_BASE_URL ?? 'https://api.x.ai/v1',
        matchHeaders: {
          Authorization: `Bearer ${sandboxEnv.XAI_API_KEY}`,
        },
        transformHeaders: {
          Authorization: `Bearer ${env.XAI_API_KEY}`,
        },
      }),
    ];
  },
  instructionMapping: {
    type: 'filesystem',
    path: '.grok/AGENTS.md',
  },
  providerAuthentication: {
    gateway: {
      env: {
        GROK_CLIENT_NAME: { $source: 'client-app-name' },
        GROK_CLIENT_VERSION: { $source: 'client-app-version' },
        XAI_API_KEY: { $source: 'gateway-api-key' },
        GROK_XAI_API_BASE_URL: {
          $source: 'gateway-base-url',
          ensureSuffix: '/v1',
        },
        GROK_MODELS_BASE_URL: {
          $source: 'gateway-base-url',
          ensureSuffix: '/v1',
        },
      },
    },
  },
});
```

没有 Gateway 凭据时，此配置使用直接的 `XAI_API_KEY` 认证。Gateway 环境提供客户端名称和版本归属信息。
Grok Build 在内部处理其内置的安全操作。对于通过 ACP 发送的权限请求，适配器按工具类型应用配置的 Harness `permissionMode`，并对其余请求显式审批。

## 已知限制

- ACP v1 不暴露模型步骤边界或每步用量。适配器会推断边界并报告未知的每步用量；终端提示词用量提供轮次总计。
- 标准 ACP v1 没有可移植的手动压缩或轮次中途引导 API。
- ACP v1 没有可移植的内置工具过滤 API。你仍然可以使用 `activeTools` 和 `inactiveTools` 过滤宿主执行的工具，但过滤 ACP 内置工具会抛出错误。
- 更改宿主工具目录需要 ACP 实现刷新其 MCP 工具列表。保留过期工具的实现会显式失败。
