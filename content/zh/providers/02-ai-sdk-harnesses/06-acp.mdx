# 智能体客户端协议适配器

智能体客户端协议（ACP）适配器将 `HarnessAgent` 连接到任何兼容 ACP 版本 1 的适配器。通用适配器负责桥接、ACP 客户端、主机工具中继、事件转换、审批和生命周期行为；内联配置文件描述如何安装和配置一个 ACP 运行时。

除了 ACP 适配器之外，您只需要一个提供 ACP 兼容实现的 NPM 包，例如 `@agentclientprotocol/claude-agent-acp` 或 `@agentclientprotocol/codex-acp`。然后，您可以通过几行代码配置 ACP 适配器。

<Note>
  适配器包是**实验性**的。随着这个早期 API 的进一步完善，版本之间可能会有破坏性更改。
</Note>

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-acp @ai-sdk/sandbox-vercel" />

## 基本用法

定义一个 ACP 适配器配置文件，例如下面[完整实现](#complete-acp-harness-implementations)之一，并将其传递给 `HarnessAgent`：

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { createVercelSandbox } from '@ai-sdk/sandbox-vercel';
import { codexACPHarness } from './codex-acp-harness';

const agent = new HarnessAgent({
  harness: codexACPHarness,
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
});

const session = await agent.createSession();
try {
  const result = await agent.generate({
    session,
    prompt: '检查测试失败并修复生产代码。',
  });
  console.log(result.text);
} finally {
  await session.destroy();
}
```

## 适配器设置

`createACP` 接受：

- `harnessId`：此配置文件的稳定 kebab-case 标识。
- `version`：ACP 协议版本。默认值为 `'v1'`，目前仅支持该版本。
- `source`：ACP 包的来源，可以是简单或锁定的 NPM 源。
- `executable`：要启动的包 bin 名称。
- `args`：传递给可执行文件的可选参数。
- `forwardEnv`：要转发到沙箱的主机环境变量名称。
- `env`：在引导时写入的持久环境值。
- `builtinTools`：用于静态类型和精确名称匹配的可选原生工具定义。
- `mcpServers`：按服务器名称键控的 MCP 服务器定义。
- `authentication`：通告的 ACP 身份验证方法、元数据和客户端能力。
- `auth`：下游提供商身份验证模式：
  - `auto`（默认）：当网关凭据和 `providerAuthentication` 配置可用时使用 AI Gateway；否则使用直接身份验证。
  - `direct`：始终使用直接身份验证，即使网关凭据可用。
  - `ai-gateway`：始终使用 AI Gateway，并在网关凭据不可用时抛出错误。这需要 `providerAuthentication` 配置。
- `providerAuthentication`：声明式的运行时特定网关环境。
- `modelId`：用于 Harness 元数据的已知实现模型标识符。
- `instructionMapping`：可选的从 `HarnessAgent` 指令到实现的原生系统或开发者提示词的映射。使用 `session-meta` 表示 ACP 会话请求的 `_meta` 字段下的路径，或使用 `launch-env-json` 表示 JSON 启动环境变量中的路径。省略时，指令将附加到第一个用户提示词之前。
- `permissionModeMapping`：从所有三种 Harness 权限模式到通告的 ACP 会话模式或配置选项的映射。当 ACP 实现不支持该模式时，将条目设置为 `null`。省略时，适配器按工具类型将 `permissionMode` 应用于 ACP 权限请求。
- `session.meta`：用于会话创建和恢复的可序列化实现特定元数据。
- `port`：暴露的桥接端口覆盖。
- `startupTimeoutMs`：桥接启动超时。默认值为 120 秒。
- `mintBridgeToken`：接收沙箱 ID 并返回桥接身份验证令牌的同步函数。默认情况下，适配器生成一个随机的 32 字节令牌。自定义实现必须返回适当机密的令牌。
- `clientApp`：可选的客户端归属信息，包含 `name` 和 `version`。默认值为已安装的 `ai-sdk/harness-acp/<version>` 标识，可用于网关环境占位符。

运行时特定的包名称、环境变量、模式和会话元数据属于内联配置文件，而不是通用适配器。

### 包源

简单的 NPM 源按名称安装单个包：

```ts
const source = {
  type: 'npm-simple',
  packageName: '@agentclientprotocol/codex-acp',
  packageVersion: '1.1.4',
} as const;
```

`packageVersion` 是可选的，提供时必须为精确版本。省略它将安装包的 `latest` dist-tag。省略版本也不会影响适配器标识，因此新的上游版本不会使现有的生命周期状态失效。

简单源仅固定请求的 ACP 包，而其传递依赖在沙箱引导时解析。要冻结完整安装，请使用锁定源并提供 `package.json` 及其 `pnpm-lock.yaml` 的内容：

```ts
const source = {
  type: 'npm-locked',
  packageJson: packageJsonContents,
  pnpmLockYaml: pnpmLockYamlContents,
} as const;
```

锁定源使用 `pnpm install --frozen-lockfile` 安装提供的文件。

## 身份验证

当 `providerAuthentication` 定义了底层 ACP 实现如何接受网关配置时，支持 AI Gateway 身份验证。适配器读取以下环境变量：

- `VERCEL_OIDC_TOKEN`
- `AI_GATEWAY_API_KEY`
- `AI_GATEWAY_BASE_URL`

使用默认的 `auth: 'auto'`，当 `AI_GATEWAY_API_KEY` 或 `VERCEL_OIDC_TOKEN` 可用时，适配器使用 AI Gateway，否则使用直接身份验证。

对于直接身份验证，使用 `forwardEnv` 配置底层 ACP 实现读取的主机环境变量名称。这些变量被列入白名单并原样转发到 ACP 进程。它们的名称取决于 ACP 实现。凭据值在运行时解析，不存储在配置文件中。

### 网关环境

将 `providerAuthentication.gateway.env` 设置为底层 ACP 实现用于其提供商端点、凭据和归属的环境变量。配置文件值如 `gateway-api-key`、`gateway-base-url`、`gateway-authorization`、`client-app`、`client-app-name` 和 `client-app-version` 是占位符，适配器仅在选择网关身份验证后解析。三个 client-app 占位符分别解析为组合的 `name/version` 标识、其名称和其版本。结构化启动环境值在其占位符解析后序列化为 JSON。

## 沙箱

每个 ACP 适配器都需要一个至少暴露一个端口的网络沙箱，例如 `@ai-sdk/sandbox-vercel`：

```ts
const sandbox = createVercelSandbox({
  runtime: 'node24',
  ports: [4000],
});
```

默认情况下，适配器使用第一个暴露的端口。在 `createACP` 上设置 `port` 以选择另一个暴露的端口。如果两者都不可用，会话启动将抛出 `HarnessCapabilityUnsupportedError`，并附带配置说明。

桥接包、ACP 安装、状态、重放日志和投影技能位于适配器拥有的目录中，位于会话项目之外。会话工作区以空状态开始。

## 工具与审批

可选的 `builtinTools` 定义仅在智能体提供与工具键或 `nativeName` 匹配的程序化名称时对原生 ACP 工具进行分类。未匹配的原生和第三方 MCP 调用仍然是有效的提供商执行的动态工具。

主机定义的 AI SDK 工具通过适配器拥有的 MCP 服务器暴露并在主机中执行。它们的递归 JSON Schema 被保留。没有 `execute` 的工具通过 `continueStream` 暂停等待调用方提供的结果。

当 ACP 实现暴露原生权限控制时，映射所有三种 Harness 权限模式，并将不支持的模式设置为 `null`。选择 `null` 映射会抛出 `HarnessCapabilityUnsupportedError`。适配器根据会话响应验证具体模式或配置选项。配置映射后，仍然发生的任何 ACP 权限请求都会成为 Harness 审批请求。没有映射时，适配器自动为 `permissionMode` 允许的工具类型选择 `allow_once`，并为其余请求 Harness 审批。拒绝选择 `reject_once`；从不推断持久选择。主机工具审批保持独立。

## 完整的 ACP 适配器实现

这些配置文件支持通过下面显示的运行时特定环境变量进行直接身份验证，以及通过 `AI_GATEWAY_API_KEY` 或 `VERCEL_OIDC_TOKEN` 进行 AI Gateway 身份验证。

### Claude Code ACP

Claude Code 接受 Anthropic 兼容的网关根 URL，不带 `/v1`。此配置文件使用运行时支持的启动环境：

```ts
import { createACP, type ACPPermissionModeMapping } from '@ai-sdk/harness-acp';

export const claudeCodeACPHarness = createACP({
  harnessId: 'acp-claude-code',
  // 定义运行时的内置工具名称和输入模式，以将提供商执行的调用暴露为类型化的 HarnessAgent 工具。
  // builtinTools: { ... },
  source: {
    type: 'npm-simple',
    packageName: '@agentclientprotocol/claude-agent-acp',
    packageVersion: '0.61.0',
  },
  executable: 'claude-agent-acp',
  forwardEnv: ['ANTHROPIC_API_KEY', 'ANTHROPIC_AUTH_TOKEN'],
  env: {
    IS_SANDBOX: '1',
  },
  instructionMapping: {
    type: 'session-meta',
    path: ['systemPrompt', 'append'],
  },
  permissionModeMapping: {
    'allow-reads': { type: 'session-mode', modeId: 'default' },
    'allow-edits': { type: 'session-mode', modeId: 'acceptEdits' },
    'allow-all': { type: 'session-mode', modeId: 'bypassPermissions' },
  } as const satisfies ACPPermissionModeMapping,
  providerAuthentication: {
    gateway: {
      env: {
        ANTHROPIC_API_KEY: { $source: 'gateway-api-key' },
        ANTHROPIC_AUTH_TOKEN: { $source: 'gateway-api-key' },
        ANTHROPIC_BASE_URL: { $source: 'gateway-base-url' },
        CLAUDE_AGENT_SDK_CLIENT_APP: { $source: 'client-app' },
      },
    },
  },
});
```

没有网关凭据时，此配置文件使用直接的 `ANTHROPIC_API_KEY` 或 `ANTHROPIC_AUTH_TOKEN` 身份验证。网关环境通过 Claude 支持的 `CLAUDE_AGENT_SDK_CLIENT_APP` 设置提供版本化归属。`IS_SANDBOX` 允许 Claude Code ACP 在沙箱进程以 root 身份运行时通告 `bypassPermissions`。

### Codex ACP

Codex ACP 通过其启动环境接受 API 密钥和 JSON 会话配置。其 OpenAI 兼容端点必须以 `/v1` 结尾：

```ts
import { createACP, type ACPPermissionModeMapping } from '@ai-sdk/harness-acp';

export const codexACPHarness = createACP({
  harnessId: 'acp-codex',
  // 定义运行时的内置工具名称和输入模式，以将提供商执行的调用暴露为类型化的 HarnessAgent 工具。
  // builtinTools: { ... },
  source: {
    type: 'npm-simple',
    packageName: '@agentclientprotocol/codex-acp',
    packageVersion: '1.1.4',
  },
  executable: 'codex-acp',
  forwardEnv: ['CODEX_API_KEY', 'OPENAI_API_KEY'],
  instructionMapping: {
    type: 'launch-env-json',
    variable: 'CODEX_CONFIG',
    path: ['developer_instructions'],
  },
  permissionModeMapping: {
    'allow-reads': null,
    'allow-edits': null,
    'allow-all': { type: 'session-mode', modeId: 'agent-full-access' },
  } as const satisfies ACPPermissionModeMapping,
  authentication: {
    methodId: 'api-key',
  },
  providerAuthentication: {
    gateway: {
      env: {
        CODEX_API_KEY: { $source: 'gateway-api-key' },
        CODEX_CONFIG: {
          model: 'openai/gpt-5.6-sol',
          model_provider: 'ai_gateway',
          model_providers: {
            ai_gateway: {
              name: 'AI Gateway',
              base_url: {
                $source: 'gateway-base-url',
                ensureSuffix: '/v1',
              },
              env_key: 'CODEX_API_KEY',
              wire_api: 'responses',
              supports_websockets: false,
              http_headers: {
                'User-Agent': { $source: 'client-app' },
                'x-client-app': { $source: 'client-app' },
              },
            },
          },
          model_supports_reasoning_summaries: true,
          preferred_auth_method: 'apikey',
        },
      },
    },
  },
});
```

Codex ACP 仅支持 `permissionMode: 'allow-all'`。其限制性会话模式启用 Codex 的内部沙箱，该沙箱不得在已提供给 `HarnessAgent` 的沙箱内运行。

`client-app` 占位符解析为带版本的 `ai-sdk/harness-acp/<version>` 标识，并将其作为 `User-Agent` 和 `x-client-app` 发送。
没有网关凭据时，此配置文件使用直接的 `CODEX_API_KEY` 或 `OPENAI_API_KEY` 身份验证。网关 `env` 值仅在选择网关时添加到 ACP 进程，因此直接运行时配置保持不变。

### Grok Build ACP

Grok Build 通过 `grok agent stdio` 直接暴露 ACP。它不为权限行为通告 ACP 会话模式，因此此配置文件省略了 `permissionModeMapping`：

```ts
import { createACP } from '@ai-sdk/harness-acp';

export const grokBuildACPHarness = createACP({
  harnessId: 'acp-grok-build',
  // 定义运行时的内置工具名称和输入模式，以将提供商执行的调用暴露为类型化的 HarnessAgent 工具。
  // builtinTools: { ... },
  source: {
    type: 'npm-simple',
    packageName: '@xai-official/grok',
    packageVersion: '0.2.111',
  },
  executable: 'grok',
  args: ['agent', 'stdio'],
  forwardEnv: ['XAI_API_KEY'],
  instructionMapping: {
    type: 'session-meta',
    path: ['rules'],
  },
  providerAuthentication: {
    gateway: {
      env: {
        GROK_CLIENT_NAME: { $source: 'client-app-name' },
        GROK_CLIENT_VERSION: { $source: 'client-app-version' },
        XAI_API_KEY: { $source: 'gateway-api-key' },
        GROK_XAI_API_BASE_URL: {
          $source: 'gateway-base-url',
          ensureSuffix: '/v1',
        },
        GROK_MODELS_BASE_URL: {
          $source: 'gateway-base-url',
          ensureSuffix: '/v1',
        },
      },
    },
  },
});
```

没有网关凭据时，此配置文件使用直接的 `XAI_API_KEY` 身份验证。网关环境提供客户端名称和版本归属。Grok Build 在内部处理其内置的安全操作。对于通过 ACP 发送的权限请求，适配器按工具类型应用配置的 Harness `permissionMode`，并为其余请求显式审批。

## 已知限制

- ACP v1 不暴露模型步骤边界或每步使用量。适配器推断边界并报告未知的每步使用量；终端提示词使用量提供回合总数。
- 标准 ACP v1 没有可移植的手动压缩或回合中转向 API。
- ACP v1 没有可移植的内置工具过滤 API。您仍然可以使用 `activeTools` 和 `inactiveTools` 过滤主机执行的工具，但过滤 ACP 内置工具将抛出错误。
- 主机工具目录的更改要求 ACP 实现刷新其 MCP 工具列表。保留过时工具的实现将显式失败。
