# Pi Harness

Pi harness 适配器将 `HarnessAgent` 连接到
`@earendil-works/pi-coding-agent`。Pi 运行在宿主 Node.js 进程中，并将
沙箱用作远程文件系统和 shell。它不会在沙箱内安装桥接程序。

<Note>
  Harness 包目前处于**实验阶段**。由于这一早期 API 仍在进一步完善，
  各版本之间可能会出现破坏性变更。
</Note>

## 设置

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-pi @ai-sdk/sandbox-vercel" />

## 导入

```ts
import { pi, createPi } from '@ai-sdk/harness-pi';
```

`pi` 等同于使用默认配置的 `createPi()`。

## 基本用法

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { pi } from '@ai-sdk/harness-pi';
import { createVercelNetworkSandboxSession } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: pi,
  model: 'anthropic/claude-sonnet-4.6',
});

const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  template: await agent.getSandboxTemplate(),
});
const session = await agent.createSession({ sandboxSession });

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: 'Check the test failures and fix the production code.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
  process.exit(exitCode);
}
```

要使用此智能体，请确保环境变量中包含用于 Vercel Sandbox 的
`VERCEL_OIDC_TOKEN`，以及 [身份验证](#authentication) 下列出的
Pi 所需变量之一。

## 适配器设置

使用 `createPi()` 配置运行时：

```ts
const harness = createPi({
  thinkingLevel: 'medium',
});
```

设置项：

- `auth`：身份验证模式（`auto`、`openai`、`anthropic`、`custom` 或
  `ai-gateway`）或隔离的身份验证环境。
- `cacheRetention`：模型请求的默认提示词缓存保留策略（`none`、
  `short` 或 `long`）。对于 Anthropic 模型，`long` 使用 1 小时缓存，
  而非默认的 5 分钟。
- `credentials`：应用程序拥有的 Pi 凭据存储。它会替换基于文件的
  `auth.json` 存储，并支持持久化的数据库后端凭据。
- `extensionFactories`：受信任的内联 Pi 扩展工厂，运行在宿主
  Node.js 进程中。
- `fileToolPathPolicy`：Pi 原生文件工具可以读取的额外沙箱根目录，
  以及它们必须拒绝的根目录。参见 [文件工具路径](#file-tool-paths)。
- `mcpServers`：以服务器名称为键的 MCP 服务器定义。
- `mcpSettings`：为 `mcpServers` 提供服务的 MCP 适配器设置，会覆盖
  包默认值。`toolPrefix`（`mcp`、`server`、`short` 或 `none`）
  设置 MCP 工具名称的前缀方式，默认为 `mcp`；只有带 `mcp` 前缀的
  工具调用才会被报告为提供商执行的动态工具，并带有解析后的 JSON
  结果。`outputGuard` 默认为 `true`；此时适配器会截断超过 50 KiB
  或 2,000 行的工具结果，并将完整文本写入宿主临时目录，而 Pi 的
  沙箱文件工具无法读取该目录。将其设置为 `false` 可返回完整结果。
- `providers`：用于自定义模型的显式 Pi 提供商配置。
- `reattachInProcess`：挂起的轮次是否可以在当前进程中复用其实时
  Pi 会话。默认为 `true`。
- `thinkingLevel`：Pi 思考级别（`off`、`minimal`、`low`、`medium`、
  `high`、`xhigh` 或 `max`）。

## 文件工具路径

默认情况下，Pi 的原生文件工具（`read`、`write`、`edit`、`ls`、`find`
和 `grep`）仅限于会话工作区，只读工具还可以读取 harness 技能目录。
使用 `fileToolPathPolicy` 更改它们可以访问的范围：

```ts
const harness = createPi({
  fileToolPathPolicy: {
    readableRoots: ['/home/vercel-sandbox', '/tmp'],
    deniedRoots: ['/home/vercel-sandbox/.credentials'],
  },
});
```

- `readableRoots`：除默认目录外，`read`、`ls`、`find` 和 `grep`
  可以访问的绝对沙箱目录。它们不会变为可写。
- `deniedRoots`：所有原生文件工具都会拒绝的绝对沙箱目录，即使在
  工作区内或可读根目录内也是如此。请求的路径和被拒绝的根目录都会
  在沙箱中解析，因此指向被拒绝根目录或从被拒绝根目录指向外部的
  符号链接都会被拒绝。被拒绝的根目录在 Pi 会话启动时解析；如果被
  拒绝的符号链接更改了目标，请启动新会话。`find` 和 `grep` 在搜索
  父目录时会跳过被拒绝的根目录。`grep` 按目录名跳过它们，因此它
  也会跳过被搜索目录下同名的其他目录。

当设置了此配置时，工具路径中开头的 `~` 会展开为沙箱主目录。

该策略仅适用于 Pi 的原生文件工具。`bash` 工具不受其限制，因此
不要将 `deniedRoots` 视为智能体所运行命令的安全边界。

## 内联扩展

使用 `extensionFactories` 为每个 harness 会话加载受信任的内联 Pi
扩展：

```ts
const harness = createPi({
  extensionFactories: [
    pi => {
      pi.on('agent_start', () => {
        console.log('Pi agent started');
      });
    },
  ],
});
```

轮次之间的常规资源刷新会复用活动的扩展运行时，不会重新初始化工厂。
如果底层 Pi 会话被重建，工厂会为新的 Pi 运行时再次初始化。

扩展工厂在宿主 Node.js 进程中执行，可以访问宿主环境，因此只传入
你信任的工厂。此设置仅启用你显式提供的工厂。文件系统扩展发现保持
禁用，包括用户、项目和基于设置的扩展。主题和提示词模板也保持禁用。

## 会话重新附加

默认情况下，当传入请求具有兼容的设置和运行时资源时，Pi 会在同一
进程中保持挂起的轮次处于活动状态，以便高效地继续。请求作用域设置
或沙箱句柄发生变化会导致从持久化的生命周期状态进行冷恢复。

对于无状态或多副本应用程序，请禁用进程内重新附加，以便每次继续
都使用当前请求的设置恢复持久化的生命周期状态：

```ts
const harness = createPi({
  reattachInProcess: false,
});
```

传入的已完成 `resume-session` 状态始终优先于进程中较旧的实时挂起
轮次。

## 身份验证

`auth` 设置选择 Pi 从宿主环境读取哪些凭据：

- `auto`（默认）：在可用时使用 AI Gateway 凭据，然后回退到环境中
  找到的所有提供商凭据。
- `openai`：使用 `OPENAI_API_KEY` 以及可选的 `OPENAI_BASE_URL`。
- `anthropic`：使用 `ANTHROPIC_API_KEY` 以及可选的
  `ANTHROPIC_AUTH_TOKEN` 和 `ANTHROPIC_BASE_URL`。
- `custom`：注册通过环境变量配置的所有提供商。
- `ai-gateway`：使用 `AI_GATEWAY_API_KEY` 或 `VERCEL_OIDC_TOKEN`
  以及可选的 `AI_GATEWAY_BASE_URL`。

如果未设置适用的凭据环境变量，除非选择了 AI Gateway 身份验证，
否则适配器会尝试从宿主系统解析原生订阅。

```ts
const harness = createPi({ auth: 'ai-gateway' });
```

传入身份验证环境以使用以编程方式解析的凭据，而无需读取
`process.env`：

```ts
const harness = createPi({
  auth: {
    MISTRAL_API_KEY: await resolveMistralToken(),
    MISTRAL_BASE_URL: 'https://api.mistral.ai',
  },
});
```

提供的记录会替换用于身份验证发现的宿主环境。Pi 会从该记录中解析
提供商 API 密钥和基础 URL。

对于在环境变量或文件之外管理的凭据，请注入应用程序拥有的凭据存储。
Pi 通过此接口执行凭据读取、刷新和更新：

```ts
import { createPi, type PiCredentialStore } from '@ai-sdk/harness-pi';

declare const credentials: PiCredentialStore;

const harness = createPi({
  credentials,
  reattachInProcess: false,
});
```

`credentials` 会替换 Pi 的 `auth.json` 存储。在请求作用域或多副本
部署中，请将其与 `reattachInProcess: false` 搭配使用，以便每次继续
都根据当前请求构建模型运行时。

使用 `custom` 时，标准提供商使用诸如 `OPENAI_API_KEY`、
`OPENAI_BASE_URL`、`ANTHROPIC_API_KEY` 和 `ANTHROPIC_BASE_URL`
等环境变量。其他提供商使用 `<PREFIX>_API_KEY` 和匹配的
`<PREFIX>_BASE_URL` 对。

身份验证变量不会标识提供商的 API 协议或模型。使用自定义模型时，
请显式注册该元数据：

```ts
const harness = createPi({
  auth: {
    MYPROVIDER_API_KEY: await resolveMyProviderToken(),
    MYPROVIDER_BASE_URL: 'https://api.example.com/v1',
  },
  providers: {
    myprovider: {
      api: 'openai-completions',
      models: [
        {
          id: 'my-custom-model',
          name: 'My Custom Model',
          reasoning: false,
          input: ['text'],
          cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 },
          contextWindow: 128_000,
          maxTokens: 16_384,
        },
      ],
    },
  },
});
```

## 沙箱

Pi 需要沙箱会话，但不需要暴露端口。你可以创建 Vercel 网络会话或
本地 just-bash 会话：

```ts
const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  template: await agent.getSandboxTemplate(),
});
```

## 内置工具

适配器通过 `agent.tools` 暴露以下常见的 Pi 内置工具：

- `read`
- `write`
- `edit`
- `bash`
- `grep`
- `glob`
- `ls`

当其他 Pi 内置工具不符合常见工具形态时，它们也可能出现在
`agent.tools` 中。

当 `permissionMode` 为 `allow-reads` 或 `allow-edits` 时，Pi 支持
内置工具审批请求。

## 已知限制

Pi 不支持结构化输出。向 `HarnessAgent` 提供 `output` 会导致该轮次
抛出 `HarnessCapabilityUnsupportedError`。
