# Pi Harness

Pi harness 适配器将 `HarnessAgent` 连接到
`@earendil-works/pi-coding-agent`。Pi 运行在宿主 Node.js 进程中，并将沙箱用作远程文件系统和 shell。它不会在沙箱内安装桥接程序。

<Note>
  Harness 包处于**实验性**阶段。随着这一早期 API 的进一步完善，版本之间可能会出现破坏性变更。
</Note>

## 设置

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-pi @ai-sdk/sandbox-vercel" />

## 导入

```ts
import { pi, createPi } from '@ai-sdk/harness-pi';
```

`pi` 等同于使用默认配置的 `createPi()`。

## 基本用法

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { pi } from '@ai-sdk/harness-pi';
import { createVercelNetworkSandboxSession } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: pi,
  model: 'anthropic/claude-sonnet-4.6',
});

const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  template: await agent.getSandboxTemplate(),
});
const session = await agent.createSession({ sandboxSession });

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: 'Check the test failures and fix the production code.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
  process.exit(exitCode);
}
```

要使用此智能体，请确保环境变量中包含用于 Vercel Sandbox 的 `VERCEL_OIDC_TOKEN`，以及 [身份验证](#authentication) 下列出的、用于 Pi 的变量之一。

## 适配器设置

使用 `createPi()` 配置运行时：

```ts
const harness = createPi({
  thinkingLevel: 'medium',
});
```

设置项：

- `auth`：身份验证模式（`auto`、`openai`、`anthropic`、`custom` 或
  `ai-gateway`），或一个隔离的身份验证环境。
- `cacheRetention`：模型请求的默认提示词缓存保留策略（`none`、
  `short` 或 `long`）。对于 Anthropic 模型，`long` 使用 1 小时缓存，
  而非默认的 5 分钟缓存。
- `credentials`：由应用拥有的 Pi 凭据存储。它会替换基于文件的
  `auth.json` 存储，并支持持久化的、由数据库支持的凭据。
- `extensionFactories`：在宿主 Node.js 进程中运行的受信任内联 Pi 扩展工厂。
- `fileToolPathPolicy`：Pi 原生文件工具可读取或写入的额外沙箱根目录，
  以及它们必须拒绝的根目录。参见 [文件工具路径](#file-tool-paths)。
- `mcpServers`：以服务器名称为键的 MCP 服务器，由 Pi 原生 MCP 支持提供。
  每个条目都是 Pi 的 MCP 服务器配置，可以是 stdio
  （`command`、`args`、`env`、`cwd`）或可流式传输的 HTTP（`url`、`headers`）。
  工具命名为 `mcp__<server>__<tool>`，其中任一名称中的 `-` 都会替换为
  `_`。`exposure` 默认为 `direct`，即向模型声明服务器的工具；使用 `deferred` 时，
  模型先通过 Pi 的 `tool_search` 工具找到它们。不支持 Pi 的 `codemode` 暴露方式。
  使用该方式的条目，或被 Pi 拒绝的条目，会导致会话启动失败。Pi 会截断超过 20 KB 的文本结果，
  并将完整文本写入宿主临时目录。该 harness 没有登录流程，因此需要身份验证的 HTTP 服务器
  必须携带 `Authorization` 头或 `auth.provider`。
- `mcpSettings`：已弃用。Pi 原生 MCP 没有工具前缀或输出保护设置，因此
  `toolPrefix` 不是 `mcp`，或 `outputGuard: false`，会导致会话启动失败。
- `providers`：用于自定义模型的显式 Pi 提供商配置。
- `reattachInProcess`：挂起的轮次是否可以在当前进程中复用其活动的 Pi 会话。
  默认为 `true`。
- `thinkingLevel`：Pi 思考级别（`off`、`minimal`、`low`、`medium`、
  `high`、`xhigh` 或 `max`）。

## 文件工具路径

默认情况下，Pi 的原生文件工具（`read`、`write`、`edit`、`ls`、`find` 和
`grep`）仅限于会话工作区，只读工具还可以读取 harness 技能目录。使用
`fileToolPathPolicy` 更改它们可以访问的范围：

```ts
const harness = createPi({
  fileToolPathPolicy: {
    readableRoots: ['/home/vercel-sandbox'],
    writableRoots: ['/tmp', '/mnt/artifacts'],
    deniedRoots: ['/home/vercel-sandbox/.credentials'],
  },
});
```

- `readableRoots`：除默认目录外，`read`、`ls`、`find` 和
  `grep` 可以访问的绝对沙箱目录。这些目录不会变为可写。
- `writableRoots`：除工作区外，`write` 和 `edit` 可以访问的绝对沙箱目录。
  可写根目录也可读。
- `deniedRoots`：所有原生文件工具都会拒绝的绝对沙箱目录，
  即使位于工作区或可读根目录内也是如此。请求路径和被拒绝的根目录都会在沙箱中解析，
  因此指向被拒绝根目录或从被拒绝根目录指向外部的符号链接都会被拒绝。配置的根目录会在每次文件操作时
  重新解析；会话启动时捕获的规范化被拒绝根目录仍保持被拒绝状态。
  `find` 和 `grep` 会剪除精确匹配的被拒绝路径，且不跟随目录符号链接，
  而 `ls` 会隐藏直接被拒绝的条目。其他同名目录仍可访问。

每个配置的根目录都必须是绝对沙箱路径。被拒绝的根目录优先于工作区、harness 技能目录和允许的根目录。
在工作区外写入不会发出工作区 `file-change` 事件。

当存在该设置时，工具路径中的前导 `~` 会展开为沙箱主目录。

该策略仅适用于 Pi 的原生文件工具。`bash` 工具不受其限制，因此不要将 `deniedRoots` 视为智能体所运行命令的安全边界。

## 内联扩展

使用 `extensionFactories` 为每个 harness 会话加载受信任的内联 Pi 扩展：

```ts
const harness = createPi({
  extensionFactories: [
    pi => {
      pi.on('agent_start', () => {
        console.log('Pi agent started');
      });
    },
  ],
});
```

每个工厂还会收到其运行所在的 harness 会话作为第二个参数：

- `sandboxSession`：会话的沙箱，仅限于 harness 工具可使用的操作。
- `sessionWorkDir`：会话工作的沙箱目录。
- `instructions()`：当前轮次的指令。指令随每个轮次到达，因此应在轮次运行时调用它，
  而不是在工厂运行时调用。

```ts
const harness = createPi({
  extensionFactories: [
    (pi, session) => {
      pi.on('agent_start', async () => {
        const { stdout } = await session.sandboxSession.run({
          command: `git -C ${session.sessionWorkDir} status --short`,
        });
        console.log(session.instructions(), stdout);
      });
    },
  ],
});
```

仅接收 Pi API 的工厂可以保持不变继续工作。

轮次之间的常规资源刷新会复用活动的扩展运行时，不会重新初始化工厂。如果底层 Pi 会话被重建，
工厂会为新 Pi 运行时再次初始化。

扩展工厂在宿主 Node.js 进程中执行，并可访问宿主环境，因此只传入你信任的工厂。此设置仅启用你显式提供的工厂。
文件系统扩展发现仍处于禁用状态，包括用户、项目和基于设置的扩展。主题和提示词模板也仍处于禁用状态。

## 会话重新附加

默认情况下，当传入请求具有兼容的设置和运行时资源时，Pi 会在同一进程中保持挂起的轮次存活，以便高效继续。
请求作用域设置或沙箱句柄发生变化会导致从持久化的生命周期状态进行冷恢复。

对于无状态或多副本应用，请禁用进程内重新附加，以便每次继续都使用当前请求的设置恢复持久化的生命周期状态：

```ts
const harness = createPi({
  reattachInProcess: false,
});
```

传入的已完成 `resume-session` 状态始终优先于进程中较旧的活动挂起轮次。

## 身份验证

`auth` 设置选择 Pi 从宿主环境读取哪些凭据：

- `auto`（默认）：在可用时使用 AI Gateway 凭据，然后回退到环境中找到的所有提供商凭据。
- `openai`：使用 `OPENAI_API_KEY` 和可选的 `OPENAI_BASE_URL`。
- `anthropic`：使用 `ANTHROPIC_API_KEY` 以及可选的
  `ANTHROPIC_AUTH_TOKEN` 和 `ANTHROPIC_BASE_URL`。
- `custom`：注册通过环境变量配置的所有提供商。
- `ai-gateway`：使用 `AI_GATEWAY_API_KEY` 或 `VERCEL_OIDC_TOKEN` 以及
  可选的 `AI_GATEWAY_BASE_URL`。

如果未设置适用的凭据环境变量，除非选择了 AI Gateway 身份验证，否则适配器会尝试从宿主系统解析原生订阅。

```ts
const harness = createPi({ auth: 'ai-gateway' });
```

传入身份验证环境，以使用以编程方式解析的凭据而不读取 `process.env`：

```ts
const harness = createPi({
  auth: {
    MISTRAL_API_KEY: await resolveMistralToken(),
    MISTRAL_BASE_URL: 'https://api.mistral.ai',
  },
});
```

提供的记录会替换用于身份验证发现的宿主环境。Pi 会从该记录中解析提供商 API 密钥和基础 URL。

对于在环境变量或文件之外管理的凭据，请注入由应用拥有的凭据存储。Pi 通过此接口执行凭据读取、刷新和更新：

```ts
import { createPi, type PiCredentialStore } from '@ai-sdk/harness-pi';

declare const credentials: PiCredentialStore;

const harness = createPi({
  credentials,
  reattachInProcess: false,
});
```

`credentials` 会替换 Pi 的 `auth.json` 存储。在请求作用域或多副本部署中，请将其与
`reattachInProcess: false` 搭配使用，以便每次继续都根据当前请求构建模型运行时。

使用 `custom` 时，标准提供商使用诸如
`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`ANTHROPIC_API_KEY` 和
`ANTHROPIC_BASE_URL` 的环境变量。其他提供商使用 `<PREFIX>_API_KEY` 和匹配的
`<PREFIX>_BASE_URL` 对。

身份验证变量不会标识提供商的 API 协议或模型。使用自定义模型时，请显式注册该元数据：

```ts
const harness = createPi({
  auth: {
    MYPROVIDER_API_KEY: await resolveMyProviderToken(),
    MYPROVIDER_BASE_URL: 'https://api.example.com/v1',
  },
  providers: {
    myprovider: {
      api: 'openai-completions',
      models: [
        {
          id: 'my-custom-model',
          name: 'My Custom Model',
          reasoning: false,
          input: ['text'],
          cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 },
          contextWindow: 128_000,
          maxTokens: 16_384,
        },
      ],
    },
  },
});
```

## 沙箱

Pi 需要沙箱会话，但不需要暴露端口。你可以创建 Vercel 网络会话或本地 just-bash 会话：

```ts
const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  template: await agent.getSandboxTemplate(),
});
```

## 内置工具

适配器通过 `agent.tools` 暴露以下常见 Pi 内置工具：

- `read`
- `write`
- `edit`
- `bash`
- `grep`
- `glob`
- `ls`

当其他 Pi 内置工具不符合常见工具形态时，它们也可能出现在 `agent.tools` 中。

当 `permissionMode` 为 `allow-reads` 或 `allow-edits` 时，Pi 支持内置工具审批请求。

## 已知限制

Pi 不支持结构化输出。向 `HarnessAgent` 提供 `output` 会导致该轮次抛出
`HarnessCapabilityUnsupportedError`。

Pi 不支持在图像部分之后包含文本部分的用户消息；所有文本都必须出现在第一张图像之前。
