# fx 工具链

fx 工具链适配器通过 Agent Client Protocol (ACP) 将 `HarnessAgent` 连接到 [fx](https://fx.sh)。该适配器将安装、会话、流式传输、工具和生命周期管理委托给 `@ai-sdk/harness-acp`。

<Note>
  工具链包是**实验性**的。随着这个早期 API 的进一步完善，版本之间可能会有破坏性变更。
</Note>

## 设置

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-fx @ai-sdk/sandbox-vercel" />

当第一个会话启动时，ACP 工具链会在沙箱内运行 [标准 fx 安装程序](https://fx.sh/docs/getting-started/installation)。安装程序会跟踪最新的 fx 版本，并将可执行文件安装到 ACP 实现的私有主目录中。

## 导入

```ts
import { createFx, fx } from '@ai-sdk/harness-fx';
```

`fx` 等同于使用默认配置的 `createFx()`。

## 基本用法

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { fx } from '@ai-sdk/harness-fx';
import { createVercelSandbox } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: fx,
  model: 'openai/gpt-5.6-luna',
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
});

const session = await agent.createSession();

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: '检查测试失败并修复生产代码。',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  process.exit(exitCode);
}
```

## 适配器设置

使用 `createFx()` 配置运行时：

```ts
const harness = createFx({
  auth: 'ai-gateway',
  port: 4001,
  startupTimeoutMs: 180_000,
});
```

设置：

- `auth`：选择 `auto`、`direct` 或 `ai-gateway` 认证，或接受用于以编程方式解析凭据的认证环境。fx 始终通过 Vercel AI Gateway 发送模型请求，因此 `direct` 和 `ai-gateway` 的区别仅在于工具链如何将 Gateway 凭据传递到沙箱中。
- `credentialForwarding`：可选的同步或异步回调，用于在工具链适配器将每个凭据转发到沙箱进程之前对其进行自定义。它接收原本会被转发的凭据值（真实凭据或掩码值）以及用于暴露该凭据的环境变量名称。此回调仅控制转发到沙箱进程的值。它不限制工具链适配器在主机进程中可以发现、读取或以其他方式访问哪些凭据。
- `mcpServers`：按服务器名称键控的 MCP 服务器定义。fx ACP 会话仅使用 ACP 客户端提供的服务器。
- `port`：ACP 桥接端口覆盖。
- `portEndpoint`：当沙箱会话无法直接暴露端口时，ACP 桥接的主机端点。
- `startupTimeoutMs`：等待 ACP 桥接启动的最长时间。
- `mintBridgeToken`：接收沙箱 ID 并返回 ACP 桥接认证令牌的同步函数。默认情况下，适配器会生成一个随机的 32 字节令牌。

适配器固定了安装源、可执行文件、启动命令和 ACP 版本。这些实现细节无法通过 `createFx()` 覆盖。

## 认证

fx 使用 [Vercel AI Gateway 认证](https://fx.sh/docs/getting-started/authentication)。设置以下环境变量之一：

- `VERCEL_OIDC_TOKEN`
- `AI_GATEWAY_API_KEY`

当两者都可用时，fx 优先使用 `VERCEL_OIDC_TOKEN`。当沙箱支持请求转换时，适配器仅将选定的凭据代理到配置的 Gateway 源。其他沙箱保留直接的凭据转发。

当主机在运行时解析凭据而不是通过 `process.env` 暴露它们时，请传递认证环境：

```ts
const gatewayHarness = createFx({
  auth: {
    AI_GATEWAY_API_KEY: await resolveGatewayToken(),
    AI_GATEWAY_BASE_URL: 'https://ai-gateway.vercel.sh',
  },
});
```

提供的记录会替换用于认证发现的主机环境。适配器不会将其凭据添加到 `process.env`，也不会将其值包含在持久化的 ACP 生命周期身份中。

两种认证配置都能访问 AI Gateway：

```ts
const directHarness = createFx({ auth: 'direct' });
const gatewayHarness = createFx({ auth: 'ai-gateway' });
```

## 沙箱

fx 通过 `@ai-sdk/harness-acp` 在沙箱内运行。它需要一个至少暴露一个端口的网络沙箱：

```ts
const sandbox = createVercelSandbox({
  runtime: 'node24',
  ports: [4000],
});
```

第一个会话需要网络出口来下载 fx。后续的模型和 Web 请求也需要网络访问。

## 内置工具

适配器将 `glob_files`、`grep_files` 和 `web_search` 映射到通用的 `glob`、`grep` 和 `webSearch` 工具链工具名称。

其他工具仍以其原生 fx 名称提供，包括 `list_files`、`read_file`、`write_file`、`edit_file`、文件修改和元数据工具、`terminal`、`semantic_search`、`web_fetch`、技能工具、子智能体、MCP 发现工具、`ask_user_question`、`vision` 和 `read_tool_result`。

适配器将 `allow-reads` 和 `allow-edits` 映射到 fx 的 `ask` ACP 模式。`allow-all` 映射到 fx 的 `code` ACP 模式。`allow-edits` 映射是保守的，因为 fx 不提供允许文件编辑但仍需批准终端命令的模式。fx 可能会解析安全操作或应用自己的权限策略，而无需发送 ACP 权限请求。

## 已知限制

- fx 的 ACP v1 工具更新省略了程序化工具名称和原始输入，除非在请求权限时。原生工具仍然执行，但普通的原生工具事件并不总能与类型化的内置工具名称关联。
- ACP v1 不暴露模型步骤边界或每步使用量。适配器推断边界，并在 fx 不提供总数时报告未知的每步使用量。
- ACP v1 没有可移植的手动压缩或回合中转向 API。
- ACP v1 没有可移植的内置工具过滤 API。支持过滤主机工具，但过滤 fx 内置工具会抛出不支持的能力错误。
- fx ACP 不暴露结构化输出元数据映射，因此不支持基于模式的结构化输出。
