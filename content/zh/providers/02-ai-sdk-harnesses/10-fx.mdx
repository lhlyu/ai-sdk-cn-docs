# fx Harness

fx harness 适配器使用 [libfx](https://www.npmjs.com/package/libfx) 将 `HarnessAgent` 连接到 [fx](https://fx.sh)。运行时在主机上运行，而内置的文件系统和 shell 工具仅在沙箱中操作。沙箱内不运行任何桥接进程。

<Note>
  Harness 包目前处于**实验性**阶段。随着这一早期 API 的进一步完善，各版本之间可能会出现破坏性变更。
</Note>

## 设置

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-fx @ai-sdk/sandbox-vercel" />

libfx 随适配器一起安装。会话启动时，不会在沙箱内下载或安装任何 fx 可执行文件。

## 导入

```ts
import { createFx, fx } from '@ai-sdk/harness-fx';
```

`fx` 等同于使用默认配置的 `createFx()`。

## 基本用法

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { fx } from '@ai-sdk/harness-fx';
import { createVercelNetworkSandboxSession } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: fx,
  model: 'openai/gpt-5.6-luna',
});

const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  template: await agent.getSandboxTemplate(),
});
const session = await agent.createSession({ sandboxSession });

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: 'Check the test failures and fix the production code.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
  process.exit(exitCode);
}
```

## 适配器设置

使用 `createFx()` 配置运行时：

```ts
const harness = createFx({
  auth: 'ai-gateway',
  effort: 'low',
  serviceTier: 'default',
});
```

设置项：

- `auth`：选择 `auto`、`direct` 或 `ai-gateway` 认证方式，或接受一个用于以编程方式解析凭据的认证环境。`auto` 优先使用 Gateway 凭据，`direct` 优先使用订阅凭据并以 Gateway 作为回退，`ai-gateway` 仅使用 Gateway。
- `mcpServers`：以服务器名称为键的 MCP 服务器定义。支持 HTTP 和 SSE 服务器，包含 `url`、可选的 `type`、`headers` 和 `disabled` 字段。连接在主机上运行；不支持命令/stdio 服务器。
- `headers`：从主机随 AI Gateway 请求发送的额外请求头。
- `effort`：适用于支持该设置的模型的推理强度。
- `serviceTier`：选择 `default`、`fast` 或 `ultrafast`。`default` 等同于省略该设置，并保持 libfx 的默认值不变。Fast 和 Ultra 需要支持所选层级的模型。
- `backend`：libfx 运行时后端（`auto`、`native` 或 `wasm`）。默认值为 `auto`，优先使用原生后端。WASM 后端需要 JavaScript Promise Integration (JSPI) 支持。

## 认证

fx 支持 [Vercel AI Gateway 认证](https://fx.sh/docs/getting-started/authentication)以及 Codex 或 Grok 订阅。对于 Gateway 认证，请设置以下环境变量之一：

- `VERCEL_OIDC_TOKEN`
- `AI_GATEWAY_API_KEY`

当两者都可用时，适配器优先使用 `AI_GATEWAY_API_KEY`。`AI_GATEWAY_BASE_URL` 可选择性地覆盖 Gateway 端点。凭据在主机上使用，不会转发到沙箱中。

当 Gateway 凭据缺失时，`auto` 会按以下顺序发现订阅凭据：

1. fx Codex：`~/.fx/chatgpt-auth.json`。
2. fx Grok：`~/.fx/grok-auth.json`。
3. 原生 Codex：`CODEX_HOME` 或 `~/.codex` 下的凭据存储，遵循 `cli_auth_credentials_store` 和原生密钥环设置。
4. 原生 Grok：`GROK_HOME/auth.json` 或 `~/.grok/auth.json` 中的 xAI OAuth 记录。

libfx 会在订阅令牌临近过期时以及认证被拒绝后刷新令牌。适配器会将轮换后的凭据保存回所选存储。选择之后的失败不会静默切换订阅或回退到 Gateway。凭据绝不会包含在持久化的生命周期状态中。

当主机在运行时解析凭据而不是通过 `process.env` 暴露凭据时，请传入认证环境：

```ts
const gatewayHarness = createFx({
  auth: {
    AI_GATEWAY_API_KEY: await resolveGatewayToken(),
    AI_GATEWAY_BASE_URL: 'https://ai-gateway.vercel.sh',
  },
});
```

提供的记录会替代主机环境用于认证发现。适配器不会将其凭据添加到 `process.env`，也不会将其值包含在持久化的生命周期状态中。

使用 `direct` 在 Gateway 之前尝试订阅，或使用 `ai-gateway` 禁用订阅发现：

```ts
const directHarness = createFx({ auth: 'direct' });
const gatewayHarness = createFx({ auth: 'ai-gateway' });
```

显式指定的认证环境不会检查环境中的订阅存储。恢复的会话会保留其原始提供商，并且需要与该提供商兼容的凭据。

## 沙箱

fx 在主机上运行，并接受受限沙箱会话或网络沙箱会话。不需要暴露沙箱端口：

```ts
const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  template: await agent.getSandboxTemplate(),
});
```

主机需要网络访问权限以使用 AI Gateway 和已配置的 MCP 服务器。沙箱不需要网络访问权限来处理模型请求。内置工具使用沙箱的文件和命令执行 API；沙箱必须提供 Bash 和 GNU 命令行工具，例如 `find`、`grep`、`realpath` 和 `base64`。

## 内置工具

适配器暴露 `read`、`write`、`edit`、`bash`、`grep`、`glob`、`ls` 和 `askUserQuestions`。文件系统和 shell 操作在会话沙箱中运行。适配器不会暴露 fx CLI 的其他内置工具。

通过 `activeTools` 和 `inactiveTools` 支持内置工具过滤。使用 `permissionMode: 'allow-reads'` 时，文件编辑和 shell 命令需要审批。使用 `allow-edits` 时，只有 shell 命令需要审批。`allow-all` 会在无需审批请求的情况下运行这些工具。

## 已知限制

- 稳定版 libfx 不支持手动压缩，并会抛出 `HarnessCapabilityUnsupportedError`。
