# Grok Build Harness

Grok Build harness 适配器通过 Agent Client Protocol (ACP) 将 `HarnessAgent` 连接到
[Grok Build CLI](https://x.ai/cli)。
该适配器将 ACP 安装、会话、流式传输、工具和生命周期管理委托给
`@ai-sdk/harness-acp`。

<Note>
  Harness 包目前处于**实验阶段**。随着这一早期 API 的进一步完善，
  各版本之间可能会出现破坏性变更。
</Note>

## 设置

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-grok-build @ai-sdk/sandbox-vercel" />

ACP harness 会在首个会话启动时，在沙箱内安装固定版本的 Grok Build CLI。

## 导入

```ts
import { createGrokBuild, grokBuild } from '@ai-sdk/harness-grok-build';
```

`grokBuild` 等同于使用默认配置的 `createGrokBuild()`。

## 基本用法

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { grokBuild } from '@ai-sdk/harness-grok-build';
import { createVercelSandbox } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: grokBuild,
  model: 'grok-build-0.1',
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
});

const session = await agent.createSession();

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: 'Check the test failures and fix the production code.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  process.exit(exitCode);
}
```

要使用此智能体，请确保环境变量中包含用于 Vercel Sandbox 的 `VERCEL_OIDC_TOKEN`，
以及 [身份验证](#authentication) 下列出的、用于 Grok Build 的变量之一。

## 适配器设置

使用 `createGrokBuild()` 配置运行时：

```ts
const harness = createGrokBuild({
  auth: 'ai-gateway',
  reasoningEffort: 'high',
  port: 4001,
  startupTimeoutMs: 180_000,
});
```

设置项：

- `auth`：选择 `auto`、`direct` 或 `ai-gateway` 身份验证，或接受一个隔离的身份验证环境。
  默认值为 `auto`，当存在 Gateway 凭据时选择 AI Gateway，否则选择直接 xAI 身份验证。
- `credentialForwarding`：可选的同步或异步回调，用于在 harness 适配器将每个凭据转发到
  沙箱进程之前立即对其进行自定义。它接收原本会被转发的凭据值（真实凭据或掩码值）
  以及用于暴露该凭据的环境变量名。此回调仅控制转发到沙箱进程中的值。
  它不会限制 harness 适配器在宿主进程中能够发现、读取或以其他方式访问哪些凭据。
- `reasoningEffort`：支持推理的模型的推理强度。支持的值为 `none`、`minimal`、`low`、
  `medium`、`high`、`xhigh` 和 `max`。省略时，Grok Build 使用其配置的默认值。
- `mcpServers`：以服务器名称为键的 MCP 服务器定义。
- `port`：ACP 桥接端口覆盖。
- `startupTimeoutMs`：等待 ACP 桥接启动的最长时间。
- `mintBridgeToken`：同步函数，接收沙箱 id 并返回 ACP 桥接身份验证令牌。默认情况下，
  适配器会生成一个随机的 32 字节令牌。自定义实现必须返回一个足够安全的令牌。

适配器固定了 Grok Build CLI 和 ACP 启动命令。这些实现细节无法通过
`createGrokBuild()` 覆盖。

## 结构化输出

Grok Build 支持基于 schema 的 [`HarnessAgent` 结构化输出](/docs/ai-sdk-harnesses/harness-agent#generate-structured-output)。
其 profile 将 JSON Schema 映射到 Grok Build 的私有 ACP 提示词元数据，
运行时通过其提供商结构化输出机制强制执行该元数据。

## 身份验证

默认情况下，身份验证从宿主环境解析。当沙箱支持附加式请求转换时，
Grok Build 会收到一个占位符，适配器会将凭据注入到匹配的出站请求中。
其他沙箱则保留直接凭据转发。

支持的环境变量：

- `VERCEL_OIDC_TOKEN`
- `AI_GATEWAY_API_KEY`
- `AI_GATEWAY_BASE_URL`
- `XAI_API_KEY`

如果未设置适用的凭据环境变量，适配器会尝试从宿主系统解析原生订阅，
除非选择了 AI Gateway 身份验证。

使用直接身份验证时，适配器使用 `XAI_API_KEY`。使用 AI Gateway 时，
它将 Gateway 凭据作为 `XAI_API_KEY` 提供，将以 `/v1` 结尾的 Gateway
基础 URL 映射到 `GROK_XAI_API_BASE_URL` 和 `GROK_MODELS_BASE_URL`，
并设置 `GROK_CLIENT_NAME` 和 `GROK_CLIENT_VERSION` 用于客户端归属。

当两种凭据都可用时，强制使用特定的身份验证路由：

```ts
const directHarness = createGrokBuild({ auth: 'direct' });
const gatewayHarness = createGrokBuild({ auth: 'ai-gateway' });
```

当宿主在运行时解析凭据时，传入一个身份验证环境：

```ts
const gatewayHarness = createGrokBuild({
  auth: {
    AI_GATEWAY_API_KEY: await resolveGatewayToken(),
    AI_GATEWAY_BASE_URL: 'https://ai-gateway.vercel.sh',
  },
});
```

所提供的记录会替换用于身份验证发现的宿主环境，因此它也可以通过 `XAI_API_KEY`
选择直接身份验证。

## 沙箱

Grok Build 通过 `@ai-sdk/harness-acp` 在沙箱内运行。它需要一个至少暴露一个端口的
网络沙箱，例如 `@ai-sdk/sandbox-vercel`：

```ts
const sandbox = createVercelSandbox({
  runtime: 'node24',
  ports: [4000],
});
```

首个会话需要网络出口，以便 ACP harness 能够在沙箱内安装
`@xai-official/grok@1.0.5`。

## 内置工具

适配器将这些 Grok Build 内置工具映射到常见的 harness 工具：

- `bash` (`run_terminal_command`)
- `edit` (`search_replace`)
- `grep`
- `webSearch` (`web_search`)
- `write`

其他 Grok Build 工具仍以其原生名称可用，包括 `read_file`、`list_dir`、
`todo_write`、`spawn_subagent`、`monitor`、工作流和调度器工具，以及图像生成工具。

Grok Build 不会为其权限行为公布 ACP 会话模式。当 Grok 发送 ACP 权限请求时，
ACP harness 会根据工具类型应用配置的 Harness `permissionMode`。
Grok 可能会在内部处理安全的内置操作，而不发送权限请求。

## 已知限制

- ACP v1 不暴露模型步骤边界或每步用量。当 Grok 未提供总计数据时，
  适配器会推断边界并报告未知的每步用量。
- ACP v1 没有可移植的手动压缩或回合中途引导 API。
- ACP v1 没有可移植的内置工具过滤 API。支持过滤宿主工具，
  但过滤 Grok 内置工具会抛出不支持能力的错误。
- Grok Build 目前不支持内置工具审批请求。请在此适配器中使用
  `permissionMode: 'allow-all'`。宿主执行的 AI SDK 工具审批仍然有效。
- 更改宿主工具目录后，Grok Build 需要刷新其 ACP MCP 工具列表。
  如果实现保留了过时的工具，该回合会显式失败。
- 自定义 `headers` 不受原生支持，只能通过沙箱外部请求转换应用。
  因此，当提供不支持该能力的沙箱时，无法传递自定义 `headers`，它们会被忽略。
