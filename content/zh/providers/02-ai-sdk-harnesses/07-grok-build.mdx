# Grok Build 工具

Grok Build 工具适配器通过 Agent Client Protocol (ACP) 将 `HarnessAgent` 连接到
[Grok Build CLI](https://x.ai/cli)。
该适配器将 ACP 安装、会话、流式传输、工具和生命周期管理委托给 `@ai-sdk/harness-acp`。

<Note>
  Harness 包为**实验性**。随着这个早期 API 的进一步完善，版本之间可能会有破坏性变更。
</Note>

## 设置

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-grok-build @ai-sdk/sandbox-vercel" />

当第一个会话启动时，ACP harness 会在沙箱内安装固定版本的 Grok Build CLI。

## 导入

```ts
import { createGrokBuild, grokBuild } from '@ai-sdk/harness-grok-build';
```

`grokBuild` 等同于使用默认配置的 `createGrokBuild()`。

## 基本用法

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { grokBuild } from '@ai-sdk/harness-grok-build';
import { createVercelSandbox } from '@ai-sdk/sandbox-vercel';

const agent = new HarnessAgent({
  harness: grokBuild,
  sandbox: createVercelSandbox({
    runtime: 'node24',
    ports: [4000],
  }),
});

const session = await agent.createSession();

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: '检查测试失败并修复生产代码。',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  process.exit(exitCode);
}
```

要使用此智能体，请确保环境变量包含用于 Vercel Sandbox 的 `VERCEL_OIDC_TOKEN`，以及
[认证](#authentication) 下列出的用于 Grok Build 的变量之一。

## 适配器设置

使用 `createGrokBuild()` 配置运行时：

```ts
const harness = createGrokBuild({
  auth: 'ai-gateway',
  model: 'grok-code-fast-1',
  port: 4001,
  startupTimeoutMs: 180_000,
});
```

设置：

- `auth`：选择 `auto`、`direct` 或 `ai-gateway` 认证。默认值为 `auto`，当存在 Gateway 凭据时选择 AI Gateway，否则选择直接 xAI 认证。
- `model`：通过 ACP 选择的 Grok 模型 ID。省略时，Grok Build 会选择自己的默认模型。
- `mcpServers`：以服务器名称作为键的 MCP 服务器定义。
- `port`：ACP 桥接端口覆盖。
- `startupTimeoutMs`：等待 ACP 桥接启动的最长时间。
- `mintBridgeToken`：接收沙箱 ID 并返回 ACP 桥接认证令牌的同步函数。默认情况下，适配器会生成一个随机的 32 字节令牌。自定义实现必须返回一个足够机密的令牌。

适配器固定了 Grok Build CLI 和 ACP 启动命令。这些实现细节无法通过 `createGrokBuild()` 覆盖。

## 结构化输出

Grok Build 支持基于模式的 [`HarnessAgent` 结构化输出](/docs/ai-sdk-harnesses/harness-agent#generate-structured-output)。
其配置文件将 JSON Schema 映射到 Grok Build 的私有 ACP 提示词元数据，运行时通过其提供商结构化输出机制强制执行。

## 认证

默认情况下，认证从宿主环境中解析。当沙箱支持附加请求转换时，Grok Build 会收到一个占位符，适配器会将凭据注入到匹配的出站请求中。其他沙箱保留直接凭据转发。

支持的环境变量：

- `VERCEL_OIDC_TOKEN`
- `AI_GATEWAY_API_KEY`
- `AI_GATEWAY_BASE_URL`
- `XAI_API_KEY`

使用直接认证时，适配器使用 `XAI_API_KEY`。使用 AI Gateway 时，它将 Gateway 凭据作为 `XAI_API_KEY` 提供，将以 `/v1` 结尾的 Gateway 基础 URL 映射到 `GROK_XAI_API_BASE_URL` 和 `GROK_MODELS_BASE_URL`，并设置 `GROK_CLIENT_NAME` 和 `GROK_CLIENT_VERSION` 用于客户端归属。

当两种凭据都可用时，强制使用特定的认证路由：

```ts
const directHarness = createGrokBuild({ auth: 'direct' });
const gatewayHarness = createGrokBuild({ auth: 'ai-gateway' });
```

## 沙箱

Grok Build 通过 `@ai-sdk/harness-acp` 在沙箱内运行。它需要一个至少暴露一个端口的网络沙箱，例如 `@ai-sdk/sandbox-vercel`：

```ts
const sandbox = createVercelSandbox({
  runtime: 'node24',
  ports: [4000],
});
```

第一个会话需要网络出口，以便 ACP harness 可以在沙箱内安装 `@xai-official/grok@0.2.111`。

## 内置工具

适配器将这些 Grok Build 内置工具映射到常见的 harness 工具：

- `bash` (`run_terminal_command`)
- `edit` (`search_replace`)
- `grep`
- `webSearch` (`web_search`)
- `write`

其他 Grok Build 工具仍以其原生名称提供，包括 `read_file`、`list_dir`、`todo_write`、`spawn_subagent`、`monitor`、工作流和调度工具，以及图像生成工具。

Grok Build 不会为其权限行为通告 ACP 会话模式。当 Grok 发送 ACP 权限请求时，ACP harness 会根据工具类型应用配置的 Harness `permissionMode`。Grok 可能会在内部处理安全的内置操作，而无需发送权限请求。

## 已知限制

- ACP v1 不暴露模型步骤边界或每步使用量。适配器会推断边界，并在 Grok 未提供总计时报告未知的每步使用量。
- ACP v1 没有可移植的手动压缩或回合中转向 API。
- ACP v1 没有可移植的内置工具过滤 API。支持过滤宿主工具，但过滤 Grok 内置工具会抛出不支持的能力错误。
- 更改宿主工具目录需要 Grok Build 刷新其 ACP MCP 工具列表。如果实现保留了过时的工具，回合将明确失败。
